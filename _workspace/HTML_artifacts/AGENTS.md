# AGENTS — `_workspace/HTML_artifacts/`

## Зачем это

Иногда ответ — это большая работа: что сделано, какие файлы изменены, крупный анализ с кучей предложенных правок. Простынёй текста в чате это читать тяжело. Вместо простыни — собери **сканируемый HTML-отчёт** и открой его в браузере.

Типичные кейсы:

- **отчёт о работе** — что сделал, какие файлы тронул, что осталось;
- **дашборд** — крупная цифра в фокусе (сколько файлов изменено), плитки-метрики;
- **предложение правок** — анализ и пачка изменений по разным файлам с diff.

## Что это НЕ

- не `knowledge/`, не `_ops/` и не owner-док — это рабочий HTML-артефакт;
- не канон — это разовый отчёт, источник правды живёт в owner-файлах;
- **не шаблон** — структуру придумываешь заново под каждый ответ.

## Единственное фиксированное правило

Не пиши стили в файле-ответе — линкуй общий лист. Шапка (всё, что фиксировано):

```html
<!doctype html>
<html lang="ru">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>agentic-research — отчёт</title>
<link rel="stylesheet" href="styles.css">
</head>
<body>
  <!-- здесь твой HTML -->
</body>
</html>
```

- Файл кладёшь **рядом** со `styles.css`, имя `ГГГГ-ММ-ДД-короткий-слаг.html`.
- Открыть пользователю: `open <файл>.html`.
- Устарел — перенеси в `_archive/` (там ссылка станет `../styles.css`).

## Творческая свобода

`styles.css` — фундамент (типографика + готовые блоки), **не клетка**. Внутри `<body>` верстаешь под смысл: горизонтальные ряды, дашборд, большие цифры, график, раскрытие по клику. Сверх готовых блоков можно:

- **график** — inline `<svg>` (рисуй цветами `var(--accent)`, `currentColor` —
  тогда живёт и в тёмной теме) или CDN-библиотека, если действительно нужно;
- **интерактив по клику** — нативный `<details><summary>` (без JS) либо
  маленький inline `<script>` для уникального поведения;
- **уникальный стиль одного блока** — локальный `<style>` в этом файле. Общий
  `styles.css` под конкретный ответ не правь — он на все отчёты сразу.

## Готовые блоки

Пишешь голый HTML — вид берётся сам. Классы только там, где нужен особый блок:

| Что нужно | Как |
|---|---|
| Заголовок, текст, список, цитата, код, таблица | просто `<h1>`/`<p>`/`<ul>`/`<blockquote>`/`<pre>`/`<table>` — стилизованы |
| Подзаголовок-надпись над H1 | `<span class="kicker">` |
| Вводный абзац крупнее | `<p class="lead">` |
| Дата/контекст под шапкой | `<p class="meta">` |
| Горизонтальные блоки в ряд | `<div class="row">…</div>` (дети встают рядом, переносятся на узком) |
| Сетка карточек | `<div class="grid">`, либо `grid-2/3/4`, либо `split` (2 колонки) |
| Карточка | `<div class="card">` |
| Метрики-плитки | `<div class="stats"><div class="stat"><span class="num">47</span><span class="label">файлов</span></div></div>`; акцентная — `class="stat accent"` |
| Одна огромная цифра-фокус | `<p class="bignum">47</p>` |
| Статус-метка | `<span class="badge add">` (add/mod/del/accent или просто `badge`) |
| Список изменённых файлов | `<ul class="files"><li><span class="badge mod">изм</span><span class="path">путь</span><span class="desc">что</span></li></ul>` |
| Правка файла (имя + код) | `<figure class="code-file"><figcaption>путь <span class="badge mod">изм</span></figcaption><pre><code>…</code></pre></figure>` |
| Diff внутри `<pre>` | строки в `<ins>` (добавлено) / `<del>` (удалено) |
| Выделить мысль | `<div class="callout warn">` (info/ok/warn/danger) |
| Свернуть/раскрыть по клику | `<details><summary>Заголовок</summary>…</details>` |
| Мини-график (полосы) | `<div class="bars"><div class="bar"><span>метка</span><span class="track"><span class="fill" style="width:70%"></span></span><span class="val">70%</span></div></div>` |
| Иконка | `<span class="ic">rocket_launch</span>` (модификаторы `fill`, `accent`/`ok`/`warn`/`danger`) |
| Диаграмма, схема | `<pre class="mermaid">flowchart TD …</pre>` + строка `<script src="mermaid-init.js"></script>` перед `</body>` |
| Цитата из дока базы | `<figure class="quote"><blockquote>точный кусок канона</blockquote><figcaption>файл#секция</figcaption></figure>` — точные куски тащи через `md search-read`/`md extract`, не пересказывай |

Тёмная тема, мобильная вёрстка и печать/PDF — уже учтены в `styles.css`.

Живой образец всех блоков — `example.html` рядом (это **показ возможностей**, а не структура, которую надо повторять).

## Иконки (Material Symbols)

Иконки подключены автоматически через `styles.css` — ничего в `<head>` добавлять не надо. Пиши имя иконки в `<span class="ic">`:

```html
<span class="ic accent">bolt</span>  <span class="ic fill ok">check_circle</span>
<h2><span class="ic accent">folder_open</span> Что сделано</h2>
```

Используй их **активно** — для быстрой навигации глазом: иконка перед заголовком раздела, в callout-е, рядом со статусом файла, в `<summary>`, маркером смысла в тексте. Иконка наследует цвет соседнего текста; `accent`/`ok`/`warn`/`danger` и `fill` — модификаторы. Имена бери на fonts.google.com/icons (стиль **Rounded**). Офлайн иконка покажется словом-именем — не ставь их туда, где это сломает смысл.

## Диаграммы (Mermaid)

Когда схема яснее текста (процесс, ветвление, статусы, поток) — рисуй Mermaid. В артефакт с диаграммой добавь перед `</body>` одну строку:

```html
<script src="mermaid-init.js"></script>
```

Рядом лежащий `mermaid-init.js` держит загрузку и тему диаграмм (тёплая палитра, крупный шрифт, тёмный режим). Сама схема:

```html
<pre class="mermaid">
flowchart TD
  A[Заявка] --> B[Оплата]
  B --> C[Принят заказ]
</pre>
```

**Чтобы график всегда помещался в рамку, а текст был крупным** (правила из скила `1mermaid`, перенесённые на HTML):

- **узко и вертикально** — `flowchart TD`, а не широкий `LR`: широкий граф
  ужимается под ширину рамки, и подписи становятся микроскопическими;
- **мало узлов, короткие подписи** — деталь выноси в текст рядом, не в узел;
- **большую тему дроби** на несколько маленьких диаграмм друг под другом — один
  гигантский граф запрещён;
- вертикальная стадийная схема — для 4–6 крупных стадий, не для длинного списка
  шагов;
- не начинай подпись узла с «1. » / «2. » (ломает парсер) — пиши «Шаг 1: …»;
  многословные подписи в `quadrantChart` бери в кавычки.

Рамка, масштаб по ширине, центрирование и тёмная тема уже в `styles.css` + `mermaid-init.js` — про них думать не нужно, думай только про то, чтобы граф был узким и коротким.
