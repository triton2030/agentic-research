# HTML-артефакт

## Результат

Последний содержательный ответ или указанная пользователем тема превращены в
один простой HTML-файл в `_workspace/HTML_artifacts/`. Файл должен быть понятнее
чата: больше контекста, меньше терминов, линейная мысль, главное в начале,
сканируемые блоки. В чате после работы дай одну короткую строку с абсолютным
путём к файлу; не дублируй весь артефакт обратно.

## Вход / Пропуск

Используй только по явному ручному вызову: `1html-artifact`, "переведи это в
html", "сделай HTML-артефакт", "не понял - оформи просто", "перепиши понятно в
HTML".

Предмет по умолчанию - твой последний содержательный ответ. Если пользователь
указал документ, тему, кусок диалога или текущую развилку, делай артефакт по
этому предмету.

Пропускай:

- обычный чат-ответ, когда HTML не просили;
- сжатие текста без смены формата -> `1smart-simple`;
- Obsidian Markdown UX -> `1obsidian`;
- правку самой системы `_workspace/HTML_artifacts/` (`styles.css`,
  `mermaid-init.js`, локальный `AGENTS.md`) без явного запроса.

## Писать Проще

Вызов означает: пользователь потерялся или не понял прежний ход. Не защищай
исходный ответ и не делай просто красивую версию того же текста.

- Верни контекст: о чём речь, зачем это важно, какое решение поддерживает.
- Убери программистский жаргон. Неизбежный термин объясни рядом одной простой
  фразой.
- Двигайся линейно: один вывод, потом причина, потом следующий шаг.
- Главное поставь в начало.
- Используй живой простой русский.

## Owner-Доки И Цитаты

Если артефакт опирается на локальные owner-документы, не пересказывай их как
новый канон. Найди точное место и процитируй коротко с источником:

- если доступен `md`: `md search-read <корпус> --query "<смысл>" --expanded
  --json`, `md toc`, `md extract`;
- если `md` не подходит: используй `rg` и прямое чтение выбранного файла.

В HTML отделяй такие места как "цитата из дока" с указанием `файл#секция` или
`файл:строка`.

## Рабочий Ход

1. Назови для себя предмет артефакта: последний ответ или указанная цель.
2. Проверь, есть ли локальная система:
   `_workspace/HTML_artifacts/AGENTS.md`.
   Если есть - прочитай её и используй местный toolkit, `styles.css`,
   `mermaid-init.js` и правила блоков.
3. Если папки нет, создай `_workspace/HTML_artifacts/` и сделай один
   самодостаточный HTML с inline CSS. Не создавай `AGENTS.md`, `styles.css` или
   отдельную систему артефактов без отдельного запроса.
4. Имя файла: `YYYY-MM-DD-короткий-слаг.html`.
5. Собери страницу как читаемый артефакт: заголовок, короткий вывод, контекст,
   2-5 смысловых блоков, если нужно - простая схема или список решений.
6. Проверь, что файл существует. Если возможно в текущей среде, открой его
   (`open <abs-path>`); если нет - дай абсолютный путь.

## Проверка

Минимум перед финалом:

- `test -f <abs-path>`;
- если использован внешний CSS/JS - проверь, что путь существует;
- если цитировал owner-доки - проверь, что источник реально прочитан.

## Стоп

Остановись, когда HTML-файл создан, понятность улучшена, источники не
искажены, путь проверен, а чат-ответ сведен к короткой ссылке/пути. Если skill
часто вызывается, это feedback о стиле чата; не записывай память без явной
просьбы пользователя.
