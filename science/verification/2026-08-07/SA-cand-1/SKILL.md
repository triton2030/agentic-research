# skill-architect

Порядок: провал → необходимость → механизм → поверхность.

- «Не начинай с названия, структуры папки или списка возможностей.» Сначала
  trace без скилла, потом **deficit** — недостающий control act.
- Proof Gate: назови точный случай trace, который не закрывает минимальный
  comparator (одно правило, вопрос, check, delta ближайшего owner-а). «Не
  можешь назвать — остановись на ней.»
- «не выбирай surface раньше диагноза: иначе формат начинает диктовать
  объяснение проблемы».
- Форма скила: SKILL.md скила ≤2000 символов; reference-файлов сколько угодно,
  каждый ≤2000; переполнение файла решается выносом в новый reference, не
  резкой смысла.

Открывай ровно один файл момента, не весь `references/`.

| Момент | references/ |
|---|---|
| начал дизайн | trace |
| нужен ли скил вообще | why |
| класс пакета | class |
| доказываю необходимость | necessity |
| проектирую механизм, рычаги | mech-1…3 |
| пишу примеры | demos-1,2 |
| сверяю форму самого текста | form |
| выбираю surface, границу, stop | surface, stop |
| пишу description | discovery |
| сдаю Skill Frame | frame |
| Frame → implementation | anchor |
| доказываю изменение | evidence-1,2 |
| каталог типовых провалов | failures |
| термин двусмыслен или меняется словарь | gloss-1…10 |
| Claude-пакет, metadata, источники | plat-1…5 |
| «make a local skill», rewrite, port | local-1…4 |
| broad audit, дизайн разрастается | anti-1…4 |
| полный аудит landscape/control system, не для одной правки | audit-1…4 |
