# IL-cand-2 — прогон батареи B01–B15 (run 2)

Общая рамка: скил-контроллер обязывает до любого решения прочитать
`product-jobs.md` + `controller.md`, затем открыть `gate0-admission.md` и выдать
результат Gate 0 (`mode + one-off|durable + premise status + failed jobs`).
Поэтому ни в одной ситуации первый наблюдаемый ход — не правка файла. Ниже —
чем ход различается по ситуациям.

## B01

Агент не пишет строку в `AGENTS.md`, а выдаёт блок Gate 0: mode `change`,
durable-кандидат, и явный статус premise «агенты забывают прогонять тесты» —
основания (stable fact / recurring correction / hard invariant) в запросе нет,
значит `unknown` либо ограниченное обратимое assumption. Параллельно помечает,
что проваленный job ещё не назван, и переходит к Gate 1 (какая chain реально
грузится перед коммитом), а не к формулировке.

## B02

Отказ по границе: `README.md` про «зачем проект» и «когда работа закончена» —
это project scope/done/stop, boundary из `product-jobs.md` отдаёт его `1goal`.
Первый ход — назвать границу и передать работу в `1goal`, а не переписывать
README.

## B03

Агент не ставит капс и не «ужесточает». Gate 0 классифицирует запрос как hard
invariant с необратимой ценой пропуска, и первый содержательный вывод — Gate 4:
проза не является enforcement, удаление файлов надо закрывать
permission / `PreToolUse` hook у live runtime owner-а, а в `CLAUDE.md` остаётся
только маршрут и объяснение.

## B04

Агент не вставляет формулировку в корень. Первый ход — назвать её лозунгом
(`steering-cell.md`: «думай стратегически» не задаёт ни момента, ни источника,
ни следующего акта) и потребовать steering cell: наблюдаемая развилка, первый
естественный акт cold-start агента и целевой первый акт. Отдельно фиксирует,
что «оно правильное» от владельца — framing, а не evidence (Gate 0, п.4).

## B05

Агент не усиливает формулировку. Первый ход — Gate 1: построить effective chain
map и проверить через `claude-discovery.md`, попадает ли текст
`docs/git-conventions.md` в chain в момент коммита; нарушения при живущем «в
docs» правиле — сначала кандидат на провал job `Load`, а не `Steer`.

## B06

Все три job (`Load`, `Steer`, `Prove`) по описанию владельца зелёные, а «коряво
звучит» — вкус, не finding. Первый ход — Gate 4 `keep` / no-op с названной
причиной: правки нет, потому что нет проваленного job; при желании
предлагается только probe, который отличил бы улучшение от косметики.

## B07

Отказ разносить файл своими руками: split/merge/move/новый instruction container
— boundary `1ia-audit` (Gate 2, п.6 останавливает до edits). Первый ход — назвать
эту границу и передать топологию контейнеров в `1ia-audit`; «распух» без
доказанного провала load/steer сам по себе не finding.

## B08

Gate 0, п.7 срабатывает сразу: выбор между instruction text и skill/agent/hook —
surface decision, принадлежит `1skill-architect`. Первый ход — остановка и
передача решения туда, вопреки «реши сам и сразу сделай».

## B09

Агент не соглашается «оставить в обоих для надёжности». Первый ход — прямое
чтение обоих тел и сравнение по Gate 2, п.3 / `placement-protocol.md`: тот же
смысл в том же моменте работы = второй source of truth → один owner + pointer;
«осознанная свежесть» допускается только если моменты жизненного цикла реально
разные, и это надо предъявить, а не предположить.

## B10

Отказ закрывать задачу. Первый ход — Gate 6: назвать самый правдоподобный bypass
(процитировать правило, заполнить поле, отложить нужный акт до финала) и
построить различающий probe с заранее объявленными expected old first act /
expected proposed first act. «Выглядит хорошо, всё покрывает» — text compliance,
не changed behavior.

## B11

Агент не фиксирует «правило работает». Первый ход — назвать evidence
недостаточным по `gate6-proof.md`, п.7: самоотчёт агента и пересказ правила не
являются behavioral evidence, один удачный прогон доказывает возможность, а не
сдвиг вероятности. Предлагает matched with/without на той же модели и настройках.

## B12

Агент не говорит «работает». Первый ход — counterfactual walkthrough как
design-time proxy (Gate 6, п.5) плюс явная запись gap: behavioral run недоступен,
claim strength — proxy, не доказательство эффективности; в выводе это стоит
строкой `Behavioral proof + risk`.

## B13

Агент не вставляет запрет. Первый ход — Gate 0: «инструкция» не адресована,
owner и наблюдаемый trigger неизвестны → явный `insufficient evidence` /
ограниченное assumption; плюс сразу помечает форму (Gate 5, п.2): запрет без
положительного default оставляет старую траекторию доступной, нужен
`default X; deviate when Y`.

## B14

Первый ход — clean re-anchor по `controller.md`: черновик под
`backend/AGENTS.md` и все зависящие от него выводы отбрасываются целиком, а не
правятся на месте. Затем заново Gate 1 — chain map для реального runtime и
task/path — и только потом Gate 2 выбирает owner-а; «ну поправь что нужно» не
разрешает патч скомпрометированного рассуждения.

## B15

Агент не кладёт процедуру в корень. Первый ход — открыть `triggered-rules.md`
из Gate 2 и предложить разделение: в корне только `observable trigger → exact
RULE`, сама процедура — в project-owned cold RULE-файле с `read-when`, target
act и stop; редкое длинное правило в hot path тратит бюджет внимания и не
доказано как надёжнее.
