# Четыре framework-трассы: сжатие управляющих текстов

Прогон `1deep-agents` 2026-08-06. Один task packet, четыре history-isolated
advisor-а (Opus 5), по одному framework на поток, без инструментов и без
реализации. Трассы сохранены дословно с механической чисткой преамбул —
это archived evidence, root-summary их не заменяет.

Синтез root-а лежит не здесь, а в чате сессии и далее в проектном решении.

**Task packet (общий для всех четырёх).** Решение: какой механизм должен нести
скил, сжимающий управляющие тексты (skill-файлы, системные промпты, файлы
правил), не разрушая скилы, чей продукт — видимое в чате представление.
Факты: бюджет правил 96%→20–60%; артефакт 0–4% против 97%; снятие инструментов
0→74.7%; корпус 55315 скилов (38.5% действующих правил в теле); сжатие 86%
сохранило-или-улучшило, 14% ухудшило, причина «пример как спецификация»;
человеческие скилы +16.6 п.п., модельные −8.1…−11.5 п.п.; верность видимой
цепочки 25–39%, kappa экспертов 0.130. Материал: разбор `1expert-lens` (~86
операндов, ~60 одновременно, около 4/5 сочтены выводимыми из контракта выхода).
Встречный случай: `1product-shaping`, чей продукт — пошаговый разбор в чате,
на котором владелец учится.

## Поток 1 — Value Engineering / FAST

**Framework:** Value Engineering, Function Analysis по методу FAST, внутри VE Job
Plan. **Цель:** отделить базовую функцию, обязанную выжить при снижении
стоимости, от вторичных и ненужных — до решения резать. **Topology:** linear.

**Spine:** S1 Information → S2 Function Analysis (глагол+существительное, FAST
«Как?»/«Почему?», базовая функция, критический путь, all-the-time и same-time,
тест How/Why, функции без потребителя) → S3 Creative → S4 Evaluation →
S5 Development → S6 Presentation.

**Оговорка потока:** VE Job Plan по памяти стандартизован SAVE International,
FAST восходит к Байтуэю (1965). Источники не открывались — spine помечен
recollection-grade, не source-verified.

**Mapping:** компонент → нормативное утверждение или блок текста; стоимость →
доля бюджета одновременно действующих правил; потребитель → **два**: агент и
владелец; базовая функция → то, ради чего текст существует у данного
потребителя; носитель функции → блок текста либо не-текст (инструмент,
артефакт-гейт). Вердикт: fit есть. Названное ограничение: две шкалы
несоизмеримы (соблюдение измеримо, понимание владельца — нет); по практике VE
неоцениваемая функция переводится в ограничение, а не в предмет размена.

### S1 Information

Вход: доли корпуса, кривая бюджета, разобранный пример.
Операция: разнесение компонентов и потребителей с привязкой стоимости.

| Компонент | Доля | Занимает бюджет правил |
|---|---|---|
| нормативные утверждения | 38.5% | да, 1 единица каждое |
| фон / обоснование | 40.7% | нет |
| примеры | 12.9% | **неопределённо** — «пример как спецификация» действует как правило, не будучи посчитанным |
| шаблоны | 7.6% | частично |

Результат: объём и стоимость — разные величины. 61.5% тела не покупает почти
ничего измеренной стоимости; внутри 12.9% примеров сидит незабюджетированная
стоимость. Разобранный пример стоит ~60 единиц при кривой, где 20 даёт 20–60%.
Gap: разбавляет ли объём прозы внимание — замера нет.

### S2 Function Analysis

Функции парой «глагол + существительное»: сузить пространство действий (агент);
сделать нарушение видимым (оба); назвать разрываемый дефолт (агент);
**построить понимание задачи (владелец)**; показать форму выхода (агент);
задать неявное обязательство (агент); нести контракт выхода (оба); ввести
систему в работу (агент); вывести систему из работы (агент).

Две FAST-диаграммы:

- **A (агент):** `получить пригодный результат без переделки` ← **[базовая]
  изменить выбор агента** → `сузить пространство` → `сделать нарушение видимым`
  → `предъявить артефакт`. Тест How/Why проходит.
- **B (владелец):** `принять решение по собственной задаче` ← **[базовая]
  построить понимание задачи у владельца** → `разобрать вопросы по шагам в чате`
  → `назвать дефолты и развилки`. Тест How/Why проходит.

Вне критического пути: **one-time** — триггер, исключения; **all-the-time** —
держать границу scope, держать приоритет «готовое перед своим», держать
пропорцию срабатывания; **same-time** — объяснить дефолт.

Прогон разобранного примера: четыре обороны, оказавшиеся выводимыми, при
вопросе «Почему?» сходятся в функцию, которую уже несёт контракт выхода —
дублирующие носители на критическом пути. Три невыводимых остатка ложатся в
позиции вне критического пути (one-time и all-the-time).

**Результат шага (ключевой):** выводимо ровно то, что лежит на критическом пути;
невыводимо ровно то, что FAST по построению туда не кладёт. Наблюдение n=1
получает механизм. Вторая находка: блок, выглядящий фоном на диаграмме A, на
диаграмме B стоит **на критическом пути** — встречный случай становится
предсказуемым классом.

Функции без потребителя: правило без проверяемого артефакта (стоимость есть,
доставка 0–4%) — чистая ненужность; дублирующий носитель обороны. **Не сюда:**
фон целиком — часть фона единственный носитель базовой функции B.

### S3 Creative

| Функция | Носитель | Стоимость | Доставка |
|---|---|---|---|
| сузить пространство | прозаические правила | N | 20–60% при N≈20 |
| та же | снятие инструмента | 0 | 74.7% |
| та же | требование артефакта | 1 | 97% |
| изменить выбор | контракт выхода, обороны выводятся | 1 вместо ≥4 | не замерено |
| построить понимание владельца | развёрнутая проза-разбор | 0 по бюджету правил | владелец подтверждает словами |

Отдельная альтернатива: вынос в отдельный файл — снижает видимый объём, не
снижает бюджет правил, и именно на нём зафиксированы 14% регрессий.

Три качественно разных хода: удалить стоимость без функции; вывести дублирующий
носитель; **перенести функцию на другой носитель, в том числе нетекстовый**.

### S4 Evaluation

| Альтернатива | Где снимается стоимость | Что теряет носителя | Вердикт |
|---|---|---|---|
| Резать по форме («только действующие правила») | почти нигде: 61.5% не занимает бюджет | базовая функция B режется первой | **отклонить как ядро** — удешевление по категории компонента, а не по функции |
| Вывести обороны из контракта выхода | внутри 38.5%, где стоимость реально есть | ни одной, если выводимость держится | **принять условно**, доказательства нет |
| Перенести на нетекстовый носитель | максимально: N → 1 или 0 | ни одной, доставка растёт | **принять**, сильнейшее evidence |
| Переписать компактнее | объём, не бюджет | риск подмены носителя (+16.6 против −8.1…−11.5) | **отклонить как ядро** |
| Вынести в файл | объём | единственный носитель неучтённой функции | **принять только с проверкой носителя** |

Переформулировка причины 14%: регрессия наступает, когда перемещают компонент,
не построив карту функций, и он оказывается единственным носителем функции,
которой нет в списке. «Пример как спецификация» — частный случай; общий класс —
любой невыявленный единственный носитель.

Обращение с несоизмеримостью: базовая функция B не участвует в размене и не
может быть срезана на основании метрики другого потребителя. Корпусная цифра
38.5% описывает диаграмму A и ничего не говорит о диаграмме B.

### S5 Development

- **Перенос** применим, когда функция формулируется как «сделать нарушение
  видимым» или «сузить пространство» — то есть когда нетекстовый носитель
  возможен в принципе.
- **Вывод из контракта выхода** применим только к компонентам на критическом
  пути диаграммы A. Наблюдаемое условие — тест «Почему?»: ответ приводит к
  функции контракта выхода → дублирующий носитель; ответ уводит в one-time или
  all-the-time → **компонент невыводим, и сокращение есть потеря функции**.
- **Вынос** применим только после ответа «какая функция теряет здесь
  единственного носителя?».
- **Сквозное ограничение:** компонент допустим к сокращению, только если он вне
  критического пути **обеих** диаграмм и не имеет потребителя.

Gap теперь фальсифицируем: построить FAST для второго скила и проверить, ложится
ли невыводимый остаток снова в one-time/all-the-time.

### S6 Presentation

| Недопустимо как доказательство | Почему |
|---|---|
| прочитать сжатый текст и признать хорошим | kappa 0.130 |
| видимая цепочка рассуждения агента | верность 25–39% |
| «правило присутствует в тексте» | 0–4% при том же тексте |

| Допустимо | Что показывает |
|---|---|
| выход агента против контракта выхода до и после | сохранение функции A |
| наличие затребованного артефакта | доставка «сделать нарушение видимым» |
| собственное действие владельца после чтения | единственное доказательство функции B; прокси не существует |

### Вывод потока 1

1. Сжатие — это функциональный анализ перед удалением; «сократить до сути» без
   карты функций режет по категории компонента и уносит единственных носителей.
2. Наивная постановка внутренне противоречива численно: резать фон — снимать
   61.5% объёма и почти ноль измеренной стоимости, уничтожая базовую функцию
   второго потребителя.
3. Механизм обязан быть двухпотребительским; критический путь строится дважды.
4. **Главный рычаг — не сокращение, а смена носителя.** Единственные измеренные
   скачки (0→74.7%, 0–4%→97%) получены переносом на среду и артефакт.
5. Выводимость имеет структурную границу: из контракта выхода выводимо то, что
   на критическом пути; триггер, исключения, экономический приоритет, момент и
   пропорция лежат вне его.
6. Переписывание проваливает оценку: удешевление обязано идти удалением и
   переносом при сохранении оставшихся строк.
7. Единица стоимости — одновременно действующее правило, не токен.

## Поток 2 — Minimum Description Length

**Framework:** MDL, crude two-part code `L(H) + L(D|H)` (Rissanen 1978; изложение
Grünwald 2007). **Цель:** выбрать гипотезу, минимизирующую суммарную длину
описания. Обучение = сжатие; несжимаемое = шум. **Topology:** linear.

**Spine:** S1 класс моделей H → S2 код L(H) → S3 код L(D|H) → S4 сумма по
кандидатам → S5 argmin → S6 интерпретация регулярность/шум.

**Оговорка потока:** принцип двухчастного кода и трактовка «регулярность =
сжатие» — канон; пронумерованная процедура S1–S6 — добросовестная
операционализация, не цитата из источника. Порядок S1→S3 обязателен по существу:
коды нельзя выбирать после того, как посмотрел на данные.

**Mapping:** H → текст или отдельное утверждение; D → множество нужных поведений;
L(H) → стоимость текста у приёмника; L(D|H) → остаточное описание; априор
приёмника → дефолты модели 2026; H₀ → голая модель без инструкции. Fit есть.
Поправка на входе: L(H) задан в двух единицах сразу, двухчастный код требует
одной — решается на S2.

### S1 Класс гипотез

Различение: класс A = {файл исходный, файл сжатый} (класс корпусного
исследования); класс B = подмножества нормативных операндов.

Проба: в классе A встречный случай невыразим — нет объекта, способного нести
человеко-адресованную ценность, есть только файл целиком. В классе B выразим.
Тот же тест на 14%: причина «пример как спецификация» в классе A невыразима, в
классе B выразима как «удалённый операнд, чей код никем не дублировался».

Результат: класс = B. **Обязательно включается H₀** — три числа (−8.1, −11.3,
−11.5) суть случаи, где нулевая гипотеза победила; класс без H₀ скрыл бы
победителя.

Gap: MDL по доктрине не обосновывает выбор класса — он выбирается снаружи
метода. Вопрос «должен ли такой скил существовать» этой линзой не решается.

### S2 Код гипотез L(H)

Кандидаты валюты: длина в токенах против числа одновременно связывающих
операндов с попарным членом.

Различающий факт: эксперимент с инструментами — Δтокены = 0, поведение
изменилось на 74.7 п.п. Валюта, в которой стоимость не сдвинулась, а результат
сдвинулся на три четверти шкалы, не измеряет то, что дорого. Второй факт: форма
падения нелинейна и идёт через попарные конфликты; токены аддитивны.

Результат: **L(H) = число одновременно связывающих операндов с попарным членом.**
Следствие: корпусный замер «−39% тела, −48% описания» — измерение падения
прокси, а не L(H). Отдельно: сужение набора инструментов сокращает **носитель
самих данных D**, не добавляя к H ни бита.

### S3 Код данных L(D|H)

Инстанциация принципа владельца: «сюрприз» = −log P(поведение | априор
приёмника). Базовая линия L(D|H₀) — код нужного поведения при голых дефолтах.

Линза добавляет ось, которой в формулировке владельца нет: L(D|H) — ожидание по
распределению задач, значит **цена элемента = сюрприз × масса случая**.
Удивительное правило про редкий случай покупает мало бит.

Обнаружение недостающего члена: классический код предполагает безотказное
декодирование, а приёмник применяет H лишь с вероятностью p:

```
L_эфф(D|H) = p · L(D|H применена) + (1 − p) · L(D|H₀)
```

Это смыкает S2 и S3: добавление правила увеличивает L(H) и **одновременно
снижает p у всех остальных**. Артефакт (0–4% → 97%) — подъём p при неизменном H.
Помечено как расширение канона под наблюдаемый факт, не как канон.

Gap: распределение задач нигде не задано; веса «массы случая» сравнимы только
качественно.

### S4 Сумма по кандидатам

| Сравнение | L(H) | ΔL(D\|H) к H₀ | Вердикт |
|---|---|---|---|
| Модельно-сгенерированный скил vs H₀ | > 0 | **отрицательный** (−8.1…−11.5) | H₀ выигрывает |
| Человеческий скил vs H₀ | > 0 | +16.6 | H выигрывает |
| Сжатый файл vs исходный | −39% в **прокси** | не измерялся | сравнение не проведено |
| Правило без артефакта vs с ним | равны | p: 0–4% → 97% | артефакт при нулевой цене H |
| Текст vs сужение инструментов | 0 против 0 | 0% → 74.7% | сужение выигрывает |

Первая строка: в двухчастном коде хуже нуля — это подпись **неверной** H, а не
бесполезной: платишь и за модель, и за поправки к её ошибкам. Модельный текст
высоковероятен под собственным априором (сюрприз ≈ 0), но операнды связывают
бюджет и сбивают p у остальных.

Третья строка — центральная диагностика: **практика сжатия измеряла только L(H),
причём в отброшенной валюте, а L(D|H) заменяла суммарным баллом.** 14%
ухудшений — случаи, где L(D|H) выросло больше, чем упало L(H); величину, которая
росла, никто не мерил.

Наблюдение «4/5 выводимы» читается как избыточный код, но условие проверяемо
абляцией, а не суждением. Названная неизвестность «априор наблюдаем косвенно,
через поведение без инструкции» — **и есть предписанное измерение**.

### S5 Минимизатор

Argmin поэлементный, не «файл целиком». Три следствия:

1. Целевой процент сжатия (39/48) — не минимум: **задавать долю сокращения
   значит подменять поиск минимума константой**.
2. Минимум **не инвариантен к приёмнику**: универсально сжатого управляющего
   текста не бывает; смена поколения двигает argmin.
3. **Направление минимизации не совпадает с направлением укорачивания.** Один
   добавленный операнд (артефакт) поднимает p с 0–4% до 97% и делает выводимыми
   десятки других: в токенах текст удлинился, в MDL-смысле сжался. Глагол
   «сократить» указывает не в ту сторону в неверных единицах.

### S6 Регулярность и шум

**Регулярность:** то, что приёмник восстанавливает из спецификации артефакта
плюс собственный априор — кандидат — те самые 4/5.

**Несжимаемый остаток неоднороден, и различение решает исход:**

- **Ставка владельца** — произвольный выбор среди равно допустимых; длина кода
  ровно log(число вариантов), **не сокращается принципиально**. Шум в точном
  смысле MDL.
- **Триггер и момент** — не про содержание поведения, а про величину p.
  Сокращать их — отправлять весь остальной текст в неприменённое состояние.
- **Исключения** — границы носителя данных; их удаление расширяет D.

**Ложный остаток:** корпусная статистика формы (38.5/40.7/12.9/7.6) в эту
классификацию не переводится — она по виду, MDL классифицирует по эффекту на
сумму. «Резать фон» как правило из неё не выводимо.

### Вывод потока 2, включая ответ про человека-читателя

Механизм — поэлементный счёт двух частей против наблюдаемой базовой линии; три
терма (цена в связывающих операндах, остаток при голом априоре, вероятность
применения p) — ни один не измеряется длиной. Класс обязан содержать H₀.
Сильнейшее сжатие — перенос ограничения в носитель, а не удаление текста.

**Человек-читатель:** элемент, сокращающий описание задачи для человека,
находится **не на стороне H, а на стороне D**. Двухчастный код определён
относительно приёмника; если продукт скила — представление, на котором владелец
учится, то в D входит понимание владельцем задачи, и порождающий текст — **канал
доставки D**, не фон в L(H).

Точный диагноз встречного случая: критерий «оставить только действующие правила»
проваливается не потому, что MDL не работает, а потому что **в нём неверно
указан D**. Ошибка совершается до первого удаления, в определении данных.

Два следствия: счёт становится двухведомственным (`L(H) + L(D_агент|H) +
L(D_человек|H)`, коды не общие), и **«информация = сюрприз» — величина
относительно приёмника; два приёмника расходятся по ней систематически**.
Сжатие по априору агента разрушает человеко-адресованную ценность закономерно,
а не случайно. Сжимать можно генератор, но не полезную нагрузку: MDL — рамка без
потерь.

Названная граница метода: человек, читая, **учится**, его априор растёт —
нестационарного приёмника crude two-part code не моделирует.

**Crude vs refined.** Crude — рабочая рамка: произвольность L(H) здесь не помеха,
а предмет решения. Refined нужен в одном месте: класс B огромен (2^86), и
двухчастный код на классе такого размера **переобучается**. 14% регрессий по
профилю похожи на это. Практический вывод: поэлементная цена — crude; отбор
победившего подмножества обязан нести штраф за размер перебранного класса.

## Поток 3 — FMEA

**Framework:** FMEA с явными осями Severity / Occurrence / Detection. **Цель:**
найти отказы, которые операция вносит незаметно, и упорядочить по обнаружимости.
**Topology:** linear.

**Spine:** S1 границы и функции → S2 режимы отказа → S3 последствия и S →
S4 причины и O → S5 контроли и D → S6 приоритет → S7 действия и переоценка.

**Оговорка потока:** последовательность совпадает со структурой FMEA по практике
(MIL-STD-1629A → AIAG/VDA), в поздней редакции RPN заменён таблицей Action
Priority; источник не проверялся, spine не назван каноническим, **все шкалы —
собственные, не отраслевой стандарт**. Occurrence переопределён как доля актов
сжатия, в которых режим реализуется.

### S1 Функции фрагмента

Различение формы и функции: корпусная разбивка — таксономия **формы**, а
критерий «оставить действующие правила» применяется как таксономия **функции**.
Что это не одно и то же, доказано изнутри пакета: фрагмент формы «пример» нёс
функцию «задавать поведение», иначе его удаление не давало бы регрессию.

| ID | Функция | Проявление |
|---|---|---|
| Fn1 | быть найденным и загруженным | скил срабатывает |
| Fn2 | ограничить действие в момент действия | продукт отличается от продукта без фрагмента |
| Fn3 | потребовать проверяемый артефакт | соблюдение предъявимо и потому реально |
| Fn4 | задать спецификацию показом | поведение в случае, описанном только примером |
| Fn5 | ограничить область | число одновременных правил остаётся низким |
| Fn6 | породить видимую форму ответа | владелец видит пошаговый разбор |
| Fn7 | изменить понимание читателя | владелец после чтения понимает задачу лучше |

Fn6 и Fn7 обслуживают человека и потому невидимы для любого критерия вида
«оставить действующие правила».

Шкала собственная: 9–10 бьёт по способности владельца решать либо портит

**Причинная связь, разворачивающая интуицию:** правило без артефакта соблюдается

### S4 Occurrence

Опорный базовый уровень: 14.0% ухудшились, около трети из них — настоящая
потеря → **≈5% актов сжатия с реальной регрессией** по тому, что бенчмарк умел

FM-R1 = 9 (инертной прозы больше всего, она первая под нож) · FM-V2 = 7 (скелет
читается как шаблон и сохраняется, вещество читается как фон и режется — 40.7%
против 7.6%) · FM-P1 = 7 · FM-V1 = 7 · FM-A1 = 6 · FM-E1 = 6 · FM-R2 = 6 ·
FM-T1 = 5 · FM-S1 = 5 · FM-T2 = 4.

**Проба на инвертированном ожидании:** проверено, не защищает ли форма фрагмента
его функцию. Оказалось наоборот — чем важнее функция для человека, тем сильнее
её носитель похож на фон. Частота растёт вместе с тяжестью. Сценарий не «редкий
и страшный», а «частый и страшный».

### S5 Detection

Инвентарь реальных контролей: К1 агент перечитывает и судит · К2 самоотчёт
агента · К3 владелец читает результат · К4 откат из git.

К1 и К2 обнуляются данными: верность 25–39%, самоотчёт — «наименее надёжный
артефакт траектории», эксперты при kappa 0.130. **Если эксперт-человек не
отличает, агент-автор сжатия тем более не отличает свою же работу.** К4 — не
обнаружение, а смягчение. Остаётся К3, смотрящий только на Fn6 и с задержкой.

FM-V2 = **10** (форма на месте, K3 подтверждает «выглядит правильно», сигнал —
угасание пользы без момента) · FM-A1 = 9 · FM-S1 = 9 · FM-P1 = 9 · FM-E1 = 8 ·
FM-R2 = 8 · FM-R1 = 8 · FM-T1 = 7 · FM-T2 = 6 · **FM-V1 = 4**.

**Разведение встречного случая на две половины по обнаружимости:** громкая
(форма исчезла) — самая обнаружимая позиция реестра, D=4. Тихая (форма осталась
пустой) — единственная D=10. **Владелец сформулировал опасение как «скил
перестанет писать в чат»; ось Detection говорит, что именно этот вариант почти
безопасен, а опасен тот, о котором он не спрашивал.**

Потолок: никакой контроль, основанный на чтении текста, не опускается ниже D≈8.

## Поток 4 — Cognitive Apprenticeship

**Framework:** Cognitive Apprenticeship (Collins, Brown & Newman, 1989). **Цель:**
сделать скрытый экспертный процесс наблюдаемым и постепенно передать исполнение.
**Topology:** заданная линейная, с оговорками ниже.

**Spine:** S1 Modeling → S2 Coaching → S3 Scaffolding → S4 Articulation →
S5 Reflection → S6 Exploration.

**Оговорки потока:** состав шести методов — канон по памяти, не проверенная
цитата. **Строгая линейность — не канон:** авторы группируют методы в три
кластера, а sequencing у них отдельное измерение фреймворка наряду с content и
sociology; порядок пройден как заданный, линейность помечена как форма подачи.
**Fading — сквозной принцип, а не отдельный шаг:** в источнике он идёт связкой
«scaffolding and fading», разобран дважды — как критерий снятия в S3 и как телос
в S6.

**Mapping — главный структурный факт: два вложенных отношения «мастер — ученик»
внутри одного файла.**

| | R1 (внутреннее) | R2 (внешнее) |
|---|---|---|
| Мастер | текст скила (написан человеком) | агент, исполняющий скил |
| Ученик | агент | владелец |
| Скрытый процесс | как делать работу правильно | как разобрать собственную задачу |
| Артефакт обучения | выход агента | текст в чате |
| Свойство ученика | следует правилам, примеры игнорирует | правилам не следует вовсе, только читает |

### S1 Modeling

| Что это | Отношение | Куда попадает при подсчёте 38.5% |
|---|---|---|
| пример с показанным ходом мысли | R1 | bucket «примеры», 12.9% — «не правило» |
| спецификация того, что обязано стать видимым | R2 | частью «правила», частью «фон» (40.7%) и «шаблоны» (7.6%) |

**Ни один из двух материалов modeling не лежит целиком в 38.5% действующих
правил.** Скил из разобранного примера несёт только R1 — у него нет
ученика-человека. Первое место, где критерий «оставить только действующие
правила» становится не нейтральным сокращением, а выбором стороны.

### S2 Coaching

Причинная связь вместо корреляции: канонический coaching требует, чтобы
исполнение ученика было **наблюдаемо** — без этого обратная связь физически
невозможна. Правило без артефакта оставляет исполнение ненаблюдаемым. **0–4% —
не слабая формулировка, а отсутствие петли: мастер сформулирован, но не
смотрит.** Артефакт замыкает петлю → 97%.

Coaching-материал — самый сжимаемый в R1: полностью выражается парой «правило +
артефакт», и такое сжатие усиливает, потому что освобождает бюджет.

В R2 coaching структурно слаб: пакет не сообщает, наблюдает ли агент ответ
владельца и корректирует ли по нему разбор. Gap, не превращаю в факт.

### S3 Scaffolding

Канонический критерий «поддержка ровно там, где ученик не справляется» как
фильтр даёт цепь:

> операнд, выводимый из требований к выходу → поддержка в точке, где ученик
> справляется сам → всё равно занимает слот бюджета → соблюдение несущих правил
> падает с 96% к 20–60%.

**Переоценка: удаление 4/5 операндов — не косметика, а восстановление
работоспособности оставшейся пятой части.** Избыточный скаффолдинг в CA — не
безобидная забота, а поражение обучения; статистика даёт этому механизм.

Различающая проба: операнд есть поддержка в точке компетентности, если прогон с
ним и без него на его же точке даёт одно поведение.

**Fading, первая половина ответа:** у ученика-модели fading **не продольный** —
модель не набирает компетентность от повторного чтения файла. Он относительный:
поддержка снимается против дефолтов текущей модели. Значит «сколько скаффолдинга
нужно» — свойство пары (файл, модель), пересматриваемое при смене модели.
Косвенное подтверждение: примеры хода мысли когда-то помогали точности, теперь
игнорируются — дефолты ученика сдвинулись, часть исторической поддержки стала
мёртвым грузом сама собой.

CA-критерий и критерий «только действующие правила» **расходятся в обе стороны**:
CA режет глубже (часть формально действующих правил — поддержка в точке
компетентности) и одновременно защищает часть «фона» и «примеров».

### S4 Articulation

| | Вопрос-input | Вопрос-articulation |
|---|---|---|
| Кому нужен ответ | агенту, чтобы продолжить | владельцу, чтобы сформулировать нечёткое |
| Проверка | владелец ответил бы и без предшествующего текста | ответ возможен только после прочитанного пересказа |
| Как сжимается | в список полей, без потери | **в список тем не сжимается** |

Несущее свойство вопроса-articulation — что на него **нельзя ответить готовым**.
Это свойство формулировки, не темы. Нормализация «задай вопросы про цель,
ограничения, аппетит» сохраняет норму и уничтожает функцию.

**Количество вопросов режется свободно, формулировка — нет.**

### S5 Reflection

Исполнение ученика здесь — **внутренняя нечёткая формулировка задачи самим
владельцем**; исполнение мастера — пересказ своими словами. Пересказ не сообщает
нового знания, он даёт объект, рядом с которым владелец впервые видит
собственную формулировку.

**Обучающий эффект несёт расхождение между двумя формулировками, а не точность
второй.** Два следствия против интуиции:

1. Сжатие пересказа до «только уверенного и подтверждённого» уменьшает
   поверхность расхождения и ослабляет эффект сильнее, чем сокращение длины.
   Признание дефолтов и развилок выглядит как фон, а функционально это и есть
   поверхность сравнения.
2. **Граница показа.** Факт 25–39% означает: modeling учит показанному, а не
   выполненному. Если сжатие превратит «сделай X и покажи X» в «покажи X», R2
   формально уцелеет, а R1 исчезнет — владелец начнёт учиться процессу, которого
   агент не исполняет. **Не ловится проверкой «сохранены ли действующие
   правила»**, потому что правило показа при этом сохранено.

Gap сужен до проверяемой пробы: измерять стоит не «что понравилось», а **где
владелец правит пересказ** — место правки = место расхождения = место обучения.

### S6 Exploration и fading

Развилка телоса, обе ветки удержаны: **A** — автономия (канонический для CA),
fading уместен, объём показа убывает; **B** — постоянное делегирование, обучение
как побочный эффект, fading вреден.

Различающий признак: ученик учится **не предмету, а собственной текущей задаче**,
и задача каждый раз новая. Компетентность «понимать свою задачу вообще»
накапливается гораздо медленнее, чем навык в ремесле.

Вывод, не зависящий от ветки: **fading в R2 применим к мета-слою** (объяснение
жанра, зачем этот вопрос, что такое дефолт) **и не применим к исполнению на
новом материале**. Сжимается объяснение метода, не сжимается его исполнение.

**Главный риск задуманного скила:** объём файла и объём видимого выхода — **два
разных бюджета, направленных в противоположные стороны**. Файл может быть
коротким, выход обязан быть развёрнутым. Компрессор, обученный на «режь фон и
шаблоны», будет резать файл — но мандат на развёрнутость выхода живёт как раз в
bucket'ах «фон» и «шаблоны». Сжимая файл, он с высокой вероятностью **сожмёт
предписанный выход, не заметив**, потому что по его метрике доля действующих
правил вырастет.

Отсюда форма ответа на неизвестность: вопрос «сколько текста скила нужно для
порождения представления» поставлен неверно — связи «короче файл → короче показ»
быть не должно, и её появление есть симптом дефекта компрессии, а не её успех.

### Вывод потока 4

**Признак, различающий два класса текстов — назови ученика скила.** Единственный
ученик агент → текст компилируется в правила с обязательным артефактом. Есть
второй ученик-человек → часть текста является **партитурой показа**, адресованной
не исполнителю.

Операциональная проверка: замени весь видимый выход сжатым вердиктом. Владелец
теряет способность сделать следующий шаг сам → текст был партитурой показа.
Короткий маркер: **скил меняет состояние работы или состояние человека?**

**Что нельзя сжимать по критерию «оставить только действующие правила»:**

1. Состав и порядок показанных ходов — порядок несёт причинность, перечень тем
   ему не эквивалентен.
2. Требование исполнять на материале конкретной задачи владельца.
3. Предъявление неуверенного и дефолтного — поверхность расхождения.
4. Формулировку сильных вопросов (не их число).
5. Пример, который является спецификацией — вынос его есть удаление мастера из
   комнаты.
6. Сцепку «сделай X и покажи X».

**Шкала сжимаемости по методам CA:**

| Метод | Сжимаемость | Почему |
|---|---|---|
| Coaching | высокая | выражается парой «правило + артефакт»; сжатие усиливает |
| Scaffolding | высокая, условная | режется по «ученик и так справляется»; зависит от модели |
| Exploration / мета-объяснения | высокая | fadeable по определению |
| Articulation | средняя | число режется, формулировка нет |
| Reflection | низкая | нужен объект сравнения |
| **Modeling** | **самая низкая** | должен быть исполнен, а не описан |

**Два режима, невидимых метрике «доля действующих правил»:** театр (показ
оторвался от исполнения, доля правил растёт, R1 исчезает) и слипание бюджетов
(компрессор режет файл и вместе с ним предписанный выход, метрика улучшается).

**Риск самого компрессора:** modeling требует мастера, действительно держащего
скрытый процесс; модельно-сгенерированный файл воспроизводит поверхностную форму
без исполненной экспертизы, и компрессор по построению двигает файл в этот
класс. Узкое смягчение: **modeling-материал сохранять дословно, а не
перефразировать** — перефраз это ровно место, где мастерство утекает.

## Что осталось нерешённым во всех четырёх

- Абляция «выводит ли модель выводимые операнды сама» не проводилась; вся идея
  вывода из контракта выхода остаётся суждением.
- Датчика обучающей функции не существует; лучшая заготовка — проба потока 4
  «место, где владелец правит пересказ».
- Телос (автономия против постоянного делегирования) — вопрос владельца, и он
  решает, применим ли fading вообще.
