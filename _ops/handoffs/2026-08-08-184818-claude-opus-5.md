# Хендоф — кампания мета-скилов

## Где мы сейчас

За одну сессию перестроено ядро системы скилов. Создано/переформировано
шесть, все через цикл `1skill-shaping` (интервью → триада → допуск → черновик
в чате → аудит → «да» владельца → запись):

- `1skill-shaping` (заменил `1skill-architect`) — создание скилов через
  интервью владельца;
- `1instruction-shaping` (заменил `1instruction-layer`) — agent harness: шов
  пяти слоёв корень·папка·скил·хук·план; сжатие разросшихся текстов — его
  режим 3;
- `1index` — записи только как оплаченные поиском маршруты;
- `1goal` — GOAL как верхнеуровневый контекст, «выше просьб владельца»;
- `1planning` — план = инструкция с триадой, происхождением требований и
  пунктом GOAL; поглотил `1break-down`;
- `1use-principles` — новый: двухпроходная матрица принципов перед чистовой
  записью.

Сняты и заархивированы: `1skill-architect`, `1instruction-layer`,
`1break-down`, `1lossy-product-refactor` — каждый в `skills/<имя>/` с
live/tracked снапшотами.

**Ни один скил не проверен поведением.** Все — candidate (lifecycle в
`evidence.md` каждого). Это главный долг.

## Происхождение задачи — без этого дух теряется

Владелец начал с противоречия двух школ: «распиши когнитивные шаги —
стабильнее» против «задай цель и критерии — не программируй маршрут». Из
первой школы у него выросли скилы в десятки тысяч строк процедур. Его ответ —
третий слой: **не программировать маршрут мышления, программировать условия
правильного мышления и наблюдаемые критерии результата**. Вся кампания —
материализация этого вывода.

Телос (его словами, полные цитаты в chat-recall): любая инструкция = триада
«что я хочу · что считать выполненным · что целью не является»; хорошая
инструкция — «вектор + бортики, чтобы мне не приходилось работать вместо
агента, бесконечно его поправляя». Корневая боль: «агенты не получают
достаточно контекста, либо неправильно понимают мои задачи».

## Что владельцу нравится / не нравится — рабочий дух

**Хочет:** сначала разговор, черновик в чате, файлы только после его «да» —
«ну вот по сути, как мы сейчас с тобой работаем» · цель вместо процедур для
сильных моделей 2026 · стереотипы модели во благо (жанровые словари) · цель
короткая и обширная, подробности в принципах · принципы закрывают развилки
автономно · находки показывать с ценой, не чинить молча · основания из
исследований последних полугода · телеграфный плотный текст.

**Не хочет:** реактивные инструкции «от поведения, которое не нравится» (сам
назвал своей старой ошибкой) · знание в инструкциях (знание → файлы/INDEX) ·
списки буквальных триггер-фраз в description («мы никогда не угадаем, как я
вызову в моменте») · расплывчатые слова без стоп-условий · пустые ритуальные
разделы · агентские догадки, выданные за его волю.

## Ключевой механизм дня: допуск к черновику

Живой провал: черновик `1use-principles` написан до разбора дефолтов; разбор
по требованию владельца радикально переписал механику; аудит структурно не мог
поймать («у отсутствующего анализа нет строки для цитаты»). Лечение выбрали
три семьи независимо (Claude + Kimi k3 max + Codex xhigh, советники вслепую):
обязательный шаг механики ДО черновика — цепочка «естественный ход модели →
рабочий ход человека с основанием → различие, меняющее механику»; нет
различия — скила нет. Внесено в оба мета-скила. Риск назван: «правдоподобный
театр трёх стрелок».

### Инцидент: черновик до разбора дефолтов

- **до:** черновик `1use-principles` собран сразу после триады и показан
  владельцу;
- **trigger:** владелец потребовал «подумай, какой дефолт сделает этот скилл
  не настолько полезным» — разбор дал 7 жёстких шагов вместо мягкого порядка;
- **цена:** полная пересборка механики скила; один лишний цикл
  черновик-обсуждение;
- **почему поздно:** шага не существовало в механике — непронумерованное
  модель читает как необязательное; аудит проверяет написанное;
- **предотвращение:** шаг 6 «Допуск к черновику» в `1skill-shaping` + третий
  жёсткий переход в `1instruction-shaping` (внесено, коммит `Допуск к
  черновику…`).

## Следующий шаг

**Первые поведенческие прогоны** — самый дешёвый и самый важный: (1) тест
«Индия» для `1use-principles` — два principles-файла разных тем,
переворачивающий принцип без словарного пересечения с задачей; смотреть,
находит ли свип по осям и появляется ли след без подсказки; (2) cold-start
`1planning` — контракт по новой схеме, чужой агент продолжает по файлу.
Причина: шесть кандидатов установлены глобально как правда — единственное, что
их отличает от текста, это прогон.

После: строка-обязанность в корневой `CLAUDE.md` («скилы/инструкции/планы не
пишутся без мета-скила и „да"») — без неё дисциплина держится на памяти
сессий; затем переформирование `1product-shaping` (накоплены сигналы: осевые
заголовки принципов, over-форма «X важнее Y», учёт цели).
