## Решения и почему

### Апгрейд SDK отложен сознательно

`api.py` между 0.1.0b3 и 0.144.4 **побайтово идентичен**. Апгрейд закрывает одну
регрессию и не даёт ни одной из трёх нужных владельцу способностей. Отвергнуто:
делать его первым просто потому, что он был первым в моём плане.

### Остаёмся на бинаре ChatGPT.app, не на бандле SDK

Три аргумента: enum-шим нужен в любом случае (дрейф живой); каталог моделей
пишет именно этот движок; `default_subagent_model` есть в нём и отсутствует в
бандле. Плюс замер: старый бандл не читает текущий `auth.json`
(`invalid type: map, expected a string` на `agent_identity`), потому что оба
бинаря делят один `~/.codex`. **Пиннинг бандла не даёт воспроизводимости.**

### `codex_sdk_compat.py` НЕ удалять

В 0.144.4 открыты **2 enum-класса из 104**. Мой собственный докстринг врал
(«новые SDK решили это сами»), и на него опёрся Codex-ревьюер, рекомендовавший
удаление. Дрейф наблюдается живьём.

### Прогресс через tee потока, а не своя телеметрия

`TurnResult` собирает штатный сборщик SDK, приёмка не меняется. Отвергнуто:
переписать сборку самим.

### Прогресс скрыт по умолчанию

Решение владельца. Stdout не растёт; сводка по требованию. Отвергнуто:
периодические строки прогресса.

### Monitor не используется для ожидания

По его же документации: для одного уведомления — фоновый Bash. Каждая строка
Monitor — сообщение в контексте агента.

### Фон — умолчание для любого оплаченного turn

Было «фон для долгих» — слово «долгих» и создало дыру.

### `codex_orchestrate_state.py` разделён

→ `codex_run_ledger.py` + `codex_git_scope.py`. Имя врало. Конверт трёх входов
**намеренно не трогал**.

### Три яруса вызова

Решение владельца. Дефолт `medium`. Тяжёлый ярус на пути ревьюера сам заводит
персистентный тред.

### `max` возвращён в шкалу

По каталогу движка `max` = максимальная глубина, `ultra` = та же глубина **плюс
делегация**. Между `xhigh` и `ultra` была дыра.

### Описание скила — на состояние агента

Решение владельца. 896 → 407 символов, при этом **шире** по охвату.

### Из чужого плагина взято четыре вещи, брокер отвергнут

Взято: preflight, нативный `review/start`, `turn/interrupt`, `thread/name/set`.
Отвергнут брокер: он single-flight, у нас SDK маршрутизирует по turn-у.

### `--mode diff` не врёт про effort

## Что я понял, чего нет в файлах

### Возможности были у нас всё время

`output_schema`, типизированный стрим, `thread_list/resume/fork`,
`sandbox_policy.writable_roots`, `SkillInput` — всё в **запиненном** SDK.
Проблема была не в версии, а в том, что мы не пользовались тем, что держим.

### `~/.codex` — общий мутирующий стейт, а не наш конфиг

Auth, конфиг и кэш моделей пишет автообновляемый ChatGPT.app. Отсюда: старый
бандл ломается на новом `auth.json`; `service_tier` может измениться без нас.
`--doctor` существует, чтобы это увидеть.

### `models_cache.json` — бесплатный авторитетный каталог

`~/.codex/models_cache.json` → `supported_reasoning_levels` с описаниями от
самого движка. Мы полгода сочиняли шкалу усилий вместо того, чтобы прочитать.

### Codex может позвать обратно в Claude и повиснуть навсегда

Замер: 9 часов, `last=mcpToolCall claude-mcp/claude_ask`, `steps` замерли. На
уровне моста не блокируется.

### Постфлайт не отличает мои правки от правок субагента

Создал файл в проекте, пока работал исследователь, — `scope_status=failed`.
Детектор прав, но параллельная работа оркестратора для него неотличима от
нарушения контракта.

### Interrupt гарантирует меньше, чем кажется

Ловит осознанный SIGTERM нашему процессу. Не покрывает таймаут, убивающий
движок раньше нас, и зависший MCP-вызов.

### Мой неверный комментарий породил неверную рекомендацию ревьюера

Докстринг в `codex_sdk_compat.py` → Codex-ревьюер рекомендовал удалить модуль.
Неверный комментарий не лежит мёртвым грузом, он **командует** следующим
читателем, включая машинного.

## Где проект сбил мою рамку

### README как источник правды о внешнем мире

Собирался: процитировать README про «SDK не знает модель». На деле: устарело на
полтора месяца. Перекос: **контекст молчал — дефолтнул** на ближайший
письменный источник. Чинить: в `AGENTS.md` моста уже есть «живой SKILL.md
сильнее старых repo notes», но нет «внешний факт проверяй у источника, не у
своего README». Кандидат в `1instruction-layer`.

### «Долгие прогоны — фоном» читалось как «только долгие»

Собирался: гонять короткие вызовы в форграунде. На деле: любой оплаченный turn
может занять минуты. Перекос: **инструкция указала не туда** — квалификатор
«долгие» дал лазейку. Чинить: правило без квалификатора. Уже исправлено, но
класс ошибки шире: любое «делай X для больших Y» читается как «для малых можно
не делать».

### Имя `codex_orchestrate_state.py` увело от общего владельца

Собирался: искать журнал прогона там, где он логически должен быть. На деле:
лежал в модуле с именем про оркестратор. Перекос: **имя врёт**. Уже исправлено
разделением.

### `--mode review` — имя коллидирует с нативным режимом движка

Наш `--mode review` — обёртка над транскриптом. У движка `review/start` — совсем
другое. Перекос: **имя врёт**, причём наружу. Не исправлено: переименование
сломало бы скил и мышечную память. Записано как долг.

Просил склонировать GitHub-репо — `git clone` не прошёл, DNS к `github.com`

### Codex-исследователь: 53 теста упали из-за read-only песочницы

При проверке нашей работы он попытался прогнать наш suite — 53 environmental
error на временных каталогах. Честно пометил. **Вывод: Codex не может
подтвердить наш зелёный прогон тестов, только прочитать код.**

### Мой bash-таймаут в 10 минут убил форграундный прогон

Запустил нативный ревью в форграунде — харнесс убил на 600s. Interrupt не
сработал: движок умер раньше. **Вывод: форграунд — не только неудобство, но и
потеря результата.**

### `timeout` отсутствует в macOS-shell

`(eval):4: command not found: timeout`. Использовать `&` + `sleep` + `kill`.

### `md index` требует двухфазного подтверждения

`md index` на большой дельте отказывает: сперва `--dry-run`, забрать
`_envelope.lock.transaction_id`, потом `--confirm --transaction-id`. Без этого
`error: confirm_required`.

`1codex` очередь не дойдёт.
