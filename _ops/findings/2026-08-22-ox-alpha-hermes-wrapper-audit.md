## 2. Критические находки

**C1. Ответ тихо деградирует до недоказанного stdout.** scripts/hermes_advisor.py:240 — `response = evidence.final_assistant_content(metadata) or response`. Если экспортированная запись есть, но не содержит пригодного ассистентского сообщения (частичная запись, `--redact`, смена формы данных), ответом становится сырой stdout CLI — без какого-либо warning. При этом `pre_commit_ok` (:284) требует лишь непустой `metadata`, так что `ok=true` выдаётся с телом ответа, происхождение которого не доказано session store — ровно класс «ответ чужой модели за ответ запрошенной». Сценарий: export возвращает запись с пустым `messages` (или сообщения переехали в другое поле после обновления Hermes) при сработавшем fallback-chain в конфиге — метаданные сходятся, а текст в `response` может быть от другой модели. Чинить: при fallback добавлять warning и поле `response_source` (`session|stdout`), а для `ok=true` требовать session-происхождение либо явный opt-in вызывающего.

**C2. Нет верхнего страховочного обработчика — оплаченный прогон теряется без JSON.** Тело `_run` не имеет общего `try/except`, эмитящего `{"ok": false}`; ловятся только `TimeoutExpired`/`OSError` (hermes_advisor.py:197–210). Любое иное исключение после завершения платного прогона ломает контракт «JSON на stdout»: потребитель получает traceback на stderr и пустой stdout. Конкретные триггеры: (а) строка JSONL, являющаяся не объектом (массив/строка), в `_runtime_evidence.py:49–52` — `record.get` бросит `AttributeError`; (б) `\x00` в brief из stdin → `ValueError: embedded null byte` в `Popen` (scripts/_runtime_execution.py:51, вне try); (в) ошибка декодирования при `text=True` под не-UTF-8 локалью. Побочный ущерб: worktree, созданный на hermes_advisor.py:163, на этих путях не восстанавливается — в репо остаётся сирота-worktree и ветка. Чинить: обернуть `_run` целиком, любой исход исключения — терминальный JSON с `ok=false` и восстановлением worktree.

**C3. Биллинг-гейт одноразовый: сверка цены после прогона отсутствует.** Проверка бесплатности выполняется только до старта (_advisor_contract.py:93); прогон Ox по конституции идёт часами (`DEFAULT_TIMEOUT_SEC = 10800`, hermes_advisor.py:27). Пост-фактум в `usage` уже лежат `estimated_cost_usd`/`actual_cost_usd`/`cost_status` (_runtime_evidence.py:92–94) — и ни одно из них не гейтируется: смена цены между проверкой и звонком или «неизвестная» стоимость дают `ok=true` на платном прогоне. Это ровно тяжелейший класс из ТЗ («платным или неизвестной ценой»). Чинить: для `ox_requested` после чтения metadata требовать fail-closed: обе стоимости присутствуют, численно равны нулю, `cost_status` в доверенном множестве.

## 3. Существенные находки

**E1. Непиннутый провайдер на fresh-прогоне не проверяется вовсе.** `_advisor_contract.py:71` — при `--model` без `--provider` провайдер = `None`; `runtime_verdict` сравнивает только при истинном `expected` (:152), поэтому `resolved.provider` может быть любым — `ok=true` без предупреждений, хотя биллинг и «семья» зависят от провайдера. SKILL.md:225 требует совпадения `resolved.provider` с запрошенным — при `None` условие невыполнимо по построению. Чинить: предупреждать, когда запрошенный провайдер не зафиксирован, либо резолвить его до прогона через каталог.

**E2. session_id добывается регексом из всего stderr.** hermes_advisor.py:215 — берётся первое совпадение `session_id:` в MULTILINE. Любая посторонняя строка лога с таким префиксом (эхо конфига, вложенный вывод инструмента) выберет чужой существующий sessionId; дальше `read_metadata` (:237) и route-дельта (:253–255) честно докажут правильность *чужой* сессии, и `ok=true` будет подкреплён непротиворечивыми, но нерелевантными доказательствами. Чинить: требовать ровно одно совпадение (при нескольких — fail-closed) или брать последнюю строку непосредственно перед завершением.

**E3. Асимметрия route-доказательства для не-Ox resume.** _runtime_evidence.py:196–206 — ветка не-Ox учитывает только `task == ""`, игнорируя и base_url, и все auxiliary-вызовы: теневой endpoint с той же моделью/провайдером или платные побочные звонки (title generation и т.п.) не видны, тогда как Ox-ветка (:186–194) отклоняет любой оф-маршрутный дельта-вызов. Чинить: включить `billing_base_url` в критерий точности и считать auxiliary-вызовы наблюдаемыми (как минимум warning) для всех маршрутов.

**E4. ox_gate повторно парсит сырую строку toolsets.** _advisor_contract.py:86–89 заново режет `args.toolsets.split(",")` вместо использования нормализованного списка из `validate` (:31–36). Сегодня эквивалентно; любое будущее изменение нормализации (алиасы, кавычки) рассинхронизирует admission-гейт и фактическую команду — класс латентного обхода.
