# Поиск и применение записанных слов владельца

Владелец решает, как находить релевантные сессии с его записанными словами, восстанавливать применимую позицию из полного контекста и проверять полноту retrieval.

## Назначение и границы продукта

- Владелец предложил рассматривать `1chat-recall` как продукт, который должен выполнять определённую пользовательскую задачу. [2026-08-03-232246-codex-019fc8d8.md#L32]
- Владелец задал критерием проекта помощь агентам в получении полезной информации из его прошлых цитат. [2026-08-19-221010-claude-3a023b71.md#L26]
- Владелец задал критерий продукта 1chat-recall: агент должен находить нужную сессию и читать всю её историю, а не одну вырванную цитату; выдача должна возвращать список наиболее подходящих файлов для восстановления цепочки цитат одной сессии. [2026-08-19-221010-claude-3a023b71.md#L35]
- Владелец поправил границу `1chat-recall`: это скилл для поиска, чтения и записи цитат, а не для написания правил в память или инструкции. [2026-08-20-041346-claude-12da2cc9.md#L27]
- Владелец задал критерий продукта: глобальный скилл должен находить цитаты в любом проекте. [2026-08-20-041346-claude-12da2cc9.md#L33]
- Владелец задал, что `1chat-recall` ищет, читает и записывает прошлые цитаты, которые не являются отражением мира и не образуют полную хронологию событий. [2026-08-20-041346-claude-12da2cc9.md#L35]
- Владелец уточнил, что в эксперименте 1chat-recall проверяется механизм поиска цитат, а не скилл целиком. [2026-08-11-163847-codex-019ff09d.md#L22]
- Владелец требует, чтобы работа по поиску цитат приводила к конкретному улучшению механизма, а не останавливалась на дизайне различающего эксперимента. [2026-08-11-163847-codex-019ff09d.md#L23]

## Хранилище, единица сессии и поисковый контекст

- Владелец предложил поискать исследование о том, будет ли агенту удобнее один большой файл базы данных с поиском своими инструментами вместо множества Markdown-файлов, сравнив варианты по экономии токенов, скорости работы, желанию агентов пользоваться ими и качеству получаемых знаний. [2026-07-30-131247-codex-019fb215.md#L15]
- Владелец предложил добавить в запись ещё одно поле `контекст`. [2026-08-03-232246-codex-019fc8d8.md#L24]
- Владелец задал критерий, что цитата, вырванная из контекста, иногда может быть непонятной. [2026-08-03-232246-codex-019fc8d8.md#L25]
- Владелец уточнил правило для `context-note`: контекст должен существовать по умолчанию как дельта-сюрприз, которую нельзя вывести из цитаты, не повторять очевидное и быть вынесенным выше, чтобы агент не пропускал этот факт. [2026-08-03-232246-codex-019fc8d8.md#L29, 2026-08-03-232246-codex-019fc8d8.md#L30, 2026-08-03-232246-codex-019fc8d8.md#L31]
- Владелец решил, что у каждого файла цитат должна быть одна короткая постоянно актуализируемая поисковая карточка сессии, которая помогает найти нужный разговор, не заменяет цитаты, не пересказывает решения и не является правдой владельца. [2026-08-14-124028-codex-019fff2e.md#L20]
- Владелец решил хранить `session-context` отдельным полем `session_context` в JSON и `--show`, а карточку индексировать отдельным маршрутом, не смешивая её с embeddings цитат. [2026-08-14-124028-codex-019fff2e.md#L26]
- Владелец поправил методику backfill `session-context`: для Codex holder-ов карточку следует выводить из полной rollout-сессии, а не только из сохранённых quote-records. [2026-08-14-124028-codex-019fff2e.md#L22]
- Владелец решил вручную обновить реальные файлы цитат и их метаданные, чтобы предметно тестировать поиск на живом архиве. [2026-08-14-124028-codex-019fff2e.md#L21]
- Владелец решил использовать Luna для фонового чтения полного массива Codex rollout sessions при backfill `session-context`. [2026-08-14-124028-codex-019fff2e.md#L23]
- Владелец решил ускорить backfill `session-context`, разрешив каждому из четырёх Luna background threads запускать внутренних same-thread subagents и самостоятельно сводить evidence. [2026-08-14-124028-codex-019fff2e.md#L24]
- Владелец поправил назначение `context-note`: он должен улучшать поиск, называя предметы своими именами, даже если сам владелец формулирует цитату неточно. [2026-08-20-041346-claude-12da2cc9.md#L25]
- Владелец поправил, что русский перевод допустим только для поля `session-context` в метаданных существующих chat-recall holder-ов, если он улучшает русскоязычный поиск, а не для всего текста или owner quotes. [2026-08-14-124028-codex-019fff2e.md#L34, 2026-08-14-124028-codex-019fff2e.md#L34]

## Поисковые маршруты и формулировка запроса

- Владелец решил добавить в корневую инструкцию очень короткую инструкцию с терминальной командой для вызова воспоминаний о прежних словах владельца и поиска по имбеддингам, сформулированную так, чтобы агент захотел ею пользоваться. [2026-08-01-172241-codex-019fbd46.md#L15]
- Владелец задал критерий для развития поиска нужных цитат: рассматривать более продвинутые и эффективные локальные технологии, свежие и лёгкие на текущий момент. [2026-08-03-232246-codex-019fc8d8.md#L22]
- Владелец решил после проверки перевести local hybrid-поиск chat recall из экспериментального статуса в полноценный дефолт. [2026-08-03-232246-codex-019fc8d8.md#L23]
- Владелец поправил `1chat-recall`, указав, что правильные `type` и `topic` существенно помогают поиску и должны быть описаны в основном теле скила. [2026-08-08-195321-codex-019fe1dd.md#L25]
- Владелец поправил `1chat-recall`, потребовав дать в основном теле несколько советов по использованию `chat_digest.py`, чтобы агент всегда применял этот скрипт. [2026-08-08-195321-codex-019fe1dd.md#L26]
- Владелец поправил известный сбой retrieval: агент должен пробовать разные способы, чтобы подтвердить отсутствие темы в цитатах владельца, а не ограничиваться однотипными запросами. [2026-08-08-195321-codex-019fe1dd.md#L28]
- Владелец задал критерий retrieval: искать качественно, меняя формулировки и маршруты поиска. [2026-08-08-195321-codex-019fe1dd.md#L29]
- Владелец задал критерий для поиска цитат: он должен быть лёгким и быстрым и превосходить стандартный агентный поиск; улучшение не обязано быть многократным. [2026-08-11-163847-codex-019ff09d.md#L24, 2026-08-11-163847-codex-019ff09d.md#L25, 2026-08-11-163847-codex-019ff09d.md#L27]
- Владелец уточнил роль INDEX.md в benchmark: файл показывает, что лежит в проекте, а искать evidence нужно в папке _ops/chat-recall. [2026-08-11-163847-codex-019ff09d.md#L26]
- Владелец решил опробовать поиск без скрипта: агент использует стандартные инструменты и явные стратегии по topics и types, потому что такой подход может оказаться сильнее скрипта. [2026-08-11-163847-codex-019ff09d.md#L29]
- Владелец потребовал сделать topics и types видимыми агенту как часть урока эффективного и быстрого поиска. [2026-08-11-163847-codex-019ff09d.md#L31]
- Владелец сообщил, что в русскоязычной речи называет глобальный `1chat-recall` скиллом цитат или скиллом воспоминаний, поэтому поиск только по официальному английскому названию не находит нужные записи. [2026-08-13-120315-claude-8e9d58e3.md#L18]
- Владелец предложил для `1chat-recall` гибридный поиск: искать ключевые слова и синонимы, находить лучшие файлы-кандидаты и только затем передавать их `gpt-5.6-luna` через `codex_recall.py` на сжатие; короткие пересказы он считает снижающими качество, потому что формулировки теряют смысл. [2026-08-13-120315-claude-8e9d58e3.md#L20]
- Владелец решил для поиска по `1md-graph` строить запрос по предмету скила, а не по его имени: вместо слова граф нужно искать markdown-ссылки как проявление работы со связями. [2026-08-13-120315-claude-8e9d58e3.md#L22]
- Владелец решил, что `records` ranking ищет по цитатам и `context-note`, а BM25 с dense rerank схлопывает выдачу до одного кандидата на файл. [2026-08-14-124028-codex-019fff2e.md#L26]
- Владелец решил, что при отсутствии существенного термина в `record-index` совпавшие карточки идут отдельным top-5 `session_candidates`, не меняя порядок `records`, а при пустом `records` служат fallback. [2026-08-14-124028-codex-019fff2e.md#L26]
- Владелец решил, что card-only fallback с `--timeline` возвращает все записи найденных файлов, а file-level карточка и rank только выбирают файл для полного чтения и не доказывают позицию владельца. [2026-08-14-124028-codex-019fff2e.md#L26, 2026-08-14-124028-codex-019fff2e.md#L35]
- Владелец решил, что `--json` отдаёт `address` для record-кандидатов и `session_candidates` для file-level маршрутов, а без подготовленной модели `--lexical` сохраняет два раздельных lexical-маршрута. [2026-08-14-124028-codex-019fff2e.md#L26]
- Владелец решил включить в acceptance проверку, при которой существенный термин отсутствует в цитатах и `context-note`, но есть только в `session-context`, а default JSON показывает нужный файл в top-5 `session_candidates`, не меняя порядок `records`. [2026-08-14-124028-codex-019fff2e.md#L26]
- Владелец поправил, что находимость англоязычного `session-context` зависит от формулировки запроса и использования поискового скрипта, а не только от языка карточки. [2026-08-14-124028-codex-019fff2e.md#L28]
- Владелец решил, что первый запрос к цитатам формулируется естественно для BM25+E5, повторяется не более одного раза и использует три-четыре отдельных wildcard-корня. [2026-08-14-124028-codex-019fff2e.md#L35]
- Владелец решил оставить `session-context` отдельным BM25 file-route с прежним novel-term gate либо минимум двумя совпавшими корнями; карточка не входит в `records`, E5 её не ранжирует, а card-only records пусты кроме timeline. [2026-08-14-124028-codex-019fff2e.md#L35]
- Владелец предложил убрать из `chat_digest` выдачу текстов отдельных цитат в `records`, считая такой функционал вредным. [2026-08-18-133335-claude-d89e3d9a.md#L19]
- Владелец решил объединить несколько `--query` в одну карту сессий и добавить рабочий режим `--support`, который отвечает по адресу опоры или сообщает, что опоры в корпусе нет. [2026-08-20-041346-claude-12da2cc9.md#L26]

## Ранжирование и выдача

- Владелец решил, что запрос 1chat-recall сначала должен показывать top 10 файлов с полным session-context, а рейтинг должен быть сбалансированным по сходству запроса с session-context и цитатами, без буквального фиксированного веса 50-50. [2026-08-19-135233-codex-01a01922.md#L21, 2026-08-19-135233-codex-01a01922.md#L22, 2026-08-19-135233-codex-01a01922.md#L26]
- Владелец задал критерий сохранения выдачи: нужно не терять список top 10 с описанием давности вроде `два дня назад`, а также сведения о количестве типов и тем. [2026-08-19-135233-codex-01a01922.md#L23, 2026-08-19-135233-codex-01a01922.md#L24, 2026-08-20-041346-claude-12da2cc9.md#L28]
- Владелец предположил, что длинная сессия может быть полезной, если в ней много полезного содержания. [2026-08-19-135233-codex-01a01922.md#L25]
- Владелец решил, что 1chat-recall должен подсказывать читать три-четыре релевантные сессии, отдавая приоритет самым свежим среди релевантных и пропуская явно нерелевантные. [2026-08-19-135233-codex-01a01922.md#L28, 2026-08-19-135233-codex-01a01922.md#L29]

## Полное чтение, хронология и доказательство позиции

- Владелец предложил вместо передачи recall другому агенту рассмотреть буквальное чтение агентом сохранённых цитат владельца в их записанном виде через стандартные инструменты, даже ценой расхода контекстного окна. [2026-08-12-170654-claude-4bc752e5.md#L15]
- Владелец предложил использовать файл как единицу сессии: сначала находить нужную сессию, затем читать весь файл целиком. [2026-08-13-120315-claude-8e9d58e3.md#L19]
- Владелец решил, что файлы цитат нужно читать целиком и учитывать хронологию цитат внутри сессии, поскольку более поздняя реплика может вытеснить более раннее решение. [2026-08-13-120315-claude-8e9d58e3.md#L21]
- Владелец решил, что любой hit только выбирает holder, который нужно прочитать от первой до последней строки, после чего проверить более новые holder-ы по тому же claim. [2026-08-14-124028-codex-019fff2e.md#L35]
- Владелец задал критерий читать holder-файлы `_ops/chat-recall` целиком, потому что полный файл даёт больше контекста и понимания владельца. [2026-08-18-133335-claude-d89e3d9a.md#L18]
- Владелец задал критерий: `1chat-recall` нужно применять на протяжении всей работы, а не только в начале. [2026-08-13-120315-claude-8e9d58e3.md#L23]
- Владелец запретил записывать непроверенные claims: наличие metadata-стратегии нельзя считать доказательством её использования или вклада без tool-trace. [2026-08-11-163847-codex-019ff09d.md#L32]

## Субагенты и полнота coverage

- Владелец решил кратко указать в `1chat-recall` важность множества дешёвых субагентов для качественного восстановления прошлых цитат, оставив Claude- и Codex-агентам понимание конкретных путей вызова. [2026-08-20-181330-claude-a7539038.md#L20]
- Владелец задал критерий надёжности: множество дешёвых субагентов, каждый читающий примерно 20–30 файлов, оправдано большим расходом токенов, потому что система поиска и её embeddings несовершенны и только такой веер позволяет убедиться, что найдено всё необходимое. [2026-08-20-181330-claude-a7539038.md#L21]
- Владелец поправил способ проверки этой идеи: нужно измерить, улучшает ли она качество поиска, сравнив baseline и веер субагентов на gold-фикстуре, а не проводить простую фактологическую сверку. [2026-08-20-181330-claude-a7539038.md#L22]
- Владелец уточнил роли в Retrieval: главный агент должен вызывать субагентов для поиска нужных файлов, субагенты не должны пересказывать цитаты, главный агент обязан полностью прочитать найденный файл, а субагенты должны объяснять, почему именно этот файл полезен в текущем контексте. [2026-08-20-181330-claude-a7539038.md#L24]
- Владелец предпочитает поглощать правило о субагентах в более высокий текст `1chat-recall`, а не добавлять отдельный раздутый блок инструкций по лучшим практикам написания скилов. [2026-08-20-181330-claude-a7539038.md#L25]
- Владелец решил, что главный агент должен всегда искать по максимуму всё полезное и всегда вызывать субагентов, потому что сам не знает, чего не знает. [2026-08-20-181330-claude-a7539038.md#L27]
- Владелец предложил для `1chat-recall` использовать множество дешёвых фоновых субагентов для параллельного поиска релевантных файлов цитат во время основной работы. [2026-08-20-235300-codex-01a02084.md#L18]
- Владелец решил закрепить в Retrieval `1chat-recall` правило: до первого существенного решения одновременно спрашивать корпус и запускать несколько дешёвых субагентов по разным направлениям, продолжать независимую работу, а перед зависимым решением собирать от каждого только путь и краткую связь с claim-ом, явное отсутствие результата или blocker; позицию владельца доказывает только полностью прочитанный holder. [2026-08-20-235300-codex-01a02084.md#L19]
- Владелец указал, что сейчас не нужно запускать новых агентов. [2026-08-19-135233-codex-01a01922.md#L27]
- Владелец поправил процесс текущей правки глобального `1chat-recall`: прекратить использовать субагентов. [2026-08-20-235300-codex-01a02084.md#L20]

## Capture, metadata и provenance

- Владелец скорректировал правило: ссылки добавлять не следует, потому что они гниют. [2026-08-03-232246-codex-019fc8d8.md#L27]
- Владелец скорректировал отбор реплик для `1chat-recall`: служебные согласия не следует фиксировать, а сохраняемая реплика должна быть полезной единицей знания. [2026-08-03-232246-codex-019fc8d8.md#L28]
- Владелец скорректировал приоритет краткого описания `1chat-recall`: важнее не забывать фиксировать важные цитаты, поскольку чтение отсутствующих цитат бессмысленно. [2026-08-03-232246-codex-019fc8d8.md#L34]
- Владелец поправил `1chat-recall`, указав, что гарантии, автоматически обеспечиваемые `chat_capture.py`, не нужно дублировать в инструкциях. [2026-08-08-195321-codex-019fe1dd.md#L32]
