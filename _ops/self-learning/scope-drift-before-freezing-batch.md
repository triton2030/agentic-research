# Scope Drift Before Freezing Batch

## Observation

При большой параллельной batch-задаче модель может начать с широкого
естественного толкования ("все skills" = все skill-папки и references), а
пользователь потом сужает периметр. Без ранней фиксации периметра это создаёт
лишние правки и откатную работу.

## Counter

- 2026-05-21 [GPT-5.5]: при переводе skills сначала были переведены и non-`1`
  skill-папки; после пользовательской поправки "Меняем только скилы с цифрой 1
  вначале" non-`1` пришлось восстанавливать из backup, а `1*` references
  доводить отдельно.
- 2026-05-22 [GPT-5.5]: при ремонте partial-index я начал кодовый патч после
  первого локального вывода, а пользователь остановил вопросом "ты уверен?"
  и попросил шире проверить жизненные сценарии; правильный scope оказался
  `status → dry_run → index → search/audit/profile`, не только `search`.

## Possible upgrade

Перед запуском субагентов на batch-редактирование явно фиксировать scope в
одной строке: какие папки входят, какие исключены, входят ли `references/` и
metadata. Для фразы "все skills" отдельно уточнять, идёт ли речь о всех
installed skills или о семействе `1*`.
