# Инструкции Для `_ops`

`_ops/` — рабочая операционная поверхность проекта. Здесь нельзя складывать
рандомные заметки: каждый файл должен попадать в правильный слой и через
правильный скилл.

## Папки

- `GOAL.md` — короткий контракт проекта: что делаем, что не делаем, definition
  of done и stop rules. Владелец: `1goal` (он думает goal-formation
  internal работой и пишет; thinking не делегируется в отдельный strategy skill).
- `user-said/` — legacy/manual сырой архив цитат пользователя по дням
  (`YYYY-MM-DD.md`). Автозапись `UserPromptSubmit` отключена; не
  рассчитывать, что папка наполняется автоматически. Дальнейшая обработка —
  manual, отдельным проходом.
- `self-learning/` — legacy/read-only поверхность прежнего `lessons.md`.
  Новые факты о промахах ИИ пишет `1findings` в `_ops/findings/**` с префиксом
  `self-learning:`; старые тематические файлы, счётчики и архивы не
  восстанавливать.
- `rules/` — условные холодные rule-docs для редких правил с явным trigger,
  owner и check. Wording держит `1instruction-layer`; механизм — live settings/hook
  pass. Если route/owner rule-doc меняется, синхронизировать root `AGENTS.md`.
  Читать только по конкретному
  trigger из `AGENTS.md` или owner-файла, не как preload.
- `interviews/` — временные интерактивные вопросники для случаев, когда агенту
  нужно много ответов пользователя. Маршрут задаёт `1interview-tool`, wording
  маршрута чинит `1instruction-layer`, читаемую форму для Obsidian —
  `1writing-style`. После разбора смысл переносится к владельцам
  (task-файлы, roadmap, GOAL/README, knowledge).
- `interviews/_archive/` — архив полностью разобранных интервью.
- `findings/` — fan-out inbox побочных проблем, которые агенты уже увидели по
  пути другой работы, но не должны решать внутри её scope. Каждый quick jot
  через `1findings` создаёт отдельный уникальный файл; много активных файлов
  здесь ожидаемо. Это capture-слой до проверки, маршрутизации, задачи,
  skill-правки или решения, не второй source of truth.
- `findings/_archive/` — архив файлов находок, которые уже разобраны: проблема
  решена, смысл перенесён в задачу/критерий/roadmap/GOAL/README/skill/knowledge
  или пользователь решил больше не держать её активной.
- `plans/` — временные task-файлы только для активной сложной работы. Владелец:
  `1planning`.
- `plans/_archive/` — архив неактивных plan/task-файлов.
- Каждая папка внутри `plans/` получает свой `_archive/`, когда создаётся.

## Рекурсивное Планирование

- Планирование ведёт `1planning`: Level 1 task-файлы → Level 2 подшаги.
- План создаётся постепенно: агент сужает фокус до активного уровня и не
  раскрывает всё дерево заранее.
- Если верхний уровень меняется, старые нижние task-файлы сначала
  reconciled/archived, а не продолжают управлять работой по инерции.

Markdown-поиск по папке — owner, тема, section targets, related files,
duplicates и выбор файлов/секций — идёт через `$1md-navigator`. Внутри уже
начатого route он же bounded раскрывает выбранные `description`, заголовки,
секции, `read-related` и `walk`; короткий known file читай напрямую.

Связи Markdown-документов внутри `_ops` — YAML frontmatter,
`read-before-edit`, `edit-after-edit`, related-docs sections и
dependency-radius — проверяет `$1md-graph`. Смысл файла при этом остаётся за
владельцем папки.

## Как Работать С `interviews/`

- Использовать `interviews/` только когда чат стал бы длинным списком вопросов.
- Один файл интервью называется по дате и теме: `YYYY-MM-DD-short-topic.md`.
- Файл интервью должен быть удобен пользователю в Obsidian: короткие русские
  блоки по `1writing-style`, а агентные подсказки — под сворачиваемым блоком.
- Когда пользователь ответил и сказал “проверь”, агент читает интервью и
  переносит смысл к владельцам: план/task scope через `1planning`,
  GOAL/README через `1goal`, знания в `knowledge/`.
- После полного разбора переместить файл в `interviews/_archive/`. Активная
  папка показывает только незавершённые или ещё неразобранные интервью.

## Как Работать С `findings/`

- Использовать `1findings` для побочных находок, audit/subagent results,
  рабочих открытий и self-learning фактов, которые могут быть актуальной
  проблемой или будущей правкой поведения.
- Trigger автономный: агент уже читает файл / код / tool output ради active
  task и замечает конкретную collateral-проблему вне scope. Прямой просьбы
  пользователя о записи не ждать.
- Не открывать findings и не читать дополнительные источники перед capture:
  дописать одной строкой уже увиденное `что | где | трение` и продолжить task.
- Имя `YYYY-MM-DD-<time>-<pid>-<random>.md` выдаёт script. Каждый
  capture получает новый файл; параллельные Codex/Claude workers не делят
  write target.
- Current-scope проблему решать сразу. Если находка ставит под сомнение сам
  текущий результат или путь, поднять blocker, а не молча отложить её.
- Идеи, backlog, обычные заметки и слабые догадки без уже наблюдаемого сигнала
  сюда не класть.
- Если проблема становится направлением работы, сначала выбор лица:
  goal/scope/done меняются → `1goal` (он думает + пишет
  GOAL/README/ROADMAP); approach-choice в моменте задачи без задевания goal
  остаётся коротким decision pass текущего owner-а. Потом `1planning` делает
  task-файл только если задача реально нужна.
- Если находка противоречит текущему roadmap/task/stage, передать в
  `1planning` для reconcile/archive; если противоречит выбранному подходу
  для задачи — пересмотреть подход в текущем owner-контексте; если задевает
  goal/scope shape — `1goal`.
- Если проблема содержит устойчивое правило пользователя или красную линию,
  не записывай интерпретацию в `user-said/` автономно: автозапись отключена,
  а превращение цитаты в правило AGENTS / CLAUDE или decision в GOAL —
  manual, отдельным проходом, не здесь.
- Если проблема меняет roadmap content (current path сдвинулся, Stage closed),
  передать в `1planning`. Если меняет roadmap shape или goal/scope —
  `1goal`.
- Если проблема стала знанием, гайдом или примером, перенести смысл в
  `knowledge/`.
- Когда все находки в файле решены или перенесены в правильные owner-файлы,
  переместить файл в `findings/_archive/`. Архив не означает «решено»; он
  означает «файл больше не активен».

## Красные Линии

- Не использовать `findings/` как backlog.
- Не использовать `rules/` как shadow-`AGENTS.md`, shadow-`GOAL.md`, backlog или
  склад полезных мыслей.
- Не использовать `findings/` как папку обычных наблюдений, идей или общих
  находок без уже увиденного сигнала и текущего трения.
- Не использовать `self-learning/` как живой маршрут записи; новые
  self-learning факты идут через `1findings`.
- Не использовать `interviews/` как новую постоянную память или замену
  `INTERVIEW.md`.
- Не писать в `plans/`, пока strategy не решила, что это действительно задача.
- Не редактировать записанные цитаты в `user-said/` автономно — это сырой
  legacy/manual архив, обработка manual.
- Не копировать тела скилов в этот файл; здесь только маршруты `_ops`.
