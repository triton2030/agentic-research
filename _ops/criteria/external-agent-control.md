# External Agent Control Criteria

## Зона ответственности

Когда работа проектирует, настраивает или проверяет внешних LLM-агентов через
Codex: Claude, Gemini, MCP/CLI bridge, профили запуска, model defaults,
память, скилы, системные инструкции, prompt-reference, recovery и process
cleanup.

## Цель

Внешний агент работает как управляемый проверяющий или исполнитель с явной
ролью, наблюдаемой траекторией, проверяемым evidence и безопасным завершением.

## Критерии

Rule: Внешний агент запускается с ролью, линзой, файлами или context packet, применимыми criteria и проверяемым claim/task.
Why: Пользователю нужна ручная внешняя проверка, а не бесконтекстный ответ или перенос длинного чата.

Rule: Долгий или рискованный запуск должен быть наблюдаем по ходу.
Why: Пользователь хочет видеть зацикливание, неверное понимание или уход не туда до финального ответа.

Rule: Если внешний агент не может выполнить роль, даёт пустой полезный ответ или не виден в инструментах, Codex чинит вызов или останавливается.
Why: Пользователь не хочет скрытый перенос работы обратно в Codex; невидимость MCP/CLI — это проблема регистрации или видимости инструмента, а не оценка модели.

Rule: Ответ внешнего агента нужно отделять от evidence проекта, пересказа Codex и recovery-пути.
Why: Внешний агент должен судить по источникам, а отчёт не должен выдавать прямой CLI recovery за чистый MCP-вызов.

Rule: При read-only доступе внешний агент возвращает текст, findings, patch или инструкцию, а Codex применяет изменения сам после локальных criteria.
Why: Пользователь хочет полноценную внешнюю проверку без передачи записи туда, где агент не должен писать.

Rule: После разговора через MCP/CLI/bridge нужно проверить, что связанный внешний агентский процесс (`agy`, `gemini`, `claude`) или `tmux`-сессия больше не выполняется; Codex-held stdio MCP server process под текущим app-server допустим как активный транспорт инструмента.
Why: Пользователь прямо указал, что висящие внешние агенты могут продолжать тратить деньги или ресурсы. Сам MCP server не является модельным запуском и может жить пока Codex держит tool transport.

Rule: Для Claude `claude-mcp` даёт профили контроля под ситуацию: память, скилы, системные инструкции, права, evidence чтения контекста и recovery из bridge logs при усечённом `chat_relay`.
Why: Пользователь часто вызывает Claude как почти равного советника и хочет управляемость, наблюдаемость и доказательство фактического чтения.

Rule: Claude Code через CLI допускается как полноценный агент с файлами и сетью.
Why: Локальная проверка показала чтение внешнего файла через `--add-dir` и web-доступ через `Bash`.

Rule: Claude и Gemini peer agents должны есть пользовательский аккаунт через локальный CLI, а не API credentials.
Why: Пользователь прямо поправил: "нам надо чтобы они оба ели мой аккаунт а не апи кредиты".

Rule: В `claude-mcp` и `gemini-mcp` нельзя держать API/SDK/Vertex/credential fallback "на всякий случай"; если такой путь не является выбранным аккаунтным CLI-контрактом, его нужно удалить, а не прятать за флагом.
Why: Пользователь прямо уточнил: "надо удалить из гемини и клод всякие кодовые вещи которые на всякий случай".

Rule: Для Google One / individual Gemini path `gemini-mcp` предпочитает Antigravity CLI и `Gemini 3.5 Flash (High)`, а старый Gemini CLI остаётся legacy account-backed путь для managed-run/tmux сценариев.
Why: Пользователь прямо захотел новую Google-модель Flash 3.5 и после migration notice Gemini CLI выбрал переход через Antigravity 2.

Rule: Отсутствие API-key env для Claude/Gemini не считается поломкой; поломкой считается отсутствие рабочего аккаунтного CLI или смешение аккаунтного CLI с credential fallback.
Why: Пользователь выбрал аккаунтный доступ как рабочий контракт для внешних Claude/Gemini агентов.

Rule: Gemini MCP перед живым запуском проверяет точный backend, путь и версию: `agy` для Antigravity, `gemini` только для legacy CLI.
Why: Локальная проверка показала одновременно новый `/Users/triton/.local/bin/agy`, актуальный `/Users/triton/.local/bin/gemini` и старый `/opt/homebrew/bin/gemini`; смешение путей ломает диагноз.

Rule: Таймаут клиента Codex/MCP нужно отличать от таймаута Gemini-сервера или CLI-процесса.
Why: Тест показал, что сбой может происходить на клиентском ожидании, даже когда серверный слой настроен отдельно.
