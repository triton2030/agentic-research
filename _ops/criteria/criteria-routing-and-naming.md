# Criteria Routing And Naming Criteria

## Зона ответственности

Когда работа выбирает, создаёт, делит, сжимает, переименовывает или ссылается
на `_ops/criteria/*.md`.

## Цель

Criteria-файлы работают как точная рабочая память: будущий агент загружает
ровно тот файл, который помогает задаче, без смешанных ролей, дублей и лишнего
контекста.

## Критерии

Rule: Criteria-файл выбирается по сфере будущей работы, а не по редактируемому пути.
Why: Один путь может требовать разные criteria; сам файл-цель не доказывает нужный критерий.

Rule: Один criteria-файл держит одну recurring work area, узнаваемую по названию и зоне ответственности.
Why: User signal: смешанные роли грузят лишнее и мешают точному вызову criteria под задачу.

Rule: Если criteria-файл регулярно приносит нерелевантные правила, его нужно сжать, сузить, разделить или переименовать.
Why: Criteria нужны для точного применения, а не как общий контекстный склад.

Rule: Новый criteria-файл создаётся только если существующий owner-файл не покрывает сферу без лишнего контекста.
Why: Слишком мелкая нарезка создаёт дубли и заставляет будущего агента угадывать между похожими файлами.

Rule: Название criteria-файла должно быть task-ready: богатым, конкретным и достаточно говорящим, чтобы понять момент вызова без чтения тела.
Why: User signal: названия файлов должны помогать точному выбору criteria.

Rule: Заголовки внутри criteria-файла должны быть чёткими и описательными, чтобы `1md-navigator` при скане заголовков показывал смысл файла без чтения всего тела.
Why: User signal: пользователь хочет, чтобы heading-scan по criteria сразу давал понимание содержания и помогал будущему агенту выбрать правильную память.

Rule: Дубли между criteria-файлами схлопываются через выбор одного owner-файла и перенос только недостающего смысла.
Why: User signal: дубли заставляют агента читать больше и получать расхожие правила.

Rule: Durable user signal, red line, future rule или acceptance criterion пишется в criteria через `1user-truth`; если перед substantive write нет подходящего criteria-файла, агент останавливается и вызывает `1user-truth`.
Why: Criteria являются пользовательской правдой; agent inference или ближайший похожий файл создаёт ложную уверенность.

Rule: При split/rename criteria-файла обновить все Codex-editable ссылки или назвать read-only исключение.
Why: Говорящие имена бесполезны, если свежая сессия идёт по старым ссылкам.
