# Instruction Layer Criteria

## Зона ответственности

Когда работа меняет `AGENTS.md`, `CLAUDE.md`, root/subtree instructions,
routing, precedence, criteria links, memory placement или правила fresh-session
поведения.

## Цель

Инструкционный слой должен быть понятным человеку, коротким для модели и
достаточным, чтобы новая сессия нашла правильный owner без устного контекста.

## Критерии

Rule: Каждое новое правило должно иметь одну owner surface.
Why: Одно и то же правило в нескольких местах становится источником drift.

Rule: Root-инструкции должны хранить routing и invariants, а не пересказывать тела скиллов.
Why: Skill body грузится в нужный момент и сильнее root-текста при конфликте.

Rule: Instruction files должны ссылаться на применимые `_ops/criteria/*.md`, а не копировать criteria-текст или criteria-протокол внутрь себя.
Why: Criteria и protocol должны иметь живых владельцев, иначе AGENTS/CLAUDE и criteria начнут расходиться.

Rule: `1user-truth` задаёт шаблон и протокол записи `_ops/criteria/*.md`; `1instruction-layer` отвечает только за placement, ссылки на criteria и правила instruction-layer.
Why: Цели, красные линии и критерии качества должны приходить из user truth, а instruction layer должен только показать, где это читать.

Rule: Если правка instructions выявляет новую устойчивую цель, красную линию, проектный факт или критерий качества, запись в `_ops/criteria/*.md` идёт через `1user-truth`.
Why: Instruction-layer может заметить durable signal, но не должен сам становиться writer protocol для user truth.

Rule: Criteria-файлы должны выбираться по конкретной сфере будущей работы и готовности для агента, а не по редактируемому пути.
Why: Один файл может требовать разные критерии в зависимости от задачи; путь файла сам по себе не говорит, что проверять.

Rule: Новый criteria-файл создаётся только если существующие файлы не покрывают сферу работы без лишнего контекста.
Why: Богатые названия помогают агентам, но дубли и тонкие варианты одного файла создают drift.

Rule: Если агент хочет задать пользователю вопрос из-за нехватки контекста, он сначала читает `README.md`, `_ops/PROJECT-ROADMAP.md`, релевантные `_ops/criteria/*.md` и текущий task-file, если он есть.
Why: Вопрос к пользователю должен закрывать настоящий пробел после чтения project truth, а не заменять чтение доступных источников.

Rule: Если критерии начинают повторяться или пухнуть, сначала сжать назначение внутри текущего файла.
Why: Новые criteria-файлы создаются только когда появились разные сферы работы, которым нужны разные правила в контексте задачи.
