# 1work-artifacts — происхождение

## Намерение владельца

29 октября 2026 владелец попросил отдельный общий скил для папки рабочих артефактов: она есть во многих его проектах, а порядка, как разбирать чужие старые папки, нет.
Каждая новая папка должна говорить, какой агент и какая сессия в ней работали, чтобы ей можно было написать, в том числе из Codex в Claude и обратно, не только через T3.
Папку архивируют после работы; в ней же идут дизайн-парламент, оркестрация, картинки и другие промежуточные файлы сессии.[^idea]

Владелец принял предложение агента целиком:[^selection]

- одна работа — одна папка `дата-тема` с README для владельца и `agents/` для служебного;
- в `agents/sessions.md` строка на каждую сессию, работавшую в папке;
- всё промежуточное туда же, парламент из `/tmp` переезжает в рабочую папку;
- своя работа закончена — итог в канон и вопрос владельцу об архиве;
- чужая папка неделю без правок — заметивший агент пишет её сессиям, ответы и папки без живых сессий приносит владельцу одним списком;
- скил общий, с номером 1; особенности проекта остаются в `AGENTS.md` его папки рабочих артефактов;
- архив чужой папки разрешает владелец, одним списком.

Имя — как у папки, по-английски: `1work-artifacts`.
Знать о скиле должны только скилы, которым нужна папка для своих файлов; владелец назвал оркестрацию и парламент и допустил другие.[^naming]

## Функция

Сильный агент без скила заводит папку по правилу проекта, но не оставляет в ней, как связаться с его сессией, не знает, что номер потока T3 наследуется дочерним процессом, и не знает, какой путь доставки доступен из Codex в Claude.
Старые чужие папки он не трогает или спрашивает владельца по одной.

## Источники

- Маршруты сообщений проверены 2026-10-29: `t3 thread send --help`, переменные `T3CODE_THREAD_ID` и `CLAUDE_CODE_SESSION_ID` в сессии Claude под T3, `printenv CODEX_THREAD_ID` в логе потока Codex под T3, код T3 `AGENT_THREAD_ENV = "T3CODE_THREAD_ID"`, `claude agents --json`, `codex queue --help` и PR openai/codex#39092.
- Правила папок: `subfrost/_workspace/work-artifacts/AGENTS.md`, `mavo3/_workspace/work-artifacts/AGENTS.md`.

## Граница изменения

Новый пакет `skills/shared/1work-artifacts/`.
Указатели в скилах со своими папками для файлов: `1orchestration` (Claude и Codex), мост `1codex`, `1recraft` (скрипт получил `--dest-dir` вместо постоянной папки `_workspace/design/recraft-images/`), `1design-review` у Codex (только живой пакет), проектный `2design-parliament` в Subfrost.
Строка-указатель в `AGENTS.md` папок рабочих артефактов Subfrost и mavo3.
Не входят: `1html` (общая галерея `_workspace/HTML_artifacts/` с библиотеками), `1handoff`, `1planning`, `1interview-tool`, `1chat-recall`, `1findings`: у них реестры проекта, а не след одной работы.

## Решения автора

Владелец их не обсуждал; основания — проверки 2026-10-29 и первая волна проверяющих.

- Путь по умолчанию `_workspace/work-artifacts/` для проекта без правила: имя скила владелец взял от этой папки.
- Строку не пишет только субагент внутри процесса: он делит номера сессии с родителем. Исполнитель в своём потоке T3 или прогоне Codex пишет свою, как сказано в принятом предложении.
- Живая сессия T3 — поток, который владелец не закрыл (`settled` false): закрытые потоки возвращаются командой `show`, а сообщение в них — новый платный ход.
- Застывшая папка определяется по времени файлов, а не по коммитам: незакоммиченные правки и прогоны Codex вне git иначе выглядят мёртвыми.
- Отметка в `sessions.md` ставится до чтения папки, чтобы параллельные сессии не принесли владельцу тот же список; ответов не ждут.
- `1design-review` включён по слову владельца о картинках и промежуточных файлах сессии, хотя 2026-08-13 владелец назначил ему `_workspace/design/1design-review/`; новое место добавлено в `.gitignore` Subfrost и mavo3, как было прежнее.
- Поток T3 у Codex скрипт ищет во внутренней базе T3 (`statev2.sqlite`, таблица `orchestration_v2_projection_provider_threads`): T3 не даёт Codex `T3CODE_THREAD_ID`, а `orchestrator_capabilities` из Codex возвращает пустой `parentThreadId`. Смена устройства базы оставит строку без потока, о чём скрипт скажет.
