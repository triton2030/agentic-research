# Сохранность 1plan-map

| Смысл | Носитель | Вердикт |
| --- | --- | --- |
| Human map, не executor prompt | Context + Goal 1 | сохранён |
| Frames/Principles/Goal до карты | Protocol 1 | сохранено по буквальному owner-решению |
| Non-overlap, порядок, зависимости и proof эпиков | Goal 2 | восстановлено по acceptance loss |
| Явная map acceptance | Protocol 3 | восстановлено по acceptance probe |
| Evidence-state без процента | Goal 1 | сохранено по live false-100% case |
| Один sequential frontier | Protocol 3 | восстановлено по live-task-outside-frontier case |
| Conditional INDEX route | Protocol 4 | сохранено по названному вреду трудно найденного маршрута и второй правды |
| Exact schemas, assets, validator | — | снято: project-specific форма, не функция |

## Agent-default chains

- `source truth`: агент строит эпики по доступному запросу → запрос выглядит
  полной целью → карта расходится с Product Frames → цена: один полный reread.
- `frontier`: несколько live epics выглядят как полезный parallelism → теряется
  риск-порядок → dashboard скрывает фактический next → цена: последовательная
  модель для этой семьи карт.
- `epic acceptance`: «непротиворечивая» композиция выглядит достаточной →
  эпики перекрываются или не ведут к проверяемому Done → карта не направляет
  работу → цена: явно держать result, порядок, зависимости и proof.
- `no percentage`: closed/created выглядит удобным знаменателем → JIT-задачи ещё
  не созданы → `100%` ложно означает Done → цена: нет грубой progress-метрики.
- `1index seam`: найденный факт хочется скопировать → поиск становится второй
  правдой → маршрут добавляется только по допуску и одной ссылкой → цена:
  дополнительная authority-проверка.
