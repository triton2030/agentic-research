# Схема карты, эпика и дашборда

Вход: ты пишешь или правишь файл эпика, дашборд или их поля.
Выход: файл, который дашборд видит, а человек читает глазами.

Схема снята с работающего проекта и по решению владельца служит стандартом для
новой карты и для полей, которые ты и так пишешь. Существующую чужую форму карты
она не переписывает: расхождение предъявляется владельцу отдельным решением.

Пересмотреть, если проект держит карту не в `_ops/map` или живёт без Obsidian:
тогда этот файл описывает мир, которого в проекте нет, и его адреса надо
перевыводить заново.

## Размещение

```
_ops/map/
├── Дашборд.md              проза для человека и легенда статусов
├── Дашборд.base            таблицы эпиков и вопросов
├── Планы.base              таблицы задач
├── вопросы/                открытые вопросы владельцу, тип: вопрос
└── эпики/
    └── <Имя эпика>/
        ├── <Имя эпика>.md  сам эпик, тип: эпик
        └── <Имя задачи>.md задачи этого эпика рядом с ним, тип: задача
```

- Задача лежит внутри папки своего эпика, а не в отдельной папке планов.
  Колокация — это и есть структура, из-за которой создать задачу, не открыв
  эпик, физически невозможно; вынесенная в общую папку задача возвращает сцепку
  в статус правила, которое можно тихо не выполнить.
- Папка эпика называется точно так же, как файл эпика внутри неё: иначе
  принадлежность задачи приходится выводить из поля, а не видеть глазами.
- Дашборд различает три типа по ключу `тип`: `эпик`, `задача`, `вопрос`.
  Файл без верного `тип` не попадает ни в одно представление и для владельца не
  существует.

## Frontmatter эпика

| Ключ | Что несёт |
| --- | --- |
| `тип` | `эпик` |
| `описание` | одна строка, которую владелец читает в таблице |
| `область` | группа, к которой относится эпик |
| `порядок` | место в последовательности |
| `статус` | из словаря ниже |
| `health` | 🟢 · 🟠 · 🔴 |
| `запуск` | `true`, если эпик стоит на главном пути проекта |
| `критерий` | доказуемое условие достижения исхода |
| `ранний-индикатор` | наблюдаемый признак, что эпик идёт не туда |
| `зависит-от` | эпики, без которых этот не начинается |
| `задач`, `задачи`, `задач-готово` | связь с колоцированными задачами |
| `evidence` | доказательство закрытия |
| `обновлено` | дата |

Разделы тела эпика идут в этом порядке, и намерение стоит прозой сразу под
заголовком, до первого `##`:

- **проза под заголовком** — мир эпика и его результат: то, из чего пишущий
  задачу выводит задачу;
- `## Принципы` — адреса применимых рамок и принципов и то, как они сужают
  именно эту работу;
- `## Аппетит` — сколько работы эпик стоит; здесь и только здесь допустим
  ориентир по сроку, потому что это граница вложения, а не план работ;
- `## No-gos` — что этот эпик не делает, включая задачи, остановленные проверкой
  выводом;
- `## Апдейты` — датированные изменения состояния и выведённые задачи.

- `критерий` пишется доказуемым условием, а не намерением: «сделать хорошо»
  невозможно опровергнуть, и эпик закрывается по ощущению.
- `ранний-индикатор` называет то, что видно до провала. Индикатор, совпадающий с
  самим провалом, срабатывает, когда цена уже уплачена.
- `health` берёт значение из **последней записи `## Апдейты`** и обязан ей
  равняться: словарь у них один, и проверяющий прибор проекта сверяет их между
  собой. Значение — 🟢 · 🟠 · 🔴; жёлтого 🟡 в этом словаре нет. Замер
  2026-09-03: `scripts/check-map.py:51` принимает только эти три и остановил
  запись с 🟡, а прежняя строка этой таблицы называла именно его.
- `health` отвечает на один вопрос: сработал ли `ранний-индикатор`. Он стоит
  первым в главном представлении, где `evidence` нет вовсе, и зелёный кружок без
  привязки к индикатору и есть состояние без доказательства.
- `зависит-от` называет только то, без чего эпик не начинается: зависимость
  «было бы удобнее после» блокирует порядок без причины.
- `задач` и `задачи` обновляет тот, кто создал задачу, тем же ходом, а
  `задач-готово` и `evidence` — тот, кто её закрыл. Иначе знаменатель, по
  которому владелец меряет остаток, тихо расходится с содержимым папки.

## Словарь статусов

✅ готово · 🔨 в работе · ◽ в очереди · 🔒 заблокировано · 🛑 затык · ⏳ отложено

- Словарь общий для эпиков и задач и живёт здесь; схема задачи его зеркалит.
  Расхождение двух словарей делает дашборд нечитаемым быстрее, чем ошибка в
  отдельном файле.
- `🔒 заблокировано` выводится из незакрытой зависимости, `⏳ отложено` — решение
  владельца, и отложение старше блокировки: иначе отложенный эпик показывается
  заблокированным и владелец ищет несуществующий блокер.

## Проценты

- Процента готовности у эпика нет. Задачи нарезаются по мере надобности,
  знаменатель открыт, и `100%` означал бы завершение только созданных задач.
  Ответ «сколько осталось» даёт полоса статусов в порядке эпиков.
- Процент считается только у задачи и только по её явному списку подзадач: там
  знаменатель закрыт и виден в самом файле.

## Дашборд

`Дашборд.md` — проза для человека: что показывает карта и легенда статусов.
`Дашборд.base` держит представления **По порядку** (`тип == эпик` и
`запуск == true`, сортировка по `порядок`), **Затыки**, **Открытые вопросы**
(`тип == вопрос`) и **Отложенное**. `Планы.base` держит **Живые планы** и
**Завершённые задачи** по `тип == задача`.

- Закрытый эпик остаётся видимым в представлении «По порядку», у которого нет
  фильтра по статусу, а закрытая задача — в «Завершённых задачах». Ни то, ни
  другое не удаляется и не уезжает в архив: владелец назвал видимость сделанного
  частью ответа «сколько осталось».
- Когда `порядок` и `запуск` задают последовательность, живая задача вне
  текущего места этой последовательности показывается конфликтом, а не тихо
  работает: порядок эпиков и есть ответ «сколько осталось».
- Меняя набор полей, поменяй и представление, которое их показывает, тем же
  ходом. Поле, которого нет в представлении, для владельца не существует, а
  представление со ссылкой на исчезнувшее поле показывает пустой столбец и
  выглядит рабочим.
