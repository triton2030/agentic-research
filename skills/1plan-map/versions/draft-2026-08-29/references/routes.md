# Маршруты стадий

Закрой этот файл с названием одной следующей стадии.

- Новая карта:
  `опора → композиция → форма → валидация → состояние карты → приёмка → дашборд`.
- Изменение состава:
  `опора → композиция → форма → валидация → состояние карты → приёмка → обновление`.
- Событие эпика:
  `состояние → статусы → фронтир → валидация → состояние карты → приёмка → обновление`.
- Ремонт прибора: `валидация → состояние карты → приёмка`.
- Ремонт человеческой поверхности: `дашборд` для отсутствующей поверхности,
  иначе `обновление`.
- Допуск задачи маршрутизируй в `1planning`, файл задачи — в `1plan-task`.

Файлы стадий: [опора](map-source.md), [композиция](epic-composition.md),
[форма](epic-form.md), [состояние](epic-state.md),
[статусы](epic-status.md), [фронтир](frontier.md),
[валидация](map-validation.md), [состояние карты](map-state-validation.md),
[приёмка](map-acceptance.md),
[дашборд](dashboard.md), [обновление](dashboard-update.md).

Каждая стадия обновляет один пакет карты; новая версия заменяет прежнюю,
поэтому результаты прошлых стадий не остаются отдельными обязательствами.
Новую карту не записывай до валидации: эта стадия создаёт карту и прибор вместе,
а затем запускает команду проверки.
