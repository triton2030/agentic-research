# Схема карты, эпика и дашборда

## Задача

Оформи новую карту или изменяемые файлы эпиков и дашборда по общей конвенции.

## Цель

Файлы читаются одной картой: эпики задают границы задач, а представления показывают человеку согласованное состояние и историю.

## Зачем

Obsidian связывает файлы по точным именам, ключам и фильтрам. Семантику результата определяет тело скилла; эта схема даёт форму, которую невозможно вывести из цели. Стандарт применяется к новой карте и изменяемым полям; расхождение с существующей формой требует отдельного решения, иначе обновление состояния превращается в миграцию.

## Размещение

```
_ops/map/
├── Дашборд.md              проза для человека и легенда статусов
├── Дашборд.base            таблицы эпиков и вопросов
├── Планы.base              таблицы задач
├── вопросы/                открытые вопросы владельцу, тип: вопрос
└── эпики/
    └── <Имя эпика>/
        ├── <Имя эпика>.md  сам эпик, тип: эпик
        └── <Имя задачи>.md задачи этого эпика рядом с ним, тип: задача
```

Дерево задаёт имена и колокацию: у папки и файла эпика один `<Имя эпика>`, у задачи собственное `<Имя задачи>`. Это делает принадлежность видимой, но не доказывает чтения эпика.

## Frontmatter эпика

| Ключ | Что несёт |
| --- | --- |
| `тип` | `эпик` |
| `описание` | одна строка, которую владелец читает в таблице |
| `область` | группа, к которой относится эпик |
| `порядок` | место в последовательности |
| `статус` | из словаря ниже |
| `health` | 🟢 · 🟠 · 🔴 |
| `запуск` | `true`, если эпик стоит на главном пути проекта |
| `критерий` | доказуемое условие достижения исхода |
| `ранний-индикатор` | наблюдаемый до провала признак, что эпик идёт не туда |
| `зависит-от` | эпики, без которых этот не начинается |
| `задач`, `задачи`, `задач-готово` | связь с колоцированными задачами |
| `evidence` | доказательство закрытия |
| `обновлено` | дата |

## Тело эпика

Порядок и назначение частей ниже — единый формат эпика, по которому читатель находит рамки и историю:

| Место | Содержание |
| --- | --- |
| Проза сразу под заголовком, до первого `##` | Мир эпика и его конечный результат |
| `## Принципы` | Адреса применимых рамок и принципов и их влияние на эту работу |
| `## Аппетит` | Граница вложения; только здесь допустим ориентир по сроку |
| `## No-gos` | Исключённая работа, включая задачу, остановленную проверкой выводом |
| `## Апдейты` | Датированные изменения состояния и выведённые задачи |

## Производные значения

- `health` равен значению последнего `## Апдейты` в словаре 🟢 · 🟠 · 🔴: иначе поле и история одновременно показывают владельцу разные состояния. Смысл оценки по раннему индикатору задаёт критерий состояния в теле скилла.
- `задач` и `задачи` обновляет создавший задачу агент тем же ходом: иначе карта не видит новую работу.
- `задач-готово` и `evidence` обновляет закрывший задачу агент тем же ходом: иначе карта показывает старый остаток после доказанного результата.

## Статусы

✅ готово · 🔨 в работе · ◽ в очереди · 🔒 заблокировано · 🛑 затык · ⏳ отложено

Словарь принадлежит этой схеме, задача зеркалит его: расхождение обозначений ломает общую карту.

- `🔒 заблокировано` означает незакрытую необходимую зависимость; иначе удобный порядок выглядит невозможностью работать.
- `⏳ отложено` означает решение владельца; иначе агент выдаёт собственное бездействие за выбор человека.
- Отложение старше выведенной блокировки: иначе владелец ищет блокер у работы, которую сам отложил.

## Представления Obsidian

Форма представлений — часть механизма чтения карты:

| Файл | Представления / содержание |
| --- | --- |
| `Дашборд.md` | Пояснение карты и легенда статусов |
| `Дашборд.base` | **По порядку**: `тип == эпик`, `запуск == true`, сортировка по `порядок`, без фильтра статуса; **Затыки**; **Открытые вопросы**: `тип == вопрос`; **Отложенное** |
| `Планы.base` | **Живые планы** и **Завершённые задачи**, `тип == задача` |

- Завершённые файлы остаются на своих местах: архивирование убирает их из указанных представлений, а владелец считает видимость сделанного частью ответа «сколько осталось».
- Процент задачи равен доле завершённых подзадач её явного списка: у этого знаменателя есть граница. Отсутствие процента эпика защищено критерием состояния тела скилла.
- Живая задача вне текущего места последовательности `порядок`/`запуск` показывается конфликтом: иначе карта обещает один порядок, а работа идёт в другом.
