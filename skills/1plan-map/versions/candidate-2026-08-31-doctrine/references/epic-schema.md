# Схема карты, эпика и дашборда

Вход: ты пишешь или правишь файл эпика, дашборд или их поля.
Выход: файл, который дашборд видит, а человек читает глазами.

Схема описана не как вкус, а как то, от чего зависит видимость: дашборд
собирается запросом по полям, и ключ, написанный по памяти, не ломает файл
заметно — эпик просто исчезает с поверхности владельца, оставаясь на диске.

## Размещение

```
_ops/map/
├── Дашборд.md              проза для человека и легенда статусов
├── Дашборд.base            таблица эпиков
├── Планы.base              таблица задач
└── эпики/
    └── <Имя эпика>/
        ├── <Имя эпика>.md  сам эпик
        └── <Имя задачи>.md задачи этого эпика рядом с ним
```

1. **Задача лежит внутри папки своего эпика, а не в отдельной папке планов.**
   Колокация — это и есть структура, из-за которой создать задачу, не открыв
   эпик, физически невозможно; вынесенная в общую папку задача возвращает
   сцепку в статус правила, которое можно тихо не выполнить.

2. **Папка эпика называется точно так же, как файл эпика внутри неё.** Иначе
   принадлежность задачи эпику приходится выводить из поля, а не видеть глазами.

## Frontmatter эпика

| Ключ | Что несёт |
| --- | --- |
| `тип` | `эпик` — по нему дашборд отличает эпик от задачи |
| `описание` | одна строка, которую владелец читает в таблице |
| `область` | группа, к которой относится эпик |
| `порядок` | место в последовательности |
| `статус` | из словаря ниже |
| `health` | 🟢 · 🟡 · 🔴 — самостоятельная от статуса оценка здоровья |
| `запуск` | `true`, если эпик стоит на главном пути проекта |
| `критерий` | доказуемое условие достижения исхода |
| `ранний-индикатор` | наблюдаемый признак, что эпик идёт не туда |
| `зависит-от` | ссылки на эпики, без которых этот не начинается |
| `задач`, `задачи`, `задач-готово` | связь с колоцированными задачами |
| `evidence` | доказательство закрытия |
| `обновлено` | дата последнего изменения |

Разделы тела эпика: `## Принципы` · `## Аппетит` · `## No-gos` · `## Апдейты`.

3. **`критерий` пишется доказуемым условием, а не намерением.** «Сделать
   хорошо» невозможно опровергнуть, поэтому эпик с таким критерием закрывается
   по ощущению, а не по исходу.

4. **`ранний-индикатор` называет то, что можно увидеть до провала.** Индикатор,
   совпадающий с самим провалом, не индикатор: он срабатывает, когда цена уже
   уплачена.

5. **`зависит-от` называет только то, без чего эпик не начинается.** Зависимость
   «было бы удобнее после» блокирует порядок без причины, и владелец видит
   заблокированным то, что можно делать.

## Словарь статусов

✅ готово · 🔨 в работе · ◽ в очереди · 🔒 заблокировано · 🛑 затык · ⏳ отложено

6. **Словарь общий для эпиков и задач и живёт здесь.** Схема задачи его
   зеркалит; расхождение двух словарей делает дашборд нечитаемым быстрее, чем
   любая ошибка в отдельном файле.

7. **`🔒 заблокировано` выводится из незакрытой зависимости, `⏳ отложено` —
   решение владельца, и отложение старше блокировки.** Иначе отложенный эпик
   показывается заблокированным, и владелец ищет несуществующий блокер.

## Проценты

8. **Процента готовности у эпика нет.** Задачи нарезаются по мере надобности,
   знаменатель открыт, и `100%` означал бы завершение только уже созданных
   задач, а не достижение исхода. Ответ «сколько осталось» даёт полоса статусов
   в порядке эпиков, а не число.

9. **Процент считается только у задачи и только по её явному списку подзадач.**
   Там знаменатель закрыт и виден в самом файле.

## Дашборд

`Дашборд.md` — проза для человека: что показывает карта, что означает
«полностью» в этом проекте, легенда статусов. `Дашборд.base` и `Планы.base` —
запросы Obsidian Bases: фильтр по `тип`, представления «По порядку», «Затыки»,
«Живые планы», «Завершённые задачи», формулы связи задач с эпиком.

9. **Когда `порядок` и `запуск` задают последовательность, живая задача вне
   текущего места этой последовательности показывается конфликтом, а не тихо
   работает.** Порядок эпиков — это и есть ответ «сколько осталось»: работа,
   идущая мимо него, не видна на поверхности как отклонение и обнаруживается
   только тем, что остаток не уменьшается.

11. **Закрытый эпик и закрытая задача остаются на дашборде в отдельном
    представлении, а не удаляются и не уезжают в архив.** Владелец назвал
    видимость сделанного частью ответа «сколько осталось».

12. **Меняя набор полей, поменяй и запрос, который их показывает, тем же
    ходом.** Поле, которого нет в представлении, для владельца не существует, а
    представление, ссылающееся на исчезнувшее поле, показывает пустой столбец и
    выглядит рабочим.
