## Функция

Владелец решений и долговечной правды о композиции и состоянии эпиков, включая
дашборд владельца. Показывает потребность в допуске задачи, но не решает и не
пишет её.

## Новые ограничения

- Композиция и состояние — два названных write-scope. Событие состояния не
  может попутно менять топологию эпиков.
- Карта оптимизирована для чтения владельцем. Исполнительная цель, критичный
  контекст и ограничения одной задачи принадлежат task-файлу.
- Фронтир без задачи — planning-сигнал, а не разрешение создать задачу. Это
  снимает тройное владение JIT-созданием.
- Форма карты владеет общим словарём статусов и нормализацией
  `эпик-снимок`; task-форма повторяет их как исполнительский mirror.
- Композиция, состояние эпика и dashboard — самостоятельные стадии; результат
  каждой записывается до открытия следующего reference.
- Событие карты меняет только эпик. Статус задачи пишет `1plan-task`, а карта
  лишь читает его для производных полей и dashboard.

## Цена строгости

- **Композиция отдельно от состояния:** default — status-update попутно меняет
  топологию → механизм — два write-scope → вред — нельзя исправить очевидную
  композицию тем же событием → цена — отдельное видимое утверждение.
- **Карта для человека:** default — эпик превращается в dump инструкций →
  механизм — исполнительный контекст остаётся в task-файле → вред — детали
  скрыты от владельца → цена — дашборд показывает состояние и evidence, а не
  полный prompt.
- **Фронтир только сигнал:** default — карта сама изобретает JIT-задачу →
  механизм — допуск через `1planning` → вред — лишний цикл для очевидного
  следующего хода → цена — одно сообщение может явно утвердить композицию и
  срез.
- **Общая схема у карты:** default — задача и dashboard расходятся по статусу
  или снимку → механизм — один владелец и буквальный mirror → вред — карта
  становится зависимостью task-формы → цена — прибор проверяет parity.
- **Один reference на write-scope:** default — агент держит форму, состояние и
  dashboard одновременно → механизм — три самостоятельные стадии → вред —
  лишний переход при создании карты → цена — результат предыдущей стадии
  остаётся входом следующей, а не памятью чата.
- **Событие только эпика:** default — map-update попутно правит task-файл →
  механизм — status задачи пишет текущий task-writer → вред — дополнительный
  handoff → цена — прибор и dashboard читают task-состояние без второго writer.
- **Composition-only снимок:** default — state-event ложно инвалидирует задачу
  → механизм — снимок исключает state/derived поля → вред — состояние не видно
  через snapshot → цена — lifecycle читает текущее состояние отдельно.
- **Trigger-only description:** default — metadata пересказывает функцию →
  механизм — оставить только момент вызова → вред — skip/near-miss не видны →
  цена — границы живут в русском теле и проверяются контрастами.
- **Русский runtime:** default — English-тело затрудняет owner review → механизм
  — инструкции на русском → вред — перевод устойчивых токенов → цена — имена,
  команды, schema keys и код сохраняются литерально.

  записи разделяет состояние и композицию.
- «Эпик должен содержать инструкции исполнителю» → протокол 4 оставляет их в
  `1plan-task`.
- «Общая схема ничья» → форма карты владеет словарём статусов и нормализацией
  снимка; задача только потребляет.
- «Закрытие задачи позволяет `1plan-task` напрямую править эпик» → граница
  оставляет запись состояния карте.
