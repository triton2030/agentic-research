# Карта изменений

| Участок | Было → стало | Основание |
| --- | --- | --- |
| SKILL, «Выбор корпуса», первый абзац | «Используй абсолютный корень» → корень определён по `.md-tools.toml`; объяснено, почему подпапка — отдельный корпус без фильтров и куда ведёт подсказка инструмента с индексом и без него | Сбой контрольного агента на MAVO; `md status` подпапки; проверка кода и проба check-trajectory |
| SKILL, «Поиск и чтение», абзац после команды | «Сначала проверь ошибку» → отказ приходит обычным ответом с кодом 4; проверка распространена на скрипты; поток ошибок держать отдельно и сохранять | Сбой автора в замере; код 4 проверен запуском; причина `dense: false` в потоке ошибок — по коду |
| lifecycle, «Область действия» | Снято: место индекса и запрет вложенного индекса | Смысл перенесён в тело, в момент выбора корпуса; lifecycle читается только после тела |
| lifecycle, «Обычная индексация» | Добавлен абзац о выводе confirm после абзаца о плане | Смешанный или обрезанный вывод теряет итоговый JSON; обрыв процесса не воспроизведён и не утверждается |

Сохранены без изменений: description и metadata, разрешение на отправку,
dry-run нового scope, фильтры во всех фазах, контракт чтения тела,
авторитет по декларациям корпуса, вторая попытка, выдача и handoff.

## Решения по находкам

| Находка | Решение |
| --- | --- |
| «Подпапку сужает фильтр общего индекса» противоречит правилу об OR для includes (instructions, intent) | Принята: фраза заменена ссылкой на описание фильтров ниже |
| «Отставший от чужих правок» сужает причину отказа (instructions, intent) | Принята |
| До первой индексации `.md-navigator/` нет (instructions, trajectory) | Принята |
| При существующем корневом индексе вложенная индексация отклоняется (intent) | Принята: оба варианта названы |
| Хвост «пустой список секций…» повторяет смысл; есть код 4 (intent) | Принята; код 4 проверен запуском |
| Поток ошибок нужно сохранять, не выбрасывать (intent) | Принята |
| Абзац о confirm стоял до абзаца о плане (intent, trajectory) | Принята: переставлен |
| Обрыв процесса при `head` не воспроизводится (trajectory) | Принята: причинное утверждение снято, оставлена потеря итогового JSON |
| Нет пробы случая без индекса с вопросом через подпапку (trajectory) | Проведена отдельной пробой, см. evidence.md |
| Правило «объединять grep и поиск по смыслу для перечня» | Снято до черновика: оба агента без правила объединяли сами |

## Последующая правка после изменения инструмента

`md-tools` `d3db97f`: холодный предок с `.md-tools.toml` теперь тоже владеет
поддеревом — `index`, `status` и warmup-подсказка поиска переводят действие
на него. Фраза «пока его нет, подсказка ведёт в подпапку» стала неверной;
абзац «Выбор корпуса» описывает новый ответ инструмента и оставшийся обход
`--allow-nested-corpus`. Три роли проверки для этой фактической поправки не
повторялись; её проверяет аудит Codex вместе с кодом.

Аудит Codex (gpt-6-sol/xhigh) нашёл в `d3db97f` нестабильный приоритет
собственного конфига подпапки, выход поиска за корень репозитория и обход
через `cache_dir`; исправлено в `cee91a0`, оговорка «без собственного
`.md-tools.toml`» снята из абзаца. Скил в проверенном CLI-сценарии аудит
признал держащимся.
