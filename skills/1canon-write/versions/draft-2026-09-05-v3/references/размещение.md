# Размещение канона

Вход: утверждённое знание и роль либо предложенный адрес.
Выход: один смысловой дом; при первом файле — папка с инструкцией строителю.

## Задача

Найди место, из которого агент нужной роли получит это решение без чтения
чужого канона и без второй копии.

## Цель

По дереву и именам понятно, кто пользуется каждым документом и каким вопросом
он владеет.

## Зачем

Владелец читает проект по именам и меняет расположение файлов. Роли задают
границы рабочего контекста агента, а отдельный общий дом удерживает
согласованность между ними без перекрёстных копий.

## Устройство

- Роли определяет GOAL текущего проекта. Их папки находятся внутри `_canon`;
  сквозное для нескольких ролей живёт в соседней папке «Компания», чтобы
  общему решению не требовалась копия у каждого читателя.
- Внутри роли подпапка отделяет несколько поверхностей, например вход и
  кабинет. Дальнейшая глубина оправдана понятностью списка; папки на вырост
  и на одного жителя ничего не объясняют.
- Сценарий находится в самой нижней папке, охватывающей участвующие
  поверхности. Факт одной роли помещается в её цель; отдельный файл фактов
  оправдан несколькими читающими ролями.
- Имя имеет вид `Цель — предмет`, `Сценарий — предмет` или `Факты — предмет`.
  Предмет задаёт один связный вопрос; обзор папки уже выражен её именами,
  поэтому отдельный README или файл-пересказ не нужен.

## Выбор дома

Подходящие имена проверяются содержимым, в том числе когда адрес дал
вызывающий. Пустой файл подходящего предмета уже является домом. Отсутствие
дома обосновывается областью поиска и ближайшими отклонёнными кандидатами в
ответе: иначе новый файл неотличим от второго дома.

## Первый файл проекта

`_canon` находится рядом с `_docs` и `_ops/GOAL.md`. Папки создаются под
содержимое текущей записи; вместе с корнем канона появляется `AGENTS.md`
для строителя. Он не повторяет метод письма, а объясняет полномочия читателя:

```markdown
# AGENTS — `_canon`

Канон содержит утверждённые решения, которые дорого менять после реализации.
Цели, сценарии и факты размещены по ролям; общие решения — в «Компании».

- Для своей работы читай GOAL, «Компанию» и папку своей роли; при изменении
  общего поведения учитывай связанные документы других затронутых ролей.
- Строй по совокупному смыслу канона: устройство реализации выбираешь ты,
  а важные решения продукта принадлежат владельцу.
- Противоречие в каноне или с GOAL покажи владельцу исходными местами;
  не выбирай удобную версию самостоятельно.
- Запись документов начинается с `1docs-write`, письмо канона — с
  `1canon-write`; догадки и исследования не становятся каноном от своего
  расположения. Задачи принадлежат `_ops`, материалы для решений — `_docs`.
```
