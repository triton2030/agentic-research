# Решения и почему

Что решено 4 сентября 2026 и на каком основании. Отвергнутое названо, чтобы к нему не возвращаться.

| Решение | Почему | Что отвергли и почему |
|---|---|---|
| Документ — интерфейс, код — реализация | В документ идёт только то, что Founder не хочет узнать постфактум: переделка дорога. Всё остальное дешевле поправить в коде, чем описать | Документировать устройство: доки становятся дублем кода и расходятся с ним |
| Две рабочие папки плюс `_ops` | `_docs` (Бизнес, Разработка) — где решения рождаются, `_canon` — что выведено и утверждено, `_ops` — работа. Ось разреза не «для кого», а «строим ли из этого»: иначе факт нужен обоим и получает два дома | Делить «для меня / для агентов»: деньги нужны и презентации, и биллингу — дубль |
| Ступени по времени | Решение рождается в бизнесе, утверждается в каноне, исполняется в коде. Каждая ступень читает только предыдущую, и агенту не дают ступень выше его работы: контекст модели ограничен | Держать анализ рынка и закон рядом с целями: агент грузит то, из чего не строит |
| Три вида файла с видом в имени | Founder читает по именам; вид виден до открытия; форма проверяется по имени | Один универсальный формат: «Деньги» в контекст-цель-критерии не укладываются |
| Файл «Цель» = контекст, цель, критерии | Контекст подводит к цели и держит «почему»; критерии — ограничения, проверяемые состояния; устройство агент додумывает сам | Разделы «не-цели», «границы», «статус»: разрастаются бесконечно, а статус у цели невозможен |
| До 2000 символов, до восьми критериев | Модель забывает и игнорирует инструкции при длинных списках; Founder не удерживает длинный текст | Полные спецификации: агент не выполняет их целиком |
| Без ссылок между файлами | Папки будут переезжать; файлов мало, агент найдёт заново | Ссылки: каждый переезд ломает сеть |
| Первый уровень — роль | Founder думает ролями; агент, строящий кабинет, читает одну папку целиком | Первый уровень — жанр («Сценарии/», «Цели/»): чтобы понять одну роль, открывать четыре папки |
| Сквозное — уровнем выше | Заявка проходит витрину и кабинет — живёт в «Компании». Одно правило для целей, сценариев и фактов | Дублировать сквозное в каждой роли |
| Нет файлов-обзоров и пересказов | В старой документации одна тема жила в четырёх слоях пересказа; слово «Принять» стояло в 101 файле | «Родитель» с обзором детей и view-файлы «другим жанром» |
| Отдельного слоя принципов нет | Принцип = «когда… делай… почему… следствия»; это контекст плюс критерий одной «Цели». Второй слой того же даёт дубли. Сквозные тайбрейкеры — в GOAL, не больше восьми; способность решать неописанное держит контекст, написанный как «почему» | Рамки по областям: 8 файлов, 63 000 символов, 51 принцип поверх канона |
| Инженерные предпочтения — в `AGENTS.md` | «Готовое против своего» и «модуль против правки по всему сайту» — про поведение агента, а не про продукт; относятся к каждому файлу сразу | Писать их в каждую «Цель»: дубли и минус строка из восьми |
| Новый файл — крайний случай, конфликт — Founder-у | У вопроса один дом; знание кладётся в него; расхождение видит Founder, а не решает агент | Агент выбирает одну из двух версий сам: канон перестаёт быть Founder-овым |
| Канон пишет агент, правда остаётся у Founder-а | Писать руками медленно; граница держится не автором, а источником: каждая строка восходит к словам Founder-а или утверждённому решению | «Агент никогда не трогает канон»: слишком строго, Founder снял это сам |
