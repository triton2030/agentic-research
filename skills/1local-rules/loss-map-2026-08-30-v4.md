# Loss map повторной проверки

Сравнение выполнено после clean-room draft против текущего official package,
всей папки истории и owner-слов. Старый текст использован как evidence, а не
как шаблон нового candidate.

## Сохранено

| Смысл | Где в candidate |
| --- | --- |
| Обычный skill authoring принадлежит `$1skill-creation` | Уникальный контекст и единственная creator-установка |
| Package активен только в одном проекте | Локальная дельта и ограничения кандидата |
| Имя начинается с `2` | Ограничение `2<имя>` |
| Package предназначен одновременно Claude и Codex | Уникальный контекст и две проекции |
| Содержательный конфликт с global/root instructions недопустим | Compatibility gate после exact approval |
| Owner и обе проекции разрешаются из проекта, а не придумываются | Topology gate до authoring |
| Missing либо contradictory topology не создаёт новый source tree | Fail-closed blocker |
| Создание и обновление заканчиваются portable parity | Состояние `present` и direct parity check |
| Снятие удаляет owner и обе проекции | Состояние `absent` и direct absence check |
| Conflict gate не блокирует снятие | Явная ветка `absent` |
| Обязательное evidence возвращает адреса и прямые checks | Финальная квитанция |

## Поглощено commander's intent

| Старое средство | Почему отдельная инструкция больше не нужна |
| --- | --- |
| Перечень `SKILL.md`, `references/`, `scripts/`, `assets/`, common `agents/` | `portable package` и recursive parity задают тот же результат без хрупкого manifest-каталога |
| Объяснение, что project-only не запрещает глобальную authoring history | Явное владение полного authoring у `$1skill-creation` отделяет history от package surface |
| Формула «замени generic install; второй install не запускай» | Candidate использует единственную установку самого `$1skill-creation`, поэтому второго маршрута больше нет |
| Отдельное требование не принимать частичное создание, обновление или снятие | Два исчерпывающих доказанных состояния `present | absent` и прямой check удерживают границу |

## Снято

| Смысл clean-room либо старого package | Причина снятия |
| --- | --- |
| Собственные authoring-, trigger- и behavior checks | Дублируют действующий `$1skill-creation` |
| Самостоятельный local approval flow | Exact approval уже принадлежит `$1skill-creation` |
| Обязательный rollback при любой ошибке | Владелец требовал конечное состояние, но не этот способ; rollback может быть невозможен или принадлежать проекту |
| Запрет всех runtime-specific вариантов | Слишком широк: project-owned runtime metadata является допустимой platform delta |
| Drift-recovery как отдельный режим | Не запрошен и выводится из owner + parity contract при фактическом drift |
| References для conflict и sync | Оба режима обязательны в каждом lifecycle-действии и не дают progressive disclosure; владелец поместил критичные детали в body |

## Не выводимые добавки, оставленные в body

| Инструкция | Дефолт → механизм → вред без строки → цена строгости |
| --- | --- |
| Префикс `2` | Агент выберет обычное имя → соглашение произвольно → потеряется routing локального package → фиксированное имя |
| Обе Claude/Codex-проекции | Агент установит только текущий runtime → локальная среда кажется достаточной → другой runtime останется stale → обязательна двойная projection |
| Topology только из project sources | Агент выведет owner по свежести файлов → projection похожа на source → появится второй owner → missing topology блокирует работу |
| Conflict gate | Более узкий scope кажется достаточным precedence → локальное правило ослабит старшее → нарушится прямой критерий владельца → конфликтующий candidate отклоняется |
| Единственная creator-установка | Последовательный вызов двух skills выглядит как два install-а → обе процедуры считают себя owner-ом записи → drift либо двойная mutation → остаётся один install |
| Portable parity и explicit metadata delta | Похожее содержимое кажется достаточным → скрытый файл расходится → runtimes ведут себя по-разному → требуется recursive check |
| Снятие всех трёх поверхностей без conflict gate | Удаление одной projection кажется достаточным, а конфликтующий package кажется нельзя трогать → stale runtime остаётся активен → `absent` неделим |
| Адресная квитанция | Самоотчёт кажется завершением → parity/conflict нельзя проверить → ложный terminal result → требуется прямое evidence |
