# Локальные скилы

## Уникальный контекст

Локальный скил — обычный скил, чей project-only lifecycle обозначен префиксом
`2` и зеркалом Claude↔Codex. Project-only относится к активному package и его
проекциям, а не к глобальной authoring-истории. Общий authoring принадлежит
`1skill-creation`.

## Результат

При создании или обновлении вызови `$1skill-creation` с требованиями, что
результирующий кандидат активен только в одном целевом проекте и назван
`2<имя>`. Доведи общий authoring до точного утверждённого кандидата, затем для
`2*` замени generic install `$1skill-creation` следующей единственной
установкой; второй install не запускай:

1. При создании или обновлении прочитай применимые глобальные инструкции Claude
   и Codex и корневые инструкции целевого проекта; содержательный конфликт
   делает кандидат недействительным. Снятие этот gate не проходит.
2. Разреши owner и обе проекции по реестру и корневым инструкциям проекта;
   их расхождение либо отсутствие owner-контракта возвращает blocker без
   изменения поверхностей и без нового source tree.
3. При создании или обновлении запиши утверждённый кандидат в owner, затем один
   раз синхронизируй в обе проекции `SKILL.md`, `references/`, `scripts/`,
   `assets/` и общие agent-role files из `agents/`; проверь их рекурсивное
   совпадение. Различаться может только явно runtime-owned metadata вне
   portable surface, например Codex `agents/openai.yaml`.
4. При снятии удали owner и обе проекции и подтверди отсутствие всех трёх
   поверхностей, даже если действующий скил конфликтует со старшими
   инструкциями.

При создании или обновлении верни адреса трёх поверхностей и instruction-
источников вместе с прямыми conflict и parity checks. При снятии верни адреса
трёх поверхностей и прямой absence check. Частичное состояние не является
результатом.
