# Карта рефактора

До рефактора в live-контракте было 29 самостоятельно нарушаемых указаний и
ограничений. Первый кандидат скрыл 46 единиц в составных строках, второй
оставил 22–29 активных единиц. После двух аудитов кандидат сведён к шести
самостоятельным режимам. Консервативный активный набор: тело 9; допуск 10,
всего 19; форма 10, всего 19; проверка кандидата 10, всего 19; поведенческое
доказательство 11, всего 20; установка 11, всего 20; снятие 10, всего 19.

| Группа старого текста | Решение | Где удержан смысл |
| --- | --- | --- |
| Когда локальному правилу нужен skill surface | Сжато | `admission.md`: один проект, наблюдаемое действие, ненадёжность cold route, полезная дельта |
| Четырёхкратное меню соседних authoring skills | Снято | Это routing-каталог соседей; один route ссылался на несуществующий `references/routing.md` |
| Закон «условие × дельта» и длинный пример `marketing/` | Сжато | `form.md` и falsifying trigger checks |
| Категория хуже пути или действия | Сохранено | `form.md` запрещает category-only trigger |
| Два архетипа тела | Сохранено | `form.md`: бинарное ограничение либо осознанный выбор |
| Тонкое тело и conditional references | Выведено | Общий progressive-disclosure contract принадлежит creator skill, не этому жанру |
| Объяснение глобального префикса `1` | Снято | Не меняет создание локального продукта `2*` |
| `2` как локальность и Claude↔Codex sync | Сохранено | Цель, Уникальный контекст, установка и снятие |
| Локальные skills без `2` приватны одному runtime | Снято | Не требуется внутри trigger этого скила |
| Один владелец и зеркало, пути определяет проект | Сохранено | `install.md` и `retire.md` |
| Не переносить якоря одного проекта в другой | Сохранено | Project-only admission |
| Страж устаревания по GOAL/scope/structure/rule set | Сохранено | Тот же допуск запускается после изменения контекста проекта |
| Ручное обновление вместо self-rewrite hook | Сжато | Желаемое состояние принимается явно и применяется через owner; автоматического маршрута нет |
| Старый checklist `Готово / Стоп` | Пересобрано | Candidate checks, behavior proof, install и retire с rollback |

Новых продуктовых ограничений нет. Поведенческое доказательство и rollback
заменяют прежнюю недоказуемую декларацию «правило срабатывает».

## Коррекция после установки

Владелец сузил функцию: локальный скил не является отдельным жанром authoring,
а лишь обычным скилом с локальной дельтой. Поэтому шесть режимов первой версии
поглощены обратно владельцем общей логики `1skill-creation`.

| Первая версия | Решение второй версии |
| --- | --- |
| `admission.md` | Снято: admission любого скила принадлежит `1skill-creation` |
| `form.md` | Снято: имя, description и форма тела принадлежат `1skill-creation`; здесь остался только префикс `2` |
| `candidate-checks.md` | Снято: structural и routing checks общие для всех скилов |
| `behavior-proof.md` | Снято: evidence contract общий для всех скилов |
| `install.md` и `retire.md` | Сжато в один инвариант одновременного состояния owner↔Claude↔Codex |
| Локальность одного проекта | Сохранено в теле |
| Отсутствие конфликта с глобальными и корневыми инструкциями | Добавлено прямым критерием владельца |

Новый активный контракт содержит только два уникальных conditional-режима
вместо шести стадий первой версии. Консервативный набор текущей стадии:
main — тринадцать единиц, `conflict.md` вместе с переходом — семь, `sync.md`
вместе с переходом — двенадцать. Завершённые стадии повторно не считаются.

## Коррекция раскладки

Владелец подтвердил, что критичные local-инварианты помещаются в теле. Поэтому
`conflict.md` и `sync.md` сняты как лишняя навигация: их обязательный смысл
выполняется в каждом lifecycle-действии и не образует редких самостоятельных
режимов. Literal-аудит подтвердил, что полный активный набор превышает мягкую
цель в двадцать единиц; последняя прямая коррекция владельца сохраняет
критичные подробности в теле, поэтому references не возвращаются.

Финальный literal-аудит насчитал 46 body-единиц и одну routing-единицу до
последнего условного разделения квитанции. Активный набор намеренно превышает
мягкую цель: create/update и retire имеют разные обязательные evidence outputs,
а владелец выбрал видимость критичных подробностей в теле.

## Повторная clean-room проверка v4

Обновлённый `1skill-creation` потребовал пересоздать пакет из нового
commander's intent, а не сокращать установленный v3. Intent сохранил четыре
отличия от обычного skill creation: один проект, префикс `2`, Claude/Codex
parity и отсутствие конфликта с применимыми global/root instructions.

Чистый исполнитель, не видевший старого package, независимо восстановил те же
инварианты, но добавил собственный install workflow, rollback, drift-recovery и
33–39 активных единиц. Zero-based authoring снял эти средства: общий flow,
exact approval и единственная установка принадлежат `$1skill-creation`, а
`1local-rules` передаёт ему только локальные ограничения и проверяет local
terminal state.

Полная preservation/removal карта и оправдание невыводимых строк лежат в
`loss-map-2026-08-30-v4.md`. Первый literal checker насчитал в исходном v4 54
body-единицы плюс одну routing-единицу; прежняя оценка 20/19/12 снята как
ошибочное объединение независимо нарушимых предикатов. References снова не
созданы, потому что все локальные инварианты обязательны в одном lifecycle-
моменте и владелец прямо выбрал критичные подробности в body. Итоговый счёт
после первой коррекции: 66 body-единиц плюс routing, 54 активны в
create/update и 44 в retire. Последняя authority/topology-коррекция передана
финальному checker-раунду. Итоговый счёт SHA `eb262405…`: 80 body-единиц плюс
routing; 61 активна в create/update и 55 в retire. Candidate сохраняет
критичные подробности в body, но не проходит новое требование писать каждую
самостоятельную инструкцию с новой строки; после двух повторов review это
остаётся явным blocker-ом, а не поводом для непроверенной третьей версии.

Текущий official owner и live packages остаются неизменённым baseline до exact
approval. Отдельная skill-specific Product Frame отсутствует; новая пара не
создана, чтобы не вводить второй semantic owner рядом с owner-словами и
history.
