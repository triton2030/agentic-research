# Черновые артефакты

## Режим и результат

Сначала выбери режим по намерению пользователя:

- **Создать:** подготовь отдельный reader-facing Markdown-файл, который помогает
  понять тему, увидеть логику или проверить предложенный план.
- **Показать:** прочитай и покажи названный либо однозначно указанный артефакт;
  не создавай дубликат. Если файл нельзя надёжно определить, задай один короткий
  вопрос.
- **Продолжить:** изменяй существующий артефакт только по прямой просьбе.
- **Обсудить skill:** ответь на метазапрос о `1draft-artifacts`; не создавай и не
  изменяй артефакт без отдельной просьбы.

Для нового файла выбирай путь в таком порядке: путь пользователя → ближайший
project contract для draft/scratch-файлов →
`<project-root>/_workspace/draft-artifacts/`. Project root — корень текущего
репозитория или единственный активный workspace; при нескольких кандидатах
выбери владельца исходного материала, а если это всё ещё неоднозначно — спроси.
Создай fallback-папки, если их нет. Дай файлу новое понятное имя с расширением
`.md`.

В начале файла обозначь: это черновой объясняющий артефакт, не Канон и не
источник правды. После создания или показа верни пользователю кликабельный путь
к файлу и одной фразой назови его статус.

## Контракт объяснения

- Сначала дай лучшее связное объяснение или предложение. Вопросы необязательны;
  задавай их свободным текстом только для реальной синхронизации.
- Пиши по-русски, если пользователь не выбрал другой язык. При первом
  употреблении аббревиатуры расшифруй её простыми словами; точные термины кода
  и API сохраняй и объясняй на языке артефакта.
- Для материального вывода сделай проверяемой трассу: **источник → вывод →
  следствие**. Источником может быть явное утверждение пользователя, owner-файл,
  код или tool output; вывод агента помечай как вывод. Давай только краткое
  обоснование, нужное для проверки, а не внутреннюю цепочку рассуждений.
- Разделяй факт, позицию пользователя, вывод агента, предложение и неизвестное.
  Только цитата пользователя несёт его голос.
- Покрой все материальные части запроса и связи без смысловых дыр; полнота не
  означает многословие.

## Форма

Plain Markdown — default. Таблица нужна для точного сопоставления, Mermaid —
когда порядок, причинность или структура сами несут знание. Применяй
`1writing-style` только при явном запросе на оформление, визуализацию, Obsidian
или когда сложная связь материально выигрывает от визуальной формы.

## Границы и готовность

Не изменяй Канон, `_ops`, код или owner-файлы. Не используй черновики как
evidence или dependency без явного указания пользователя; их claims всё равно
сверяй с живыми owners. Несколько черновиков могут существовать одновременно;
не архивируй, не перемещай и не удаляй их без прямой просьбы.

Готово, когда выбран верный режим и нет незапрошенной записи. В режиме артефакта
файл создан или показан по правильному пути, статус виден, материальные выводы
трассируемы, неизвестное обозначено, а ссылка возвращена пользователю. В
метарежиме запрос закрыт без создания постороннего файла.
