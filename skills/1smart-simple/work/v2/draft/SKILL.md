# Умное упрощение

## Уникальный контекст

Читатель текста, который ты упрощаешь, — агент, и у него в точке действия
есть предел удержания: шесть-семь разнотипных обязательств одновременно — уже
перелом, за восемью надёжного выполнения нет, и теряются они в случайном
порядке, а не «самые неважные». Знание этому пределу не подчиняется: факт не
удерживается в голове, а открывается в тот момент, когда он понадобился.
Поэтому текст в разы длиннее предела почти целиком бесполезен — агент удержит
из него случайное подмножество, — а файл, который нужен в один момент,
держать нужно только в этот момент, и в остальные моменты он удержания не
занимает. Модель-редактор по умолчанию сжимает формулировки внутри структуры
оригинала и режет заметное вместо лишнего: удалённую строку легко обвинить в
будущей ошибке, а вред сохранённой размазан по всем будущим запускам. Понятая
цель текста разрешает сменить его жанр: сотню описанных находок можно
заменить одним правилом, как такие находки выводить самому, и условием, когда
это правило применять.

## Задача

Возьми один текст и назови, какой агент — или какие агенты — и после какого
события его читают. Оставь в точке входа, где читатель открывает текст, новый
текст, который он удержит целиком. Сам оригинал не удаляй: перенеси его в
архив и держи там по адресу, записанному для владельца.

## Цель

- Каждый файл, который читатель открывает, служит одной цели, нужен после
  одного события, не несёт того, что читателю понадобится лишь позже этого
  события, и держит не больше восьми обязательств; при этом функция
  оригинала — то, ради чего он существовал, — из этих файлов выводима.
- Ни одна потеря не случилась молча: каждый блок оригинала либо заменён
  правилом, по которому читатель выведет его сам, вместе с условием, когда это
  правило применять, либо остался в файле своего момента, либо для читателя
  потерян — и тогда он назван владельцу как потеря до замены, а сохранён
  только в архиве для владельца.
- Новый текст порождён из цели и наращён от неё в сторону оригинала, а не
  получен сокращением оригинала до предела.

## Критерии принятия

- Одна цель каждого файла записана в чате раньше, чем написана хоть одна
  строка этого файла. В первом тексте, написанном из этой цели, каждое
  предложение либо выводится из неё, либо явно названо фактом, который
  читатель сам не выведет; ни одна рубрика и ни один порядок изложения не
  взяты из оригинала — кроме рубрик, которых требует схема дома этого файла, и
  кроме порядка, который сам является фактом и потому записан как факт, а не
  унаследован как структура. Каждое обязательство, добавленное при
  наращивании, названо вместе с причиной, по которой оно вошло раньше
  остальных; у фактов такой причины не требуется. Без этого следа
  переписывание неотличимо от сокращения.
- Каждый блок оригинала получил ровно одну судьбу, и она записана: остался в
  точке входа · перенесён в файл того момента, когда он нужен · свёрнут в
  правило вывода, и это правило вместе с условием применения названо ·
  потерян для читателя и хранится в архиве. Владельцу перед «да» показаны
  свёрнутые и потерянные блоки. Адрес архива записан там, где владелец найдёт
  его после сессии, а не строкой в теле, которую читатель примет за указание
  открыть; архивный оригинал не читается индексом дома как живой файл.
- Каждый файл, который открывает читатель, кроме точки входа, назван вместе с
  читателем и событием, после которого тот его открывает — например «перед
  тем как писать первую задачу», — и этот файл не читается вместе с точкой
  входа; имя и место файла выбраны по `1document-system`: у каждого вопроса
  один дом, и по имени дома виден его деловой тип. Файл, у которого события
  нет, разделён по теме, а не по моменту, и удержания он не снижает.
- Факт, которого читатель сам не выведет, — решение владельца, контракт
  инструмента, число, дата, адрес, цитата, — стоит дословно в файле того
  момента, когда он нужен. Заменять такой факт советом или пересказом нельзя:
  пересказанное evidence перестаёт быть evidence.
- Для каждого файла, который открывает читатель, названо число обязательств,
  полученное пересчётом его текста. Обязательство — это одно отдельное
  действие или воздержание, которое читатель обязан выполнить сам, включая
  переход в файл другого момента по событию; факты, которыми обязательство
  исполняется — команда, адрес, число, — это его контекст, а не новые
  обязательства. Число не больше восьми; сверх восьми допустимо только когда
  второй файл запрещает названная схема дома или решение владельца — причина
  адресом, а не рассуждением. Длина текста в символах мерой не является.

## Протокол

Способ владельца дословно: «удалить всё и все сотни строк заменить одной целью
и уже потом наращивать цель так чтобы она была ближе к оригиналу».

1. Восстанови функцию оригинала одним глаголом и одним существительным
   (**Function Analysis / FAST**) и поднимай эту функцию вопросом «зачем»
   (**Action Identification**, Vallacher & Wegner, 1987) до тех пор, пока не
   получишь governing thought по **Pyramid Principle** (Minto) — одно
   утверждение, из которого выводится функция оригинала. Выше этого
   утверждения не поднимайся: более общая цель уже ничего не порождает.
2. Если подъём даёт больше одной цели либо разные части текста нужны читателю
   после разных событий, перед тобой не один документ, а несколько. Назови
   каждый момент чтения, назови границу между ними и дальше веди каждый файл
   отдельно по этому же протоколу с шага 1. Момент дописывания — тоже момент:
   если оригинал пополняли, дай этому моменту правило, по которому новая
   запись сначала проверяется на покрытие уже стоящим правилом, иначе файл
   отрастёт в прежний жанр.
3. Напиши из одной цели первый текст по **Commander's Intent** — что должно
   стать правдой и зачем — в форме контекст → задача → цель → критерии
   принятия; там, где схема дома требует своих рубрик, эта форма ложится
   внутрь них, а где схемы нет, она и есть рубрики. Включай в него только то,
   чего читатель из цели сам не выведет. Протокол или пошаговый способ пиши
   лишь там, где чистый агент по одной цели к нужному способу не придёт.
   Покажи этот первый текст в чате до того, как начнёшь наращивать: показ —
   след, а не остановка, и ответа владельца здесь не жди; порядок «сначала из
   цели, потом из оригинала» и есть след того, что текст порождён, а не
   сокращён.
4. Наращивай текст из оригинала блок за блоком, пока не упрёшься в предел
   удержания читателя. В текст входят: условия, без которых цель вводит в
   заблуждение; факты, которых читатель не выведет; правило вывода с условием
   применения вместо серии однородных находок — для этого поднимись по
   **лестнице абстракции** (Hayakawa) на ту ступень, где отдельные случаи
   становятся одним правилом; пример — только если после всего этого осталось
   место. Упёрся в предел, а нужное не вошло — вернись к шагу 2 и найди
   событие, после которого это нужно; события нет — оставь сверх восьми только
   по причине, которую допускает критерий счёта.
5. Единственная остановка: покажи владельцу точный текст каждого файла
   целиком. Только после его «да» замени оригинал в точке входа новым
   текстом, а оригинал перенеси в архив по адресу, записанному для владельца;
   после «да» текст ни одного файла не меняй.
