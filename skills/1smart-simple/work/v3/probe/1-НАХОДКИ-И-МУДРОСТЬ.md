# Принципы оркестратора

Founder 2026-09-01: «о таких всяких мудростях и важных находках и советах
будущему себе лучше помнить а значить стоит записать отдельным файлом в папку
оркестрации тоже».

Мост, воркеры, приборы и git исполняют ровно то, что названо, ровно в тех
условиях, которые названы. Всё неназванное — ни выполнено, ни проверено, а
выглядеть при этом может как успех. Каждый принцип ниже оплачен минимум одним
потерянным кругом; истории — в архиве.

- **Требование без условий выполнимости — не требование.** Называя прибор,
  мутацию, файл вне зоны или соседний контракт, назови и то, при чём это
  исполнимо: зависимости в worktree, файлы шва в allowlist, разрешённый способ
  мутации, «сосед сейчас меняет X». Иначе честный воркер вернёт «неизвестно»,
  изобретательный потратит круг на обход, а красный окажется артефактом
  изоляции.
- **Зелёный прибор доказывает только свой предмет.** После волны гоняй не
  список её приборов, а класс её правки: миграция → полный набор; смена
  identity движка → поиск отставшего ref по всем носителям, включая
  замороженные. Зелёные зоны в зелёный проект не складываются.
- **Критерий, который может позеленеть при невыполненной цели, — не критерий.**
  Для каждого критерия назови контрпример вслух; прибор называй точкой входа,
  а не командой тестов; мутация ложится в продуктовый файл, не в помощника
  теста; красный по таймауту — не доказательство шва.
- **Запрос — не факт, журнал — не состояние.** После прерывания, фонового
  пуска, слияния и перед любой уборкой проверь фактическое состояние процесса,
  дерева и `main`, а не exit code и не запись в логе. Уверенность при
  неоткрытом источнике — сигнал открыть файл.
- **Красное считай по причинам, а не по отказам.** Сначала различные сообщения
  и точки броска, потом число; красный по среде не отменяет продуктовый
  красный — он его прячет, и счёт неизвестен, пока прибор не дошёл до предмета.
- **Один дефект в разных зонах — мой шаблон; разные ракурсы одной зоны — одна
  причина.** Считай зоны, не отчёты: чини промпт, а не возвращай воркера, и не
  читай веерную проверку как эпидемию.
- **Знание доходит только по названному адресу.** Воркер не открывает отчёт
  решений и не видит чужого дерева: всё нужное — в файле задачи и адресом в
  поручении; допуск выдаётся по полю «граница», а не по тому, что работа
  тронет.
- Перед составлением `--tasks` и пуском волны открой `МОСТ-КОНТРАКТ.md`; после
  волны, перед приёмкой и уборкой — `ПОСЛЕ-ВОЛНЫ.md`.

Новая запись здесь появляется только когда машина повела себя не так, как я
ожидал, и ни один принцип выше этого не покрывает; покрывает — запись не
нужна, история идёт в архив.
