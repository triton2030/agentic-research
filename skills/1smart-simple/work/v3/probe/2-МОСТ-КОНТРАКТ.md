# Контракт моста и хоста — перед пуском волны

Составление задач:
- `--tasks` ждёт голый JSON-массив, не `{"tasks": [...]}`.
- `files` обязателен и непустой даже для read-only аудита; директорию класть
  нельзя (`files entry points to a directory`); файл, которого ещё нет на
  диске, — только с `"allow_create": true`, иначе валидация роняет всю волну.
- Worktree — чистая копия от коммита: нет `node_modules`, LFS-ассеты лежат
  указателями, untracked и ignored файлы главного дерева не видны. Поручению с
  прибором нужен первый шаг `npm ci && git lfs checkout`; материал аудитору —
  инлайном в промпт. Аудит — по интегрированному дереву.
- Тёплый `thread_id` закрытой волны мёртв: закрытие архивирует треды
  (`threads_archived`), задача падает с `session ... is archived`, а
  `scope_status: passed` при `changed_files: []` значит, что воркер не работал.
  В том же ходе, что пуск: `$B/.venv/bin/python $B/codex_threads.py unarchive THREAD_ID --project "$PWD"`.
  CLI `codex` на хосте нет, совет из ошибки неисполним.
- `--tree-setup 'git reset --hard <старый>'` ломает слияние: мост сравнивает
  с `main`, и мои файлы после этой вершины становятся out-of-scope воркера.
  Независимость ревью даёт порядок «сначала пуск судьи, потом мой вердикт».
- PostgreSQL в песочнике прогона не поднимается (`shmget: Operation not
  permitted`) — граница среды, не дефект; вне песочницы поднимается.
  `kern.sysv.shmmni` = 32 на хост, сегменты не освобождаются: четыре воркера с
  PG-тестами упрутся. Перед возвратом красного проверь `ipcs -mo`; уборка:
  `ipcs -mo | awk '$1=="m" && $7+0==0 {print $2}' | xargs -n1 ipcrm -m`
  (NATTCH — седьмая колонка).

Пуск и наблюдение:
- `--dry-run` создаёт run-dir, боевой запуск в него не пишет (`Run dir already
  exists`) и молча не стартует.
- `nohup ... &` возвращает exit 0 сразу; после пуска проверь, что
  `events.jsonl` растёт. Сырой `events.jsonl` не читать: `codex_progress.py
  "$RUN_DIR"` даёт `stalest` и `idle_sec`.
- Воркеры не коммитят; сигнал приземления одного воркера — событие `OK <id>`
  от `codex_watch.py watch`; `results.jsonl` пишется в конце прогона.
- Заголовок `> [!note]- Отчёт` в файле задачи зарезервирован `check-map.py`
  (ровно один `статус YYYY-MM-DD:` на подзадачу); свою заметку называй иначе.
- Хост: `timeout` нет; `cd` не переживает вызов Bash — абсолютный путь первой
  командой; `chat_capture.py --session` требует полный UUID; расигнорировать
  `dir/` нельзя — только `dir/**` + `!dir/**/` + `!dir/**/*.md`.
