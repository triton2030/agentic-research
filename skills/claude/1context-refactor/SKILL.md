# Рефактор контекста

## Контекст

Это скил мета-анализа диалога. Цель — проанализировать весь контекст, который
агент получил: глобальные инструкции, папочные инструкции, скилы, прочитанные
файлы, подключаемые сообщения и слова владельца. Если что-то пошло не так и
агент где-то ошибся — значит, проблема в контексте.

Правило допускается, только когда его эффект дороже того, что оно отменяет;
цена — активные обязанности в точках решения траектории, которые правило должно
пережить, не длина текста, а context volume — отдельная цена. Сомнение, что
строка неожиданно уведёт мысль агента, — не пиши её вовсе. Полный владелец цены
— «налог на строгость» в
[agent-defaults](../1skill-creation/references/agent-defaults.md).

## Протокол

Три шага. Виновник называется на шаге 2 и только потом чинится.

1. **Перечитай весь текущий диалог и найди шероховатости.** Что ищешь: лишнее
   чтение — прочитал три-четыре файла там, где инструкция могла сразу сказать,
   где искать; сделал → обнаружил, что ошибся → переделал; слишком долгая
   работа; прочие неэффективности. Каждая шероховатость предъявляется местом в
   диалоге, а не по памяти: ненайденное место — не находка.
2. **Проанализируй, из-за чего каждая произошла**, и спроси вперёд: можно ли
   было её предотвратить, если бы агент знал что-то заранее — и что именно.
   Ответ на этот вопрос и есть кандидат в правку. Причина без места в диалоге не
   чинится.
3. **Чини настоящего виновника — не всегда это инструкции.**

   | Виновник | Куда идти |
   | --- | --- |
   | слой инструкций: глобальная, папочная — только если причина действительно в них | правь инструкцию здесь, инструментарий ниже |
   | документ ввёл в заблуждение | чини документ у его владельца |
   | скил вёл в заблуждение: тело | `1skill-creation`, режим `references/refactor.md` |
   | скил вёл в заблуждение: не вызвался или вызвался не в тот момент | `1skill-creation`, режим `references/routing.md` |
   | слова владельца | попроси владельца больше так не говорить или подправить |
   | инструкции ещё нет, её надо создать | `1instruction-authoring` |
   | инструкция есть, но по форме не роутер — перегруз, дубли | `1instruction-authoring` |

   Инструментарий для случая «виновник — слой инструкций»: карта смыслов и
   вердикты → [refactor](skills/claude/1context-refactor/references/refactor.md); пересечения слоёв →
   [coherence](references/coherence.md); сокращение →
   [simplify](references/simplify.md); независимое окно по риску →
   [audit](references/audit.md); проверка заявленного →
   [check](references/check.md).

## Обязанность сверх протокола

**Правка доказывается той же шероховатостью.** Назови, какое место диалога
пошло бы иначе. Чтение, заполненность и самоотчёт evidence не являются;
непроверенное остаётся candidate.

## Соседи

- инструкции создаются, а не чинятся, либо свод перегружен, а прошедшей
  работы нет — пересборка в роутер → `1instruction-authoring`;
- виновник вне scope текущей работы — записать и продолжить → `1findings`;
- виновник — тело скила → `1skill-creation`, режим `references/refactor.md`;
  его вызов → `1skill-creation`, режим `references/routing.md`;
- нужен новый скил → `1skill-creation`.

## Завершение

Инструкционные поверхности — корень, папка, хук, план: точный итоговый текст
записывается после «да» владельца; правка после «да» — новое «да». Починка
обычного документа-виновника идёт по владельцу документа, без этого гейта;
поверхность skill — по автономной границе `1skill-creation`.

Сдача: список шероховатостей с местами в диалоге · причина каждой · названный
виновник · что изменено и у кого · какие шероховатости остались без виновника ·
какие claims остались candidate. Пошёл путь «виновник — слой инструкций» —
сдача дополняется таблицей потерь из [refactor](skills/claude/1context-refactor/references/refactor.md).
Не вошедшее сохраняется в истории с причиной, а не возвращается соседним
правилом. В сдаче цитируй применённые пункты канона; имя
без пункта — не применение →
[canon](../1skill-creation/references/canon.md).
