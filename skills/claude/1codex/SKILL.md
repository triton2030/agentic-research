# 1codex — второй мозг: Codex как напарник по мышлению

Он не инструмент, который зовут по заявке, а **второй мозг под рукой**: другая
model-family, думающая независимо от тебя. Порог вызова низкий намеренно —
сомнение уже достаточный повод. Пропущенный вызов стоит дороже лишнего:
лишний — это прочитанный и отвергнутый совет, пропущенный — твоя ошибка,
которую никто не поймал.

Backend:
`/Users/triton/Documents/GitHub/agentic-research/experiments/codex-bridge/`,
python — `<backend>/.venv/bin/python`. Биллинг идёт через ChatGPT-подписку, не
через API-ключ, и entrypoints сами вырезают billing keys из env — платного
режима у моста нет. Остальная runtime-правда (tier, ledger, профили sandbox,
версии) живёт в `<backend>/README.md` и меняется вместе с кодом; сюда её не
копируй — устареет молча.

**Кредиты не жалей:** лимит подписки не переносится; «дешевле» — не критерий.
Ярус выбирается по характеру задачи, а не по цене.

## Почему второй мозг, а не второй исполнитель

Ценность — **де-корреляция**. Кодируй её операционно: первый вердикт blind, без
твоего вывода и авторства; расхождение — находка; синтез твой. Отдавай Codex
проблему, не разжёванное решение. Findings проверяй первичкой, а severity и
действие калибруй от outcome и blast radius. Evidence-модель →
[`references/model-mixing.md`](references/model-mixing.md).

## Дисциплина запуска

Куда идти — решает роутер ниже. Здесь только то, что роутер не говорит:

- **Codex назван или триггер сработал** — разрешения повторно не спрашивай,
  запускай рано и фоном.
- **Domain-скил не отменяется.** `1md-read` / `1md-search`, diagnosing и code-скилы
  ведут ТВОЮ работу; `1codex` добавляет cross-model взгляд поверх. Оба.
- **Один прогон = один вопрос** с ожидаемым влиянием и проверяемым результатом.
- **В задание ЛЮБОГО прогона клади запрет обратного вызова:** «не вызывай
  инструменты claude-mcp, работай файлами и shell». У Codex есть MCP обратно в
  Claude, ответить ему некому — замер 2026-07-28 дал 9 часов тишины. Почему это
  не лечится конфигом — в «Среда субагента».
- **Проверка чужой работы — только свежим `task`** с исходными критериями и
  путями. Транскрипт исполнителя — самоотчёт, не evidence.
- **Решение → blind-советник:** decision packet без твоего вывода; вопрос
  стабилен — запускай и продолжай работу →
  [`references/advisor.md`](references/advisor.md).
- **Решение, которое дорого откатывать** (внешний эффект, миграция, правка
  глобального скила, выбор, на котором строится остальное) → **Claude × Codex
  blind + твой diff**; `1fresh-eyes` остаётся in-family проверкой →
  [`references/model-mixing.md`](references/model-mixing.md).

## Роутер: куда попадёт результат?

Оплаченный прогон всегда пишет audit `run_dir`; ось ниже — deliverables Codex.

- **Только ответ/поиск; project edit не нужен** (файлы/веб, советник, ревью) →
  **ревьюер** `codex_review.py`, default `task`, filesystem sandbox read-only.
  `--mode ask` тянет транскрипт для вопроса по диалогу/траектории;
  `--mode review` — негативно смещённый adversarial аудит по транскрипту, не
  навигация. Воркера верифицируй свежим `task` по критериям и diff, не его
  транскриптом.
- **Ревью git-дифа** → `--mode diff`: НАТИВНЫЙ ревьюер движка (`review/start`),
  а не наш промпт. Таргеты: без флагов — незакоммиченное, `--base REF`,
  `--commit SHA`, а свободный текст даёт `custom` с инструкциями. Оговорка:
  усилие там наследуется из конфига движка, `--effort` не действует (ledger
  пишет `inherit`). Диф большой — сузь таргет: на всём дереве ревьюер уходит
  на сотни шагов.
- **Markdown evidence-packet** («сходи в knowledge/vault, принеси адреса») →
  Codex **`md-scout`** через `run_md_scout.py`: read-only executor
  `1md-search`, без вердиктов/правок; wrapper может сохранить JSON через
  `--out`. Обычный платный index warmup заранее разрешён и обязателен: scout
  греет derived cache и повторяет query, не меняя source. Его `terra`+`medium` —
  ярус самого инструмента, не моста; тот же корпус можно blind разведать
  Claude-скаутом. Приёмка md-scout — по пакету, не по exit
  code: непустой `packet` + `runtime.returncode: 0` + `corpus_unchanged: true`
  валиден и при exit 1 — ненулевой exit даёт также дословная сверка цитат
  (`evidence_errors`; скаут любит «…»-сокращения). Такие цитаты проверь
  первичкой по адресам, пакет не выбрасывай.
- **История позиции владельца по корпусу цитат** («как менялась», «всё, что он
  говорил про X») → `codex_recall.py`: читающая модель уходит в своё окно и
  возвращает переваренный ответ на пару килобайт вместо десятков команд и
  килобайтов выдачи в твоё. Процедурой recall владеет `1chat-recall` — здесь
  только маршрут; обычный вопрос к корпусу закрывает его локальный поиск за
  секунды, сюда идут только история и полнота. Способ поиска модели не диктуй:
  замер 2026-08-12 — навязанный протокол стоил вдвое и не нашёл больше.
- **Артефакты в отдельную рабочую папку, без project edit** («изучи X, напиши
  отчёт») → **исследователь** `codex_investigate.py`. Built-in filesystem writes
  sandboxed в `run_dir/out/` + system temp; postflight проверяет drift проекта.
  Забирай `result.json` и `out/`.
- **Файлы проекта — Codex должен внести правки** → `codex_orchestrate.py`.
  Воркер работает в своём git worktree, волна закрывается сама. Перед запуском
  прочитай [`references/fleet.md`](references/fleet.md): нарушенный там контракт
  стоит потерянных правок.

## Веер: чем платит каждая роль

Читающие и ревьюеры разворачиваются веером бесплатно: read-only, ни деревьев,
ни тредов. У пишущих веер платит диском — дерево воркера стоит выкладки
проекта: 22 МБ на текстовом репозитории, 650–780 МБ на большом фронтенде.

Поэтому **единица деления у пишущих — группа задач, а не задача**: двадцать дел
это четыре воркера по пять, каждому `subagents: true`. Связную работу (одна
фича, один слой) не дроби вовсе — целиком у одного дешевле. Число воркеров
выбирай по цене дерева и связности, не по числу дел.

Потолок «3–4 окна» из `1orchestration` — про окна Claude-подписки: Codex-агенты
его не тратят (биллинг ChatGPT), их лимит — кредиты и деревья.

Делегация нужна явным словом: системный промпт движка запрещает субагентов,
пока их не попросят — «Do not spawn sub-agents unless the user or applicable
AGENTS.md/skill instructions explicitly ask». Независимым взглядом они не
являются: наследуют рамку родителя.

## Советник — момент и диалог

**Первый момент — старт существенной работы, не финальное ревью.** Запусти
фоном «как бы ты решил X» — цель и ограничения, без твоего плана — и делай
по-своему; его ответ вернётся к середине, и чистый Codex от цели иногда видит
маршрут круче твоего. Дальше по событию: развилка, коррекция пользователя,
труднообратимость, 2 круга без сходимости. `ask` нужен только для
намерения/истории/траектории: транскрипт заякоривает. `--dialog --topic` создаёт персистентный тред;
`--continue THREAD_ID` сохраняет контекст. Независимая проверка — свежий тред.
Глубина — [`advisor.md`](references/advisor.md); чужие и старые треды —
[`threads.md`](references/threads.md).

## Вход: как писать задание

Дефолт «расписать шаги» здесь работает против тебя вдвойне: план съедает твоё
окно ради работы, которую ты и отдавал, а исполнитель со своими скилами и
поиском превращается в дорогой автокомплит. Отдавай результат и границы.

Четыре блока, которые движок ждёт (`learn.chatgpt.com/guides/best-practices`,
сверено 2026-08-14):

| Блок | Что в нём | Частый провал |
|---|---|---|
| **Цель** | что должно измениться или появиться | вместо цели — список действий |
| **Контекст** | какие файлы, папки, доки, ошибки важны | вставленное содержимое файлов вместо путей |
| **Границы** | что обязано сохраниться, чего делать нельзя | границы не названы, и он решает сам |
| **Готово, когда** | по чему проверяется результат | «сделай хорошо» без проверяемого условия |

**Самодостаточность — единственное, чего он не восстановит сам.** Диалога с
владельцем Codex не видит: принятые решения и неочевидную project-дельту назови
явно, каждую один раз. Всё остальное — его работа, а не твоя опека.

Доки Codex живут на `learn.chatgpt.com/docs`; старые адреса
`developers.openai.com/codex/*` туда редиректят.

## Среда субагента — инструкции тоже промпт

Твоё задание — не весь его вход. Codex склеивает глобальный и папочные
`AGENTS.md`, свои скилы, плагины и hooks; «чистого» прогона не бывает, и
конфликт твоего задания с ними ты увидишь только в ответе. Сомневаешься, что он
получит, — посмотри до траты: `codex debug prompt-input` печатает системные
блоки, скилы, плагины и склеенный AGENTS бесплатно.

Bridge владеет built-in filesystem profile и postflight, не исчерпывающим
каталогом capabilities. Внешние MCP могут жить вне sandbox; их наличие не
разрешает side effects в non-write профиле.

**Почему запрет обратного вызова кладётся в задание** (правило — в «Дисциплине
запуска»): у Codex есть свой скил `1claude-mcp`, который по умолчанию велит
звать блокирующий `claude_ask`; ответить ему некому, оба ждут друг друга.
Approval-политика на эти инструменты в конфиге стоит, но отклонит ли она
рекурсивный вызов — непроверено (живой пробник означал бы намеренный deadlock);
мост его не блокирует. Запрет в задании — единственная защита, которой
управляешь ты.

## Команды

```bash
B=/Users/triton/Documents/GitHub/agentic-research/experiments/codex-bridge
# Ревьюер/советник (read-only, без транскрипта):
$B/.venv/bin/python $B/codex_review.py "САМОДОСТАТОЧНОЕ ЗАДАНИЕ" --project "$PWD"
# Диалог и продолжение:

# Транскрипт сессии:
$B/.venv/bin/python $B/codex_review.py --mode review --project "$PWD"
$B/.venv/bin/python $B/codex_review.py --mode ask --question "ВОПРОС" --project "$PWD"
# Нативный ревью git-дифа (движок, не промпт):
$B/.venv/bin/python $B/codex_review.py --mode diff [--base REF | --commit SHA] --project "$PWD"
# Прогон не получается — сперва это, кредитов не тратит:
$B/.venv/bin/python $B/codex_review.py --doctor --project "$PWD"
# История позиции владельца по корпусу цитат (процедура — у `1chat-recall`):
$B/.venv/bin/python $B/codex_recall.py "ВОПРОС" --project "$PWD"
# Доска диалогов / md-scout / исследователь:
$B/.venv/bin/python $B/codex_threads.py list --project "$PWD"
(cd /Users/triton/Documents/My_projects/md-tools && uv run python scripts/run_md_scout.py КОРПУС --question "ВОПРОС" [--path-include GLOB] [--out FILE.json])
$B/.venv/bin/python $B/codex_investigate.py "ЗАДАНИЕ + формат выхода" --project "$PWD"
# Флот воркеров (правит файлы проекта) — codex_orchestrate.py: см. references/fleet.md
```

Редкий флаг или полный CLI surface: `<python> <entrypoint>.py --help`; не
копируй каталог сюда. Каждый **оплаченный** прогон создаёт audit `run_dir` в
`<проект>/_workspace/codex-artifacts/<run_id>/`; `--run-dir` — override. Успех
такого прогона — только `status=completed` и `ok=true`; failure/partial
response не синтезируй как готовый результат. Читающие команды (`codex_threads.py
list`, `codex_progress.py`, `--print-prompt`) `run_dir` не создают; `--dry-run`
флота создаёт run_dir с `status=validated` — это план, не результат. `--doctor` отвечает на вопрос
«почему не работает» до траты кредитов: аккаунт, эффективный конфиг и
наследуемый `service_tier` (мост его не шлёт, так что это единственное место,
где видно, на каком тире пойдёт прогон). У `run_md_scout.py` своя схема —
критерий приёмки назван в его пункте роутера.

## Фон — умолчание, а не режим для долгих

**Любой оплаченный turn запускай через `Bash` с `run_in_background: true`.** Не
«если покажется долгим»: заранее ты этого не знаешь, а форграундный вызов молча
вешает сессию на минуты — пользователь видит замерший экран. Форграунд остаётся
для мгновенного и бесплатного: `--dry-run`, `codex_threads.py list`, `--help`.

Запустив, сразу скажи пользователю: Codex работает фоном и **в списке агентов
не виден** (это фоновый процесс, не Agent-субагент) — назови `RUN_DIR` и ручку
`codex_progress.py RUN_DIR`. Иначе «запустил Codex» при пустом списке агентов
читается как ложь. Воркеры флота видны владельцу чатами в Codex Desktop
(`thread_id` в `results.jsonl`) — это его монитор, не твой.

Механика фонового прогона — пайпы, heartbeat, чтение прогресса сводкой, доска
`--board`, события — у [`orchestration.md`](references/orchestration.md); туда
же перед worker→verify→fix и многочасовой задачей.

## Stop

- Write footprint неизвестен — не запускай флот; сперва read-only разведка.
- 2–3 круга verify→fix без сужения носителей — стоп, блокер пользователю.
- **Волна не закрыта, пока не названы `wave.cleanup_done` и `wave.kept_branches`
  из отчёта** (копия формулировки-владельца из `fleet.md`, правь вместе): непустые
  ветки — незабранная работа, висящее дерево — выкладка проекта.
- **Прогон не закрыт, пока не назван его эффект:** одной строкой — что ответ
  Codex изменил в твоём решении либо почему не изменил. Запуск, пересказ ответа
  и «учёл» эффектом не являются. Без этой строки лишний вызов неотличим от
  полезного: видно трату, не видно влияния — и скил вырождается в ритуал.
