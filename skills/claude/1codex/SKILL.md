# 1codex — второй мозг: Codex как напарник по мышлению

Он не инструмент, который зовут по заявке, а **второй мозг под рукой**: другая
model-family, думающая независимо от тебя. Порог вызова низкий намеренно —
сомнение уже достаточный повод. Пропущенный вызов стоит дороже лишнего:
лишний — это прочитанный и отвергнутый совет, пропущенный — твоя ошибка,
которую никто не поймал.

Backend (на этой машине):
`/Users/triton/Documents/GitHub/agentic-research/experiments/codex-bridge/`
Python: `<backend>/.venv/bin/python`. Биллинг — ChatGPT-подписка, не API;
entrypoints вырезают billing keys из env. Service tier не шлётся (наследуется
из `~/.codex/config.toml`; `--service-tier priority` — осознанный opt-in fast).
Ledger фиксирует запрошенные effort/tier, не их применение сервером. Полная
runtime-правда — `<backend>/README.md`.

**Кредиты не жалей:** лимит подписки не переносится; «дешевле» — не критерий.
Ярус выбирается по характеру задачи, а не по цене.

## Ярус вызова — три, не один

| Ярус | Для чего | Как звать |
|---|---|---|
| **`sol` + `xhigh`** | **дефолт на всё**: думать, писать, разбирать, работать параллельно | ничего не передавай |
| **`sol` + `max`/`ultra`** | глубже дефолта: `max` — глубина одного прогона, `ultra` — она же плюс делегация субагентам внутри движка | `--effort max` |
| **`luna`** | тупое и большое: много механического текста, где нужна пропускная способность, а не суждение | `--model gpt-5.6-luna` |

Решение владельца 2026-08-14 — «сол экстра хай всегда, луна только для тупых и
больших заданий». `terra` доступен явным `--model` (дефолт `md-scout`), штатным
ярусом моста быть перестал.

**`max` и выше — это разговор, а не выстрел.** Они долго читают и долго думают;
одиночный ответ такой глубины почти всегда хочется поправить или углубить.
Поэтому на пути ревьюера такой прогон **сам** заводит персистентный тред и
печатает `thread_id` — продолжай его через `--continue THREAD_ID`, а не задавай
вопрос заново. Осознанный одиночный выстрел — `--no-dialog`.

На дефолтном `xhigh` тред сам не заводится: автотред на ярусе по умолчанию
делал бы отдельный чат в Codex Desktop из каждого вызова моста. Нужен
разговор — проси `--dialog` явно.

## Почему второй мозг, а не второй исполнитель

Ценность — **де-корреляция**. Кодируй её операционно: первый вердикт blind, без
твоего вывода и авторства; расхождение — находка; синтез твой. Отдавай Codex
проблему, не разжёванное решение. Findings проверяй первичкой, а severity и
действие калибруй от outcome и blast radius. Evidence-модель →
[`references/model-mixing.md`](references/model-mixing.md).

## Дисциплина запуска

Куда идти — решает роутер ниже. Здесь только то, что роутер не говорит:

- **Codex назван или триггер сработал** — разрешения повторно не спрашивай,
  запускай рано и фоном.
- **Domain-скил не отменяется.** `1md-read` / `1md-search`, diagnosing и code-скилы
  ведут ТВОЮ работу; `1codex` добавляет cross-model взгляд поверх. Оба.
- **Один прогон = один вопрос** с ожидаемым влиянием и проверяемым результатом.
- **Проверка чужой работы — только свежим `task`** с исходными критериями и
  путями. Транскрипт исполнителя — самоотчёт, не evidence.
- **Решение → blind-советник:** decision packet без твоего вывода; вопрос
  стабилен — запускай и продолжай работу →
  [`references/advisor.md`](references/advisor.md).
- **Дорогая коррелированная ошибка → Claude × Codex blind + твой diff**;
  `1fresh-eyes` остаётся in-family проверкой →
  [`references/model-mixing.md`](references/model-mixing.md).

## Роутер: куда попадёт результат?

Оплаченный прогон всегда пишет audit `run_dir`; ось ниже — deliverables Codex.

- **Только ответ/поиск; project edit не нужен** (файлы/веб, советник, ревью) →
  **ревьюер** `codex_review.py`, default `task`, filesystem sandbox read-only.
  `--mode ask` тянет транскрипт для вопроса по диалогу/траектории;
  `--mode review` — негативно смещённый adversarial аудит по транскрипту, не
  навигация. Воркера верифицируй свежим `task` по критериям и diff, не его
  транскриптом.
- **Ревью git-дифа** → `--mode diff`: НАТИВНЫЙ ревьюер движка (`review/start`),
  а не наш промпт. Таргеты: без флагов — незакоммиченное, `--base REF`,
  `--commit SHA`, а свободный текст даёт `custom` с инструкциями. Оговорка:
  усилие там наследуется из конфига движка, `--effort` не действует (ledger
  пишет `inherit`). Диф большой — сузь таргет: на всём дереве ревьюер уходит
  на сотни шагов.
- **Markdown evidence-packet** («сходи в knowledge/vault, принеси адреса») →
  Codex **`md-scout`** через `run_md_scout.py`: read-only executor
  `1md-search`, без вердиктов/правок; wrapper может сохранить JSON через
  `--out`. Обычный платный index warmup заранее разрешён и обязателен: scout
  греет derived cache и повторяет query, не меняя source. Его `terra`+`medium` —
  ярус самого инструмента, не моста; тот же корпус можно blind разведать
  Claude-скаутом. Приёмка md-scout — по пакету, не по exit
  code: непустой `packet` + `runtime.returncode: 0` + `corpus_unchanged: true`
  валиден и при exit 1 — ненулевой exit даёт также дословная сверка цитат
  (`evidence_errors`; скаут любит «…»-сокращения). Такие цитаты проверь
  первичкой по адресам, пакет не выбрасывай.
- **История позиции владельца по корпусу цитат** («как менялась», «всё, что он
  говорил про X») → `codex_recall.py`: читающая модель уходит в своё окно и
  возвращает переваренный ответ на пару килобайт вместо десятков команд и
  килобайтов выдачи в твоё. Процедурой recall владеет `1chat-recall` — здесь
  только маршрут; обычный вопрос к корпусу закрывает его локальный поиск за
  секунды, сюда идут только история и полнота. Способ поиска модели не диктуй:
  замер 2026-08-12 — навязанный протокол стоил вдвое и не нашёл больше.
- **Артефакты в отдельную рабочую папку, без project edit** («изучи X, напиши
  отчёт») → **исследователь** `codex_investigate.py`. Built-in filesystem writes
  sandboxed в `run_dir/out/` + system temp; postflight проверяет drift проекта.
  Забирай `result.json` и `out/`.
- **Файлы проекта — Codex должен внести правки** → `codex_orchestrate.py`.
  Воркер работает в своём git worktree, волна закрывается сама. Перед запуском
  прочитай [`references/fleet.md`](references/fleet.md): нарушенный там контракт
  стоит потерянных правок.

## Ты оркестратор: веер идёт на любой роли

Множественность — не свойство пишущего флота. Веер разворачивается на всех трёх
ролях, и роль решает, чем расплачиваешься:

| Веер | Чем платишь | Ручка |
|---|---|---|
| **Читающие** — каждому свой участок корпуса, диска, веба | ничем: read-only, деревья не нужны | несколько `codex_review.py` фоном; корпус `.md` — `md-scout` |
| **Ревьюеры** — каждому своя ось критики одного артефакта | ничем; расхождение осей — находка | `codex_review.py` фоном, узкий вопрос каждому |
| **Пишущие** — каждому своя группа задач | диском: дерево на воркера | один `codex_orchestrate.py` на волну |

Общее для всех трёх: узкий вопрос каждому, **одна схема выхода**, синтез твой.
Твоё дело — траектория и волевые решения, а не пересказ чужих шагов; контракт
волны (карта до запуска, барьеры, отчёт после) держит `1orchestration`, здесь
только то, чем Codex отличается.

**У пишущих единица деления — не задача, а группа задач.** Дерево воркера
стоит выкладки проекта: 22 МБ на текстовом репозитории, 650–780 МБ на большом
фронтенде. Поэтому двадцать дел — это не двадцать воркеров, а четыре по пять,
и каждому разрешена своя делегация: `subagents: true` кладёт это разрешение в
его контракт, и его субагенты работают внутри его дерева, не в общем. Число
воркеров выбирай по цене дерева и связности работы, не по числу дел; связную
работу (одна фича, один слой) не дроби вовсе — она дешевле целиком у одного.

Делегация нужна явным словом: живой системный промпт движка молчит про
субагентов, пока их не попросят — «Do not spawn sub-agents unless the user or
applicable AGENTS.md/skill instructions explicitly ask». У движка для этого своя
команда (`spawn_agent`, `followup_task`, `wait_agent`, `list_agents`) и
`fork_turns` — сколько контекста уходит вниз. Независимым взглядом субагенты не
являются: они наследуют рамку родителя.

**Глубина** — один тяжёлый прогон: `--effort max` — «maximum reasoning depth
for the hardest problems» по каталогу движка; `--effort ultra` — тот же
максимум плюс «automatic task delegation», то есть ту же команду движок
разворачивает сам. Одиночному тяжёлому вопросу делегация не нужна и только
размывает ответ.

Ширину не подменяй глубиной: пять узких прогонов почти всегда информативнее
одного `ultra` по всему сразу. Механика фона — «Фон» ниже.

## Советник — момент и диалог

Зови по событию: развилка, коррекция пользователя, труднообратимость, 2 круга
без сходимости. `ask` нужен только для намерения/истории/траектории: транскрипт
заякоривает. `--dialog --topic` создаёт персистентный тред;
`--continue THREAD_ID` сохраняет контекст. Независимая проверка — свежий тред.
Глубина — [`advisor.md`](references/advisor.md); чужие и старые треды —
[`threads.md`](references/threads.md).

## Вход: как писать задание

**Опиши желаемый результат, а не путь к нему.** Codex — не исполнитель твоего
плана: у него свои скилы, свой поиск и своё чтение файлов, и он сам погрузится в
контекст. Расписанные шаги отнимают у него именно ту работу, которую он делает
лучше пошагового следования, и превращают его в дорогой автокомплит.

Четыре блока, которые движок ждёт (`learn.chatgpt.com/guides/best-practices`,
сверено 2026-08-14):

| Блок | Что в нём | Частый провал |
|---|---|---|
| **Цель** | что должно измениться или появиться | вместо цели — список действий |
| **Контекст** | какие файлы, папки, доки, ошибки важны | вставленное содержимое файлов вместо путей |
| **Границы** | что обязано сохраниться, чего делать нельзя | границы не названы, и он решает сам |
| **Готово, когда** | по чему проверяется результат | «сделай хорошо» без проверяемого условия |

Дальше — только то, чего он не восстановит сам:

- **Самодостаточность.** Диалога с владельцем он не видит: принятые решения и
  неочевидную project-дельту назови, каждую — один раз.
- **Долговременные правила не в промпт**, а в `AGENTS.md` зоны или скил: движок
  сам называет перегруз промпта durable-правилами типовой ошибкой.
- **Дай ему увидеть свою работу** — команду сборки или теста, если она
  неочевидна. Без неё он не может проверить себя и сдаёт непроверенное.
- **Многошаговое — сперва план.** На сложной или неоднозначной задаче попроси
  план до правок: движок называет пропуск планирования типовой ошибкой.
- **Форма выхода**, а в веере — одна схема на всех. Нужный Codex skill назови.
- Анализу запрети edits; работе дай самой довести критерии.

Доки Codex живут на `learn.chatgpt.com/docs`; старые адреса
`developers.openai.com/codex/*` туда редиректят.

## Среда субагента — инструкции тоже промпт

Инструкции собираются шире, чем «AGENTS.md проекта»: сперва глобальный
`~/.codex/AGENTS.override.md` или `AGENTS.md`, затем по каталогам от корня репо
до cwd, ближний перекрывает дальний, и на всю склейку есть лимит. Скилы
приходят из repo/user/admin/system, плагины приносят свои скилы, MCP и hooks, а
hooks добавляют контекст или блокируют действие. На этой машине глобальный
AGENTS, плагины и hooks уже включены — «чистого» прогона не бывает.

Что модель реально увидит, печатает `codex debug prompt-input` — бесплатно, без
прогона: системные блоки, скилы, плагины и склеенный AGENTS.

Bridge владеет built-in filesystem profile и postflight, не исчерпывающим
каталогом capabilities. Внешние MCP могут жить вне sandbox; их наличие не
разрешает side effects в non-write профиле.

**Обратный вызов в Claude вешает прогон намертво.** У Codex в live-окружении
есть MCP-сервер, ведущий обратно в Claude (`claude-mcp`/`claude_ask`). Если он
им воспользуется, ответить некому: оба ждут друг друга. Замер 2026-07-28 —
**9 часов** тишины, `last=mcpToolCall claude-mcp/claude_ask`, `steps` замерли.
Поэтому клади прямой запрет в задание ЛЮБОГО прогона, не только долгого: «не
вызывай инструменты claude-mcp, работай файлами и shell». Цена от длины не
зависит, а у Codex есть свой скил `1claude-mcp`, который по умолчанию велит
звать блокирующий `claude_ask`. Approval-политика на эти инструменты в конфиге
стоит, но отклонит ли она рекурсивный вызов — непроверено (живой пробник
означал бы намеренный deadlock); мост его не блокирует. Запрет в задании —
дешёвая защита, которой управляешь ты.

## Команды

```bash
B=/Users/triton/Documents/GitHub/agentic-research/experiments/codex-bridge
# Ревьюер/советник (read-only, без транскрипта):
$B/.venv/bin/python $B/codex_review.py "САМОДОСТАТОЧНОЕ ЗАДАНИЕ" --project "$PWD"
# Диалог и продолжение:
$B/.venv/bin/python $B/codex_review.py "ВОПРОС" --dialog --topic "ТЕМА" --project "$PWD"
$B/.venv/bin/python $B/codex_review.py "УТОЧНЕНИЕ" --continue THREAD_ID --project "$PWD"
# Транскрипт сессии:
$B/.venv/bin/python $B/codex_review.py --mode review --project "$PWD"
$B/.venv/bin/python $B/codex_review.py --mode ask --question "ВОПРОС" --project "$PWD"
# Нативный ревью git-дифа (движок, не промпт):
$B/.venv/bin/python $B/codex_review.py --mode diff [--base REF | --commit SHA] --project "$PWD"
# Прогон не получается — сперва это, кредитов не тратит:
$B/.venv/bin/python $B/codex_review.py --doctor --project "$PWD"
# История позиции владельца по корпусу цитат (процедура — у `1chat-recall`):
$B/.venv/bin/python $B/codex_recall.py "ВОПРОС" --project "$PWD"
# Доска диалогов / md-scout / исследователь:
$B/.venv/bin/python $B/codex_threads.py list --project "$PWD"
(cd /Users/triton/Documents/My_projects/md-tools && uv run python scripts/run_md_scout.py КОРПУС --question "ВОПРОС" [--path-include GLOB] [--out FILE.json])
$B/.venv/bin/python $B/codex_investigate.py "ЗАДАНИЕ + формат выхода" --project "$PWD"
# Флот воркеров (правит файлы проекта) — codex_orchestrate.py: см. references/fleet.md
```

Редкий флаг или полный CLI surface: `<python> <entrypoint>.py --help`; не
копируй каталог сюда. Каждый **оплаченный** прогон создаёт audit `run_dir` в
`<проект>/_workspace/codex-artifacts/<run_id>/`; `--run-dir` — override. Успех
такого прогона — только `status=completed` и `ok=true`; failure/partial
response не синтезируй как готовый результат. Читающие команды (`codex_threads.py
list`, `codex_progress.py`, любой `--dry-run` или `--print-prompt`) ни `run_dir`,
ни этот статус не дают — судить их по нему нечем. `--doctor` отвечает на вопрос
«почему не работает» до траты кредитов: аккаунт, эффективный конфиг и
наследуемый `service_tier` (мост его не шлёт, так что это единственное место,
где видно, на каком тире пойдёт прогон). У `run_md_scout.py` своя схема —
критерий приёмки назван в его пункте роутера.

## Фон — умолчание, а не режим для долгих

**Любой оплаченный turn запускай через `Bash` с `run_in_background: true`.** Не
«если покажется долгим»: заранее ты этого не знаешь, а форграундный вызов молча
вешает сессию на минуты — пользователь видит замерший экран и не понимает, идёт
работа или всё умерло. Фоновый запуск снимает это без единой строки кода:
харнесс сам присылает **одно** уведомление о завершении, а ты тем временем
продолжаешь работу или разговор.

Запустив, сразу скажи пользователю: Codex работает фоном и **в списке агентов
не виден** (это фоновый процесс, не Agent-субагент) — назови `RUN_DIR` и ручку
проверки `codex_progress.py RUN_DIR`. Иначе «запустил Codex» при пустом списке
агентов читается как ложь.

`Monitor` для этого НЕ нужен и вреден: каждая его строка становится сообщением и
съедает контекст — то самое окно, ради экономии которого субагент и существует.
Его собственная документация отправляет за одним уведомлением к фоновому Bash.

Форграунд остаётся только для мгновенного и бесплатного: `--dry-run`,
`codex_threads.py list`, `--help`.

Перед worker→verify→fix или многочасовой задачей прочитай
[`references/orchestration.md`](references/orchestration.md). Не ставь pipe на
background-команду; сохрани `RUN_DIR` и task id; межагентные данные — через диск.

**«Он завис или думает?»** Прогон пишет свою активность на диск: выполненные
команды, изменённые файлы, шаги, план. Смотри её **сводкой**, а не журналом:

```bash
$B/.venv/bin/python $B/codex_progress.py "$RUN_DIR"          # один прогон
$B/.venv/bin/python $B/codex_progress.py --board "$PWD"      # все прогоны, по строке
```

Читает `steps`, `idle_sec`, последний шаг, а у флота — `active` и `stalest`
(воркер, молчащий дольше всех). `--board` отвечает на другой вопрос — «кто из
моих запусков ещё жив и кто встал»: три сводки подряд дали бы тот же ответ
ценой трёх выхлопов в окно. Он же кричит `ДЕРЕВЬЯ-ВИСЯТ`, если волна закрылась
без уборки. Субагент существует, чтобы **беречь твоё контекстное окно**: по
умолчанию активность скрыта, заглядывай по подозрению на зависание, а не по
расписанию. Сырой `events.jsonl` в окно не читай.

## Stop

- Не зови только для точной одноступенчатой механики: известная команда,
  короткое чтение или patch без broad retrieval, независимого review,
  investigation, decision либо delegated implementation.
- Цель или scope изменились после запуска — фоновый ответ stale: не синтезируй
  его, перезапусти.
- Write footprint неизвестен — не запускай флот; сперва read-only разведка.
- 2–3 круга verify→fix без сужения носителей — стоп, блокер пользователю.
- **Волна не закрыта, пока не названы `wave.cleanup_done` и `wave.kept_branches`
  из отчёта.** Не «помни про уборку»: непустые ветки — незабранная работа,
  висящее дерево — выкладка проекта. Поля разобраны в `fleet.md`.
