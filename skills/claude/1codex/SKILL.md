# 1codex — Codex как второй мозг

Порог вызова низкий намеренно: сомнение — уже повод. Лишний вызов стоит
прочитанного и отвергнутого совета, пропущенный — твоей ошибки, которую никто
не поймал.

Backend:
`/Users/triton/Documents/GitHub/agentic-research/experiments/codex-bridge/`,
python — `<backend>/.venv/bin/python`. Биллинг идёт через ChatGPT-подписку;
entrypoints сами вырезают billing keys из env. Остальная runtime-правда (tier,
ledger, профили sandbox, версии) живёт в `<backend>/README.md` и меняется
вместе с кодом — сюда её не копируй, устареет молча.

## Роутер: куда попадёт результат?

Ось — место, куда падают deliverables.

| Что нужно | Чем звать |
|---|---|
| ответ, поиск, ревью — **project edit не нужен** | `codex_review.py`, default `task`, sandbox read-only |
| ревью git-дифа | `codex_review.py --mode diff` — НАТИВНЫЙ ревьюер движка, не наш промпт. Усилие там НАСЛЕДУЕТСЯ из конфига движка (`--effort` не действует, ledger пишет `inherit`); большой диф сузь `--base`/`--commit`, на всём дереве он идёт долго |
| вопрос по нашему диалогу или траектории сессии | `--mode ask` (тянет транскрипт); `--mode review` — негативно смещённый аудит хода, не навигация |
| markdown-evidence «сходи в knowledge, принеси адреса» | `run_md_scout.py` — read-only executor `1md-search`, без вердиктов; приёмка по пакету, не по exit code (критерий — в самом инструменте) |
| артефакты в свою папку, **без project edit** | `codex_investigate.py`; забирай `result.json` и `out/` |
| **файлы проекта — Codex вносит правки** | `codex_orchestrate.py`; сперва прочитай `fleet.md` |

**Веер вместо одного прогона** — когда работа делится. Читающим по своему
участку, ревьюерам по своей ОСИ критики: расхождение осей и есть находка, а
пять одинаковых прогонов её не дают. **Схема выхода одна на весь веер** — иначе
пять форм ответа нормализуешь в своём окне, ради экономии которого веер и
заводился.

## Ярус

`gpt-5.6-sol` + `xhigh` — **дефолт на всё**, ничего не передавай. `--model gpt-5.6-luna` —
**тупое и большое**: переименования, форматирование, перенос по образцу, где
нужна пропускная способность, а не суждение. Решение владельца 2026-08-14: «сол
экстра хай всегда, луна только для тупых и больших заданий»; `max`/`ultra`
сняты — «не будем использовать, чтобы было проще».

**Кредиты не жалей:** лимит подписки не переносится, «дешевле» — не критерий.

**Дерево и тред — только у пишущего воркера** (инвариант владельца 2026-08-14):
чтение, ревью и поиск обходятся без обоих. Разговор с советником — явный
`--dialog`.

## Вход: как писать задание

Дефолт «расписать шаги» работает против тебя вдвойне: план съедает твоё окно
ради работы, которую ты и отдавал, а исполнитель со своими скилами превращается
в дорогой автокомплит. Отдавай результат и границы — и **проблему, а не
разжёванное решение**.

| Блок | Что в нём | Частый провал |
|---|---|---|
| **Цель** | что должно измениться или появиться | вместо цели — список действий |
| **Контекст** | какие файлы, папки, доки, ошибки важны | вставленное содержимое файлов вместо путей |
| **Границы** | что обязано сохраниться, чего делать нельзя | границы не названы, и он решает сам |
| **Готово, когда** | по чему проверяется результат | «сделай хорошо» без проверяемого условия |

**Самодостаточность — единственное, чего он не восстановит сам.** Диалога с
владельцем Codex не видит: принятые решения и неочевидную project-дельту назови
явно, каждую один раз. Остальное — его работа, а не твоя опека.

Твоё задание — не весь его вход: Codex склеивает глобальный и папочные
`AGENTS.md`, свои скилы, плагины и hooks. Сомневаешься, что он получит, —
`codex debug prompt-input` печатает это бесплатно, до траты.

**`read-only` — профиль моста, а не гарантия неподвижности диска.** Мост владеет
built-in filesystem-профилем, не исчерпывающим каталогом capabilities: внешние
MCP могут жить вне sandbox. Postflight-сверка диска есть только у исследователя
и у флота — у ревьюера её нет вовсе. Их наличие не разрешает side
effects в непишущем профиле — запрещай их заданием.

## Дисциплина запуска

- **Codex назван или триггер сработал** — разрешения повторно не спрашивай,
  запускай рано и фоном.
- **Любой оплаченный turn — через `Bash` с `run_in_background: true`.** Заранее
  ты не знаешь, что окажется долгим, а форграунд вешает сессию на минуты.
  Запустив, скажи пользователю `RUN_DIR` и что Codex **в списке агентов не
  виден** — это фоновый процесс, не Agent-субагент. Тем же ходом повесь витрину
  завершений (`codex_watch.py`, [`references/orchestration.md`](references/orchestration.md)):
  владелец должен видеть в панели десктопа, что агенты работают, и получать
  строку, когда каждый кончил.
- **В задание ЛЮБОГО прогона клади запрет обратного вызова:** «не вызывай
  инструменты claude-mcp, работай файлами и shell». У Codex есть свой скил
  `1claude-mcp` с блокирующим `claude_ask`; ответить ему некому — замер
  2026-07-28 дал 9 часов тишины. Запрет в задании — единственная защита,
  которой управляешь ты.
- **Один прогон = один вопрос** с ожидаемым влиянием и проверяемым результатом.
- **Проверка чужой работы — только свежим `task`** с исходными критериями и
  путями. Транскрипт исполнителя — самоотчёт, не evidence.
- **Труднообратимое решение** (внешний эффект, миграция, правка глобального
  скила, выбор, на котором строится остальное) → **Claude × Codex blind + твой
  diff**; `1fresh-eyes` остаётся in-family проверкой.

```bash

$B/.venv/bin/python $B/codex_review.py "САМОДОСТАТОЧНОЕ ЗАДАНИЕ" --project "$PWD"
$B/.venv/bin/python $B/codex_review.py "ВОПРОС" --dialog --topic "ТЕМА" --project "$PWD"
$B/.venv/bin/python $B/codex_review.py "УТОЧНЕНИЕ" --continue THREAD_ID --project "$PWD"
$B/.venv/bin/python $B/codex_review.py --mode diff [--base REF | --commit SHA] --project "$PWD"
$B/.venv/bin/python $B/codex_review.py --doctor --project "$PWD"   # не работает — сперва это; он же считает след моста снаружи. Кредитов не стоит
$B/.venv/bin/python $B/codex_threads.py list --project "$PWD"
$B/.venv/bin/python $B/codex_progress.py "$RUN_DIR" [--steer "ТЕКСТ"] [--worker ID]
$B/.venv/bin/python $B/codex_progress.py --board "$PWD"   # доска идёт ОДНА, без RUN_DIR
$B/.venv/bin/python $B/codex_watch.py watch "$RUN_DIR"    # витрина: строка на каждое завершение — вешай нативным Monitor
$B/.venv/bin/python $B/codex_watch.py look "$PWD"         # «над чем они там» — снимок живых агентов по запросу владельца
$B/.venv/bin/python $B/codex_investigate.py "ЗАДАНИЕ + формат выхода" --project "$PWD"
(cd /Users/triton/Documents/My_projects/md-tools && uv run python scripts/run_md_scout.py КОРПУС --question "ВОПРОС")
# Флот воркеров — codex_orchestrate.py: см. references/fleet.md
```

Редкий флаг или полный CLI surface: `<python> <entrypoint>.py --help`. Успех
оплаченного прогона — только `status=completed` и `ok=true`; failure или partial
response не синтезируй как готовый результат. `--dry-run` создаёт run_dir со
`status=validated` — это план, не результат.

## Stop

- Write footprint неизвестен — не запускай флот; сперва read-only разведка.
- 2–3 круга verify→fix без сужения носителей — стоп, блокер пользователю.
- **Волна не закрыта, пока не названа её квитанция из отчёта** — поля и что
  значит каждое пустое: `fleet.md`, «Закрытие волны». Уборка не заканчивается
  словом «убрал».
- **Прогон не закрыт, пока не назван его эффект:** одной строкой — что ответ
  Codex изменил в твоём решении либо почему не изменил. Запуск, пересказ ответа
  и «учёл» эффектом не являются. (Выведено аудитом 2026-08-14, не слова
  владельца.)
