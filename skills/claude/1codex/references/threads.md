# Треды: статусная доска, подхват, чистка

Читай, когда: заходишь в проект, где мог работать другой агент (или прошлая
оборванная сессия); хочешь продолжить чужой/старый диалог с Codex; диалоги
накопились и пора чистить.

## Доска статусов

Append-only реестр `<проект>/_workspace/codex-artifacts/dialog-threads.jsonl`
(события `start` — с темой и сессией, `continue`, `archive`). Смотреть не сырой
файл, а свёртку:

```bash
B=/Users/triton/Documents/GitHub/agentic-research/experiments/codex-bridge
$B/.venv/bin/python $B/codex_threads.py list --project "$PWD"   # (+ --json)
```

**Доска моста — не все треды Codex.** В неё попадает только то, что завёл мост
в этом проекте; сессии владельца в Codex Desktop и в терминале там не значатся
вовсе. Их печатает `codex_threads.py mine` — чтение общего store `~/.codex`
(тот же, что видит Desktop), с именем, временем, папкой и веткой; кредитов не
тратит, `--all-projects` снимает фильтр по проекту. Это ответ на «что у меня
сейчас открыто с Codex» и способ подхватить тред, о котором доска не знает. `--dialog` без `--topic` берёт темой первые 80 симв. задания — **для
диалога, который может пережить сессию, задавай `--topic` явно**: это то, что
увидит следующий агент. Тема уходит и в движок (`thread/name/set`), поэтому её
видно в Codex Desktop и в нативном `thread/list` — безымянный тред там найти
нечем.

## Ориентация нового агента (не читая переписку)

1. `codex_threads.py list` → тема, свежесть, чья сессия, путь последнего run.
2. «Где остановились» = `final.md` последнего run — компактный последний ответ
   Codex, НЕ вся переписка. Нет `final.md` (ход упал) → `result.json` там же
   несёт ошибку.
3. Продолжить: `codex_review.py "реплика" --continue THREAD_ID` — контекст
   треда цел, Codex помнит всё сам; пересказывать историю не нужно.

## Кто чей тред — правила

Раздел работает на два момента: **подхватить прерванное** (ремонтный круг,
оборванная сессия) и **сориентироваться, не читая переписку**. Вне этих двух
доступ к чужому треду ценности не имеет — заводи свой. Носитель обмена между
агентами — диск (`run_dir`, `final.md`, findings путём), тред лишь экономит
разогрев уже прогретого исполнителя.

- **Чужой живой тред не трогай**: свежая активность другой сессии (часы, не
  дни) → не продолжай, не архивируй, не «исправляй»; для своей задачи заведи
  свой тред.
- **Подхват после обрыва — норма**: сессия-владелец оборвалась (свет, kill,
  compaction), а задача передана тебе или явно продолжается пользователем →
  продолжай её треды через `--continue`, это и есть смысл персистентности.
- Один живой диалог на тему; thread_id — ручка наравне с RUN_DIR: называй его
  в видимой заметке, если диалог не закончен к концу хода.
- `--continue-foreign` (тред не из реестра проекта) — осознанный override;
  после первого такого продолжения тред «усыновляется» реестром (с темой — дай
  `--topic`) и дальше продолжается обычным `--continue`. Архивация чужого
  треда его НЕ усыновляет — provenance дают только start/continue.
- **Право записи на тред одно.** Продолжение треда, загруженного приложением
  Codex, падает `-32600: already has an active writer`; ход не начинается,
  кредитов не стоит. Это заявленный инвариант движка (`codex-rs/app-server/
  README.md`, коммит «Enforce single-writer ownership», 2026-07-23), отобрать
  writer нечем: лок уходит с выгрузкой треда (~30 мин без подписчиков) или с
  выходом приложения. Автор треда не важен — свой тред, открытый владельцем,
  закрыт и для тебя. Пометка «запись занята» в `mine` информационная: она
  подтверждает «занято», но её отсутствие ничего не гарантирует — дешёвый и
  честный ответ даёт сама попытка.
- **Ремонт занятого треда — свежий воркер, не форк.** Тред прогрет, но занят →
  дешевле и честнее новый прогон с findings путём, чем ветвление. `thread_fork`
  берётся только когда нужен именно накопленный контекст, и тогда он —
  **одноходовая производная**: получил ответ → оба id и результат в `run_dir`
  волны → форк архивируй. Иначе у владельца копятся одноимённые чаты-двойники,
  у которых нет единственного актуального владельца: 91 форк за трое суток уже
  лежит в его store, из них один создан этим правилом.
- **Чужая сессия — источник для чтения, не поверхность контракта.** Дословная
  переписка лежит в `~/.codex/sessions/<Y>/<M>/<D>/rollout-*-<thread_id>.jsonl`
  и пишется в реальном времени; `session_meta` даёт `originator`
  (`Codex Desktop` — владелец, `codex_python_sdk` — мост), `cwd` и
  `forked_from_id`. Формат вендором интерфейсом не объявлен и уже дрейфовал —
  читай для диагностики и ориентации, не строй на нём то, что должно пережить
  обновление приложения.

## Чистка — правило двух дней

Диалог с активностью старше **48 часов** считается брошенным — архивируй:

```bash
$B/.venv/bin/python $B/codex_threads.py archive --stale --project "$PWD"
# или точечно: ... archive THREAD_ID --project "$PWD"
```

- Архив штатный (SDK `thread_archive`) и **обратимый**:
  `codex_threads.py unarchive THREAD_ID` (доска снимет `[archived]`). Ошибка
  на одном треде не обрывает батч (`rc=1` при частичном провале); `--stale`
  отказывает на битом реестре — чини или архивируй точечно.
- Живой тред другой сессии под правило не попадает (свежая активность);
  задача ещё идёт, но пауза >2 дней — сначала прочитай последний `final.md`,
  потом решай.
- Руками файлы в `~/.codex` НЕ удалять (общий store с Desktop); глубокая
  чистка диска `~/.codex` — отдельная отложенная задача владельца.
