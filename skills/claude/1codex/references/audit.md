# Аудит: варианты входа

**Вход:** ты отдаёшь Codex проверку сделанного и выбираешь, как его запустить.
**Выход:** прогон, чей вердикт опирается на запуск, а не на чтение.

```bash
B=/Users/triton/Documents/GitHub/agentic-research/experiments/codex-bridge
$B/.venv/bin/python $B/codex_launch.py agent --name аудитор-<суть> --run-dir RUN_DIR --prompt-file ЗАДАНИЕ.md --project "$PWD"
$B/.venv/bin/python $B/codex_launch.py agent --name ревью-дифа --run-dir RUN_DIR --project "$PWD" -- --mode diff [--base REF | --commit SHA]
```

- Дефолтный режим проверяет что угодно по твоему заданию.
- `--mode diff` — нативный ревьюер движка вместо твоего задания. Усилие он
  берёт из конфига движка, `--effort` на него не действует, а на всём дереве
  идёт долго — сужай `--base` или `--commit`. Роли и общих правил моста он не
  получает, а задания не принимает: нужны границы поручения — бери обычный
  аудит по файлу задания.
- `--scratch` даёт аудитору свежую копию проекта вместо самого проекта. Бери,
  когда проверки оставляют следы в дереве или рядом ещё пишут: копия не
  меняется под ним во время хода. На большом репозитории она стоит полминуты,
  удаляется после хода, с `--mode diff` не работает.
- Интернет открыт в любом режиме: сверку с внешней документацией заказывай
  прямо.
- `--mode review` — намеренно негативно смещённый аудит хода сессии. Для поиска
  слабых мест годится, для навигации даёт ложные возражения.
- Чужую работу проверяй свежим прогоном с исходными критериями и путями:
  транскрипт исполнителя — самоотчёт, не evidence.
- Мост диск не сверяет: правку аудитора вопреки «файлы не меняй» увидишь только
  сам, в `git status` после хода.
