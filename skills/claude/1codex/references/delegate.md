# Исполнение: Codex делает работу

**Вход:** работа отдаётся целиком, а не выносится на суждение. **Выход:**
результат в проекте либо артефакт, который ты забрал и проверил.

Codex-писатель — такой же субагент, как твой собственный: один прогон, полный
доступ, запись прямо в проект. Отдавай ему то, что отдал бы своему пишущему
субагенту (владелец 2026-09-27: «как рабочих и как писателей тоже»).

| Куда падает результат | Что написать в задании |
|---|---|
| в файлы проекта | зону: какие файлы и папки менять, что не трогать |
| отчёт, черновик, данные | форму выхода; место по умолчанию — `out/` прогона, мост говорит его Codex сам |
| за пределы проекта: пакеты, домашняя папка, система | что именно можно менять; ответ обязан перечислить изменённое — git проекта этого не видит |
| адреса в markdown-корпусе | не Codex-прогон: `(cd /Users/triton/Documents/My_projects/md-tools && uv run python scripts/run_md_scout.py КОРПУС --question "ВОПРОС")` — read-only executor `1md-search`, без вердиктов; приёмка по пакету, не по exit code |

Вход один на всё — `codex_launch.py agent` (команда в `SKILL.md`).

## Несколько писателей разом

Каждый писатель — своя фоновая карточка со своим `--name`; `tasks.json` и волн
больше нет. Зоны и соседей называешь словами задания (правило в `SKILL.md`),
и мост в это не вмешивается: пересечение ловишь ты, когда смотришь дифф.

**Единица деления — группа задач, а не задача:** двадцать дел это четыре
писателя по пять. Связную работу — одну фичу, один слой — не дроби вовсе:
целиком у одного дешевле. Число писателей выбирай по связности работы и по
тому, сколько диффов ты потом прочтёшь, а не по числу дел.

Делегация внутрь писателя нужна явным словом: системный промпт движка запрещает
субагентов, пока их не попросят. Его субагенты пишут в то же дерево, поэтому
и им нужны зоны; независимым взглядом они не являются — наследуют рамку
родителя.

**Веер проверок или разведки — с одной схемой выхода.** Пять форм ответа ты
нормализуешь в своём окне, ради экономии которого веер и заводил. Минимум,
ниже которого возвраты снова читаются, а не просматриваются: первая строка —
вердикт; дальше по пункту на вывод — прибор и его exit code дословно, адрес
`путь:строка`, блокеры отдельно. Логи целиком не заказывай: они и так лежат в
`run_dir`. Писателю форму возврата задаёт задача: результат писателя — дифф, а
не отчёт.

Нужен ремонтный круг в том же контексте — запускай первый ход с `--dialog`,
тогда поправка уходит через `--continue THREAD_ID` (тем же `--model`). Без
диалога ремонт — свежий прогон с путём к `final.md` прошлого и строкой «вот что
не так».

## Приёмка

- Готовность подтверждает не ответ Codex, а твоя сверка: дифф его зоны против
  критерия задания и прибор, который критерий проверяет (тесты, сборка, линт).
  Проверку, без которой работа не готова, пиши в «Готово, когда»: писатель
  прогонит её сам, но зачёт — твой повторный запуск или чтение её вывода.
- Изменённое сверх зоны не откатывай вслепую: сначала пойми, чьё оно — рядом
  писали другие.
- Существенную или спорную работу писателя проверяет не он сам: аудит —
  отдельным свежим прогоном (`audit.md`) после того, как правки легли. Обычную
  закрывает твоя сверка диффа и прибора.

## Остановка и остатки

`TaskStop` прерывает ход штатно, но сделанное до остановки уже лежит в дереве
недописанным: прочитай `git status` и дифф зоны, прежде чем перезапускать.

Ветки `codex-fleet/*` и деревья `~/.codex-bridge/worktrees` в других проектах
остались от прежнего флота — это незабранная работа, разбирай её, а не удаляй.
Деревья под `~/.codex/worktrees` создаёт Codex Desktop: там может лежать
незабранная работа владельца — руками не удаляй.
