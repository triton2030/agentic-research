# Исполнение: результат, писатели, ремонт

**Вход:** работа отдаётся Codex целиком, а не выносится на суждение.
**Выход:** результат в проекте либо артефакт, который ты забрал и проверил.

## Куда падает результат

| Результат | Что написать в задании |
|---|---|
| в файлы проекта | зону: какие файлы и папки менять, что не трогать |
| отчёт, черновик, данные | форму выхода; место по умолчанию — `out/` прогона, мост говорит его Codex сам |
| за пределы проекта: пакеты, домашняя папка, система | что именно можно менять; ответ обязан перечислить изменённое — git проекта этого не видит |
| адреса в markdown-корпусе | не Codex-прогон: `(cd /Users/triton/Documents/My_projects/md-tools && uv run python scripts/run_md_scout.py КОРПУС --question "ВОПРОС")` — read-only исполнитель `1md-search`, без вердиктов; приёмка по пакету, не по exit code |

## Несколько писателей

- Каждый писатель — своя фоновая карточка со своим `--name`. Зоны и соседей
  задают только слова задания; пересечение мост не ловит, его ловишь ты в
  диффе.
- Число писателей выбирай по связности работы и по тому, сколько диффов потом
  прочтёшь, а не по числу дел: двадцать дел — это четыре писателя по пять.
- Делегация внутрь писателя нужна явным словом: системный промпт движка
  запрещает субагентов, пока их не попросят. Его субагенты пишут в то же дерево,
  поэтому и им нужны зоны; независимым взглядом они не являются — наследуют
  рамку родителя.
- Веер проверок или разведки — с одной схемой выхода, иначе пять форм ответа ты
  нормализуешь в своём окне. Минимум: первая строка — вердикт; дальше по пункту
  на вывод — прибор и его exit code дословно, адрес `путь:строка`, блокеры
  отдельно. Логи целиком не заказывай: они лежат в `run_dir`. Результат
  писателя — дифф, а не отчёт.

## Ремонтный круг

Нужна поправка в том же контексте — запускай первый ход с `--dialog`, тогда
поправка уходит через `--continue THREAD_ID` тем же `--model`. Без диалога
ремонт — свежий прогон с путём к `final.md` прошлого и строкой «вот что не так».

## Остановка и остатки

- `TaskStop` прерывает ход штатно, но сделанное до остановки уже лежит в дереве
  недописанным: прочитай `git status` и дифф зоны, прежде чем перезапускать.
- Ветки `codex-fleet/*`, деревья `~/.codex-bridge/worktrees` и
  `~/.codex/worktrees` могут держать незабранную работу, в том числе владельца
  из Codex Desktop: разбирай её, руками не удаляй.
