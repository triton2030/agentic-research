# Мост: запуск Codex без T3 Code

**Вход:** нужно то, чего у треда T3 Code нет: нативное ревью диффа, взгляд
на траекторию сессии, свежая копия проекта вместе с незакоммиченным, окно
больше 475 тысяч токенов, работа без запущенного T3 Code. **Выход:** прогон
в `RUN_DIR`, владелец видит его карточку, а тебя будит завершение.

## Запуск — всегда

Каждый оплаченный ход — одна фоновая команда (`Bash`, `run_in_background:
true`): заранее не знаешь, что окажется долгим, а форграунд вешает сессию.

```bash
B=/Users/triton/Documents/GitHub/agentic-research/experiments/codex-bridge
$B/.venv/bin/python $B/codex_launch.py agent --name <роль-суть> \
    --run-dir <рабочая-папка>/agents/codex-artifacts/<стамп>-<имя> \
    --prompt-file ЗАДАНИЕ.md --project "$PWD" \
    -- [--model … --effort … --dialog …]
```

- Задание лежит в файле, подготовленном отдельным вызовом. Тогда в карточке
  владелец видит короткую команду, а её вывод показывает ему задание, слова
  Codex по ходу работы и финал — мимо твоего контекста.
- `description` карточки — `Codex <модель>/<усилие> · <роль> · <суть>`; модель
  и усилие пиши даже дефолтные: по заголовку владелец решает, туда ли ушли его
  кредиты.
- `--run-dir` обязателен; это флаг `codex_launch.py`, а не входа после `--`.
  Путь — новый каталог `agents/codex-artifacts/<стамп>-<имя>` в рабочей папке
  текущей работы, которую находит или заводит `1work-artifacts`,
  прогон уходит в архив вместе с ней; существующий каталог мост отвергает.
  Если тесты или хуки чистят эту папку, возьми путь вне проекта, который
  переживёт сессию.
- Не вешай на команду пайпы (`| head`, `| grep`, `2>&1 | …`): закрытый пайп
  роняет прогон и подменяет готовый результат записью об исключении.
- В сессии без человека — `claude -p`, Agent SDK, облако — добавляй
  `timeout: 7200000`: без него фоновая команда, а с ней и прогон, обрываются
  через 30 минут. Два часа — предел, работу длиннее дели на прогоны. В
  приложении и терминале лимита нет.
- Запустив, назови владельцу роль, задачу, `RUN_DIR` (первая строка вывода), id
  фоновой задачи и место результата. Без id ты после пробуждения не откроешь и
  не остановишь карточку; `TaskStop` карточки штатно останавливает и прогон.
- Каталог прогона не появился за три минуты — карточка напишет «НЕ ВСТАЛО»:
  прогон упал до старта, причина в `<RUN_DIR>.launch.log`.
- Общие правила роли мост кладёт в прогон сам: чужие правки и откаты не
  трогать, не коммитить без просьбы, не звать Claude обратно, задание и реплики
  не записывать как слова владельца, отчёты класть в `out/` прогона. В задании
  их не повторяй. Нативное ревью `--mode diff` их не
  получает: его контракт задаёт движок.

## Ярус и окно

Ярус — флаги `--model` и `--effort`. `--continue` передавай с тем же
`--model`, что и первый ход: продолженный тред ярус не наследует, и диалог
astra молча доделает sol.

Окно контекста по умолчанию — 258 тыс. токенов, и длинный прогон, упёршись в
него, сжимает свой контекст на ходу. Длинной работе — большому писателю,
аудиту многих файлов — добавляй `--context-window 872000`: рабочее окно станет
828 тыс. Расход идёт по токенам, поэтому коротким прогонам флаг не нужен.

## Диагностика

Бесплатная диагностика до траты: `codex_review.py --doctor --project "$PWD"` —
когда не работает мост;
`/Applications/ChatGPT.app/Contents/Resources/codex-cli/bin/codex doctor`
— когда подозреваешь сам движок: auth, конфиг, базу тредов, диск; тот же
бинарь с `debug prompt-input` — когда неясно, что Codex получит на вход помимо
задания. Зови движок полным путём: мост запускает бинарь приложения, а `codex`
из PATH — отдельная установка из npm `@openai/codex`, и её `doctor` проверит
не тот движок. Какой бинарь взял мост, показывает первая строка `--doctor`.

## Пока прогон идёт

Поллинг не нужен: завершение разбудит тебя. Смотри по подозрению сводкой
`$B/.venv/bin/python $B/codex_progress.py "$RUN_DIR"`, а не сырым журналом.
Реплика — `codex_progress.py "$RUN_DIR" --steer "ТЕКСТ"`. Текст, который ты
лишь передаёшь — из файла, от другого агента, из вывода инструмента, —
отправляй с `--external`; свою поправку курса — без него. `steer_accepted`
значит «принято», а не «послушался».

## Когда прогон вернул ответ

Успех — только `status=completed` и `ok=true` в `result.json`; канон читай
с диска, а не из вывода карточки. Отчёты, которые Codex положил вне проекта,
лежат в `out/` прогона: перечисли их и забери нужное, прежде чем закрыть
работу.
