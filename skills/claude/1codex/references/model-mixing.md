# Model-mixing: механизм, evidence, протокол

Читай при настройке перекрёстной проверки Claude × Codex или когда нужно
откалибровать cross-model паттерн (кому верить при расхождении, что считать
подтверждением).

## Механизм

Ценность второй model family — **де-корреляция ошибок**, не «характер» модели.
Наблюдения вида «GPT буквальнее, Claude системнее» нестабильны между версиями
— не кодируй их; кодируй операционную независимость: одинаковый вход, blind
первый проход, арбитраж по первичным evidence.

## Измеренные факты (2024–2026, собраны 2026-07-11; пересматривай при смене model lineup)

- **Self-preference bias.** LLM-судьи завышают свои выводы; сила эффекта
  коррелирует со способностью узнавать собственный текст
  (arxiv.org/abs/2404.13076). Механизм — familiarity: судья завышает
  low-perplexity «знакомый себе» текст, даже чужой (arxiv.org/abs/2410.21819).
- **Сдвиг семейный, не только чекпойнтный:** Claude-судьи завышают
  Claude-модели, GPT — GPT, независимо от качества
  (arxiv.org/html/2508.06709v1).
- **Self-attribution.** Монитор мягче к действиям, идущим после
  assistant-turn; триггер — имплицитная рамка, не подпись автора. Поэтому
  blind-передача артефакта как свежей user-задачи без следа авторства — часть
  механизма, не вежливость (arxiv.org/abs/2603.04582).
- **Панель судей из разных семей** бьёт одного большого судью и показывает
  меньше intra-model bias (arxiv.org/abs/2404.18796).
- **Popularity trap.** Голосование похожих моделей усиливает общую
  правдоподобно-неверную ошибку; diversity-отбор работает уже на двух моделях
  (arxiv.org/abs/2510.21513). Команды, усредняющие мнения, проигрывают своему
  лучшему участнику до 37.6% (arxiv.org/abs/2602.01011) → арбитраж по
  evidence, не консенсус и не голос.
- **Асимметрия cross-review** (одно контролируемое исследование, Claude Opus
  4.7 × Codex GPT-5.5, KDD'26): ревью Claude→Codex подняло pass rate
  71.6→89.7%, обратное НАВРЕДИЛО 91.4→82.8%
  (researchgate.net/publication/407032793). Направление может меняться с
  версиями; устойчивое следствие: **чужое ревью — источник findings для
  арбитража оркестратора, никогда не авто-гейт «переделывай»**.

## Протокол blind cross-check

1. **Одинаковый вход обоим**: критерии, evidence-пути, формат выхода
   (verdict / claims / evidence paths / assumptions / unresolved).
2. **Blind**: ни одна модель не видит вывод, rationale или авторство другой до
   первого вердикта. Claude-сторона пишет вердикт в файл
   (`_workspace/…`) — диф воспроизводим; у Codex вердикт уже в run_dir.
3. **Диф оркестратора**: совпадения → подтверждено предварительно; уникальные
   находки каждого; прямые противоречия и разошедшиеся допущения — отдельные
   находки, не шум.
4. **Арбитраж по первичным файлам**, не по голосованию; cross-critique
   (показать модели ответ другой) — только после фиксации обоих независимых
   ответов.
5. **Совпадение ≠ доказательство**: обе модели могли унаследовать твою рамку
   из задания. Для high-blast решений ключевые совпавшие claims сверь по
   файлам сам.
6. **Факт ≠ масштаб**: в каждой находке два claim'а — «что там» (обычно
   подтверждается) и «насколько это страшно» (систематически завышено).
   Живой кейс 2026-07-20: blind-аудит принёс факт `exclude_none`,
   перевернувший диагноз оркестратора (правда), и «49 errors — suite failed» —
   артефакт read-only песочницы самого ревьюера, поданный как провал набора
   тестов. Факт принимай после сверки с первичкой; severity мерь сам от цели
   и blast-radius, не от тона вердикта.
