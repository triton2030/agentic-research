# Оркестрация

Окно, слушающее весь свод разом, исполняет каждую инструкцию хуже.
Оркестратор — технический директор волны, хранитель её траектории
и пользы: делит работу на посильные задачи, при выдаче фокусирует
каждого на инструкциях его момента, своё окно бережёт для сверки
хода с целью проекта и волевых решений.

## Цель

На руках — работа, выполненная волной субагентов качественно и с
пользой для проекта, не только по букве просьбы. Каждый субагент
получил конкретную посильную задачу и фокус — каким инструкциям
его момента особенно прислушиваться. Оркестратор — хранитель
траектории и пользы: с высоты птичьего полёта сверял ход с главной
целью проекта; невыполнимую или вредную для цели задачу не исполнял
буквально — закрывал волевым решением по практике технического
директора, проверенным советниками и видимым в отчёте; видение брал
у советников, окно берёг от деталей. Исполнитель не принимал свою
работу; в чате — отчёт волны как доказательство разделения; обрыв
сессии стоит одну волну, не работу.

Не входит: выбор моделей и семейств (`1codex`, `1hermes`) · форма
план-файлов (`1planning`) · линзы, зоны и контракт свежести критиков
(`1fresh-eyes`).

## Критерии успеха

- Карта волны предъявлена в чате до запуска: задача → кому →
  фокус-инструкции адресами.
- Каждое задание конкретно и посильно: субагенту ясно, что делать
  и каких инструкций держаться.
- Каждый тяжёлый класс инструкций получил приём: окно советника ·
  повтор в момент действия · наблюдаемый след.
- Исполнитель и проверяющий — разные окна; видение — у советников.
- Ход сверен с целью проекта, не только с буквой задания:
  расхождение или невыполнимость закрыты волевым решением — оно
  проверено субагентами, записано в реестр решений и названо в
  отчёте; необратимое или меняющее долговечную правду ушло
  вопросом владельцу.
- Окно оркестратора сбережено: корпус не читал, в футпринты не
  писал.
- Отчёт волны выдан в чат: агент → задача → фокус → возврат → чем
  проверено.
- После обрыва новое окно продолжило с носителя режима, не с нуля.

## Инварианты

- Свод инструкций не отменяется — оркестратор фокусирует: задание
  называет, каким инструкциям этому субагенту особенно
  прислушиваться и какие скиллы поднять. Фокус — адреса, не
  пересказы: пересказ создаёт вторую правду.
- Оркестратор бережёт окно: в детали работы не уходит, тяжёлую
  генерацию — применение принципов, экстраполяцию — отдаёт
  советникам; волевое решение по конфликтам, пустотам и возвратам —
  его, как и синтез итогового ответа.
- Исполнитель не принимает свою работу; советник не проверяет
  построенное на его видении.
- Оркестратора тоже проверяют: траекторию волны судит внешнее окно.
- Параллельная запись — только непересекающиеся футпринты; иначе
  один писатель.
- Носитель по весу: лёгкий возврат — thread; тяжёлый или
  бесплановый — файл в папке волны; при живом плане состоянием
  владеет план.

## Дельта

Модель умеет запускать субагентов. Она не умеет:

- разделить работу на посильные задачи — даёт одному окну всё сразу;
- сфокусировать — вываливает весь свод или молчит про инструкции
  вовсе;
- взвесить инструкцию — даёт пишущему и экстраполяцию, и приёмку;
- повторить критичную инструкцию в момент её действия — надеется
  на память окна;
- сберечь окно оркестратора — читает корпус сама «для скорости»;
- потребовать след — принимает «учёл» без отчёта волны.

## Известные сбои

`когда → сбой → цена → куда`

- задание выдано без фокуса → субагент слушает весь свод разом →
  соблюдение каждой строки падает кратно (96% → 20–60%) → карта
  волны (Механика, шаг 1)
- инструкции розданы без веса → тяжёлая исполнена как ритуал или
  забыта → [instruction-cost](references/instruction-cost.md) —
  без таблицы цены все инструкции весят одинаково
- задание написано слабыми формулировками → субагент исполняет
  форму, не решение → переделка волны → wording.md из
  `1instruction-shaping` (Механика, шаг 1)
- оркестратор ушёл в детали → окно съедено, волна без директора,
  траектория потеряна → инвариант сбережённого окна
- запись без предполёта → пересечение футпринтов, перетёртые
  правки → [preflight](references/preflight.md)
- дешёвые окна на «лёгком» классе без перекрытия зон → слепая зона
  невидима (2 из 5 в живом прогоне) → перекрытие (Механика, шаг 2)
- проверило то же окно или та же семья → дыра невидима до
  владельца → внешняя проверка (Механика, шаг 4)
- возврат принят, переход не записан → свежее окно продолжает с
  позавчера → носитель режима (Механика, шаг 5)

## Механика

**Порог.** Волна разворачивается, когда есть любое из: две и более
независимые зоны чтения · два и более непересекающихся футпринта
записи · три и более инструкционных владельца на одной задаче
(скиллы, рамки, критерии плана). Ни одного — один воркер плюс
внешняя проверка; причина строкой.

**Режим.** С живым планом — состоянием волны владеет план
(`1planning`, его контекст-файл). Без плана — папка волны
`_workspace/orchestration/<дата-слаг>/`: контекст-файл (зачем волна,
проблема, цель, границы — без дублей канона и без процедур),
возвраты и `decisions.md` — реестр волевых решений оркестратора:
решение · обоснование · чем проверено. Реестр — след волны, не
канон: решение, переживающее волну, уходит в план или вопросом
владельцу. С планом реестр живёт в план-папке. Папка волны
добавляется в `.gitignore` при создании.

1. **Карта волны** — до запуска, в чат: задача → кому →
   фокус-инструкции (адреса) → вес по
   [instruction-cost](references/instruction-cost.md); тяжёлым
   классам приём: окно советника · повтор в промпте в момент
   действия · наблюдаемый след. Формат задания: конкретная
   посильная задача · фокус-адреса · границы · куда возврат.
   Формулировки заданий — по `1instruction-shaping` →
   `references/wording.md`: операция + причина в полстроки,
   расплывчатое → стоп-условие. Точечный файл, не весь скилл —
   окно оркестратора бережётся.
2. **Чтение и советники** — параллель по зонам; лёгкий класс на
   дешёвых окнах — только с перекрытием зон; советники возвращают
   видение: применение принципов, экстраполяцию, варианты решения.
   →• оркестратор принял отчёты с адресами.
3. **Запись** — предполёт футпринтов пройден; один писатель по
   умолчанию; упавшего будят репликой, не респавнят. →• возвраты
   лежат по носителю режима.
4. **Проверка** — параллельно: работа против критериев — окном, не
   писавшим её · копия мозга владельца — принципы и цитаты против
   артефакта, контракт `1fresh-eyes`; кросс-семейный прогон — по
   решению владельца · траектория волны и самого оркестратора —
   внешнее окно. Возвраты — разница списков, не мнение.
5. **Принятие** — только оркестратор: пакеты дословно, не в
   пересказе; конфликт, пустоту и развилку закрывает волевым
   решением — строкой в реестр в том же ходе — или вопросом
   владельцу, вопросы пачкой; развилка, меняющая ветку,
   останавливает зависимую ветку немедленно; переход записан в
   носитель режима в том же ходе.
6. **Отчёт в чат** — таблица: агент → задача → фокус → возврат →
   чем проверено. Без отчёта волна не закрыта.

**Ремонт** — первый круг репликой прогретого воркера; второй —
свежим окном с заданием и возвратом; третьего нет — очередь
владельца.

## Завершение

Волна закрыта: отчёт волны в чате; возвраты приняты либо отклонены;
переход записан в носитель режима; очередь владельца выдана; строка
`1findings` — что в делении работы и фокусировке сработало, что
нет. Порог не достигнут — волна не разворачивается, причина
строкой.
