# Общая очередь проверяющих

## Когда запускаешь пакеты

`max-review` принимает подготовленные задания и запускает отдельную Codex CLI
сессию для каждого. Распределение требований и приёмка смысла остаются
координатору. Оболочка использует Python 3 без внешних библиотек и существующий
вход Codex CLI через ChatGPT; фиксирует `gpt-5.6-luna` и усилие `max`.

Если команды нет, установи launcher из установленного пакета:

```sh
python3 <skill>/scripts/install_cli.py
max-review doctor --json
```

`<skill>` — абсолютный путь к этому пакету. Launcher ставится в
`~/.local/bin`; каталог должен быть в PATH. Codex CLI устанавливается
отдельно. Doctor проверяет локальный запуск и вход, но не гарантирует
доступность модели на сервере или допустимость высокой параллельности.

## Передача

Сохрани задания в UTF-8 JSONL, по одному объекту в строке:

```json
{"id":"P01","cwd":"/absolute/project","prompt_file":"/absolute/session/prompts/P01.md"}
```

Пути абсолютные; `id` уникален. Prompt содержит только brief данного пакета,
адреса первичных источников, версию, unit ID и контракт короткого ответа.
Проверяющий возвращает финальный отчёт; файл за него сохраняет оболочка.
Сам проверяющий работает с shell sandbox read-only, без разрешения исправлять
цели или рекурсивно запускать другие проверки. Для отчёта, совместимого
с механизмом покрытия, добавь к run `--output-schema <skill>/assets/report.schema.json`.

```sh
max-review run --tasks /absolute/session/tasks.jsonl --run-dir /absolute/session/run --parallel 4 --timeout 300 --json
max-review status /absolute/session/run --json
max-review results /absolute/session/run --json
max-review retry /absolute/session/run --failed --parallel 4 --json
```

Один run-dir принадлежит одному запущенному диспетчеру. `run` работает в
переднем плане; длительный вызов можно наблюдать средствами терминала.
Сотня строк — сотня заданий; `--parallel` ограничивает число одновременно
работающих процессов. Новые задания не сливаются ради занятого слота.

## Результат и продолжение

В каталоге запуска сохраняются копии prompts, состояния и отдельные файлы
каждой попытки: финал, JSONL события и stderr. Повтор не затирает прежние
ответы и не запускает уже успешные задания; он продолжает ошибки и задания,
которые ещё не начинались. После остановки очереди
незавершённые задания требуют продолжения; потерянный ответ не становится
успешным. Таймаут задания ограничивает длительность одной попытки.

`--json` выдаёт JSON в stdout; это envelope оболочки, не ответ модели.
Ошибки имеют ненулевой код выхода и JSON-описание при этом флаге. Подробные
выводы процесса хранятся в файлах; при обычном опросе читай короткий status.
`results` возвращает индекс с путями отчётов; сами тексты читай адресно,
не загружая все ответы в контекст. Конкретные поля и аргументы показывает
`max-review --help`.

Успех процесса означает полученный финальный ответ, не чистый аудит.
Координатор проверяет его схему, соответствие manifest и свидетельства;
для механизма покрытия сохраняет отчёт по ID пакета в reports/, сохраняя
связь с исходной попыткой. Системные ошибки остаются пробелами проверки.
Копия prompt и завершённый процесс не доказывают неизменность прочитанных
файлов: их снимки и проверка хешей остаются частью приёмки 1-max-review.

Оболочка отключает загрузку пользовательского config.toml у дочернего CLI,
чтобы не наследовать интерактивную модель, широкие разрешения и MCP-настройки.
Сохранённая CLI-авторизация, применимые инструкции и execpolicy остаются.
Переменные API-ключей не передаются дочернему процессу. Это выбранный маршрут
через ChatGPT; поддержки отдельной API-оплаты в этой версии нет.
