# Сборка и очередь

## Установка

`max-review` использует Python 3, установленный Codex CLI и его ChatGPT-вход.
Из установленного пакета выполни:

```sh
python3 <skill>/scripts/install_cli.py
max-review doctor --json
```

Launcher ставится в `~/.local/bin`; каталог должен быть в PATH. Doctor
проверяет локальный маршрут, но не гарантирует доступность модели на сервере.
Модель Luna Max зафиксирована; отдельной API-оплаты и fallback нет.

## План из исходных участков

Пути абсолютные. Номер строки начинается с 1; обе границы включены.
Отсутствие `lines` у цели означает весь файл. В примере source содержит
ровно 12 строк; подставь реальные границы своего источника.

```json
{
  "targets": [{"id": "T1", "path": "/project/document.md"}],
  "sources": [{"id": "S1", "path": "/project/AGENTS.md", "targets": ["T1"]}],
  "packets": [{
    "id": "P1", "targets": ["T1"],
    "rules": [{"source": "S1", "lines": [1, 12]}]
  }],
  "excluded": [],
  "gaps": []
}
```

Source без `targets` применяется ко всем объявленным целям. Большую цель
можно объявить с `lines: [start, end]`, сохраняя необходимый связный контекст.
Дополнительные тексты пакета идут в `context: [{"path": "/project/context.md"}]`;
там тоже допустим `lines`. Это контекст для толкования, не ещё один набор правил.

Неприменимость запиши в `excluded` как
`{"source":"S1","lines":[13,20],"targets":["T1"],"reason":"причина"}`.
Без `targets` исключение относится к целям этого источника. `gaps` содержит
строки с известными пробелами. Пропущенные строки объявленного источника
для применимой цели останавливают сборку; отсутствующий в плане источник
этим способом обнаружить невозможно.

## Выполнение

```sh
max-review prepare --plan /session/plan.json --out /session/prepared --json
max-review run --tasks /session/prepared/tasks.jsonl --run-dir /session/run --parallel 3 --timeout 600 --output-schema /session/prepared/report.schema.json --json
max-review status /session/run --json
max-review retry /session/run --failed --parallel 3 --json
max-review check --prepared /session/prepared --run-dir /session/run --json
```

`prepare` создаёт новый каталог: снимки, готовые prompts, схему ответа,
задачи для очереди и `coverage.json`. Каждый prompt уже содержит нужные тексты
с адресами строк и полный контракт reviewer. Leaf не получает весь план
или задания соседей. Объём чтения виден до запуска. Запись данных считается
завершённой только после успешного prepare; ошибочный каталог не используй.

`run` работает в переднем плане, по одному процессу на пакет; `--parallel`
ограничивает одновременность, а не общее число пакетов. Попытки и ответы
сохраняются раздельно. Retry продолжает ошибки и незапущенные задания,
сохраняя прежние попытки и не повторяя успешные. Таймаут ограничивает одну
попытку; потерянный ответ остаётся ошибкой.

`results` даёт индекс путей ответов, `check` — короткий итог проверки учёта
и путь подробностей. Схема ответа содержит packet, status, findings и gaps.
Успешный процесс ещё не означает semantic clean. Координатор принимает
содержание по [правилам результата](results.md).

## Границы

Оболочка копирует prompts и проверяет их хеши перед продолжением. После
изменения источников собери новую версию; старые ответы её не подтверждают.
`prepare` сохраняет соответствие исходный участок → пакет; `check` связывает
его с фактически полученным ответом. Атомарный реестр требований не нужен.

Leaf получает поручение вернуть один ответ без инструментов. Это ограничение
задачи, а не технический запрет всех tool calls. CLI дополнительно работает
read-only с approval policy never, без пользовательского config и переменных
API-ключей. Нейтральная рабочая папка убирает проектную навигацию из задачи;
платформенные инструкции и стоимость запуска сохраняются. Если leaf всё же
пользуется инструментами, это нарушение маршрута, которое надо учитывать
при оценке результата и нагрузки.
