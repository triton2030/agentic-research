# Планирование

План — инструкция от агента агенту: цель даёт траекторию, план — шаги, которые
по чуть-чуть приближают к ней. Проза дешевле кода, поэтому подробный план
ощущается прогрессом до первого свидетельства — это главный самообман жанра.

Режимов задачи два, и «искать путь — тоже задача, которую надо исполнять»:

- **Wayfinding** — путь материально не ясен: задача разрешает решения;
- **Execution** — путь ясен: задача ведёт результат через вехи.

Полный план вперёд + ре-план по событию не уступает пошаговому контролю и
кратно дешевле; пошаговость чаще застревает в циклах. Контроль — по событиям,
не по шагам.

## Цель

На руках — один живой контракт выбранной работы, по которому следующая сессия
с чистым окном продолжает или останавливается **по самому файлу**, без
скрытого чата. Контракт называет приближаемый пункт `GOAL.md`.

Не входит: цель проекта (`1goal`) · создание принципов (`1product-shaping`) ·
побочные находки (`1findings`) · маршруты к знанию (`1index`).

## Критерии успеха

- Контракт несёт триаду: Цель-состояние · Критерии · Не входит — и пункт
  GOAL, к которому шаг.
- Каждое существенное требование несёт происхождение: слово владельца / Frame
  / документ / допущение планировщика. «Слово владельца» доказуемо записью
  chat-recall.
- Режим задачи честный и виден в файле; вехи Execution рождены осью разреза,
  не хронологией.
- Один текущий Next; будущие ветки не исполняются потому, что записаны ниже.
- Стык назван: чем выход задачи съедобен следующей.
- Cold-start: новый агент восстанавливает по файлу что · зачем · границы · на
  каком свидетельстве.
- «Да» владельца на обоснование получено до создания файла.

## Инварианты

- План доверяет исполнителю маршрут, но не даёт додумывать замысел: пробел
  замысла — вопрос или допущение с происхождением, не тихий дефолт.
- Текущая правда вместо хроники: свидетельство переписывает план; заплатка
  поверх устаревших вех создаёт зомби-план, который выглядит живым.
- Развилку, не покрытую планом, сначала неси в `1use-principles`: принципы и
  цель закрывают её без владельца. Эскалация — когда они молчат.
- Условия входа: «задача имеет смысл, пока верно X»; X нарушено → стоп и
  эскалация, не творческая адаптация.
- Новое материальное неизвестное возвращает задачу в Wayfinding; названный
  вопрос без ответа — это решение, а не туман.
- Отложенный состав требует акта вывода: когда составом deliverable владеет
  contract/canon/spec, первым актом перечисли его из источника и держи
  Done-строку, падающую при непокрытом требовании. Чужой список — вход для
  сверки, не замена перечислению.
- Ни одного план-файла до «да» владельца на обоснование: цель · польза ·
  режим · аппетит. Полный текст плана в чат не льётся.

## Дельта

Модель умеет раскладывать работу на шаги. Она не умеет:

- остановить разложение до свидетельства — расписывает дерево по трём
  непроверенным маршрутам;
- пересобрать план вместо заплатки — патчит устаревшее;
- отличить «путь ясен» от «путь кажется ясным»;
- резать по зависимостям — режет по хронологии «спроектировать → реализовать
  → проверить», пряча риск в связи между этапами;
- удержать обязательства к концу длинного плана;
- не превратить свой дефолт через два пересказа в «волю владельца».

## Известные сбои

`когда → сбой → цена → куда`

- план до свидетельства → дерево шагов по непроверенным маршрутам → переделка
  всего дерева → [modes](references/modes.md)
- новое свидетельство → заплатка поверх вех → зомби-план ведёт работу →
  [modes](references/modes.md)
- путь неясен, но задача «исполняется» → архитектурный выбор на ходу без
  основания → [modes](references/modes.md)
- режу тяжёлую работу → хронология вместо оси → риск спрятан между этапами →
  [decompose](references/decompose.md)
- требование без происхождения → догадка планировщика стала «волей владельца»
  → [contract](references/contract.md)
- стык не назван → выход задачи 2 несъедобен задаче 4 → переделка на границе →
  [contract](references/contract.md)
- сессия сменилась → статус не отражает реальность → следующая сессия
  переделывает готовое → [contract](references/contract.md)
- работа шире одного контекста → воркеры без file-disjoint контракта →
  перетёртые правки → [delegation](references/delegation.md)

## Механика

Жёстких перехода два — остальное постусловия:

- **«да» владельца до файла**: обоснование (цель · польза · режим · аппетит) —
  в чат, файл — после согласия;
- **перечитай контракт до нового material-шага**: продолжение по памяти чата
  вместо файла — источник зомби-планов.

Допуск: работа выбрана и переживает сессию; активен нативный Plan Mode →
молчи; иначе — разбор в чате без файла.

Постусловия живого контракта — в любом порядке:

- режим назван; Wayfinding держит карту решающих вопросов, Execution — 2–5
  вех от оси разреза ([decompose](references/decompose.md));
- Next один; свидетельство классифицировано (подтверждает / противоречит /
  недостаточно) → текущая правда переписана;
- развилка вне плана прошла `1use-principles` до эскалации;
- переход режима и стоп — по событию.

## Завершение

Закрытие — по критериям триады контракта, не по усталости. Применимое
подтверждено; статус отражает реальность; проектный `STATUS.md` (если
маршрутизирован) обновлён; следующая сессия может продолжить или закрыть по
файлу. Не вошедшее — в `cut.md` строкой с причиной.
