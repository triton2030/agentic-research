# Evidence

## Support Envelope

- Target: Claude Opus 5 в Claude Code CLI (`claude -p`), default effort.
- Harness: global skills `~/.claude/skills`, global agents `~/.claude/agents`.
- Required tools: `Skill`, `Agent`, project reading, `1chat-recall` Retrieval
  через `Bash`, web.
- Required isolation: отдельный субагент в чистом окне.

## Что доказано и что нет

- **Активация — частично.** Денежный вопрос поднимает скил надёжно. Приказ на
  изменение состава («убери эту страницу») не поднимает: реплика читается как
  задача на исполнение, и маршрутизация уходит в «делай». Это и есть главный
  сценарий владельца, поэтому дыра названа, а не замазана.
- **Применение и завершение — не проверены.** Полный цикл «отчёт аналитика →
  след в чате» не прогонялся: в прогоне `Agent` был намеренно запрещён.
- **Read-only держится списком `tools`** (нет `Edit`/`Write`), кроме `Bash` —
  он нужен для Retrieval `1chat-recall` и теоретически может писать. Та же
  дыра у живого `md-scout`; прозой не закрывается.
- `qv-skill` — valid; `rumdl` — чисто; проекции совпадают с owner-ом.

## Следующий шаг, если дыра важна

Скил по устройству может не подняться. Гарантия на приказ-распоряжение живёт не
в описании, а в always-true слое — строка в корневой инструкции владельца.
Решение владельца, не агента.
