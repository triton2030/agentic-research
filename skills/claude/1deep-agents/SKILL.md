# Глубокие Агенты

## Цель

Закрытая пустота: автономное решение, обоснованное несколькими
несводимыми профессиональными методологиями с наблюдаемым следом каждой.

Не входит: вопросы с уже записанным решением владельца истины;
долговечная правда владельца — стоп и вопрос по корневому правилу
записи; выполнение самой задачи субагентами; панель линз по траектории
(`1fresh-eyes`).

## Критерии успеха

- След поиска предъявлен: владелец истины → где смотрел (адрес) →
  пусто либо конфликт источников.
- У каждого агента ровно один метод целиком; методы выбраны под разные
  когнитивные операции; для технической задачи ≥1 domain-native.
- Каждый trace показывает task-specific преобразование каждого шага и
  вход из предыдущего; факт / вывод / пробел различимы.
- Решение принято, названо победившее основание; конфликт методов
  показан, не заглажен.
- Конфликт решений владельца или durable-правда → вопрос владельцу.

## Инварианты

1. **Пустота доказана, не заявлена.** Запуск — только после следа
   поиска у владельцев истины: иначе методологии авторитетно решат уже
   решённое. Конфликт производных артефактов решается автономно с
   названным источником-победителем; конфликт решений владельца —
   вопрос. Антипример: «в спеке за минуту не нашёл» → запуск.
2. **Один агент — один метод — целиком.** Сущности задачи отображаются
   на метод; сам метод не режется, не переставляется, не смешивается:
   гибрид возвращает один привычный вывод под тремя ярлыками.
   Антипример: «First Principles + Premortem» в одном ответе.
3. **След важнее вывода.** Гладкий текст с названиями шагов — театр;
   шаг существует, только если видно его преобразование и что оно дало
   следующему шагу. Антипример: все шаги «complete», промежуточных
   представлений нет.

## Дельта

Модель умеет называть методологии. Не умеет: не подменять пустоту
статистически вероятным ответом с ярлыком метода; держать три метода
несмешанными; отличать след применения от пересказа учебника;
остановиться на чужой (durable) развилке.

## Известные сбои

`когда → сбой → цена → куда`

- метод выбран по теме/словарю профессии → мимо реальной когнитивной
  работы → [frameworks](references/frameworks.md) — реестр-сид, не
  белый список
- запуск через fork/наводящий пакет → методы выровнены до старта →
  [runtime-orchestration](references/runtime-orchestration.md)
- один удачный прогон → раздутые claims о «глубине» →
  [characterization](references/characterization.md)

## Механика

**Гейт входа (след обязателен).** Таблица в рабочем контексте: владелец
истины (принципы / GOAL / спеки / доки / recall) → адрес, где смотрел →
пусто | конфликт. Durable-правда или конфликт решений владельца — стоп,
вопрос владельцу; порог автономии — корневое правило записи, здесь не
пересказывается (помеченная копия смысла из «Не входит»).

**Диагноз.** Вытащи из задачи её когнитивную работу — что должно
измениться: представление, причинная модель, поле вариантов, проверка —
и выбери минимум три метода под разные операции. Реестр — сид для
контраста; метод вне реестра выбирается при установленной родословной
шагов.

**Запуск.** Чистые non-fork агенты (адаптер runtime — reference),
каждому: одинаковый сырой task packet + один метод + полный скелет его
шагов + требование: «каждый шаг: вход → наблюдаемое преобразование →
результат → факт/вывод/пробел; метод не менять; задачу не выполнять;
недостающее evidence — пробел, не факт».

**Приёмка (след обязателен).** Для каждого trace процитируй шаг с
task-specific преобразованием, использующим результат предыдущего.
Нет такого шага — один перезапуск замены с тем же пакетом; второй
провал — честный blocker, не склейка ответов.

**Решение.** Raw traces публикуются; затем: где методы разошлись и
почему · что увидел только один · решение с победившим основанием ·
оставшиеся пробелы. Без голосования; консенсус не доказательство.

## Завершение

Решение принято и записано в рабочий контекст с основанием и следом
поиска; traces доступны; durable-ветка ушла вопросом владельцу;
исполнение решения — отдельная работа основного окна, не субагентов.
