# Референс-файлы

Вход: скилу нужен самостоятельный режим или стадия, либо один момент работы
остаётся перегружен после смыслового разбора.

Цель: разделить скил на самостоятельные когнитивные режимы и стадии так, чтобы
в каждый момент агент работал с телом и одним референс-файлом. Ориентир
компактности файла — до 20 самостоятельных единиц; он не гарантирует надёжности.

## Порядок

1. Назови наблюдаемые вход и выход стадии.
2. Проверь самостоятельность: стадия выполнима по телу скила, одному
   референс-файлу и артефактам прошлых стадий.
3. В теле оставь только общие правила и условие чтения референс-файла.
4. Всю локальную логику стадии помести в её референс-файл.
5. Посчитай единицы файлов отдельно и оцени совместную нагрузку тела и
   текущей стадии, включая продолжающие действовать требования прошлых стадий:
   чтение в разные моменты не означает раздельного исполнения.
6. Превышение ориентира 20 единиц — повод переписать файл из цели стадии по
   `1smart-simple`, а деление стадий применяй как крайнюю меру, когда
   переписывание риск не сняло.

## Правила

- Стадию можно держать её Задачей, Целью, Зачем и — там, где названо
  препятствие, — Критериями принятия, оставив в протоколе только те шаги, способ которых агент
  сам не выберет: цель и критерии задают результат для проверки, а остальной
  протокол агент строит сам. Это способ написать стадию заново, а не способ формально уменьшить счёт
  единиц уже перегруженного файла — там действует правило ниже.
- Не маскируй превышение символьным сжатием, удалением строк, укрупнением
  пунктов либо переносом единиц в Критерии принятия; свернуть дешёвую единицу в
  правило высшего порядка можно только вместе с переписыванием механики, а не
  вместо него.
- Если одному моменту нужны несколько референс-файлов, объедини их, перестрой
  стадии или раздели скил.
- Референс-файл не требует и не запускает чтение другого референс-файла.
- Единственное исключение — `refactor.md`: он запускает `goal-context.md` и
  возвращает агента в тело `1skill-creation`, чтобы заново пройти полный
  протокол создания, а затем принимает результат для проверки потерь.
- Дословный протокол пользователя не сокращай и не перефразируй без его
  согласия; снять его целиком можно там, где чистый агент приходит к тому же
  поведению по одному намерению.
- Файлы в `agents/` создавай только по просьбе пользователя.
- Используй `agents/` внутри скила как папку самостоятельных файлов ролей,
  которые основной протокол прозой передаёт независимым чистым субагентам при
  названных условиях.
- Файл в `agents/` считай самостоятельным, когда он выполним по собственному
  входу и файлам, названным в этом входе; перечисли их там явно.
- Пиши файл роли той же формой, что и тело: Задача, Цель, Зачем, Критерии
  принятия и только то, чего чистый субагент сам не сделает, — он
  читает этот файл как свой промпт.
- Саму процедуру проверки помещай в файл роли, а в основном протоколе оставляй
  только вызов: проверяющий загрузит её в собственное окно, и активный набор
  основного агента её не несёт.

Выход: карта режимов и стадий с их входами, выходами и количеством единиц.
