# Создание скилов

## Контекст

Скил для пользователя — его личный промпт под кодовым словом. Читает его
сильный агент без истории создания, поэтому полезна только дельта:
неизвестное устройство ситуации или поправка к поведению, которое иначе
выглядит разумным.

В этой работе повторяются два сбоя. В тексте автор пересказывает одно
намерение в разных разделах, заполняет критерии очевидным и собирает
требования в общий список: обязательств у читателя больше, понимания
меньше. В процессе правка начинается раньше, чем пользователь, который
думает вслух, договорил замысел, а проверки наслаиваются: сделанное уходит
в корзину, и малая правка тянется часами.

## Задача

Создай или переработай скил из намерения пользователя, проверь его поведение
в объёме по типу правки и доставь в предназначенные среды.

## Цель

Агент, исполняющий скил, выбирает нужные пользователю действия при минимуме
одновременно необходимых требований. При споре между полнотой шаблона
и достаточным пониманием сохраняй существенный смысл и меняй способ его
передачи.

## Когда начинаешь

Мастерская глобальных скилов — `/Users/triton/Documents/GitHub/agentic-research`,
даже когда запрос пришёл из другого репозитория. Прочитай её `AGENTS.md`
и найди владельца пакета по `skills/shared/README.md`: правка начинается
с tracked owner, установленный пакет — его проекция. Прочитай `1agent-steering`
целиком: он задаёт форму текста, этот скил — форму скила, проверку и доставку.

Для существующего скила прочитай пакет, принципы у владельца и `user-said.md`
в истории `skills/<имя>/` и назови тип правки: адресная — названо, что менять;
полная переработка — переосмыслить функцию. Затем покажи пользователю
набросок в 3–5 строк — для нового скила это момент вызова и что изменится
против поведения без него — и спроси, что ещё. Пиши после ответа.

## Когда пишешь намерение

Форма: Контекст → Задача → Критерии принятия, если нужны → Цель, затем
разделы «Когда …» по реальным моментам работы.

- Контекст связывает подтверждённые факты, которых читатель не знает,
  с последствиями для пользователя: почему возникла работа и почему важны
  цель и ограничения.
- Задача называет вмешательство и результат. Сравни с поведением сильного
  агента без этого скила: нет различия — найди недостающее местное условие
  или признай, что скил не нужен.
- Критерий закрывает неверный результат, который ещё допускают Контекст,
  Задача и Цель вместе; нет такой лазейки — нет раздела.
- Цель — высшее намерение и тайбрейкер при конфликте способов.
- Тело и references — по-русски; имя и `description` — по-английски,
  по `references/description.md`.

## Когда добавляешь содержание

Строка проходит, если меняет выбор сильного агента сверх уже переданного
намерения: неизвестный факт, наблюдаемое нарушение, необходимый порядок.
Способ, который предложил пользователь, проходит тот же отбор, но снимается
только с названной ему причиной; его дословные слова меняются в пределах его
разрешения.

Reference-файл — для ветки, нужной не каждому запуску; условие чтения стоит
в теле. Reference самостоятелен и не отправляет читать другой reference.
Файл роли в `agents/` — только по просьбе пользователя.

## Когда проверяешь

Объём — по типу правки:

- адресная — одна проба затронутого случая и один проверяющий из другой
  семьи моделей;
- полная переработка или новый скил — пробы ключевых случаев и три
  проверяющих по `references/review.md`; допустима одна повторная волна.

Проба — свежий агент получает скил по нейтральному пути и рабочее задание
без ожидаемого ответа; песочницу и порядок его действий даёт
`scripts/probe.py`. Каждый прогон начинается с нетронутого случая. Согласие
проверяющих и прогноз пробы не заменяют. Находку принимай по словам
пользователя, контракту или наблюдению, а не по уверенности проверяющего.

## Когда доставляешь

Уже данное разрешение на правку и установку сохраняет силу. Запиши версию
во владельца, синхронизируй проекции и сверь каждую среду:

```bash
python3 skills/shared/sync_simple_projections.py <имя> --write --install
python3 skills/shared/sync_simple_projections.py <имя> --check
```

Среду, куда доставка не состоялась, назови. История — в `skills/<имя>/`:
снимок `versions/<id>/` и один рассказ в `work/<id>/README.md` — граница,
что сохранено и снято, пробы, находки и решения. README истории и `cut.md`
получают по строке со ссылкой на него, принципы — у владельца, строка
реестра в `skills/shared/README.md` не пересказывает пакет.
