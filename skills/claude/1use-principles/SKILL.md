# Применение принципов

Принципы — сжатые, уже оплаченные ответы владельца. Скилл восстанавливает
его ответ в ситуации, которую он не видел: на развилке — выбором варианта,
в пустоте — порождением состава. Восстановление — не настроение, а матрица:
экстраполяция — додумка с множеством возможных решений, самый громкий
принцип даёт очевидный вывод, который тихий принцип из другой темы
переворачивает. Эталон владельца — в [compile](references/compile.md).

Имена этой механики — ярлыки, ничего сверх названного из книг сюда не входит,
а принципы этим скилом не создаются: шаг 1 — метод Далио («Принципы»); ветка
шага 3 «ни одна ось не задета, решение продуктово значимо» — commander's
intent, её правила — инвариант ничьей и [compile](references/compile.md),
«Граница». Молчат и Frame, и принципы — это не ветка шага 3: её владелец —
шаг 2.

## Цель

На руках — решение или чистовая запись, которые владелец узнал бы как свои:
развилка или пустота закрыта так, как закрыл бы её он, — ответ восстановлен
из принципов, цели и конкретной сцены, а не выведен из жанрового дефолта.
След делает реконструкцию проверяемой; его форму держит «Мини-матрица» в
[compile](references/compile.md), адрес записи — шаг 5.

Не входит: создание и правка принципов и цели · внешние необратимые действия
наружу (деплой, прод, внешние траты, публикация) без явного разрешения
владельца.

## Критерии успеха

Критерии — для материальной развилки и пустоты; форма «перед записью»
отвечает своим следом (Механика).

- На развилке варианты названы **до** первой цитаты принципа; в пустоте
  принципы работают генератором вариантов (шаг 2).
- Релевантные принципы процитированы, не пересказаны, и для каждого названо,
  что он означает именно для этого решения.
- Контрпринципная проверка имеет след: названный контрпринцип **или** «осей
  против нет» с перечнем просмотренных файлов — голое «противников нет» не
  считается.

## Инварианты

- Вывод — для пустоты и расхождения, не поверх записанного: где ответ уже есть
  у своего owner-а, скил применяет его и нового не выводит. Соблазн обратного
  силён — выведенное собственной матрицей выглядит обоснованнее найденной
  чужой строки, и так у одного утверждения появляется второй владелец.
- Однопринципный вывод запрещён: следствие проверяется против полного
  релевантного набора — другой принцип может его перевернуть, и прямая
  экстраполяция самого громкого выглядит послушанием, давая противоположное
  воле владельца.
- Релевантность принципа определяется его **последствиями** для вариантов, не
  словарным сходством с задачей: переворачивающий принцип живёт в другой теме.
- Ничья не эскалируется:
  тайбрейкер затронутого Frame → затем тайбрейкер GOAL → решает;
  специальный принцип → бьёт общий; при конфликте пар специальная бьёт
  общую вдоль старшинства, объявленного в её Frame;
  всё ещё ровно → специфицируй заново → назван результат, способный
  развернуть выбор → `1fresh-eyes` → иначе лучшая практика для конечного
  результата проекта.
  Владельцу — след с рекомендацией, не блокирующий вопрос. Середина запрещена
  как операция: воля владельца не усредняется.
- У ответа один владелец, у результата — один из трёх типов, названный в
  следе: **записанный ответ owner-а** — примени и процитируй; **обратимый
  вывод** — приземли сразу ходом owner-а с provenance «выведено» и
  следом-цитатой, не прямой правкой из компиляции; owner-а нет — вывод живёт
  в рабочем артефакте с той же пометкой, вторым владельцем правды не
  становясь; **рекомендация владельцу** — материальный бизнес-выбор из Stop
  цели; иного невыводимого нет — закрытый список исключений держит compile,
  «Граница». Расходятся принцип и
  нижний слой — принцип выше, но чинится нижний слой своим авторизованным
  ходом; втихую выбирать победителя нельзя.
- Пометка «выведено» падает строкой в дом находок проекта — иначе выведенное
  видно только тому, кто перечитает весь результат. Повторяющийся класс
  молчания принципов — дыра в принципах: сигнал `1product-shaping` (осевые
  заголовки, over-форма «X важнее Y»), не поток эскалаций.
- Применение без следа неотличимо от неприменения — и не считается.

## Известные сбои

`когда → сбой → цена → куда`

- решение принято до чтения → принципы цитируются под готовый ответ →
  уверенно-неверное решение с идеальным следом → тело, шаги 1–2
- ответ owner-а уже записан → скил выводит свой → вторая правда с provenance
  «выведено» → тело, шаг 1
- поиск по словам задачи → контрпринцип из другой темы не найден → «Индия
  отменена» против воли владельца → [compile](references/compile.md)
- свип прерван на первом подходящем → набор не пройден до конца → уверенный
  вывод из половины принципов → тело, шаг 3
- громкий короткий принцип → тихий специфичный проигран → mood вместо правила
  → [compile](references/compile.md)
- два принципа тянут в стороны → выбрана середина → воля владельца усреднена в
  кашу → тело, инвариант ничьей
- «противников нет» без перечня просмотренного → театр следа → лазейка
  рационализации → тело, критерии
- пустота без вариантов → жанровый шаблон вместо сцены → генерик-интерфейс с
  идеальным следом → [generate](references/generate.md)

## Механика

Порядок жёсткий, перестановка ломает результат: записанный ответ до вариантов,
варианты до оценки, свип до вывода, обратный проход до следа. Уже прочитанное
в этой сессии не перечитывается.

Форма «перед записью» — перед генерацией нового (код, документ, спека):
прочитай целиком все Frame + Principles продукта и тайбрейкеры GOAL — цена
контекста всего проекта; заголовки, snippets и память чтением не считаются
(копия критерия `1product-shaping`). Пар в проекте нет — назови это в следе и отталкивайся от
GOAL: цель — верхняя продуктовая рамка. След — одна-две строки рядом с
результатом генерации: применённые принципы и что из-за них не сделано;
микрорешения отдельного следа не несут — их покрывает след формы.
Материальная развилка или пустота — полный порядок шагов ниже.

1. **Назови, что решается, и поищи записанный ответ** — вопрос одной строкой,
   до открытия принципов; затем открой места, где ответ лежал бы: спецификации
   и документация проекта, прошлые слова владельца (`1chat-recall`). Глубина —
   по цене решения: обратимой мелочи хватает своего файла. Предъяви одно из
   трёх:
   - **ответ есть** — цитата с адресом: он и есть решение, вывод не нужен;
     расходится с принципом — не переписывай, это ремонт нижнего слоя;
   - **ответы расходятся** — цитаты расходящихся становятся вариантами шага 2;
     проигравший слой чинится своим ходом, победитель несёт пометку
     «выведено»;
   - **ответа нет** — для каждого адреса заголовок раздела, где ответ лежал
     бы, либо «файла нет».
   Перечень имён без заголовков не считается: его можно написать не открыв
   файлы, и тогда вывод неотличим от непоиска.
2. **Перечисли варианты** — минимум два реальных; свой любимый — один из.
   Пустота — вариантов нет вовсе → построй их: (а) сцена одной строкой — кто
   пришёл, с чем, что до и после — из Frame и GOAL, не из жанра; (б) каждый
   релевантный принцип — вопросом «что велит здесь построить, убрать,
   подчеркнуть?» — генератор, не фильтр; (в) собери из ходов два непохожих
   концепта — различающихся блоками, а не порядком блоков; оба идут дальше по
   шагам 3–4, чучельный концепт, собранный проигрывать, не считается.
   Принципы и Frame молчат — сцену и ходы строить не из чего: это
   пустота без владельца, маршрут `1deep-agents`, не жанровый шаблон.
3. **Матрица по последствиям**: прочитай целиком Frame затронутых scope и
   тайбрейкеры GOAL, затем матрица: слоты Frame + заголовки всех файлов принципов × каждый
   вариант — «P-X → для A значит…, для B…». Набор проходится до
   конца, не до первого подходящего; абстрактное слово
   принципа специфицируй под случай до взвешивания. Ни одна ось не задета:
   обратимое микрорешение — строка «оси не задеты, смотрел X, Y» и дальше;
   продуктово значимое — построй вывод из цели, границ и «чем не является»
   GOAL · сцены Frame · соседних принципов вопросом «какое правило владелец
   уже оплатил рядом?», с пометкой «выведено, прямого принципа нет».
4. **Обратный проход** по лидирующему варианту: какой принцип мог бы его
   перевернуть? След обязателен.
5. **След** — решение + 2–3 строки матрицы, в работе или плане; ссылка на
   принцип несёт имя пары (`витрина:P-001`), голый `P-N` неоднозначен.
