# Каталог ЛЛМ-перекосов

Reference самодостаточен: skill может активироваться без соседних пакетов.
Authoring-time owner — source package; installed copy является deployment, не
второй truth. Если каталог повторяется в других source packages, синхронизируй
их до deployment.

## Принцип

Модель — машина наиболее вероятного продолжения. Систематическая опасность сидит
ровно там, где **наиболее вероятное ≠ нужное**. Эти места нельзя вычислить за
столом — у тебя нет доступа к собственным приорам; их **ловят в моменте**,
узнавая себя в одном из перекосов ниже. Каждая запись — место, где дефолт
расходится с нужным, в одной форме: _дефолт / нужное / тэлл (как поймать себя)_.

Что делать с пойманным перекосом — по цене ошибки:

- дёшево / обратимо → назови допущение вслух, спроси по EVPI или впиши дельту;
- дорого / необратимо → текст не enforcement: гейт (тест, валидатор, checkpoint).

Дельта — место осознанного отклонения от дефолта модели; её и стоит описывать.
Правило, которое не меняет решение агента (дефолт и так совпал с нужным), —
лишнее, его убирают.

## Универсальные — кусают в любой работе

### Рвётся выполнять

Дефолт: начать выдавать запрошенное сразу. Нужное: сперва прочитать ограничения,
owner-файлы и контекст. Тэлл: тянусь к Edit / Write / ответу раньше, чем прочитал
то, что управляет этой зоной.

### Имя вместо содержимого

Дефолт: принять имя папки / файла / символа за его смысл (`путь_клиента` → «про
интерфейс»). Нужное: открыть — имя врёт чаще, чем кажется. Тэлл: вывел, что
внутри, из названия, не заглянув.

### Тихое допущение о намерении

Дефолт: молча выбрать одно прочтение размытой просьбы и действовать по нему.
Нужное: вербализовать допущение о намерении до действия — это снижает и
сикофантию сильнее, чем общая просьба «будь честен». Тэлл: «и так понятно, что он
имел в виду» — без явно названного допущения.

### Дефолт на пропуске контекста

Дефолт: где контекст молчит — заполнить статистически средним ответом. Нужное:
средний ответ может быть именно тут неверным; пометь пробел, а не закрашивай.
Тэлл: выбрал очевидный вариант для того, чего документы вообще не задавали.

### Конфабуляция

Дефолт: выдать уверенный правдоподобный ответ. Нужное: «не знаю / нет в
контексте». Тэлл: не могу назвать строку, факт или источник, из которого вывод
следует.

### Поддакивание (сикофантия)

Дефолт: согласиться с рамкой пользователя — тем сильнее, чем увереннее звучит
«очевидно X». Это измеримое свойство модели, не лечится просьбой «спорь со мной».
Нужное: независимая проверка; несогласие — в начале ответа, с «почему именно».
Тэлл: чем очевиднее звучит — тем меньше я перепроверил.

### Подразумеваемое осыпается

Дефолт: из голой цели не вывести «что профессионал сделал бы сам собой» —
тацитную работу (тесты, регресс, обратимость, доки). Под нагрузкой осыпается даже
общеизвестное. Нужное: подразумеваемое → явные критерии готовности + гейт сверки
перед «готово». Тэлл: объявляю «готово» без списка, против которого сверился.

### Frame lock

Дефолт: защищать первую гипотезу против накопленного evidence. Нужное: после
нескольких раундов той же критики — пересобрать подход, не строчку. Тэлл: третий
раунд правок на тот же подход.

### Streetlight

Дефолт: работать там, где канона много и удобно. Нужное: главный unknown часто
там, где канона мало. Тэлл: «здесь много готовых ответов» — а развилка точно не в
другом месте?

### Симптом вместо механизма

Дефолт: починить строчку / файл / ошибку. Нужное: причину. Тэлл: что снова
вызовет эту ошибку после моей правки? Цел механизм — фикс поверхностный.

## При письме инструкций / текста — кусают будущего читателя-модель

### Буквальность scope (особенно Opus)

Дефолт: правило про один инстанс применить только к нему, не обобщить на класс.
Нужное: если правило про класс — пиши scope явно. Тэлл: «не трогай GOAL.md» — а
criteria.md рядом? Модель не распространит молча.

### Risk-слова overtrigger

Дефолт: читать CRITICAL / MUST / NEVER как риторическое усиление и подчиняться им
как mandate. Нужное: беречь сильные слова для реальных hard contracts. Тэлл:
«MUST» стоит на мягком предпочтении.

### Hyrum — непреднамеренный контракт

Дефолт: применять как правило любую observable деталь — «обычно мы…», пример,
комментарий, расположение секций. Нужное: отделить descriptive от prescriptive,
писать «default X; deviate when Y». Тэлл: строку-описание модель исполняет как
приказ, которого автор не давал.

### Lost-in-the-middle

Дефолт: вес началу и концу, середина длинного файла теряется на длинных ходах.
Нужное: hard rule не прятать в середину длинного файла. Тэлл: ключевое правило в
разделе 8 из 15.

### Лишнее правило backfire

Дефолт автора: больше правил = надёжнее. Нужное: начать с pruning — убрать
obsolete scaffolding, повторы, generic brevity и правило, которое не меняет
решение агента; vague / конфликтный контракт не лечить новым слоем текста. Тэлл:
не могу назвать, какое решение агента это правило меняет.
