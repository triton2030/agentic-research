# Muse Code под обёрткой

Замеры сделаны 2026-10-13 на Muse Code 1.4.7 с моделью `muse-wonder-1.0`.
Где сказано «по документации», живой проверки не было.

## Права без диалога

| Действие | Голый `muse exec` | Обёртка по умолчанию | Обёртка с `--read-only` |
| --- | --- | --- | --- |
| читать рабочую папку | да | да | да |
| читать файл вне рабочей папки | да | да | да |
| веб-поиск и чтение страниц | да | да | да |
| писать и править файлы рабочей папки | да | да | нет |
| команда оболочки | да, в песочнице | да, в песочнице | нет |
| запись командой вне рабочей папки | `Operation not permitted` | `Operation not permitted` | — |
| сеть из команды (`curl`) | да | да | — |

Обёртка по умолчанию передаёт `--disable-approval`, с `--read-only` —
`--disable-write --disable-shell`. Песочница в обоих случаях остаётся
включённой. От голого `muse exec` умолчание обёртки отличается одним:
подтверждения отключены, чтобы прогон не мог на них зависнуть.

Аудитор с правами по умолчанию и словами «файлы не меняй» в пробе запустил
проверочную команду и ничего не изменил: `changed: nothing`.

Встроенный профиль `--permission-profile :read-only` разрешает читающие
команды оболочки, но пишущую команду держит на подтверждении, и прогон висит.
С `--disable-approval` и `--approval-mode` профиль не сочетается, поэтому
обёртка его не использует. Имена профилей начинаются с двоеточия:
`:read-only`, `:ask-me`, `:auto-review`, `:unrestricted`.

Документация обещает, что песочница держит `.git` рабочей папки только на
чтение. На деле `git commit` из команды прошёл. В той же документации сказано,
что без просьбы Muse не коммитит; в пробе правки он оставил изменения
незакоммиченными.

`--yolo` снимает и подтверждения, и песочницу; обёртка его не передаёт.

## Что обёртка читает из `muse`

Она запускает `muse exec --json` и разбирает построчные события:

| Событие | Что берётся |
| --- | --- |
| `run.model.configured` | имя модели |
| запись с `stream.kind == "session"` | id сессии |
| `tool.result` | имя инструмента, исход, первая строка текста |
| `task.lifecycle.*` | вызов, который был предложен и не принят |
| последнее `run.terminal.*` | исход хода и текст ответа |

Имя модели в событии повторяет запрос и настоящую модель не доказывает:
на `--model muse-nope-9` пришёл обычный ответ с `model_id: muse-nope-9`.
Поэтому обёртка до вызова ищет закреплённую модель в локальном каталоге
`~/.local/share/muse/model-catalog/`.

Расхода токенов в событиях нет. Он есть в выгрузке
`muse export --session <id> --out файл.json`.

Список `changed:` обёртка строит сама: в git-папке это изменённые
и неотслеживаемые файлы с временем правки после старта, в остальных — обход
папки. Удалённые файлы в него не попадают.

По документации код возврата `muse exec` означает исход хода: 0 — завершён,
1 — сбой или отмена, 2 — ошибка вызова.

## Инструкции и чужой контекст

| Источник | Голый `muse exec` | Обёртка |
| --- | --- | --- |
| личные правила и скилы владельца из Claude Code и Codex | грузятся | отключены флагом `--no-foreign-personal-context` |
| `AGENTS.md`, скилы и хуки проекта | только в доверенной папке | то же; `--project-rules` доверяет папке на один прогон |
| встроенные скилы Muse | грузятся | грузятся |

По ответу самого Muse, с чужим контекстом в его каталоге 93 скила, без него 35. Запрос
подаётся только аргументом или через `--prompt-file`: stdin `muse exec` не
читает, поэтому обёртка пишет бриф во временный файл.

## Разговоры

`--resume` передаёт `--session-id`. Muse отказывает, если рабочая папка
другая. Сессии лежат в `~/.local/share/muse/sessions/`. Команда `muse resume`
открывает диалоговый интерфейс и для вызова без диалога не годится.

## Медиа

| Вид | Итог |
| --- | --- |
| PNG через чтение файла и через `--image` | открывается |
| PDF, MP3, WAV, M4A | `file is not valid UTF-8; binary tool-output refs are not implemented` |
| MP4 | `the selected model does not support video input` |

Отдельная команда `muse voice transcribe файл` расшифровала MP3 и WAV верно,
а M4A отвергла. Обёртка её не вызывает.

## Модели и лимиты

Видимые модели каталога: `muse-wonder-1.0` (по умолчанию),
`muse-wonder-full-1.0`, `muse-spark-1.3`, `muse-spark-1.2`. Уровни усилия:
`minimal`, `low`, `medium`, `high`, `xhigh`, `max`. Умолчания заданы
константами `DEFAULT_MODEL` и `DEFAULT_EFFORT` в `scripts/muse.py`; значения
флагов `--model` и `--effort` обёртка до вызова сверяет с каталогом.

`muse-wonder-full-1.0` на аккаунте владельца отвечает. По документации это
старший вариант, доступный только в планах Power и Maximum.

По документации лимит подписки считается в запросах за пять часов. Команды,
показывающей остаток, в справке и документации нет.

## Данные

Запросы и прочитанные файлы уходят в Meta. По документации в подписке по
умолчанию включён режим Contributor: он даёт больше лимита в обмен на право
Meta учить модели на содержимом. На один прогон его меняет флаг
`--contributor-mode on|off`; обёртка этот флаг не передаёт.

## Дочерние агенты

Muse умеет сам писать сценарий (`workflow`) и запускать до восьми дочерних
агентов разом; они наследуют права ведущего. Кроме того, каждый прогон
сопровождают его встроенные агенты-напоминатели. Обёртка просит Muse не
запускать сценарии без просьбы в брифе, но не запрещает их.

## Общие правила в приписке

К каждому брифу обёртка добавляет приписку: права прогона и общие правила —
не коммитить без просьбы, чужие правки не трогать и не откатывать, сценарии,
дочерних и других агентов не запускать без просьбы, бриф и свои ответы не
записывать как слова владельца. Текст лежит в константах `SHARED_RULES`,
`WRITER_NOTE` и `READ_ONLY_NOTE`.
