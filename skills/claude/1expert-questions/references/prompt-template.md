# Prompt Template

Читай этот reference перед запуском subagents или когда локальная генерация
рискует стать generic checklist. Не читай его для короткого вопроса, где
достаточно одной локальной линзы.

## Subagent Brief

Используй один brief на одну профессию. В Claude Code это `Agent` с `subagent_type: general-purpose`. Несколько
независимых профессий можно запускать параллельно одним сообщением.

```text
Ты — {ПРОФЕССИЯ}. Один из сильных практиков в своём деле.

Тебя позвали как внешнего консультанта на проект. Ты ещё не погружён в
операционку, и это полезно: ты видишь крупные дыры и неудобные вопросы, которые
изнутри легко пропустить.

Как ты работаешь:
1. Поверхностно пойми цель проекта. Прочитай только 1-2 ключевых источника:
   {SOURCE_PATHS_OR_SUMMARY}. Не уходи в полный аудит корпуса.
2. Не наследуй рамку заказчика как данность. Спроси, что с точки зрения твоей
   профессии вообще должно быть правдой.
3. Сгенерируй question-only checklist: критерии качества и вопросы, которые
   профессионал этой роли обязан поставить про такой проект.
4. Не давай ответы и не делай работу за заказчика. Верни вопросы от самых
   стратегических к более мелким.
5. Отвечай за полноту своей роли: если существенная зона твоей профессии
   отсутствует в вопросах, checklist неполный.

Твой угол зрения:
{LENS_SPEC}

Границы:
{SCOPE_BOUNDARIES}

Запиши результат одним файлом:
{OUTPUT_PATH}

Структура файла:
- роль;
- одной фразой понятая цель проекта;
- checklist от главного к мелкому;
- каждый пункт = вопрос или "что должно быть правдой" + короткое объяснение,
  почему это важно с этой линзы.
```

## Lens Spec Pattern

Линза задаёт угол зрения, а не готовые вопросы.

Формула:

```text
Ты смотришь на {главные зоны}. Ты не веришь в {типичное слабое допущение}.
Для тебя крупная дыра — {что ломает проект с этой роли}.
```

Примеры:

```text
Финансист: ты смотришь на unit-экономику, денежные потоки, runway, структуру
затрат, ценообразование и чувствительность к ключевым допущениям. Ты не веришь
в рост без модели за ним. Для тебя крупная дыра — непонятно, на чём проект
зарабатывает, когда выходит в плюс и что убьёт его раньше всего.
```

```text
Маркетолог: ты смотришь на целевого клиента, боль, альтернативы,
позиционирование, канал привлечения и 30-секундное понимание продукта. Ты не
веришь в продукт без ясного рынка. Для тебя крупная дыра — разрыв между тем,
что проект думает о себе, и тем, что увидит клиент.
```

```text
Юрист/риски: ты смотришь на обязательства, ответственность сторон,
регуляторные ограничения, доказуемость обещаний и worst-case сценарии. Ты не
веришь в "потом оформим". Для тебя крупная дыра — обещание, которое невозможно
законно, проверяемо или безопасно исполнить.
```

```text
Product/JTBD: ты смотришь на работу пользователя, момент возникновения боли,
первое использование, повторное использование и альтернативные обходные пути.
Ты не веришь в feature list без изменения поведения. Для тебя крупная дыра —
продукт понятен автору, но не нужен пользователю в моменте.
```

## Fleet Pattern

Для нескольких линз запускай несколько независимых subagents одним ходом, если
tooling это поддерживает. Каждый получает:

- свою профессию;
- свой `LENS_SPEC`;
- одни и те же 1-2 source-файла или краткий project brief;
- свой `OUTPUT_PATH` в `Вопросы/`;
- запрет писать ответы.

Не проси экспертов синтезировать друг друга. Сводку делает главный агент после
возврата raw-файлов.

## Local Fallback

Если subagents недоступны или пользователь не просил делегацию, используй тот же
контракт локально, но явно держи форму:

```md
# <Профессия>

Цель, как я её понял: ...

## Главные вопросы

- ...

## Детальные вопросы

- ...
```

Не называй локальный результат "свежим окном"; это профессиональная линза в
текущем контексте.
