# T3 Code под скилом

Замеры сделаны 2026-10-14 на T3 Code 0.0.46-nightly с уровнем входа
`full-access`, Muse Code 1.4.7 и `gemini-3.8-flash-high`. Где сказано «по
документации» или «по описанию инструмента», живой проверки не было.

## Подключение

MCP-сервер живёт внутри приложения: `http://127.0.0.1:3773/mcp`. В Claude Code
он добавлен на уровне пользователя под именем `t3`. Без запущенного T3 Code
инструментов нет. Сессия, начатая до подключения сервера, их не получает;
субагенты новой сессии получают.

Вход клиента одобряет владелец и выбирает уровень. При уровне «только чтение»
запуск треда отклоняется: `capability_denied … approved for read-only access`.
Владелец повторяет `claude mcp login t3` и выбирает полный доступ. Тред не
получает прав шире уровня входа. По документации вход действует 30 дней.

## Инструменты сервера

Сервер отдаёт около сотни инструментов. Часть из них действует от имени
вызывающего треда и клиенту снаружи отказывает: `This tool acts as the calling
T3 thread … This MCP client signed in from outside a thread`. Агент внутри
треда получает тот же сервер под именем `t3-code` и может всё.

| Группа | Инструменты | Снаружи |
| --- | --- | --- |
| что доступно | `orchestrator_capabilities`, `t3_environment_read` | да, замерено |
| проекты | `t3_project_list`, `t3_project_create`; `t3_project_read`, `_update`, `_clone`, `_delete` | первые два замерены |
| треды | `t3_thread_launch`, `_send`, `_wait`, `_read`, `_list`, `_configuration`, `_interrupt` | да, замерено |
| настройка и порядок | `t3_thread_configure` (сменить модель), `_update` (имя, пул-реквест), `_organize` (закрепить, отложить, закрыть, в архив), `_search` | по описанию; `_search` на существующий заголовок вернул пусто, а `_list` с `titleContains` нашёл |
| ветки и контекст | `t3_thread_fork`, `_merge_back`, `_transfers` | по описанию |
| очередь реплик | `t3_queue_list`; `_read`, `_edit`, `_cancel`, `_reorder`, `_promote_to_steer` | чтение замерено |
| вопросы агента | `t3_pending_request_list`, `_read`, `_respond`; разрешение на команду так не даётся | по описанию |
| вложения | `t3_attachment_prepare_upload`, затем `t3_thread_send_attachments`: картинки до 10 МБ, файлы до 50 МБ, до восьми за раз | по описанию |
| рабочие деревья | `t3_worktree_list`; новое дерево даёт `workspaceStrategy` в `t3_thread_launch` | по описанию |
| расписание | `schedule_task`, `list_scheduled_tasks`, `update_scheduled_task`, `run_scheduled_task_now`, `delete_scheduled_task` | чтение замерено |
| пул-реквесты | `link_pull_request`, `watch_pull_request`, `unwatch_pull_request`, `list_thread_pull_requests`, `write_pull_request_guides`, `read_pull_request_guide` | по описанию |
| сценарии Claude | `t3_workflow_stop` | по описанию |
| дочерние агенты | `delegate_task`, `task_status`, `task_cancel`, `create_threads` | нет: нужен вызывающий тред |
| браузер | `preview_open`, `_navigate`, `_click`, `_type`, `_snapshot`, `_evaluate`, запись экрана | нет, замерено |
| телефон | `device_list`, `device_open`, `device_screenshot`, `device_close` | нет, замерено |
| страница в ответе | `html_preview`, `html_render` | нет, замерено |
| прочее от имени треда | `request_secret`, `t3_worktree_handoff`, `t3_worktree_status`, `t3_environment_preferences_update` | нет, по описанию |

Что стоит знать до вызова, по описаниям инструментов:

- Расписание: интервал от минуты, фиксированное время по дням недели или
  вебхук. Вне треда каждый запуск открывает новый тред на умолчании проекта.
  Публичный адрес вебхука есть только при включённом T3 Connect.
- Слежение за пул-реквестом проверяет его раз в две минуты и будит тред при
  упавшей проверке, прошедших обязательных проверках, чужом комментарии или
  конфликте с базой. Кончается оно слиянием, закрытием или
  `unwatch_pull_request`.
- Браузер внутри треда общий с владельцем: он видит вкладку и может перехватить
  управление; профиль браузера несёт сохранённые входы.
- `device_open` поднимает симулятор iOS или эмулятор Android и показывает его
  владельцу; дальше агент водит устройство утилитой `agent-device`.
- `html_render` вставляет готовую HTML-страницу в ответ треда, `html_preview`
  возвращает её снимок и вывод консоли.
- `request_secret` показывает владельцу закрытую карточку; значение агенту не
  возвращается.
- `delegate_task` даёт агенту треда дочернего агента на любом провайдере:
  тот получает только текст задачи, без истории родителя.

## Проект и рабочая папка

- Вызывающий вне треда обязан дать `projectId` или `scratch: true`.
- `t3_project_create` с `title` и `workspaceRoot` регистрирует существующую
  папку и файлов в ней не трогает. С одним `title` T3 Code сам заводит
  git-репозиторий в `~/.t3/projects/<title>`.
- `scratch: true` даёт треду отдельную пустую папку в `~/.t3/scratch/`.
- Без `workspaceStrategy` тред работает в корне проекта. Стратегия `worktree`
  заводит отдельное рабочее дерево; незакоммиченные правки в него не
  копируются — по описанию инструмента.

## Права и контекст агентов

| Что | Muse | Gemini |
| --- | --- | --- |
| уровни прав | `full-access` и `approval-required` | все четыре |
| запись инструментом вне рабочей папки | проходит | отклоняется: `Access to path … is denied. It is outside the workspace` |
| чтение инструментом вне рабочей папки | не мерилось в треде; под `muse exec` читает любой файл | отклоняется: `Access to path … is denied. It is outside the allowed workspace directories` |
| команды оболочки вне рабочей папки | не мерилось | пишут и читают |
| личные правила и скилы владельца из Claude Code и Codex | загружены: 95 скилов и заголовки личных инструкций | не загружены |
| `AGENTS.md` проекта | выполнен | не выполнен; загружен ли файл, не установлено |
| коммит без просьбы | не делал | не делал |

Muse умеет сам писать сценарий и запускать до восьми дочерних агентов — по
документации Muse Code; по документации T3 Code он получает и инструменты
T3 Code. Под `muse exec` с чужими скилами в контексте он запустил семь дочерних
агентов ради вопроса о шести файлах.

По документации Muse Code чужие личные скилы отключает пользовательская
настройка; её имя там не названо, и она не проверялась. Свои общие скилы
Antigravity берёт из `~/.gemini/config/skills` — по документации T3 Code.

## Модель и усилие

`modelSelection` — объект с полями `instanceId`, `model` и `options`. Усилие
передаётся элементом массива `options`:
`{"id": "reasoningEffort", "value": "xhigh"}`. Доступные модели и уровни
показывает `orchestrator_capabilities`; список моделей Antigravity владелец
сократил до одной в настройках T3 Code.

| Ярус Muse | Замер |
| --- | --- |
| `muse-wonder-full-1.0` + `xhigh` | задача из пяти шагов с правкой и тестами — 130 с в треде; аудит трёх файлов с запуском скриптов — 519 с под `muse exec` |
| `muse-wonder-1.0` + `high` | вопрос по одному файлу — 15–40 с под `muse exec` |

Имя модели в ответе треда повторяет запрос. В пробе та же модель записана
и в сессии самого Muse. При запуске имя не сверяется: тред с выдуманной
моделью создался, а его первый ход упал за две секунды с `model … does not
exist or you lack access`.

## Реплика и продолжение

- `mode: "auto"` запускает простаивающий тред, правит идущий ход или встаёт
  в очередь. `steer` отклоняется с `thread_not_sendable`, пока тред готовится.
- Muse принимает реплику в тот же ход: `delivery: "steered"`.
- У Gemini ход отменяется — в ленте `The request was cancelled by the
  client` — и запускается заново с поправкой. Первую поправку в пробе он
  выполнил наполовину: назвал функцию по-новому и оставил старое имя
  псевдонимом; это нашёл аудит Muse. Вторую выполнил.
- Реплика в законченный тред начинает новый ход с памятью прежнего и той же
  моделью: `delivery: "started"`.
- `clientRequestId` делает повтор отправки безопасным.

## Ожидание и чтение

- `t3_thread_wait` с `timeoutMs` 58000 проходит; 180000 клиент обрывает
  с `The operation timed out`. Работу треда это не прерывает.
- `t3_thread_read` с `view: "messages"` отдаёт сообщения, с `view: "activity"`
  — шаги: команды с выводом, чтения и правки файлов, рассуждения. Длинный
  текст обрезается; остаток даёт тот же вызов с `itemId` и `textOffset`.
- Запись `checkpoint` в конце хода — изменённые файлы всей рабочей папки
  с числом строк. Автора она не различает, файлов вне папки не видит.
- По документации вопрос агента с фиксированными вариантами держит тред и при
  `full-access`: его показывает `t3_pending_request_list`, отвечает
  `t3_pending_request_respond`.

## Медиа в треде

Gemini: инструмент чтения вернул на MP3 и MP4 сырые байты. Цвета кадра он
получил разбором через `ffmpeg`, речь не получил. Те же файлы скрипт над `agy`
разобрал дословно за 29 секунд. По документации T3 Code вложение, кроме
картинки, передаётся агенту путём к файлу.

Muse под `muse exec`: PNG открывается чтением файла; PDF, MP3, WAV и M4A —
`file is not valid UTF-8`; MP4 — `the selected model does not support video
input`.

## Чтение и веб в треде

Gemini в треде проекта свёл семь файлов за 84 секунды: все семь адресов
`путь:строка` и цитат сошлись с файлами, рабочая папка не изменилась. Файл
вне проекта он не открыл и по строке «обходов не ищи» остановился за десять
секунд.

Страницу он прочитал инструментом `read_url_content`, другую нашёл
инструментом `search_web`: два пункта за 37 секунд, цитаты с адресами.

## Данные и лимиты

Запросы и прочитанные файлы уходят в Meta и Google. По документации в подписке
Meta по умолчанию включён режим Contributor: Meta вправе учить модели на
содержимом; режим меняет владелец. Остаток лимитов по документации показывает
T3 Code в разделе Usage → Limits; для Gemini его даёт и `agy -p /usage`.
