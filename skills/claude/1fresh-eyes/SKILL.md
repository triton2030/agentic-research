# Свежие Глаза — Панель Советников

## Цель

Взвешенная траектория: по одному вопросу на столе панель заведомо разных
линз возвращает разные отчёты; расхождения синтезированы, следующий ход
назван владельцу решения.

Не входит: методы самих ролей (живут в их definitions), cross-model
ревью (`1codex`), правка артефактов, финальная приёмка (продукт
`auditor`).

## Критерии успеха

- Вопрос на столе назван до запуска: что взвешиваем и что изменит ответ.
- У каждой линзы своя зона; брифы не взаимозаменяемы (swap-тест).
- Отчёты различаются: из каждого процитирована строка, которой нет в
  других.
- Родные вердикты сохранены; расхождение показано, не сведено
  голосованием.
- Decision-changing находка проверена по источнику; следующий ход назван.

## Инварианты

1. **Панель зовётся под вопрос на столе.** Нет названного вопроса и
   того, что изменится от ответа, — нет запуска: панель без вопроса —
   ритуал прогресса, те самые «зря их вызвали». Антипример: «много
   сделано, пора проверить» без решения на столе.
2. **Каждой линзе — своя зона; никому — моя рамка.** Проектная правда
   (GOAL, product-frames, findings, планы) — материал брифа; моя
   гипотеза, маршрут и подозреваемое место — нет. Первый проход — только
   новая non-fork `Agent`-инвокация. Иначе панель умножает мой prior.
   Антипример: три роли, один файл, один вопрос — различие только в
   `subagent_type`.
3. **Расхождение — продукт.** Совпадение всех отчётов — сбой запуска
   (одна линза под разными ярлыками), а не подтверждение. Антипример:
   свести отчёты к «все согласны — продолжаем».

## Дельта

Модель умеет запускать субагентов. Не умеет: удержать свою гипотезу вне
брифа; развести зоны так, чтобы отчёты не могли совпасть; прочитать
консенсус как сбой; сохранить родные формы вместо среднего вердикта.

## Известные сбои

`когда → сбой → цена → куда`

- бриф собран на глаз → зоны взаимозаменяемы → одна работа куплена
  трижды → [brief-templates](references/brief-templates.md)
- панель вернулась → вердикты усреднены → продукт потерян →
  [synthesis-and-evidence](references/synthesis-and-evidence.md)
- вернувшемуся нужен до-спрос → новый запуск вместо диалога (куплен
  дубль) либо диалог выдан за свежий голос →
  [steering-and-dialogue](references/steering-and-dialogue.md)

## Механика

**Гейт входа (след обязателен).** Перед запуском покажи: вопрос на
столе · что изменит ответ · состав (минимум три разные линзы ростера:
`business-critic`, `developer-critic`, `architecture-critic`, `smith`) ·
зона каждой. Swap-тест: бриф осмыслен в чужих руках — зона не выведена,
собери заново.

**Запуск.** Новые non-fork `Agent`-инвокации параллельно; бриф — по
шаблону reference: факты, материал проекта, зона, границы, read-only.
Роль не пересказывается — её метод живёт в definition.

**Одиночное исключение.** Явный запрос одного именованного критика или
evidence-продуктов `auditor`/`md-scout` (они не линзы панели) — без
панели, но через тот же гейт изоляции и ненаводящий бриф.

**Барьер.** Пока обязательные отчёты не вернулись — не коммитить, не
«готово», не финализировать решение.

**Приёмка (след обязателен).** Из каждого отчёта процитируй строку,
которой нет в других. Не нашёл — панель сбойная: почини зоны и
перезапусти слившиеся линзы; копии панелью не синтезируются.

**Синтез.** Родные вердикты · расхождения и их причина · проверка
источников decision-changing находок · следующий ход. Без голосования.

## Завершение

Следующий ход назван; родные отчёты доступны владельцу решения;
совпадения разобраны. Два до-спроса подряд не сузили решение — стоп.
`Agent` недоступен или роль не selectable — честный стоп без имитации.
