# Инструмент интервью

## Контекст

Когда несколько связанных решений владельца неудобно собирать по одному в
чате, обычная тематическая анкета создаёт правдоподобные вопросы, но не
гарантирует, что ответы изменят будущий результат и покинут временный файл.

## Цель

Временная форма `_ops/interviews/YYYY-MM-DD-topic.md` собирает только
связанные решения владельца, которые меняют названный результат. У каждого
ответа заранее есть адрес в настоящем owner-е и материальное последствие
неверной догадки; после проверки ответы перенесены, форма архивирована в
`_ops/interviews/_archive/`. Project root — ближайший `_ops`, затем VCS
root, иначе явный project cwd.

Интервью владеет формой и границей голосов; допуск вопроса — применение
правил `1use-principles`, `1planning` и `1product-shaping` к форме. Текущая
правда после обработки живёт у owners результата.

## Известные сбои

`когда → сбой → цена → куда`

- карта вопросов допущена, пора собирать форму → произвольная разметка
  смешивает вопрос, рекомендацию и голос владельца → неверный перенос →
  [cookbook](references/plain-markdown-cookbook.md)

## Механика

1. **Результат и факты до вопросов.** Назови решение или действие, которое
   разблокирует форма, тип результата и `owner/path`. Кандидат-вопрос не
   входит в форму, если ответ записан — добудь его; след поиска, как в
   `1use-principles`, шаг 1: заголовок раздела, где ответ лежал бы, либо
   «файла нет», — или выводится из Goal, принципов и записей владельца —
   маршрут `1use-principles` (копия словаря `1planning/questions.md`, правь
   вместе). Каждый снятый кандидат — строкой в блоке формы «Уже проверено,
   поэтому не спрашиваем». Повторяющийся класс молчания принципов — дыра в
   принципах: сигнал `1product-shaping`, не поток вопросов (копия инварианта
   `1use-principles`, правь вместе).

   Для каждого оставшегося решения составь карту
   `<метка вопроса> → адрес ответа → что станет неверным при ошибке`
   (примеры адресов: продуктовое — Frame/Principles, ход работ — план).
   При рефакторе каждый атомарный элемент получает отдельный блок. Форму
   заводи, когда связанных user-owned решений несколько и их ответы уходят
   к разным owners либо зависят друг от друга; иначе задай вопросы в чате.
   Если один ответ выбирает owner, тип результата или отменяет ветку,
   сначала создай маленькую форму только для этой развилки с адресом
   `owner unresolved`; продолжи после ответа.

2. **Форма.** Собери её из блоков
   [cookbook](references/plain-markdown-cookbook.md): каждый вопрос —
   самостоятельная секция с собственным полем ответа; уровни заголовков,
   метки и запреты разметки — там. Внесённый в поле ответа текст — голос
   владельца.

   Технический вопрос переводится в мир владельца: владелец отвечает про
   мир, следствие называет агент (копия `1product-shaping` →
   references/interview.md, «Поднимай язык»; правь вместе). Вопрос о том,
   что уже происходило, формулируй фактом и прошлым поведением
   («The Mom Test»); вопрос, фиксирующий требование, — бытовым сценарием
   «что должно произойти, когда…» («Specification by Example»);
   рекомендация в формулировку вопроса не встраивается. Имена — ярлыки:
   сюда входит только названная ось, ничего сверх неё.

   Под вопросом покажи, что ответ изменит, и рекомендацию с основанием;
   честной рекомендации нет — назови недостающий факт или owner-сигнал.
   Слабый default становится выбором владельца только после общей отметки
   «Готово к проверке»; пустое поле и молчание согласием не являются.
   Видимую часть пиши простым русским; техническое имя оставляй только
   рядом со ссылкой на owner-артефакт.

3. **Перенос до архива.** После команды «проверь» отдели проверенные факты,
   ответы владельца, выводы агента и unresolved items, затем перенеси ответы
   по исходной карте: дополняй существующий semantic owner; новый документ,
   включая `SPEC`, — только при отдельном читателе, lifecycle и owner-е,
   место определяет owner результата. Добавь в форму:

   ```md
   > Результат перенесён: <owner paths>
   > Pending: <items с owner-ом и причиной либо нет>
   ```

   Только затем перемести форму в `_ops/interviews/_archive/`.

## Завершение

Предъяви owner-paths результата, каждый pending item с его owner-ом и путь
архивированной формы.
