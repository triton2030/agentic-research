# Plain Markdown cookbook

Момент: карта вопросов допущена и нужно собрать форму. Файл владеет только
разметкой; отбором вопросов и lifecycle владеет `SKILL.md`.

Содержание: общий каркас · свободный ответ · выбор · решения по элементам ·
воротный вопрос · готовность.

## Общий каркас

```md
# Интервью: <тема>

Отвечайте прямо в файле: отмечайте варианты и заменяйте строки
«Напишите ответ здесь». В конце отметьте «Готово к проверке» или напишите
в чате «проверь».

<details>
<summary>Для агента — контракт результата</summary>

- Разблокирует: <решение или действие>
- Итог: <тип результата> → <owner/path>
- Достаточно, когда: <критерий>
- Уже проверено, поэтому не спрашиваем:
  - <факт> — <owner/source>
- Карта ответов:
  - «<вопрос>» → <owner/path#claim или решение caller-а>
    - Если угадать неверно: <материальное последствие>

</details>

---
```

## Свободный ответ

```md
## <N>. <вопрос>

<Что это решение изменит в результате.>

**Моя рекомендация:** <ход и основание>.

<details>
<summary>Для агента</summary>

- Адрес ответа: <owner/path#claim или решение caller-а>
- Если ошибиться: <материальное последствие>

</details>

### Ответ пользователя — <уникальная метка>

_Напишите ответ здесь, заменив эту строку._

---
```

Если честной рекомендации нет, вместо неё напиши, какого факта или
owner-сигнала не хватает.

## Выбор

Варианты должны различаться последствиями, а не формулировками. Нет честного
выбора — используй свободный ответ.

```md
## <N>. <вопрос>

<Что это решение изменит в результате.>

**Моя рекомендация:** <вариант> — <основание>.

- [ ] <вариант A> — <отличающее последствие>
- [ ] <вариант B> — <отличающее последствие>
- [ ] Другое — опишите ниже

<details>
<summary>Для агента</summary>

- Адрес ответа: <owner/path#claim или решение caller-а>
- Если ошибиться: <материальное последствие>

</details>

### Ответ пользователя — <уникальная метка>

_Напишите пояснение, если нужно._

---
```

Для выбора нескольких вариантов используй тот же блок и строку
`Отметьте всё подходящее`.

## Решения по элементам

При refactor-е каждый атомарный элемент получает отдельный блок. Вопрос
касается его функции и будущего owner-а, а не происхождения текста.

```md
## <N>. <атомарная единица>

Функция сейчас: <какое решение или действие она меняет>.

**Моя рекомендация:** <оставить / слить / перенести / удалить> — <основание>.

- [x] Оставить
- [ ] Слить
- [ ] Перенести
- [ ] Удалить

### Ответ пользователя — <уникальная метка>

_Если default неверен, напишите почему и что сделать._

---
```

Карта в начале формы адресует каждый элемент отдельно.

## Воротный вопрос

```md
# Интервью: <воротная развилка>

<Какой дальнейший результат зависит от ответа.>

**Моя рекомендация:** <вариант> — <основание>.

- [ ] <вариант A> — <отличающее последствие>
- [ ] <вариант B> — <отличающее последствие>
- [ ] Другое — опишите ниже

### Ответ пользователя — воротная развилка

_Напишите короткое пояснение, если нужно._

## Готовность

- [ ] Готово к проверке
```

Зависимую форму собери только после ответа.

## Готовность

Каждая полная форма заканчивается одинаково:

```md
## Готовность

- [ ] Готово к проверке
```
