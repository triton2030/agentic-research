# HTML

## Страница — Визуальное Дополнение К Чату

Владелец зовёт этот скил, когда слов в чате не хватило. Весь текст уже сказан;
страница не пересказывает его, а показывает. Её жанр — лучшая посадочная
страница, не документация и не окно переписки.

Соседние страницы и `_template.html` — не образец: зона даёт primitives, не
design template. Существующие артефакты могли быть собраны до этой планки;
наследовать их облик нельзя.

Обычная работа не включает аудит, browser-loop, скриншоты и проверку командами.

## Дизайн Золотого Стандарта

Центр скила. Правила красивого дизайна здесь не перечислены — ты их знаешь.
Держи золотой стандарт красивого, интересного, вдохновляющего дизайна по
книгам, авторам и методикам из своей памяти. Имена ниже — ярлыки осей, на самой
странице они не пишутся:

- **лучшие посадочные страницы и award-winning лендинги** — очень мало текста,
  крупные заголовки, креативные структуры: карточки, сетка, бенто, hero с одним
  сообщением, ритм секций;
- **«Refactoring UI»** — иерархию делают размер, вес и воздух, а не рамки;
- **Presentation Zen и Нэнси Дуарте** — экран несёт одну идею, слова уступают
  образу;
- **редакционный дизайн журналов** — выразительная типографика, врезки,
  контраст плотностей, крупное число как иллюстрация;
- **швейцарская сетка и бенто** — плитки разного веса в одной композиции:
  размер означает важность, а не порядок.

Следствия, за которые отвечает эта страница:

- несколько текстовых блоков подряд на одной ступени — облик чата и
  документации. Сворачивай в заголовок верхней ступени, число с подписью, схему
  или подпись к визуалу. Карточки и плитки с теми же абзацами внутри остаются
  той же стеной текста;
- анимация — носитель наравне с остальными, а не редкое украшение: она законна
  там, где показывает изменение, переход, причинность или связь. Уважает
  `prefers-reduced-motion`;
- parent владеет отношениями между частями, component — своим внутренним
  пространством, overlay — своей safe area. Одна форма ломается на разных
  ширинах — правь её общего владельца, а не добавляй заплатку под показанный
  экран: breakpoint меняет названную композицию, а не компенсирует ошибку
  базовой геометрии.

## План До Кода

Первое сохранение файла — план, не разметка. Он живёт в свёрнутом `details`
в начале `<body>`, сразу после шапки, и остаётся в странице.

План состоит только из присвоений — строк, которые видно в готовом файле
пальцем. Обещание поведения («слежу за отступами», «держу планку») в план не
пишется: замер показал, что имена и числа исполняются, а обещания — нет. План
не описывает внешний вид, порядок работы и намерения.

Присвой семь вещей:

- **страница → одна идея → композиция.** Главная идея страницы одной фразой и
  имя композиции, которая её несёт: `бенто`, `hero + auto-grid`, `switcher`,
  `timeline`, `split`. Имя должно быть видно в разметке. Страница делает одну
  работу читателя, а не собирает несколько.
- **блок → отношение → носитель.** Перечисли блоки. Каждому — какое отношение
  он показывает и чем идея передана с минимумом слов: имя DaisyUI component,
  carrier из `COMPONENTS.md`, режим Mermaid, график, анимация или отметка
  «такого отношения в Daisy нет, композиция своя». Проза законна только как
  явно записанное «отношения нет — проза».
- **блок → минимум ширины.** Число в `rem` или `ch`. Перенос назначается по
  минимуму блока, не по ширине экрана.
- **блок → что на узком.** Столбцы схлопываются, таблица прокручивается внутри
  рамки, подпись уходит вниз. Именованных переломов единицы; координат и
  наложений нет. Тянет написать `@media` → открой
  [layout-primitives](references/layout-primitives.md) → установленный класс
  раскладки зоны, который переносится сам, и форма порога.
- **текст → ступень.** Объяви шкалу страницы: не больше семи ступеней, каждая
  — готовая утилита зоны, не свой класс. Верхняя ступень гигантская, между
  соседними — пропасть, а не полшага. Каждому текстовому блоку — ступень.
  Собственных `font-size` и `font-family` в `assets/<slug>.css` — ноль.
- **свой класс → отношение.** Дефолт — ноль: композицию сначала ищи в Daisy и
  классах раскладки зоны из `COMPONENTS.md`. Отношению, которого там нет, —
  поимённый список авторских классов; каждый назван за отношение, не за вид.
  В CSS существуют только классы из списка.
- **свой CSS → потолок.** Сколько собственных `background`, `border`,
  `border-radius` и `padding` появится в `assets/<slug>.css` и на каких блоках.
  Совпала анатомия — ноль.

Разошёлся план с кодом — правь план, а не оставляй расхождение.

## Одна Общая Zone

Артефакт живёт в общей `_workspace/HTML_artifacts/` и связан с галереей
`index.html` — оттуда владелец находит все страницы:

```text
HTML_artifacts/
├── AGENTS.md · CLAUDE.md   # эта же stance для следующих агентов
├── COMPONENTS.md           # local tags уже установленных carriers
├── index.html              # каталог всех страниц
├── <slug>.html             # самостоятельные visual explainers
├── assets/<slug>.css       # дизайн конкретной страницы
├── assets/shared/          # общие components/styles/adapters
└── lib/                    # общие локальные libraries
```

Per-page bundle, отдельные `lib/assets` и копия runtime не создаются.

Создай страницу из корня проекта:

```bash
"<каталог skill>/scripts/new_html_artifact.sh" "<slug>"
```

Не корень — передай его вторым аргументом. Команда достроит недостающий shared
layer, создаст `<slug>.html` и `assets/<slug>.css`, пересоберёт каталог и
напечатает ссылки. Дальше сразу редактируй страницу.

Шапка со ссылкой на `index.html` уже стоит первым элементом `<body>` — не
удаляй её. Удалил или переименовал HTML руками — пересобери каталог:

```bash
"<каталог skill>/scripts/rebuild_html_catalog.sh" "<project-root>"
```

## Покажи, Не Пересказывай

Проза — последний носитель. Абзац остаётся только смыслу, в котором нет
показываемого отношения; прозе законно принадлежат подпись, связка, короткий
вывод и текстовое резюме визуала.

- вложенность — вложенной композицией;
- процесс, ветвление, движение данных — flow;
- план и события — steps или timeline;
- сравнение — рядом или таблицей;
- реальные величины, доли и изменение — chart;
- действие и смена состояния — управляемым motion;
- необязательная глубина — `details`, popover, `dialog` рядом с тезисом.

Носитель выбирай по отношению, не по эффектности; недобравший носитель поднимай
по лестнице [visual-routing](references/visual-routing.md) до названного там
порога, выше не поднимай. Нет реального отношения — visual не нужен.

Артефакт переводит подтверждённый материал в наглядную форму, а не сочиняет
удобную версию. Свой комментарий — риск, гипотезу, вывод, аналогию — назови и
отдели от фактов. Существенный смысл живёт в semantic DOM: headings, labels,
captions, text summary, обычные links; цвет, position, hover, анимация и canvas
не несут ответ в одиночку.

## Объясняй Просто И С Удовольствием

Язык страницы — по тем же методам, что «Форма Ответа» /123-explain (правь
вместе): Фейнман — сложное простым языком; «Made to Stick» — конкретика против
проклятия знания; Брайсон и «What If» Манро — бытовая аналогия, лёгкая шутка,
живой рассказ. Берётся только язык: вёрстка, порядок разделов, эмодзи и таблицы
«Формы Ответа» принадлежат чату, не странице.

- одна мысль — одно предложение; действие — глаголом; абстракция — конкретным
  «было → стало»; термин пояснён рядом;
- трудный смысл несёт бытовую аналогию — подписью, сравнением или inline SVG;
- шутка живёт в подписях и пустых состояниях, не в данных: факты и числа
  остаются точными.

## Что Уже Готово

Палитра одна: DaisyUI theme `cupcake`, `<html data-theme="cupcake">`. Второй
палитры нет — authored CSS, SVG, ECharts, Mermaid, React Flow и каталог берут
Daisy semantic tokens либо `color-mix()` от них; vendor bytes не переписываются.
`base-content` — обычный foreground; значимые marks на бумаге —
`primary-content`, `secondary-content`, `accent-content`; `neutral-content` —
только на `neutral`; `info`/`success`/`warning`/`error` — только настоящие
статусы, не категории данных. Цвет различает больше трёх категорий →
`option.color` из brand-content/base-content и `color-mix()`. Shared adapters
переводят Daisy OKLCH в формат runtime — своего кода конвертации не пиши.

Совпала анатомия — бери Daisy component (card, badge, collapse, modal, tabs,
steps, timeline, table, alert, tooltip): он несёт свои состояния и сам выбирает
content-цвет. Композиция, вложенность, page-grid, канва, типографика и ритм
принадлежат странице. Нет носителя в Daisy — создай свободно; custom layout не
называй `card`, `hero`, `navbar`, `drawer` без их contract.

Tailwind, Alpine и Lucide подключены. Table, Mermaid, ECharts и React Flow
лежат в `lib/` и `assets/shared/` — подключи tags нужного носителя из его
reference, без CDN, installer, server и build step. Всё локально: страница
открывается по `file://` без сети. React Flow node содержит любой semantic HTML
и по составу принадлежит странице; ECharts recipes задают отношения data/options,
не page composition.

## Готово

План в `details` совпадает с кодом; страница не похожа ни на чат, ни на
документацию; главная идея и реальные отношения читаются глазами; факты не
выдуманы; термины, которых читатель может не знать, пояснены рядом; трудный
механизм несёт помеченную аналогию; страница открывается по первой напечатанной
ссылке. На этом остановись.
