# Форма По Смысловой Связи

Читай перед композицией сложного explainer, plan, diagram или data story.
Сначала найди отношение в источнике; затем выбери самый простой носитель,
который делает это отношение видимым.

## Карта

| Отношение | Первый носитель | Не использовать |
| --- | --- | --- |
| Состав, «что внутри чего» | вложенные semantic blocks; card внутри card только при реальной иерархии | глубже двух визуальных уровней; зависимость вместо состава |
| Последовательность | steps | независимые темы |
| Время, план, события | timeline; Mermaid `timeline`/`gantt` при данных | приоритеты без времени |
| Процесс, причинность, ветвление | малая схема HTML/SVG; Mermaid `flowchart` | линейные 2–3 шага |
| Поток данных между rich nodes | React Flow при выполнении его порога | статичная схема и дерево страниц |
| Сравнение по общим полям | table; два объекта — side-by-side | tabs, которые прячут сравниваемое |
| Часть от целого | одна 100% stacked bar + числа; pie только для 2–4 реальных долей | оценочные числа, >5 долей, сравнение периодов |
| Величина по категориям | bar; horizontal при длинных labels | данные без общей единицы |
| Изменение во времени | line/`xychart`; при <4 точках — table | неравные интервалы без явной оси |
| Связь двух величин | ECharts scatter при реальном числовом ряде | категории или три случайные точки |
| Потери/перераспределение потока | ECharts Sankey при известных значениях links | обычная последовательность шагов |
| Иерархия с вкладом частей | ECharts treemap при числовых `value` | структура без сопоставимых величин |
| Текущее состояние | stat + контекст, `<meter>` или `<progress>` | когда вывод в динамике |
| Состояния одного объекта | native control или Alpine toggle/tabs | другой reader job |
| Действие и переход | motion, привязанный к реальной смене state | decorative autoplay и ложный progress |
| Необязательная глубина | `details`, popover, `dialog` | главный ответ, риск или следующий ход |

## Лестница Носителей

1. Native semantic behavior + совпавшая DaisyUI-анатомия + CSS composition:
   nesting, disclosure, steps, timeline, stat, table и простые bars. Custom CSS
   связывает готовые components, но не перерисовывает их anatomy.
2. Inline SVG: одна фиксированная схема или chart с небольшой геометрией.
3. Mermaid: topology или chart задаётся данными; нужен auto-layout либо viewer.
4. ECharts: несколько quantitative views, exploration либо Sankey/treemap/
   heatmap/scatter требуют одного общего local runtime.
5. React Flow: одновременно нужны rich interactive nodes, pan/zoom и
   направленные data-flow edges.

Не переходи вверх, пока более дешёвый носитель показывает то же отношение.

## Chart — Только Для Данных

Chart требует числового ряда, единицы и честного масштаба. Если числа являются
оценками, категориями или порядком, визуализируй их как статусы, labels или
steps. Pie не является default: 100% stacked bar легче сравнивается; pie
оставь одному целому с 2–4 заметно различимыми сегментами.

Каждый chart получает title/caption, labels значений и короткий вывод. Цвет не
заменяет label. Не добавляй data interaction, если control не меняет вывод.

## Motion — Носитель Изменения

Motion как **носитель смысла** показывает направление потока, причинность,
перенос объекта или смену state. Запускай его по действию читателя либо
привязывай к реальному progress. Сохраняй статический кадр с тем же смыслом и
reduced-motion вариант.

Motion как **подача** — появление секции, отклик на hover, плавный переход
состояния — принадлежит языку страницы и здесь не ограничивается: он не несёт
смысла, поэтому и не может его исказить. Требование одно: `prefers-reduced-motion`
и читаемая страница без анимации вовсе.

Scroll-driven story оправдана только когда минимум три шага меняют один общий
visual и каждый добавляет один вывод. Обычная череда секций не scrollytelling.

## Falsifier

Удали visual мысленно. Если вместе с ним исчезает только декор, а не отношение,
visual не нужен. Если visual понятен только после чтения исходного абзаца,
перестрой его или оставь текст.
