# DaisyUI Как Язык Рассказа

Выбирай компонент после того, как понятна задача читателя. Компонент должен
сокращать путь к выводу, сравнению или действию.

## Три Слоя Информации

| Слой | Что входит | Как показывать |
| --- | --- | --- |
| Must-see | Вывод, действие, критический риск | Всегда видимо: hero, verdict card, alert |
| On-demand | Evidence, источники, оговорки, примеры | `collapse`, accordion, tabs или modal по смыслу |
| Omit | Повтор, служебный шум, неработающая ветка | Не выводить |

Не прячь содержание только ради чистого экрана. Progressive disclosure нужен,
когда вторичный материал полезен, но мешает первому чтению.

## Карта Смысловых Ходов

| Задача читателя | DaisyUI-форма | Правило |
| --- | --- | --- |
| Унести один вывод | `card` + `alert` | Вывод и причина видимы сразу |
| Выполнить процедуру | `steps` | Один шаг — одно действие |
| Понять хронологию | `timeline` | События идут во времени, не по приоритету |
| Сравнить два состояния | `diff` или side-by-side cards | Один критерий сравнения |
| Выбрать из равноправных вариантов | `tabs` | Не использовать для линейного процесса |
| Услышать разговор | `chat` | Реплики короче обычных абзацев |
| Увидеть числовой сигнал | `stats` | Только реальные числа с контекстом |
| Переключить представление | `swap` или `tabs` | Смысл сохраняется в обоих состояниях |
| Проверить UI states | DaisyUI `select` + Alpine `x-model` / `x-show` | Чистый экран по умолчанию; states не дублируются страницами |
| Показать комментарии к прототипу | Alpine toggle + `alert` / drawer | Комментарий отделён от продуктового текста |
| Раскрыть evidence и оговорки | `collapse` / accordion | Основной вывод остаётся снаружи |
| Сфокусировать редкое действие | `modal` | Не прятать основной маршрут |

## Progressive Disclosure

- Один независимый блок подробностей — нативный `details.collapse`.
- Несколько взаимоисключающих блоков — accordion.
- Равноправные представления одних данных — tabs.
- Редкая подробная задача, требующая фокуса, — modal.
- `tooltip` содержит только короткое необязательное пояснение.
- `carousel` подходит для необязательных примеров или изображений, но не для
  аргумента, который читатель обязан увидеть.
- Drawer оправдан только реальной дополнительной навигацией или инструментами.

Предпочитай нативные `details`, `dialog`, radio и checkbox controls. Alpine нужен
только когда нативного состояния недостаточно.

Для нескольких UI states, comments и общего prototype instrument используй
[`alpine-prototypes.md`](alpine-prototypes.md), а не inline state-комбайн в
каждом HTML.

## Семантические Ограничения

- `badge` — короткий статус, тег или число. Фраза и предложение принадлежат
  обычному тексту, heading, alert, card или collapse title.
- `alert` — важное видимое событие, а не декоративная плашка.
- `steps` отвечает на «что делать», `timeline` — на «что произошло».
- `tabs` не заменяют последовательное чтение.
- Иконка не должна быть единственным носителем смысла.
- Интерактивный элемент обязан менять понимание, фокус или объём видимого
  контекста; иначе оставь статичный текст.

Точную структуру выбранного компонента ищи по его имени в
`references/daisyui-llms.txt`, не загружая весь файл.
