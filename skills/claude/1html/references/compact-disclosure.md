# Компактное Раскрытие Без Потери Смысла

Читай этот reference, когда материал уже полезен, но одновременно видимых
блоков, controls или деталей слишком много. Цель — уменьшить visual load и
число решений на первом экране, не сокращая существенный смысл.

## Содержание

- Инвариант

- Карточки механик

## Инвариант

Оставляй видимыми главный смысл текущего представления и минимальную опору для
его чтения. Для explainer это может быть короткий вывод; для plan — порядок и
текущий момент; для canvas или prototype — модель и начальное состояние.
Скрывай только связанную глубину: evidence, пример, определение, edge case,
альтернативное представление или служебный инструмент.

Компактность означает «меньше одновременно», а не «меньше знания». Default
state обязан быть понятен сам по себе. Trigger называй по обещанной глубине:
«Показать расчёт», «Сравнить состояния», «Открыть комментарии», а не
«Подробнее».

## Карта Выбора

| Отношение между частями | Механика | Оставить видимым |
| --- | --- | --- |
| Один тезис и необязательная глубина | `details.collapse` | тезис и краткий вывод |
| Несколько однотипных глубин, читается одна | accordion | названия всех секций |
| Равноправные виды одного объекта | tabs | общий контекст и вывод |
| Одно бинарное состояние | toggle или `swap` | точное имя состояния |
| Один выбор из многих состояний | `select` | текущий state и его результат |
| Короткий набор действий или вариантов | dropdown / popover | основной ход страницы |
| Несколько тесно связанных controls | `join` | общий label группы |
| Сужение списка или таблицы | filter controls | число результатов и active filters |
| Редкая сфокусированная задача | native `dialog.modal` | причина открытия и результат |
| Большой вторичный workspace | drawer | основной artifact без панели |
| Микропояснение control | tooltip | доступное имя control |
| Два изображения «до / после» | `diff` | текстовый вывод сравнения |
| Серия ракурсов одного объекта | carousel | порядок и подписи кадров |

Если меняется reader job, создавай отдельную HTML-страницу. Состояния одной
модели можно оставлять внутри страницы.

## Карточки Механик

### Collapse: Ближайшая Глубина

Используй нативные `details`/`summary` с DaisyUI `collapse` для evidence,
источника, примера или оговорки к ближайшему видимому тезису. DaisyUI допускает
`details` как owner открытия; отдельный Alpine-state не нужен.

Не помещай внутрь единственный носитель главного смысла или новую независимую
тему. Не вкладывай disclosure друг в друга без реальной иерархии: второй слой
обычно означает, что материалу нужен собственный section или page.

### Accordion: Один Из Однотипных Разделов

Используй accordion для FAQ, вариантов реализации или диагностических веток,
когда достаточно держать открытым один элемент. Начинай с native
`<details name="group">`: браузер сам держит открытым один пункт. DaisyUI
`collapse` оформляет те же semantic elements; radio-вариант нужен только при
доказанной несовместимости target browser.

Не используй accordion для последовательного аргумента: закрытие предыдущего
шага разрушит контекст.

### Tabs: Равноправные Виды Одного Объекта

Используй tabs для «обзор / данные / интерфейс», состояний одного prototype или
разных проекций одной сущности. DaisyUI показывает tab-content через radio
inputs; одна группа получает уникальный `name`.

Не прячь в tabs одновременно сравниваемые варианты. Для comparison используй
side-by-side, table или `diff`. Tabs не заменяют навигацию между reader jobs.

### Toggle И Swap: Два Состояния

Используй `toggle` для настоящего on/off свойства: комментарии, annotations,
technical names. В DaisyUI toggle остаётся checkbox, поэтому label должен
называть состояние, а не только действие.

Используй `swap`, когда в одном compact control заменяются ровно два небольших
представления — иконка, label или короткий preview. `swap-on` и `swap-off`
управляются checkbox или классом `swap-active`.

Не используй toggle или swap как ссылку на другую страницу и не прячь за ними
длинный самостоятельный рассказ.

### Select, Dropdown И Filter: Компактный Выбор

Используй `select`, когда состояний много и каждое имеет короткое устойчивое
имя. Для 2–4 равноправных видов tabs обычно быстрее считываются.

Используй dropdown для короткого меню или локальных действий. Начинай с
нативных `details`/`summary` или `popover` + `popovertarget`; они дают light
dismiss и top layer без Alpine. Не переноси туда обязательную инструкцию или
длинную справку.

Используй DaisyUI `filter` для одного взаимоисключающего признака: это radio
group с reset. Для нескольких независимых фильтров или derived results применяй
готовый Alpine table helper, не создавая параллельный state.

Объединяй тесно связанные buttons или inputs через DaisyUI `join`: прямые дети
получают общий визуальный контур, горизонтальный или вертикальный. `join` не
уменьшает число решений, поэтому не склеивай им несвязанные действия.

### Modal И Drawer: Вторичный Рабочий Слой

Начинай modal с нативного `<dialog>`: он подходит редкой сфокусированной задаче,
закрывается через dialog semantics и удерживает focus внутри. Popover-вариант
уместен только когда focus trap не нужен.

Используй drawer для большого вторичного workspace: comments, sources,
properties или inspector. DaisyUI drawer требует держать основной page content
в `drawer-content`; панель живёт в `drawer-side`.

Не делай modal или drawer складом обязательного содержания. После закрытия
основной artifact должен оставаться понятным.

### Tooltip: Только Микропояснение

Используй tooltip для расшифровки иконки или короткого термина. Сохраняй
видимый либо доступный label: hover не является надёжным способом передать
существенный смысл и отсутствует на touch как постоянное состояние.

### Diff, Carousel И Table: Плотные Специализированные Формы

Используй `diff` для пространственного сравнения двух изображений и рядом дай
текстовый вывод. Используй carousel для ракурсов или кадров одного объекта;
порядок, подписи и ключевой кадр не должны зависеть от случайного scroll.

Используй table, когда ценность находится в строках и сравнении полей. На малом
экране DaisyUI рекомендует wrapper с horizontal overflow; поиск, filters и sort
добавляй только когда они сокращают путь к нужной строке.

## Граница Alpine

Сначала выбирай native HTML + DaisyUI. Подключай Alpine, только если несколько
controls меняют одну модель или появляется derived presentation.

- `x-show` — часто скрываемая ветка; DOM и local state сохраняются.
- `<template x-if>` — редко создаваемая тяжёлая ветка; внутри нужен один root.
- `x-if` не поддерживает `x-transition`; для обычного disclosure предпочитай
  `x-show` или native `details`.
- `x-transition.opacity` достаточно для большинства смен состояния.
- Persist, Focus, Collapse и Sort plugins не входят в core bundle; не добавляй
  plugin без повторяемого эффекта, который нельзя выразить текущими средствами.

## Провалы

- Первый экран состоит из controls, но не объясняет модель или начальное
  состояние.
- Все sections закрыты, и читатель должен угадывать маршрут.
- Trigger называется «Подробнее» и не объясняет, что откроется.
- Tabs скрывают сравниваемые варианты или заменяют дерево страниц.
- Tooltip, цвет или иконка остаются единственным носителем смысла.
- Несколько toggle управляют одним состоянием из разных мест.
- Modal и drawer содержат обязательный следующий шаг.
- Carousel используется для prose, которую надо прочитать целиком.
- Интерактивность добавлена ради демонстрации DaisyUI, а не ради сокращения пути
  к пониманию.
