# Самостоятельные случаи и reference-файлы

Reference-файл нужен, когда его содержание требуется в отдельный момент.
Число файлов не уменьшает нагрузку, если читатель всё равно должен
применять их одновременно.

## Когда выбираешь границу

Назови решение, ради которого нужен файл, наблюдаемый вход и окончание
случая. Проверь, достаточно ли читателю тела, этого файла и результатов
завершённых стадий. Требования, которые продолжают действовать после выхода,
остаются частью активной нагрузки.

Тело держит условие чтения; файл — уникальную логику случая. Сам адрес не
говорит, когда материал нужен. Если правило уже доступно в теле, reference
добавляет недостающую механику или evidence, а не пересказывает его заново.

## Когда пишешь файл

Дай ему достаточный Контекст, конкретную Задачу и Цель выбора; Критерии
появляются только при остаточной лазейке. Каждый раздел имеет собственную
роль. Объём и набор заголовков не служат квотой для заполнения.

Reference не запускает цепочку чтения других references. Исключение —
`refactor.md`, который восстанавливает намерение через `goal-context.md`
и возвращает в тело до проверки потерь. Если одному моменту нужны несколько
файлов, пересмотри границы: объедини связанную логику или разведи реальные
стадии. Формальный перенос не выключает обязательство.

## Когда проверяешь разделение

Возьми конкретное решение и назови действующие сейчас знания и требования
из тела, текущего файла и старших инструкций. Сравни с соседним моментом:
ненужное уже завершено, позднее ещё не включено. Короткий случай остаётся
коротким; наполнять его до числа не требуется.

При совместно необходимых условиях сохрани связь и объясни, почему их
разделение потеряет смысл. Повторы и общие советы проходят отбор на снятие;
необходимые частные решения сохраняются. Ни количество заголовков, ни
склейка пунктов не доказывают меньшей нагрузки.

## Когда оформляешь роль или слова пользователя

Файл роли в `agents/` создаётся по запросу пользователя. У роли есть свой
вход, предмет проверки и выход; она не зависит от памяти основного автора.
Отдельное окно разгружает автора только от переданного решения, но не
освобождает проверяющего от его собственных требований.

Дословные слова пользователя сохраняют свою силу. Их сокращение,
переформулирование или снятие опирается на его разрешение; принятое изменение
фиксируется с причиной. Утверждённая граница правки не требует заново
спрашивать разрешение на уже названное изменение.

Выход: самостоятельные файлы с понятными входами и окончаниями, без
повторных владельцев одного правила.
