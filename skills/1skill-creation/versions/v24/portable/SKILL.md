# Создание скилов

## Контекст

Скил — личный промпт пользователя под кодовым словом.
Исполняет его агент без истории создания — Opus, Sonnet-субагент или Codex, —
поэтому полезна только дельта к знанию этого исполнителя.

В этой работе повторяются два сбоя: автор пересказывает одно намерение
в разных разделах, а правка начинается раньше, чем пользователь, который
думает вслух, договорил замысел, — и проверки наслаиваются, сделанное уходит
в корзину, малая правка тянется часами.

## Задача

Создай или переработай скил из намерения пользователя, проверь его в объёме
по типу правки и доставь в предназначенные среды.
Форму текста задаёт `1agent-steering`; этот скил — форму скила, проверку
и доставку.

## Цель

Исполнитель скила выбирает нужные пользователю действия при минимуме
одновременно необходимых требований.
При споре между полнотой шаблона и достаточным пониманием сохраняй
существенный смысл и меняй способ его передачи.

## Когда начинаешь

Мастерская глобальных скилов — `/Users/triton/Documents/GitHub/agentic-research`,
даже когда запрос пришёл из другого репозитория.
Прочитай её `AGENTS.md`, найди владельца пакета по `skills/shared/README.md` —
правка начинается с tracked owner, установленный пакет — его проекция —
и прочитай `1agent-steering` целиком.

Для существующего скила прочитай пакет и принципы у владельца: в них
действующие решения пользователя.
История в `skills/<имя>/` — архив; снятые там правила не помечены, и по ней
не пишут.
Назови тип правки: адресная — названо, что менять; полная переработка —
переосмыслить функцию.
Покажи пользователю набросок в 3–5 строк — для нового скила это момент вызова
по `references/description.md` и что изменится против поведения без скила —
и спроси, что ещё.
Пиши после ответа.
При полной переработке веди с начала границу заказа и карту потерь: что
снято, где смысл теперь или почему снят.

## Когда пишешь

- Порядок: Контекст → Задача → Критерии принятия → Цель, затем разделы
  «Когда …» по реальным моментам работы, по самым важным и сложным частям,
  включая моменты, когда включается знание. Раздел есть, только если у него
  есть содержание: малому скилу хватит абзаца.
- Задача — вмешательство и результат: что исполнитель делает иначе, чем
  без скила. Цель — высшее намерение и тайбрейкер при споре способов.
- Важное стоит в начале тела: после сжатия разговора Claude Code возвращает
  только первые 5 000 токенов скила. Правило, которое нельзя нарушить
  ни разу, оформляй хуком.
- Способ, предложенный пользователем, снимается только с названной ему
  причиной; его дословные слова меняются в пределах его разрешения.
- Reference — для ветки, нужной не каждому запуску; условие чтения стоит
  в теле. Reference самостоятелен и не отправляет к другому reference.
  Файл роли в `agents/` — только по просьбе пользователя.
- Тело и references — по-русски; имя и `description` — по-английски,
  по `references/description.md`.

## Когда проверяешь

Сначала проверь сам: прочитай черновик против источников и пройди ключевые
случаи.
Проверку субагентами предложи пользователю в конце, когда черновик готов,
и запускай после его разрешения: на незаконченном черновике она проверяет то,
что потом изменится.
Объём — по типу правки: адресной — одна проба затронутого случая и один
проверяющий из другой семьи моделей; новому скилу и полной переработке —
пробы ключевых случаев и три проверяющих по `references/review.md`,
допустима одна повторная волна.

Проба — свежий агент на модели-исполнителе со скилом и рабочим заданием
без ожидаемого ответа, каждый раз на нетронутом случае.
В составе предложенной проверки сравнение с прежней версией и замер вызова
в Claude Code ведёт `skill-creator`; песочницу и порядок действий агента даёт
`scripts/probe.py`.
Согласие проверяющих пробы не заменяет.
Смысловая правка после пробы отменяет её результат для затронутого поведения:
перепроверь его с разрешения пользователя или назови непроверенным.
Находку принимай по словам пользователя, контракту или наблюдению, а не
по уверенности проверяющего.

## Когда доставляешь

Уже данное разрешение на правку и установку сохраняет силу; одобрение
наброска разрешением на установку не является.
Если установка ещё не разрешена, покажи готовый результат и получи разрешение.
Запиши версию во владельца, синхронизируй проекции и сверь каждую среду:

```bash
python3 skills/shared/sync_simple_projections.py <имя> --write --install
python3 skills/shared/sync_simple_projections.py <имя> --check
```

Среду, куда доставка не состоялась, назови.
История — в `skills/<имя>/`: снимок `versions/<id>/` и один рассказ
в `work/<id>/README.md` — что сохранено и снято, пробы, решения; README
истории получает строку со ссылкой на рассказ, решения пользователя —
принципы у владельца.
