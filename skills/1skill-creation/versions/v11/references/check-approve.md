# Проверка и утверждение

Вход: полный черновик готов к проверке перед записью в официальные папки скила.
Не записывай его до решения пользователя.

## Желаемый результат

- Черновик, `cut.md`, продуктовая рамка, находки и решения сохранены в
  папке-истории.
- Два независимых проверяющих дали выводы по буквальному выполнению и по цели с
  траекторией.
- Каждая находка получила решение основного агента `принять` либо `отклонить`
  с прямым evidence; принятые исправления внесены.
- Материально изменённые свойства имеют evidence, способное их опровергнуть;
  внутренние ссылки и пути проверены на полной exact-byte версии.
- Пользователь видит точную проверенную версию и безусловно утверждает именно
  её до записи в официальные папки.

## Принципы доказательства

- В каждой волне независимо запусти с чистым окном ровно двух проверяющих по
  `../agents/check-instructions.md` и `../agents/check-trajectory.md`. Передай
  каждому весь названный там вход и не показывай выводы другого. Реалистичный
  случай входит в trajectory-проверку; третьего проверяющего для него не нужно.
- Считай вывод проверяющего гипотезой, а не приказом или approval. Ищи
  альтернативное объяснение и принимай находку только когда она подтверждена
  буквальными словами владельца, действующим протоколом либо наблюдаемым следом
  и не противоречит им; отклонение сохраняй с причиной.
- Одна волна проверяет одну неизменную версию и заканчивается одним terminal
  ответом каждого проверяющего. Они не вызывают других проверяющих и не входят
  в переписку, повторную приёмку или совместное согласование.
- За всю задачу создания или рефактора допустимы максимум две волны:
  `черновик → волна 1 → решения и исправления → волна 2 → финальные решения и
  исправления → стоп`. Новая версия, repair-cycle или переименование claim-а
  счёт не обнуляют; после второй волны субагентов больше не вызывай.
- После финальных исправлений основной агент сам проверяет текущие точные байты,
  причинно затронутое semantic evidence и остаточные риски.
- Semantic evidence принадлежит устойчивой паре `property + falsifier`.
  После дельты трассируй
  `изменение → решение или допущение → property → falsifier`: новое или
  материально изменённое свойство требует нового evidence, а незатронутое
  сохраняется только с причинным обоснованием.

## Непреодолимые границы

- Проверяющие не утверждают версию и не решают, какие изменения принять.
- Не сохраняй stale evidence для затронутого свойства и не отменяй semantic
  evidence только из-за изменения общих входных байтов.
- Механически проверяй текущую полную версию после каждой правки.
- Любая правка отменяет exact approval, но только причинно затронутое semantic
  evidence.
- Не меняй молча дословное решение пользователя и не возвращай отклонённое из
  `cut.md`.

Выход: решение пользователя по точной проверенной версии.
