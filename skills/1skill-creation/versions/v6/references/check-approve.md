# Проверка и утверждение

Вход: черновик готов, и его пора разнести по официальным папкам скила —
живым пакетам и tracked owner. Не записывай — сначала пройди этот протокол.

1. Подготовь черновик к записи:
   1. Собери в папке-истории скила черновик целиком.
   2. Перечитай `writing-rules.md` и сверь черновик с ним и с `canon.md`.
   3. Обнови `cut.md` и продуктовую рамку (если есть).
2. Запусти двух субагентов с чистым окном по полному черновику, каждому —
   его файл инструкции:
   - `agents/check-instructions.md`;
   - `agents/check-harm.md`;
   - каждому передай функцию словами пользователя, его буквальные цитаты,
     `cut.md` и принятые решения;
   - каждый возвращает список правок; пустой список законен.
3. Запусти субагента-исполнителя с чистым окном на пробный случай по
   черновику; проследи его фактические шаги и сравни с целью пользователя —
   расхождение это правка.
4. Правки принимай сам; принятые перед внесением сверь с буквальными
   цитатами пользователя в папке-истории и с `cut.md`: правку, меняющую
   дословную цитату пользователя или возвращающую отклонённое в `cut.md`,
   сам не принимай — неси в разбор. После внесения повтори шаги 2–3 по
   полному изменённому черновику — не более двух повторов.
   - Остаток правок после повторов неси в разбор.
   - Списки правок и решения по ним сохраняй в папке-истории.
5. Напиши разбор в чат — максимально понятно, простыми словами, структурно,
   по порядку, с markdown-разметкой: какие когнитивные шаги скил выполняет ·
   количество инструкций · где агент может убежать · чем доказывается
   выполнение; каждый пункт — с цитатой держащей строки.
6. Спроси, утверждает ли пользователь версию.
7. После «да» пользователя запиши сам скил по адресам установки
   (`writing-rules.md`); «да» с оговоркой — это правка, не «да».
8. В сдачу включи: функцию словами пользователя · добавки с основаниями ·
   допущения · списки правок двух проверяющих и что принято · след
   фактических шагов исполнителя и найденные расхождения · снятое — с
   причиной в `cut.md` · применённые пункты канона — цитатой из `canon.md` и
   с указанием, на какие строки пункт повлиял.

- Правка после «да» возвращает в черновик: измени его и повтори проверку —
  это новый заход, счёт повторов с нуля; записанный скил в обход проверки не
  правь.

- Выход: записанный скил, прямые ссылки и сдача в чате.
