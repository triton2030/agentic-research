# v12 — контекст как управление целью

Источник решения владельца:
`_ops/chat-recall/2026-08-31-001517-codex-01a05418.md:34-35`.

## Функция изменения

Не дать агенту подменить Уникальный контекст общей справкой или молча объявить,
что он понял цель: контекст должен содержать неизвестную модели ситуацию либо
желание, материально менять понимание цели, а применение протокола должно быть
наблюдаемым в чате.

## Изменено

- В Уникальном контексте тела закреплено, что неизвестная модели ситуация или
  желание управляет исполнением как смысловое дополнение к цели.
- `goal-context.md` требует показывать в чате порядок, наблюдаемый результат и
  применение метода по каждому пункту протокола.
- Уникальный контекст допускает только неизвестное модели и значимое для
  понимания либо исполнения цели.
- Каждый элемент контекста проходит removal-test: если без него правильное
  понимание или исполнение цели не меняется, элемент удаляется либо
  переписывается.

## Сохранено

- Функция скила, mandatory routes и двухволновый предел проверки не меняются.
- Уникальный контекст не содержит инструкций; протокол поведения остаётся их
  владельцем.
- Clean-room результат v11 и его карта потерь сохраняются: изменение затрагивает
  только принцип Уникального контекста и стадию `goal-context.md`.

## Проверяемые свойства

- `unknown-to-model`: контекст, который компетентная модель уже знает без
  owner/project evidence, должен быть отвергнут.
- `goal-linked`: удаление любого принятого элемента контекста должно менять
  правильное понимание или исполнение хотя бы одной цели.
- `chat-visible`: до выхода стадии чат содержит порядок, источники,
  наблюдаемые результаты применения метода и основания принятых либо
  отброшенных элементов.
- `no-protocol-duplication`: детали этой проверки принадлежат
  `goal-context.md`, а тело хранит только управляющий принцип.
