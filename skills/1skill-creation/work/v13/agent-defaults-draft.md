# Аудит формулировок и дефолтов агента

Вход: проверяющий оценивает каждую сформулированную агентом строку черновика,
включая пересказ слов пользователя.
Цель: найти формулировку, которая искажает смысл владельца, допускает
двусмысленное поведение, добавляет неоправданную нагрузку либо не убеждает
агента применить скил.

1. Для каждой строки назови её источник, требуемый смысл и ближайшее
   правдоподобное неверное прочтение.
2. Закончи фразу: «без этой строки агент сделает X, потому что Y выглядит
   разумным».
3. Для строк Уникального контекста и целей пользователя источником обязана быть
   фраза владельца. Считай находкой строку, у которой такого источника нет:
   агент написал её из собственной базы, а значит она известна любой
   компетентной модели и не делает контекст и цель уникальными.
4. Проверь, даёт ли Уникальный контекст агенту причину применить скил: названо
   ли то, чего агент не знает, и что это знание ему даёт. Считай находкой
   контекст, который верен, но агента ни в чём не убеждает, потому что
   неубеждённый агент выполняет скил некачественно.
5. Не принимай симптом, название исследования или недоверие к агенту за
   механизм поведения.
6. Считай строку лишней, если цель или существующая инструкция уже меняет тот же
   выбор.
7. Считай знание оправданным, только когда оно меняет названное действие,
   решение или границу агента.
8. Учитывай, что требование против дефолта и новое активное обязательство
   повышают риск отказа.
9. Учитывай, что жёсткая инструкция закрывает допустимые пути к цели.
10. Считай строку оправданной, только если предсказанный вред без неё дороже
    потерянной автономности.
11. Если нарушение недопустимо, предложи убрать путь к нему вместо усиления
    формулировки; текст сам по себе не является гарантией.

Выход: для каждой находки — `источник → формулировка → неверное прочтение →
дефолт → изменяемое решение → вред → цена строгости → минимальная правка`.

- Пустой список находок законен; не выдумывай правки ради счёта.
