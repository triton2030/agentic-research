# Именованные агенты

Вход: скилу нужна отдельная повторяемая роль с чистым окном, собственным
контрактом или runtime-ограничениями.

Цель: создать агента, которого среда обнаруживает по точному имени, чьи права
ограничены слоем исполнения, а общий смысл не расходится между средами.

1. Создавай постоянный agent-файл только по просьбе пользователя и только для
   устойчивой повторяемой роли с самостоятельным контрактом. Для разовой подзадачи
   достаточно брифа
   обычному субагенту.
2. Дай роли одно точное имя и описание момента вызова, по которым её можно
   выбрать без чтения полного промпта.
3. Единый смысловой владелец роли задаёт её функцию, не-цели, вход, выход,
   доказательства и условие остановки.
4. Контракт роли самостоятелен: он не требует тела вызвавшего скила или цепочки
   его reference-файлов для понимания своей работы.
5. Скил вызывает точное имя, передаёт только данные текущей задачи и не повторяет
   инструкции роли.
6. Claude-проекция агента — Markdown с YAML frontmatter для
   `~/.claude/agents/` или `.claude/agents/`; папка `agents/` внутри скила
   агента не регистрирует.
7. Codex-проекция агента — TOML с `name`, `description` и
   `developer_instructions` для `~/.codex/agents/` или `.codex/agents/`.
8. `agents/openai.yaml` описывает UI и invocation policy скила, а не
   регистрирует именованного агента.
9. Runtime-файлы — проекции одного смыслового владельца; они расходятся только в
   метаданных и runtime-механизмах, которые реально различаются между средами.
10. Ограничивай критические права runtime-механизмом — allowlist инструментов в
    Claude и sandbox в Codex; не полагайся только на текст промпта.
11. До безусловного утверждения храни agent-проекции только в папке-истории;
    после утверждения они устанавливаются отдельно от пакета скила.
12. В вызывающем скиле зафиксируй: если среда не обнаруживает обязательного
    именованного агента, остановись и не имитируй его роль в том же окне.

Выход: один смысловой владелец роли и готовые к проверке runtime-проекции в
папке-истории.
