# evidence — firecrawl-developer-index, 2026-09-23

Владелец: скил упомянут в корне, но вызывается редко; агент изобретает
велосипед вместо того, чтобы обновить, установить или прочитать, как
делать[^order][^obs]. Для этого описания лимит 200 знаков снят[^len].
Итоговая версия — `live-2026-09-23.md`, прежняя — `live-2026-08-23.md`.

## Как мерили

Живые сессии `claude -p` (Claude Code 2.1.280, `claude-opus-5-5`) с настоящим
`~/.claude/CLAUDE.md` и всеми 49 скилами, по одной чистой папке на прогон,
по два прогона на сцену. MCP выключены. Вызов засчитан только по trace:
`Skill(firecrawl-developer-index)` в выводе `stream-json`. Стенд, сцены,
сводка и последовательности действий — `work/trigger-2026-09-23/`.

| Набор | Сцены | Что проверяет |
| --- | --- | --- |
| P | просьба написать код: cron, повтор запросов, проверка ссылок, импорт vCard | прямой момент |
| M | вопрос, для ответа на который агент пишет код: битые ссылки, контакты без телефона, frontmatter | код как средство |
| Q | вопрос о дефолте `fetch` в Node 22 и о версии `model_validate` в pydantic | ответ по памяти |
| E | просьба починить `ERR_REQUIRE_ESM` от `node-fetch` 3 | чужая ошибка библиотеки |
| N | переименование; свой падающий тест | ложный вызов |

В P, Q, E и N инструмент Bash закрыт, в M открыт без установок пакетов.
В прогонах P для вариантов 2026-08-23 и V17 не был закрыт Monitor: в одном
прогоне агент через него запустил `firecrawl`, `lychee` и `curl`. На счёт
вызовов скила это не влияет. Для V20 и новых наборов Monitor закрыт.

## Хук: почему не предлагается в таком виде

Тестовый хук PreToolUse один раз за сессию отклонял первую встроенную
программу на Python с причиной «сначала проверь firecrawl-developer-index».

- В M скил загружен в 6 из 6, поиск выполнен в 5 из 6. Причина отказа
  называла скил по имени, поэтому это исполнение прямого указания; вклад
  описания здесь не измерен.
- Решение изменилось в 2 из 6, в обеих сценах со ссылками: после отказа агент
  проверил `which lychee` и взял установленный инструмент. Сам индекс
  `lychee` не вернул. В одной сцене со ссылками свой проверщик на цикле shell
  успел выполниться до скила: такие циклы хук не распознаёт. В одной сцене
  frontmatter агент поиск пропустил: «one-off check».
- Проверяющий прогнал логику хука по ~415 реальным сессиям владельца за
  21 день[^replay]. Отказ получили бы 286 сессий. Из 25 случайных первых
  отказов 20 пришлись бы на рутину: разбор JSON, замер длины, правку текста.
  Около 97% следующего кода в сессии хук уже не проверяет. По синтаксису
  велосипед не отличить от вспомогательного скрипта.

## Codex и YAML

- В каталоге Codex 105 скилов, каждое описание обрезано примерно до 150
  знаков. Старое обрывалось на «…писать любой новый код с»[^codex]. Первая
  фраза нового — 146 знаков: момент, «even unasked» и польза видны целиком.
  Второй момент (память, исследование) Codex не видит.
- Старое описание не проходит строгий YAML: «правки: сначала» читается как
  ключ. PyYAML падает; Claude и Codex разбирали его снисходительно. Новое
  проходит `yaml.safe_load`.

| Находка | Решение |

| Снята граница с `1cli-tools` без пробы | принято: граница возвращена хвостом |
| Снята одобренная фраза про уверенность без повторной пробы | принято: проба Q показала 3/4 без неё, аналог возвращён, 4/4 |

| «helper» — слово соседа `1cli-tools` | принято: снято |
| «even unasked» вне окна Codex | принято: перенесено в первую фразу |
| Разовый скрипт даёт повод пропустить поиск | принято: «A throwaway script counts; one unscoped query is the whole check» |
| Выигрыш дала проверка установленного, в теле её нет | принято: шаг `which` / `--version` в маршруте «About to build» |

## Что не доказано

- По два прогона на сцену: результат показывает возможность, не вероятность.
- Сцены обновления нет: момент «workaround при сбое установленного
  инструмента» и путь «upgrade» живьём не проверены.
- Codex живьём не прогонялся, проверен только видимый каталог.
- Вклад описания против корневой строки не разделён: в P и Q они действуют
  вместе.
- Тело правилось во время прогона V17: 7 из 8 вызовов загрузили прежнее тело.
  На счёт вызовов это не влияет.
