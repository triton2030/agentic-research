# Куда класть правило в Mantine

Этот файл решает только Mantine-специфичное размещение. Общая архитектура
приложения остаётся у проекта; его живая конвенция сильнее любой схемы ниже.

## Владельцы Mantine-интеграции

| Владелец | Что ему принадлежит |
| --- | --- |
| app / runtime root | `MantineProvider`, global CSS и его порядок, SSR/hydration, color scheme, portal bootstrap |
| theme definition | `createTheme`, продуктовые tokens/aliases, `theme.components`, CSS variables resolver; может жить отдельно от runtime root |
| reusable UI capsule | публичная композиция Mantine, props-контракт, локальный CSS Module, тест/story компонента |
| feature / page | композиция экрана, состояние формы, loading/error/empty и workflow |
| domain / data | schema, API, permissions и бизнес-правила; Mantine ими не владеет |

Копия инварианта `SKILL.md`, править вместе: один runtime-root имеет одну точку
Mantine-интеграции, а определение темы — отдельного владельца. Несколько
приложений или разделённые server/client roots могут иметь отдельные точки,
если это разные runtime-границы.

## Fallback, когда у проекта нет конвенции

Это рекомендация скила, не официальная архитектура Mantine. Не создавай папку,
пока в ней нет отдельного владельца.

```text
src/
  app/                 # entry и runtime-интеграция
  theme.ts             # определение темы
  components/
    ComponentName/
      ComponentName.tsx
      ComponentName.module.css
      ComponentName.test.tsx
      index.ts
  features/
    feature-name/
      FeaturePage.tsx
      components/
      model/
  domain/
    feature-name/
```

Файлы создаются по факту: нет локальных стилей — нет `.module.css`; нет теста
или публичного barrel — нет соответствующего файла. Schema/API/permissions не
переносятся в UI-капсулу ради симметрии дерева.

## Лестница

| Знание | Механизм Mantine |
| --- | --- |
| значение уровня продукта: цвет, шрифт, отступ, радиус | `createTheme` вне тела рендера; семантические алиасы — `cssVariablesResolver` |
| дефолт всех инстансов одного компонента | `theme.components` + `Component.extend({ defaultProps })` |
| повторяющийся селектор, состояние, вариант | CSS-модуль + `classNames`, публичные `data-*` и CSS-переменные компонента |
| повторяющийся вертикальный или горизонтальный layout | подходящий `Stack`, `Group`, `Flex` или другой публичный composition primitive — копия инварианта `SKILL.md`, править вместе |
| один преднастроенный компонент без темы | `Component.withProps(...)` |
| дефолты для поддерева, а не всего приложения | `MantineThemeProvider` |
| настоящий one-off, не выражаемый public composition | локальный проп или style prop |
| продуктовая роль, право, workflow | свой компонент с узким контрактом |

One-off style не заменяет public Mantine composition.

## Где механизм врёт

- `theme.other` не виден из CSS: нужен явный мост через CSS-переменную.
- Брейкпоинты темы и переменные PostCSS не синхронизируются сами — это один
  контракт в двух местах.
- Резолвер варианта владеет только цветами; остальные свойства варианта — через
  классы и `data-*`.
- Приватные `--_*` — не публичный API. Статические `.mantine-*` ломаются при
  `classNamesPrefix`.
- `unstyled` и headless-режимы убирают не только оформление: могут пропасть
  переменные, глобальные классы и поведение цветовой схемы.

## Обёртка и свой примитив

Обёртка оправдана, только если владеет хотя бы одним настоящим контрактом:
продуктовое имя, право или подтверждение, async-состояние, конечный
семантический API вместо сырых опций, повторяющаяся композиция с устойчивой
анатомией. Обёртка 1:1 не проходит: она обязана зеркалить растущий набор пропов,
`ref` и полиморфизм, а поведение и DOM Mantine всё равно протекают.

`factory`, `useProps`, `useStyles`, `varsResolver`, `polymorphicFactory` нужны,
только если свой примитив должен полноценно участвовать в дефолтах, Styles API,
`ref` и полиморфизме. `polymorphicFactory` дорог по TypeScript; честный
фиксированный корень дешевле. Для подмены корня — router Link, своя кнопка —
используй документированный `renderRoot` и прокидывай все пришедшие пропы,
иначе потеряешь стили и доступность.

## Признаки, что пора выйти за Mantine

Несколько сразу: нужный семантический HTML конфликтует с DOM компонента;
большинство инстансов идут через `unstyled`; публичные селекторы и переменные не
выражают дизайн; фокус, портал или клавиатура регулярно отключаются; локальные
переопределения лезут во внутренние селекторы. Изолируй одну возможность.
