# Product Frame — 1orchestration v7 candidate

## Цель-сцена

Root собирается поручить результат субагенту либо разделить собственную
перегруженную работу. Он восстанавливает общую цель, полный `done_when` и
влияющие канонические источники, затем передаёт конкретный результат через их
адреса и только отсутствующую `delta`. Root отдельно оценивает активные наборы
исполнителя и своей следующей точки решения. Очевидно посильный одиночный
результат не создаёт полный реестр; спорная нагрузка получает внешний count и
budget verdict. Выбранная граница должна позволять участнику забыть целые
единицы, сохранять способность и действующие полномочия. Зависимый ход
открывается только доказанной приёмкой.

## Тайбрейкеры

1. Полнота критериев и канонических источников сильнее краткости prompt-а.
2. Адрес плюс отсутствующая `delta` сильнее пересказа доступного канона.
3. Отдельная примерная оценка actor/root обязательна; полный реестр условен.
4. Ориентир около `20` мягкий; честная неразложимость сильнее деления ради
   числа.
5. Минимальная способная форма и живые authority-owners сильнее общего
   control-plane.
6. Evidence каждого критерия сильнее process-report; изменившийся вход
   инвалидирует только затронутые производные с самой ранней стадии.

## Аппетит и пересмотр

Пакет остаётся короче официального predecessor: одно тело, шесть
самостоятельных references и без общего carrier/runtime. Пересмотри форму,
если чистый исполнитель пропускает влияющий критерий, не различает нагрузку
actor/root, принимает `20` за hard cap, создаёт вторую topology, теряет
runtime-владельца либо открывает зависимость без evidence.

Это рамка candidate, а не утверждённого owner-а. До безусловного одобрения
exact version официальный пакет и projections не меняются.
