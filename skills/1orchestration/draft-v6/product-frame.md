# Product Frame — 1orchestration v6 candidate

## Цель-сцена

Root собирается поручить работу либо сам не удерживает её активный набор. Он
читает влияющие канонические источники и формирует поручение из цели, полного
`done_when`, адресов входов и отсутствующей в них `delta`. Затем он оценивает
отдельные примерные числа активных единиц исполнителя и следующей точки root.
Очевидно малое поручение получает прямое назначение без устройства волны.
Неясная или высокая нагрузка получает перечисленный реестр и вердикт;
декомпозиция законна только когда следующий участник сможет отбросить часть
единиц. Специализированный контроллер сохраняет собственную схему, а сложная
собственная схема получает только нужные ей карту, приёмку и recovery-state.

Приёмка пропорциональна выбранному пути: всегда наблюдаемы карта влияния,
поручение, примерная оценка root/исполнителя, решение о форме и доказанный
результат; реестр нагрузки, карта запуска и переходы состояния появляются
только когда соответствующая развилка их требует.

## Привязка к цели проекта

Это межпроектный контракт качества делегирования. Поручение не создаёт второй
канон, простая работа не становится волной, специализированный контроллер не
получает второго оркестратора, жизненный цикл среды выполнения не дублируется,
а носитель остаётся только реестром переходов.

## Тайбрейкеры

1. Выполнимость активного набора и способность исполнителя сильнее числа окон
   и полноты процедурного следа.
2. Адрес источника + `delta` сильнее пересказа; живой владелец может требовать
   адресованную критичную выдержку.
3. Порог 20 мягкий; честная неразложимость сильнее дробления ради соответствия.
4. Root владеет общей траекторией, но его точки решения оцениваются так же.
5. Специализированная схема и жизненный цикл среды сильнее общего механизма.
6. Полный реестр нужен для спорной нагрузки; очевидная оценка не создаёт
   артефакт только ради единообразия.

## Аппетит

- Тело — 20 единиц; каждый reference и каждый одновременно активный набор
  остаются в пределах 20 по карте в `refactor-map.md`.
- Все 14 содержательных references получили локальную `Цель`; `carrier` также
  получил локальный `Уникальный контекст` о recovery без второго канона.
- Локальные цели и снятые выводимые строки следуют прямому решению
  `_ops/chat-recall/2026-08-29-163434-codex-01a04d4a.md:22`.
- Цитаты владельца живут в истории и доказательствах, а не в runtime body по
  прямому решению `_ops/chat-recall/2026-08-29-160553-claude-0bee3f3d.md:19`.
- Тело и references — по-русски; `description` — короткий английский trigger
  без процесса и рекламы по решению
  `_ops/chat-recall/2026-08-29-163434-codex-01a04d4a.md:20`.
- Codex `short_description` следует тому же trigger-only правилу, а
  `default_prompt` остаётся русским инструкционным текстом.
- Пересмотр: поручение пропускает источник или критерий, реестр даёт голое
  число, root не оценён, исполнитель неспособен, специализированная схема
  перехвачена, лёгкий путь создаёт волну, обязательный возврат не принят либо
  условный носитель стал безусловным.
