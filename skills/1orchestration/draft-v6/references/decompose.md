# Декомпозиция cognitive work

Вход: provisional task получил verdict `decompose`. Выход: минимальный список
provisional tasks, для которых тело снова выберет следующий когнитивный этап.

- Дели по самостоятельно принимаемому решению, outcome, owner-границе или стадии.
- Каждая граница должна уменьшать одновременно активный набор, а не только длину
  prompt-а.
- Зависимое выполняй последовательно; параллельно оставляй только независимое.
- Сохрани в каждом child все действительно применимые owner-адреса.
- Не создавай отдельного агента, если staged task тому же окну дешевле handoff-а.
- Root оставляет у себя целую просьбу, траекторию, решения и интеграцию.
- Если ниже 20 без потери результата не разложить, назови принятый overload и
  усили staged checkpoints и независимую приёмку соразмерно риску.
