# Оркестрация

## Уникальный контекст

Субагенты покупают независимость и чистоту контекста ценой координации.
Оркестратор распределяет между окнами работу и instruction load, а root
удерживает просьбу владельца, пользу для проекта, траекторию, решения
и интеграцию.

## Цели

- Найдена минимальная окупающаяся форма: работа у root, один уже
  требуемый managed-offload поток либо общая волна.
- Каждое окно владеет посильным outcome, сфокусированными инструкциями
  своего момента, write ownership и проверяемым возвратом.
- Root принимает один результат по evidence, разрешает конфликты и не теряет
  траекторию в промежуточном шуме.

## Стандарт решения

- До карты root сам читает load-bearing owner-источники цели, продуктовой
  правды и прежних решений; citation или summary субагента чтение не
  заменяют.
- Root сверяет буквальную работу с пользой и выполнимостью: обратимую in-scope
  коррекцию принимает и показывает сам, а меняющую долговечную правду,
  полномочия или необратимый ход отдаёт владельцу.
- Новая general wave окупается только независимым evidence stream, непересекающимся
  write ownership, изоляцией шумного контекста или реальным сокращением времени.
  Явный managed-offload контракт уже допускает один bounded поток: не отменяй его
  и не размножай без отдельной выгоды.
- Дели по самостоятельному результату или owner-границе и бери минимальное число
  окон. Зависимый этап получает отдельное окно лишь когда смена ownership,
  чистый контекст или recovery сами окупают handoff.
- Не создавай окно только ради общей перепроверки; независимая приёмка нужна,
  только когда её требует риск или действующий контракт.

## Контракт волны

Порядок несёт корректность: зависимый ход не начинается до обязательных
возвратов, а плохое деление не чинится поздним синтезом.

1. **До запуска покажи карту в чате.** Для каждого потока назови outcome,
   независимость или место в staged-порядке, барьер, write ownership,
   instruction focus и return packet. Один managed-offload поток помещается
   в одну строку.
2. **Дай каждому окну self-contained brief:** outcome · live-адреса исходных данных
   и обязательных инструкций его момента · границы и write ownership ·
   return packet `результат · адресуемое evidence · gaps · blockers`. Оставь
   owner-источники адресами и сфокусируй первое решение исполнителя; не
   пересказывай ему весь свод.
3. **Запускай параллельно только независимое.** Пересекающиеся записи получают
   одного писателя либо последовательный handoff. Root продолжает только то,
   что не зависит от незавершённых обязательных потоков.
4. **Прими возвраты до синтеза.** Адресуемое evidence подтверждает результат;
   progress report — нет. Если независимая приёмка обязательна, её делает окно,
   не писавшее проверяемую работу.
5. **Синтезирует только root.** Он разрешает конфликты по owner-источникам,
   проверяет load-bearing claims, интегрирует и не голосует по числу агентов.
   В чате остаются принятые результаты, gaps/blockers, проверка интеграции
   и следующий ход.

## Носитель и восстановление

При живом плане task-file владеет state и записывает outcome каждого probe/repair;
этот скилл владеет картой волны, барьерами и wait/probe/repair. Без живого
плана создай [cold-start carrier](references/wave-folder.md), только когда потеря root-
контекста стоит дороже одной переиздаваемой волны.

После первого bounded wait без изменения названного return/artifact/diff открой
[bounded repair](references/repair.md); новую импровизированную волну не создавай.

## Завершение

Результат скила — обоснованный no-wave либо минимальная запущенная форма, в которой
обязательные возвраты приняты, интеграция проверена, а решения, gaps и blockers видимы.
