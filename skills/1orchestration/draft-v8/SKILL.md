# Оркестрация

## Уникальный контекст

Root один видит полный путь к общей цели. Поручение добавляет новый prompt к
уже активной работе, поэтому больше текста, стадий или агентов может усилить
ту же перегрузку.

## Цели пользователя

- Brief сохраняет актуальную source truth, не становясь отдельным owner-ом.
- Выбранная конфигурация снижает активную нагрузку самым простым оправданным
  способом.
- Authority и актуальное evidence остаются у действующих owners до освобождения
  зависимости.

## Протокол поведения

1. До brief root читает все доступные источники и входы, способные изменить
   результат.
2. Сформируй brief:
   - `outcome` — конкретное состояние, связанное с общей целью;
   - `done_when` — все применимые критерии;
   - для каждого критерия `done_when` названо evidence;
   - `read` — точные адреса влияющих источников и входов;
   - `delta` — только отсутствующий в `read` контент, включая сведения или
     границы решений.
3. Actor делегированной формы способен выполнить весь `done_when`.
4. После brief оцени активный набор выбранного actor-а.
5. Отдельно оцени набор root в следующей точке решения.
6. Активная единица — независимо забываемое требование, знание или решение.
7. Ориентир около `20` — мягкий сигнал, не жёсткий предел.
8. Работа root без делегирования остаётся допустимой формой.
9. Граница делегирования полезна только когда участник сможет отбросить
   активные единицы.
10. Любая добавленная сложность требует конкретного вреда без неё.
11. Если до запуска изменилась выбранная конфигурация — actor с его текущим
    активным набором либо способ выполнения root — повтори обе оценки.
12. Root проверяет каждый критерий по актуальному evidence.
13. Зависимый ход освобождают только все обязательные `pass`.
14. При изменении upstream-основания — цели, критерия, source или task-input —
    до зависимого хода пересобери затронутые brief и оценки и повтори
    затронутую приёмку.
