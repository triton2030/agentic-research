## Commander's intent

### Уникальный контекст

Оркестратор один видит полный путь к общей цели. Поручение добавляет временный
слой поверх существующих владельцев правды. Качество падает не только от
сложности, но и от числа независимо забываемых требований, знаний и решений,
которые root и исполнитель должны одновременно удерживать. Простое увеличение
числа агентов или текста эту нагрузку не уменьшает.

### Цели пользователя

1. Каждый передаваемый результат получает доказуемый контракт из цели, полного
   `done_when`, адресов влияющих источников и только отсутствующей в них
   `delta`; ссылка без чтения root и неполные критерии успехом не считаются.
2. Активные наборы root и каждого исполнителя остаются посильными; ориентир
   около `20` мягкий, а деление считается полезным только когда следующий
   участник действительно может отбросить часть единиц.
3. Минимальная достаточная форма сохраняет способности исполнителя, полномочия
   специализированных контроллеров и runtime-владельцев; зависимый ход
   начинается только после доказанной приёмки, а процессный след сам по себе
   успехом не считается.

### Момент вызова

Перед назначением любого субагента или разделением собственной перегруженной
когнитивной работы. Локальная работа root без этих условий — near-miss.

Формула одновременно активного набора каждого режима:

`применимые единицы тела + не дублирующие их единицы выбранного reference +
ещё действующие критерии/решения источников и задачи`.

- `orient`: source-bound часть целей + route `orient` + один читаемый источник;
  завершённые строки `адрес → влияние` внешне зафиксированы, но их ещё
  применимые правила переходят в карту.
- `brief`: source-bound часть целей + route `brief` + схема контракта +
  применимые строки карты. Каждый записанный критерий можно снять из памяти до
  финальной сверки полноты контракта.
- low path: цели выполнимости + route estimate/shape + готовый контракт + две
  примерные оценки. Реальная clean-проба дала actor `13`, root `9`.
- `count`: цели выполнимости + route `count` + активный контракт и по одному
  строящемуся реестру; записанная строка снимается только когда внешний
  носитель действительно освобождает следующий ход.
- `budget`: два готовых реестра как внешние входы + `budget.md`; сами записи
  перечитываются последовательно, а не добавляются к инструкции символическим
  повтором.
- `shape`: цели формы/authority + route `shape` + готовые оценки или вердикты +
  `shape.md`; доменные capability и authority constraints остаются отдельными.
- `accept`: evidence-цель + route `accept` + контракт, актуальные sources,
  возвращённый результат и критерии, проверяемые по одному.

Поэтому история не заявляет универсальный фиксированный total без реального
контракта: именно его доменные единицы определяют, откроется ли полный
`count → budget`. Доступный адрес не снимает применимое правило, а превышение
`20` остаётся мягким сигналом, не автоматическим fail или делением.
