# Вход независимой проверки

Текущий заказ и новое намерение: `intent.md` (включая последнюю реплику #L18).
Снимки до правки: `before/`. Кандидат: `candidate/`.
Чистый автор `/root/intent_only_draft` получил только новое намерение и вернул
Контекст / Задачу / Цель. Его ответ доступен в родительской задаче; отдельной
копии полного возврата нет. Авторская сборка сохраняет выведенную форму и
добавляет невыводимые runtime-условия.

## Существенные решения автора

- Центр — пригодность общей работы и свобода исполнения, без оптимизации
  мыслительных усилий, числа прочитанных файлов или числа проверок.
- Обязательное объяснение декомпозиции до передачи сохраняется. Сняты
  одинаковая ведомость по всем вложенным правилам, универсальное число семь
  в runtime-поручении и повторное доказательство при любом новом источнике.
  Подробный разбор применяется при неясной посильности. Это предложенная
  замена механизма в ответ на просьбу владельца; качество её поведения
  проверяется сравнительной пробой, общий выигрыш надёжности не заявляется.
- Нет фиксированной последовательности рассуждения. Специфика API не
  пересказывается: актуальный контракт инструмента уже различает подготовку
  и готовый ID, fork завершённой истории, cursor и права создания задач.
- Сохраняются выбранные модели и усиление по сложности, независимый Opus,
  локальная доработка с пределом, первичные материалы и актуальность проверки,
  ответственность за интеграцию, файловое владение и реальные права среды.
- Память сохраняет продолжимость. Рутинный отчёт каждого субагента не нужен;
  содержательный артефакт допустим. Нет запрета читать первичные материалы
  при вопросе, требующем собственного разбора.
- Старые карты потерь запрещают возвращать обязательный file-per-worker,
  фиксированное число исполнителей, глобальный сбор метрик и самоотчёт вместо
  evidence. Эти решения не возвращаются.
- Отдельные общие Критерии принятия не добавляются: требуемый результат
  задан намерением, специфичные условия — в соответствующих ситуациях.

## Проверяемые свойства и опровержения

| Изменение | Проверяемое свойство | Что его опровергает |
| --- | --- | --- |
| Свободный ход вместо пошагового preflight | Агент формулирует конкретное посильное поручение и объясняет разделение | Задание «сделай по всему протоколу» без раскрытых существенных условий или совсем нет объяснения |
| Нет цели экономить мышление | Неизвестный риск вызывает нужное чтение/проверку | Агент принимает непроверенный или устаревший результат ради краткости |
| Компактные возвраты | Доказательство остаётся доступным, итог не подменяет проверку | Авторское done без актуального основания принимается как pass |
| Условные подробности | Простое независимое поручение не требует отчёта-файла и полной ведомости | Агент создаёт их без потребности результата/продолжения |
| Runtime-условия | Конкретные модели, маршруты и права не смешиваются | Claude требует Codex Desktop-параметры, Codex присваивает личную задачу или обходит запрет |
| Продолжение | Есть единый текущий носитель состояния и проверенный следующий ход | Дубли состояния либо история выдаётся за действующий образец |

## Граница вывода

Независимая текстовая проверка и ограниченная проба не доказывают улучшения
общей скорости или надёжности на распределении рабочих задач. Версия пока
не установлена; утверждается конкретный проверенный текст.

## Решения после первой волны

Проверенные байты v1 остаются в `candidate/`; следующая редакция получает
отдельный адрес `candidate-v2/`. Полные ответы проверяющих доступны в основной
задаче: native `skill_delta_audit` и Opus 5, session
`83429fbd-9881-4dfa-96c7-490ddd96bdb2` (terminal success; получение обрезанного
ответа завершено, всего четыре находки).

| Находка | Решение и основание |
| --- | --- |
| Auditor F2 и Opus 4: повторный специалист стал лишь возможностью | Принято. Предпочтение свободной подходящей сессии возвращается в сам выбор исполнителя; отдельного обязательного обхода истории не добавляем. |
| Opus 1: объяснение может не раскрыть оставшуюся нагрузку | Принято в минимальной форме. Объяснение показывает, какие требования остаются у каждого после разделения. Общий протокол может сохранить их целиком; неизвестные требования не считаются отсутствующими. Фиксированная таблица и число семь не возвращаются. |
| Opus 2: исходное состояние Git стало лишь финальным свойством | Принято. Восстановимость существующих правок обеспечивается до существенного изменения; commit/merge общей папки остаются у оркестратора, итоговое сохранение подтверждается ревизией и remote. |
| Opus 3: в callable schema якобы нет различия подготовки и готовности | Не принято. Действующий `create_thread` прямо различает готовый `threadId` и подготовительный `clientThreadId`; инструкции приложения требуют ожидания после асинхронного создания. Кандидат сохраняет подтверждённый запуск как результат. Дублировать доставленный контракт инструмента оснований нет. Это проверка текущего runtime, не гарантия любой будущей среды. |
| Auditor F1: в разделе приёмки смешаны восемь самостоятельных условий | Приёмка и существенная смена способа относятся к разным решениям. Повторное требование независимого суждения удаляется из приёмки: существенная замена способа явно входит в уже существующий случай развилки. Право владельца задавать заказ остаётся в Задаче. Набор приёмки не прячется за укрупнёнными маркерами. Число семь — ограничение применённого метода авторинга, не установленная вместимость модели. |

## Сравнительная проба

Точные входы и условия: `probe-manifest.json`. А получил текст кандидата с
добавленным прежним обязательным preflight; B — тот же кандидат без этого
блока. Оба в отдельных чистых окнах подготовили реальные тексты поручений,
не запускали исполнителей и не меняли файлы. Возвраты: native
`wording_probe_a` и `wording_probe_b` в основной задаче.

| Наблюдение | А | B |
| --- | --- | --- |
| Приёмка по устаревшей v1 после изменения спецификации | Отложена до независимой проверки по v2 | Отложена до независимой проверки по v2 |
| Организация оставшейся работы | Один писатель Покупателя; проверка Студии; условное исправление; итоговая проверка | То же разделение и те же четыре текста поручений |
| Занятый специалист и личная задача владельца | Не переназначены | Не переназначены |
| Модели и память | Luna Max / Opus, local, существующий файл задачи | То же |
| Нагрузка | Две подробные таблицы; посчитано 8–19 требований; деление работы не изменилось | Смысловые условия в поручениях, таблиц подсчёта нет |

В этом случае обязательная ведомость изменила отчётность, а не выбранную
декомпозицию и решение о приёмке. Проба не измеряла внутренние когнитивные
усилия, время и стоимость исполнения либо реальное качество итоговых статей.
Новый текст также породил подробные поручения и дополнительные организационные
шаги: снятие preflight само по себе не гарантирует краткости или оптимальности.
Вложенный неизвестный протокол и поведение после сжатия здесь не испытывались.
Локальные уточнения v2 проверяются по тексту и источникам; v1-проба не выдаётся
за исполнение финальных байтов v2.

## Вторая волна и финальная локальная коррекция

Оба проверяющих закончили вторую волну по `reviewed-v2.json`; новых волн нет.
Auditor: оставшиеся нарушения `[]`, F1/F2 и сохранение дельты после правок
подтверждены по байтам. Opus: исходные 1/2/4 закрыты; возражение 3 о готовности
запуска снято после проверки доставленного контракта инструмента.

Opus нашёл три локальных дефекта v2. Все приняты: замена способа может
возникнуть на любом этапе, а не только при первичном выборе исполнителя;
Задача должна прямо требовать исполнения под условия владельца; раннее
сохранение Git применимо и при одном писателе. Финальные формулировки
исправляют только эти места в `candidate-v3/`; v2 сохраняется неизменным.

Финальные байты сверяются локально с этой ограниченной коррекцией,
исходными условиями и обеими runtime-версиями. Это не третья независимая
волна. Независимые отзывы относятся к v1/v2, поведенческая проба — к v1;
выполнение полного рабочего задания по v3 не заявляется.
