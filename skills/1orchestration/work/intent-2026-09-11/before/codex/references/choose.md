# Выбор исполнителей

## Задача

Выбери сочетание исполнителей и разрежь работу вместе с влияющим контекстом.

## Цель

У каждой части есть подходящий исполнитель и проверяемый результат; стоимость
его работы, передачи контекста и приёмки оправдана пользой для общего заказа.

## Зачем

Владелец заранее выбрал экономику большой работы: Luna Max пишет, Opus даёт
независимое суждение, параллельность сокращает ожидание. Дробление только по
объёму файлов оставляет оркестратору прежнюю нагрузку всех чужих обязательств.

## Критерии принятия

По распределению и действующим источникам можно назвать отдельно нарушимые
обязательства каждого, включая оркестратора, и проверить их по возвратам.
Количество агентов и короткие ссылки вместо длинных текстов не доказывают
разгрузку.

## Неизвестные агенту настройки

- Для большой пишущей работы, множества писателей или изменяемых файлов
  первый выбор — видимые незакреплённые фоновые задачи `gpt-5.6-luna`,
  `thinking: max`. Владелец выбрал их ради стоимости;
  собственный субагент не считается выполнением этого предпочтения.
- `gpt-5.6-sol` с `thinking: medium` или `xhigh` остаётся исключением под
  конкретную сложность сверх возможностей Luna; обычный сбой не доказывает
  необходимость более дорогой модели.
- Для существенной развилки и аудита большой работы привлекай независимого
  Opus через `1claude-mcp`. Другая модель может дать дополняющее суждение,
  но согласие моделей не доказывает качество; обещания улучшения любой пары
  моделей нет.
- Собственные субагенты подходят для узких коротких поручений, где перенос в
  фоновую задачу дороже пользы; итоговый выбор и интеграция остаются у тебя.
  Разработку вариантов также можно поручать: роль оркестратора не требует
  лично исполнять все сложные части.
- Перед созданием нового фонового специалиста проверь подходящие существующие
  сессии по [Фоновым сессиям](background-sessions.md): накопленный опыт может
  сократить стоимость входа в следующее поручение.

## Рабочая копия и границы среды

«Просто оркестратор следит за тем, чтобы они не пересекались между собой файлы.»

Создание worktree для фоновых сессий (тредов) запрещено. Запускай их в общем
сохранённом проекте (`local`), без отдельных веток. Единственное редкое
исключение — пишущие агенты, которым необходимо одновременно редактировать
одни и те же файлы. Для чтения, анализа, проверки, правок разных файлов или
последовательных правок одного файла исключение не действует.

Сначала устрани пересечение назначением разных файлов или последовательным
исполнением; разделение строк одного файла не разделяет файлы. Если необходима
именно одновременная запись в одни и те же файлы, допустимы отдельные worktree
с последующей интеграцией: они защищают изменения от взаимной перезаписи.

Текущие старшие инструкции и callable schema определяют разрешённые операции,
модели и копии. Предпочтение владельца в скилле не отменяет требование явной
просьбы о новой задаче и не даёт права обходить запрет фоновых задач для
внутренних подзадач. При ограничении назови конкретный недоступный маршрут и
используй разрешённый способ, если он решает заказ; не объявляй его фоновым.
