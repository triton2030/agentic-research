# Наблюдаемый результат read-only пробы

Вход: `input.md`, `../tool-contracts.md` и runtime-пакет `../candidate/` из
манифеста `../reviewed-v1.json`. Свежий native-агент `/root/desktop_behavior`
вернул действия 2026-09-11. При пробе он не получал авторский intent,
принципы из истории или ожидаемый ответ. Ни один показанный вызов приложения
не выполнялся. Ниже сохранены действия и адресные фрагменты его возврата.

| Случай | Фактический выбор агента | Что этим проверено |
| --- | --- | --- |
| A: явно заказаны задачи | Три автора Luna Max по трём областям, существующий свободный Sol medium как общий проверяющий; он обращается к независимому Opus для итога | Агент построил собственную схему и выбрал повторного специалиста |
| A: связи | Авторы отправляют результаты в `2222…`; проверяющий отправляет итог в `1111…`. Поручения содержат полный адрес, hostId и требование выполнить `send_message_to_thread` | Связь проходит через реальный инструмент, а не только слово «отчитаться» |
| A: границы | Занятый «Переезд API» и личные «Мои заметки об Atlas» не привлечены; всем писателям назначены разные папки, `task.md` остаётся голове | Новое знание не вытеснило эти условия старой версии в данном случае |
| A: создание | `create_thread` получает `projectId: atlas-docs`, `environment: {type: local}`, `model: gpt-5.6-luna`, `thinking: max` после явно данного выбора владельца | Подготовленные поля соответствуют текущему контракту |

| C: завершение | Конкретный обратный вызов с дефектом, проверенной версией и адресами источника; локальный финал зависит от успеха отправки | Финал отдельного разговора не подменил доставку |

Фрагмент фактического поручения авторам в A:

> По завершении вызови mcp__codex_app__send_message_to_thread с threadId 22222222-2222-4222-8222-222222222222 и hostId local. В prompt передай собственный готовый threadId и hostId, результат, пути изменённых статей, Git HEAD и хеши результата и использованных источников, выполненные проверки, оставшиеся вопросы. Попроси проверить область и включить её в общую проверку.

Фактическое следующее действие в C:

```js
mcp__codex_app__send_message_to_thread({
  threadId: "11111111-1111-4111-8111-111111111111",
  hostId: "local",
  prompt: "Возврат проверки Atlas из задачи 55555555-5555-4555-8555-555555555555, hostId local. Проверен commit abc123: три области справки проверены по первичным материалам; все ссылки проходят. Вердикт: требуется исправление. В help/billing/refund.md:18 обещано 30 дней, тогда как sources/approved-terms-v4.md:52 разрешает только 14 дней. Правок я не вносил. Назначь автору billing исправление обещания до 14 дней и верни изменённую версию для повторной проверки затронутого обещания. Новая коммерческая политика не требуется: условие уже установлено договором. До повторной проверки исправленный результат не принят."
})
```

Предел вывода: это один агент и три подготовленных случая, без живого создания,
обратной доставки, гонок между задачами и принятия изменённого проекта.
Сравнение частоты успеха с предыдущей версией не проводилось. Агент сам выбрал
три писателя и два раунда доработки; скилл не предписывает эти числа.
Длинные поручения показывают, что добавление Desktop-механики не доказывает
уменьшение процедурности или нагрузки. Проверена возможность корректного
прочтения и составления операций в этих условиях.

## Продолжение по сохранённому файлу

Дополнительный вход — `resume.md`; проверен runtime desktop-v2, манифест
`reviewed-v2.json`. Тот же `/root/desktop_behavior` выбрал следующие действия:

1. `read_thread` по `66666666-6666-4666-8666-666666666666`, hostId local,
   turnLimit 3, includeOutputs true, maxOutputCharsPerItem 12000.
   Если нужный финал не вошёл, продолжить по возвращённому cursor.
2. После чтения — `send_message_to_thread` в сохранённый адрес проверяющего
   `22222222-2222-4222-8222-222222222222`, hostId local. В поручение включён
   фактически прочитанный финал как зависимость `billingFinal`, повторная
   проверка h-billing-2 и общего стыка, остаток одного раунда исправлений,
   первичные артефакты и требование вернуть результат через тот же инструмент
   голове `11111111-1111-4111-8111-111111111111`, hostId local.
3. `wait_threads` по адресу проверяющего с timeoutMs 30000 и последующим
   afterCursor. Ожидаемый возврат содержит фактические version/verdict/evidence,
   мнение Opus, открытые вопросы и требуемое решение; положительный вердикт
   не предполагается заранее.
4. В единственном task.md — отметить восстановление и передачу результата;
   после содержательной проверки обновить принятую версию, основания,
   остаток раундов и следующий ход. Архивирование преждевременно.

Это подготовленные операции продолжения. Агент уже видел A/B/C, поэтому
результат не доказывает независимый cold-start. Запись task.md, вызовы и
доставка не выполнялись. Финальная v3 только явно называет оба носителя
в уже общем пункте адресов; операции продолжения от этого не изменились.
