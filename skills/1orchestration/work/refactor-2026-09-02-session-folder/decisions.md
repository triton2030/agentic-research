# Решения — допуск инструкций (behavior-protocol.md)

Построенный случай: root ведёт двухдневную перекройку корпуса из 40 файлов
пятью пишущими исполнителями; окно сжимается трижды; владелец отсутствует.

## Отбор кандидатов

| # | Кандидат | Предсказание чистого агента по одному намерению файла | Вердикт |
| --- | --- | --- | --- |
| S1 | `state.md` ≤1000 знаков, перезапись целиком | без правила агент ведёт журнал дописыванием — дефолт «не терять» сильнее; критерий 1 ловит, но способ владелец назвал сам | число — прочтение агентом двусмысленного «на более 1000»; ждёт слова владельца (I3, волна 1) |
| S2 | состав `state.md` (цель словами владельца, принятое, в работе, следующее действие, вопросы владельцу) | агент выведет «следующее действие», но пропустит «где ляжет возврат» и «вопросы владельцу» — после сжатия он не знает, что ждёт ответа | **не выводится**, принято |
| S3 | окно после сжатия начинается со `state.md` | после сжатия агент читает summary и продолжает по нему; файл он не откроет, если не сказано — это и есть точка отказа из науки | **не выводится**, принято; дублируется в теле как условие возврата в файл, потому что после сжатия сам файл не в окне |
| S4 | `decisions.md` дописывается в момент решения | критерий 2 закрывает; правило нужно как содержание файла (что, почему, что заменяет, чем отменить) — «чем отменить» агент сам не напишет | принято как состав, момент — критерием |
| S5 | поручение лежит сверху файла прогона, возврат пишется ниже в тот же файл | агент отправит поручение текстом в prompt и получит возврат в окно — дефолт runtime; переиздание после сжатия невозможно | **не выводится**, принято |
| S6 | поручение отправляется адресом файла | следует из S5? нет: агент может держать файл «для истории» и всё равно вставлять текст в prompt, тогда возврат идёт в окно | **не выводится**, принято |
| S7 | исполнитель пишет только в свою зону и свой файл прогона | тело уже требует названную зону; здесь — что файл прогона входит в неё | принято одной строкой внутри S5 |
| S8 | `log.md` строкой на событие со временем и адресом | владелец просил файл истории; без формы агент напишет прозу на страницу | принято как состав |
| S9 | имя папки `<дата>-<суть>` | конвенция проекта; глобально — агент назовёт папку разумно сам | **выводится**, снято |
| S10 | адрес папки называется владельцу в чате | тело уже требует «владелец видит в чате, кому что ушло» — адрес папки туда входит | **влечётся**, снято |
| S11 | что делать, когда у проекта нет папки оркестраций | агент заведёт её в рабочей зоне проекта; Задача говорит «там, где проект держит» | **выводится**, снято |

## Дом каждого принятого

Критерием закрыты моменты (2) и предел (1); механизма — скрипта, схемы — нет:
никакой скрипт не отличит «следующее действие» от журнала. Остальное — состав
файлов — инструкцией в файле стадии.

## Achieve-план на Maintain-цели

Проверено: все правила файлов сформулированы как режим ведения («при каждой
смене положения», «в момент решения», «строкой на событие»), не как однократный
акт. Пустого срабатывания на уже выполненной цели нет.

## След выполнения

| # | След |
| --- | --- |
| S1–S3 | `state.md` существует, ≤1000 знаков, содержит «следующее действие»; в `log.md` строка «сжато» и следом действие, названное в `state.md` |
| S4 | запись в `decisions.md` датирована раньше строки `log.md` о работе, которая на неё оперлась |
| S5–S7 | файл прогона содержит поручение и под ним возврат, написанный исполнителем; prompt исполнителю — адрес |
| S8 | `log.md` — строки, не проза |

## Счёт единиц `references/session.md`

Файлы: `state.md` — 3 (предел и перезапись; состав; окно начинается с него);
`decisions.md` — 2 (момент; состав); `runs/` — 5 (поручение сверху; возврат
ниже в тот же файл с вердиктом и адресом; исполнитель пишет только в зону; ты
дописываешь приём; отправка адресом); `log.md` — 2 (строка на событие; время и
адрес). Задача — 1 (заведи там, где проект держит). **Итого 13.** Критерии
принятия — 5, вне счёта.

Тело: +1 абзац в «Когда читать» (условие входа; возврат после сжатия) — 2
единицы к прежним.

## Правка тела

Только абзац в «Когда читать». Клауза Цели «решения волны … живут файлом
дольше твоей сессии» не тронута — файл стадии её реализует.
