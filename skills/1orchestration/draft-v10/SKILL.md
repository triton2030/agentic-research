# Оркестрация

## Уникальный контекст

Поручение перераспределяет когнитивную нагрузку, а не снимает её.
Root — технический директор оркестрации: он удерживает пользу и траекторию
общей цели, принимает решения, интегрирует результаты и владеет приёмкой,
пока остальные участники удерживают только выполнимые наборы.

## Цели пользователя

- Активные наборы каждого actor-а и следующего решения root выполнимы.
- Brief не становится owner-ом правды, адресованной в `read`.
- Root открывает зависимый ход только после `pass` каждого обязательного
  критерия по актуальному evidence.

## Протокол поведения

1. До brief root читает load-bearing owner- и authority-источники, нужные ему
   для общей цели, границ решений и приёмки; делегируемое evidence читает
   назначенный исполнитель.
2. Сформируй brief:
   - `outcome` — состояние поручаемого результата, связанное с общей целью;
   - `done_when` содержит все применимые критерии;
   - для каждого критерия `done_when` названо требуемое evidence;
   - `read` — точные адреса влияющих источников и входов;
   - `delta` — только сведения и границы решений, отсутствующие в содержимом
     источников и входов, адресованных в `read`.
3. После brief приблизительно оцени активный набор каждого предполагаемого
   actor-а.
4. Отдельно оцени активный набор root в следующем решении.
5. Активная единица — одна независимо забываемая вещь.
6. Ориентир около `20` — мягкий сигнал, а не предел.
7. Выбери простейшую форму, удовлетворяющую целям выше.
8. Делегируй только через границу, после которой хотя бы один участник
   перестаёт удерживать часть активного набора.
9. Утверждение о результате, отчёт о ходе и «done» не являются evidence;
   каждый `done_when` получает `pass` только по обещанному адресу либо
   наблюдаемому результату.
10. Если изменился влияющий источник или вход, верни затронутую работу к
    первому результату, который перестал быть актуальным.
