## FAST и commander's intent

Функция: перед поручением превратить когнитивную работу в результат и набор
влияющих инструкций, посильные выбранному actor/model, не отдавая root-ом
пользу, траекторию, решения, интеграцию и приёмку общей работы.

Момент вызова: root собирается поручить работу субагенту либо разделить
перегруженную когнитивную работу.

### Уникальный контекст

В работе пользователя на одно поручение одновременно влияют глобальные,
проектные, папочные, skill- и task-инструкции. Они различаются когнитивной
ценой и посильностью для конкретного actor/model; около 20 одновременно
удерживаемых единиц — мягкий сигнал риска деградации, а не предел.

### Цели пользователя

- Root сохраняет посильным собственный активный набор и владеет пользой,
  траекторией, решениями, интеграцией и приёмкой общей работы; каждый actor
  получает посильный результат с посильной именно ему совокупностью работы и
  влияющих инструкций.
- Brief сохраняет все применимые критерии приёмки и адресует влияющие
  источники, но не пересказывает их и добавляет только отсутствующую в них
  дельту.
- Зависимый ход начинается только после наблюдаемого `pass` каждого
  обязательного критерия; отчёт о ходе или `done` успехом не считается.

## Clean-room reimplementation / Zero-based design

Чистый исполнитель получил только новый commander's intent и не видел старого
пакета. Он независимо восстановил Уникальный контекст и три цели, а также
предложил пять hard lines: authority root, посильность выбранному actor/model,
полнота критериев без пересказа sources, self-report не evidence и all-pass
barrier.

Смысловой результат принят как вход авторских режимов, но его структура и
строки не считаются готовой формой. Три из пяти hard lines повторяют цели;
они останутся отдельными только при доказанном behavior-gap.

## Полный авторский черновик

### Кнопка запуска

После wave-1 `description` уточнён: `Use when about to assign a subagent or
split overloaded cognitive work.` Он короче 200 символов, содержит только
наблюдаемый момент и различает состояние до и после поручения.

- use-before assignment: «Поручи субагенту проверить три исходных файла»;
- skip-after assignment: «Поручение субагенту уже отправлено вчера»;
- use-before split: «Раздели перегруженную когнитивную работу между агентами»;
- skip-after split: «Перегруженная работа уже разделена между агентами»;
- near-miss: «Раздели модуль по архитектурным границам сейчас» — это
  design-решение, пока поручения actor-у нет.

### Протокол поведения

Сохранён только невыводимый когнитивный порядок:

1. root читает влияющие на качество входы до brief;
2. brief фиксирует точный интерфейс `outcome · done_when/evidence · read ·
   delta`;
3. только после готового brief оцениваются actor/root и когнитивная цена;
4. оценка завершается выбором простейшей границы, реально уменьшающей набор
   хотя бы одного участника.

Порядок теперь опирается на неповреждённые буквальные фрагменты owner-речи.
Токен `<unk>` между фрагментами исходной записи не реконструирован: авторская
связка стоит снаружи кавычек.

Это закрывает четыре правдоподобных неверных прочтения: делегировать чтение,
оценить неполное поручение, считать единицы равными и превратить ориентир 20 в
механический hard cap. Повторы целей и отдельный runtime self-check не
добавлены.

### Референс-файлы

Не созданы. У runtime один связный момент `brief → оценка → выбор формы`, а
разделение добавило бы route и постоянные обязательства, не уменьшая активный
набор.

### Дефолты агентов

| Добавка | Дефолт → механизм → изменяемое решение → вред без строки → цена строгости |
| --- | --- |
| чтение до brief | actor сам прочитает → root не знает load-bearing вход → делегирует чтение вместо подготовки brief → неполные критерии и неверная дельта → root тратит окно на влияющие входы |
| четыре поля brief | свободный prompt выглядит достаточным → пропускается один контрактный слой → поручение нельзя принять по источникам → ложное или неполное `done` → фиксирован короткий interface |
| оценка после brief | ранняя оценка кажется дешевле → реальные критерии ещё неизвестны → выбирается actor по неполному набору → скрытая перегрузка → обязательна одна приблизительная оценка |
| independently forgettable unit | число bullet-ов выглядит счётом → связанные формулировки маскируют отдельные обязательства → нагрузка занижается → ориентир 20 теряет смысл → требуется смысловой, не символьный счёт |
| простейшая форма | декомпозиция кажется страховкой → процесс дробится ради порога → участники получают больше стадий без снижения нагрузки → skill сам создаёт перегрузку → запрещена необоснованная сложность |

Hard line `self-report ≠ evidence` не продублирован в протоколе: после
наблюдаемого clean failure он встроен непосредственно в третью цель.
