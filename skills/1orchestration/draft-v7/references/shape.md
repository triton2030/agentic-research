# Минимальная форма

## Цель

Выбрать форму, в которой способный участник получает меньший посильный набор,
а действующие владельцы не теряют своих полномочий.

Вход: уверенно посильные отдельные оценки исполнителя и root либо вердикты их
реестров. Выход: `root-work`, `direct-assignment`, `controller-handoff` либо
минимальная схема нескольких результатов.

1. Выбери наименьшую способную форму.
2. Граница полезна только если после неё конкретный участник вправе отбросить
   целые активные единицы.
3. Зависимые результаты выполняй последовательно.
4. Независимо доказуемые результаты можешь выполнять параллельно.
5. Выбери участника, способного выполнить `outcome`.
6. Участник должен уметь предъявить требуемое evidence.
7. Малый набор не компенсирует отсутствующую способность.
8. Специализированный контроллер сохраняет свою topology.
9. Специализированный контроллер сохраняет приёмку своей схемы.
10. Живой runtime-владелец сохраняет весь execution lifecycle.
11. Если честная граница не уменьшает перегруз, оставь работу root.
12. Если root принимает неустранимый перегруз, назови риск и более частую
    проверку.
13. Не создавай поручение ради процесса.
14. Только для новых результатов многорезультатной схемы вернись к шагу 3 тела:
    актуальная карта есть, а контракт каждого нового результата ещё отсутствует.
15. `root-work` завершает shaping возвратом работы root.
16. `direct-assignment` завершает shaping возвратом готового контракта
    runtime-владельцу.
17. `controller-handoff` завершает общий skill передачей контрактов и
    вердиктов специализированному владельцу.
