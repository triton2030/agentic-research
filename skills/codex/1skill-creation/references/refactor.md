# Изменение существующего скила

Старый пакет — источник принятого смысла и материал для проверки потерь.
Автор читает его сам и пишет новую редакцию из восстановленного намерения.
Сохранённая стадия относится к конкретному незавершённому заказу: новая
просьба пользователя сначала уточняет его границу, а не подчиняется старой
записи о состоянии.

## Когда определяешь границу изменения

Прочитай пакет по реестру владельцев, действующие принципы и состояние в
папке-истории. Карта прежних снятий объясняет, почему возвращать старую
формулировку только по привычке нельзя.

| Заказ | Маршрут |
| --- | --- |
| Пользователь назвал конкретное дополнение, исправление или область изменения | Адресная правка: меняются названное и необходимые согласования; незатронутые части сохраняются. Отдельная фраза «остальное не трогать» для этого не нужна. |
| Пользователь просит переосмыслить функцию или пересоздать скил целиком | Полная переработка: старый текст проверяет сохранность смысла, но не задаёт форму нового. |
| Неясность меняет требуемый результат или расширяет границу | Выясни именно эту неясность, продолжая независимую работу. Оценка автора «правка маленькая» сама по себе маршрут не определяет. |

Сохрани границу, маршрут и источники старого пакета. Нужные исходники и
артефакты стадии остаются в истории, а не у отдельного пишущего агента.

## Когда выбираешь следующий шаг

Входом служат маршрут и стадия вместе. Названия старых стадий ниже позволяют
продолжить сохранённую работу без нового участника процесса.

| Сохранённое состояние | Следующее действие |
| --- | --- |
| Новый заказ; состояния текущего заказа нет; `нужен новый commander's intent` | Восстанови только затронутое намерение по `goal-context.md`. В полном маршруте затронут весь замысел. |
| `готово новое намерение`; `готово обновлённое намерение`; `нужен полный авторский черновик`; `ожидается смысловой черновик` | Автор сам пишет полный черновик в пределах сохранённого маршрута. Существующий промежуточный результат учитывается, если относится к этому заказу. |
| `готов полный черновик` | Проверь потери по разделу ниже. |
| `рефактор завершён` в продолжаемом заказе | Карта потерь уже принята. Продолжи незавершённую проверку версии или доставку по телу; если обе завершены, новой работы нет. |
| `нужен ответ владельца` | По новому ответу обнови намерение и вернись к самой ранней затронутой стадии того же маршрута; без ответа зависимый выбор остаётся открытым. |

После шага запиши его результат и следующую стадию. Для черновика вернись
к условным разделам тела: смысл намерения, допуск содержания и моменты
применения. Поздняя правка повторяет только причинно затронутую работу.

## Когда черновик готов

Сопоставь его со старым пакетом, источниками и границей заказа. Проверь
функцию, существенные результаты, пользовательские способы и незатронутые
части. Однозначный пропуск автора восстанови без нового вопроса владельцу.
Конфликт источников или новый выбор сохрани вместе с состоянием
`нужен ответ владельца`; повтор после ответа сохраняет прежний маршрут.

Снятие явно заказанного способа требует объяснения и проверки, что нужное
поведение сохранилось; дорогое снятие проверяется сравнением действий.
Явная отмена способа пользователем задаёт новое основание проверки.

Запиши в `cut.md` карту: что сохранено, переформулировано или снято, почему
и по какому свидетельству проверено. Приведи карту к финальным байтам после
разбора находок. Незавершённая проверка потерь не пропускает черновик на
проверку готовности. Принятая карта переводит состояние в `рефактор завершён`;
дальше отдельно идут проверка версии и доставка по телу скила.
