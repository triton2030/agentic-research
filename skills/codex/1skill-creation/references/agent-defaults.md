# Аудит формулировок и дефолтов агента

Вход: проверяющий оценивает каждую сформулированную агентом строку черновика,
включая пересказ слов пользователя.
Цель: найти формулировку, которая искажает смысл владельца, допускает
двусмысленное поведение, добавляет неоправданную нагрузку либо не убеждает
агента применить скил.

## Порядок

1. Для каждой строки назови её источник, требуемый смысл и ближайшее
   правдоподобное неверное прочтение.
2. Закончи фразу: «без этой строки агент сделает X, потому что Y выглядит
   разумным» — и запиши вывод до чтения оснований в папке-истории, иначе шагу 5
   не с чем сравнивать.
3. Для строк Контекста, Задачи и Цели проверь, что источником
   служит фраза владельца или evidence проекта с адресом, которого автор
   черновика в этой работе не писал; строку из evidence, расходящегося со
   словами владельца, считай находкой, пока расхождение не решил он. Считай
   находкой строку, у которой такого источника нет: агент написал её из
   собственного предположения без опоры на заказ. Критерии принятия добавляют
   только уникальное условие, невыводимое из Контекста и Задачи: защищаемый
   смысл принадлежит пользователю, а остаточную лазейку и её проверку
   устанавливает автор скила.
4. Проверь, передаёт ли Контекст неизвестное читателю устройство ситуации,
   из которого можно вывести проблему и направление действий. Общая теория
   или повтор задачи не заменяют недостающее звено описания мира.
5. Для каждой инструкции и каждого критерия проверь названную в единице
   причину и её связь с результатом по источникам допуска. Единица без причины —
   находка. Несовпадение с твоим прогнозом из шага 2 требует проверки, а не
   отклонения: причин может быть несколько, а твой прогноз может быть ошибочным.

## Критерии суждения

- Не принимай симптом, название исследования или недоверие к агенту за механизм
  поведения.
- Считай строку лишней, если доступный контекст, задача или другое требование
  уже меняют тот же выбор. Общность Цели сама по себе выводимость не доказывает.
- Считай знание оправданным, только когда оно меняет названное действие, решение
  или границу агента.
- Учитывай, что требование против дефолта и новое активное обязательство
  повышают риск отказа.
- Считай строку оправданной, только если предсказанный вред без неё дороже
  потерянной автономности.
- Если нарушение недопустимо, предложи убрать путь к нему вместо усиления
  формулировки; текст сам по себе не является гарантией.
- Пустой список находок законен; не выдумывай правки ради счёта.

Выход: для каждой находки — `источник → формулировка → неверное прочтение →
дефолт → изменяемое решение → вред → цена строгости → минимальная правка`;
проверяющий проходит эту цепочку внутри своей находки, а не вторым форматом
ответа.
