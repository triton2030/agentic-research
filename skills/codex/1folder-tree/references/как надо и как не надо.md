# Как надо и как не надо

Парные примеры из разных продуктов. Имена вещей и полок выдуманы. Имена файлов заменены ролью вопроса в угловых скобках — `<зачем>`, `<как устроено>` — потому что реальные имена вопросов задаёт владелец проекта в конвенциях. Ничто здесь не образец именования. Существующие имена в базе владельца не меняются, чтобы стать похожими на эти.

Сгруппировано по правилу. В каждой паре: ошибка, исправление, одна строка почему.

---

# Путь — это знание: вложенность = принадлежность

## Вложенность без принадлежности

Не надо (одна поверхность бывает в разных пакетах):
```
словарь/
  пакет поверхностей/
    поверхность/
      ракурс/
```
Надо:
```
словарь/
  пакет поверхностей/
    <что это>
    <как устроено>          ← перечисляет поверхности по имени
  поверхность/
    <что это>
    ракурс/
      <что это>
```
Путь «пакет → поверхность» утверждает, что поверхность есть только в этом пакете. Это ложь — и её прочитает каждый, кто увидит путь. Ракурс принадлежит одной поверхности — вложен честно.

Не надо (онлайн-школа, преподаватель ведёт несколько курсов):
```
словарь/
  курс/
    урок/
    преподаватель/
```
Надо:
```
словарь/
  курс/
    <что это>
    урок/
      <что это>
  преподаватель/
    <что это>
```
Урок — часть одного курса, вложен. Преподаватель — нет, сосед.

Не надо (клиника):
```
словарь/
  врач/
    приём/
```
Надо:
```
словарь/
  врач/
    <что это>
  приём/
    <что это>
    <как устроено>          ← «проводит один врач»
```
Приём связан с врачом, но не принадлежит ему: у приёма есть ещё пациент, кабинет, время. Связь — упоминание, не вложенность.

## Принадлежность, не отражённая в пути

Не надо (CRM):
```
словарь/
  сделка/
  этап сделки/
  комментарий к сделке/
```
Надо:
```
словарь/
  сделка/
    <что это>
    этап/
      <что это>
    комментарий/
      <что это>
```
Этап и комментарий существуют только внутри сделки. Плоская раскладка теряет это знание, и имена приходится удлинять, чтобы его вернуть. Путь «сделка → этап» говорит это сам.

## «Для» принято за «внутри»

Не надо:
```
основа/
  аудитория/
    покупатель/
      <кто это>
      каталог/              ← экран внутри аудитории
```
Надо:
```
основа/
  аудитория/
    покупатель/
      <кто это>
для покупателей/
  каталог/
```
Каталог — для покупателя, а не часть покупателя. Кружка для чая не лежит внутри чая.

## Путь прочитан и не использован

Не надо:
```
[агент открыл общее/оплата/возвраты/<как устроено> и первой строкой написал:
 «Возвраты — часть процесса оплаты, который является сквозным процессом…»]
```
Надо:
```
[агент начинает с сути: «Покупатель может вернуть деньги до этапа производства…»]
```
Путь уже сказал, что возвраты — часть оплаты, а оплата — процесс. Повторять это в файле — дубль.

# Папка — вещь, файл — вопрос про неё

## Свойство вместо вещи

Не надо (маркетплейс):
```
безопасность/
  пароли
  оплата
  личные данные
```
Надо:
```
для покупателей/
  вход/
    <как устроено>          ← правила про пароли
общее/
  оплата/
    <как устроено>          ← правила про защиту платежа
```
Безопасность нельзя показать пальцем и посчитать. Папка-свойство становится второй свалкой: правило живёт и там, и у вещи, и они расходятся.

Не надо (онлайн-школа):
```
качество обучения/
  проверка домашних
  обратная связь
```
Надо:
```
общее/
  проверка домашнего задания/
    <как устроено>
    <что бывает не так>
```
«Качество» — свойство. Проверка домашнего — вещь: у неё есть начало, конец, участники.

## Тема или тип документа вместо вопроса

Не надо (клиника):
```
запись на приём/
  описание
  функционал
  требования
  спецификация
  заметки
```
Надо:
```
запись на приём/
  <зачем>
  <как выглядит>
  <как устроено>
  <что бывает не так>
```
«Описание» и «функционал» — про одно и то же, агент положит факт в оба. «Спецификация» — тип документа, а не вопрос. Вопросы из набора владельца не пересекаются.

## Мешок

Не надо (CRM):
```
карточка клиента/
  <как устроено>
  детали
  разное
  прочее
  заметки
```
Надо:
```
карточка клиента/
  <как устроено>
  <что бывает не так>
  <что видит человек>
  _<техническое>
```
«Детали» и «разное» — «всё остальное». Никто не знает, что туда класть и что оттуда читать. Разобранный на вопросы мешок показывает владельцу то, что было в нём похоронено.

## Файл с именем папки

Не надо (фитнес):
```
тренировка/
  тренировка
  <как устроено>
```
Надо:
```
тренировка/
  <зачем>
  <как устроено>
```
Файл-тёзка пытается описать вещь целиком и дублирует свойства рядом.

## Список разного под общим именем

Не надо:
```
основа/
  принципы           ← 30 пунктов: и «студия видит цену до принятия», и «скорость важнее красоты»
```
Надо:
```
основа/
  <порядок предпочтений>   ← 6 пунктов, только тайбрейкеры
для студий/
  согласование/
    <как устроено>         ← «студия видит цену до принятия» — правило этой вещи
```
Тест на каждый пункт: называет конкретную вещь — уезжает к ней. Ни про что конкретное и помогает выбрать между двумя хорошими вариантами — остаётся.

## Свой вопрос, придуманный на ходу

Не надо:
```
корзина/
  <зачем>
  <как устроено>
  пограничные кейсы          ← агент придумал, хотя в наборе есть вопрос про то, что бывает не так
  UX-соображения             ← агент придумал
```
Надо:
```
корзина/
  <зачем>
  <как устроено>
  <что бывает не так>
```
Набор вопросов один для всех вещей типа. Нет подходящего вопроса — это абзац в существующем файле или подвещь, а новый вопрос вводит только владелец, сразу для всего типа.

# Полка — не вещь

## Полка с файлами

Не надо:
```
для покупателей/
  <зачем>
  чего хочет покупатель
  каталог/
```
Надо:
```
основа/
  аудитория/
    покупатель/
      <кто это>
      <чего хочет>
для покупателей/
  каталог/
```
У полки нет свойств, поэтому в ней нет файлов. Покупатель как вещь живёт в основе; полка — место, где лежат его экраны.

## Вещь, принятая за полку

Не надо (клиника):
```
врачи/            ← только папки, значит «полка»
  расписание/
  профиль/
```
Надо:
```
основа/
  аудитория/
    врач/
      <кто это>
      <чего хочет>
для врачей/
  расписание/
  профиль/
```
Если про врачей есть что сказать — это вещь, ей нужны файлы. Полка — только когда сказать нечего, кроме «здесь лежит вот это».

# Когда появляется папка

## Действие без экрана как папка

Не надо:
```
корзина/
  добавление товара/
  удаление товара/
  изменение количества/
```
Надо:
```
корзина/
  <как устроено>          ← абзацы: добавить, удалить, изменить
```
Но:
```
для студий/
  добавление продукта/
    <как выглядит>
    <как устроено>
    _<техническое>
```
Кнопка — абзац. Экран с формой в несколько шагов — вещь.

## Папка ради одного абзаца

Не надо (фитнес):
```
словарь/
  подход/
    <что это>             ← три строки, больше сказать нечего
```
Надо:
```
словарь/
  подход
```
Одиночный файл с именем понятия, пока не появится второй вопрос. Тогда файл становится папкой.

## Файл порезали вместо вещи

Не надо:
```
каталог/
  как работает 1
  как работает 2
  как работает продолжение
```
Надо:
```
каталог/
  <как устроено>          ← абзац: «фильтрация и сортировка — отдельно»
  фильтры/
    <как устроено>
  сортировка/
    <как устроено>
```
Файл вырос — внутри вещи прятались другие вещи. Резать вещь, не файл.

## Папка, созданная агентом молча

Не надо:
```
[агент получил материал про уведомления и создал]
общее/
  нотификации/
    <как устроено>
```
Надо:
```
[агент спрашивает владельца]
Материал про уведомления не ложится ни в одну вещь. Варианты:
1. общее/уведомления — сквозной процесс, уведомления идут и студии, и покупателю
2. абзац в общее/путь заказа — если уведомления только про заказ
3. словарь/уведомление — если это понятие, которое встретится во многих экранах
Какой?
```
Папка рождается через владельца. «Нотификации» — агентское слово; владелец сказал бы «уведомления». Выбор записывается в конвенции.

# Один факт — одно место

## Процесс размазан по экранам

Не надо:
```
для покупателей/
  оформление заказа/
    <как устроено>        ← весь путь заказа
для студий/
  карточка заказа/
    <как устроено>        ← снова весь путь заказа
```
Надо:
```
общее/
  путь заказа/
    <как устроено>        ← описан один раз
для покупателей/
  оформление заказа/
    <как устроено>        ← «начинает путь заказа, этап заявка»
для студий/
  карточка заказа/
    <как устроено>        ← «показывает путь заказа с этапа согласования»
```
Экран говорит, где в процессе стоит. Два пересказа разойдутся.

## Знание о вещи там, где с ней работают

Не надо:
```
для меня/
  фабрика поверхностей/
    <как устроено>        ← здесь требования к картинке ракурса
```
Надо:
```
основа/
  словарь/
    поверхность/
      ракурс/
        <как устроено>    ← требования к картинке
для меня/
  фабрика поверхностей/
    <как устроено>        ← «создаёт поверхности и ракурсы» — называет, не объясняет
```
Верно про ракурс независимо от экрана — у ракурса. Страница товара покажет те же ракурсы, и строящий её агент будет искать требования у понятия, а не в чужом инструменте.

Не надо (клиника):
```
для пациентов/
  запись на приём/
    <как устроено>        ← здесь определено, что приём 30 минут, первичный и повторный
```
Надо:
```
основа/
  словарь/
    приём/
      <что это>           ← первичный и повторный, длительность
для пациентов/
  запись на приём/
    <как устроено>        ← «пациент выбирает приём»
```
Длительность приёма нужна и расписанию врача, и напоминаниям. Определение — у вещи.

## Группировка по типу документа

Не надо:
```
дизайн экранов/
  каталог
  корзина
логика экранов/
  каталог
  корзина
```
Надо:
```
для покупателей/
  каталог/
    <как выглядит>
    <как устроено>
  корзина/
    <как выглядит>
    <как устроено>
```
Понять корзину — одна папка, не две. Агент загружает одну папку.

## Папки по ролям или этапам работы

Не надо:
```
дизайн/
  каталог
разработка/
  каталог
маркетинг/
  каталог
```
Надо:
```
для покупателей/
  каталог/
    <как выглядит>        ← «дизайн»
    <как устроено>
    _<техническое>        ← «разработка»
```
Роль — кто читает, а не что описано. Кто читает — решает маркер агентского файла, не место в дереве.

## Документация на код

Не надо:
```
основа/
  _техника/
    функции корзины/
      addToCart
      removeFromCart
```
Надо:
```
основа/
  _техника/
    <устройство системы>   ← где лежит код корзины, одной строкой
```
Канон кода — код. Описание функций устаревает при первом коммите.

# Упоминают вещи, а не файлы

Здесь агент ошибается чаще всего, потому что ссылка на файл кажется точнее.

## Ссылка на файл

Не надо:
```
каталог/<зачем>:
  «см. основа/аудитория/покупатель/<чего боится>»
```
Надо:
```
каталог/<зачем>:
  «каталог — то, что видит покупатель; что бы ни решал, помни про него»
```
Набор файлов у вещи меняется, имя вещи — нет. Читатель сам откроет папку и возьмёт нужное.

## Ссылка на файл в стиле вики

Не надо:
```
согласование/<как устроено>:
  «Цена рассчитывается по правилам из [[словарь/цена/как устроено]]»
```
Надо:
```
согласование/<как устроено>:
  «Студия видит цену, рассчитанную по правилам цены.»
  (при желании — [[словарь/цена]], но смысл несёт имя)
```
Если файл переименуют или вопрос переедет в другой файл — ссылка врёт. Имя вещи и путь к её папке — нет.

## Указание, какой файл читать

Не надо:
```
корзина/_<техническое>:
  «Перед реализацией прочитай общее/оплата/_<техническое> и общее/оплата/<что бывает не так>»
```
Надо:
```
корзина/_<техническое>:
  «Корзина передаёт заказ в оплату.»
```
Агент, строящий корзину, сам откроет папку оплаты и решит, что ему нужно сегодня. Список файлов устареет, а зависимость от вещи — нет.

## Пересказ вместо упоминания

Не надо (CRM):
```
сделка/<как устроено>:
  «Клиент — это компания или человек, с которым мы ведём переговоры;
   у него есть контакты, история, ответственный менеджер…»
```
Надо:
```
сделка/<как устроено>:
  «Сделка всегда принадлежит одному клиенту.»
```
Что такое клиент — у клиента. Сделка называет его по имени.

## Единственное допустимое исключение

Можно:
```
напоминания/<как устроено>:
  «Время напоминания зависит от длительности приёма.»
```
Документ по смыслу зависит от одного конкретного свойства другой вещи — можно назвать свойство словами. Но если так приходится делать часто — длительность на самом деле вещь, и ей нужна своя папка.

# Имена

## Имена под агента

Не надо:
```
каталог/
  spec_catalog_v2_final
  каталог 2026 09 09
  catalog_reqs_UPDATED
  как работает (старое)
```
Надо:
```
каталог/
  <как устроено>
```
Версии и даты — признак, что файл боятся править. Правят файл; почему поменяли — в журнале решений.

## Имя не из речи владельца

Не надо:
```
для покупателей/
  страница каталога товаров/
  экран корзины пользователя/
  модуль оформления/
```
Надо:
```
для покупателей/
  каталог/
  корзина/
  оформление заказа/
```
Владелец говорит «каталог», не «страница каталога товаров». Имя вещи — как в разговоре: существительное, единственное число, без «страница», «экран», «модуль».

## Смешение языков и транслит

Не надо:
```
для покупателей/
  checkout/
  корзина/
  katalog/
```
Надо:
```
для покупателей/
  оформление заказа/
  корзина/
  каталог/
```
Язык имён один — язык владельца. Даже если в коде это checkout.

## Переименование существующего

Не надо:
```
[в базе была папка «покупка»; агент переименовал в «оформление заказа», потому что так правильнее]
```
Надо:
```
[агент оставляет «покупка» и пишет владельцу]
В базе есть «покупка», по смыслу это экран оформления заказа. Оставить или переименовать? На «покупку» ссылаются четыре файла.
```
Имя вещи — часть карты владельца и адрес для упоминаний. Меняется только его решением.

# Что важно владельцу, а что агенту

## Развилка спрятана в агентский файл

Не надо:
```
каталог/_<техническое>:
  «Бесконечная лента вместо пагинации. Дебаунс поиска 300 мс.»
```
Надо:
```
каталог/<что бывает не так>:
  «Товары подгружаются лентой при прокрутке, без страниц.»
каталог/_<техническое>:
  «Дебаунс поиска 300 мс.»
```
Решили бы наоборот — владелец заметил бы? Лента вместо страниц — да. 300 мс вместо 500 — нет.

## Технические подробности в читаемом файле

Не надо:
```
корзина/<как устроено>:
  «Состояние корзины хранится в localStorage и синхронизируется
   с сервером по debounce 1 с через PATCH /cart…»
```
Надо:
```
корзина/<как устроено>:
  «Корзина сохраняется между визитами.»
корзина/_<техническое>:
  «localStorage + синхронизация PATCH /cart с дебаунсом 1 с.»
```
Владелец читает за минуту. Как именно сохраняется — не его вопрос.

## Спорная строка

Не надо:
```
[агент сам решил, что «сортировка по умолчанию — по популярности» — техническая деталь, и убрал вниз]
```
Надо:
```
каталог/<как устроено>:
  «По умолчанию товары отсортированы по популярности. ❓»
```
Сомнение — оставить в читаемом и пометить. Владелец передвинет; пара уходит в конвенции.

# Планы — не источник

## Решение осталось в закрытом плане

Не надо:
```
[план задачи «фильтры каталога» закрыт; в нём «решили: фильтр по цене — ползунок»; в базе про это ничего]
```
Надо:
```
каталог/фильтры/<что бывает не так>:
  «Цена задаётся ползунком, не двумя полями.»
[в плане — ничего, или «перенесено в базу»]
```
Через месяц никто не читает закрытые планы. Решение переезжает — не копируется — в папку вещи.

## План внутри базы

Не надо:
```
для покупателей/
  каталог/
    план работ
    что сделано
    статус
```
Надо:
```
[в базе — только свойства каталога; план и статус — в слое планирования]
```
Работа — не свойство вещи. База отвечает «что верно», план — «что делаем».
