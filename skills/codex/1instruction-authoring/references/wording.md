# Формулировка

Вход: формулировка строки инструкции спорна.

- Строка инструкции — изменение решения, а не описание хорошего поведения;
  рабочая форма: операция или состояние [+ причина против привлекательного
  ошибочного дефолта].
- Причина нужна только там, где без неё агент честно вернётся к неверной
  ветви; капслок, повтор и длинное объяснение причину не заменяют.
- Проверь строку тремя вопросами: какой наблюдаемый след появится после
  применения · как дешевле всего формально выполнить её без результата ·
  какой законный путь она закрывает.
- «Достаточно», «качественно», «тщательно», «учти», «при необходимости» и
  похожие слова оставляют модели неназванный выход — замени observable
  condition либо удали.
- По умолчанию пиши цель, границы и контракт выхода; порядок оставляй только
  по procedure boundary — когда шаги нельзя переставить без потери
  корректности (владелец разбора — скил `1context-refactor`).
- Готово, когда из чистого окна остаётся одно честное прочтение и оно ведёт к
  проверяемому действию без лишнего ограничения маршрута.

Выход: решённая формулировка — вернись в прерванную стадию.
