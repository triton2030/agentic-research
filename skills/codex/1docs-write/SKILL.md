# Запись документов

## Задача

Размести новое знание или содержание старого документа в подходящем актуальном
тексте либо передай его владельцу другого вида записи с основанием.

## Цель

Внутри `_docs` у знания есть один понятный по имени дом, а решение,
предположение и материал для выбора различимы.
Документы сохраняют актуальный смысл без внутренних дублей и истории
поправок; развёрнутые исследования и объяснения могут пересекаться с кратким
утверждённым намерением в `_canon`.
Существенные противоречия доступны владельцу для решения, а форма записи
соответствует её назначению.

## Зачем

Владелец находит ответы по именам файлов и папок, хотя его мысли распределены
по месяцам разговоров и старым документам. Идеи помогают ему принять решение,
а утверждённое направляет работу; смешение статусов меняет продукт без его
согласия. Второй дом внутри документации и история дополнений заставляют
заново собирать актуальный ответ. Поэтому подходящий документ уточняется, а обнаруженный конфликт
возвращает владельцу вопрос, который уже обсуждался.

## Критерии принятия

- Дом знания обоснован содержанием подходящих документов; новый файл в
  `_docs` не дублирует другой файл внутри `_docs`. В ответе есть ссылка и краткое основание выбора,
  чтобы отсутствие поиска нельзя было выдать за отсутствие дома.
- Статус утверждения подтверждён исходными словами в контексте;
  неподтверждённое различимо в результате, чтобы метка записи и уверенный тон
  не превращали предположение в решение.
- Неразрешённый конфликт предъявлен двумя исходными местами и предложением;
  изменение не делает спорную позицию действующей, чтобы автор не выбирал
  за владельца.
- Существенное содержание входа отражено, уже покрыто или передано с
  основанием. Источник и результат позволяют проверить его судьбу, чтобы
  сокращение не скрывало потерю; ответ об обработке остаётся в чате.
- Текст понятен своему читателю, соответствует назначению и доступен по
  ссылке из ответа. У внешних сведений есть дата и источник, чтобы владелец
  мог оценить их актуальность.

## Маршрут работы

### Метаданные и карта

Каждый Markdown-документ в папке документации проекта (`_docs`, `Docs` или
её местный аналог) имеет YAML-frontmatter: `description` — одно короткое
предложение о вопросе и границах файла; `aliases` — список коротких поисковых
имён. Обновляй их вместе с содержанием, чтобы карта не обещала устаревший ответ.

Алиасы связывают документ с речью владельца и реализацией: бери реальные
формулировки из найденных через `1chat-recall` цитат и точные связанные имена
из прочитанного кода — переменные, поля, функции, типы. Обычно это одно-два
слова либо один идентификатор с сохранением регистра и написания. Не добавляй
общие теги, придуманные синонимы и случайные имена; если один источник отсутствует,
используй другой, если оба не дали имён — `aliases: []`. Основания выбранных
алиасов показывай адресами цитат и кода в ответе: совпадение слов само по себе
не доказывает связь. Устаревшее имя реализации заменяй при изменении связи;
прежняя формулировка владельца остаётся полезной для поиска его цитат.

Для выбора документов запусти [скрипт карты](scripts/doc_map.py):

```bash
uv run --script <папка-этого-скила>/scripts/doc_map.py <папка-документации>
```

Подставь путь загруженного скила и фактическую папку проекта. Команда выводит
в stdout Markdown-таблицу всех путей, описаний и алиасов, включая скрытые
файлы и пустые папки; файлы не меняет. Симлинки перечисляет без обхода,
вложения без Markdown отмечает отдельно. Код 1 означает видимые пробелы
метаданных или ошибки чтения, 2 — неверный корень. Нужны `uv` и Python 3.10+;
`uv` обеспечивает PyYAML из объявления скрипта (при первом запуске возможна
загрузка зависимости). Карта выбирает кандидатов, содержание которых нужно
прочитать полностью; отсутствие описания не исключает файл из поиска.

### Выбор режима

1. Целый старый документ или расшифровка ещё не разобраны —
   [разбор источника](references/разбор-источника.md): отделяет утверждения
   и их основания, чтобы не перенести старую структуру вместе с повторами.
2. У подготовленного знания ещё нет места —
   [размещение](references/размещение.md): определяет статус и владельца
   записи, затем существующий дом; без этого идея может попасть в канон.
3. Дом вне канона определён —
   [запись на месте](references/запись-на-месте.md): сохраняет назначение
   документа при уточнении, чтобы новый материал не стал довеском или
   незапрошенной перестройкой папки.
