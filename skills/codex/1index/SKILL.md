# Индекс оплаченных маршрутов

Запись в INDEX — не ссылка на файл: инструменты листинга у агента и так есть.
Запись — **короткий путь, оплаченный прошлым поиском**: предыдущий агент уже
прочитал файл целиком, нашёл зарытое знание и записал маршрут, чтобы следующий
не платил тот же поиск. Вторая работа индекса — тематическая компиляция: где
лежит относящееся к теме X, когда оно размазано по файлам разных папок.

## Цель

В корне проекта — а при папочных инструкциях и рядом с ними — живёт `INDEX.md`,
по которому холодный агент за **один переход** находит знание, лежащее не там,
где он стал бы искать.

Не входит: дерево файлов · вторая правда · заявка на полноту · сами
инструкции (`1instruction-shaping`) · поиск по смыслу (`1md-search`).

## Критерии успеха

- Пять представительных намерений → попадание за один переход.
- Каждая запись оплачена реальным поиском или явным словом владельца — не
  сгенерирована из листинга.
- Промах безопасно падает в живую навигацию; INDEX не заявляет полноту.
- Ни одна строка не стала второй правдой.
- Указатель на INDEX стоит в корневой цепочке инструкций (ставится через
  `1instruction-shaping`).

## Инварианты

- Запись рождается из проведённого поиска, не из видимой структуры: «вижу в
  дереве» — не основание для строки.
- Строка несёт маршрут и короткое действие («что там узнать»); статус, число,
  решение, обещание живут только у owner-а.
- Знание-маршруты, выгнанные из свода инструкций (`knowledge-out`),
  приземляются здесь.
- Папочный INDEX существует только рядом с папочной инструкцией — симметрия:
  инструкция несёт поведение поддерева, индекс — его зарытое знание.
- Индекс знает свою папку и ведёт только вниз, в своё поддерево: маршрут
  наверх — чужая зона. Корневой индекс может покрывать весь проект и ссылается
  на дочерние индексы.
- Маршрут живёт в одном индексе — ближайшем к знанию: дубль между индексами —
  вторая правда, расходящаяся молча.
- Один роутер на область: эквивалентный живой intent-router обновляется, второй
  INDEX не создаётся.
- Ложный маршрут хуже отсутствия: переезд файла или раздела правится в той же
  работе, которая его переместила.
- Новый INDEX-файл создаётся после «да» владельца; дозапись маршрута в
  существующий свободна — это и есть самопомощь по ходу работы.

## Дельта

Модель умеет писать оглавления — и поэтому пишет их зря:

- генерирует красивую карту из имён файлов, которая не экономит ни одного хода;
- не отличает «нашёл дорогим поиском» от «вижу в листинге»;
- не записывает находку в момент находки — заканчивает задачу и уносит маршрут
  с собой;
- затаскивает в индекс статусы и решения, создавая вторую правду.

## Известные сбои

`когда → сбой → цена → куда`

- новый или мелкий проект → INDEX ради формы → налог без экономии, стоп-правило
  в Механике → [writing](references/writing.md)
- создаю записи → строки из дерева файлов → индекс ничего не экономит →
  [writing](references/writing.md)
- пишу маршрут → затащил статус или решение → вторая правда, расходится с
  owner-ом молча → [writing](references/writing.md)
- нашёл зарытое по ходу работы → не записал → следующий агент платит тот же
  поиск снова → [upkeep](references/upkeep.md)
- конец длинной сессии → INDEX не тронут → оплаченные находки сессии потеряны
  для будущих агентов → [upkeep](references/upkeep.md)
- файл переехал → маршрут не поправлен → ложный маршрут дороже отсутствия →
  [upkeep](references/upkeep.md)
- несколько индексов → маршрут задублирован между ними → копии расходятся
  молча → [upkeep](references/upkeep.md)

## Механика

1. **Допуск.** Поиск в проекте реально дорог: файлы большие, имена не выдают
   содержимое, знание размазано. Мелкий прозрачный проект → стоп, INDEX не
   нужен.
2. **Вход** — один из трёх: вызов владельца (основной) · протокол `1handoff`
   в конце длинной сессии · находка по ходу работы.
3. **Кандидаты** — из слов владельца о ближайшей работе, живых целей и
   повторявшихся дорогих поисков.
4. **Записи** в формате (точная форма — здесь, в теле):

   ```markdown
   ## <намерение — зачем пришёл>
   - [файл#раздел](path.md#anchor) — что там узнать или сделать
   ```

5. **Проверка** пятью представительными намерениями: попадание за один переход.
6. **Согласование.** Новый INDEX-файл — после «да» владельца; указатель в
   корневой цепочке — через `1instruction-shaping`.

## Завершение

Пять намерений прошли за один переход; каждая запись оплачена; вторых правд
нет; изменённый Markdown прошёл локальный lint, ссылки — `1md-graph`. Для
нового INDEX-файла есть «да» владельца. Что не вошло — названо.
