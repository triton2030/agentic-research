# Оркестрация

Субагенты покупают независимость и чистоту контекста ценой координации.
Оркестратор распределяет работу и instruction load, а у себя держит просьбу
владельца, пользу для проекта, траекторию, решения и интеграцию. Исполнителям
он отдаёт только ограниченные потоки с проверяемым возвратом.

## Цель

Когда волна окупается, на руках — один результат, полезный цели проекта и
собранный из минимального числа потоков: root не утонул в промежуточном шуме,
каждый субагент владел ограниченной задачей, а конфликты, пробелы и решения не
потерялись при синтезе. Если не окупается, правильный результат скила — не
открывать её и сохранить работу у root или одного субагента.

Волна не владеет формой живого плана, выбором методологии советника или
продуктовой истиной; root читает их live owners и координирует работу против
них.

## Стандарт решения

- До карты root сам читает load-bearing owner-источники цели, продуктовой
  правды и прежних решений; citation или summary субагента чтение не заменяют.
  Буквальная работа сверяется с пользой и выполнимостью: обратимую in-scope
  коррекцию root принимает и показывает сам, а меняющую долговечную правду,
  полномочия или необратимый ход отдаёт владельцу.
- Открывай волну, только когда разделение покупает хотя бы одно из:
  независимый evidence stream · непересекающееся владение записью · изоляцию
  шумного контекста · реальное сокращение времени.
- Параллельно идут только независимые потоки. Зависимый следующий этап получает
  отдельное окно лишь когда смена ownership, чистый контекст, независимая
  приёмка или recovery сами окупают handoff; иначе цепочку держит root либо
  один субагент.
- Используй минимальное число окон, покрывающее независимые потоки. Не создавай
  субагента только ради общей перепроверки; отдельная приёмка нужна лишь когда
  её требует риск или действующий контракт.
- Деление идёт по самостоятельному результату или owner-границе, не по
  равным кускам текста и не по ролям ради самих ролей.

## Контракт волны

Порядок здесь несёт корректность: плохое деление нельзя починить поздним
синтезом, а зависимый ход нельзя начинать до обязательных возвратов.

1. **До запуска покажи карту волны в чате.** Для каждого потока назови
   самостоятельный результат, независимость или место в staged-порядке,
   обязательный барьер, write ownership, instruction focus и return packet.
2. **Дай каждому окну self-contained brief:** outcome · live-адреса исходных
   данных и обязательных инструкций его момента · границы и write ownership ·
   return packet `результат · адресуемое evidence · gaps · blockers`.
   Не пересказывай owner-источники и не выгружай весь свод; активные инструкции
   не отменяются, а brief фокусирует первое решение исполнителя. Root решает,
   что достаточно дать адресом, что повторить в момент действия и где нужен
   отдельный evidence owner; статическая таблица классов это решение не заменяет.
3. **Запускай параллельно только независимое.** Пересекающиеся записи получают
   одного писателя либо последовательный handoff. Root продолжает только
   работу, не зависящую от незавершённых обязательных потоков.
4. **Прими возвраты до синтеза.** Адресуемое evidence подтверждает результат;
   сообщение «учёл» или progress report — нет. Когда независимая приёмка
   действительно обязательна, её делает окно, не писавшее проверяемую работу.
5. **Синтезирует только root.** Он разрешает конфликты по owner-источникам,
   проверяет load-bearing claims, интегрирует изменения и не голосует по числу
   совпавших агентов. После волны в чате остаются принятые результаты,
   нерешённые gaps/blockers, проверка интеграции и следующий ход.

## Носитель и восстановление

С живым планом план владеет state и записывает outcome каждого repair;
порядок, барьеры и сам wait/probe/repair остаются у этого скила. Без плана
durable носитель нужен, когда потеря root-контекста будет стоить больше одной
переиздаваемой волны; тогда прочитай
[wave-folder](references/wave-folder.md) и создай cold-start carrier. В любом
режиме ожидаемый возврат без material delta открывает
[repair](references/repair.md), а не новую импровизированную волну.

## Неснимаемые сбои

- fan-out без независимости → координация дороже работы → закрой волну или
  оставь один поток;
- весь свод в каждом brief → context hygiene потеряна → оставь live-адреса и
  инструкции момента;
- progress report принят за результат → бесконечные ожидания → проверяй
  названный return/artifact/diff;
- синтез до обязательного барьера → решение построено из неполного evidence →
  останови только зависимую ветку.

## Завершение

У запущенной волны полезный результат собран; обязательные возвраты приняты;
интеграция проверена; решения, gaps и blockers видимы; durable носитель
обновлён, если был нужен; отчёт волны дан в чате. Если стандарт решения не
пройден, волна не запускается: названа причина, работа продолжается у root или
одного субагента.
