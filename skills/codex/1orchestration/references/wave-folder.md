# Папка волны — шаблон носителя

Только без плана; с планом носитель — план (`1planning`/delegation).
Папку добавить в `.gitignore` при создании.

## context.md

    # Волна <дата-слаг>
    Зачем · проблема · цель · границы: …
    Runtime/session handle: …

    ## Задачи
    - <stable id> · assignment · worker handle · return path ·
      status pending|running|returned|accepted|repair

    ## Переходы
    <после каждого принятия — в том же ходе>

    ## Закрытие — перечитать при каждом возврате
    - проверяло окно, не писавшее работу; возврат — разница
      списков, не мнение
    - конфликт, пустота, развилка → волевое решение в decisions.md
      или вопрос владельцу пачкой
    - меняющая ветку развилка → немедленный стоп зависимой ветки
    - переход записан выше в том же ходе
    - отчёт таблицей в чат: агент → задача → фокус → возврат →
      чем проверено

До запуска заполнено всё, кроме worker handle — его дописать сразу
после запуска. Нужный после обрыва возврат воркер пишет по return
path до ответа; остальные могут остаться в thread.

Блок «Закрытие» — помеченная копия шага 4 Механики SKILL.md
(повтор в момент по таблице цены); правится вместе с ним.

## decisions.md

Решение · обоснование · чем проверено. След волны, не канон:
переживающее волну решение уходит в план или вопросом владельцу.
