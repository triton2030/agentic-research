## Контекст

Recraft MCP — внешний платный инструмент. Owner brief не является prompt:
аналитическое требование сначала переводится в наблюдаемые признаки будущего
кадра, иначе модель может буквально визуализировать служебные числа и символы.
Вызов оправдан только прямой просьбой использовать Recraft/Рекрафт.

## Цель

Получить пригодное изображение с первого кредитного вызова: prompt описывает
визуальные причины нужного эффекта, а не повторяет формулировку владельца.
Сохранить результат и точный prompt, затем назвать живой остаток кредитов.

## Обязательный ход

1. Подтверди прямой Recraft-триггер. Не подменяй недоступный Recraft другим
   генератором молча.
2. Не пиши prompt напрямую из просьбы. Сначала отдели **намерение управления**
   от **буквального содержимого** и составь внутреннюю карту
   `требование → видимый признак`. Проценты, координаты, pixel dimensions и
   служебные числа перенеси в tool parameters либо переведи в композицию:
   `объект доминирует`, `плотный кадр`, `узкие поля`, `края близко к границам`.
   Не переноси исходные числа в prompt, если владелец не просит показать их как
   текст или не задаёт точное количество видимых объектов.
3. Определи назначение, формат и пропорции результата. Недостающие визуальные
   решения выведи из задачи; без назначения используй `1:1`.
4. Перед кредитным вызовом собери самодостаточный структурированный промпт по
   [prompting.md](references/prompting.md). Не оплачивай исследовательский промпт
   из 3–6 слов. Не вставляй историю чата, метакомментарии или инструкции агенту.
5. Выбери инструмент по [tools.md](references/tools.md). По умолчанию:
   `generate_image`, `model=recraftv4_1`, `n=1`. Другую модель или несколько
   вариантов используй только когда это прямо следует из просьбы владельца.
6. Вызови Recraft. Если инструмент вернул несколько результатов, сохрани каждый.
7. Сразу сохрани результат через `scripts/save_generation.py`:

   ```bash
   python3 \
     /Users/triton/.codex/skills/recraft-images/scripts/save_generation.py \
     --project-root "/absolute/project/root" \
     --name "краткое-смысловое-имя" \
     --source "URL_ИЛИ_ПУТЬ" \
     --prompt "ТОЧНЫЙ_ПРОМПТ"
   ```

   Бери корень из активного workspace/project context; не подставляй `$PWD`,
   если shell находится в подпапке. Повтори `--source` для нескольких
   результатов. Скрипт создаёт
   `_workspace/design/recraft-images/<MM-DD>/`, сохраняет raster как PNG,
   нативный vector как SVG и рядом — одноимённый `.md`, содержащий только точный
   промпт.
   Для prompt-tool сохрани точный отправленный prompt, для `call_agent` — точный
   отправленный `message`, для инструмента без текста — точную инструкцию
   владельца, вызвавшую операцию.
8. После каждого Recraft-вызова, который создаёт новый image output, один раз
   вызови `get_user`. Заверши сообщением: `Осталось N кредитов Recraft.` Не
   вычисляй баланс по прайсу и не повторяй старое число.
9. Покажи сохранённый результат абсолютной Markdown-ссылкой и кратко назови
   использованные tool/model. Не объявляй успех, если файл и парный `.md` не
   существуют.

## Модель и формат

- Дефолт — `recraftv4_1`, один результат.
- `recraftv4_1_pro` — только при явном запросе Pro, крупного/печатного или
  повышенного разрешения.
- Любая другая модель — только по прямому запросу и только если её допускает
  живая enum-схема текущего tool. Не изобретай model id из названия в Studio.
- Для SVG сначала проверь живую enum-схему. Если нативный Vector недоступен,
  не маскируй два платных шага `generate_image → vectorize_image` под один:
  назови ограничение и запроси разрешение на дополнительную операцию.
- Не передавай `input_style` или `input_style_id` моделям V4/V4.1: официальная
  таблица совместимости запрещает styles для этого семейства, даже если поле
  присутствует в общей MCP-схеме.

## Входные локальные изображения

Recraft image tools принимают URL. Для локального PNG/JPEG/WEBP вызови
`request_upload_url`, следуй возвращённой инструкции загрузки и передай
полученный URL целевому tool. Не публикуй upload URL или учётные данные в
итоговом ответе. Маску загружай тем же способом.

## Границы

- `delete_style` — только по прямой просьбе после проверки точного style id.
- Не создавай custom style «на всякий случай»; он нужен только по запросу и
  должен использоваться с совместимой моделью и типом.
- Не обещай актуальную цену из памяти. Подписочные кредиты списывает удалённый
  MCP; текущий остаток — только из `get_user`.
- Не создавай отдельную папку на изображение, не добавляй год в дневную папку и
  не добавляй заголовки или metadata в парный `.md`.

## Известные сбои

`когда → сбой → цена → куда`

- обычная image-задача без слова Recraft → ложная активация → неверный платный
  путь → Контекст
- короткий платный prompt → эстетика отдана случайности → потеря кредита →
  [prompting.md](references/prompting.md)
- owner brief скопирован в prompt → служебные проценты/координаты становятся
  видимым содержимым → неверный кадр → Обязательный ход, шаг 2
- copied model id не входит в live enum → tool отклоняет вызов → нулевой
  результат → [tools.md](references/tools.md)
- V4.1 получает style field → несовместимый вызов → ошибка или ложное ожидание
  style control → Модель и формат
- output остался только по URL → проект теряет генерацию/provenance →
  `scripts/save_generation.py`
- после генерации назван старый баланс → владелец не видит расход → шаг 8
