# Chat recall

## Инвариант

Source-bound evidence владельца первично. Дословная цитата остаётся цитатой,
Plan-выбор — selection, а note/raw evidence явно остаётся недословным. Ошибка
или отсутствие даты, type, topic либо формата никогда не отменяет запись.
Retrieval включает exact, legacy, partial, multiline и raw records.

Лог — датированное evidence, не текущий канон. Поздняя цитата может отменить
раннюю, а approximate timeline нельзя выдавать за «текущую истину».

## Router

- Появилось свежее durable evidence владельца: в том же ходе сохрани каждый
  самостоятельный полезный тезис отдельной записью. Пропускай согласие,
  подтверждение или команду, если сами слова не образуют долговечного знания.
  Всегда пропускай credentials и вставленный материал, который не выражает
  позицию владельца.
- Прежний ввод или Plan-выбор текущего чата может изменить долгоживущий
  результат: прочитай evidence текущего чата.
- Текущая существенная развилка зависит от уже высказывавшихся целей, границ,
  решений, критериев, коррекций или предпочтений: прочитай только тот
  recall-кластер, который может изменить решение.
- Пользователь явно спрашивает, что говорил, просит найти цитаты или сделать
  recall-harvest: используй corpus retrieval.
- У существующей записи есть diagnostics или повреждённая metadata: используй
  repair. Только эта ветвь разрешает искать другую сессию.

## Evidence текущего Codex-чата

Когда прежний пользовательский ввод или Plan-ответ может изменить долгоживущий
результат:

```bash
RECALL="${CODEX_HOME:-$HOME/.codex}/skills/1chat-recall/scripts/chat_recall.py"
python3 "$RECALL" read
python3 "$RECALL" search "<точный фрагмент>" --scope user
python3 "$RECALL" show <record-id>
```

Обычный режим читает только живой `CODEX_THREAD_ID` и по умолчанию исключает
текущий turn. Для exact capture свежей реплики добавь
`--include-current-turn` к `read`, `search` или `show`; если record всё равно
отсутствует, используй честный `turn-context` fallback ниже. Не угадывай
соседний чат. Plan option написан агентом: это `selection` (“пользователь
выбрал X”), не дословная цитата.

## Запись

Автоматически сохраняй не всякую durable реплику, а каждый самостоятельный
полезный тезис владельца: решение, коррекцию, предпочтение, идею, критерий,
правило-кандидат, факт о workflow или фактическое утверждение. Запись проходит
usefulness gate, только если её собственные слова вне соседних сообщений могут
изменить будущее решение, границу, критерий, предпочтение либо понимание
владельца. `«Да, давай так исправим»` gate не проходит: смысл живёт в чужом
контексте, а не в цитате. Сокращай deletion-only; не превращай agent summary,
вставленный текст, credentials или недолговечную команду в цитату.

Exact transcript record:

```bash
CAPTURE="${CODEX_HOME:-$HOME/.codex}/skills/1chat-recall/scripts/chat_capture.py"
python3 "$CAPTURE" \
  --quote "<слова владельца>" \
  --source-timestamp "<timezone-aware transcript timestamp>" \
  --type решение --topic документация-и-знания --agent codex \
  --project "$PWD" --session "$CODEX_THREAD_ID"
```

Если уже полезная deletion-only цитата всё ещё содержит неясный референт,
добавь `--context-note "<одно короткое пояснение агента>"`. Заметка хранится
inline в той же записи, явно остаётся недословной и показывается через `show`;
она не участвует в record ID, BM25 или dense ranking. Она только называет
обсуждаемый объект или ситуацию: не добавляет новый вывод, мотивацию, URL, путь
либо ссылку на transcript/другую запись. Ограничение — 300 символов;
`--kind note` с `--context-note` недопустим. Context note никогда не делает
слабую цитату достойной записи: сначала usefulness gate, затем пояснение.

`--source-timestamp` всегда имеет значение: timezone-aware ISO, approximate
ISO/date или `unknown`. Для approximate/unknown обязательно укажи
`--timestamp-source`, обычно `--timestamp-precision`, при необходимости
`--source-ref`. Для выбранного agent-authored варианта используй
`--kind selection`, для позднего пояснения — `--kind note`.

Default `source=transcript` допустим только после чтения exact native record.
Время из памяти, filename или semantic match остаётся repaired/approximate даже
в timezone-aware ISO-записи: передай честный source и non-exact precision.

Если свежая реплика отсутствует в native transcript, сохрани timestamp
наблюдения и явно передай `--timestamp-source turn-context` вместе с
`--timestamp-precision minute` (либо `date`). Capture отвергает exact для
turn-context; не называй observation time source-exact.

### Metadata

Выбирай metadata по долгоживущему смыслу тезиса, а не по случайным словам или
названию текущей задачи. Код проверяет принадлежность словарю, но не смысловую
правильность: перед записью агент обязан сам выбрать и перепроверить смысл.
Если словарь неясен, выполни `python3 "$CAPTURE" --list-metadata`.

Классифицируй речевой акт, а не форму предложения:

- Явное исправление прежнего понимания, решения или действия — `коррекция`,
  даже если оно одновременно устанавливает новое состояние.
- Условие оценки качества, готовности, успеха или реалистичности — `критерий`.
- Принятый долгоживущий курс или состояние — `решение`; ещё не принятая
  возможность — `идея`.
- Устойчивый вкус или ожидание между задачами — `предпочтение`; устойчивый
  личный или workflow-контекст — `обо-мне`.
- Повторяемая инструкция, ожидающая продвижения в своего owner-а, —
  `правило-кандидат`.
- Фактическое утверждение без более сильного речевого акта — `факт`; это
  фиксирует слова владельца, а не независимо доказывает истинность.

Topic — один широкий retrieval-owner:

- `цели-и-приоритеты` — назначение, outcomes и приоритеты.
- `границы-и-объём` — scope, красные линии и намеренно исключённое.
- `продукт-и-ценность` — поведение продукта, предложение и польза.
- `пользователи-и-потребности` — аудитории, задачи, боли и сценарии людей.
- `бизнес-и-монетизация` — модель бизнеса, цены, продажи и экономика.
- `бренд-и-коммуникация` — позиционирование, голос и внешняя подача.
- `контент-и-редактура` — тексты, медиа, публикация и редакционные решения.
- `дизайн-и-опыт` — визуальный язык, интерфейс и опыт использования.
- `исследования-и-источники` — поиск, provenance, evidence и цитирование.
- `данные-и-аналитика` — данные, метрики, расчёты и интерпретация.
- `архитектура-и-модель` — структура системы, доменная модель и связи.
- `код-и-реализация` — поведение кода, API и техническая реализация.
- `инструменты-и-автоматизация` — CLI, приложения и автоматизированные потоки.
- `агенты-и-ии` — модели, агенты, prompts и agentic-поведение.
- `работа-и-процессы` — workflow, координация, порядок и рабочие привычки.
- `документация-и-знания` — документы, память, навигация и owner truth.
- `качество-и-проверка` — acceptance, review, тесты и критерии готовности.
- `безопасность-и-доступ` — секреты, права, приватность и допустимый риск.
- `операции-и-инфраструктура` — среды, сервисы, deployment и эксплуатация.
- `обо-мне-и-предпочтения` — личный контекст, вкус и устойчивые ожидания.

Если подходят несколько тем, выбери owner, который вероятнее всего будет искать
этот тезис позже; не создавай более узкий label. Используй
`работа-и-процессы` для организации работы,
`инструменты-и-автоматизация` — для самого инструмента или автоматического
потока, `документация-и-знания` — для authority/навигации документов,
`архитектура-и-модель` — для сущностей системы и связей. `неопределено` и
`без-темы` — независимые repair-only значения; при добавлении repair-note любое
требует `--kind note`, и ни одно не является fallback для свежей цитаты.

## Retrieval по recall-корпусу

Когда записанное owner evidence может изменить текущую работу либо нужен явный
поиск цитат или harvest, задай runtime-specific переменные:

```bash
DIGEST="${CODEX_HOME:-$HOME/.codex}/skills/1chat-recall/scripts/chat_digest.py"
RECALL_DIR="$PWD/_ops/chat-recall"
```

Затем следуй
[`references/reading-the-log.md`](references/reading-the-log.md): этот файл
владеет `check`, inventory, локальным hybrid/lexical retrieval, filters,
timeline, `show`, bounded output и abstention.

## Repair

Исторический поиск вне живого треда разрешён только для ремонта уже
существующей recall-записи:

```bash
python3 "$RECALL" --repair-session <uuid> search "<точный фрагмент>" \
  --scope user --include-current-turn --verbose
```

Следуй
[`references/repairing-the-log.md`](references/repairing-the-log.md). В
read-only задаче покажи backlog `--check`, не переписывай. При разрешённой
mutation чини session-пакетами, ставь exact только после сверки текста/выбора с
native record и явно маркируй неразрешённое.

## Границы и stop

- Для `_ops/chat-recall` retrieval принадлежит `chat_digest.py`;
  `1md-search`/`1md-read` его не заменяют. `chronicle` хранит экранную историю,
  а не native transcript evidence.
- Не отправляй цитаты или transcript evidence в сеть, не импортируй цитаты из
  посторонних чатов и не объявляй датированный лог текущим каноном.
- Остановись, когда свежие durable тезисы сохранены либо на bounded-вопрос дан
  ответ или явный abstain, а provenance и diagnostics видны.
