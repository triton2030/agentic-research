# Терминальный запуск

`max-review` использует Python 3, установленный Codex CLI и его ChatGPT-вход.
Установка launcher в `~/.local/bin` и проверка маршрута:

```sh
python3 <skill>/scripts/install_cli.py
max-review doctor --json
```

Doctor проверяет локальную готовность; доступность Luna на сервере выясняется
при запуске. API-оплаты и автоматического перехода на другую модель нет.

## Задания и ответы

Сохрани каждое простое задание в отдельный текстовый файл. Вложи выбранные
исходники и [контракт короткого ответа](reviewer.md). В `tasks.jsonl` — одна
строка на задание с уникальным ID и абсолютными путями:

```json
{"id":"check-01","cwd":"/project","prompt_file":"/session/check-01.txt"}
{"id":"check-02","cwd":"/project","prompt_file":"/session/check-02.txt"}
```

```sh
max-review run --tasks /session/tasks.jsonl --run-dir /session/run --parallel 3 --timeout 600 --json
max-review status /session/run --json
max-review results /session/run --json
```

JSON здесь — вход оболочки и её служебный вывод. Сами агенты отвечают обычным
текстом. `--parallel` ограничивает одновременные процессы, а не число заданий.
Подходящая параллельность зависит от лимитов сервиса.

`results` показывает пути сохранённых ответов. Оболочка сохраняет исходные
prompts и все попытки. Успех процесса означает полученный ответ, не отсутствие
ошибок в проверяемом тексте. Для технически неудавшихся запусков:

```sh
max-review retry /session/run --failed --parallel 3 --json
```

Retry сохраняет прежние попытки и не повторяет успешные процессы. Если ответ
непригоден из-за постановки, исправь задание и запусти его отдельно; прежняя
версия остаётся историей. Timeout относится к одной попытке.

CLI работает read-only с approval policy never, без пользовательского config
и API-ключей. Это не технический запрет всех инструментов: просьба отвечать
без tool calls остаётся в задании, а нарушение видно по журналу процесса.
