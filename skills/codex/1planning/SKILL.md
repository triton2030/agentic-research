# Планирование

План — инструкция от агента агенту. Автономией управляют не длинные чёткие
процедуры — сколько ни расписывай, забытый пункт найдётся, и ошибка живёт
именно в нём, — а цель, которую нельзя понять иначе, чем правильно, плюс
перенесённый замысел (`context.md`), направляющий к ней.

Режимов задачи два, и «искать путь — тоже задача, которую надо исполнять»:
**Wayfinding** — путь материально не ясен, задача разрешает решения;
**Execution** — путь ясен, задача ведёт результат через вехи. Полный план
вперёд + ре-план по событию кратно дешевле пошагового контроля; устройство
режимов и цикл корректировки — [modes](references/modes.md).

## Цель

На руках — живой контракт выбранной работы и её `context.md`, по которым
следующая сессия с чистым окном продолжает или останавливается **по самим
файлам**, без скрытого чата. Контракт называет приближаемый пункт `GOAL.md`.

Не входит: цель проекта (`1goal`) · создание принципов (`1product-shaping`) ·
побочные находки (`1findings`) · маршруты к знанию (`1index`).

## Критерии успеха

- Контракт и `context.md` проходят cold-start-проверку из
  [contract](references/contract.md): новый агент восстанавливает что · зачем ·
  границы · на каком свидетельстве.
- Каждое существенное требование несёт происхождение: слово владельца / Frame /
  документ / допущение планировщика; «слово владельца» доказуемо записью
  chat-recall.
- Один текущий Next; записанные ниже ветки — не разрешение их исполнять.

## Инварианты

- План доверяет исполнителю маршрут, но не даёт додумывать замысел: пробел
  замысла — вопрос или допущение с происхождением, не тихий дефолт.
- Развилку, не покрытую планом, сначала неси в `1use-principles`: принципы и
  цель закрывают её без владельца; молчание принципов — вывод с пометкой
  «выведено», не эскалация.

## Дельта

Модель умеет раскладывать работу на шаги. Она не умеет:

- остановить разложение до свидетельства — расписывает дерево по трём
  непроверенным маршрутам;
- пересобрать план вместо заплатки — патчит устаревшее;
- отличить «путь ясен» от «путь кажется ясным»;
- резать по зависимостям — режет по хронологии, пряча риск в связи между
  этапами;
- перенести замысел из чата — контракт говорит «что», а «зачем» умирает с
  окном;
- удержать обязательства к концу длинного плана;
- не превратить свой дефолт через два пересказа в «волю владельца».

## Известные сбои

`когда → сбой → цена → куда`

- план до свидетельства → дерево шагов по непроверенным маршрутам → переделка
  всего дерева → [modes](references/modes.md)
- новое свидетельство → заплатка поверх вех → зомби-план ведёт работу →
  [modes](references/modes.md)
- путь неясен, но задача «исполняется» → архитектурный выбор на ходу без
  основания → [modes](references/modes.md)
- режу тяжёлую работу → хронология вместо оси → риск спрятан между этапами →
  [decompose](references/decompose.md)
- требование без происхождения → догадка планировщика стала «волей владельца»
  → [contract](references/contract.md)
- стык не назван → выход задачи 2 несъедобен задаче 4 → переделка на границе →
  [contract](references/contract.md)
- сессия сменилась → статус не отражает реальность → следующая сессия
  переделывает готовое → [contract](references/contract.md)
- работа шире одного контекста → воркеры без file-disjoint контракта →
  перетёртые правки → [delegation](references/delegation.md)
- контракт записан, чат умер → замысел не перенесён в `context.md` →
  исполнитель не может усомниться в шаге, который ухудшает картину →
  [contract](references/contract.md)
- контекст пишется «на всякий случай» → дубль канона, Frame и контракта →
  вторая правда стареет молча → [contract](references/contract.md)
- правлю чужой контракт по памяти → условия входа и акт вывода не встречены →
  работа идёт по нарушенной предпосылке → [contract](references/contract.md)

## Механика

Жёстких перехода два — остальное постусловия:

- **«да» владельца до файлов**: обоснование (цель · польза · режим · аппетит) —
  в чат; контракт и `context.md` — после согласия. Полный текст плана в чат не
  льётся. Обоснованию предшествует прогон `1use-principles` на составе плана,
  а не только на замеченной развилке: без него метка `Frame/принцип` в
  происхождении не ставится.
- **перечитай контракт и `context.md` до нового material-шага**: продолжение
  по памяти чата — источник зомби-планов; классификация свидетельства и
  пересборка — у [modes](references/modes.md).

Допуск: работа выбрана и переживает сессию; активен нативный Plan Mode →
молчи; иначе — разбор в чате без файла.

Постусловия живого контракта:

- форма файлов — по [contract](references/contract.md); `context.md` записан из
  породившего разговора вместе с контрактом;
- режим назван; вехи Execution — от оси разреза
  ([decompose](references/decompose.md));
- статус — текущая правда без хроники.

## Завершение

Закрытие — по критериям триады контракта, не по усталости. Применимое
подтверждено; статус отражает реальность; проектный `STATUS.md` (если
маршрутизирован) обновлён; следующая сессия может продолжить или закрыть по
файлу. Не вошедшее — в `cut.md` строкой с причиной.
