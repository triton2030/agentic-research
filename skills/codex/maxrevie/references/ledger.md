# Учёт покрытия

## Контекст

Один потерянный ответ не должен раствориться в сотне успешных. Этот реестр
проверяет бухгалтерию проверки; извлечение требований и истинность выводов
остаются за участниками.

## Задача

В сессии запиши `manifest.json` и `reports/<packet-id>.json`, чтобы механизм
мог сверить назначения, полноту ответов и версии. Идентификаторы стабильны
в пределах ревизии; исправление входа создаёт следующую ревизию.

```json
{
  "inputs": [
    {"id": "S1", "path": "/absolute/rules.md"},
    {"id": "T1", "path": "/absolute/target.md"}
  ],
  "rules": [
    {"id": "R1", "source": "S1", "targets": ["T1"], "disposition": "check"}
  ],
  "units": [{"id": "U1", "rules": ["R1"], "targets": ["T1"]}],
  "packets": [{"id": "P1", "units": ["U1"]}]
}
```

`inputs` включает все используемые нормативные источники и цели. Доступное
требование текущего поручения можно сохранить отдельным входом; скрытое
содержимое инструкций среды не экспортируют. Полный текст требований и
условия находятся в `rules.jsonl` с теми же ID и адресами источников.
`not_applicable` и `superseded` вместо `check` требуют `reason`;
недоступность источника сюда не относится — это пробел в state.
Каждая пара check-rule/target должна попасть в unit и назначенный пакет.
У правила связи перечислены все её цели; unit проверяет их совместно.
Независимая повторная проверка получает отдельный unit ID; один unit нельзя
назначить дважды, но области разных проверок могут пересекаться.

```bash
python3 <skill>/scripts/coverage.py seal <session>/manifest.json
python3 <skill>/scripts/coverage.py check <session>/manifest.json <session>/reports
```

`seal` добавляет отсутствующие SHA-256 после проверки плана и `plan_hash`
всего manifest; существующие хеши входов не перезаписывает. Каждый отчёт
содержит этот `plan_hash`: совпадения packet ID недостаточно для переноса
ответа на другую ревизию. `check` возвращает JSON со статусом, счётчиками, ошибками
и всеми находками. Код 0 — механический clean, 1 — findings/incomplete,
2 — invalid. Сохраняй полный вывод на диск; в контекст читай счётчики и
нужные находки. Не вырезай текст из проверяемого отчёта ради чистого статуса.
