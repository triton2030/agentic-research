# Инструмент интервью

## Контекст

Когда несколько связанных решений владельца неудобно собирать по одному в
чате, обычная тематическая анкета создаёт правдоподобные вопросы, но не
гарантирует, что ответы изменят будущий результат и покинут временный файл.

## Цель

Временная форма `_ops/interviews/YYYY-MM-DD-topic.md` собирает только связанные
решения владельца, которые меняют названный результат. У каждого ответа заранее
есть адрес в настоящем owner-е и материальное последствие неверной догадки;
после проверки ответы перенесены, а форма архивирована.

Интервью владеет формой и границей голосов. Текущая правда после обработки
живёт у owners результата.

## Известные сбои

`когда → сбой → цена → куда`

- карта вопросов допущена, пора собирать форму → произвольная разметка смешивает
  вопрос, рекомендацию агента и голос владельца → неверный перенос →
  [cookbook](references/plain-markdown-cookbook.md)

## Механика

1. **Результат и факты до вопросов.** Назови решение или действие, которое
   разблокирует форма, тип результата и `owner/path`. Добудь доступные факты и
   не спрашивай их. Для каждого оставшегося решения составь карту
   `<метка вопроса> → адрес ответа → что станет неверным при ошибке`.

   Создавай форму, только если осталось не менее четырёх связанных user-owned
   решений; иначе задай вопросы в чате. Если один ответ выбирает owner, тип
   результата или отменяет ветку, сначала создай маленькую форму только для
   этой развилки с адресом `owner unresolved`; продолжи после ответа.

2. **Форма.** Собери её из блоков cookbook. Каждый вопрос — отдельный
   H3-заголовок `### <N>. <вопрос>`; не прячь вопрос в абзаце, жирной строке
   или пункте списка. Под вопросом покажи, что ответ изменит, и рекомендацию с
   основанием. Если честной рекомендации нет, назови недостающий факт или
   owner-сигнал; варианты без различимых последствий замени свободным ответом.

   Поле ответа вложи H4-заголовком
   `#### Ответ пользователя — <уникальная метка>`. Внесённый туда текст
   становится голосом владельца. Слабый default становится его выбором только
   после общей отметки `Готово к проверке`; пустое поле и молчание согласием
   не являются. Видимую часть пиши простым русским; техническое имя оставляй
   только рядом со ссылкой на owner-артефакт.

3. **Перенос до архива.** После команды «проверь» отдели проверенные факты,
   ответы владельца, выводы агента и unresolved items, затем перенеси ответы
   по исходной карте. Дополняй существующий semantic owner. Новый документ,
   включая `SPEC`, создавай только при отдельном читателе, lifecycle и owner-е;
   место определяет owner результата.

   Добавь в форму:

   ```md
   > Результат перенесён: <owner paths>
   > Pending: <items с owner-ом и причиной либо нет>
   ```

   Только затем перемести форму в `_ops/interviews/_archive/`.

4. **Место.** При первом интервью найди project root по ближайшему `_ops`,
   затем VCS root, иначе явному project cwd. Создай `_ops/interviews/` и
   `_archive/` лениво; никогда не пиши в `/`.

## Завершение

Предъяви owner-paths результата, каждый pending item с его owner-ом и путь
архивированной формы.
