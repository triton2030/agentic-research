# Намерение и карта сохранения

## Функция

На материальной развилке ведущий получает независимые способы проверить
направление относительно пользы пользователю. Именованный специалист — один
родной результат с той же изоляцией. Авторинг может улучшить передачу этой
функции; смена состава панели и методов ролей не входит в этот рефактор.

## Почему добавлено

Общий факт не равен диагнозу ведущего: запрет передавать диагноз не должен
лишать нового агента цели, ограничений или самого объекта проверки. Это
применение 1agent-steering: дельта — неизвестное новому читателю устройство
ситуации. Конкретные границы запуска сохраняются рядом с зависимым действием.
Новый пакeт поясняет общий вход один раз вместо скрытой надежды на память
вызвавшего агента. Социальное давление и принуждение к разным вердиктам не
добавлены: задача требует независимых оснований, а не послушания критике.

Внешняя инженерная опора: [Anthropic, How we built our multi-agent research
system](https://www.anthropic.com/engineering/multi-agent-research-system),
прочитано 2026-09-12: objective, source/tools guidance, task boundaries,
сохранение независимых направлений и оценка результата вместо одного пути.
Это согласующаяся практика, а не измерение эффективности нашего скила.

## Разбор Opus

`opus-baseline-review.md`, фактическая модель `claude-opus-5`:

1. Устаревшая frame и FE-4 → принято согласование по текущему контракту и
   подтверждённым психологом источникам. Архивный draft не повышался до истины.
2. Четвёртый отчёт назван native в Claude synthesis → исправлено общей
   формулировкой «три родных отчёта и Premortem» с cross-family проверкой тела.
3. Нет незавершённого исхода при копиях вместо независимых оснований →
   принято явное `panel_incomplete` до восстановления независимости.
4. Generic sync не различает source-only frame и runtime → подтверждено.
   Перенос активной пары в `skills/1fresh-eyes` отклонён: root AGENTS прямо
   назначает эту папку архивом. Новое shared-дерево не создаётся ради
   симметрии. Сохраняются текущие owners и явный runtime manifest без двух
   продуктовых файлов; общий helper оставлен отдельной находкой.
5. Claude продолжение не называет ID → принято: сохранить ID и продолжать
   именно его доступным механизмом resume, не сочиняя версионную API-схему.

Сохранены Premortem-first и две runtime-копии. Цитата о закрытом составе
нативной тройки оставлена у момента её запуска; общая цитата о траектории
переформулирована в назначение по разрешённому рефактору, исходник сохранён
в frame и baseline. Слово владельца не превращено в требование критиковать.
