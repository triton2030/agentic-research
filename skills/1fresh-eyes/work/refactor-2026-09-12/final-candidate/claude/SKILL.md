# Свежие глаза

## Контекст

Долгая работа сужает рамку ведущего агента. Новый эксперт может унаследовать
её через объяснение в поручении, даже не видя переписки. Пользователю нужны
разные способы проверить направление: Ladder поднимается к цели, Solvent
разбирает допущения, Prospector ищет внешние прецеденты, Premortem исследует
вред от успешного выполнения. Методы и родные формы ответа принадлежат ролям.
Критика может испортить хорошую работу; совпавший итог при независимых
основаниях не делает отчёты копиями.

## Задача

Организуй независимую проверку конкретного решения и верни владельцу
обоснованный следующий ход. По умолчанию работают четыре линзы; явно
названный специалист получает один изолированный вызов.

## Цель

Дальнейшая работа служит конечному результату пользователя: ведущий агент
может пересмотреть путь по проверенным основаниям или сохранить его.
Разнообразие относится к исследованию, а решение принимается по свидетельствам,
не по числу поддержавших его агентов.

## Когда определяешь предмет проверки

Назови вопрос на столе и что изменит ответ. Восстанови конечный результат
из GOAL, применимых продуктовых рамок и доступных источников. При неполноте
отдели подтверждённое от профессионального вывода и пробела; предполагаемая
«настоящая цель» не заменяет заказ владельца. Без предмета проверки сначала
выясни его по имеющимся материалам, а не запускай общую критику проекта.

Выбери `panel` либо `named` с явно названным профилем. До первого запуска
подготовь [пакеты](references/packet.md) одной версии вопроса и исходников.

## Когда пакеты готовы

| Режим | Следующий ход |
| --- | --- |
| `named`, профиль Premortem | Получи [Premortem](references/premortem.md). |
| `named`, другой специалист | Получи [родной результат](references/named.md) выбранной роли. |
| `panel` | Сначала получи [Premortem](references/premortem.md), затем [три нативных отчёта](references/panel.md) по заранее подготовленным пакетам. |

Полная панель содержит все четыре терминальных отчёта, включая Premortem
другой фактической модельной семьи. Незапущенная, технически заблокированная
проверка (например, `search_blocked`) или нарушение независимости оставляют
проход `panel_incomplete` с точным препятствием. Готовые отчёты сохраняются,
но не выдаются за полный синтез. Содержательные `uncertain`, `rung_missing`
и другие родные выводы о пробеле допустимы после выполненной проверки;
неопределённость сохраняется в синтезе. Незавершённость этого прохода
не означает остановку всей пользовательской работы.

## Когда результаты получены

Ошибочную посылку исправь по [коррекции](references/steering.md); несогласие
с выводом само по себе не основание повторять вызов. Для полной панели
выполни [синтез](references/synthesis.md). В режиме `named` верни родной
результат или точный blocker и закончи проход без добавления панели.
