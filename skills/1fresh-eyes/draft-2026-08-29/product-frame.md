# Product Frame — 1fresh-eyes — draft 2026-08-29

Статус: installation candidate под финальной проверкой. Tracked owners и
installed projections ещё не обновлены.

## Цель-сцена

Длинная работа дошла до материальной развилки: главный агент называет якорь
решения, запускает панель четырёх направлений в изолированных потоках и по их
проверяемым основаниям выбирает следующий ход, альтернативу либо продолжение
без изменений. Когда пользователь явно назвал один доступный specialist
profile, тот запускается как named exception без панели и
возвращает свой native product.

## Тайбрейкеры

1. Названное следствие для решения сильнее ритуала: без него панель не зовётся.
2. Изоляция рамки главного агента сильнее полноты его гипотезы: проектная правда входит как материал, не как желаемый вывод.
3. Разные пути проверки сильнее стилистического расхождения: одинаковый итог допустим, одинаковые метод, источник и следствие — провал запуска.
4. Fixed four-lens panel — default широкой траекторной развилки; named exception существует только для явно названной пользователем роли.
5. Критика не самоцель: surviving route с source-supported опорой полноценен.

## Владение

Skill владеет якорем решения, изоляцией входа, составом панели и синтезом.
Определения ролей владеют методом и родной формой ответа. Runtime-специфичные
запуск и коррекция живут только в соответствующей форме; история и Product
Frame не устанавливаются в runtime package.

## Bounded-pass по commander's intent

В `Уникальный контекст` перенесены причина утечки рамки, источник свежести,
владение методом роли и ценность расхождения. В `Цель пользователя` перенесены
нейтральный вход, независимые пути проверки, native handback и запрет
голосования. Поэтому три отдельных admission-шагa стали одним якорем решения,
а дубли о методе роли, native form, обязательном чтении зоны, action labels и
группировке удалены.

Hard lines сохранены только у невыводимых швов: заморозить пакеты до первого
отчёта; запустить native и cross-family маршруты их точными интерфейсами;
остановить recursive call или неполную четвёрку; продолжить коррекцию через
того же runtime-owner; проверить различие путей и source support перед
handback. Их абстрактная замена снова откроет наблюдавшиеся зависание,
подмену четвёртой линзы или усреднение голосов.

## Диагностика внимания

Число 20 — сигнал риска, не product goal или acceptance gate; оно не
оправдывает дробление, которое делает панель церемониальной. Финальный
независимый пересчёт после bounded-pass сохраняется в install evidence; nested
runtime-owner остаётся открыто более тяжёлым, чем локальная фаза.
Пересмотр: панель запускается без decision consequence; briefs взаимозаменяемы;
named exception теряет isolation; consensus принимается без разных оснований;
одна линза регулярно не даёт отдельного decision input.
