# Карта смыслов: раскройка пары на пять скилов

Черновик, редакция 2 — после двух независимых Opus-аудитов (линза «лишнее» и
линза «потерянное/выдуманное»). Источник — `skills/shared/1instruction-shaping/portable/**`
и `skills/shared/1skill-shaping/portable/**` в состоянии сегодняшнего
незакоммиченного рефактора. Старые папки не тронуты; пятёрка создана рядом.

Вердикты: **kept(owner)** — смысл живёт целиком у названного нового владельца ·
**absorbed(чем)** — выводится из более общей строки, отдельной строки не
получает · **cut(причина)** — **кандидат** на снятие, окончательное решение не
моё.

Пять новых пакетов:

| Скил | Момент запуска |
| --- | --- |
| `1instruction-placement` | куда положить одно правило |
| `1instruction-refactor` | свод целиком: собрать с нуля или перестроить |
| `1skill-authoring` | нужен новый скил или новая функция существующего |
| `1skill-routing` | скил не вызывается / вызывается не в свой момент |
| `1skill-refactor` | скил вызывается, но раздут, ритуален, ничего не меняет |

## 3a. Метод курации (слова владельца 2026-08-26)

Резка ред. 2 велась тремя правилами владельца, а не признаком «дубль / не
дубль»:

1. **Ранжирование.** Сначала выбраны главные инструкции скила, остальное
   резалось относительно них.
2. **Зонтик.** Несколько инструкций сворачиваются в одну инструкцию-зонтик,
   подразумевающую нижние уровнем; законность зонтика проверяется прежним
   правилом поглощения — из зонтика выводится каждое снятое.
3. **Дельта от цели.** При сомнении «оставить процедурную строку или оставить
   цель, из которой она выводится» выбрана цель.

Применённые зонтики и их выводимость:

| Зонтик | Что свёрнуто | Чем выводится |
| --- | --- | --- |
| placement обяз. 3 «самый дешёвый достигающий слой, один owner» | I-14 «уже сказанное чинится у owner-а» | если смысл уже живёт у owner-а, самый дешёвый достигающий слой и есть этот owner |
| placement обяз. 4 «цель и границы вместо способа» | I-12 список correctness-случаев | список — именованное исключение из зонтика, оставлен адресом у `behavior-package` |
| authoring обяз. 2 «замысел словами владельца — до черновика» | дефицит · класс · триада · провенанс | все четыре восстанавливаются из слов владельца в один момент и у одного владельца `interview.md` |
| authoring обяз. 3 «поглощение и бюджет» | трихотомия S-21, условие выводимости, число ~10 | бюджет — количественная цель того же поглощения |
| routing обяз. 1 «всё "когда использовать" живёт в `description`» | формула, отрицательная граница, mid-trajectory, бюджет активации, cut test | цель скила (голая фраза 5–10 слов поднимает именно его) + адрес владельца делают процедуру выводимой |
| skill-refactor обяз. 2 «пересобирай от оригинала» | перечень провенанса | оригинал по определению включает слова владельца с адресами |
| skill-refactor обяз. 3 «один вердикт на смысл» | переразделение тело/references | носитель — одно из измерений вердикта «переместить» |

**Проход «идеи сессии в пятёрку» (verify-first, ред. 2).** Из четырёх идей три
уже имели владельца и сверены без правки: зонтик с проверкой выводимости —
`simplify.md` оператор 2; невыводимый остаток — оператор 3; «самоотчёт не
evidence» для чисел сдачи — `check.md`. Добавлены три недостающие строки, все в
references, счёт обязанностей тел не изменился: ранг и порядок конвейера →
`simplify.md` («## Операторы»); доказательство вердикта «поглощено» цитатой →
`audit.md` («## Выход»); pause point «проекции спорного содержания не
порождаются до вердикта» → `check.md` (перед «Сдача»). Последняя строка написана
по сегодняшнему живому провалу: yaml-проекции были созданы до вердикта и
бесшумно исполнили нерешённый cut.

**Отклонение от пакета координатора (одно).** Пункт 8 требовал убрать
правило «тело/reference» из тела `1skill-refactor`, оставив только адрес. Но
переразделение носителей — часть устава этого скила по разрезу владельца, и без
него устав в теле не виден. Сильнее оказался зонтик: носитель возвращён как
измерение уже существующего вердикта (`обяз. 3`), само правило деления осталось
у `reference.md`. Счёт обязанностей от этого не вырос.

## 4. Счёт обязанностей по скилам

Метод счёта — аудиторский: считаются обязанности **Контекста**, обязанности
**Цели** и **«Не входит»** (когда они несут правило, а не исход), нумерованные
обязанности и **контракт сдачи**. Ориентировка («Соседи», адреса рядом с
обязанностью) не в счёт.

Каркас «не навредить» после ред. 2 — ровно два предложения, две единицы:
допуск правила по цене отмены (с определением цены и context volume) и «сомнение
— не пиши». «Чтение и самоотчёт не evidence» переехало в evidence-обязанность
своего скила; «каждое сужает поле решений» снято как проза.

## 7. Спорные развилки — предложения агента, не решения владельца

1. **`wording.md` отдан `1instruction-placement`**, не `1instruction-refactor`.
   Довод: placement — единственный из пяти, чей выход буквально одна новая
   строка. Falsifier: если в живых запусках `1instruction-refactor` открывает
   `wording.md` чаще, владельца надо поменять.
2. **База `audit.md` / `check.md` — у `1instruction-refactor`**; скиловая дельта
   аудита — у `1skill-authoring`, дельта проверки — у `1skill-refactor`. Цена:
   `1instruction-placement` и `1skill-routing` за независимым окном ходят к
   соседу.
3. **`canon.md` — новый файл** (ред. 2). Прежде блок жил в теле пары. Довод
   аудита: список имён без инвариантов в теле `1instruction-refactor` нарушал
   собственный запрет семьи на голые ярлыки. Теперь имена и формула применения
   в одном файле, а в телах — только обязанность цитировать.
4. **Три строки про имя скила в `description.md` — agent addition.** В исходной
   паре про имя не было ни строки, но разрез владельца отдаёт имя
   `1skill-routing`, и его `description` его называет. Кандидат на проверку
   владельцем.
5. **Отклонение от пакета аудита:** правило деления тело/`references/`
   возвращено в `1skill-refactor` как измерение вердикта (см. §3a).
6. **Раздел «Известные сбои» распущен.** Его роль заняли триггеры пяти и
   `failures.md`. Если владелец считает таблицу-роутер самостоятельной
   ценностью, её место — тело `1skill-refactor`.
