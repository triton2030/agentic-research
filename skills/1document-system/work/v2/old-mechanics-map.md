# Карта механики старого пакета — 1document-system v1

Разбор до сути, сделанный основным агентом по `refactor.md` «После нового
намерения» §1. Исполнителю с чистым окном этот файл **не передаётся**: он
существует, чтобы на стадии проверки потерь сверить новый пакет с тем, что
старый действительно делал.

Отпечаток разобранного пакета — `old-package-fingerprint.txt`, manifest
`5266326f…`. 68 механизмов.

## Тело — `SKILL.md`

| № | Механизм |
| --- | --- |
| 1 | Аксиома прайора: имя типа = включённый профессиональный стереотип + жанровый запрет; писать только отклонения |
| 2 | Цель: типизированный корпус, один владелец на изменяемый ответ, маршрут «намерение → зона → файл» по имени и описанию |
| 3 | Критерии успеха: один семантический владелец · жанровый бан пройден · нет пустой структуры · чистая сессия находит владельца без лишних файлов · корпус и слой управления не растут |
| 4 | Живой локальный контракт побеждает целиком; скил — fallback, не enforcement. **Отменён владельцем 2026-08-31** |
| 5 | Семья артефактов чужого скила — тоже живой контракт: не переклассифицировать, маршрутизировать владельцу; принципы стоят выше канона |
| 6 | Порядок проектирования: claims → owner → typed carrier → derived views → control. Старт с каталога размазывает одну идею по всем жанрам |
| 7 | Инверсия шаблона: пустой слот не материализуется — ни заголовка, ни плейсхолдера, ни «не применимо»; статус-маркер только для реального вопроса без ответа; покрытие проверяется в голове |
| 8 | Текущая правда · история решений · производный вид · ops-состояние · evidence остаются различимы; продвижение вида во вторую правду — центральный провал системы |
| 9 | Допуск нового типа атомарен: запись реестра + первый содержательный артефакт одним изменением; нужен независимый шов (владелец, lifecycle, читатель, валидация), scope швом не является |
| 10 | Структурное правило без исполняемого гейта дрейфует: проза держит стиль, скрипты держат структуру |
| 11 | Слой управления платит тот же бюджет правил, что корпус; каждое добавление называет, что вытесняет |
| 12 | Дельта модели: не держит один ответ в одном доме · не сопротивляется заполнению слотов · не замечает дрейф жанра внутри файла · не видит стоимость на уровне корпуса |
| 13 | Восемь маршрутов `known failures` → нужный reference-файл |
| 14 | Mode gate: смена владельца/типа/топологии → system; один артефакт или проекция → direct; известный владелец + локальный контракт → молчать |
| 15 | Local first: локальный реестр читается до любого дефолта, его словарь — рабочий |
| 16 | Жёсткий переход: рефактор живого корпуса останавливается на карте владельцев; переписывание, перенос и удаление — отдельная принятая задача |
| 17 | Жёсткий переход: ни папки, ни шаблона, ни записи реестра до первого содержательного артефакта |
| 18 | Completion: артефакт или карта + жанровый бан + список сознательно не написанного + затронутые владельцы; выросший результат называет вытесненное |

## Безопасность сжатия — `references/compaction-safety.md`

| № | Механизм |
| --- | --- |
| 56 | Дефолтный провал — не «сжали мало», а молчаливая потеря: текст удалён как «выводимый у владельца», у владельца его нет, ссылка резолвится, линтеры зелёные |
| 57 | Entry gate: до первого реза каждая цель получает строку `baseline path#locator · снимаемое обязательство · финальный владелец path#locator · локальная дельта · защищённые ID и потребители`; нет финального владельца — это не дедупликация |
| 58 | Дом до реза, владеющая сторона заморожена на всю кампанию и не входит ни в одну волну как цель сжатия; финальный проход проверяет инвариант, а не ищет дыры |
| 59 | Coverage test: удалять можно, только когда владелец семантически покрывает всё снимаемое обязательство — scope, актёры, модальность, условия, время, дефолты, исключения; частичное покрытие оставляет непокрытую часть локальной дельтой; взаимные ссылки владельцев — круг, не вывод |
| 60 | Что дублем не является: локаторы и ID · неактивные контракты (`deferred`/`planned`) · локальная координационная дельта · обязательства формы данных (дефолт, кардинальность, обязательность, взаимоисключение, момент фиксации) |
| 61 | Loss ledger: режет один, проверяет другой; ledger возвращает адресуемые baseline-утверждения, которых нет ни в новой версии, ни у владельца; исходы `restored` / `covered-at-owner` / `retained-local-delta` / `owner-unresolved`; непустой ledger без исходов блокирует следующую волну и закрытие |
| 62 | Проверки, которые ничего не доказывают: зелёный link-checker · совпавшие заголовки и frontmatter · целые счётчики полей и строк · grep вместо `md impact` |
| 63 | Форма после реза: колонка из прочерков — форма без содержания; пустой заголовок заполняется или входящие указатели перенаправляются; необъяснённый разрыв нумерации читается как потеря и обычно ею является |
| 64 | Калибровка: цель — ноль молчаливых потерь, а не максимум процентов; систематические возвраты проверяющего означают, что корпус держит больше собственной правды, чем кажется |

## Делегирование — `references/delegation.md`

| № | Механизм |
| --- | --- |
| 65 | Fan-out gate: делегировать только при независимых потоках evidence или непересекающихся срезах корпуса и только когда веер снижает контекст корня или задержку; число выходов гейтом не является |
| 66 | Staged DAG: корень фиксирует рамку → первая волна собирает инвентарные шарды → корень строит карту типов и выборочно проверяет адреса → IA-ревьюер судит уже предложенную форму → корень выбирает шаблоны и синтезирует → аудит метадаты по уже созданному. Выбор шаблона, разрешение конфликтов и финальная сборка не делегируются; инвентарный воркер не становится ревьюером |
| 67 | Контракты возврата пяти воркеров: inventory · future scenarios · IA review · metadata audit · compaction verifier |
| 68 | Воркерам — точные пути и минимальный локальный контекст; корень ждёт обязательные шарды, признаёт непокрытый scope и не маскирует конфликт голосованием |
