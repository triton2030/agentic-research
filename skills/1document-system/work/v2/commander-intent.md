## Функция скила (FAST)

| Уровень | Функция |
| --- | --- |
| Зачем всё | Корпус не разрастается; следующий агент находит и правит правду по имени файла |
| **Базовая функция** | **Дать документу имя типа как адрес и удержать его в стартап-объёме** |
| Как именно | Выбрать тип · запретить чужой жанр · один дом на ответ · метадата как поверхность поиска · отделить производный вид · не потерять ответ при сжатии |

Прайор типа состоит из двух частей, и они тянут в разные стороны. Имя и
разделы — механизм: агент знает, что где лежит, до открытия файла.
Корпоративный объём — цена: он и есть причина раздувания, ради которой владелец
заказал этот рефактор. Новый пакет оставляет первую часть и меняет вторую.

## Момент вызова

Любое письмо документа: скил включается каждый раз, когда агент собирается
писать или существенно править документ проекта. Прежний узкий момент — смена
владельца правды, типа или топологии корпуса — отменён владельцем 2026-08-31.

Предмет — **один документ**. Разгребание готового корпуса из скила уходит
целиком: владелец подтвердил это 2026-08-31 после смыслового черновика
(`_ops/chat-recall/2026-08-31-223050-claude-9ee6a678.md#L20`).

## Уникальный контекст

**Русский (для утверждения владельцем).**

Агенты думают стереотипами: по одному имени документа модель уже знает, что где
лежит и как это писать, а разделы приводят её сразу к нужному месту. Но тот же
корпоративный стереотип тянет за собой корпоративный объём, и документы начали
раздуваться. Без имени типа агент пишет прозу и свои мнения, превращает
спецификацию в летопись. Имя типа видно до открытия файла: агент заранее знает,
в каком разделе что искать.

**English (as it goes into the package).**

Agents think in stereotypes: from a document's name alone the model already
knows what lives where and how to write it, and the sections take it straight to
the right place. But the same corporate stereotype carries corporate volume, and
the documents have started to bloat. Without a type name the agent writes prose
and its own opinions, and turns a specification into a chronicle. The type name
is visible before the file is opened: the agent knows in advance which section
to look in.

## Цели владельца

**Русский.**

1. Документ выходит в стартап-стиле: написано только то, без чего нельзя
   действовать или найти ответ; полный набор разделов, заполненный ради
   покрытия, успехом не считается.
2. У каждого изменяемого ответа одно место, и по имени типа и его разделам
   агент находит это место, не открывая лишних файлов.
3. Документ не выходит за свой жанр — ни мнений, ни летописи в спецификации;
   корпус, выросший без вытесненного текста, успехом не считается.

**English.**

1. A document ships in startup style — only what is needed to act or to find the
   answer is written; a full set of sections filled for coverage is not success.
2. Every mutable answer has one place, and from the type name and its sections
   the agent finds that place without opening extra files.
3. A document never leaves its genre — no opinions, no chronicle in a
   specification; a corpus that grew without displacing text is not success.

## Способы, сохранённые отдельными решениями

Поднимать их до целей нельзя: владелец настаивает на них именно как на способах.

- **Пакет пишется по-английски.** «этот скилл помогает писать текста на
  английском… все эти термины типовых корпоративных документов, они все на
  английском языке» — 2026-08-09,
  `_ops/chat-recall/2026-08-09-175000-claude-337dc5a6.md`.
- **Жанр судит скил, имена уступают проекту.** Жанровые запреты (мнения,
  летопись, разрастание, пустая структура) действуют всегда; имена типов,
  разделы и метадату живой локальный реестр проекта побеждает. Отменяет прежний
  полный fallback — 2026-08-31,
  `_ops/chat-recall/2026-08-31-223050-claude-9ee6a678.md#L18`.
- **Списка типов в скиле нет — есть методика выбора.** «не называть прям
  буквальные документы а дать имя методики выбора нужной документации для
  стртапа и в каждом проекте выбирается релевантные, чем фиксировать список» —
  2026-08-31, `#L19`. Отменяет каталог 15 типов старого пакета и запрещает
  заменять его новым перечнем. Стандартность термина при этом обязательна:
  прайор включается только у настоящего делового имени, иначе механизм не
  работает вовсе.
- **Вытеснение не имеет границы по авторству.** «Ну переписывает да» —
  2026-08-31, `#L20`. Устаревший текст переписывается независимо от того, кто
  его написал; историю держит git.

## Проверка мысленным удалением

Пройдена: с одними контекстом и целями компетентный агент назовёт файл типом,
напишет минимум и положит ответ в одно место.

| Элемент контекста | Что ломается при удалении |
| --- | --- |
| Стереотип по имени | Исчезает механизм: незачем типизировать файл |
| Корпоративный объём как источник раздувания | Агент выдаёт полный корпоративный шаблон — ровно то, что делал старый пакет |
| Проза, мнения, летопись | Жанровая цель теряет причину: агент не узнаёт провал |

## Открытый вопрос, в пакет не вносится

Раздел `refactor.md` «После нового намерения» требует передать этот intent
исполнителю с чистым окном (clean-room). В текущей сессии агент не имеет права
поднимать субагентов без прямой просьбы владельца, поэтому гарантия clean-room
зависит от его ответа.
