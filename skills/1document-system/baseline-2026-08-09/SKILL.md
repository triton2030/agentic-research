# Documentation System

## Result

Return either the smallest documentation topology that lets the next bounded
work find and change material truth without guessing its owner, or one cohesive
typed artifact/projection under a confirmed local contract. Familiar document
types remain semantic compression and routing aids; they do not authorize
duplicate truth, mandatory ceremony, or speculative completeness.

## Mode Gate

- Owner, boundary, admitted type or topology changes → read
  [System Mode](references/system-mode.md).
- One typed artifact or source-bound projection must be assembled or rebuilt,
  and its zone/owner can be determined → read
  [Direct Mode](references/direct-mode.md).
- Owner, type and local section contract are already known and the task is
  ordinary prose inside them → this skill does not activate; follow the local
  authoring contract.

## Central Model

Design in this order:

```text
material claims and questions
→ co-change and co-validation owner
→ familiar typed carrier
→ derived reader views
→ operational control and evidence
```

Do not start from a catalog of documents and distribute one idea across every
genre that can mention it.

## Semantic Ownership and Placement

- Give every mutable answer one semantic owner: the artifact whose primary
  information job owns its future change and validation.
- Split an idea into atomic claims before routing it. Decision rationale,
  current rule, entity meaning, lifecycle, product requirement, and
  implementation mechanics may have different owners; no owner receives the
  whole discussion by default.
- A consumer keeps an exact pointer plus only its non-deducible local
  consequence. Move text to the owner only when the owner already semantically
  covers that answer and the consumer merely repeats it. If an owner change
  invalidates a genuine local application, keep the application at the consumer
  and record the required dependency/review edge.
- Keep current truth, decision history, derived projection, operational state,
  and evidence distinguishable. A useful view or index never becomes a second
  truth owner.
- A BDR is self-contained append-only decision history, never a current owner or
  graph hub: no Markdown/wikilinks or graph dependencies; relate records and
  owners only by plain stable IDs.
- Prefer the nearest existing project owner and contract. Create a new routing
  map only when no current owner can answer the recurring retrieval question.

## Familiar Type Patterns

Use a familiar type name only to activate a professional prior and cognitive
checklist. The project may admit a subset, local aliases or different types.
When no local registry exists, select from the conditional catalog below; never
materialize the full catalog, empty folders or templates in advance.

## Type Admission and Split Test

Admit or split a type only when it owns a recurring mutable answer and has a
materially independent seam: owner, lifecycle or cadence, primary reader, or
validation contract. Scope or familiarity alone is not enough.

Keep related rules, concepts, and lifecycle facts together when they change and
validate together. Preserve a separate decision record when the historical
choice and rationale have an independent append-only lifecycle. Use derived
projections for reader-specific explanations rather than duplicating current
truth.

## Shape Without Ceremony

- Treat the type pattern as a cognitive checklist, not a mandatory table of
  contents. Check every relevant question internally; emit only material
  answers.
- Give an admitted type two to four minimal core information jobs where
  possible. Add conditional modules only when real content exists.
- Omit empty optional fields and sections physically; do not emit structure
  only to demonstrate coverage. A live local section contract may instead
  require a heading, closure marker or bounded status enum, and wins completely.
- Prefer atomic statements, IDs, mappings, and decision tables when they reduce
  ambiguity. Do not use tables as questionnaires.
- Use prose only for causal argument, material rationale, ambiguity, or an
  accepted trade-off. Professional tone does not justify administrative filler.
- Record an unresolved item only when it can change the current mechanism,
  next handoff, material promise, accepted risk, or one-way door; give it an
  owner and trigger.

## Retrieval, Identity, and Validation

Keep these contracts distinct:

1. semantic claim and owner identity;
2. section or schema classification;
3. resolvable retrieval address;
4. validator or conformance key;
5. generated navigation index.

Do not treat a heading label, opaque checker marker, version string, hash, or
generated row as all five. A generated index contains addresses and authority
metadata only; it does not explain or own truth.

When measured growth or default-reading cost is material, the system result is
incomplete until a project-local owner defines an executable guard. The project
owns scope, metric and units, baselines, ceilings, overrides, link policy, and
exit behavior. This skill does not invent universal numeric budgets or claim
that prose is enforcement.

## Refactor Safety

For a live corpus, return a target owner map before rewrite. For every moved or
removed claim, identify its current occurrence, final owner and resolvable
destination, retained local consequence, and protected conditions, defaults,
exceptions, triggers, evidence, and stable IDs.

An ID inventory proves continuity of named units, not semantic equivalence.
Independent before/after review and a real change cycle must be able to reveal
lost meaning or unchanged maintenance cost. Do not preserve unsupported future
speculation in a provenance sidecar merely to avoid deletion.

## Conditional References

- Type selection without a local registry → [catalog](references/catalog.md),
  then one `references/template-<code>.md`; local type contract wins.
- Metadata/section closure → [metadata](references/metadata-contract.md); the
  complete live local contract wins.
- Reader view → [projections](references/projections.md); zones/default homes →
  [topology](references/topology-contract.md).
- Accepted cutover → [compaction safety](references/compaction-safety.md);
  already-sharded large corpus → [delegation](references/delegation.md).

## Evidence and Stop

The design is sufficient when:

- each material answer has one owner or an explicit unresolved ownership gap;
- every admitted type has a distinct information job and justified seam;
- cognitive coverage does not force empty emitted structure;
- projections, indexes, operations, and evidence cannot override current truth;
- retrieval addresses resolve independently of schema classification;
- every claimed hard constraint has a named project-local executable owner.

Stop before destructive corpus cutover without its accepted task and compaction
contract, global type promotion, or a validation claim unsupported by executed
evidence.
