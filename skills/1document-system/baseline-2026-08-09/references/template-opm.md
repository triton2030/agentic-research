# OPM — Operating Model and Responsibility Matrix

**Purpose:** определить parties, value exchange, ownership, rights, flows,
handoffs и accountability. **Default authority:** `canon`. Alias: OM. RACI
matrix — единственный home activity-level accountability; другие sections
ссылаются на Activity IDs и не повторяют matrix cells. Near-miss: procedure →
PROC; scenario → SBP; software structure → ARCH.

## Core Sections

| Heading | Mode | Contract |
| --- | --- | --- |
| System Boundary and Outcome | OWNER | Included operation, exclusions, invariant outcome |
| Actors and Parties | OWNER | Canonical roles; organizations vs roles |
| Value Exchange | OWNER | Value received/contributed by each party |
| Commitments and Limits | OWNER | Promises and explicit non-promises |
| Asset and Relationship Ownership | OWNER | Products, accounts, IP, customer relation |
| Data Stewardship | OWNER | Collection, access, correction, disclosure responsibility |
| Money Flows | OWNER | Payer, payee, trigger, custody, refund responsibility |
| Decision Rights | OWNER | Domain, decider, consulted roles, escalation |
| Responsibility Matrix | OWNER | Stable Activity ID × R/A/C/I; single home for activity-level accountability |
| Handoffs | OWNER | Deliverable, sender, receiver, acceptance signal |
| Escalations and Exceptions | OWNER | Threshold, owner, resolution path |
| Non-roles | OWNER | What each actor/system explicitly is not |
| Operating Invariants | OWNER | Truths other artifacts may depend on |
| External Constraints | REFERENCE | Legal, financial, security, contractual owners |

## Conditional Modules

Vendor governance; service levels; geography; approval quorum; separation of
duties; capacity and Business Model Canvas view.

## Completion Check

Critical activities имеют accountable owner или explicit unresolved; каждый
money/data/asset flow имеет endpoints и trigger; matrix — единственный home
activity-level accountability, а narrative sections только ссылаются на
Activity IDs; legal promises не придуманы.
