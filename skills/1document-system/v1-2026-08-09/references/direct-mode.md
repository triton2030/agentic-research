# Direct Mode

Result: one cohesive typed artifact (authority `canon | decision | ops |
evidence`) or one source-bound projection — never an auto-decomposed package
of documents.

## Course

1. Classify: typed artifact or projection. A reader view is never promoted to
   a standard type.
2. Typed artifact → select via [catalog](catalog.md), read
   [metadata-contract](metadata-contract.md) and exactly one template. On
   material mismatch propose the better type aloud — never substitute
   silently. Live local type, section and metadata contracts win wholesale.
3. Projection → [projections](projections.md): fix reader, canon lineage and
   output format; hand format execution to the fitting skill or tool.
4. Ask only what changes type, authority, scope or a key decision. A real
   question without an answer gets
   `SECTION-STATUS: unresolved | not-evidenced — reason`; everything else
   follows template inversion — not materialized.
5. Filename: `<CODE> — <Standard English Type> — <scope>.md`; code from
   catalog or local registry, scope and body in the project language.
6. Write decision-dense: exact mappings in lists and tables, IDs for every
   decision, prose only for rationale, ambiguity and argument. State each
   decision once in its home section; other sections cite its ID.
7. Register the artifact in the local docs map if one exists; do not create a
   control layer for one clear file.

## Coverage before compression

Run the type's sections as an internal checklist against the evidence before
final writing — in the head, not as emitted headings. Fallback ownership modes
when no local contract exists:

- `OWNER` — the full mutable answer lives here;
- `REFERENCE` — owner pointer + minimal context, no spec copies;
- `LOCAL` — owner pointer + this artifact's own application/delta.

A large source draft is covered progressively: heading map → bounded extracts
→ source coverage ledger → artifact; an unread remainder blocks any
decision-complete claim.

If one logical unit exists as prose, table and machine spec, choose one
normative representation and the direction `normative → derived`; manual sync
of two editable forms is not validation.

## Lifecycle

`draft` while proposal or owner unresolved; `active` when the request installs
a current owner and the uniqueness gate passed. `approved` is the user's
personal mark: any semantic edit resets it; it changes neither authority nor
retrieval.

## Closeout

One type and scope · correct authority and home · no invented claims or
duplicate owner · every included section closed by its mode · retrieval label
satisfies the metadata contract. Two cheap recheck signals (signals, not
stops): a section retells another owner's decisions; the artifact clearly
exceeds its type's usual size.
