# SBP — Service Blueprint

**Purpose:** show one end-to-end service scenario across actor actions,
frontstage, backstage, support and recovery. **Default authority:** `canon`.
Near-miss: customer-emotion view → projection; one operation → PROC; screen flow
→ PRD UX module; global responsibilities → OPM.

**Ban:** SBP owns one scenario across its lanes, not global responsibilities,
not procedure steps, not screen design.

**Non-obvious contracts:** Support Systems and Processes, Data and Produced
Artifacts, Money and State Events, Responsibility Handoffs = LOCAL: owner links
→ phase-specific mapping only. Post-service Boundary is owned: what continues
elsewhere.

**Conditional modules:** timing/SLA lane; physical evidence; channel variants;
customer emotions; capacity constraints; regulatory checkpoints.

**Completion check:** happy path and material failures both end in an explicit
outcome or escalation.
