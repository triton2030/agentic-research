## Намерение

Задача: сохранить значимые слова владельца и вернуть применимые слова в контекст текущего решения.
Цель: свежий агент располагает применимыми словами либо точной причиной неприменимости; новые важные реплики доступны следующему окну локальными адресуемыми записями с исходными авторством, условиями и силой; неизвестность и противоречия видимы.
Зачем: будущий агент не имеет разговора; метаданные помогают найти слова, но не являются позицией; ошибочное применение хуже честного пробела.

## Типы целей и отрицание

| Листовое состояние | KAOS | Отрицание / ложная победа | Evidence и читатель |
| --- | --- | --- | --- |
| Новая значимая речь сохранена в текущем ходе | Achieve | потеря реплики за бесконечным поиском отмены | квитанция/адрес либо явный сбой; владелец и следующий агент |
| Авторство, условия и сила неизменны | Maintain/Avoid | паста стала цитатой, идея решением, ситуативное общим | исходная реплика и запись; проверяющий |
| Запись находится из другого окна | Achieve | голая цитата без именованных референтов; потеря старых тем карточки | metadata и запись; следующий агент |
| Применённое evidence относится к claim | Maintain | совпадение слов заменило scope/chronology/commitment | цитаты, даты, адреса live owner; владелец |
| Причина неприменимости видна | Maintain | конфликт/ошибка/усечённый поиск стали «слов нет» | bounded result и отдельные conflict/gap адреса; агент |
| Repair не становится авторством | Maintain/Avoid | изменение незаказанных записей, переписанный источник | before/after + source + validation; владелец |

Пустого результата отрицания нет: каждому режиму нужны критерии против названных лазеек.

## Невыводимые интерфейсы и порядок

- Существующие helper-ы, corpus path, runtime запуск и --help: API невозможно вывести из цели; проверяется реальным CLI.
- Полная карта тем и текущий holder перед обновлением карточки: словарь принадлежит корпусу, карточка целому разговору; проверяется выбранной темой/сохранением прежних предметов.
- Дословный owner-порядок «Сначала найти старую цитату, затем сохранить новую» + отдельное уточнение о ненайденной старой записи: защищает от ложного none и потери новой речи. Результат — anchor либо unresolved metadata.
- Capture одной операцией с receipt: существующий transaction owner, не ручная запись; проверяется CLI и rollback tests.
- Дешёвый фоновый исполнитель на важный claim: локальный runtime seam сохраняется, дорогое замещение не вводится.
- Repair source → backup → mutation → validation: порядок защищает исходник и до/после.

## Карта смыслов

Сохранены: три режима в одном пакете; same-turn capture; deletion-only и selection; type/topic/context-note/session-context; локальность; обычный поиск только corpus; named-session explicit transcript repair; dated evidence и scope; живой owner; legacy tolerance; one cheap background helper; no profile/summary layer; atomic receipt.
Поглощены целями/критериями: перечисление когнитивных шагов отделения речи, классификации, выбора применимости и прекращения поиска. Обязательства не сняты, их результат назван в точке приёмки.
Исправлены: исполнение Capture до определения отмены; ложное описание query фильтра; пустая первая карта; скрытые конфликты; неразличение силы и сбоя поиска; отсутствие исхода при ненайденной отменяемой цитате.
Снято как ложное утверждение: «справка ... разойтись с поведением не может» — docstring и argparse help тоже могут устареть. --help остаётся единственным интерфейсным справочником, расхождение с наблюдаемым поведением — дефект, не основание для самоубеждения.
Не добавлены: новый memory backend, автоматическая ретроразметка/repair, постоянный профиль владельца, ссылки на транскрипт в корпусе, новые зависимости.
