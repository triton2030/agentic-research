# Ремонт 1chat-recall — 22 сентября 2026

Владелец принёс шесть наблюдений другой сессии и поручил их исправить, затем уточнил: «Видимо `1chat-recall` надо отремотировать». Отчёт другого агента — свидетельство сбоя, не слова владельца о продуктовой модели.

Цель: следующая сессия получает именно сохранённую реплику с её вопросом и областью действия. Рост файла и второй ответ «да» не должны незаметно менять источник решения.

Изменение ограничено идентичностью записей, повторной записью одного исходного ответа, безопасностью совместной записи и восстановлением адресов. Прямое чтение цитат, различение quote/selection, датированный контекст, поиск позднейших слов, карта тем, границы repair и различия runtime сохраняются. Перенос продуктовых черновиков MAVO в канон не входит в ремонт.

Выбран устойчивый заголовок рядом с цитатой: обычная Markdown-ссылка остаётся читаемой без отдельной базы адресов. Номер строки оставлен подсказкой для текущего просмотра. Текст цитаты не определяет личность ответа: source-ref относится к конкретному ответу, включая часть сообщения. Общая файловая блокировка сериализует сотрудничающие помощники; ручное редактирование и старые writers её обходят.

## Сохранность

| Прежнее свойство | Изменение и основание | Проверка |
| --- | --- | --- |
| Дословная цитата и контекст | Сохранены; новый heading перед записью | identity tests, сравнение bytes |
| Capture/Retrieval/Integrity | Все три входа сохранены | полный набор тестов обоих runtime |

Исходные пакеты находятся в `before/codex` и `before/claude`. Красные регрессии — `red-runtime.log`; результаты runtime — `green-*.log` и `identity-*.log`. Проверки не доказывают надёжность ручных редакторов, полную исправность старого корпуса или качество всех будущих агентных решений.
