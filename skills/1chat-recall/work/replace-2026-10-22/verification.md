## Пробы

Два свежих агента, по одному прогону: [результат](probe-result.md).
Случай «забрал на ходу» — перезапись; случай «передумал после работы с причиной» —
новая запись со ссылкой.

## Тройка проверяющих

Одна волна: смысл разделов, необходимость требований, маршруты и evidence.

| Находка | Решение |
| --- | --- |
| Рамка передаёт только ветку перезаписи; тайбрейкер 6 сужен | Принято: абзац рамки называет условия и ветку указателя, тайбрейкер 6 возвращён |
| Связи прежней версии теряются молча | Принято: фраза в capture.md и `dropped_relations` в квитанции |
| Время версии из нескольких реплик не названо | Принято: время реплики, решившей итог |
| Удаление своей записи выводилось из контраста в SKILL.md | Принято: удаление без новой версии — только по слову владельца |
| «Прежние записи не перекладываются» спорит с перезаписью | Принято: «ради связи» |
| Перезапись записи, на которую уже ссылаются, меняет смысл ссылки (проба проверяющего: `supersedes-not-newer`) | Принято: helper отказывает; фраза в capture.md |
| Красные линии `_ops` без условия | Принято: «по правилу Capture» |
| Ошибка неизвестного id уводила к repair | Принято: «copy the anchor from its capture receipt» |
| Запись правила отменяет запись 2026-08-10 целиком | Отклонено: оставшийся в силе пункт держит неотменённая запись 2026-08-29 `:31`; остаток назван в `cut.md` |

Вторая волна не запускалась: правки прямые, helper-часть покрыта тестами
(Claude 59, Codex 59). Граница: пробы шли по промпту «обработай последние
реплики по скилу» — заметит ли агент без этой подсказки, что реплика меняет
запись, не проверено; Codex-рантайм поведенчески не пробовался.
