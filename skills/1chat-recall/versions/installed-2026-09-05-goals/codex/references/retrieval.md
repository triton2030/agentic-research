# Retrieval

## Задача

Верни применимые слова владельца для текущего решения либо причину, почему
опереться на найденное нельзя.

## Цель

Решение опирается на адресуемую речь владельца в её исходных условиях и с её
действительной силой: идея остаётся возможностью, предпочтение — ориентиром,
принятое решение — решением в своём scope.
Противоречие, недостаточность evidence и незавершённый поиск различимы, а
независимая от них работа продолжается.

## Зачем

Ранг показывает сходство, а не применимость. Обычный query исключает из
кандидатов на применение `note`, `raw`, явно отменённые и спорные записи;
релевантные конфликты и неустановленные отмены возвращаются отдельно.
Непомеченная отмена ещё может быть в корпусе, а более поздняя дата сама по себе
не отменяет совместимую мысль и не переносит её на другой предмет.

## Критерии принятия

- Применённая позиция имеет прочитанную цитату, scope, тип высказывания,
  абсолютную дату, возраст в часах или днях и адрес. Карточка, поисковый балл
  и вывод субагента — указатели: подмена ими цитаты делает вывод непроверяемым.
- Применению не противоречат более поздние слова в том же scope, явные связи
  отмены и относящиеся к предмету действующие документы. Неразрешённое
  расхождение предъявлено адресами обеих сторон; молчаливый выбор прячет риск
  от владельца. Если в проекте есть `_ops/findings/`, расхождение с живым
  владельцем правды оставлено там для следующей сессии.
- При неразрешённом конфликте вопрос владельцу задан, а зависимое решение
  остаётся открытым. Его ответ не подменён собственной трактовкой;
  независимая работа продолжается, потому что спор не делает её невозможной.
- Выход различает состояния ниже и называет существенные ограничения поиска.
  Пустая или усечённая выдача не доказывает, что владелец ничего не говорил.

| Состояние | Что получает текущая работа |
| --- | --- |
| Применимое evidence | Позиция с указанной силой, датой и адресом |
| Конфликт или неустановленная отмена мешает решению | Обе найденные стороны либо адрес и пробел; вопрос владельцу |
| Подходящие слова не найдены | Проверенный предмет и границы поиска; собственное суждение агента названо своим |
| Поиск недоступен или не завершён | Причина и непроверенное; вывода об отсутствии слов нет |

## Инструмент

[chat_digest.py](../scripts/chat_digest.py) читает только локальный корпус.

```bash
ROOT="${CODEX_HOME:-$HOME/.codex}/skills/1chat-recall"
TARGET_PROJECT_ROOT="${TARGET_PROJECT_ROOT:-$PWD}"
uv run --locked --script "$ROOT/scripts/chat_digest.py" \
  "$TARGET_PROJECT_ROOT/_ops/chat-recall" --query "<предмет решения>" --json
```

Не подготовлен hybrid runtime — отдельный запуск того же helper-а с
`--prepare`, без пути корпуса и retrieval flags. Bootstrap недоступен —
`--lexical` оставляет рабочий поиск с названным ограничением.

`holders` ведут к цитатам, `topic_candidates` — к границам предметов из карты.
Если первый маршрут не дал достаточного evidence, выбранный handle задаёт
`--topic`; `--timeline` без `--query` позволяет прочитать историю этой темы,
включая исключённые из обычного query записи. Полный holder нужен, когда
условия или хронология не восстанавливаются из самой записи.

Остановка определяется решением: evidence достаточно для применения либо
достигнут явный пробел, который дальнейший доступный поиск не закрыл.
`truncated` требует расширения только там, где невидимые записи способны
изменить решение; ни автоматический отказ, ни игнорирование усечения не
свидетельствуют о применимости.

## Независимый поиск

На важный предмет запускается ровно один дешёвый фоновый исполнитель с явно
выбранной самой дешёвой доступной моделью: второе окно ищет независимо, пока
основной агент продолжает собственный поиск. В Codex это `spawn_agent` с
`agent_type: "default"` и `fork_turns: "none"`. Его brief — read-only,
corpus-only поиск с абсолютным путём целевого корпуса, claim и выбранной темой;
возврат — фактически проверенный корпус, address, date, age и gaps. Без пути
чистое окно может молча искать в другом проекте.
Новые адреса проверяются основным агентом перед использованием. При смене
предмета нужен поиск по новому claim; прежний результат его не покрывает.
Недоступность дешёвого исполнителя остаётся gap, без подмены дорогим.
