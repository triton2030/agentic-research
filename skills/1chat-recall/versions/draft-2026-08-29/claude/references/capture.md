# Capture

## Протокол поведения

> «В скиле запоминание цитат, честно говоря, большое внимание надо уделить
> протоколу записи именно тем. То есть вот эта вся логика того, что у нас есть
> файл существующих тем, и прежде чем записывать какую-то цитату, надо этот
> файл существующих тем прочитать. Потому что метаданные каждой цитаты, если
> они будут записаны некачественно, то тогда цитата теряется навсегда. Поэтому
> выбрать правильную тему очень важно.»

> «И еще кое-что я хотел бы исправить, чтобы контекст у каждой цитаты был
> короткий и был более написан, ну, похож был на сборник ключевых слов, чем на
> контекст. Потому что это поможет нашему поиску по ключевым словам, как
> работает у нас сейчас система.»

1. Прочитай holder текущей сессии. Не дублируй тот же тезис; повторный Capture
   допустим только для полной текущей строки `session-context` и может вернуть
   `context-updated`, не переписывая запись.
2. Перед записью любого `quote` или `selection` выбери тему строго в этом
   порядке: полностью прочитай `_ops/chat-recall/topics.md`; назови долговечный
   предмет записи; сравни его по смыслу с каждой существующей границей, а не по
   совпадению слов; переиспользуй ближайшую подходящую тему. Только если не
   подходит ни одна, создай через `--new-topic` короткое латинское имя темы и
   границу в одну строку. Плохая тема делает запись практически ненайденной,
   поэтому inventory-вывод не заменяет чтение карты.

   ```bash
   python3 "${CLAUDE_SKILL_DIR:-$HOME/.claude/skills/1chat-recall}/scripts/chat_capture.py" \
     --list-metadata --project "$PWD"
   ```

3. Для каждого `quote` или `selection` пиши короткий `context-note` как набор
   ключевых именных фраз: отсутствующие именованные референты, непрозрачно
   названный выбранный вариант, устойчивые имена артефактов и полезные поисковые
   синонимы. Не пиши прозу, не повторяй и не пересказывай тезис, не утверждай
   текущую правду и не расширяй scope. Если неповторяющиеся поисковые ключи
   назвать нельзя, вернись к исходному контексту, а не придумывай их.
4. Для каждого `quote` или `selection` пиши одну полную строку
   `session-context`: сохрани прежние крупные задачи, артефакты, операции и
   имена, затем добавь новый предмет и полезные синонимы. Эта строка помогает
   поиску, но не утверждает решений или текущей правды.
5. Используй текущее время с таймзоной только для слов этого хода; для прежних
   слов бери timestamp из native transcript.
6. Прямо несовместимая прежняя позиция в том же scope получает адрес через
   `--supersedes`; если победитель неясен, используй `--contested`;
   совместимая деталь не требует ни одного из этих полей.
7. Выполни одну запись через helper. Добавляй `--kind selection` только для
   выбранного варианта, а остальные необязательные флаги — лишь когда они
   применимы:

    ```bash
    ROOT="${CLAUDE_SKILL_DIR:-$HOME/.claude/skills/1chat-recall}"
    SESSION="${CLAUDE_SESSION_ID:-${CLAUDE_CODE_SESSION_ID:-}}"

    python3 "$ROOT/scripts/chat_capture.py" \
      --quote "<дословные слова владельца>" \
      --context-note "<короткие ключевые референты, имена артефактов, синонимы>" \
      --session-context "<задачи; артефакты; операции; имена и синонимы>" \
      --source-timestamp "$(date -Iseconds)" \
      --type <речевой-акт> --topic <тема> \
      --agent claude --project "$PWD" --session "$SESSION" --json
    ```

8. Проверь JSON-квитанцию и открой возвращённый адрес. Сообщи этот адрес; для
   новой темы — ещё и строку карты; для отмены — прежний адрес; для
   самоисправления — `context-updated`; для пропущенной реплики — причину по
   гейту полезности.
