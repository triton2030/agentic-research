# Repair и pre-capture backfill

## Протокол поведения

> «В скиле запоминание цитат, честно говоря, большое внимание надо уделить
> протоколу записи именно тем. То есть вот эта вся логика того, что у нас есть
> файл существующих тем, и прежде чем записывать какую-то цитату, надо этот
> файл существующих тем прочитать. Потому что метаданные каждой цитаты, если
> они будут записаны некачественно, то тогда цитата теряется навсегда. Поэтому
> выбрать правильную тему очень важно.»

> «И еще кое-что я хотел бы исправить, чтобы контекст у каждой цитаты был
> короткий и был более написан, ну, похож был на сборник ключевых слов, чем на
> контекст. Потому что это поможет нашему поиску по ключевым словам, как
> работает у нас сейчас система.»

1. Допускай только существующую запись с diagnostics или сомнительным
   provenance либо явный запрос владельца восстановить полезные докаптурные
   реплики. Если дубликату текущей сессии не хватает только полного
   `session-context`, заверши Repair квитанцией
   `capture-needed · адрес записи · missing session-context`; любой другой
   диагностированный дефект остаётся в Repair.
2. До чтения назови один проект и одну конкретную сессию либо ограниченный
   набор сессий; не угадывай соседний чат и не импортируй посторонние разговоры.
3. Разрешай evidence в таком порядке: названный native transcript → точный
   уникальный локальный фрагмент → ограниченный локальный semantic/manual поиск
   точной native-записи → явный gap. Semantic similarity, имя файла,
   frontmatter, сырое время или `unknown` сами по себе не разрешают Capture.
4. Читай evidence Claude transcript по явно названной сессии; для чужой сессии
   передай её точный `--session-id`:

   ```bash
   ROOT="${CLAUDE_SKILL_DIR:-$HOME/.claude/skills/1chat-recall}"
   SESSION="<канонический UUID сессии>"

   python3 "$ROOT/scripts/chat_recall.py" --session-id "$SESSION" \
     --all --include-current-turn
   ```

5. Используй один semantic type; только невосстановимая Repair-метадата может
   принять `неопределено` или `без-темы`, а существующие `quote` и `selection`
   нельзя превращать в `note` ради sentinel.
6. Сохраняй исходный timestamp, а не время Repair. Применяй `exact` только после
   сверки native-текста или выбора; иначе используй `minute` либо `date`;
   `unknown` допустим только для `note`. Имя holder-а, frontmatter и заголовок
   следуют самой ранней дате источника с precision `exact|minute`, а precision
   `date` никогда не перемещает holder.
7. Перед записью восстановленного `quote` или `selection` полностью прочитай
   `_ops/chat-recall/topics.md`, назови долговечный предмет записи, сравни по
   смыслу каждую границу темы и переиспользуй ближайшую подходящую. Создавай
   короткую латинскую тему и границу в одну строку, только если не подходит ни
   одна; inventory-вывод не заменяет чтение карты. Используй `неопределено` или
   `без-темы` только когда после этой попытки native evidence не позволяет
   восстановить поле.
8. Дай каждой восстановленной `quote` или `selection` поисковую метадату:
   короткий, непересказывающий `context-note` из ключевых фраз с отсутствующими
   именованными референтами, непрозрачно названным выбранным вариантом,
   устойчивыми именами артефактов и полезными синонимами; плюс полный
   неутверждающий `session-context`. Пиши через `chat_capture.py`; добавляй
   `--kind selection` только для выбранного варианта и остальные необязательные
   флаги лишь когда они применимы:

   ```bash
   ROOT="${CLAUDE_SKILL_DIR:-$HOME/.claude/skills/1chat-recall}"

   python3 "$ROOT/scripts/chat_capture.py" \
     --quote "<исходный текст>" --context-note "<ключевые референты и синонимы>" \
     --session-context "<задачи; артефакты; операции; имена и синонимы>" \
     --source-timestamp "<native timestamp>" --type <type> --topic <topic> \
     --agent claude --project "<корень проекта>" \
     --session "<канонический UUID исходной сессии>" --json
   ```

9. В read-only работе сообщи backlog без mutation. Когда mutation разрешена,
   сначала сохрани checksums и untracked backup исходников вне проверяемого
   корпуса; объединяй дублирующиеся holder-ы только внутри одного проекта и
   одной сессии.
10. Проверь результат явной локальной командой ниже, затем докажи: multisets
    прежнего текста и raw-блоков не уменьшились; новые quotes существуют в
    native sources; timestamps и sessions честны; записи открываются по точному
    адресу; diagnostics остались видимыми либо исправлены; в проекте не больше
    одного holder-а на сессию. Сообщи восстановленный сигнал, точные адреса,
    provenance, chronology, structure proof, неразрешённые diagnostics либо
    точный blocker.

    ```bash
    python3 "${CLAUDE_SKILL_DIR:-$HOME/.claude/skills/1chat-recall}/scripts/chat_digest.py" \
      "<корень проекта>/_ops/chat-recall" --check --strict
    ```
