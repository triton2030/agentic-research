# Работа с T3 не забивает контекст — 2026-11-10

## Граница

Адресная правка `skills/claude/1t3`: контракт отчёта в `references/common.md`
(«When writing the brief») и предел чтения хода треда в
`references/claude-code.md` («While a turn runs»). Заказ владельца: «Гигиена
и отчёт в файл» — выбор из стратегий, предложенных в той же сессии.
Codex-версия (`skills/codex/1t3-codex`) не затронута.

## Замер

Сессия subfrost `8ecb1bb3-60a5-4ba7-8c5a-6bc82f487b8a`: около 100 тредов,
24 сжатия контекста. Результаты вызовов без дублей записей, в знаках:

| Статья T3 | Знаков |
| --- | --- |
| итоговые сообщения через `t3 thread show --messages 1` | ~420 тыс. |
| брифы при запуске | ~260 тыс. |
| `t3_thread_read`: activity с `limit` 25 без `maxCharsPerItem`, в среднем 5,1 тыс., до 27,5 тыс. | ~170 тыс. |
| квитанции, список тредов, каталог моделей | ~170 тыс. вместе |

Всё T3 — около 1,3 млн знаков, примерно 3 тыс. токенов на тред. Сама работа
оркестратора (скриншоты, `Bash`) заняла примерно втрое больше.

## Что снято из предложенного

- Правила для списка тредов, каталога моделей и опроса статуса: по замеру
  их доля мала, а циклы `thread show` уже обрезались через `sed`.
- Статус треда тремя строками даёт `t3 thread show <id> --messages 0`. Это
  видно из `--help`, поэтому в скил не вписано.

## Проба

Sonnet (`high`) получил черновик по пути в `/tmp/skill-probe/t3-report-new`
и всухую готовил поручение аудитору. Он вписал абсолютный путь отчёта
и концовку не длиннее пяти строк, сам разрешил запись только этого файла,
а чтение хода треда планировал с `limit: 5`, `maxCharsPerItem: 300`.

## Проверяющий

Codex gpt-6.1-sol/max, тред `mcp:e9780428-a12a-4f41-b938-3a0fe8c67353`:

- Принято: обязательный файл спорил с «файлы не меняй» для аудитора
  в `1orchestration`. Добавлено: это единственный файл, который пишет
  read-only агент. Контракт сужен до брифа треда: скрипт `gemini.py` писать
  не может.
- Принято: повтор о приёмке по диффу снят. Он живёт в `1orchestration`,
  на который ссылается `claude-code.md`.
- Не принято: дочитывать обрезанную запись. Способ (`itemId`
  с `textOffset`) уже есть в описании инструмента.

## Не проверено

Формулировка о единственном файле и сужение до брифа треда внесены после
пробы. Проба показала то же поведение без них, но повторно не запускалась.
