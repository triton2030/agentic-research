# Ветка «внутри T3», 2026-11-05

Граница: тело `SKILL.md` — только как определить, где работает агент, и какой reference читать; всё остальное ушло в `references/`.

- Причина: Claude, запущенный владельцем из T3, по прежнему телу запустил двух исполнителей Codex через `t3_thread_launch` сервера `t3`; владелец поправил — внутри T3 исполнители идут через `delegate_task` сервера `t3-code` дочерними задачами треда; сервер `t3` — путь из обычного Claude Code. Внутри T3 подключены оба сервера, поэтому признак один: есть ли `mcp__t3-code__*`.
- Владелец: «надо как то сверху в скиле прям написать вилку … тело просто 20 слов максимум и остальное в реф файлах», затем «можно длинее, надо чтобы он понял как понять где он»; одобрил тело с одной проверкой.
- Раскладка: `common.md` — контекст, цель, параметры моделей, бриф, провайдеры, квоты, сбои; `claude-code.md` — прежние разделы запуска, ожидания, хода, завершения и продолжения без изменений; `inside-t3.md` — новое.
- Снято из прежнего контекста: «T3 doesn't wake you when a turn ends …» перенесено в `claude-code.md` — для дочерних задач неверно.
- Проба (Sonnet, песочница `probe.py`): внутри T3 агент сам выбрал `delegate_task`, не тронул `mcp__t3__*`; взял параметры модели наугад, потому что правило Codex лежало только в ветке Claude Code — правило перенесено в `common.md`.
- Проверяющий другой семьи (Codex gpt-6.1-sol) запущен до установки; владелец велел ставить, не дожидаясь. Его находки — отдельной правкой.
