# Сторож постит события в сессию — 2026-11-10

## Граница

Адресная правка `skills/claude/1t3`: `scripts/wake_on_any.sh` и абзац
«When waiting» в `references/claude-code.md`. Заказ владельца: «Да,
переделай» — в ответ на предложение перевести сторож на сообщения в сессию.
Codex-версия (`skills/codex/1t3-codex`) не затронута: у неё нет
`wake_on_any.sh`.

## Что изменено

- Сторож постит каждое событие, кроме последнего, во входящий сокет сессии
  (`$CLAUDE_CODE_MESSAGING_SOCKET`) и следит дальше. Последнее событие, как
  прежде, завершает его.
- Пост засчитывается, только когда его уникальная метка появилась
  в транскрипте сессии записью `queued_command`; окно 180 с. Без
  подтверждения сторож выходит по-старому.
- Тик в режиме поста — сообщение и сброс таймера.

## Источники

- Docs: https://code.claude.com/docs/en/cross-session-messaging.md,
  раздел «The session's inbox socket», прочитано 2026-11-10.
- Формат строки сообщения взят из бинаря Claude Code 2.1.321: в доках только
  строка auth.

## Пробы

- Строка простым текстом: `nc` код 0, сообщение не пришло.
- JSON-строка с токеном: пришла посреди хода.
- Заглушки: без сокета — выход на первом событии; без подтверждения —
  откат к выходу; с подтверждением — выход на последнем; тик постится.
- Живые треды T3 (версия до подтверждения): событие треда A начало новый ход
  в простаивающей сессии; на треде B сторож вышел.
- Запись пишется в файл после текущего вызова инструмента: окно 10 с
  не хватило внутри 30-секундного вызова, отсюда 180 с.
- Вид записи зависит от состояния сессии: посреди хода — вложение
  `queued_command`, в простое — `user` с `origin.kind: "peer"`. Проверка
  только `queued_command` в простое не нашла метку и откатилась через 180 с.
  Итоговый фильтр (peer и метка) подтвердил оба случая: в простое выход
  на 31-й секунде с тредами 5 и 30 с.

## Проверяющие

- Fable 5.2 (medium, по просьбе владельца): главное — `nc` возвращает 0 при
  потерянном сообщении. Принято: подтверждение по транскрипту. Также
  приняты: метка против отбрасывания одинаковых тиков, формулировка после
  автоперезапуска, правки абзаца.
- Codex gpt-6.1-sol/max, тред `mcp:b5062d7f-4218-4fba-8833-927fc4ee6c22`:
  существенных ошибок нет. Принято: подтверждение разбирает JSON через `jq`,
  а не ищет подстроки. Не принято: вернуть выход на каждом событии ради
  независимости от формата транскрипта — владелец выбрал непрерывного
  сторожа, а отказ подтверждения и так возвращает выход.

## Не проверено

- Поведение при `crossSessionInbound: hold` или `refuse`: ожидается откат
  по истечении окна.
- Пост из сторожа, запущенного субагентом: по окружению уйдёт в главную
  сессию.
