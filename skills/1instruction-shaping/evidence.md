# Чем проверен

## Support envelope

Проектировался под `Claude Opus 5` и `GPT-5.6` в Claude Code / Codex,
инструменты чтения-записи файлов. Длинная автономия не предполагается: скил по
конструкции останавливается на владельце перед записью.

## Статус проверок — 2026-08-08

| Что | Как проверено | Статус |
|---|---|---|
| Текст соответствует собственным правилам | аудит по `references/audit.md`, применён к своему черновику | сделано |
| Внешние основания под каждой ключевой строкой | сверка с источниками, перечислены в `origin.md` | сделано |
| Активация: голая фраза поднимает скил | — | **не прогонялось** |
| Негативы near-miss не поднимают скил | — | **не прогонялось** |
| Применение: свод меняет решения агента | — | **не прогонялось** |
| Мера цели: агент доходит до первого верного действия быстрее | — | **не прогонялось, и метрика не определена операционально** |
| Сравнение с прежним `1instruction-layer` | — | **не прогонялось** |

**Поведение не измерено.** Всё сделанное — конструкция, сверка с источниками и
текстовый аудит. По правилу самого скила это означает: не доказано.

## Известные слабые места конструкции

- **Перенос −39% на многофайловый свод — экстраполяция.** Источник мерил
  ограничения внутри одного промпта, не конфликт `CLAUDE.md` против скила.
  Направление правдоподобно, величина не наша.
- **Хуки** — территория без источников; `placement.md` описывает их по
  рассуждению, не по evidence.
- **Вынос знания в `INDEX.md`** — решение владельца. Внешняя опора косвенная.
- **Два жёстких перехода в механике** — рассуждение, не измерение.
- **Мера «ускорение»** не операционализирована: «быстрее до первого верного
  действия» пока не имеет счётчика.

## Ближайшая проверка

Взять один реальный репозиторий без свода, собрать его этим скилом и без него,
и сравнить на трёх задачах число ходов до первого верного действия и число
неверных ходов.
