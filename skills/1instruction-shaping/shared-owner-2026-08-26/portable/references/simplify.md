# Смысловое упрощение

Упрощение имеет две независимые оси:

- semantic load — обязанности и конфликты;
- context cost — объём и частота загружаемого текста.

Короткий текст с теми же обязанностями не стал семантически проще, но может
стать дешевле для context. Ориентировка и факты не являются обязанностями, но
тоже занимают context.

## Операторы

1. **Удалить выводимое.** Модель надёжно делает это без строки — снять; claim
   привязать к target model.
2. **Поглотить частное общим.** Общая цель или принцип законны, только если из
   них выводится каждый снятый смысл.
3. **Сохранить Delta.** Число, authority, local exception, decision rule и
   anti-pattern остаются явными, если меняют решение.
4. **Результат вместо пути.** Шаги заменяются конечным состоянием, только если
   не несут execution-critical параметры, recovery, safety, reproducibility,
   редкое локальное знание или обязательную проверку.
5. **Имя вместо изложения.** Канонический метод сжимается так:

   trigger → точное имя → ключевые инварианты или decision rules → evidence → stop

   Голый ярлык неоднозначен. При local deviation или обязательном порядке
   оставь минимальный SOP либо условие чтения SOP.
6. **Доставить позже.** Редкая деталь уходит в reference, folder или tool
   interface к моменту решения; перенос не снимает её цену в тот момент.

Не используй универсальные пороги строк, токенов, обязанностей или числа skills:
их нет для всего текущего model set. Если сжатие заявляет сохранение behavior,
проверь old/new на одном resolved model и задаче.

Выход: число снятых обязанностей · удалённый resident context · сохранённые
невыводимые смыслы · непроверенные потери.
