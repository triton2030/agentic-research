# 1-max-review

## Контекст

Обычный агент вызывает нескольких проверяющих и незаметно даёт каждому
большую работу. Короткое поручение этого не исправляет: для ответа всё ещё
приходится читать много файлов и удерживать множество условий. У прозы
потеря одного условия может менять смысл, не вызывая ошибки инструмента.

Нужная поправка — много простых проверок. Прежняя попытка формализовать их
породила отдельную работу с пакетами, схемами и адресами; полезные замечания
терялись среди ошибок этого учёта.

У маленького проверяющего меньше контекста, поэтому его находка может быть
ошибочной. Её польза — повод главному агенту заново посмотреть на упущенное
место, в том числе обнаружить другую ошибку при проверке самой находки.

## Задача

Раздели выбранную область на много маленьких проверок по вопросу пользователя.
Для проверки инструкций охвати все применимые правила; вопрос о бизнес-пользе
задаёт свою точку зрения. Отдельный координатор читает источники, распределяет
задания без отдельного каталога требований, запускает проверяющих через
терминал и собирает короткие ответы для вызвавшего скилл главного агента.
Не исключай правило только потому, что оно кажется уже выполненным.

## Цель

Каждому проверяющему легко удержать небольшую задачу с достаточным для неё
материалом. Главный агент получает поводы заметить упущенное и сам проверяет
находки. Безошибочность малых агентов не является условием пользы.

## Запуск

Листовые агенты в обеих средах — **Luna `gpt-6-luna`, effort `max`** через
общий CLI `max-review`. Модель закреплена в оболочке; молчаливой замены нет.
[Команды](references/cli.md) запускают обычные задания и сохраняют ответы.
Схема JSON для ответа и отдельная подготовка пакетов не нужны.

Передай одному свежему координатору область, существенные решения пользователя,
режим и адрес скилла. `audit` только проверяет; в `repair` главный агент
исправляет подтверждённое им в пределах поручения. Для неоднозначной «базы»
установи предмет: документы, схема или данные.
[Особенности среды](references/runtime.md) определяют маршрут координатора.

Работа хранится в отдельной `1-max-review-<тема>` внутри принятой папки
оркестрации, иначе — в `.1-max-review/<тема>`. `state.md` сохраняет область,
источники и текущий шаг. Вызывающий ждёт и читает итоговый `summary.md`.

| Момент | Материал |
|---|---|
| Координатор делит работу | [Небольшие задания](references/prepare.md) |
| Leaf получает своё задание | [Короткий ответ](references/reviewer.md), вложенный в поручение |
| Координатор разбирает ответы | [Принятие результата](references/results.md) |
