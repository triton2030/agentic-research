# Product Frame — 1handoff

## Цель

Когда владелец явно вызывает platform handle `$1handoff` или `/1handoff` перед
завершением рабочей repo-сессии — либо агент сам поднимает скил при явно
разросшемся окне, не больше одного хендофа на сессию чата (решение владельца
2026-08-09), — текущий агент одним пользовательским действием закрывает
независимые ветки:

- сохраняет долговременные owner-сигналы через собственный контракт
  `1chat-recall` соответствующего runtime;
- прибирает слой агентного управления — план и статус, находки,
  INDEX-маршруты, устаревшие строки инструкций, git (решение владельца
  2026-08-18);
- создаёт continuation packet с невосстановимой разговорной дельтой и точным
  следующим действием;
- передаёт модель предмета: рабочую модель местности и ловушки, которые эта
  местность порождает у любого, кто её читает (решение владельца 2026-08-23).

Свежая сессия получает явный путь к handoff и live-состояние проекта, но не
старый чат. Продукт принят, если она без пересказа владельца выбирает и начинает
правильное первое действие, видит material veto, не повторяет оплаченный
тупик и не собирает заново уже опровергнутую модель предмета. Evidence —
реальный или чистый consumer-side resume, а не полнота шаблона, lint или
самооценка автора.

Frame владеет общим обещанием и правилами конфликта. Процедурой continuation
владеют tracked `skills/claude/1handoff/` и `skills/codex/1handoff/`
(`~/.claude/skills/1handoff/`, `~/.codex/skills/1handoff/` — их projections);
с 2026-08-29 процедура разложена на тело, шесть стадийных reference-файлов и
скелет пакета в `assets/`.
Source-bound owner memory — `1chat-recall` соответствующего runtime.

## Тайбрейкеры

1. При конфликте краткости и корректного первого действия побеждает корректное
   продолжение; остальной контекст удаляется.
2. При конфликте handoff и более свежего live owner/runtime побеждает live
   truth; handoff остаётся датированной дельтой.
3. При конфликте полноты разговора и action-changing дельты сохраняется только
   то, чья потеря меняет шаг, решение, veto, риск или повторяемую ошибку.
4. При конфликте единого пользовательского ритуала и единого владельца
   побеждает композиция независимых владельцев: один вызов, разные контракты,
   без копирования их логики друг в друга.
5. При конфликте бесшовности и нового lifecycle-surface пока побеждает явная
   ручная передача пути; автоматический выбор «последнего» handoff не
   допускается без наблюдаемого сбоя этого режима.

## Аппетит

- Один явный вызов в каждом runtime, один handoff-файл и отдельный source-bound
  recall outcome.
- Изменение общего behavior contract не завершено, пока live Codex и Claude
  implementations не синхронизированы; invocation, metadata и model ID могут
  оставаться platform-native.
- Допустима ручная передача пути в новую сессию.
- Не добавлять hook, индекс «последнего handoff», consumed-state, новый tracked
  skill owner или автоматическое обнаружение.
- Недопустимы повторный пересказ владельца, молчаливое превосходство stale
  handoff над live truth, потеря durable owner-сигнала и повтор оплаченного
  тупика.
- Пересмотреть Frame при наблюдаемом сбое ручной передачи, ошибочном выборе
  stale handoff, постоянном дублировании между ветками, drift между Codex и
  Claude implementation или смене рабочего model set.
