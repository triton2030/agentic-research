# Применение принципов

Принципы — сжатые, уже оплаченные ответы владельца. Скилл восстанавливает
его ответ в ситуации, которую он не видел: на развилке — выбором варианта,
в пустоте — порождением состава. Восстановление — не настроение, а матрица:
экстраполяция — додумка с множеством возможных решений, самый громкий
принцип даёт очевидный вывод, который тихий принцип из другой темы
переворачивает. Эталон владельца — в [compile](references/compile.md).

## Цель

На руках — решение или чистовая запись, которые владелец узнал бы как свои:
развилка или пустота закрыта так, как закрыл бы её он, — ответ восстановлен
из принципов, цели и конкретной сцены, а не выведен из жанрового дефолта.
След — варианты · применённые принципы цитатами · контрпринципная проверка ·
вывод — делает реконструкцию проверяемой.

Не входит: создание и правка принципов и цели · внешние необратимые
действия без явного разрешения владельца · черновая работа.

## Критерии успеха

- Варианты названы **до** первой цитаты принципа.
- Релевантные принципы процитированы, не пересказаны.
- Для каждого названо, что он означает именно для этого решения.
- Контрпринципная проверка имеет след: названный контрпринцип **или** «осей
  против нет» с перечнем просмотренных файлов — голое «противников нет» не
  считается.
- Конфликт разрешён: тайбрейкер GOAL, «специальный бьёт общий» или выбор по
  лучшей практике со следом. Усреднение запрещено как операция.
- След остался в работе или плане.

## Инварианты

- Вывод — для пустоты и конфликта, не поверх записанного: где ответ уже есть
  у своего owner-а, скил применяет его и нового не выводит. Соблазн обратного
  силён — выведенное собственной матрицей выглядит обоснованнее найденной
  чужой строки, и так у одного утверждения появляется второй владелец.
- Однопринципный вывод запрещён: следствие проверяется против полного
  релевантного набора — другой принцип может его перевернуть, и прямая
  экстраполяция самого громкого выглядит послушанием, давая противоположное
  воле владельца.
- Релевантность принципа определяется его **последствиями** для вариантов, не
  словарным сходством с задачей: переворачивающий принцип живёт в другой теме.
- Экстраполяция — расклад, не приговор: принципы тянут в разные стороны и
  тайбрейкер молчит → углубление: специфицируй заново; назван конкретный
  результат, способный развернуть выбор, — независимый взгляд
  (`1fresh-eyes`); всё ещё ровно — выбор по лучшей практике для конечного
  результата проекта. Владельцу вслед — след с рекомендацией, не
  блокирующий вопрос.
- Качественный вывод — уже ответ владельца, не новый выбор: он закрывается
  автономно и приземляется сразу у своего owner-а со следом-цитатой.
  Неоднозначность лечится углублением, не эскалацией. Разрез и исключения —
  compile, «Граница»: внешние необратимые действия и собственные лимиты
  агента не выводятся.
- Приземление выведенного идёт авторизованным ходом owner-а (канон — его
  писателем, с provenance «выведено»), не прямой правкой из компиляции.
  Принципы выше нижних слоёв: расхождение принципа с детальной
  документацией или спецификацией — не конфликт принципов, а ремонт нижнего
  слоя его авторизованным ходом; втихую выбирать победителя нельзя.
- Повторяющийся класс молчания принципов — дыра в принципах: сигнал
  `1product-shaping`, не поток эскалаций.
- Применение без следа неотличимо от неприменения — и не считается.

## Дельта

- Решает из жанрового дефолта **до** чтения принципов, потом цитирует
  поддерживающее: принципы становятся декорацией, след идеален.
- Ищет принципы по словам задачи — и пропускает переворачивающий из другой
  темы.
- Останавливается на первом подходящем; свип не завершён.
- Конфликт принципов сплющивает в компромисс-середину.
- Пустоту заполняет жанровым шаблоном (admin dashboard, лендинг, карточка),
  принципы прикладывает фильтром постфактум: сцена продукта в составе не
  участвует.

## Известные сбои

`когда → сбой → цена → куда`

- решение принято до чтения → принципы цитируются под готовый ответ →
  уверенно-неверное решение с идеальным следом → тело, шаги 1–2
- поиск по словам задачи → контрпринцип из другой темы не найден → «Индия
  отменена» против воли владельца → [compile](references/compile.md)
- громкий короткий принцип → тихий специфичный проигран → mood вместо правила
  → [compile](references/compile.md)
- два принципа тянут в стороны → выбрана середина → воля владельца усреднена в
  кашу → [compile](references/compile.md)
- «противников нет» без перечня просмотренного → театр следа → лазейка
  рационализации → тело, критерии
- пустота без вариантов → жанровый шаблон вместо сцены → генерик-интерфейс с
  идеальным следом → [generate](references/generate.md)

## Механика

Порядок жёсткий: перестановка ломает результат — варианты до оценки, свип до
вывода, обратный проход до следа.

1. **Назови, что решается, и поищи записанный ответ** — вопрос одной строкой,
   до открытия принципов; затем открой места, где ответ лежал бы: спецификации
   и документация проекта, прошлые слова владельца (`1chat-recall` — по его
   контракту, со сверкой scope и свежести). Глубина — по цене решения, как на
   шаге 3: обратимой мелочи хватает своего файла. Предъяви одно из трёх:
   - **ответ есть** — цитата с адресом: он и есть решение, вывод не нужен;
     расходится с принципом — не переписывай, это ремонт нижнего слоя;
   - **ответы расходятся** — цитаты расходящихся: конфликт производных
     артефактов — `1deep-agents`; конфликт решений владельца — стоп и вопрос;
   - **ответа нет** — для каждого адреса заголовок раздела, где ответ лежал
     бы, либо «файла нет».
   Перечень имён без заголовков не считается: его можно написать не открыв
   файлы, и тогда вывод неотличим от непоиска.
2. **Перечисли варианты** — минимум два реальных; свой любимый — один из.
   Пустота — вариантов нет вовсе → построй их: (а) сцена одной строкой — кто
   пришёл, с чем, что до и после — из Frame и GOAL, не из жанра; (б) каждый
   релевантный принцип — вопросом «что велит здесь построить, убрать,
   подчеркнуть?» — генератор, не фильтр; (в) собери из ходов два непохожих
   концепта. Дальше шаги 3–7 без изменений.
   Принципы и Frame молчат — сцену и ходы строить не из чего: это
   пустота без владельца, маршрут `1deep-agents`, не жанровый шаблон.
3. **Свип осей по последствиям**: заголовки всех файлов принципов +
   тайбрейкеры GOAL; вопрос к каждой оси — «касается ли она любого из
   вариантов?». Ни одна не задета → для обратимого микрорешения строка
   «оси не задеты, смотрел X, Y» — и работай дальше. Для продуктово
   значимого решения молчание осей — не выход: шаг 3а.

3а. **Реконструкция без прямого принципа.** Построй картину из того, что
   есть: цель, границы и «чем не является» из GOAL · сцена Frame ·
   соседние принципы — вопросом «какое правило владелец уже оплатил
   рядом и что оно велит здесь?». Вывод несёт в следе пометку «выведено,
   прямого принципа нет». Картина не складывается — углубляйся: при полной
   пустоте без владельца — `1deep-agents`; решение выводимо практически
   всегда — из цели, рамок, следов владельца и контекста проекта. Дальше
   шаги 4–7 по выведенному; разрез вывода и приземления — compile,
   «Граница».

4. **Мини-матрица**: каждый релевантный принцип × каждый вариант — «P-X → для
   A значит…, для B…»; абстрактное слово принципа специфицируй под случай.
5. **Обратный проход** по лидирующему варианту: какой принцип мог бы его
   перевернуть? След обязателен.
6. **Разреши конфликт**: тайбрейкер GOAL → специальный бьёт общий → иначе
   углубление и выбор по лучшей практике со следом; владельцу — след с
   рекомендацией.
7. **След** — решение + 2–3 строки матрицы, в работе или плане; ссылка на
   принцип несёт имя пары (`витрина:P-001`), голый `P-N` неоднозначен.

## Завершение

След есть и содержит контрпринципную проверку · конфликт разрешён ·
молчание принципов закрыто выводом с пометкой «выведено» · выведенное
приземлено у своего owner-а его авторизованным ходом · внешние необратимые
действия не совершены без явного разрешения.
