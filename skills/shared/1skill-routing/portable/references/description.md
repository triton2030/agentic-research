# Кнопка запуска

Тело недоступно модели до срабатывания. `description` — единственная поверхность
запуска: скил с плохим описанием не существует, каким бы ни было тело.

Всё «когда использовать» живёт только здесь. Тело описание не дублирует.

Имя скила — часть той же поверхности запуска: оно читается раньше описания и
задаёт первую гипотезу о моменте. Имя по теме («качество», «документы») эту
гипотезу размывает; имя по моменту или операции сужает её до нужной.

## Формула

**наблюдаемый момент × ставка**

- **Момент** — часть релевантной скилу работы, в которую агент уже вошёл, и
  наблюдаемый признак этого в текущем контексте: фраза владельца, действие,
  файл, результат инструмента или состояние задачи. Признак может быть виден
  с первой просьбы или появиться по ходу работы. Абстрактная тема («работа с
  качеством») слабее наблюдаемого признака («появился UI, готовый к визуальной
  проверке»).
- **Ставка** — правдоподобный провал без скила. Это причина потратить контекст
  на открытие тела.

Предпочитай состояние решения, а не действие: не «при написании UI-кода», а
«когда UI-код требует продуктового решения».

Назови и обратную границу — когда для этого скила ещё рано. Без неё description
цепляет тему с начала задачи и тратит вызов раньше, чем нужна Дельта.

Состояние, признак и операцию ставь в первую фразу: хвост metadata может быть
обрезан runtime.

## Различение против соседей

Главный отказ маршрутизации — не «не нашёлся», а «нашлось несколько похожих».
Опиши не только себя, но и границу:

- чем этот скил отличается от ближайшего живого соседа;
- куда идти вместо него в смежном случае — назови сосед по имени.

Прогони глазами по живому списку скилов: если два описания подходят к одной
фразе одинаково, различение не написано.

## Бюджет активации

Выигрыш держится, пока на задачу сходится два-три скила; на четырёх и больше
падает втрое. Описание, которое цепляет всё подряд, вредит соседям.

Скил не поднимается на одношаговые задачи ни при каком описании. «Прочитай этот
файл» не стоит бюджета.

## Настойчивость — через состояние, не через фразы

Естественная ошибка моделей — недодёргивать скилы, а не передёргивать. Пиши
чуть настойчиво, но материал настойчивости — **состояние задачи и тип
решения**, не списки буквальных фраз: слова владельца в моменте не угадать
(его собственный вердикт). «Даже если владелец не назвал X» — законный ход.

Форма — третье лицо: описание попадает в системный промпт. Настойчивый
рекламный тон имеет измеренную цену — смещает выбор между похожими скилами;
различай состоянием, не громкостью.

Русские формулировки состояний первичны, английские хэндлы — для технического
жаргона.

## Cut test

Убери фразу. Выбор скила против живых соседей не изменился — фраза лишняя.

## Признак готовности

Помеченная копия цели тела `1skill-routing`, правится вместе с ней.

Голая фраза владельца в 5–10 слов, без подсказок и без имени скила, поднимает
именно этот скил. Близкий по словам, но другой по нужде запрос — не поднимает.

Если момент может возникнуть по ходу работы, проверь оба состояния: до его
наблюдаемого признака та же работа скил не поднимает, после признака — поднимает.

Проверка — в [check](../../1skill-refactor/references/check.md).
