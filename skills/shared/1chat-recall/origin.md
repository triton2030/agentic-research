Дефицит словами владельца: при записи цитаты frontmatter файла сессии должен
коротко описывать, над чем работали; при следующих цитатах агент проверяет,
не пора ли обновить описание; форма должна помогать поиску и быть похожей на
ключевые слова. Источник:
`_ops/chat-recall/2026-08-14-124028-codex-019fff2e.md:19`.

Выбранное устройство: одна постоянно актуализируемая поисковая карточка
сессии помогает найти правильный разговор, но не заменяет цитаты, не
пересказывает решения и не является правдой владельца. Источник:
`_ops/chat-recall/2026-08-14-124028-codex-019fff2e.md:20`.

После первого узкого прогона владелец отдельно потребовал одноразово заполнить

не только из сохранённых quote-records. Источник:
`_ops/chat-recall/2026-08-14-124028-codex-019fff2e.md:21-22`.

После полного прогона владелец отдельно запретил применять отдельную цитату
без чтения всего файла: иначе теряются контекст, связь и flow реплик. Источник:
`_ops/chat-recall/2026-08-14-124028-codex-019fff2e.md:31`. Финальный file-route,
later-holder postcondition и общий scope Codex/Claude выбраны там же:
`_ops/chat-recall/2026-08-14-124028-codex-019fff2e.md:35-36`.
Этот обязательный full-holder gate отменён решением 2026-08-25 ниже: теперь
агент выбирает полный topic либо короткую самодостаточную цитату, а holder
открывает только при нужной сцене или chronology.

Owner-топология: продуктовый смысл живёт в этом shared package; runtime и

## Фоновая разведка holder-файлов, 2026-08-21

Владелец одобрил точный replacement для Retrieval: до существенного решения
главный агент ищет сам и одновременно отправляет несколько дешёвых разведчиков
искать дополнительные holder-ы по разным направлениям. Он продолжает только
независимую работу и до зависимого решения собирает каждую ветку. Разведчик
возвращает только путь, одну строку связи, «ничего не найдено» или blocker;
цитаты, snippets и пересказ позиции в его return contract не входят. Позицию
владельца доказывает только текст holder-а, который главный агент прочитал
целиком.
Источник: `_ops/chat-recall/2026-08-20-235300-codex-01a02084.md:16-17`.

Этот fan-out и ожидание веток отменены решением 2026-08-25: для важной темы
разрешён ровно один фоновый субагент, главный агент продолжает собственную
работу и учитывает поздний verdict, когда тот вернётся.

## Same-agent reconciliation загруженной темы, 2026-08-24

Владелец предложил при записи новых цитат сразу сверять файл темы, но задал
жёсткий default: темы менять только в крайнем случае и правильнее редактировать
существующее лишь при расхождении. Источник:
`_ops/chat-recall/raw/2026-08-24-205601-codex-01a0347a.md:20-21`.

Механизм уточнён через context locality. Агент сначала ищет прежние слова и
читает относящиеся к работе raw-holder-ы и topic-файл. Пока разговор продолжается
по тому же предмету, именно этот агент держит лучший доступный контекст для
качественной правки темы одновременно с capture новых цитат. Источник:
`_ops/chat-recall/raw/2026-08-24-205601-codex-01a0347a.md:22`.

После всестороннего разбора владелец одобрил полный рефактор, автономное
завершение и независимую проверку реализации и всей связанной кодовой части.
Источник:
`_ops/chat-recall/raw/2026-08-24-205601-codex-01a0347a.md:23`.

Выбранное устройство сохраняет это преимущество и старую границу truth:
`raw` коммитится первым; семантический typed patch формулирует тот же
погружённый агент только для уже загруженной темы и только при материальном
расхождении; общий файл из адресных операций собирает guarded helper. Batch
update догоняет append-only backlog, а непокрытая коррекция остаётся raw-only и
чинится по одной тем же typed helper после явной загрузки topic/source;
локальная правка не сдвигает общий horizon.

После falsifying batch-прогона добавлена отдельная no-op квитанция: без неё
осознанно не попавшая в тему реплика снова становилась дельтой и могла быть
дописана поздним update. Квитанция хранит только identity raw-записи и не
становится вторым semantic owner.

Ограничение «только уже загруженная тема» отменено решением 2026-08-25 ниже:
после каждого нового durable capture выбранный topic читается обязательно, а
same-turn mutation сужена до точной замены явно конфликтующего старого факта.

## Обязательное чтение темы и два retrieval-route, 2026-08-25

Владелец заменил capture-time правило: сначала оценить важность реплики, затем
сохранить её в raw, обязательно прочитать выбранную тему и только при явном
конфликте в том же scope заменить старый факт новым. Источник:
`_ops/chat-recall/raw/2026-08-25-215514-codex-01a039d8.md#L23`.

Одновременно прежняя разведка несколькими субагентами заменена ровно одним
неблокирующим фоновым поиском только для важной темы. Его можно запустить в
начале или по ходу работы; главный агент не ждёт, а учитывает вернувшийся
verdict позже. Источник: тот же holder, `#L24`.

Retrieval получил два независимых маршрута: topic-кандидаты по handle и
короткому описанию и holder-кандидаты по `session-context` и буквальным
цитатам. Агент выбирает полный topic либо короткую цитату; scores маршрутов не
смешиваются. Источник: тот же holder, `#L25`.

## Граница улучшений протокола, 2026-08-25

После внешнего prior-art поиска владелец уточнил границу: нельзя сильно
отходить от его протокола, но сам протокол разрешено улучшать. Источник:
`_ops/chat-recall/raw/2026-08-25-215514-codex-01a039d8.md#L28-L29`.

Поэтому внешний опыт не заменил систему. Из Memory-R1 взят только известный

противоречие. Runtime получил узкую границу — `replace` разрешён лишь тогда,
когда старый и новый факты не могут одновременно быть истинны в одном scope.
