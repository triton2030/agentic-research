# OPM — Operating Model and Responsibility Matrix

**Purpose:** define parties, value exchange, ownership, rights, flows, handoffs
and accountability. **Default authority:** `canon`. Alias: OM. Near-miss:
procedure → PROC; scenario → SBP; software structure → ARCH.

**Ban:** OPM owns who is accountable, not how work is executed step by step. The
Responsibility Matrix is the single home of activity-level accountability;
narrative sections reference Activity IDs and never repeat matrix cells. Legal
promises are not invented.

**Non-obvious contracts:** Responsibility Matrix = stable Activity ID × R/A/C/I.
External Constraints = REFERENCE (legal, financial, security, contractual
owners). Non-roles is owned: what each actor or system explicitly is not.
Operating Invariants is owned: truths other artifacts may depend on.

**Conditional modules:** vendor governance; service levels; geography; approval
quorum; separation of duties; capacity and Business Model Canvas view.

**Completion check:** every money, data and asset flow has endpoints and a
trigger; each critical activity has an accountable owner or an explicit
unresolved.
