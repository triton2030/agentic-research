# Выбор поверхности

Вход: не ясно, куда класть правило — корень, папка, скил, хук — или как оно
доедет до агента.

- Выбирай не самый заметный, а самый дешёвый слой, гарантированно достигающий
  первого решения, которое меняет смысл:

| Surface | Admission |
| --- | --- |
| root | cross-task Delta, нужная большинству задач scope |
| folder | Delta поддерева |
| skill | опознаваемый момент; допустим риск, что routing не сработает |
| hook/schema/validator/test | hard invariant или детерминированное действие |
| plan | состояние одной длинной работы |
| chat prompt | невыводимая Delta текущей задачи |
| canonical owner | изменяемое значение |
| nowhere | модель быстро выводит смысл сама |

- Проза не является enforcement: «всегда делай» остаётся просьбой, пока
  correctness не удерживает механизм.
- Resident surface платит на каждой задаче; допуск требует разом: смысл
  применим к большинству задач scope · не выводится быстро из repo и task ·
  меняет observable action или check · сравнение none/always-on/selective
  оправдывает доставку на target model соразмерно риску.
- Универсального числового порога нет; бюджеты держат владельцы: скила —
  `1skill-creation`, любого файла инструкций — тело `1instruction-authoring`,
  раздел «Форма каждого файла инструкций».
- Считай по траектории representative task — владелец счёта этот файл:
  активные обязанности в каждой
  точке решения · сколько решений, фаз и compaction boundaries переживает
  persistent смысл · конфликты и уже созданные ассистентом прецеденты ·
  loaded context, включая tool output · повторную доставку или механизм
  проверки hard invariant.
- Длинный one-shot список может быть дешевле нескольких правил, обязательных
  всю большую работу; wall-clock сам по себе ничего не измеряет, чужой
  benchmark — evidence, не порог.
- Различай authority и conditioning: прежний текст ассистента и состояние
  инструментов нормой не владеют, но создают прецедент — формально старшая
  строка может проигрывать накопленной траектории.
- Ориентировка размещается по частоте обращения и тоже платит context cost:
  нужна позже или в узкой зоне — доставляется позже или ниже.
- До новой строки прочитай только применимую цепочку — system/root, folder по
  пути, пересекающийся skill, покрывающий hook, активный plan; уже сказанное
  чинится у owner-а, второе правило рядом не добавляется.

Выход: решение развилки места — вернись в прерванную стадию.
