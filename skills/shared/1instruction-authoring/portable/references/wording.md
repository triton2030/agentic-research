# Формулировка

Строка инструкции — изменение решения, а не описание хорошего поведения.

Рабочая форма:

операция или состояние [+ причина против привлекательного ошибочного дефолта]

Причина нужна только там, где без неё агент честно вернётся к неверной ветви.
Капслок, повтор и длинное объяснение причину не заменяют.

Проверь строку тремя вопросами:

1. Какой наблюдаемый след появится после применения?
2. Как дешевле всего формально выполнить её без результата?
3. Какой законный путь она закрывает?

«Достаточно», «качественно», «тщательно», «учти», «при необходимости» и похожие
слова оставляют модели неназванный выход. Замени их observable condition либо
удали.

По умолчанию пиши цель, границы и контракт выхода. Порядок оставляй только по
procedure boundary из [simplify](../../1context-refactor/references/simplify.md).

Готово, когда из чистого окна остаётся одно честное прочтение и оно ведёт к
проверяемому действию без лишнего ограничения маршрута.
