# Написание местного слоя

Вход: кандидаты с зонами, основаниями и адресами правды; ссылки, нужные на
маршруте; существующие обязательства, включая необследованные зоны.
Выход: корневая и папочные инструкции с владельцами смысла и наблюдаемыми
моментами применения. Отбор метода — в теле; здесь выбирается его местная форма.

## Когда решаешь, нужна ли строка

Для кандидата назови исчезающее вместе с ним обязательство, неизвестный
местный факт, наблюдаемое вредное поведение или необратимый вред до действия.
Если ни одного основания нет, общий совет в слой не проходит (Minimal
Critical Specification). Наличие строки в старом документе само не доказывает
её необходимость; предполагаемая выводимость из цели не доказывает
безопасности снятия.

Подъём по «зачем» (Action Identification) помогает выбрать носитель:
сохраняемое состояние зоны, остаточный критерий, существующий механизм
или дополнительная инструкция. Для каждого оставь причину выбора;
механизму принадлежит только проверка, которую он реально исполняет.
Переименование запрета в цель не снимает обязательства и нагрузки.

## Когда распределяешь правду по проекту

До записи покажи распределение владельцу. Корень доставляет общепроектные
правила и условные маршруты до выбора зоны; локальная правда принадлежит
папочным инструкциям. Новая папочная инструкция нужна при самостоятельном
местном контексте, а не для каждой папки по шаблону.

Поставь ссылки на связанные зоны и источники там, где агент встретит их
до зависимого решения. Назови условие чтения и проверь фактическую загрузку
рантаймом, не предполагая её только по имени файла. Один смысл остаётся
у одного владельца; соседняя зона ссылается на него.

## Когда формулируешь намерение зоны

Контекст передаёт неизвестную систему: местное обстоятельство, его роль
и последствия пропуска. Объяснение должно делать понятной важность работы
и существенных ограничений; общее «это важно» ничего не добавляет.

Папочная инструкция задаёт одну Maintain-цель (KAOS): состояние, которое
нужно сохранять. Назови, когда зона уже в порядке и менять её не требуется.
Корень маршрутизирует между зонами и не получает искусственную цель зоны.
Пустую цель уточни по источникам, а не дополняй списком критериев.

Для критерия ищи конкретную остаточную лазейку по Контексту, Задаче и Цели
вместе (obstacle analysis). Если сильный агент уже выводит нужное решение,
перечень критериев не создаётся. Существенная особая граница пользователя
сохраняется даже тогда, когда её неудобно выражать общей целью.

## Когда включаешь требования по стадиям

Сгруппируй содержание по решениям, в которых оно необходимо. У случая
есть наблюдаемые начало и окончание; завершённая проверка не остаётся
постоянной обязанностью следующей стадии. Знание тоже может понадобиться
только в определённом случае. Короткий случай с одной нужной инструкцией
не требует дополнения ради полноты списка.

В ключевом выборе учти применимое из корня, папки, задачи и прочитанных
скилов вместе. Сравни набор до, во время и после выбора. Разводи независимые
моменты, убирай повторы; неотделимые обязательства сохраняй и назови причину
их совместного применения. Склейка строк и перенос между файлами не
доказывают уменьшения нагрузки.

Если объединяешь частные правила в принцип, предъяви существенные частные
решения, которые читатель из него восстановит. Отбор применимого можно
передать артефакту задачи, только если местный контракт делает это его
обязанностью. Нельзя снять защиту на обещании другого файла без такого
контракта.

## Когда пишешь отдельную единицу

Сделай ясными местное обстоятельство, нужное действие или знание и цену
ошибки. Причина доступна в самой единице или непосредственно рядом;
один связанный Контекст может объяснить несколько требований без повторов.
Независимо применимые смыслы не прячутся в одном длинном предложении.

Особо дорогая граница должна быть заметна в момент риска. Скил-владелец
артефакта может передавать необходимый способ работы ссылкой с условием
чтения; собственный пересказ его протокола создаёт второго владельца.

Сохрани адреса обязательств, результаты отборов и границы непроверенного.
Это вход проверки; счёт разделов не заменяет доказательства полезной дельты.

## Когда отделяешь навигацию

Подробные подтверждённые маршруты, нужные в разных рабочих задачах, размещай
через `1index` в подходящем индексе области. Он определяет, когда полезен новый
локальный INDEX. Одна понятная ссылка может остаться в инструкции.

В AGENTS.md сохраняй местную специфику, границы ответственности и правила,
которые нужны до выбора источника. Оставь заметный вход в индекс с условием
чтения; по текущей задаче агент выбирает нужный маршрут. Перенос имеет смысл,
когда подробности можно читать отдельно: обязательное чтение всей инструкции
и всего INDEX каждый раз не уменьшает необходимый контекст.
