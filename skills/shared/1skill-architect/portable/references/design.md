# Дизайн

## Admission canvas

- `Job`: downstream outcome, не буквальная форма запроса.
- `Source`: owner correction/preference, повторный trace, knowledge/tool gap.
  Авторский вкус не становится найденным моделью failure.
- `Necessity`: default → привлекательность → вред → operator → transfer.
  Сравни с nearest owner и cheapest intervention.
- `Surface`: постоянный default → instruction; изоляция → agent; hard invariant
  → hook/validator; deterministic repeat → script; recurring inference moment →
  skill; выводимое из задачи → ничего.

## Форма следует failure

- **Outcome-controller:** способность не включается вовремя. Дай criterion,
  causal cells, point-of-action check, stop; путь оставь модели.
- **Operational package:** не хватает knowledge/schema/tool/order. Дай inputs,
  минимальный invariant sequence, exact evidence, stop.
- **Hybrid:** judgment core короткий, deterministic часть в script.

`Goal / criteria / invariants / mechanics / completion` — coverage questions,
не template. Материализуй только action-changing ответы.

## Package

`description` = observable moment × stake × near-miss boundary; trigger впереди.
`SKILL.md` = always-needed controller. Reference = редкое знание или условная
процедура. Script = deterministic operation. Mutable canon остаётся внешним
owner; skill хранит pointer и только локальное недедуцируемое следствие.

Split Knowledge Creator/Applicator оправдан разными triggers, authority, context
budget или lifecycle. Иначе один skill дешевле.

Deletion test: какое наблюдаемое ухудшение даст удаление строки? Method name +
однострочная Delta допустимы лишь если target models стабильно распаковывают
anchor; иначе верни необходимый смысл.
