# Делегирование — работа шире одного контекста

Staged run — форма восстановления и делегирования, не третий режим: он несёт
Wayfinding или Execution и не меняет Outcome задачи.

## Когда

Точное восстановление после границы сессии · несколько независимых
context/write-слайсов · флот воркеров. Не заводи staged shape из-за размера,
отдельного вопроса или блокера — sibling-задача появляется только для
независимо закрываемого Outcome.

## Контракт делегирования

- **Task — единственный изменяемый владелец.** Модуль-задание для воркера —
  неизменяемая проекция; воркер не меняет planning state.
- **File-disjoint:** каждый воркер получает непересекающийся footprint файлов.
  Пересечение — перетёртые правки, самый дорогой сбой флота.
- Задание воркеру самодостаточно: цель · критерии · границы · запреты ·
  ссылка на `context.md`; чата воркер не видит.
- Порядок волны, барьеры и лимиты параллельности — `1orchestration`;
  тяжёлая веха Execution несёт строку разметки
  `волна: чтение <зоны> · запись <футпринты> · проверка <линзы>`.
- Принял возврат → обновил `status.md` («Свидетельства и статус», «Next»)
  в том же ходе.

## Форма модуля

Каталоги рядом с task.md: `modules/` — активные задания;
`modules/_archive/` — использованные, неизменными; `modules/_returns/` —
пакеты возвратов: воркер кладёт файл до барьера, обрыв на барьере не
теряет evidence волны.

```markdown
# Модуль — <срез>
parent: ../task.md · веха <N>

## Вклад            <в какую веху и чем>
## Источники        <точные адреса; список требований сверяется
                    актом вывода (contract.md), не заменяет его>
## Границы          <чтение · запись (футпринт: конечные файлы)>
## Экипировка       <скиллы, которые воркер обязан поднять>
## Бюджет           <N шагов; «достаточно, когда …»>
## Возврат          статус success|blocked|split-proposal ·
                    изменения · evidence · пробелы ·
                    экипировка: поднял/нет + причина ·
                    след принципов: решение + имена принципов
## Проверки root-а  <чем принимается>
## Запреты          <обход гейтов; выход за границы = blocked.
                    Модуль неизменяем: воркер работает по выданному
                    тексту, правка на лету расходится с ним;
                    уточнение — репликой с пометкой «амендмент»
                    в возврате>
```

## Проверка воркеров

Самоотчёт воркера — не свидетельство. Проверяй свежим прогоном по исходным
критериям и путям: `git diff`, тесты, приёмка потребителем стыка. Транскрипт
исполнителя — материал для диагноза, не для приёмки.

2–3 круга verify→fix без сужения носителей — стоп, блокер владельцу.

## Восстановление после обрыва

Волна — единица автономии: обрыв стоит одну волну, не работу.

- Холодный старт, бюджет чтения: карта каталога задачи → task.md + status.md →
  активные modules/ → точные якоря источников. Архив, backlog и
  соседние задачи не преподгружаются.
- До перевыдачи модулей — сверка «что уже сделано»: git status/diff
  против статуса задачи. Внешнее действие не повторяется вслепую:
  повторный флот по уже применённым правкам — перетёртые правки и
  двойные коммиты.
- Пауза — состояние: открытые вопросы владельцу живут заметками-вопросами
  ([questions](questions.md)); ответ может принять другое окно и продолжить
  с места.
- Статус расходится с git → верить git, чинить статус, потом
  продолжать: чекпойнт, который врёт, хуже отсутствующего.

## Инвалидация

Изменился upstream-артефакт или контракт стыка → downstream-доказательства
недействительны: перепроверь затронутые задачи, не доверяй их старому
«готово».
