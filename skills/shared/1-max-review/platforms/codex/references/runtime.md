# Codex: запуск

Вызывающий запускает одного native subagent-координатора в свежем контексте
(`fork_turns: "none"`, где доступно). Передай ему SKILL.md и явный пакет
входа; модель координатора — сильная текущая модель. Координатор сам ведёт
очередь чтения, проверок и приёмки; вызывающий получает короткий итог.

Модель и усилие проверяющих бери из тела SKILL.md; усилие передавай полем
`reasoning_effort`. Задавай модель только при свежем/ограниченном fork,
когда так требует API.
Чистое окно не отменяет глобальные и автоматически доставляемые инструкции.
Не обещай полностью пустой контекст; ограничен именно передаваемый материал.

Перед запуском сверь доступные инструменты: вложенный spawn, лимит глубины,
живые слоты, возможность завершать агентов и фактический доступ к файлам.
Пакетов может быть сотня; одновременно работают лишь разрешённые слоты.
Если завершённые агенты занимают лимит, используй штатное освобождение;
при отсутствии такой операции фиксируй предел, а не обещай бесконечную очередь.

Проверь requested и наблюдаемую resolved model, где runtime её раскрывает.
Если resolved model не раскрывается, сохраняй requested model и эту границу
знания; не заявляй измеренное качество конкретной модели.
Не выдавай асинхронную возможность скилла
за постоянно работающий фоновый сервис после окончания текущего хода.

Не создавай пользовательские задачи приложения ради внутренних исполнителей
без прямого запроса. При недоступности вложенной оркестрации объясни владельцу,
что ожидание без диспетчеризации в вызывающем окне здесь не обеспечено.
Предложи доступный путь: вызывающий только запускает пакеты и передаёт
координатору ID и пути отчётов; состояние очереди и содержимое остаются на диске.
Альтернатива — сохранить очередь для другого запуска. До выбора статус
incomplete; ранее данное согласие на такой путь сохраняет силу.
