# Дефолты и ошибки агентов

Момент: решается, нужна ли строка сверх буквальной формулировки пользователя.
Файл даёт критерий: строка входит, только если названо, какой дефолт агента она
рвёт и почему голая команда не сработает.

- Дефолт входит с предсказанием: «модель сделает X, потому что Y выглядит
  разумным». Нет названного механизма — строка не пишется; молчание принятым
  риском не считается.
- Знает ≠ делает: модель может пересказать правило и всё равно нарушить его.
  Но голое правило разрыв не закрывает: 0–4% соблюдения без предъявляемого
  артефакта против 97% с ним (The Compliance Gap, 2026); норма подпорки
  следом — `writing-rules.md`.
- «Я прочитал», «я учёл», пересказ и красивый отчёт — не evidence применения;
  сам вызов скила не доказывает влияние на решение.
- Типовые тяготения агентов, против которых пишут строки: раздувать документ
  прозой; описывать артефакт вместо приказа исполнителю; исполнить форму без
  результата; сгенерировать проверку под желаемый ответ; объявить успех без
  следа; додумать scope расплывчатого слова в свою пользу; терять правила на
  длинной траектории — odds соблюдения падали ~5.6% с каждой следующей
  функцией (coding-agent config study, 2026).
- Налог на строгость — владелец смысла «что инструкция отменяет» для семьи
  скилов: каждая строка закрывает законные пути, в том числе на задачах,
  которых по замыслу не касается. Строгость платится только там, где эффект
  дороже отмены: необратимое или внешнее действие, security, миграции,
  обязательный порядок инструментов, воспроизводимость. Сомнение, что строка
  неожиданно уведёт мысль агента, — не пиши её вовсе.
