# Референс-файлы

Вход: инструкции скила не помещаются в тело — черновик держит 20 и больше
единиц.

Референс — способ положить по смыслу другую, относительно самостоятельную
часть скила; за счёт референс-файлов скил может держать несколько протоколов
размышления.

Эскалация по порядку:

1. Сначала сожми тело по шагу абстрагирования режима рефактора
   (`refactor.md`).
   - Дословный протокол пользователя сжимай только с его согласия.
2. Не помещается — вынеси относительно самостоятельные темы в референсы.
3. Протокол не помещается даже так — раздели его на стадии-разделы.
4. Не помещается и в стадии — предложи пользователю разделить на несколько
   скилов; большой домен направь в канонический внешний источник.

Правила референса:

- Референс читается только при необходимости; важная логика не живёт в
  референсе — кроме стадий-разделов, чей момент чтения назначает тело.
- Схема «коротко в теле, подробнее в референсе» не работает: агенту всегда
  хватает короткого текста, подробнее он не читает.
- Референс покрывает отдельную тему полностью, от начала до конца.
- В теле скила нет даже короткого описания содержимого референса — только
  инструкция, когда его читать.
- Не более 20 единиц инструкций в каждом референсе; референс-файлов — не
  более 20.

Стадии-разделы — протокол режется на последовательные референсы:

- Одна стадия — один референс-файл, желательно около 10 единиц; стадии идут
  строго друг за другом; каждая зависит только от выходных артефактов
  предыдущих, не от чтения их инструкций.
- Стадия самостоятельна: наблюдаемый вход-артефакт, все инструкции стадии — в
  её файле, наблюдаемый выход-след; чистое окно выполняет стадию, имея только
  артефакты прошлых.
- Тело остаётся дирижёром: по строке на стадию — условие чтения; файлы других
  стадий не читаются, переход — только предъявив след.
- Имя стадии называет действие или артефакт, без интриги: следующую стадию не
  должно хотеться открыть без надобности.

- Выход: перекроенные разделы — в папке-истории, показаны в чате.
