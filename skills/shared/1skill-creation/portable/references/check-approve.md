# Независимая проверка версии

Вход: законченный черновик, граница заказа, источники намерения и карта потерь
при рефакторе. Автор отвечает за результат; проверяющие ищут ошибки с разных
сторон и не утверждают версию голосованием.

## Когда готовишь проверяемый вход

Зафиксируй конкретную версию и применимый авторский контракт. Для каждого
существенно изменённого свойства приготовь основание, проверку, способную
обнаружить ошибку, и её наблюдаемый результат либо явный пробел. Для прежнего
результата объясни, почему изменение не отменило его применимость.

Для изменённого поведения выполни реалистичный случай: сохрани вход,
доступный агенту контекст, его действие и результат. Дорогой отказ от условия
требует сравнения с ним и без него. Предсказание остаётся предсказанием;
непроведённая необходимая проба оставляет это свойство непроверенным.

## Когда версия зафиксирована

Запусти три независимых проверяющих в свежих окнах. Общий вход каждого —
черновик, источники, граница заказа, применимый контракт и имеющееся evidence;
дополнительно каждый получает только собственную роль и её материалы.

| Роль | Предмет |
| --- | --- |
| `../agents/check-intent.md` | Дельта Контекста, объяснение важности, функция Задачи, самостоятельность Цели и необходимость Критериев. |
| `../agents/check-instructions.md` | Необходимость каждого добавочного требования, отсутствие повторов и сохранность существенных условий. |
| `../agents/check-trajectory.md` | Моменты применения, переходы и фактический результат в реалистичных случаях. |

Не передавай проверяющим замечания друг друга до независимых ответов.
Промпты с ожидаемым ответом непригодны для пробы самостоятельного поведения.

## Когда пришли находки

Прими находку по словам пользователя, действующему контракту или наблюдению,
а не по уверенности проверяющего. Сохрани отклонения с причинами. Исправляй
установленный разрыв, сохраняя незатронутое evidence; исправление пропуска
автора не требует нового решения пользователя.

Допустима вторая и последняя волна той же тройки для затронутых свойств.
Волна завершена после ответов всех трёх; не начавшийся или оборванный запуск
повторяется отдельно. Переименование версии не обнуляет число волн.
Неразрешённое после них существенное противоречие остаётся открытым.

## Когда закрываешь проверку

Сверь финальные байты с принятыми исправлениями. В истории сохрани результаты,
решения по находкам и границы непроверенного; обнови карту потерь и действующие
продуктовые принципы у их владельца. Покажи пользователю существенный выбор
и оставшиеся риски. Один успешный случай доказывает возможность, а не рост
вероятности успеха.

Для установки применяй уже данное разрешение на эту редакцию или границу
изменения; доставку выполняет соответствующее условие тела. Новое согласование требуется только
для нового существенного выбора, которого прежнее разрешение не покрывает.
