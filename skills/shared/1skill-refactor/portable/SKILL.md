# Рефактор скила

## Контекст

Рефактор скила — приведение его в соответствие основному скилу
`1skill-creation`: та же функция от пользователя, те же формулировки, тот же
идеал краткости. Чем меньше инструкций, тем они эффективнее и сильнее и тем
меньше риск, что агент ослушается. Лучший исход для скила, который модель умеет
целиком, — снятие скила.

Правило допускается, только когда его эффект дороже того, что оно отменяет;
полный владелец цены — «налог на строгость» в
[agent-defaults](../1skill-creation/references/agent-defaults.md).

## Цель

Меньше инструкций без потери прежнего смысла скила; разница видна в
поведении, а не в многословности.

## Протокол

1. **Квалификация.** Локальная формулировочная правка внутри прежнего claim-а —
   короткий путь: точный diff (заменяемые строки и новые), без полного
   протокола. Иначе — дальше по шагам.
2. **Сверь со `1skill-creation`.** Инструкций больше его мягких бюджетов или
   формулировки не по его правилам → пройди его протокол целиком, начиная с
   функции скила словами пользователя: без восстановленной функции рефактору
   нечего сохранять. Видно, что модель умеет весь скил целиком, — снимай
   скил, без дальнейших шагов.
3. **Абстрагируй по шагам.** Источник — оригинал целиком: тело, references,
   папка-история и слова владельца → [refactor](references/refactor.md).
   1) выпиши все инструкции пакета плоским списком единиц;
   2) сгруппируй единицы по цели, которой они служат;
   3) каждой группе выведи инструкцию высшего порядка — цель или принцип
      (canon: commander's intent); частность снимается, только если агент с
      чистым окном выведет её из нового общего; невыводимое остаётся явной
      строкой;
   4) сверь новый набор с прежним смыслом и функцией: потерянного нет.
4. **Закрой пути побега.** Большой когнитивный шаг агент может сфейкать.
   Обязательный шаг подпирай следом, который нельзя произнести не сделав:
   цитата из середины файла доказывает чтение; «учёл» не доказывает ничего.
5. **Запусти двух обязательных субагентов** с чистым окном: первый ищет, что
   ещё сократить; второй проверяет, чем изменённый скил ухудшит поведение
   вызывающего агента — каждая инструкция отупляет, а чёткий протокол не в
   свой момент ведёт хуже свободного хода. Пара одна на весь рефактор —
   прогоны протокола создания из шага 2 её не дублируют; пустой вердикт —
   законный результат. Живой сбой скила →
   [failures](references/failures.md); заявлена готовность →
   [check](references/check.md).

## Соседи

- скил не поднимается или перехватывается соседом → `1skill-routing`;
- нужна принципиально новая функция, а не рефактор → `1skill-creation`;
- виноват не скил, а контекст прошедшей работы → `1context-refactor`.

## Завершение

Перед записью новой версии — разбор в чат, «да» пользователя и ссылки на
записанные файлы по протоколу `1skill-creation` (пп. 4–5). Сдача: счёт инструкций до и после · таблица объединений — какая высшая
инструкция какие поглотила и что осталось явным как невыводимое · нефейкуемые
следы обязательных шагов · вердикты обоих субагентов · чем проверено
изменившееся поведение · снятое — с причиной в `cut.md` рядом со скилом.
Для снятого скила сдача — обоснование снятия и снятое в `cut.md`, без
таблицы объединений. В
сдаче цитируй применённые пункты канона; имя без пункта — не применение →
[canon](../1skill-creation/references/canon.md).
