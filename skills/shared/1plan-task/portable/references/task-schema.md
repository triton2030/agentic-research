# Форма задачи

Вход: создание, продолжение с изменением файла, пересборка, отложение или
закрытие одной задачи. Выход: самостоятельный контракт и правдивое состояние.
Содержательную приёмку держат C1–C5 тела скила.

## Размещение и поля

`_ops/plans/эпики/<Имя эпика>/task - <Имя задачи>.md`, рядом с
`epic - <Имя эпика>.md`. Закрытый файл остаётся там же. Новый файл заполняется
из [шаблона](../assets/task-template.md); все плейсхолдеры заменяются.

| Ключ | Тип и смысл |
| --- | --- |
| `тип` | строка `задача` |
| `эпик` | однозначный wikilink на эпик той же папки |
| `допуск` | `эпик`, если задача выводится из допущенного эпика, иначе открываемая запись решения: `путь.md:строка` (например, из `1chat-recall`) или permalink на ответ |
| `эпик-снимок` | 64 hex-символа: снимок после содержательной сверки |
| `траектория` | непустая строка: какой критерий эпика приближает задача и чем |
| `режим` | `execution` — путь известен; `wayfinding` — результатом будет проверенное знание для выбора пути |
| `статус` | общий словарь `1plan-map/references/epic-schema.md` |
| `порядок` | положительное целое, уникальное внутри эпика |
| `подзадач` | целое ≥ 0, вычисляемое число чекбоксов |
| `подзадач-готово` | целое ≥ 0, вычисляемое число `[x]` |
| `evidence` | строка с адресом доказательства целого; `""` до подтверждения |
| `обновлено` | дата ISO `YYYY-MM-DD`, последняя содержательная запись о работе |
| `вопрос` | необязательное поле: wikilink на единый файл вопроса либо `""` |

Поля, кроме `вопрос`, обязательны. Wikilinks пишутся в YAML-кавычках;
предпочтительна ссылка от корня проекта без `.md`. `допуск: эпик` требует
адреса решения в эпике. Само заполнение поля не создаёт разрешения.

Словарь статусов: `✅ готово`, `🔨 в работе`, `◽ в очереди`,
`🔒 заблокировано`, `🛑 затык`, `⏳ отложено`.

## Разделы тела

H2 идут точно в этом порядке; детализация использует H3 или списки.

| Раздел | Состав |
| --- | --- |
| `Задача` | Один порученный результат и явная граница; строка бюджета несущих единиц |
| `Зачем` | Причина работы, адреса до строки и пара ключевых дословных цитат, либо явное отсутствие внешних оснований |
| `Цель` | Наблюдаемое состояние, которое требуется достичь |
| `Критерии приёмки` | Лазейки, закрывающие их проверки, условие завершения и отдельное условие возврата |
| `Основания` | Адреса утверждённых решений, GOAL и слов владельца с влиянием на задачу; при отсутствии — явная запись. Прежний заголовок «Канон» проверка читает как этот раздел |
| `Подзадачи` | 3–7 достигнутых состояний, каждое с собственным свёрнутым отчётом |
| `Состояние` | Текущая подзадача, последнее подтверждённое, следующий ход, блокер / вопрос и его влияние |

Бюджет считает независимо нарушимые обязательства и знания, а не число строк
или YAML-ключей. При превышении двадцати после перепаковки объяснена
неделимость; состояние-фикция ради числа подзадач недопустимо.

## Подзадачи и отчёты

После каждого чекбокса сразу идёт свёрнутый callout (пустая строка допустима):

```md
- [ ] Наблюдаемое состояние части работы
> [!note]- Отчёт
> статус 2026-09-08: не начато
> доказательство:
```

У достигнутого состояния `[x]` непустой адрес `доказательство:` обязателен.
Отчёт с датой сохраняет сжатый след результата части; большой вывод живёт по
ссылке в `_evidence/`. Callout свёрнут ради владельца: он читает замысел,
границы и состояние, а доказательства читают агенты и проверяющие. Поэтому
отчёт исполнителя о части живёт здесь, а не в отдельном файле оркестрации,
и число подзадач не ограничено объёмом их отчётов. «Состояние» выше истории по актуальности и обновляется
тем же ходом, что и работа. Из него видно, что делать после обрыва окна.

## Сверка и жизненный цикл

Проверка поставляется с `1plan-map`; `<1plan-map>` ниже — путь к его пакету:

```sh
uv run --script <1plan-map>/scripts/check_plans.py --root . --snapshot '_ops/plans/эпики/Имя/epic - Имя.md'
uv run --script <1plan-map>/scripts/check_plans.py --root . --sync
uv run --script <1plan-map>/scripts/check_plans.py --root .
```

Снимок включает намерение эпика, GOAL и перечисленные в эпике файлы оснований.
Его записывает агент, сверивший задачу с этими живыми основаниями. При
расхождении сначала устанавливается совместимость задачи; автоматического
«освежения» нет. Старая закрытая задача сохраняет исторический снимок.

`--sync` вычисляет счётчики и список задач эпика, не меняя допуск, снимки,
статусы или evidence. Непроизводная ошибка останавливает запись. Проверка
синтаксиса не доказывает смысл C1–C5 или подлинность допуска.

Создание и закрытие задачи тем же ходом обновляют производные поля карты.
При закрытии агент также добавляет в `evidence` эпика адрес доказанного вклада
задачи и обновляет его «Состояние»; `--sync` этого за него не делает.
`✅ готово` требует всех `[x]` и evidence целого; эпик при этом не закрывается
автоматически. Отложение сохраняет причину и наблюдаемое условие возврата в
«Состоянии» и старше автоматически выводимой блокировки.

При ответе, меняющем продолжение, задача ссылается полем `вопрос` на один файл
по `1plan-map/references/question-schema.md`. После решения обновляется
владелец истины, затем задача сверяется с ним. Расширение цели или границы
имеет адрес нового допуска; перепаковка без расширения повторного согласия
не требует.
