# Схема файла задачи

Вход: ты создаёшь или пересобираешь файл задачи, закрываешь его, откладываешь
или правишь его поля.
Выход: файл, который дашборд видит, а следующий агент читает без чата.

Ключ, написанный по памяти, не ломает файл заметно: задача выпадает из дашборда
и перестаёт существовать для владельца, оставаясь на диске.

Пересмотреть, если проект держит планы не под `_ops/map` или живёт без Obsidian:
тогда этот файл описывает мир, которого в проекте нет.

## Размещение и имя

- Файл задачи лежит внутри папки своего эпика — `_ops/map/эпики/<Эпик>/` — рядом
  с самим файлом эпика. Колокация и есть структура, из-за которой создать
  задачу, не открыв эпик, физически невозможно.
- Файл называется именем задачи, а не служебным словом: соседние файлы
  различаются в списке только именами.

## Frontmatter

| Ключ | Что несёт |
| --- | --- |
| `тип` | `задача` — по нему дашборд отличает задачу от эпика и вопроса |
| `эпик` | ссылка на владеющий эпик |
| `эпик-снимок` | sha256 текста эпика на момент сверки |
| `траектория` | чем эта задача двигает критерий своего эпика |
| `режим` | род работы: разведка, исполнение и подобное |
| `статус` | из общего словаря |
| `порядок` | место среди задач эпика |
| `подзадач`, `подзадач-готово` | знаменатель и числитель процента задачи |
| `evidence` | доказательство результата |
| `обновлено` | дата |

- `эпик-снимок` — sha256 текста эпика **без state- и производных полей**
  (`статус`, `обновлено`, `задач-готово`, `evidence` и подобных). Иначе закрытие
  любой соседней задачи меняет текст эпика, снимки всех остальных расходятся, их
  исполнители останавливаются ложно, и после второго такого случая агент начнёт
  «освежать снимок, чтобы не мешал».
- Снимок пишет тот, кто перечитал эпик и сверил с ним задачу, и не переписывает
  его позже без новой сверки. Обновлённый «чтобы не мешал» снимок гарантирует,
  что расхождение не найдёт никто.
- `траектория` называет связь с критерием эпика, а не пересказ задачи: задача,
  не двигающая ни один критерий, читается полезной и не приближает закрытие.

## Разделы тела

- `## Зачем` несёт: результат и его пользу · границу соседней работы · условие
  входа · владельца результата · обязательное чтение точными адресами ·
  доказательство целого результата · условие остановки · текущий факт и
  следующий самостоятельный ход.
- `## Принципы` — применимые принципы адресами и то, как они сужают эту работу.
- `## Подзадачи` — список достигаемых состояний с отчётами.

Перечень `## Зачем` — это то, что схема требует записать; смысловые требования к
каждому пункту держит тело скила.

## Словарь статусов

✅ готово · 🔨 в работе · ◽ в очереди · 🔒 заблокировано · 🛑 затык · ⏳ отложено

- Словарём владеет схема карты — `1plan-map`, его `references/epic-schema.md`;
  здесь он зеркалится. Значение статуса меняют там, и расхождение двух словарей
  делает дашборд нечитаемым быстрее, чем ошибка в отдельном файле.

## Подзадачи

> «мы не теряем вот эту логику Obsidian, то, что задачи должны иметь подзадачи, а
> отчеты по подзадачам должны быть спрятаны внутри тогл»

- Подзадача называет достигнутое состояние, а не шаг: по состоянию видно,
  случилось оно или нет; по шагу видно только, что его выполнили.
- Отчёт по подзадаче лежит в свёрнутом callout `> [!note]- Отчёт` сразу под ней.
  Развёрнутые отчёты вытесняют с экрана цель и границу, и файл, из которого их не
  видно сразу, отказывает так же, как файл, где их нет.
- Отметка `[x]` ставится только вместе со строкой доказательства в этом отчёте, и
  `подзадач-готово` растёт вместе с ней. Собственный отчёт о выполнении
  доказательством не является: при выполненной и невыполненной работе он выглядит
  одинаково.

## Закрытие

- Закрывай задачу статусом `✅ готово` только по предъявленному доказательству
  целого результата, записанному в `evidence`. Исчерпанный список подзадач
  доказывает исчерпание списка, а не достижение результата.
- Закрыв задачу, тем же ходом обнови в файле своего эпика `задач-готово` и его
  `evidence`. Второго вызова не будет: если карта узнаёт о закрытии отдельным
  ходом, она узнаёт о нём тогда, когда кто-нибудь заметит расхождение.
- Создав задачу, тем же ходом обнови в эпике `задач` и `задачи`: иначе
  знаменатель, по которому владелец меряет остаток, расходится с папкой.
- Закрытый файл задачи остаётся на месте, в папке своего эпика, и виден в
  представлении «Завершённые задачи». Он часть видимой истории проекта.

## Отложение

- Откладывая задачу, поставь `⏳ отложено` и запиши в файле две вещи: почему
  отложена и при каком наблюдаемом условии в неё возвращаются. Без причины
  отложенная задача неотличима от брошенной; без условия возврата она не
  вернётся, потому что момент возврата не наступит сам.
- `⏳ отложено` — решение человека и старше выведенного `🔒 заблокировано`: иначе
  отложенная задача показывается заблокированной и владелец ищет несуществующий
  блокер.
