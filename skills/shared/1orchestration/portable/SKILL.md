# Оркестрация

Окно, слушающее весь свод разом, исполняет каждую инструкцию хуже.
Оркестратор — технический директор волны, хранитель её траектории
и пользы: делит работу на посильные задачи, при выдаче фокусирует
каждого на инструкциях его момента, своё окно держит для сверки
хода с целью проекта и волевых решений.

## Цель

На руках — работа волны субагентов, полезная проекту, а не только
буквальная: каждый субагент получил посильную задачу с фокусом,
оркестратор с высоты птичьего полёта держал траекторию и волевые
решения, а обрыв сессии стоил одну волну, не работу.

Не входит: выбор моделей и семейств · форма план-файлов
(`1planning`) · линзы, зоны и контракт свежести критиков
(`1fresh-eyes`). Волны внутри
`1fresh-eyes` и `1deep-agents` идут по их собственным контрактам и
порога здесь не поднимают.

## Критерии успеха

- Карта волны — в чате до запуска, отчёт волны — в чате после;
  без карты волна не открыта, без отчёта не закрыта.
- Ни одно окно не совмещало исполнение со своей приёмкой; тяжёлые
  классы инструкций получили приём по таблице цены.
- Ход сверен с целью проекта, не только с буквой задания:
  расхождение или невыполнимость закрыты волевым решением —
  проверено субагентами, записано, названо; необратимое или
  меняющее долговечную правду ушло вопросом владельцу.
- После обрыва новое окно продолжило с носителя режима, не с нуля.

## Инварианты

- Невидимой операции не было. Каждое решение оркестратора
  существует только предъявленным: карта с весами — до запуска,
  волевое решение с обоснованием — в реестре, переход — в носителе
  режима, отчёт — в чате. Устное «учёл» операцией не является.
- Каждому окну — только его момент. Свод не отменяется — задание
  фокусирует адресами и называет, что предъявить в возврате как
  след применения; пересказ вместо адреса создаёт вторую правду.
  Момент оркестратора — траектория, конфликты, синтез. Перед
  решением он сам читает компактные owner-источники цели,
  продуктовой правды и consequential recall-цитаты. Детали — у
  исполнителей; советники несут evidence большого корпуса и
  тяжёлую генерацию, не заменяя прямого чтения.
- Формой владеет один носитель, второй раз она не записывается:
  веса и приёмы — таблица цены; формулировки заданий — wording из
  `1instruction-shaping`; линзы и свежесть критиков — `1fresh-eyes`;
  при живом плане носители возвратов, бюджеты и ремонт — `1planning`
  (delegation); этот скилл добавляет карту, фокус, порядок, барьеры
  и лимиты параллельности.
- Оркестратора тоже проверяют: траекторию волны судит внешнее окно.

## Дельта

Модель умеет запускать субагентов. Она не умеет: разделить работу
на посильные задачи — даёт одному окну всё сразу; сфокусировать —
вываливает весь свод или молчит; взвесить инструкцию — даёт
пишущему и экстраполяцию, и приёмку; сберечь окно оркестратора —
читает корпус сама «для скорости»; потребовать след — принимает
«учёл» без отчёта.

## Известные сбои

`когда → сбой → цена → куда`

- задание выдано без фокуса → субагент слушает весь свод разом →
  соблюдение каждой строки падает кратно (96% → 20–60%) → карта
  волны (Механика, шаг 1)
- инструкции розданы без веса, дешёвые окна без перекрытия зон →
  тяжёлая инструкция исполнена как ритуал, слепая зона невидима →
  [instruction-cost](references/instruction-cost.md) — без таблицы
  цены все инструкции весят одинаково
- задание написано слабыми формулировками → субагент исполняет
  форму, не решение → переделка волны → `1instruction-shaping` → его
  `references/wording.md`
- запись без предполёта → пересечение футпринтов, перетёртые
  правки → [preflight](references/preflight.md)
- папка волны заведена по памяти → manifest без recovery-полей,
  после обрыва новое окно стартует с нуля →
  [wave-folder](references/wave-folder.md)
- проверило то же окно или та же семья → дыра невидима до
  владельца → Механика, шаг 3
- возврат принят, переход не записан → свежее окно продолжает с
  позавчера → инвариант следа

## Механика

**Порог.** Волна разворачивается при любом из: две и более
независимые зоны чтения · два и более непересекающихся футпринта
записи · три и более моментных инструкционных владельца сверх
постоянного слоя (поднятые скиллы, рамки задачи, критерии плана;
корень не считается). Ни одного — один воркер плюс внешняя
проверка, причина строкой. Окон — по числу зон; дефолтный потолок
3–4 — лимит подписки, не качества; состав больше четырёх окон —
строкой в чат до запуска.

**Режим.** С живым планом состоянием волны владеет план; реестр
решений — в план-папке. Без плана — папка волны
`<корень проекта>/_workspace/orchestration/<дата-слаг>/`; её форма —
шаблон `wave-folder`: `context.md` — manifest-истина волны с
чек-листом закрытия, `decisions.md` — реестр волевых решений.
Карта и отчёт в чате — проекции manifest.

1. **Карта волны** — в чат: задача → кому → фокус-адреса →
   вес/приём тяжёлых → что предъявить в возврате. Формат задания:
   посильная задача (одна зона чтения либо один футпринт записи) ·
   фокус-адреса · границы · форма и адрес возврата. Барьер: без
   карты не запускать.
2. **Запуск** — чтение и советники параллельно по зонам; запись
   после принятых отчётов чтения, предполёт пройден, один писатель
   по умолчанию.
3. **Проверка** — окнами, не писавшими работу: против критериев
   задания и плана · принципы и цитаты владельца —
   `1use-principles` в непишущем окне · траектория волны и
   оркестратора — внешнее окно; кросс-семейный прогон — по решению
   владельца. Возвраты — разница списков, не мнение.
4. **Принятие и отчёт** — только оркестратор, пакеты дословно:
   конфликт, пустоту, развилку закрывает волевым решением в реестр
   или вопросом владельцу пачкой; меняющая ветку развилка
   немедленно останавливает зависимую ветку; переход — в носитель
   режима в том же ходе; отчёт таблицей в чат: агент → задача →
   фокус → возврат → чем проверено.

**Ремонт без плана** — после первого bounded wait без изменения названного
return/artifact/diff выполни один read-only probe этого носителя; сообщение
воркера о ходе delta не является. Нет delta — верни `UNKNOWN`/blocker и
останови только зависимую ветку без нового окна. Delta есть — один repair
прогретому воркеру; runtime не разрешается live owner-ом — респавн только
незавершённой задачи. Второй repair — свежим окном, третьего нет. С живым
планом — `1planning/references/delegation.md`.

## Завершение

Отчёт волны в чате; переход записан; очередь владельца выдана;
возник сигнал — строка `1findings`. Порог не достигнут — волна не
разворачивается, причина строкой.
