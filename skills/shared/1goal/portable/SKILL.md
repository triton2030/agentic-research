# Цель проекта

GOAL — самый верхнеуровневый контекст проекта: короткий и обширный, подробности
живут в принципах, принципы строятся под целью. Мера его качества — мысленный
эксперимент владельца: «закончи весь проект по одному этому файлу — и я буду
доволен». Недостижимо; каждая правка двигает к этому или от этого. Пример
экстраполяции — в `craft.md`.

## Цель

На руках — `GOAL.md`, по которому агент, не читавший ничего больше, выводит
решения, не названные в нём дословно, и разрешает конфликты приоритетов.
Рядом — `README.md`: вход для человека и холодного агента. Goal-цитата в
корневых инструкциях синхронна с GOAL.

Не входит: планы и статусы (`1planning`) · правила поведения
(`1instruction-shaping`) · принципы (`1product-shaping`) · маршруты к файлам
(`1index`).

## Критерии успеха

- **Тест экстраполяции:** из GOAL выводится решение, которого в нём нет
  дословно. Не выводится ничего сверх написанного — это список, а не цель.
- **Тест тайбрейкера:** GOAL разрешает хотя бы один реалистичный конфликт
  приоритетов (скорость × качество × функционал). Нет — развилки поедут к
  владельцу или в дефолт агента.
- «Чем закончено» проверяемо, не глагольно.
- Одна durable-правда не живёт в двух документах: тема — можно, строка — нет.
- В GOAL и README нет правил, задач, статусов.
- Fresh-проба: по одним README+GOAL отвечаются три вопроса — что строим ·
  зачем · когда готово.
- Goal-цитата в корне обновлена тем же ходом.
- «Да» владельца получено до записи.

## Инварианты

- Просьбу — включая просьбу владельца, — конфликтующую с GOAL, не исполняй
  молча и не отвергай: покажи конфликт («это против „быстро запустить": цель
  устарела или увлечение?») и жди решения. Причина: владелец сам заказал
  защиту от своего увлечения; молча исполненное усложняет продукт против его
  же замысла. Граница: показывай для работы, меняющей продукт, не для починок
  и уборки.
- Слова владельца — вход, не задание: pressure-test «сказал X — имеет в виду
  Y?» до закрепления.
- Подробность, осевшую в GOAL, выселяй в принципы: GOAL растёт смыслом, не
  текстом.
- Держи иерархию GOAL → принципы → работа.
- Переводи смысл в язык целевого документа, не копируй; In scope пиши
  состоянием, не списком действий.
- Правило, просящееся в GOAL или README, отдай владельцу поверхности; красную
  линию владельца сначала запиши дословно, потом интерпретируй.
- Ни одной записи до «да» владельца.

## Дельта

Модель умеет писать красивые стратегические документы. Она не умеет:

- удержать цель вне головы сессии — реконструирует её из формулировки задачи;
- заметить конфликт просьбы с целью — исполняет просьбу, цель дрейфует;
- написать In scope состоянием — пишет перечнем проделанного;
- удержать GOAL от превращения в rulebook и статус-реестр;
- не скопировать правду в README «для надёжности».

## Известные сбои

`когда → сбой → цена → куда`

- просьба владельца против цели → исполнена молча → продукт усложняется против
  его же замысла, дрейф невидим → тело, первый инвариант
- цель изменилась → корневая цитата не тронута → в проекте две цели, молча →
  тело, шаг 7
- одна строка в GOAL и README → дрейф копий через месяц →
  [craft](references/craft.md)
- «сказал X — имеет в виду Y?» не спрошено → контракт закрепил слова вместо
  намерения → [craft](references/craft.md)
- в GOAL просится правило → принято «раз уж здесь» → второй владелец
  поведения → [craft](references/craft.md)
- GOAL распух подробностями → цель перестала читаться одним взглядом →
  выселение в принципы, тело

## Механика

1. **Вес.** Смена цели, границ, done/stop → полный разговор с владельцем.
   Правка формулировки → короткий путь.
2. Прочитай живые GOAL, README и корневую Goal-цитату — до формулировок.
3. Вопросы владельцу — только меняющие scope, done, stop; обязательно закрой
   тайбрейкеры: «при конфликте X и Y что побеждает?» Одним компактным блоком.
4. Верни владельцу триаду проекта: куда идём · чем закончено · что не входит.
5. **«Да» владельца.**
6. Запись: один владелец на смысл, перевод — не копия.
7. **Тем же ходом** — Goal-цитата в корневых инструкциях.
8. Drift-проверка прямым чтением обоих документов; fresh-проба.

Жёстких перехода два: `5 → 6` — запись до «да» необратима; шаг 7 не
откладывается — отложенная цитата означает две цели в проекте.

## Завершение

Оба теста — экстраполяция и тайбрейкер — пройдены · дублей нет · цитата
синхронна · fresh-проба пройдена · последствия маршрутизированы: план →
`1planning`, правило → `1instruction-shaping`, дословная красная линия —
в память проекта. Не вошедшее — в `cut.md` строкой с причиной.
