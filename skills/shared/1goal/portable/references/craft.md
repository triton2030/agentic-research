# Ремесло цели

## Пример экстраполяции — эталон владельца

Цель: «запустить первую версию приложения в Казахстане; скорость запуска
важнее качества и функционала; критичный для теста рынка функционал должен
быть».

Из неё выводится: «выгрузку БД клиента при его уходе не планировать — это
функционал взрослого устоявшегося проекта, не стартап-стадии», хотя про
выгрузку в цели ни слова. Это и есть работа GOAL: решения сверх написанного.
Тест экстраполяции проверяет ровно эту способность файла.

## Границы двух документов

**`GOAL.md`** — одна страница: Что делаем (состояние) · Тайбрейкеры («при
конфликте X и Y побеждает X») · In scope (3–7 состояний) · NOT in scope ·
Чем закончено (проверяемые условия) · Stop-правила.

**`README.md`** — одна страница: описание проекта, vision/мотивация, подход,
on-ramp «что агенту читать первым».

Ни один не хранит правила, задачи, статусы. Правило → владелец поверхности
(`1instruction-authoring`); задача → `_ops/plans/**` (`1planning`).

## Ментальные инструменты

В голове; заголовками в файл не выносить — «## Inversion» в GOAL это театр:

- **pressure-test** — «владелец сказал X; имеет в виду Y?»;
- **inversion** — один конкретный сценарий провала цели;
- **premortem** — что медленно разъест scope за полгода;
- **fresh-session check** — хватит ли README+GOAL агенту завтра без устного
  контекста.

## Drift-проверка

Сравни тела GOAL и README прямым чтением: одинаковая тема допустима,
одинаковая durable-строка — нет. Неочевидная парафраза → два независимо
извлекаемых тезиса в `1md-search`; вердикт split/merge/move → `1ia-audit`.

## Goal-цитата

После правки `GOAL.md#Что делаем` — обнови 3–5 строк essence в `AGENTS.md` и
корневом `CLAUDE.md` тем же ходом. Сверка прямым чтением обеих сторон, не по
памяти: цитата — проекция, GOAL — владелец.
