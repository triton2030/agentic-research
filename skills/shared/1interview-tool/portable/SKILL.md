# Инструмент интервью

## Цель

Временная форма `_ops/interviews/YYYY-MM-DD-topic.md` собирает связанные
решения владельца и приводит к названному результату в его настоящем owner-е.

Интервью владеет формой, границей голосов и переносом ответов. Текущая правда
после обработки живёт не в интервью, а у owners результата.

## Критерии успеха

- После самостоятельного поиска осталось не менее четырёх связанных решений,
  которыми действительно владеет пользователь.
- Для каждого вопроса до создания формы названы адрес ответа и материальное
  последствие неверной догадки.
- Каждый материальный ответ перенесён к owner-у либо оставлен pending с
  названным owner-ом и причиной.
- После переноса форма получила адрес результата и перемещена в `_archive/`.

## Инварианты

- До вопросов назови итоговый результат и добудь доступные факты: тематическая
  анкета без будущего адреса выглядит полезной, но не меняет следующий
  артефакт.
- Вопрос проходит в форму только вместе с парой
  `адрес ответа → что станет неверным, если угадать`. Нет любой части — вопрос
  удалить.
- Если owner или тип результата сам является предметом решения, сначала задай
  воротный вопрос с адресом `owner unresolved`; зависимую форму до ответа не
  создавай.
- Покажи рекомендацию и основание. Если рекомендации нет, назови недостающий
  факт или owner-сигнал; варианты без различимой логики замени свободным
  ответом.
- Текст, внесённый в блок
  `### Ответ пользователя — <уникальная метка>`, становится голосом владельца
  после заполнения. Заранее отмеченный слабый default становится его выбором
  только после общей отметки `Готово к проверке`; пустое поле и молчание
  согласием не являются.
- Пиши видимую часть формы простым русским. Техническое имя оставляй рядом
  только для связи с owner-артефактом.
- Дополняй существующий semantic owner. Новый документ, включая `SPEC`,
  создавай только при отдельном читателе, lifecycle и owner-е; его место
  определяется owner-ом результата, а не близостью к интервью.

## Дельта

Модель умеет составлять вопросы, но естественно строит тематическую анкету:
каждый вопрос выглядит уместным отдельно, хотя ответ может ничего не изменить
и никуда не попасть.

Скил меняет первый ход: до формулировки вопроса агент обязан назвать будущий
адрес ответа и цену неверной догадки. Поэтому форма собирает только решения,
которые изменяют результат.

## Известные сбои

`когда → сбой → цена → куда`

- нужна форма → собрана произвольная разметка → голос владельца смешан с
  рекомендациями агента → неверный перенос →
  [cookbook](references/plain-markdown-cookbook.md)
- предложены похожие варианты → пользователь выбирает формулировку, а не
  решение → ложная определённость →
  [cookbook](references/plain-markdown-cookbook.md)
- ранний ответ отменяет последующие вопросы → показано всё дерево →
  лишние решения и противоречия → Механика, воротная зависимость
- ответы получены → форма объявлена результатом → временный вход становится
  устаревающей правдой → Механика, перенос до архива

## Механика

Три зависимости порядка обязательны:

1. **Результат и факты до вопросов.** До записи формы предъяви:
   - какое решение или действие она разблокирует;
   - тип результата и `owner/path`;
   - что уже проверено и не спрашивается;
   - карту `вопрос → адрес → цена ошибки`.

   Форма допустима, только если после этого осталось не менее четырёх связанных
   user-owned решений. Иначе задай вопросы в чате.

2. **Воротный ответ до зависимой формы.** Если один ответ выбирает owner, тип
   результата или отменяет ветку, создай сначала маленькую форму только для
   этой развилки. Остальную форму собери после ответа.

3. **Перенос до архива.** После команды «проверь»:
   - отдели проверенные факты, ответы владельца, выводы агента и unresolved
     items;
   - уточни одним адресным вопросом только материальное противоречие;
   - перенеси ответы по исходной карте;
   - добавь в форму:

     ```md
     > Результат перенесён: <owner paths>
     > Pending: <items с owner-ом и причиной либо нет>
     ```

   Только затем перемести форму в `_ops/interviews/_archive/`.

Форму собирай из блоков
[cookbook](references/plain-markdown-cookbook.md). При первом реальном
интервью найди project root по ближайшему `_ops`, затем VCS root, иначе
явному project cwd; создай `_ops/interviews/` и `_archive/` лениво и никогда
не пиши в `/`.

## Завершение

Предъяви owner-paths результата, каждый pending item с его owner-ом и путь
архивированной формы.

Заполненная форма без переноса, summary без адресов и архив до переноса
завершением не являются.
