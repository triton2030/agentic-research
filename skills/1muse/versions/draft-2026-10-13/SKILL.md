# Muse — субагент через Muse Code

## Контекст

По подписке Meta владельцу доступен Muse Code (`muse`) с моделью Muse Wonder —
агентом чужой семьи, которого Meta строила под сложную инженерную работу. Он
читает файлы, ищет в вебе и видит картинки, а с правом записи правит код
и запускает команды в песочнице. PDF, аудио и видео он не открывает.
Закреплена модель `muse-wonder-1.0` с усилием `high`. Вопрос по файлам занимает
15–40 секунд, правка с прогоном тестов — от полуминуты до нескольких минут.

Вызывай его только через обёртку `scripts/muse.py`. Голый `muse exec` подводит
в трёх местах:

- Имя модели он не проверяет: на выдуманное имя сервер отвечает как обычно.
  Обёртка сверяет закреплённую модель с каталогом Muse до вызова.
- Он подгружает личные правила и скилы владельца из Claude Code и Codex.
  В пробе Muse прочитал чужой скил и сам запустил сценарий на семь дочерних
  агентов ради вопроса о шести файлах. Обёртка этот импорт отключает.
- Действие, ждущее подтверждения, держит его бесконечно: своего таймаута
  у `muse exec` нет. Обёртка выбирает права без подтверждений и обрывает
  прогон по таймауту.

## Задача

Поручи Muse часть работы через обёртку и прими результат.

## Цель

Muse выполняет поручение с первого вызова, а ты знаешь, настоящий ли пришёл
ответ и что именно он прочитал и изменил.

## Когда пишешь бриф

Muse не видит твоего разговора и не знает личных правил владельца. Правила
проекта из `AGENTS.md` он получает с `--project-rules` или в папке, уже
доверенной в Muse; о пропущенных правилах обёртка предупредит в stderr.

Назови в брифе цель, границы работы, точные пути и форму ответа. Для правки
назови ещё признак готовности и команду проверки: Muse запустит её сам.

## Когда запускаешь

```bash
python3 ~/.claude/skills/1muse/scripts/muse.py --dir /абсолютный/путь/папки <<'BRIEF'
<бриф>
BRIEF
```

| Нужно | Флаг |
| --- | --- |
| правка файлов и команды оболочки | `--write` |
| правила, скилы и хуки проекта | `--project-rules` |
| продолжить тот же разговор | `--resume <id из квитанции>`; папка та же, права задай заново |
| показать картинку | `--image /путь`, можно несколько |
| ответ строго по форме | `--schema '<JSON Schema>'` |
| работа дольше 9 минут | `--timeout 45m` и `run_in_background: true` |

Без `--write` Muse только читает, но читает любой файл на диске, а не одну
рабочую папку. Запись и оболочку в этом режиме отключает сам Muse Code,
веб остаётся доступен.

С `--write` он правит файлы рабочей папки и запускает команды в песочнице
Muse Code. Запись за пределы рабочей и временной папок запрещает система.
Коммит Muse сделать может, но без просьбы в брифе не делает.

Всё прочитанное уходит в Meta. В подписке по умолчанию включён режим
Contributor, в котором Meta вправе учить на этом модели; режим меняет владелец.
Файлы с ключами и паролями в брифе не называй.

Запускай обычным Bash с `timeout: 600000`: обёртка сама остановит Muse через
9 минут и скажет, на чём он стоял. Независимые поручения на чтение запускай
параллельно; два прогона с `--write` в одной папке мешают друг другу.

## Когда пришёл ответ

В stdout лежит ответ. В stderr — квитанция одной строкой: модель, время, id
сессии, вызванные инструменты, прочитанные файлы (`read:`), а после `--write`
ещё и тронутые за прогон (`changed:`).

Правку принимай по `changed:` и `git diff`, а проверку перезапусти сам. Код
возврата и слова Muse говорят, что ход закончился, а не что работа верна.

Без `--write` файл, которого нет в `read:`, Muse не открывал. С `--write` он
читает и через оболочку, и такие чтения в `read:` не попадают. Строка `WARNING`
называет сорвавшийся вызов инструмента, например бинарный файл. `read_skill`
среди инструментов — Muse открыл свой встроенный скил, это норма.

## Когда обёртка вернула ошибку

Сообщение называет причину и следующий шаг. В нём нет двух вещей:

- Ответа нет — скажи владельцу, что Muse не ответил и почему. Свой ответ
  или ответ другой модели на это место не ставь.
- `not in the Muse catalog` значит, что закреплённая модель ушла из подписки.
  Замену выбирает владелец.

Устройство прав, другие модели, медиа и лимиты описаны
в [references/muse-code.md](references/muse-code.md). Открой его, когда нужного
режима нет в таблице или `muse` ведёт себя иначе, чем здесь написано.
