# Разбор старого документа

## Контекст
Старые документы писались до нынешнего дерева и до нынешних правил: один файл говорит о нескольких предметах, часть текста — прежние предложения агента, часть — решения владельца, и по тону они не различаются. Уверенная формулировка в таком файле не значит ничего: она могла быть догадкой, которую никто не отменил.

## Задача
Разобрать документ на отдельные утверждения с адресами, свести повторы, установить статус каждого утверждения и назвать ему дом по правилам `1folder-tree`. Результат — перечень «утверждение → адрес в старом файле → статус → дом», по которому дальше пишутся файлы. Перечень остаётся рабочим результатом хода и в базу не ложится.

## Критерии принятия
- **Каждое утверждение несёт адрес в старом файле.** Без адреса перенос нельзя проверить, и следующий ход начнётся с повторного чтения того же документа.
- **Повторы слиты, а расходящиеся ответы на один вопрос остаются различимыми и оба видны владельцу.** Отсекает молчаливый выбор одной версии — самый дешёвый способ потерять решение владельца.
- **У каждого утверждения стоит один из трёх статусов: подтверждено словами владельца, выведено, неизвестно.** Отсекает переезд прежнего предложения агента в базу под видом решения.

## Цель
Из старого файла в базу переезжает только знание и только по одному разу; предложения, состояние работы и догадки остаются в старом файле как история и приходят владельцу в чат как вопрос. При споре между полнотой переноса и различимостью статусов выигрывает статус: неперенесённое утверждение находится по адресу, а ложно подтверждённое — нет.

## Когда в файле больше одной вещи
Включается, как только в документе видно два предмета; кончается, когда у каждого утверждения назван дом. Оставляет перечень утверждений с домами.
- Границу режь по вещи, а не по заголовкам старого файла: заголовки писались под другое дерево и разложат знание по прежней логике.
- Утверждение, дом которого — существующий файл, переезжает упоминанием вещи по имени, а не копией текста: копия удвоит факт в первый же день.
- Утверждение, у которого дома в дереве нет, — повод предложить владельцу место, а не завести папку по дороге: это решение владельца по правилам `1folder-tree`.

## Когда две формулировки говорят об одном
Включается, когда два фрагмента отвечают на один вопрос; кончается, когда осталась одна формулировка или два различимых ответа. Оставляет слитый текст либо пару адресов владельцу.
- Сливай только при совпадении по смыслу и по статусу: слияние подтверждённого с выведенным поднимает догадку в ранг решения.
- Расхождение не решай сам, даже когда одна версия явно новее: проигрывает не старая формулировка, а та, за которой нет слов владельца.
- Различающиеся ответы держи рядом с их адресами, пока владелец не выбрал: сведённые в один средний ответ, они теряют оба источника сразу.

## Когда разбор закончен
Включается, когда перечень готов; кончается, когда начата запись файлов. Оставляет старый файл нетронутым и сообщение владельцу.
- Старый файл не переписывай и не удаляй: его судьба — решение владельца, а снятое уезжает туда, куда велит `AGENTS.md` базы.
- Сноска в новом файле указывает на первоисточник утверждения, если старый документ его назвал, и на сам документ, если нет: иначе цепочка доказательств упирается в текст неизвестного автора.
- Что осталось неизвестным, идёт в файл знаком пробела, а что осталось предложением — в чат: перечень разбора никто не откроет второй раз.
