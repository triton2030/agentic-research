# Перевод старого корпуса

Вход: старый документ или папка, которую переводят в файлы новой системы. Дом для существующего файла известен; при переводе дома называет `1docs-system` после того, как утверждения выписаны.
Выход: карта судьбы каждого утверждения старого текста с адресом нового дома. Сами новые файлы пишутся дальше режимами разделов по маршрутам тела.

## Задача

Переведи старый текст в новые файлы, не потеряв ни одного факта, который знал только Founder, и не перенеся ни одного, который агент выведет сам.

## Цель

После перевода старый документ можно архивировать без потери: всё его установленное стоит в новых домах с адресами, всё выведенное снято с названной причиной, а расхождения между старыми домами предъявлены владельцу, а не склеены.

## Зачем

Старый корпус проекта — сотни файлов, где одна тема пересказана в четырёх слоях, а факт владельца стоит рядом с выводом агента без пометки. Перенос «всего подряд» воспроизводит свалку в новой форме; перенос «только красивого» теряет число или обещание, которое знал один человек. Владелец различает два корпуса по одному признаку: коммерческое число, обещание пользователю, запрет из GOAL или пометка владельца — его; остальное — выведено.

## Что агент сам не сделает

- Сначала выпиши из старого текста утверждения с признаком владельца и только потом решай, куда каждое идёт: если начать с новых файлов, старый текст читается через их форму и теряет то, что в форму не легло.
- Судьба «снято как устройство» законна только для того, что уже выражает код; «оставлено в `_business`» — для сырья решения. Утверждение без судьбы — потеря, которую следующий агент не заметит.
- Два старых дома с разными ответами на один вопрос — строка перечня с двумя адресами и цитатами, а не выбор: старые корпуса проекта расходятся в единице списания, контакте покупателя и частичном принятии, и все три ответа принадлежат владельцу.
- Число, схему и контракт, которые уже выражает код, не переноси: новый дом называет модуль словом, а не пересказывает его.
