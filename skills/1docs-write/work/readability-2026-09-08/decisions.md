# Основания и проверяемые свойства

| Изменение | Основание и предотвращаемый сбой | Проверка |
|---|---|---|
| Заголовок описывает весь раздел | Пользователь отверг заголовок о повторном использовании над определением и настройкой | Свежий редактор получает смешанный текст без подсказываемого деления |
| Связный абзац, глубина без лимита | Пользователь назвал прежний текст сборником несвязанных предложений и снял 2000 | В пробе сохраняются причинные переходы и условия, а не только headings |
| Семантическая разметка | Пользователь попросил подзаголовки, жирное, списки | Читаемый артефакт, не отчёт о намерении |
| Источники/статусы в сносках | Пользователь хочет основное знание в чистом виде | Все ссылки и примечания сопоставимы с текстом; предложение не становится фактом |
| Нет пустой строки после заголовка | Прямое требование для Obsidian | Механическая проверка Markdown + просмотр образца |

Метод: минимальная критичная спецификация из 1agent-steering; подробности нового поведения помещены в существующий режим записи, а не размножены по всем режимам. Новых runtime-файлов/механизмов нет.

Случаи добавленного правила: написание — 5 инструкций; оформление источников — 3; приёмка — 3. При правке документа со ссылками написание и источники пересекаются: 8 новых обязательств, а не два изолированных пакета. Ещё действуют сохранность смысла/модальности, существующий дом и корректность метаданных. Это превышение совместной нагрузки названо явно; оно не выдаётся за доказательство лимита в семь. В каждом отдельном случае не более семи. Удалять одобренные пользователем свойства ради счёта нельзя. Механическая проверка закрывает интервалы/парность сносок/ссылки; независимая приёмка — смысл и соответствие заголовков. Статус и условия сохраняются на всём пути. Разбор источника и выбор дома включаются только когда нужный вопрос ещё не решён.

Находки первой проверки: вернуть местное знание и причины выбора в глобальный режим (принято, соответствующий смысл восстановлен без лимита); честно назвать совместную нагрузку 5+3 (принято, подсчёт исправлен). Принудительный многопроходный алгоритм ради формального разнесения правил не введён: одно чтение документа всё равно требует совместного соблюдения, а workflow добавил бы нагрузку.

Не обследованные зоны кода/деплоя/планов не изменяются: текущая работа — редактура _docs и отдельно логика канона. Известный старый слой уже прочитан до авторинга, поэтому суждение о привычке агента — прогноз, не чистый эксперимент. Наблюдаемый сбой подтверждён самим отвергнутым образцом в текущем разговоре.
