# Поиск и возобновление обхода

## Кандидат и границы отсутствия

Имя, размер, поиск top_k и локальная синхронизированная папка не доказывают
наличия или отсутствия идентичного облачного оригинала. Поиск по имени
используй для дешёвого выбора кандидатов, а сверку делай по ID и содержимому.
Переименованную копию можно найти по размеру и хешу. Дубли имеют разные ID;
shortcut ведёт к target ID, превью и транскодирование оригинал не заменяют.

Для вывода «не найдено» запиши аккаунт, corpus, фильтры и охват папок/дисков,
дойди до последней страницы, разреши ошибки и проверь `incompleteSearch`.
Пустая страница с nextPageToken — продолжение. При отклонённом токене начни
новый проход заявленной области, устраняя дубли по ID. Неполный обход не
отменяет конкретного совпадения, но исключает общий вывод об отсутствии.

`corpora=user` с `includeItemsFromAllDrives` не является отдельным полным
обходом каждого shared drive. Явно различай My Drive/Computers, нужные shared
drives, аккаунты, корзину и Photos. Объекты без доступных хешей остаются
непроверенными по содержимому. Даже завершённое перечисление не атомарно:
отрицательный результат относится к датированной обследованной области.

## Если используется встроенный адаптер

В `assets/apps-script/Code.gs` настрой TARGETS из локального манифеста:
индекс, basename, размер и сохранённые SHA-256/MD5; полные локальные пути
в Google не отправляй. Нулевые временные файлы не подтверждают сохранность видео.
Встроенный адаптер принимает до 32 целей и сохраняет до 32 кандидатов;
большой набор обрабатывай частями, известные ID проверяй напрямую.
RUN_ID обозначает один проход; новый проход получает новый ID, продолжение
сохраняет его и неизменную конфигурацию. DRIVE_ID задавай только для явно
выбранного shared drive; пустое значение означает user corpus.

`continueArchiveScan` работает ограниченными порциями и держит служебный
курсор приватно в Script Properties. Сохраняй полученный безопасный результат
после каждого запуска. Кандидаты этого адаптера ещё не являются MATCH:
проверь локальное содержимое и свежие метаданные отдельной пары.

При смене аккаунта/конфигурации, повторяющемся токене, incompleteSearch или
переполнении лимита состояния действуй по статусу; полный результат не
объявляй. При слишком большом числе кандидатов раздели TARGETS на меньшие
наборы и начни для каждого новый проход. Сохрани startedAt, lastPageCheckedAt, completedAt и account/config/scope.
После возобновления freshInventory=false даже при успешном завершении:
дата начала и завершения показывают весь интервал обследования.
Завершённый RUN_ID исторический:
SCAN_ALREADY_COMPLETE не означает новую проверку. Лимит состояния может ограничить и число страниц; меньший набор целей не
решает переполнение истории токенов. Счётчик files означает строки API,
не гарантированно уникальные ID во всём меняющемся Drive. Изменять эти
границы без проверки кода и лимитов сервиса нельзя.

## Сохранённое состояние

Отдельно запиши завершённость перечисления и результаты по каждому файлу.
Сохраняй обновления манифеста атомарно по мере работы; локальные OAuth-токены
в resume-state не входят. Приватный курсор выбранного клиента не выводится
в общий отчёт. Если строка результата потеряна или обрезана, восстанови её
из доступного состояния либо повтори соответствующую проверку.

Официальная пагинация, проверена 2026-10-18:
[files.list](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/list).
