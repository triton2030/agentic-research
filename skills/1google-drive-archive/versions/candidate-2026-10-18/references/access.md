# Доступ к настоящим оригиналам

## Выбрать существующий путь

Сначала проверь аккаунт без вывода секретов и пригодность подключённого Drive
на известном бинарном файле. Нужные поля `files.get`:
`id,mimeType,size,sha256Checksum,md5Checksum,version,trashed,ownedByMe,capabilities(canDownload)`.
Сверяй реальный ответ. Недавнее доказательство отсутствия полей позволяет
перейти к другому действующему пути, не повторяя бесполезный запрос.

Для get/list достаточно `drive.metadata.readonly`. Этот доступ охватывает
метаданные доступных Drive-файлов, сохраняется до отзыва и не даёт скачивания,
загрузки или удаления. В другом рантайме сначала проверь его собственные
инструменты и аккаунт: наличие установки не означает общий credential bridge.

Если connector опускает хеши, используй уже разрешённый личный Apps Script
через доступный авторизованный браузер. Найди его по прошлому локальному
отчёту или списку проектов; подтвердись аккаунтом и manifest. Рабочий путь
не требует локальной копии OAuth-токена. При отсутствии доступа выполни
независимую локальную часть и назови недостающий bridge.

## Шаблон Apps Script

В пакете есть `assets/apps-script/Code.gs` и `appsscript.json`.
Это переносимый адаптер Advanced Drive v3 с явным metadata-only scope.
Параметры задаются в начале кода; helper возвращает только выбранные поля
и безопасные статусы. Установка локального скилла сама не обновляет cloud script.

Новый проект/consent или изменение существующего cloud script согласуй в
пределах действующего разрешения. Перед новым согласием проверь manifest,
default Cloud project и фактически показанные права. Новый Desktop OAuth,
установка клиента и постоянное хранение credential — отдельные конкретные
решения, если прежний доступ действительно не подходит. `drive.file` ограничен
файлами приложения/выбранными файлами и технически не является upload-only.

Перед зависимым выбором прочитай комментарии конфигурации выбранного asset.
При работе через браузер сохранённые байты редактора должны совпасть с
подготовленным кодом; дождись завершения сохранения и выполнения.
Полный лог в IDE может быть обрезан: потеря ожидаемой строки означает
неполное свидетельство, а не успешное отсутствие файлов.

## Стоимость и секреты

Используй существующую ёмкость Google Drive/Google One. Перед настройкой
нового доступа проверь актуальные официальные условия API и состояние проекта.
Google Cloud billing, карты, buckets и платное увеличение квот не подключаются.
При квоте — ограниченное ожидание или остановка. Оплаченный Google One не даёт
разрешения на расходы Google Cloud; отсутствие платёжной формы не доказывает
отсутствия привязки billing. Не обещай, что API останется бесплатным навсегда.

OAuth-токены, cookies, callback URL, headers и сырые auth-ответы не выводятся
и не попадают в отчёты. Проверяй фильтр своего нового адаптера искусственным
секретом до реального consent. Для чувствительного экрана выбирай безопасные
элементы вместо общего DOM/response dump. Если нужна помощь владельца,
показывай по одному действию и настоящий снимок без секретов и платёжных данных.

## Когда нужна загрузка

Согласуй набор, аккаунт и папку, если этого ещё нет в запросе. Проверь свободную
ёмкость (`storageQuota.limit - storageQuota.usage`, общий расход сервисов).
Используй имеющийся upload-инструмент или браузер; scope проверки не расширяй
ради загрузки автоматически. Не заменяй существующий файл без отдельного
разрешения. После неоднозначного исхода сначала найди результат операции,
чтобы не создать дубль повтором; новую копию отличай от прежнего backup.

Основания Google, проверены 2026-10-18:
[поля File](https://developers.google.com/workspace/drive/api/reference/rest/v3/files),
[scopes](https://developers.google.com/workspace/drive/api/guides/api-specific-auth),
[Advanced Drive](https://developers.google.com/apps-script/advanced/drive),
[лимиты и стоимость](https://developers.google.com/workspace/drive/api/guides/limits).
