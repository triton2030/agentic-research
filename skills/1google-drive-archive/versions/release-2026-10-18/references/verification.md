# Проверка конкретной пары

## Связать наблюдения с оригиналами

До сравнения установи соответствие выбранного локального файла и облачного
ID, аккаунт и происхождение метаданных. Превью, экспорт Google Docs, proxy и
shortcut не являются бинарным оригиналом. Shortcut разрешается до target ID.
Локальный File Provider placeholder может скачаться при хешировании и занять
место; сначала установи, есть ли независимый локальный оригинал.

Основное доказательство — одинаковые SHA-256 и размер при стабильных
свидетельствах. Это практическая криптографическая проверка, а не буквальная
сверка потоков. Если владелец требует именно byte-for-byte, прочитай облачный
оригинал и сравни потоки при стабильной версии; заранее назови объём передачи.
Без SHA-256 можно получить и хешировать оригинал через доступ к содержимому.
MD5-only остаётся слабым совпадением и не допускает удаление последней копии
в этом архивном режиме.

## Свежая проверка встроенными средствами

Локальный `scripts/archive_verify.py` использует Python standard library,
не обращается к сети и не удаляет исходники. Его --help описывает команды.
В примере `archive_skill_root` — фактический каталог установленного скилла,
`archive_evidence_dir` — выбранная локальная папка доказательств.
Имена выходов должны быть новыми: существующий отчёт helper не перезаписывает.

1. Прочитай метаданные оригинала через действующий доступ.
   Для asset Apps Script задай FILE_IDS и выполни `metadataSnapshot`.
   Сохрани одну полную JSON-строку этого ID как `before.json`.
2. Выполни свежий локальный проход:

   ```sh
   python3 "$archive_skill_root/scripts/archive_verify.py" hash \
     --path "/absolute/path/to/original" \
     --out "$archive_evidence_dir/local.json"
   ```

3. Повтори облачный snapshot того же ID после локального чтения и сохрани
   `after.json`. Аккаунт, version, размер и хеш должны оставаться согласованы.
4. Сравни свидетельства:

   ```sh
   python3 "$archive_skill_root/scripts/archive_verify.py" compare \
     --local "$archive_evidence_dir/local.json" \
     --before "$archive_evidence_dir/before.json" \
     --after "$archive_evidence_dir/after.json" \
     --out "$archive_evidence_dir/result.json"
   ```

Helper проверяет SHA-256/размер и порядок времени вокруг стабильного чтения.
Он отклоняет неполные или лишние поля: неподдерживаемый ответ другого клиента
нужно явно нормализовать из настоящего источника, не заполняя пробелы догадками.
Локальные device/inode/size/mtime_ns/ctime_ns и realpath проверяются до и после;
symlink, пустой файл, смена пути или ошибка чтения не дают MATCH.

Нормальный stdout пустой, данные пишутся в выбранные JSON mode 0600.
Exit 0 означает LOCAL_HASHED или MATCH_SHA256; exit 2 требует чтения безопасного
статуса/кода причины. Выход compare всегда содержит `deleteAllowed=false`.
`restoreAccessConfirmed` означает только наличие соответствующих metadata flags,
а не выполненный тест восстановления. Связь отчёта с ID и временем не заменяет
достоверности входов: helper не авторизует и не подписывает чужой JSON.

## Кеш и повторный вызов

Сохранённые хеши используй для поиска кандидатов без повторного чтения всего
архива. Для текущего MATCH нужно новое чтение либо достаточное свидетельство
неизменности для данного filesystem: прежние и нынешние device/inode/size/
mtime_ns/ctime_ns и realpath согласованы. Один stat size/mtime из старого
аудита для этого недостаточен. Сомнение или изменение требует перечитать
только затронутый файл. Встроенный hash намеренно всегда читает файл заново.

Перед освобождением места повторно проверь ID/хеш/версию облака и локальное
состояние: между сравнением и действием файл не должен измениться.
Это практическая проверка стабильности, без блокировки записи другими
программами и без защиты от умышленной подмены всех свидетельств.

Если локальный экземпляр уже удалён по согласованному плану, сохрани прежний
MATCH как исторический и отдельно проверь нынешнюю сохранность облачного
архива по ID, размеру и хешу. При отсутствии старого доказательства исходного
содержимого нельзя восстановить локальное совпадение задним числом.

## Результат по файлу

| Статус | Основание |
| --- | --- |
| MATCH_SHA256 | Стабильные оригиналы совпали по SHA-256 и размеру |
| MATCH_BYTES | Потоки оригиналов сравнены непосредственно |
| MATCH_MD5_ONLY | Только MD5/размер; недостаточно для освобождения последней копии |
| CANDIDATE_DIFFERS | Стабильный кандидат отличается; другая копия ещё возможна |
| NOT_FOUND_IN_SCANNED_SCOPE | Полный датированный обход заявленной области не нашёл кандидата |
| UNVERIFIED | Не хватает доступа, данных, устойчивости или полного чтения |

В манифесте свяжи локальный путь и свидетельство чтения, облачный ID/аккаунт,
метод, времена наблюдений, статус, причину и файлы доказательств. Успех одного
файла не подтверждает связанные части или весь набор. Отдельно укажи свежесть
проверки и сохранность после локального удаления. Публикуй только безопасную
сводку, а полный перечень остаётся в выбранном локальном хранилище.

Основания Google, проверены 2026-10-18:
[контрольные суммы и version](https://developers.google.com/workspace/drive/api/reference/rest/v3/files),
[скачивание оригиналов](https://developers.google.com/workspace/drive/api/guides/manage-downloads).
