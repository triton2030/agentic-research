# Форма интервью для Obsidian

Читай при записи или обновлении интервью. Владелец отвечает последовательно,
поэтому смысл варианта и его чекбокс должны находиться рядом. Широкая таблица
с абзацами в ячейках заставляет заново искать варианты при каждом ответе.

## Каркас

```md
# Интервью: <тема>

Дата: <YYYY-MM-DD>. Статус: <ожидает ответов / частично разобрано / разобрано>.
Область: <предмет и будущая работа>.

Это запись для последующего обращения к архиву, а не действующие правила.
Актуальность ответов проверяется по текущим документам проекта.

Отметьте вариант или напишите свой ответ. Можно отвечать частями.
Когда закончите, напишите в чате «проверь».

## Вопросы к владельцу

<открытые вопросы>

## Ответы, найденные при исследовании

<ценные закрытые развилки, если есть>

<сноски с источниками>
```

## Открытый вопрос

Каждый вопрос — H3 с постоянной меткой Q01; поле ответа — H4 с той же меткой.
Ситуация перед выбором объясняет только неопределённость и её последствие.
Обычно для этого хватает короткого абзаца. Длинная предыстория, повтор цитат
и перечень всех затронутых файлов не нужны для самого выбора.

```md
### Q01. <Один понятный вопрос>

<Короткая ситуация: что неизвестно и чем различаются последствия выбора>.[^q01]

#### Ответ пользователя — Q01

- [ ] **A. <Самодостаточное название решения>.** <Когда полезно; чем придётся пожертвовать>.
- [ ] **B. <Самодостаточное название решения>.** <Когда полезно; чем придётся пожертвовать>.
- [ ] **Свой вариант:** …

**Рекомендация агента:** <выбор и короткое основание>.

**Комментарий или условия ответа:**

[^q01]: [Документ, раздел](<путь#раздел>) — <точное основание неясности>.
```

Число вариантов определяется реальными альтернативами. Формулируй каждый
как самостоятельное решение с сильной стороной и ценой; простое сокращение
до ярлыков теряет смысл. Рекомендацию не размножай в отдельные повторяющиеся
блоки «почему спрашиваем», «почему ваше решение», «что определит ответ».
Если выбор требует существенного условия, помести его рядом с вариантом.

До ответа все чекбоксы пусты. Для совместимых вариантов укажи «Можно выбрать
несколько»; иначе выбор один. «Свой вариант» не заменяет содержательную
альтернативу. Не дублируй варианты отдельным списком голых букв после таблицы.
Вертикальный список — обычная форма; компактная таблица допустима, если
сравниваются короткие однородные значения и она действительно облегчает выбор.

Источники подтверждают короткое объяснение, а не заменяют его. В сноске
достаточны точная ссылка и существенное расхождение или недостающее условие;
не прячь туда весь отчёт. Список исследованных файлов и служебные коды
проверок остаются в чате или материалах исследования. Сноски собери внизу
файла с уникальными метками. Используй обычный Markdown без HTML и плагинов.

## Найденный ответ

Сохрани H3, краткую ситуацию и содержательные варианты с их основаниями.
Замени H4 на `#### Найденный ответ — Q02`, отметь выбранный вариант. Поля
ниже добавляются после вариантов; новое поле «Ответ пользователя» не создаётся.

```md
**Основание выбора:** <что разрешило развилку>.[^q02]
**Авторство и дата:** <решение владельца / факт источника / вывод агента; дата>.
**Условия исходного ответа:** <существенная область и исключения>.

[^q02]: [Источник ответа](<путь#раздел>); [где проверить актуальность](<путь#раздел>).
```

Отвергнутый источником вариант обозначь как ранее рассматривавшийся.
Не выдумывай альтернативы ради сохранения служебной находки.

## Когда обрабатываешь ответы

Существующий дословный ответ владельца сохраняется в его поле. Добавь дату
и короткую отдельную заметку о результате обработки; если поручение включало
правку документов, назови результат ссылкой, иначе отметь неприменённость.
Такие ответы не переезжают в раздел найденных при исследовании.

Не повторяй прежнее обоснование, если ответ его не изменил. Новое существенное
условие или разногласие сохраняется рядом с ответом. Объём чтения, проверка
ссылок и ход работы остаются в чате, включая обработку архивной копии.
Пустые разделы и подсказки шаблона в готовый файл не входят.
