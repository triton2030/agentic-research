# План задачи — изолированный контракт исполнения

## Уникальный контекст

Файл задачи — изолированный промп одного агента в чистом окне: он сохраняет
принятое решение, условие остановки и несущий контекст, не забирая чужую работу.

## Цели владельца

- Одна утверждённая задача становится автономным промптом одного ответственного
  агента внутри одного актуального эпика; около 20 — сигнал проверить упаковку.
- Чистое окно исполняет, пересобирает или останавливает работу по файлу;
  изменившийся смысл возвращается в `1planning`.

## Поведенческий протокол

> «скилл задач — это скилл изолированности задач»
>
> «надо рассматривать каждую задачу как промп для агента»

1. Для новой задачи потребуй материальные решения `1planning`; для
   существующей считай записанный контракт принятым, пока новое доказательство не
   докажет смысловой разрыв.
2. Определи стадию и работай только с одним reference-файлом. Сначала создай
   или сверь [контракт](references/task-contract.md), затем запиши
   [цель и контекст](references/task-context.md) и
   [подзадачи](references/task-work.md). Продолжение, переплан и закрытие идут
   по [жизненному циклу](references/task-lifecycle.md), смена писателя — по
   [передаче](references/task-handoff.md), хранение/отсрочка/runtime — по
   [хранению](references/task-retention.md). До перехода запиши результат
   стадии.
3. Ответственный агент может делегировать ограниченную проверку, но помощник не
   принимает решения задачи и не правит контракт, а возвращает адресуемое доказательство
   в `_evidence/**`.

## Границы

Допуск и существенный переплан принадлежат `1planning`, правда эпика —
`1plan-map`; доступный только владельцу вопрос остаётся адресом
`1interview-tool`.
