# Стадия подзадач

Результат стадии — ближайший проверяемый путь одной задачи, а не второй план
внутри неё.

```markdown
## Подзадачи

- [x] <результат Execution или разрешимый агентом вопрос Wayfinding>

> [!note]- Отчёт
> статус <дата>: <где мы находимся>
> доказательство: <запуск, файл `_evidence/` или приёмка потребителя>
> решение: <решение через `1use-principles`, если было>
> <свободный результат и находки>

- [ ] <следующая подзадача>

> [!note]- Отчёт
> статус <дата>: <где мы находимся>
```

1. Каждая подзадача — один результат или разрешимый вопрос с одним
   доказательством. `[x]` требует адрес `доказательство:`.
2. `3–7` — эвристика упаковки, не схема ради схемы. Честно атомарная задача
   может иметь `1–2`; превышение семи требует поискать ось, но новый файл задачи
   появляется только при самостоятельной цели.
3. Подзадачи не забирают работу другой задачи или эпика. Собственный список
   действий сам по себе не делает работу отдельной задачей.
4. Execution ведёт к принятому результату; Wayfinding ставит следующий ход
   перед ранним дорогим расхождением. Туман остаётся в «Зачем», а доступный
   только владельцу вопрос — адресом `1interview-tool`.
5. Блок отчёта стоит без отступа сразу после флажка: иначе Obsidian показывает
   код вместо свёрнутого блока.
