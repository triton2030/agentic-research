# Cut — 1plan-task

## Сохранено

- одна утверждённая задача, один агент и один действующий автор;
- автономность файла без planning-чата;
- бюджет около 20 и «информация = сюрприз»;
- full approved entry, non-duplicate scope и frontier карты;
- relevant sources и редкие load-bearing строки;
- semantic break к `1planning`, epic truth к `1plan-map`;
- создание, продолжение, handoff, defer и closure.

## Добавлено в основное тело

- `_ops/plans` как единственный дом файлов задач;
- обязательные `Цель`, `Критерии успеха`, `Контекст`, `Состояние`, `Next` и
  `Stop`;
- отдельные условные маршруты в основном теле вместо скрытой lifecycle-логики.
- состояние и evidence, достаточные для чистого continuation/handoff;
- возврат evidence закрытия в `1plan-map` без записи карты из `1plan-task`.

## Не глобализировано из `mavo-short2`

- exact frontmatter schema;
- Wayfinding/Execution taxonomy;
- Canon/SPEC vocabulary и activation gates;
- Obsidian toggles, archive layout и название `task.md`.

## Agent-default chains

- Без `_ops/plans` локальный task рядом с кодом выглядит удобнее → появляется
  неучтённый mutable owner → карта и следующий агент его не находят → цена:
  один постоянный дом.
- Без явного минимального содержания слово «самодостаточный» выглядит
  достаточным → агент пишет подробные шаги без цели, evidence или boundary →
  чистое окно оптимизирует локальное выполнение → цена: шесть адресованных
  смысловых полей.
- Без route-разделения все lifecycle-условия выглядят одновременно активными →
  task prompt перегружается → агент пропускает текущий gate → цена: в каждом
  запуске применяется только названный маршрут того же основного тела.

## Финальная дельта проверки

- `20` явно остаётся сигналом перепаковки, а не автоматического split;
- create, continue и handoff оставляют долговечный след;
- любое human-visible изменение task-state возвращается владельцу карты.
