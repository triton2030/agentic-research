## Функция

Долговечный владелец одной утверждённой задачи и её обычного жизненного цикла
исполнения. Сериализует решения о допуске, но не принимает их, и запрашивает,
а не пишет события состояния эпика.

## Новые ограничения

- Обязательная `Цель` удерживает результат, эффект, главный провал и
  доказательство даже без дополнительных документов.
- Около 20 независимых смыслов — рабочий бюджет task-промпа. Превышение
  требует аудита упаковки; разделение допустимо только по реальной оси, а
  неделимый результат сохраняет число и причину.
- `критично помнить` маршрутизирует только релевантные источники и повторяет
  дословно лишь несущие строки: так адрес не превращается в свалку документов.
- Обязательная `ось:` переносит planning-срез между чистыми окнами.
- Смысловая граница «та же автономная цель внутри эпика, границы и authority»
  отделяет обычную пересборку от существенного переплана; отдельные поля служат
  диагностическими сигналами, а не исчерпывающим tuple.
- Событие состояния эпика запрашивается у `1plan-map`, поэтому у эпика один
  писатель.
- Contract, context, work, lifecycle, handoff и retention — самостоятельные
  стадии; в каждый момент открыт один reference, а результат сохраняется в
  task-файле.
- В каждый момент task-файл пишет один ответственный writer; authority может
  явно и последовательно перейти после reread/fresh-reader gate.

## Цена строгости

- **Обязательная цель:** default — агент исполняет локальные шаги вместо
  результата → механизм — результат, эффект, главный провал и evidence →
  вред — перегруженная фраза → цена — смыслы считаются отдельно и уточняются
  ниже, но цель остаётся самостоятельной.
- **Бюджет около 20:** default — файл пересказывает весь корпус → механизм —
  surprise-отбор и оценка у границы → вред — занижение счёта или искусственный
  split → цена — считать только близко/выше ориентира и разрешать
  `неделимо — <причина>` без реальной оси.
- **Критичный контекст:** default — агент не читает нужный источник или читает
  всё → механизм — точные адреса и несколько несущих строк → вред —
  planner может ошибочно отобрать источники → цена — чистый reader называет
  недостающий контекст.
- **Обязательная ось:** default — чистое окно угадывает основание декомпозиции
  → механизм — записанная planning-ось → вред — выдуманная ось для цельной
  работы → цена — допустим единый неделимый результат с явной причиной.
- **Смысловая граница:** default — scope creep после нового evidence → механизм
  — вопрос об автономной цели, эпике, границе и authority → вред — сложнее
  механической проверки пяти полей → цена — остальные поля остаются
  диагностическими сигналами, а решение фиксирует evidence разрыва.
- **Один ответственный агент:** default — task-файл получает нескольких
  владельцев → механизм — только один агент принимает решения и пишет контракт
  → вред — запрет полезной делегации → цена — bounded evidence-probes разрешены
  без task-authority.
- **Map-owned событие состояния:** default — два писателя эпика → механизм —
  запрос к `1plan-map` → вред — дополнительный handoff → цена — единый
  доказуемый writer.
- **Один reference на стадию:** default — агент загружает всю форму и lifecycle
  сразу → механизм — contract/context/work/lifecycle/handoff/retention → вред —
  больше переходов → цена — каждая стадия самостоятельна и записывает результат
  до следующей.
- **Последовательный writer:** default — concurrent writers расходят контракт →
  механизм — явная передача после reread/fresh-reader → вред — handoff дороже →
  цена — identity не пожизненная: ответственность может перейти.
- **Provenance-покрытие:** default — один общий адрес притворяется источником
  всех требований → механизм — `требование → источник` → вред — визуальный шум
  → цена — покрываются только неочевидные несущие требования, адрес сам по себе
  не входит в active set.

## Закрытые неверные прочтения

- «Само имя задачи заменяет цель» → форма требует самостоятельную `Цель`.
- «Я перечислю все документы на всякий случай» → контекстный бюджет оставляет
  только surprise-информацию и её эффект.
- «Двадцать bullets соблюдают лимит» → считаются независимые смыслы, а не
  форматирование.
- «Больше 20 всегда означает новую задачу» → требуется реальная ось; иначе
  записывается неделимость.
- «Траектория просит заново выбрать приоритет» → это квитанция принятого
  допуска.
- «Противоречащее evidence всегда можно пересобрать локально» → до пересборки
  проверяется смысловая граница задачи.
- «Закрытие задачи разрешает менять композицию эпика» → протокол 6 допускает
  только запрос map-owned события состояния.

## Маршруты

- использовать: `Теперь запиши утверждённый task-контракт.`
- использовать до классификации: `Появилось новое evidence текущей задачи.`
- использовать после классификации: `Границы держатся; пересобери подзадачи.`
- пропустить: `Evidence изменило принятую ось задачи.` → `1planning`
- near miss: `Обнови эпик после закрытия задачи.` → `1plan-map`
