# Схема файла задачи

Вход: ты создаёшь файл задачи, закрываешь его, откладываешь или правишь его поля.
Выход: файл, который дашборд видит, а следующий агент читает без чата.

Ключ, написанный по памяти, не ломает файл заметно: задача просто выпадает из
дашборда и перестаёт существовать для владельца, оставаясь на диске.

## Размещение и имя

1. **Файл задачи лежит внутри папки своего эпика — `_ops/map/эпики/<Эпик>/` —
   рядом с самим файлом эпика.** Колокация и есть структура, из-за которой
   создать задачу, не открыв эпик, физически невозможно.

2. **Файл называется именем задачи, а не служебным словом.** Соседние файлы
   различаются в списке только именами, и `задача.md` рядом с другой `задача.md`
   заставляет открывать оба, чтобы понять, какой из них твой.

## Frontmatter задачи

| Ключ | Что несёт |
| --- | --- |
| `тип` | `задача` — по нему дашборд отличает задачу от эпика |
| `эпик` | ссылка на владеющий эпик |
| `эпик-снимок` | отпечаток текста эпика на момент сверки |
| `траектория` | чем эта задача двигает критерий своего эпика |
| `режим` | род работы: разведка, исполнение и подобное |
| `статус` | из общего словаря |
| `порядок` | место среди задач эпика |
| `подзадач`, `подзадач-готово` | знаменатель и числитель процента задачи |
| `evidence` | доказательство результата |
| `обновлено` | дата последнего изменения |

Разделы тела: `## Зачем` — результат, условие входа, владелец результата,
обязательное чтение точными адресами, текущий факт · `## Принципы` ·
`## Подзадачи`.

3. **`траектория` называет связь с критерием эпика, а не пересказ задачи.**
   Задача, которая не двигает ни один критерий, читается полезной и не
   приближает закрытие ни одного эпика — а видно это только здесь.

4. **`эпик-снимок` берётся с текста эпика в момент сверки и не переписывается
   позже без новой сверки.** Он существует ровно затем, чтобы расхождение задачи
   с пересобранным эпиком было обнаружимо машиной; обновлённый «чтобы не мешал»
   снимок гарантирует, что расхождение не найдёт никто.

## Словарь статусов

✅ готово · 🔨 в работе · ◽ в очереди · 🔒 заблокировано · 🛑 затык · ⏳ отложено

5. **Словарём владеет схема карты, здесь он зеркалится.** Значение статуса меняют
   там; расхождение двух словарей делает дашборд нечитаемым быстрее, чем ошибка в
   отдельном файле.

## Подзадачи

> «мы не теряем вот эту логику Obsidian, то, что задачи должны иметь подзадачи, а
> отчеты по подзадачам должны быть спрятаны внутри тогл»

6. **Подзадача называет достигнутое состояние, а не шаг, который надо сделать.**
   По состоянию видно, случилось оно или нет; по шагу видно только, что его
   выполнили.

7. **Отчёт по подзадаче прячется внутрь свёрнутого блока.** Развёрнутые отчёты
   вытесняют с экрана цель и границу, и файл, из которого их не видно сразу,
   отказывает так же, как файл, где их нет.

8. **`подзадач-готово` растёт только вместе с записанным доказательством.**
   Собственный отчёт о выполнении доказательством не является: при выполненной и
   невыполненной работе он выглядит одинаково.

## Закрытие

9. **Закрывай задачу статусом `✅ готово` только по предъявленному доказательству
   целого результата, записанному в `evidence`.** Исчерпанный список подзадач
   доказывает исчерпание списка, а не достижение результата.

10. **Закрыв задачу, тем же ходом обнови в файле своего эпика `задач-готово` и
    его `evidence`.** Второго вызова не будет: если карта узнаёт о закрытии
    отдельным ходом, она узнаёт о нём тогда, когда кто-нибудь заметит расхождение.

11. **Закрытый файл задачи остаётся на месте, в папке своего эпика.** Он часть
    видимой истории проекта, и дашборд показывает его отдельным представлением, а
    не прячет.

## Отложение

12. **Откладывая задачу, поставь `⏳ отложено` и запиши в файле две вещи: почему
    отложена и при каком наблюдаемом условии в неё возвращаются.** Без причины
    отложенная задача неотличима от брошенной; без условия возврата она не
    вернётся никогда, потому что момент возврата не наступит сам.

13. **`⏳ отложено` — решение человека и старше выведенного `🔒 заблокировано`.**
    Иначе отложенная задача показывается заблокированной, и владелец ищет
    несуществующий блокер.
