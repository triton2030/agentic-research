# План задачи

## Уникальный контекст

Файлы задач живут под `<project-root>/_ops/plans`.
Один файл задачи — автономное поручение одного агента.
У файла задачи один действующий автор.
Около `20` активных единиц — бюджет упаковки одной задачи.
Превышение — сигнал пересобрать упаковку, а не автоматическое основание делить
целый результат.
Информация в файле равна сюрпризу: ожидаемое знание не вытесняет несущие
условия результата.

## Цель пользователя

Один автономный файл ведёт одного действующего автора к целому утверждённому
результату, не затрагивая соседнюю работу.

## Обязательное содержание файла

- `Цель` называет целый результат, его пользу и границу соседней работы.
- `Критерии успеха` называют доказательство целого результата.
- `Контекст` даёт точные адреса только релевантной правды.
- Несущие строки, которые исполнитель вероятно пропустит, повторяются дословно.
- `Состояние` сохраняет выполненную работу и её доказательства.
- `Next` называет ближайший самостоятельный ход.
- `Stop` называет условие остановки и возврата решения владельцу.

Смысловой разрыв возвращается в `1planning`.
Правда эпика остаётся у `1plan-map`.
Любое доказанное изменение task-state, меняющее человеческую карту, передаётся
`1plan-map`.
`1plan-task` не редактирует карту.

## Маршруты

> «я хочу, чтобы агент обязательно перед работой над задачей или перед
> созданием задачи обязательно проверил карту эпиков и обязательно проверил,
> насколько эта задача ограниченная.»

### Создание или пересборка

1. Прими только утверждённый пакет с одним результатом, границей работы,
   доказательством целого результата и критичным неожиданным контекстом.
2. Прочитай текущие карту и эпик под `<project-root>/_ops/map`.
3. Прочитай соседние файлы задач под `<project-root>/_ops/plans`.
4. Убедись, что работа принадлежит допущенному эпику и не пересекается с другой
   задачей.
5. При недопустимом входе остановись и верни решение в `1planning`.
6. Запиши или пересобери task-файл со всем обязательным содержанием.

### Продолжение или возобновление

1. Считай существующий файл задачи долговечным входом вместо исходного чата.
2. Перечитай файл задачи, текущие карту и эпик и соседние файлы задач.
3. При доказанном смысловом дрейфе остановись и верни решение в `1planning`.
4. После работы обнови `Состояние`, доказательства и `Next`.

### Передача автора

1. Новый автор без записи перечитывает файл задачи, карту, эпик и соседние
   файлы задач.
2. Новый автор называет `Next` и `Stop`.
3. Прежний автор явно передаёт полномочия, после чего новый становится
   единственным автором.
4. Запиши в task-файл нового действующего автора и факт передачи.

### Отложение или закрытие

1. При отложении сохрани причину и условие повторного входа.
2. Закрывай файл только по доказательству целого результата.
