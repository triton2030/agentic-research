# Схема файла задачи

Вход: ты создаёшь или пересобираешь файл задачи, закрываешь или откладываешь
его, правишь его поля или подзадачи.
Выход: файл, который дашборд видит, прибор карты сверяет, а следующий агент
читает без чата.

Схема — конвенция, снятая с работающего проекта и по решению владельца общая
для всех проектов; здесь — форма и обязательный состав разделов, а чем
наполнять их по смыслу, говорят Цель и Критерии принятия тела скила.

Пересмотреть, если проект держит планы не под `_ops/map` или живёт без
Obsidian: тогда этот файл описывает мир, которого в проекте нет.

## Размещение и имя

- Файл лежит внутри папки своего эпика — `_ops/map/эпики/<Эпик>/` — рядом с
  файлом эпика и остаётся там после закрытия, где его показывает представление
  «Завершённые задачи». Колокация и есть структура, из-за которой создать
  задачу, не открыв эпик, невозможно; в общую папку планов задача не выносится.
- Файл называется именем задачи, а не служебным словом: соседние файлы
  различаются в списке только именами.
- Новый файл — копия [`task-template.md`](task-template.md) с заполненными
  плейсхолдерами: шаблон несёт ключи, порядок и состав разделов и форму
  отчёта, и написанное по памяти с ним не совпадает.

## Frontmatter

| Ключ | Что несёт |
| --- | --- |
| `тип` | `задача` — по нему дашборд отличает задачу от эпика и вопроса |
| `эпик` | ссылка на владеющий эпик |
| `эпик-снимок` | хеш эпика, который печатает прибор карты |
| `траектория` | чем эта задача двигает критерий своего эпика |
| `режим` | `execution` либо `wayfinding` — словарь прибора |
| `статус` | из общего словаря |
| `порядок` | место среди задач эпика |
| `подзадач`, `подзадач-готово` | знаменатель и числитель процента задачи |
| `evidence` | доказательство результата целого |
| `обновлено` | дата последнего отчёта по подзадаче |

- `эпик-снимок` печатает и сверяет прибор карты проекта — в `mavo-short2` это
  `python3 scripts/check-map.py --hash "<Имя эпика>"`. Алгоритм принадлежит
  прибору: пересчитанный по описанию хеш не сойдётся с ним никогда. Прибора у
  проекта нет — поле не заводи: невоспроизводимая сверка останавливает
  исполнителя ложно, и после второго раза он начнёт «освежать снимок, чтобы не
  мешал».
- Снимок пишет тот, кто перечитал эпик и сверил с ним задачу, и не переписывает
  его позже без новой сверки: обновлённый «чтобы не мешал» снимок гарантирует,
  что расхождение не найдёт никто.
- `траектория` называет связь с критерием эпика, а не пересказ задачи: задача,
  не двигающая ни один критерий, читается полезной и не приближает закрытие.

## Разделы тела

Порядок: `## Задача` · `## Зачем` · `## Цель` · `## Критерии приёмки` ·
`## Принципы` · `## Подзадачи`; прибор карты проверяет наличие и порядок, а
состав каждого раздела держит шаблон.

## Словарь статусов

✅ готово · 🔨 в работе · ◽ в очереди · 🔒 заблокировано · 🛑 затык · ⏳ отложено

- Словарём владеет схема карты — `1plan-map`, его `references/epic-schema.md`;
  здесь он зеркалится, а значение статуса меняют там: расхождение двух
  словарей делает дашборд нечитаемым быстрее, чем ошибка в отдельном файле.
- `⏳ отложено` — решение человека и старше выведенного `🔒 заблокировано`:
  иначе отложенная задача показывается заблокированной и владелец ищет
  несуществующий блокер.

## Подзадачи

> «мы не теряем вот эту логику Obsidian, то, что задачи должны иметь подзадачи, а
> отчеты по подзадачам должны быть спрятаны внутри тогл»

- Подзадача называет достигнутое состояние, а не шаг: по состоянию видно,
  случилось оно или нет; по шагу видно только, что его выполнили.
- Отчёт по подзадаче — свёрнутый callout по форме шаблона сразу под ней; вместе
  с `[x]` и строкой `доказательство:` растёт `подзадач-готово`. Развёрнутые
  отчёты вытесняют с экрана цель и границу.
- Подзадач у задачи от трёх до семи — решение владельца; прибор это
  проверяет, и состояние-фикция ради счёта решение не выполняет.

## Закрытие и отложение

- Закрывая задачу статусом `✅ готово`, тем же ходом обнови в файле эпика
  `задач-готово` и `evidence`: владелец меряет остаток по знаменателю, который
  иначе разойдётся с папкой; прибор считает оба поля производными и снимок
  эпика от них не меняется.
- Создав задачу, тем же ходом впиши её в эпик — `задач` и `задачи`.
- Откладывая задачу, поставь `⏳ отложено` и запиши в файле, почему отложена и
  при каком наблюдаемом условии в неё возвращаются: без причины отложенная
  неотличима от брошенной, без условия момент возврата не наступит сам.
