# Схема файла задачи

## Задача

Оформи создаваемую или изменяемую задачу и связанные поля эпика по принятой конвенции.

## Цель

Дашборд видит файл задачи, его форма сохраняет контракт и состояние, а прибор карты при наличии может сверить снимок и счётчики.

## Зачем

Ключи и формат отчёта нужны машине, разделы — следующему исполнителю. Они уже заданы шаблоном, а смысл содержания — критериями тела скилла. Повторное сочинение формы по памяти создаёт похожий файл, который читается и проверяется иначе.

## Файл и шаблон

- Задача лежит в `_ops/map/эпики/<Эпик>/` рядом с файлом эпика: принадлежность видна в дереве файлов.
- Имя файла — имя задачи, чтобы соседние задачи различались без открытия.
- Закрытая задача остаётся там же: представление «Завершённые задачи» сохраняет для владельца видимый результат.
- Новая задача создаётся заполнением [шаблона](../assets/task-template.md): он задаёт ключи, порядок разделов, подзадачу как достигнутое состояние и свёрнутый отчёт сразу под ней. Эти части уже находятся в выходном файле, поэтому их не требуется заново воспроизводить по описанию.

## Значения полей

| Ключ | Что несёт |
| --- | --- |
| `тип` | `задача` — по нему дашборд отличает задачу от эпика и вопроса |
| `эпик` | ссылка на владеющий эпик |
| `эпик-снимок` | хеш эпика, который печатает прибор карты |
| `траектория` | чем эта задача двигает критерий своего эпика |
| `режим` | `execution` либо `wayfinding` — словарь прибора |
| `статус` | из общего словаря |
| `порядок` | место среди задач эпика |
| `подзадач`, `подзадач-готово` | знаменатель и числитель процента задачи |
| `evidence` | доказательство результата целого |
| `обновлено` | дата последнего отчёта по подзадаче |

## Снимок эпика

- Значение `эпик-снимок` печатает прибор карты проекта; в `mavo-short2` это `python3 scripts/check-map.py --hash "<Имя эпика>"`. Алгоритм принадлежит прибору: вычисление по словесному описанию не гарантирует совпадения и создаёт ложную тревогу.
- Без прибора поле не заводится: невоспроизводимый снимок не даёт проверяемой сверки.
- Каждая запись снимка означает, что записавший перечитал эпик и сверил с ним задачу: обновление хеша ради снятия ошибки скрывает несовместимость. Это относится и к первой записи, и к замене значения.

## Статусы

✅ готово · 🔨 в работе · ◽ в очереди · 🔒 заблокировано · 🛑 затык · ⏳ отложено

Словарь зеркалит владельца `1plan-map/references/epic-schema.md`; изменение значений принадлежит владельцу, иначе две половины карты начинают говорить на разных языках.

- `⏳ отложено` — решение человека: исполнитель не подменяет своим бездействием его выбор.
- Отложение старше выведенного `🔒 заблокировано`: иначе владелец ищет несуществующий блокер.

## Подзадачи и связи

- Подзадач от трёх до семи — принятое ограничение владельца; фиктивное состояние ради числа не делает задачу выполнимой.
- Отметка подзадачи и её `доказательство:` отражаются в `подзадач-готово` тем же ходом: иначе отчёт и процент показывают разные результаты. Форму отчёта уже содержит шаблон.
- Созданная задача тем же ходом включается в `задач` и `задачи` эпика: иначе новая работа есть на диске, но отсутствует на карте.
- При закрытии `✅ готово` тем же ходом обновляются `задач-готово` и `evidence` эпика: иначе доказанный результат не уменьшит показанный остаток. Эти поля производные и не меняют снимок эпика.
- Отложенная задача содержит причину и наблюдаемое условие возврата: без причины она неотличима от брошенной, без условия возобновление зависит от памяти разговора.
