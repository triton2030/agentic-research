## Волна 1 — два независимых читателя

Роли: действующие `1skill-creation/agents/check-instructions.md` и
`check-trajectory.md`. Оба прочитали один неизменный draft:

Ниже решения автора по terminal-возвратам; сами возвраты доступны в текущем
разговоре Codex. Прогнозы читателей не считаются выполненными пробами.

| Находка | Решение и правка |
| --- | --- |
| Оба: `needs the owner's method` позволяет не открыть скилл | Принято: прямой триггер создания/пересмотра, без предварительного суда о нужности метода |
| Траектория: «бюджет — ориентир» ослабляет жёсткий контракт носителя | Принято: бюджет задаёт контракт; научный предел из договорённости не выводится |
| Буква: шесть маркеров скрывают около 32 смысловых единиц | Принято: число маркеров не является счётом; убраны повторные разъяснения, независимо нарушимые предложения начинаются с новой строки |
| Буква: отсутствуют следы применения отдельных различений | Принято: таблица ниже связывает различение с доступным артефактом |
| Буква: свойства ещё не имеют опровергающих результатов | Принято: структурный validator не доказывает поведение; практическая проба запрашивается отдельно |

Отклонённых находок нет. В первой записи автор ошибочно заявил, что владелец
не диктовал последовательности. Вторая буквальная проверка нашла прежние слова:
«любое управление агентов должно начинаться с двух вещей. Контекст и цель» и
«далее в инструкциях мы пишем только дельту»
(`2026-08-31-160620-claude-97782077.md:43`). Уточнение принято: последовательность
сохранена как порядок формирования смысла — мир и результат до оставшейся
дельты. Порядок разделов нового скила определяется более поздним решением
2026-09-02 15:19:25 (`2026-09-02-151925-claude-0c84f259.md:23`): Задача, Цель,
Зачем, Критерии. Сам документ science/how-to-command-agents-with-text.md уже
различает эти порядки в поправке 2026-09-02. Прежний способ не удалён и
универсальный порядок заголовков из него не выведен.
Уточнение К2 снимает лишнее требование запускать отдельного читателя при каждом
применении: метод требует проверяемой приёмки результата, а проверка нового
скилла на реальном случае принадлежит его созданию. Сравнительная проба дорогого
снятия остаётся в модели «Зонтик».

## Следы применения знания

| Различение | След, который может прочитать владелец/проверяющий |
| --- | --- |
| Контекст берётся из мира владельца | Фрагмент готового текста сопоставим с исходной репликой/фактом; выдуманного предпочтения нет |
| Цель и контекст дополняют друг друга | В тексте назван результат и влияющий на него факт; отдельный список не повторяет их следствия |
| Контекст нужен до выбора | Вход читателя включает факт или открытый источник до первого зависимого решения; одна ссылка без чтения не является trace |
| Работа отличима от результата | Раздел цели содержит желаемое состояние; конкретный маршрут не записан целью |
| Подъём не сочиняет основание | Неизвестное желание остаётся явно неизвестным в выходном тексте/вопросе |
| Achieve / Maintain | При уже выполненном условии выход не требует повторного действия; период поддержания следует из входа |
| Сломанный джин | Конкретный плохой результат отвергается названным условием и доступным свидетельством |
| Зонтик | Сохранённый скрытый факт или критическая граница в выходе; для дорогого удаления — реальные сравнимые действия с ним и без него |
| Дельта и причина | Невыводимое условие и его последствие видны рядом в итоговом тексте |
| Активная нагрузка | Счёт имеет перечень одновременно применимых обязательств; перенос файла не уменьшает его автоматически |
| Бюджет носителя | Выход соблюдает заданный бюджет либо называет конфликт, не превращая требование в рекомендацию |
| Предел научного вывода | В пакете нет универсальных процентов/порогов; источники и инженерный перенос различены |

Это спецификация evidence, а не утверждение, что все следы уже получены.

## Структурная проверка

`quick_validate.py skills/1agent-steering/draft` после первой версии и после
правки: `Skill is valid!`. Внутренних reference-ссылок в live-кандидате нет;
два внешних источника открыты web-инструментом 2026-09-05. Пакет не требует
локальных путей, чтения science либо вызова соседних авторингов.

Firecrawl Developer Index нашёл Stencila Software Design Creation и
agent-layer Skill Design Guide: это прецеденты наблюдаемых критериев и
самодостаточного скилла, но ни один найденный фрагмент не заменяет весь
заказанный владельцем метод. Поиск не доказывает отсутствия любых аналогов.

## Уточнение владельца после двух волн

Текущая роль скилла — изучение науки и её видимое применение в последующем
авторинге. Задача, Цель, Зачем и критерий изменены по второй реплике текущего
разговора; один научный reference читается целиком при вызове. Карта смыслов
сохранена в [cut.md](cut.md).

Проверка по точным байтам:

- Шесть тем науки, научная оговорка и условие пересмотра дословно совпадают
  с блоком знания первой версии; изменено только размещение.
- Оба прежних критерия управляющего текста дословно сохранены в конце reference.
- Новый критерий проверяет именно связь знания с решением в чате; общая цитата
  без этой связи его не закрывает.
- Внутренние ссылки разрешаются, путей к текущему проекту в пакете нет,
  description — 181 символ, `quick_validate.py` возвращает `Skill is valid!`.

Предварительный редакционный счёт автора: тело около 9 единиц, научный
reference около 18. Это не счёт маркеров: в теле один критерий, но он содержит
несколько связанных условий предъявления. Оба файла обязательны при вызове;
их совместная нагрузка не уменьшается от переноса знания в reference.

Фальсификатор нового критерия проверен на текущей правке автором: положение
«Без такого препятствия отдельный критерий не нужен: он повторит цель»
сопоставлено в чате с оставленным в теле критерием против пересказа без
применения. Адресуемые результат и объяснение есть; это не независимая проба.

Старые четыре выхода остаются evidence содержания научного блока, который
не менялся; они не проверяли новую обязанность полного чтения reference и
объяснения по ходу авторинга. Новый независимый прогон не проводился. Две
волны уже завершились; лимит проверки не обнулялся по имени новой версии.
Установка и подключение остаются неприменёнными.

## Уточнение контекста по третьей реплике

Сверены текущий reference, шаги 0–1 и поправка 2026-09-02 документа
`science/how-to-command-agents-with-text.md`, раздел «Цель выбирает контекст;
контекст заземляет цель» в `how-to-command-with-goal-not-procedure.md`.
В источниках уже были дельта относительно читателя, принципы из мира и
наблюдение владельца об объяснённой важности. В reference первое и третье
свойства оказались недостаточно явными; абзац Контекст обновлён по новой реплике.

Прямой след: «дельта к знанию конкретного читателя»; «самому вывести рамки и
принципы поведения»; происхождение, важность цели и последствия названы прямо;
командирское намерение уточняет состояние и закрывает оставшиеся лазейки.
Новое знание и важность как управление вниманием названы рабочей моделью
владельца. Статус отдельного причинного эффекта «почему» не повышен: в
`how-to-make-llm-obey.md:667` на момент чтения он отмечен как не изолированный.

Механическая проверка выполняется для текущих байтов и оставшегося научного
блока. Поведенческая сила нового абзаца независимо не измерена; прежняя
дословная эквивалентность абзаца Контекст больше не заявлена. Новых проверяющих
после двух волн не вызывали. Science и другие скиллы не изменялись.
