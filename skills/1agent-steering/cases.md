# Практические входы

Синтетические случаи проверки, не факты или решения владельца проекта.
Результат упражнения — четыре готовых управляющих текста, а не прогнозы.

## План задачи

Владелец хранит единственный архив фотографий в `originals/`. Работа допущена:
сделать миниатюры в `previews/` только для партии из 12 файлов, перечисленных в
`batch.txt`. Originals изменять нельзя. Читатель получит этот контекст вместе с
файлом плана. Напиши смысловые разделы плана: Задача, Зачем, Цель и необходимые
Критерии. Не требуется выполнять обработку фотографий.

## GOAL

Владелец готовит демонстрацию портфолио трём заранее выбранным дизайнерам через
две недели. Работает один; материал уже есть; хочет проверить понятность
презентации, а не спрос. Его решение: показывать на имеющейся платформе, без
разработки сайта и без оплаты. Модель монетизации неизвестна и пока не
выбирается. Напиши короткую цель, scope, done и stop для файла GOAL.

## Папочная инструкция

Папка `ui/` выглядит написанной вручную, но это полностью генерируемая
проекция `schema/screens.yaml`. Команда генерации — `make ui`. Прямые правки
пропадут при следующей генерации. Напиши папочную инструкцию для агента,
который приходит исправлять экран; исходное правило «пиши чистый код и помни
про компоненты» недостаточно. Содержимое schema корректно; экран уже совпадает
с ней. Владелец просит поддерживать соответствие, а не менять экран сейчас.

## Новый скилл

Владелец хочет скилл подготовки решений из стенограммы встречи. Он не видел
встречу и будет по записке поручать работу. Слова участника «можно попробовать»
не означают принятое решение. Авторство решения должно быть восстановимо по
цитате и отметке времени в стенограмме, а если решения не было, записка должна
это показывать. Напиши смысловую часть скилла в порядке Задача, Цель, Зачем,
Критерии принятия; процедурного протокола владелец не заказывал.
