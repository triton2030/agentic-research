# Preservation map — accepted exact candidate 2026-08-30

## Сохранено по смыслу

- Root остаётся CTO, orchestrator и владельцем business/end-to-end decision;
  receiver остаётся bounded contributor.
- Receiver определяется обращением root через этот route; owner-launched session
  не получает receiver role автоматически.
- Receiver prompt сохраняет `# Контекст` → `# Цель`, recursion boundary и
  situational constraints по concrete harm.
- Native reference сохраняет managed/launch-only, Luna/max, evidenced Sol,
  Local-first, unresolved overlap, fresh same-topic reuse, writer-only
  verification и observed lifecycle.

## Core после compression

Core содержит пять separately violable units:

1. Root как CTO/orchestrator владеет business/end-to-end решением.
2. Receiver — task, к которому root обратился через этот route.
3. Owner-launched session остаётся на ordinary progress/terminal path.
4. Receiver assignment вызывает read `receiver-message.md`.
5. Native operation вызывает read `codex-native.md`.

Mode, model, environment, reuse, launch, verification и lifecycle удалены из
core. Typed `THREAD_CARD`, typed `THREAD_DONE`, predicate labels и отдельные
stage-files не возвращены.

## Semantic unit table

Receiver-message и native surface не активны одновременно. В native surface
действуют core, общая truth и только текущее решение; завершённый выбор
становится state, а не вторым активным checklist.

Launch содержит взаимоисключающие create/fork/continue/reuse operation paths;
count берёт самый большой path, а не складывает невозможные одновременно
operations. Остальные branch gates считаются отдельно, если их можно нарушить
независимо.

## Counterfactual harm

| Surface | Вред без неё |
| --- | --- |
| Central ownership | Локальный receiver принимает business/topology решение вместо root. |
| Receiver identity | Owner-launched session ошибочно получает receiver role и recursion constraints. |
| `receiver-message.md` | Receiver теряет current truth или начинает управлять fleet. |
| Shared native truth | Controller выдумывает operation либо путает docs с live schema. |
| Mode | Handle выдаётся за outcome либо literal launch перегружается orchestration. |
| Route | Возникают prestige Sol или лишний Worktree без evidence. |
| Reuse | Follow-up уходит в неоднозначный, queued, archived или stale thread. |
| Launch | Nonblocking handle принимается за outcome либо unpinned state не проверяется. |
| Managed closure | Progress принимается за terminal, writes — по self-report, archive — до acceptance. |
