# Намерение — 2026-09-02

## Функция

По запросу владельца переносить исполнение и выработку вариантов в видимые
тематические задачи Codex, оставляя головному агенту работу CTO: пользу,
связность, выбор решения и приёмку. Отдельный буквальный запрос только на
создание или fork заканчивается подтверждённым запуском.

## Уникальный контекст

Видимые задачи Codex сохраняют тематический опыт. Головной агент отвечает за
пользу и связность общего решения. Запрос на фоновые задачи означает передачу
им исполнения и разработки вариантов. Лично открытые владельцем сессии
остаются самостоятельными. Механикой задач владеют текущие инструменты Codex
и официальная документация OpenAI.

## Задача

Организуй запрошенную работу видимых фоновых задач Codex и доведи её до
заказанного владельцем исхода.

## Цель

Работа распределена по посильным темам, а головной
агент удерживает пользу, связность решений и приёмку, минимально исполняя сам.
Подходящая тематическая задача переиспользуется с актуальными источниками
проекта, сохраняя пользу накопленного опыта.
Владелец получает подтверждённый запуск, если просил только запустить задачу,
либо проверенный общий результат или точный наблюдаемый блокер при поручении
работы под управлением головного агента.

## Критерии принятия

- Передача работы подтверждена доступными владельцу незакреплёнными задачами
  и их поручениями; идентификатор подготовки не объявлен готовой задачей.
- Изменённые артефакты приняты по независимой от автора проверке самого
  результата; для ответа без изменений такая проверка записи не требуется.
- При продолжении задачи её выводы соотнесены с актуальными файлами и
  решениями; источники проверки доступны принимающему агенту.
- Поручения сохраняют ограниченную ответственность исполнителя, а итоговый
  выбор остаётся головному агенту; принадлежность к одному проекту не делает
  самостоятельную сессию подчинённой.
- Итог управления подтверждён состоянием задач: разовая работа архивирована
  после приёмки и интеграции, тематическая задача сохраняется до завершения
  всей её темы; при блокере названо, что препятствует продолжению.

## Типы целей и отрицание

| Цель / тип KAOS | Листовые состояния | Отрицание и след |
| --- | --- | --- |
| Распределение — Maintain | Исполнители несут посильные темы; головной агент удерживает выбор и приёмку. | Головной агент делает всё сам либо исполнители присваивают общий выбор. Поручения и наблюдаемые результаты читает головной агент и владелец. |
| Полезный опыт — Maintain | Та же тема переиспользуется; актуальные sources старше прежних выводов. | Новый дубликат без причины либо устаревшие выводы принимаются за правду. Источники в продолжении проверяет принимающий агент. |
| Заказанный исход — Achieve | Ready-задача при launch-only; принятый общий результат либо наблюдаемый blocker при managed. | Queue/progress/self-report назван успехом; writer принят без внешней проверки; тема архивирована преждевременно. Читатель — головной агент/владелец, evidence — ответ инструментов, артефакт и независимая проверка. |

Пустого отрицания нет: каждому из пяти критериев соответствует наблюдаемый
способ получить формальное выполнение без желаемого результата.

## Граница текущей среды

На 2026-09-02 `create_thread` создаёт отдельную видимую задачу только по
явной просьбе пользователя. В Git-проекте его default — Worktree, Local
разрешён по явному запросу работы непосредственно в сохранённом проекте.
Модель задаётся при явном запросе пользователя. Эти ограничения инструмента
старше предпочтений скилла; совпадение общей цели не заменяет авторизацию.

Рефактор скилла не является запросом запускать видимые задачи. Проверяющие
субагенты текущего рефактора вызваны по протоколам `1chat-recall` и
`1skill-creation` и не подменяют продуктовую функцию скилла.
