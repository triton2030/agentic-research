# Нативные возможности Codex

## Уникальный контекст

Этот скилл работает с видимыми задачами приложения Codex. Наличие функции в
App Server ещё не означает, что она доступна через инструменты этой сессии.
Официальная документация объясняет возможности, текущая callable schema
задаёт имена, параметры и ограничения вызовов.

## Задача

Выполни нужную операцию над видимой задачей с настройками владельца и установи
её фактический результат.

## Цель

Запрошенное действие выполнено доступными средствами Codex с согласованными
затратами и рабочей копией, а головной агент располагает наблюдаемым
результатом для дальнейшего управления.

## Критерии принятия

- Проект и задача определены по результатам инструментов; продолжение
  тематической задачи опирается на её прочитанное состояние и актуальные
  источники.
- Готовность, завершение, закрепление и архивность подтверждены отдельным
  чтением состояния; возврат операции изменения сам по себе этого не доказывает.
- Если требуемый путь недоступен, названо конкретное ограничение инструмента;
  подмена видимой задачи субагентом или выдуманный вызов успехом не считается.

## Настройки владельца

Модель:

> Контекст такой, то что когда я вызываю этот скилл, я хочу, чтобы мы вызывали именно дешевых Луна МАКС. Это именно в протоколе скилла должно быть. Но по дефолту. Но в случае, если задача действительно сложная, то можно сменить на сол экстра хай или сол медиум.

На проверенной схеме `Luna/max` — `gpt-5.6-luna` с `thinking: max`,
а Sol — `gpt-5.6-sol` с `thinking: medium` или `xhigh`.
- Выбор Sol требует конкретного основания сложности сверх возможностей Luna.

Рабочая копия:

> Ветки должны быть только в крайнем случае, когда агенты доказано будут работать с одними и теми же файлами. Если файлы раздельны, то можно доверять агентам то, что они не будут случайно редактировать файлы друг друга, потому что есть инструкции, которые мы пишем этим агентам.

След этих решений — выбранные `model`, `thinking`, `environment` и основание
исключения.

- Пересечение, устранимое разделением ответственности за файлы, не требует
  Worktree.

Текущие ограничения инструмента старше настроек выше. У `create_thread`
модель задаётся только при явном выборе владельца; Git-проект по умолчанию
использует Worktree, а Local — при явном запросе работы непосредственно в
сохранённом проекте. У проекта без Git используется Local. Предпочтение
скилла не подменяет требуемую инструментом авторизацию.

## Карта операций

Имена ниже относятся к `mcp__codex_app`.

- Перед вызовом сверь параметры с доступной схемой.

| Нужно | Инструмент |
| --- | --- |
| Выбрать сохранённый проект | `list_projects` |
| Найти задачу и увидеть закрепления | `list_threads`; для архива — `list_archived_threads` |
| Прочитать контекст задачи | `read_thread` |
| Создать отдельную задачу | `create_thread` |
| Ответвить завершённую историю | `fork_thread` |
| Передать новое поручение | `send_message_to_thread` |
| Дождаться результата или запроса внимания | `wait_threads` |
| Вернуть задачу из архива или архивировать | `set_thread_archived` |
| Убрать закрепление своей фоновой задачи | `move_thread_to_sidebar_section` с `sectionId: null` |

- Создание и fork требуют явной просьбы владельца о новой задаче. Успешный
  запуск ещё не означает, что порученная работа завершена.

- `clientThreadId` означает подготовку; операции с параметром `threadId`
  доступны только после наблюдаемого готового идентификатора.

Fork копирует завершённую историю и не переносит текущий незавершённый ход.
- Если работа должна продолжиться в копии, ей нужно отдельное поручение через
  `send_message_to_thread`.

- Для ожидания используй `wait_threads` с возвращённым cursor как
  `afterCursor`; это сохраняет наблюдение без повторного чтения тех же
  завершённых ответов. Прогресс не является завершением.

## Официальные источники

Проверены 2026-09-02. При изменившейся возможности источником её семантики
служит текущая страница, а точного вызова — доступный инструмент:

- [Codex App Server](https://learn.chatgpt.com/docs/app-server) — жизненный
  цикл разговора и хода, чтение и архивация.
- [Long-running work](https://learn.chatgpt.com/docs/long-running-work) —
  связанная работа в одном контексте и наблюдаемый результат.
- [Worktrees](https://learn.chatgpt.com/docs/environments/git-worktrees) —
  рабочие копии, перенос задачи и очистка после архивации.
