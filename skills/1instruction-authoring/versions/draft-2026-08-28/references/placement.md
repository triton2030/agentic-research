# Выбор поверхности

Вход: спорно, в каком файле или слое должно жить правило — корень, папка,
скил, хук — или как оно доедет до агента.

- Выбирай не самый заметный слой, а самый дешёвый из тех, что гарантированно
  достигают первого решения, которое правило должно изменить:

| Surface | Admission |
| --- | --- |
| root | cross-task Delta, нужная большинству задач scope |
| folder | Delta поддерева |
| skill | опознаваемый момент; допустим риск, что routing не сработает |
| hook/schema/validator/test | hard invariant или детерминированное действие |
| plan | состояние одной длинной работы |
| chat prompt | невыводимая Delta текущей задачи |
| canonical owner | изменяемое значение |
| nowhere | модель быстро выводит смысл сама |

- Проза не является enforcement: «всегда делай» остаётся просьбой до тех пор,
  пока корректность не удерживается механизмом.
- Резидентная поверхность платит вниманием на каждой задаче; допуск на неё
  требует одновременно четырёх условий: смысл применим к большинству задач
  scope · он не выводится быстро из репозитория и задачи · он меняет
  наблюдаемое действие или проверку · сравнение вариантов доставки
  «нет/всегда/по случаю» оправдывает её на целевой модели соразмерно риску.
- Универсального числового порога не существует; бюджеты держат владельцы:
  бюджет скила — пакет `1skill-creation`, бюджет любого файла инструкций —
  тело `1instruction-authoring`, раздел «Форма каждого файла инструкций».
- Считай цену по траектории представительной задачи — владелец этого счёта
  данный файл: сколько обязанностей активно в каждой точке решения · сколько
  решений, фаз и границ compaction переживает постоянный смысл · какие
  конфликты и прецеденты уже создал ассистент · сколько контекста загружено,
  включая вывод инструментов · как повторно доставляется или проверяется
  жёсткий инвариант.
- Длинный одноразовый список может оказаться дешевле нескольких правил,
  обязательных всю большую работу; время по часам само по себе ничего не
  измеряет, а чужой benchmark — это evidence, но не порог.
- Различай authority и conditioning: прежний текст ассистента и состояние
  инструментов нормой не владеют, но создают прецедент — формально старшая
  строка может проигрывать накопленной траектории.
- Ориентировка размещается по частоте обращения и тоже платит цену контекста:
  если она нужна позже или в узкой зоне — доставляй её позже или ниже.
- Уже сказанное в применимой цепочке — system/root, папочных файлах по пути,
  пересекающемся скиле, покрывающем хуке или активном плане — чинится у его
  владельца; второе правило рядом не добавляется.

Выход: решение развилки места — вернись в прерванную стадию.
