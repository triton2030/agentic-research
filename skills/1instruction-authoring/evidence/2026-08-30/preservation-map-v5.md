## Командирский замысел

Инструкция доставляет невыводимую внешнюю правду до первого зависимого решения,
потому что компетентный агент обычно понимает свою зону, но теряет связи за её
границей. Смысл остаётся у одного владельца; инструкция выбирает своевременный
маршрут и доказывает пользу без перегрузки или закрытия законного пути.

Основания владельца:

- `_ops/chat-recall/2026-08-28-193846-claude-76aa0843.md:18-20,31-33` —
  инструкции как когнитивные маршрутизаторы межзонной правды, а не учебник зоны.
- `_ops/chat-recall/2026-08-28-193846-claude-76aa0843.md:22,28-29,36-37` —
  сохранять полезную функцию через higher-order intent, не склеивать независимые
  правила ради счётчика и экономить смыслы, а не буквы.
- `_ops/chat-recall/2026-08-29-163434-codex-01a04d4a.md:20-22` — русский body
  и references, короткие английские trigger descriptions, цель и контекст прежде
  выводимых процедур, локальная цель у самостоятельного reference.
- `_ops/chat-recall/2026-08-29-184951-codex-01a04dbd.md:19` — будущую
  изменённую версию нельзя устанавливать без нового exact approval.

## Поглощённые и разделённые процедуры

- Старый `zones.md` поглощён root-router и самостоятельным `zone-scout.md`:
  число разведчиков выводится из неизвестных рёбер и не задаётся буквальным
  ритуалом «один на каждую соседнюю папку».
- Старый `assembly.md` разделён между `placement.md`, `graph.md` и `wording.md`,
  потому что выбор поверхности, semantic ownership и формулировка являются
  разными моментами решения.
- Старый `probe.md` разделён на `trial.md` и `acceptance.md`, чтобы наблюдение не
  смешивалось с желаемым вердиктом и активный режим оставался ограниченным.
- Явные слова `plan` и `hook` из старого budget-счётчика поглощены общим правилом
  считать все применимые старшие слои и сохраняющиеся обязательства; неполный
  перечень больше не задаёт ложную границу.
- Отдельный пробник для каждой строки `Нерушимо:` удалён как вредная буквальность.
  Acceptance требует покрыть дорогой целевой случай, соседний путь, законную
  альтернативу и долгую траекторию; непокрытый claim не получает `pass`.

## Обоснование оставшихся hard lines

| Hard line | Почему её нельзя надёжно вывести только из цели |
| --- | --- |
| Один reference текущей стадии | Это критический порядок загрузки; общий preload воспроизводит устраняемую перегрузку. |
| `no-change`, `fail` и `unknown` запрещают official write | Без терминального следа агент по привычке продолжит авторинг или установку. |
| Неизвестный owner/edge требует bounded read-only scout | Граница полномочий и защита от confirmation bias не выводятся из предметной цели. |
| Сначала цель и уникальный контекст | Это подтверждённый владельцем порядок refactor, не профессиональный дефолт. |
| Точные CLI/API/schema, safety/authority, critical order и falsifying acceptance сохраняются | Эти классы содержат невыводимую механику, власть или доказательство. |
| Active path считается атомарно; превышение нельзя прятать по файлам | Владелец прямо отверг склейку независимых предикатов ради числа. |
| Matched pair меняет только instruction-tree и не получает ожидаемый ответ | Без контроля переменной наблюдение не доказывает причинность. |
| Самоотчёт не является evidence | Это невыводимая граница доказательства. |
| Official write требует unchanged positive candidate и unconditional exact approval | Поздняя коррекция владельца прямо запрещает выводить разрешение из прежней установки. |
| Tracked owner first, existing projections, byte/link parity | Это project/runtime schema, неизвестная общему агенту. |

## Применённые authoring-режимы

- FAST и Zero-based design: `commander-intent.md` задаёт функцию, «почему» и
  уникальный контекст; clean-room исполнитель не видел прежний пакет.
- Commander intent: каждый самостоятельный содержательный reference имеет
  локальные `Уникальный контекст` и `Цель`.
- Trigger authoring: frontmatter descriptions и Codex `short_description` —
  короткие английские `Use when...` без workflow summary.
- Behavior protocol: literal hard lines ограничены authority/safety/schema,
  critical order и falsifying acceptance.
- Reference architecture: root маршрутизирует к одной самостоятельной стадии;
  reference-файлы не требуют друг друга.
- Agent defaults: scout получает только невыводимую дельту — bounded scope,
  отсутствие предполагаемого ребра, evidence/inference, coverage, stop и
  authority boundary.
- Codex UI: сохранены существующие `display_name`, implicit invocation policy и
  `$1instruction-authoring` в `default_prompt`.
