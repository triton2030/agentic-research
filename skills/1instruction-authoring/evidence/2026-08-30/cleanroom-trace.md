# TRACE — clean-room candidate

## Методы

### Clean-room Reimplementation

Единственным смысловым входом был `commander-intent.md`. Кандидат выведен с
нуля из базовой функции, уникального контекста, слов владельца и трёх целей.
Старый пакет, history, projections, live copies и соседние смысловые источники
не читались и после записи не сравнивались.

### Zero-based Design

Рассмотрены три состава:

1. Только `SKILL.md`. Это минимально по файлам, но превращает редкую глубокую
   проверку и межзонную разведку в постоянную когнитивную нагрузку.
2. `SKILL.md` и один reference проверки. Это сохраняет узкий обычный путь, но
   оставляет разорванные зоны без воспроизводимого read-only поручения.
3. `SKILL.md`, самостоятельный reference проверки и самостоятельный prompt
   разведчика. Этот вариант выбран, потому что два редких механизма активируются
   независимо и не дублируют командирский замысел.

Отдельные reference или agent не создавались ради длины основного файла. Оба
вынесенных файла имеют локальную цель и применимы самостоятельно.

## Почему выбран такой состав

- `SKILL.md` содержит весь обычный маршрут: границу решения, карту доставки,
  выбор минимального механизма, порядок переписывания и критерии сдачи.
- `references/decision-probes.md` нужен только при существенном маршруте или
  приёмке; он делает критерий «улучшилось решение» наблюдаемым и
  фальсифицируемым.
- `agents/external-truth-scout.md` нужен только для разорванных зон или дорогого
  контекста; он возвращает evidence, не присваивая владение и решение.
- `platforms/codex/agents/openai.yaml` не создан: пакет не требует отдельной UI-
  поверхности, runtime-команды или Codex-специфичного default prompt для
  выполнения функции.

## Active-set counts

Единица подсчёта — директива, инвариант, gate или обязательное поле результата,
которое можно исполнить либо нарушить независимо от соседнего. Пояснения без
самостоятельного требования не считаются. Условная ветвь считается только на
пути, где её условие сработало; общий gate считается, если путь обязан его
проверить. `TRACE.md` не управляет runtime-путём и в denominator не входит.

Пути предполагают известного владельца и отсутствие материальной развилки;
поэтому ветви M20–M21 и M30–M32 не входят. В successful probe расходящиеся
ветви R25, R26 и R60 не срабатывают.

Эти числа — диагностическая мера применимого смысла, а не потолок. При
изменении операционных файлов line-addressed denominator и суммы должны быть
пересчитаны заново.

## Проверка фальсификаторов

- Обычный путь не требует reference или agent prompt: удержан.
- Опоздавшая доставка объявлена отказом, а probe фиксирует порядок открытых
  источников и первого решения: удержан.
- Маршрутизатору запрещён самостоятельный пересказ истины: удержан.
- Acceptance требует два свежих контрастных запуска и негативный сценарий;
  самооценка без них даёт `unknown`: удержан.

## Gaps

- Кандидат не выполняет автоматическое обнаружение владельцев: точный источник
  зависит от реального проекта и доступных средств чтения.
- Контрастный probe не запускался на конкретной проектной инструкции, потому что
  clean-room задача материализует пакет, а не применяет его к целевому проекту.
- Runtime-валидатор frontmatter или конкретный registry-check не задан входом;
  выполнены только доступные структурные и механические проверки пакета.
- Доставка через subagent зависит от наличия read-only делегирования в runtime;
  при его отсутствии основной агент должен пройти тот же узкий маршрут сам.
- Для базового пути теперь наблюдаемы 55 активных семантических единиц, но нет
  эмпирического evidence, достаточно ли это мало для реальной когнитивной
  нагрузки; файловый count ошибочно скрывал этот риск.
