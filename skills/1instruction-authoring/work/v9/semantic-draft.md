# Смысловой черновик — 1instruction-authoring v9

Выход `refactor.md` «После нового намерения» §1. Построен от
`work/v9/commander-intent.md` методами **Clean-room reimplementation** и
**Zero-based design**.

## Отступление от протокола, влияющее на доверие к этому файлу

Чистого окна не было: сессия несёт правило «не вызывать Agent без просьбы
владельца», а владелец её не дал. Черновик писал тот же агент, который читал
старый пакет и разбирал его механику. Компенсация частичная — при построении
структуры старый пакет не открывался, и его файлы читаются заново только на
стадии проверки потерь. Гарантия clean-room не выполнена; считать её
выполненной нельзя.

## Какие стадии обязаны существовать

Ведёт функция: доставить в момент входа в зону то, чего агент в ней не увидит.
Обратный ход от неё даёт цепь, в которой каждое звено обслуживает следующее.

| Звено | Почему без него функция не выполняется |
| --- | --- |
| предсказание поведения | размещать нечего, пока неизвестно, куда агент придёт; истории решений в проекте нет, значит источник только цели проекта |
| объявленное разделение | размещение корня и папок — одно решение; принятое по частям, оно даёт либо дубликат, либо дыру |
| размещение и связывание | «всегда актуально» — в корень, остальное в папку со ссылкой оттуда, где агент об этом должен узнать |
| деление зон | папка без своей темы не заводит инструкции; порог деления — длина, а не структура репозитория |
| форма единицы | забывание идёт поединично, значит единица должна нести свой смысл целиком |
| бюджет и объединение | 20 единиц на файл; переполнение чинится подъёмом уровня, а не вырезанием |
| проход маршрутом | единственная проверка, что доставка действительно случилась |

## Что в скил не входит

- как работать внутри зоны — прямо исключено целями;
- инвентаризация существующих файлов вместо предсказания поведения;
- отдельный режим для личной глобальной инструкции владельца;
- механика подгрузки инструкций конкретным runtime.

## Форма пакета

Один файл. Семь шагов протокола и два всегдашних правила — девять
самостоятельных единиц против лимита в двадцать, поэтому reference-файлы не
нужны и `references/reference-files.md` не открывается. Отдельный файл несёт
только Codex UI metadata, инструкций не содержит.
