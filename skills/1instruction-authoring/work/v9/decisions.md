# Решения допуска — 1instruction-authoring v9

Выход `references/behavior-protocol.md`. Вход: commander's intent готов,
смысловой черновик написан.

## Шаг 1. Что выводится из намерения и потому не стало инструкцией

| Кандидат | Чем уже покрыт | Сито |
| --- | --- | --- |
| «внутри инструкции должна быть написана цель» | цель 2 требует, чтобы агенту было видно, зачем файл существует; написанная цель — единственный способ это дать | подразумевается целью |
| «не пиши, как работать в зоне» | цель 3 прямо называет это неуспехом, Уникальный контекст — «не учебник работы в зоне» | подразумевается целью и контекстом |
| «не дублируй одну правду в нескольких файлах» | цель 3 называет дубликацию неуспехом, шаг 3 даёт механику пересылки | подразумевается целью |
| «не экономь символы» отдельной строкой | Уникальный контекст: счёт по единицам, а не по символам; хвост шага 5 повторяет это в действии | подразумевается контекстом |
| «инструкции проекта — файлы, которые агент читает при входе» | конвенции корневых и папочных файлов инструкций известны передовой модели | очевидно модели |
| «отметь, что нельзя нарушать ни при каких условиях» | цель 2 требует именно этого результата | подразумевается целью |

## Шаг 2–3. Как чистый агент прочитает добавленное неверно

| Неверное прочтение | Пробел | Цена правки |
| --- | --- | --- |
| «ориентировка, где лежит важное» → каталог всех папок репозитория в корне | нет критерия размещения | шаг 3: «актуальна всегда при вообще любой работе» |
| «предскажи поведение» → инвентаризация существующих файлов и их переписывание | не назван источник предсказания | хвост шага 1: список файлов показывает устройство, а не поведение |
| «слой не должен расти» → вырезание существующих инструкций | нет разрешённого способа сокращения | шаг 8: объединение вверх с проверкой выводимости частностей |
| доставка не случилась → добавляется ещё одна инструкция | не назван класс дефекта | хвост шага 9: недостаёт ссылки, а не инструкции |
| «20 единиц» → пересчёт всех строк файла | единица не определена | шаг 6: единица — отдельная инструкция или ограничение |
| корень и папки пишутся по очереди | решение размещения принимается по частям | шаг 2: разделение объявляется в чате до первой строки |

## Шаг 4. TWI Job Instruction по найденному разрыву

Разрыв лежит между подготовкой и проверкой, а не внутри действия: агент умеет
писать текст, но не знает, от чего отталкиваться и чем убедиться.

- Подготовка — шаг 1: источник предсказания назван, потому что истории решений в
  проекте нет.
- Ключевой момент — шаги 2 и 3: единственный тест размещения «актуальна ли
  всегда при вообще любой работе», объявленный до письма.
- Действие — шаги 4–8: деление зон, форма единицы, бюджет, объединение.
- Проверка результата — шаг 9: проход маршрутом предсказанной задачи; отказ
  чинится ссылкой.

## Шаг 5. След выполнения, который нельзя подделать пересказом

| Шаг | Неподделываемый след |
| --- | --- |
| 1 | названная в чате конкретная задача и маршрут агента по ней — на неё ссылается шаг 9 |
| 2 | текст разделения в чате, датированный раньше первой правки файла инструкций |
| 3 | в корневом файле не найдётся строки, неактуальной для названной задачи; на каждую папочную есть ссылка из точки входа |
| 4 | названа папка без своей инструкции и причина, по которой она её не получила |
| 5 | дословная цитата из середины написанного файла, в которой видно «зачем · что делает · почему важно запомнить» |
| 6 | число единиц по каждому файлу |
| 7 | ни одна инструкция файла не лежит внутри абзаца |
| 8 | перечислены снятые частности и вывод каждой из объединяющей инструкции |
| 9 | путь агента адресами ссылок от точки входа до внешнего файла |
| правило | отклонённые кандидаты с названным ситом — таблица шага 1 этого файла |

## Сглаживание устной речи владельца, требующее его согласия

`behavior-protocol.md` запрещает сокращать и перефразировать дословный текст
владельца без его согласия. Ниже всё, что изменено при переносе устной речи в
письменный текст скила; смысловых снятий нет.

| Владелец сказал | В скиле |
| --- | --- |
| «Корневые инструкции должны быть такие, которые актуальны всегда при вообще любой работе» | «Корневые инструкции — те, которые актуальны всегда при вообще любой работе» |
| «нельзя думать про корневую инструкцию, отделенную от папочной инструкции… нужен шаг какого-то такого понимания, которого он напишет в чат, что писать в корневую инструкцию, а что писать в папочной инструкции» | «Напиши в чат, что писать в корневую инструкцию, а что писать в папочной инструкции, прежде чем написать хоть строку любой из них: нельзя думать про корневую инструкцию, отделённую от папочной» |
| «Папочные инструкции не должны создаваться абсолютно в каждой папке» | «Папочные инструкции не создавай абсолютно в каждой папке» |
| «сами файлы инструкций тоже не должны иметь больше 20 единиц инструкции» | «Держи каждый файл в пределах 20 единиц» |
| «одна инструкция должна объяснять, зачем она существует коротко, что она делает и почему это важно запомнить» | «Пиши каждую инструкцию так, чтобы она коротко объясняла, зачем она существует, что она делает и почему это важно запомнить» |
| «мы можем инструкции объединять в инструкции более высокого уровня, которые подразумевают выполнение инструкции более низкого уровня» | «инструкции нижнего уровня сворачиваются в инструкцию более высокого уровня, которая подразумевает их выполнение» |
| «надо предугадать, как агент себя будет вести, отталкиваясь от целей проекта» | «Прочитай, что проект объявляет своими целями, и предугадай по ним, как агент будет себя вести» |
