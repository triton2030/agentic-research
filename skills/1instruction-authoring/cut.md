# Cut — 1instruction-authoring

2026-08-31, candidate v8 по структурной коррекции владельца:

- `Границы решений` заменены главным `Протоколом поведения`: восемь шагов
  образуют когнитивный порядок, и каждый следующий начинается с результата
  предыдущего.
- `verification.md` оставлен единственным reference, но сужен до одной
  самостоятельной стадии с явными входом и выходом; установка больше не
  смешана с причинной проверкой.
- Terminal write не вырезан: authority, owner-first sync и parity перенесены в
  последний условный шаг основного протокола.
- Новые стадии, references и agent-файлы не добавлены; scout и metadata
  сохранены без изменения байтов.

2026-08-30, candidate v7 по terminal verification contract repair-task:

- Четырёхфайловая runtime-форма v6 сохранена без новых стадий и references.
- Перечень trial-процедур заменён одним `single-blind matched controlled trial`
  с общим immutable manifest; это сохраняет blind/same-settings causal gate,
  не превращая его в каталог полей и шагов.
- Authority привязана к вычислимому идентификатору всего пакета: смена любого
  байта создаёт нового кандидата, а прежние `pass` и approval его не покрывают.
- Target, long retention и lawful non-use сведены к двум наблюдаемым cases;
  подробный trace и самоотчёт больше не являются самостоятельными условиями
  pass.
- Installation boundary осталась условной внутри того же reference и не
  активна при проверке candidate; отсутствие отдельного разрешения прямо
  запрещает установку в текущем ходе.

2026-08-30, candidate v6 по критерию simplest sufficient runtime:

- Восемь runtime-стадий `intent / placement / assembly / wording / budget /

  без него остаются конкретные риски ложной причинности, active overload,
  unauthorized write и расходящихся projections.
- `zones.md` снят как orchestration bureaucracy; отдельный `zone-scout.md`
  сохранён, потому что без чистого независимого окна автор подтверждает
  подсказанное межзонное ребро.
- Точный allowlist CLI/API/schema, safety/authority, critical order и
  falsifying acceptance сохранён: эти классы нельзя вывести из предметной цели.
- Механическое умножение references ради лимита active set прямо запрещено;
  runtime-пакет сокращён до `SKILL.md`, одного reference, одного agent contract
  и обязательной Codex UI metadata.

2026-08-29, draft v4 по утверждённому аудиту:

- Потолок «двадцать строк в каждом файле» и перенос переполнения в новый файл —
  формально позволяли спрятать тот же активный набор по нескольким носителям;
  заменены счётом всей применимой цепочки в точке решения.
- Жёсткие 500 символов для «Цели» и «Контекста» — конфликтовали с более поздним
  правилом «экономить смыслы, не буквы»; заменены тремя полными предложениями
  цели и самодостаточным минимальным контекстом.
- `Прочитай свою зону целиком` — не имело границы покрытия и противоречило цели
  загружать только необходимое; заменено точечным поиском semantic owners и
  adversarial-проходом по соседям.
- Candidate-пробник без baseline — показывал возможность, но не причинное
  изменение поведения; заменён matched baseline/candidate.
- Режим одного правила начинал со сборки и пропускал admission; теперь он
  проходит суженный «Замысел», а разведку пропускает только при доказанных
  рёбрах.
- Обязательное обратное ребро для каждой зависимости — могло раздувать общих
  владельцев декоративными ссылками; обратное ребро осталось только там, где
  изменение владельца требует действия потребителя.
- Reference-файлы без собственной цели — заставляли держать процедуры вместо
  commander's intent; локальная цель теперь владеет выводимыми действиями.
- Одновременное подключение `placement.md` или `wording.md` внутри другой
  стадии — нарушало независимость режимов; каждый режим теперь закрывается
  адресуемым выходом до открытия следующего.
- Неявное действие при нерешённом вопросе владельцу — допускало и остановку, и
  догадку; сборка продолжает только по evidence, а вопрос сохраняет как gap.
- Безусловная запись tracked owner, двух проекций и installed-копий была
  допущением текущего проекта; завершение теперь следует ownership-контракту
  проекта и не выдумывает отсутствующие проекции.
- Статический счёт «один пункт равен одной единице» скрывал составные условия;
  отдельная стадия бюджета считает каждый независимо нарушимый предикат и
  возвращает overload gap, если старшие слои уже исчерпали потолок.
- Поле `next` в каждом reference-файле — превращало самостоятельные стадии в
  последовательную цепочку и накапливало их инструкции в контексте; весь
  stage-routing возвращён единственному владельцу `SKILL.md`.
- Surprise-самоотчёт чистого агента в «Замысле» — дублировал причинный пробник
  и мог отклонить полезный кандидат по недоказанному описанию; admission
  сохраняет абляцию и вред, а causal delta принадлежит `probe.md`.
- Повторный approval после успешного gate снят для текущего exact candidate:
  безусловное разрешение уже дано в текущем разговоре; общий скил по-прежнему
  запрещает менять адреса без покрывающей точный пакет authority.
