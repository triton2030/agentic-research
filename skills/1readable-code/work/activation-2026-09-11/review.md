# Проверка границ двух скилов — 2026-09-12

## Заказ и метод

Утверждённый план: сохранить два скила, включать по существенному выбору,
развести требования по моментам применения, снять обязательную делегацию и
общий отчёт. Работа выполнена без субагентов по прямому поручению владельца.
Основание: [выбор владельца](../../../../_ops/chat-recall/2026-09-11-235250-codex-01a091cf.md#L17).
Авторский метод: дельта к сильному агенту и минимальный одновременно применимый
набор из `1agent-steering/references/steering-science.md`.

Ниже — самостоятельный разбор точных текстов до и после, а не наблюдение
исполнения другим агентом. «Применимо» означает вывод из условия в тексте;
реальное распознавание этого условия моделью не измерялось.

## Сценарии

| Вход и существенные обстоятельства | Старая редакция | Новая редакция: применимость и текущая нагрузка | Проверка текста |
| --- | --- | --- | --- |
| Исправить опечатку в сообщении, меняется один литерал | readable-code вызывается перед любой правкой; тело просит соразмерности | Оба скила пропускаются. Обычная работа агента без стратегического отчёта | Условие routine local edits исключает этот случай |
| Передать явный limit=20 вместо уже действующего значения по умолчанию, один потребитель, поведение прежнее | readable-code обязателен; смена сигнатуры или контрактное решение допускают codebase-design с общим отчётом | Оба пропускаются: обязанности, знания потребителя и восстановление не меняются существенно | Маленькая сигнатурная правка сама по себе не триггер |
| Три команды независимо держат одно правило; решить, оставить копии или передать ответственность общему модулю | Оба скила; пять оснований новой границы двусмысленны; полный Working Output | readable-code оценивает цену следующей правки; codebase-design сравнивает новую границу с текущей формой. Варианты сравниваются, если остаётся существенный выбор; reference зависимости не нужен | Одного достаточного основания с учётом цены достаточно; все пять не обязательны |
| Клиент удалённого сервиса повторяет запрос после таймаута; требуется определить, кто предотвращает дубли эффекта | Обязательства названы, но общий отчёт и обязательный falsifier не различают поведение и прогноз | codebase-design + зависимости: владелец восстановления, неоднозначный исход, свойства двойника. После реализации проверяются изменённые риски. readable-code нужен только при отдельном стратегическом выборе | Знание о последствиях повторов не потеряно; двойник не доказывает сетевые свойства |
| После оценки решено оставить локальный алгоритм: нового потребителя нет, гипотетическая смена реализации не оправдывает адаптер | Сохранение формы разрешено, но Working Output требует объяснить выбранную seam и её преимущества | Решение сохранить форму завершает выбор новой границы. Короткая причина достаточна; при отсутствии изменения реализации её тестовый этап не включается | Нет обязанности описывать несуществующий новый интерфейс |

Второй сценарий дополнительно рассмотрен как замена сигнатуры с передачей того
же явного значения в единственное вызывающее место: итог такой же. Изменение
поведения восстановления даже в одной строке, напротив, является существенным;
размер diff не принят за критерий включения.

## Пересечение и переходы

- Подход к расположению реализации меняет будущую стоимость, но внешний
  контракт остаётся прежним: readable-code применим самостоятельно.
- При выборе границы ответственности оба скила могут быть применимы. Первый
  не требует вызова второго; второй не вызывает первый при стабильном контракте.
  Повторного стратегического отчёта нет.
- Сравнение закончено после выбора. При реализации остаются выбранные
  обязательства; сравнение не повторяется без новых обстоятельств.
- Проверка реализованного изменения относится к изменённому поведению и рискам.
  Прогноз области будущей правки обосновывается её сценарием и затронутыми местами,
  а не успешным результатом поведенческих тестов.

## Разбор сохранности

Сохранены стратегический взгляд, названия знакомых методов без учебника,
приоритет безопасности и корректности; простая форма, владение, сведения для
потребителя, правомерность внутренних тестов, реальность эффектов и ограничения
двойников. Карты изменений: [readable-code](../../cut.md),
[codebase-design](../../../1codebase-design/cut.md).

Уточнение, внесённое при проверке: reference сравнения вариантов перенесён из
случая новой границы в случай определения контракта. Иначе он пропускал бы
существенный выбор между уже существующими контрактами.

## Доставка и ограничения

YAML, длины descriptions, ссылки и побайтовое совпадение проекций проверены:
[квитанция с SHA-256](validation.json). Исходники readable-code синхронизированы
в tracked и installed Claude/Codex; codebase-design установлен только в Codex.
Снимки обоих итоговых пакетов — `versions/installed-2026-09-12/` у каждого скила.
Самостоятельный Claude `codebase-design` не входит в изменение.

Поведенческие прогоны и независимая приёмка не выполнялись по принятому плану.
Применение условий в длинной реальной сессии и добавочная польза относительно
работы без скилов остаются непроверенными. Прежние поведенческие результаты
в истории относятся к прежним байтам и не перенесены на эту редакцию.
