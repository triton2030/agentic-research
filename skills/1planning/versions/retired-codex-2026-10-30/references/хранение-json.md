# Хранение плана в JSON

Вход: в `_ops/plans/` проекта лежат `epic - …json`, `task - …json`
и `вопросы/….json`. Такой проект переведён в дашборд разработки
(`~/Documents/My_projects/dev-dashboard`): владелец смотрит план там,
Bases и Markdown-записей нет. Смысл полей, разделов, статусов и роутера —
прежний, из [формы планов](форма-планов.md); здесь — хранение, команды
и проверка. `check_plans.py`, `--sync` и Markdown-шаблоны к такому проекту
не применяются.

## Запись

- Адреса: `эпики/<Эпик>/epic - <Эпик>.json`, `эпики/<Эпик>/task - <Задача>.json`,
  `вопросы/<Вопрос>.json`.
- ID записи: `<Эпик>`, `<Эпик>/<Задача>`, `вопросы/<Вопрос>`. ID пункта —
  `<ID записи>#<метка>`; метка хранится в записи и не меняется от правки,
  вставки и перестановки пунктов.
- Шапка — прежние ключи; ссылки на записи — ID вместо wikilink. Производных
  полей нет: `задач`, `задачи`, `задач-готово`, `подзадач`,
  `подзадач-готово`, `эпик` считает загрузка.
- Пункт: `текст` — первое предложение, `подробности` — следующие, по одному
  на элемент, `сноски` — источники. Ссылки — Markdown с путём от папки
  записи, и в файлах `plan edit` и `plan new` тоже; ссылка на запись плана
  ведёт к её `.json`. Шаг «Порядка» ссылается на работу
  `[Имя](<task - Имя.json#цель>)`.

## Команды

Полный список — `plan --help`. Команда работает из любой папки проекта и без
запущенного дашборда; `--root` задаёт корень копии в `/tmp`.

| Нужно | Команда |
| --- | --- |
| Прочитать запись или пункт, дать исполнителю снимок | `plan show <ID> [--out <файл>]` |
| Найти пункт по тексту | `plan grep <текст>`: ID пункта и строка |
| Отметить выполненную проверку «Готово, когда» | `plan check <ID пункта>`, все проверки записи — `plan check <ID> --все`; основание — в сообщении коммита |
| Закрыть работу | `plan set <ID> статус=готово evidence="…"`: evidence пишется только при закрытии, статус — без эмодзи; `evidence+="…"` дописывает часть через «; » |
| Другое поле шапки, например порядок | `plan set <ID> поле=значение …` |
| Поправить текст одного пункта | `plan set '<ID пункта>' текст='…'`, следующие строки пункта — `подробности='…'`; текст — как печатает `plan show '<ID пункта>'`: ссылки от корня, метки сносок; сноску потерять нельзя; `=-` читает значение со ввода |
| Показать в дашборде след работы — задание, отчёт, аудит, критику | у эпика `plan set '<Эпик>' папка=<рабочая папка от корня>`; работе принадлежат файлы с её названием или с её номером последним числом имени; номер — `порядок`, иной — поле `номер-работы` |
| Узнать до браузерного прогона или замера, что идёт сейчас | `plan runs`: прогоны без строки «закончен», жив ли их процесс, нагрузка Mac |
| Переписать текст записи | `plan edit <ID> --out <файл.md>`, правка файла, `plan import <файл.md>` |
| Новая запись | `plan new … --out <файл.md>`, заполнение, `plan import <эпик.md> <работа.md>` |
| Ссылка на запись из Markdown | `plan link <ID>` |
| Проверка | `plan validate` |

Каждая запись атомарна. Команда отказывает, если файл изменился после
чтения, и откатывает правку, которая даёт новую ошибку проверки. Поэтому
JSON руками не правят: метки ID и экранирование ломаются молча. В файле
`plan edit` метки `{…}` в начале пунктов — их ID: при правке их не трогают,
у нового пункта метки нет. Новую работу загружают вместе с эпиком, где она
стоит шагом «Порядка»: одна она проверку не пройдёт. `plan new` ставит
`порядок: 1` — сверь его с местом шага в «Порядке».

## Ссылки

Ссылка из Markdown на запись — адрес дашборда, его печатает `plan link`:
`[Имя](<http://localhost:5191/<проект>/e/<Эпик>/t/<Задача>>)`; на раздел —
`plan link '<ID>#<раздел>'`, на пункт — `plan link '<ID пункта>'` с адресом
`…?block=<ID пункта>`: дашборд раскрывает раздел и показывает пункт. Владелец
открывает его из Obsidian, `plan show` принимает его вместо ID, проверка
ссылок с `--offline` его не открывает. Старая ссылка на
`…/task - <Задача>.md` означает запись `<Эпик>/<Задача>`.

## Проверка

`plan validate` проверяет то же, что [форма планов](форма-планов.md#проверка):
поля, разделы, связи, порядок, размер роутера, ссылки и якоря из текста
записей; сверх того — повтор ID пункта. Код 0 — механика прошла, 1 — ошибка
данных. Полноту роутера и истинность evidence она не доказывает. Незакрытая
задача прежней формы здесь — ошибка: её переписывают роутером.
