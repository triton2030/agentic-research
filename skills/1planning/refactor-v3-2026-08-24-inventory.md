# Инвентарь смыслов v2 → v3 (провенанс рефактора)

Каждый смысл v2 назван с судьбой; «умирает» всегда несёт причину словами
Founder-а (recall `_ops/chat-recall/2026-08-24-130300-claude-7756c5b8.md`).

## Умирает

| Смысл v2 | Причина смерти |
| --- | --- |
| Папка задачи с `task.md`+`status.md`+`context.md` | «слишком разрослось на множество файлов, агенты множество файлов не читают» |
| `status.md` и его поля `вех-готово`/`вех-всего`/`состояние` | статус переезжает в отчёты подзадач и frontmatter задачи |
| `context.md` отдельным файлом | «файлы контекста… теперь будут просто в описании задач» |
| `modules/` как единица планирования | «у модулей я не понимаю, какой модуль, по какому порядку»; «они не должны жить в файлах планирования» |
| Вехи задачи (2–5) | заменены подзадачами-чекбоксами (3–7) со счётчиками скрипта |
| `рамки` во frontmatter эпика | «раздел про принципы… внутри эпиков и задач всегда должны быть» — переезд в тело |
| Запрет вычисляемых формул прогресса | Founder 2026-08-24: «видеть именно в процентах» — вычисляемая формула из счётчиков законна; запрет остаётся только на ручной процент |
| Колокация «файл эпика рядом с папкой» | «переместить файл эпика внутрь папки Эпика» — folder note |

## Живёт без изменений

commander's intent и «цель, которую нельзя понять иначе, чем правильно» ·
режимы Wayfinding/Execution и цикл корректировки (modes) · ось разреза и
«только до ближайшего проверяемого фронтира» (decompose) · конверты-вопросы
целиком (questions) · словарь статусов · «эпик не удаляется, ✅ навсегда» ·
полоса по порядку как ответ «сколько осталось» · происхождение требований ·
«один Next» · гейт «да» владельца до файлов · перечитка эпика до
material-шага · `эпик-снимок` пишет перечитавший, прибор сверяет ·
file-disjoint и проверка воркеров свежим прогоном · «самоотчёт — не
свидетельство» · cold-start-проверка · бюджет тела эпика 60 строк ·
Shape Up-слоты (аппетит, no-gos) · tracer bullet и правила создания карты.

## Живёт в новой форме

| Смысл v2 | Форма v3 |
| --- | --- |
| Контракт задачи (7 разделов task.md) | один файл, три раздела: Зачем (замысел+происхождение+«верно, пока») · Принципы · Подзадачи |
| Гейт сверки задача↔эпик (снимок+траектория) | тот же, поля в frontmatter файла задачи |
| context.md «только то, чего нет у владельцев» | то же правило внутри «Зачем»: адрес вместо пересказа; усилено словами Founder-а «в файле планирования не должно дублироваться то, что есть уже в документации» |
| Возвраты воркеров `modules/_returns/` | `_evidence/` эпика + строка в отчёте подзадачи |
| Брифы воркерам `modules/` | эфемерные брифы в run_dir оркестратора; состав полей модуля v2 сохранён в delegation (вклад · источники · границы · экипировка · бюджет · проверки · запреты; возврат — с «экипировка: поднял/нет») |
| Стыки (потребитель называет критерий) | правило при закрытии задачи, не раздел |
| Дашборд: Планы.base по `status.md` | Планы.base по файлам `тип: задача`; формула «Прогресс» в процентах |
| Акт вывода состава | сохранён в contract как противовес правилу адреса |
| context.md слоты (проблема · эффект · отпавшие ходы) | слоты раздела «Зачем» |
| `cut.md` задачи («не вошедшее») | строка с причиной в отчёте последней подзадачи |
| Probe/repair зависшего воркера | протокол переехал к владельцу `1orchestration`; в delegation осталась дельта планирования (след в отчёте подзадачи) |
| Атрибуции IMP и SAFe | сняты: правила сформулированы полностью, имя не сжимало; предохранитель «имена — ярлыки» возвращён в тело |
| Строка сбоя «стык не назван» | поглощена правилом стыка в contract |

## Новое (не существовало в v2)

Обязательный раздел «Принципы» в эпике и задаче со строкой влияния (вход
`1use-principles`) · отчёт-тогл под каждой подзадачей · правило размера 3–7
подзадач и «подзадача — один ход с одним доказательством» · тесты границ
(эпика · дубля · очереди/just-in-time) · запрет субагентам писать в файлы
планов (исключение `_evidence/**`) · чекер состава разделов в обе стороны ·
счётчики прогресса как производные поля · `[x]` только при доказательстве
адресом.
