# Совместимый CSV

## Задача

Реализовать одну локальную выгрузку выбранных счетов в CSV, который сторонняя
бухгалтерия принимает одним импортом без ручной правки. Работа заканчивается
после одного цикла реализации и проверки; передача данных по сети, email,
синхронизация и изменение редактора счетов в задачу не входят.

Бюджет: 35 несущих единиц: 22 независимых свойства `canon.md` и 13
контрактных ограничений цели, границы и доказательства (локальное действие,
отсутствие сети, один целый импорт, отсутствие ручной правки, только выбранные
счета, принятие валидатором, импорт без потерь, запрет email, запрет
синхронизации, запрет изменения редактора, один цикл, неизменность внешней
схемы и реальные результаты проверки с крайними случаями). После попытки
перепаковки эти единицы остаются явными в критериях и подзадачах: каждая может
отдельно сделать импорт неприемлемым, поэтому сокращать их ради лимита нельзя.
Искусственное деление не создаёт отдельный приемлемый результат: пять осей
ниже вместе образуют одну совместимую выгрузку и один проверяемый импорт.

## Зачем

Оператор сейчас вручную исправляет формат перед импортом, поэтому ближайшая
задача эпика должна убрать эту правку, сохранив локальный сценарий и границы.
Основания владельца и эпика: «Оператор передаёт выгрузку счетов в стороннюю
бухгалтерию без ручной правки» (`probes/GOAL.md#L3`) и «Успех — файл принят её
валидатором и импортирован без потери строк» (`probes/GOAL.md#L4`).
Допуск задачи уже дан утверждённым эпиком «Экспорт» с решением владельца
2026-09-08 (`probes/case.md#L6-L7`); повторное разрешение и изменение эпика
не требуются. Граница особенно существенна: «Отправка CSV по email —
запрещённая задача» (`probes/epic.md#L17-L18`).

## Цель

После действия оператора локально создан один CSV выбранных счетов. Его байты
соответствуют канону, сторонний валидатор принимает файл, а один полный импорт
тестового набора с перечисленными крайними случаями сохраняет все строки и
значения без ручной правки и без передачи данных по сети.

## Критерии приёмки

Каждое свойство проверяется на тестовом наборе, содержащем соответствующий
крайний случай; проверка чтением кода или скриншотом кнопки успеха не заменяет
результат валидатора и импорта.

| № | Независимое обязательство | Наблюдаемая проверка |
| ---: | --- | --- |
| 1 | Кодировка UTF-8 без BOM | Проверка первых байтов и декодирование тестового файла подтверждают UTF-8 и отсутствие BOM. |
| 2 | Перевод строки CRLF | Байтовая проверка каждой записи подтверждает `CRLF`; одиночные `LF` не принимаются. |
| 3 | Разделитель — запятая | Разбор сырого файла подтверждает запятую как разделитель и отсутствие подмены другим разделителем. |
| 4 | Первая строка содержит заголовки в порядке схемы | Заголовочная строка побайтно сопоставлена с порядком внешней схемы. |
| 5 | Значение с запятой заключено в двойные кавычки | Поле с запятой в fixture разбирается как одна ячейка и имеет требуемое quoting. |
| 6 | Внутренняя кавычка удваивается | Поле с кавычкой сохраняет значение после обратного разбора, а сырой CSV содержит удвоенную кавычку. |
| 7 | Перевод строки внутри значения сохраняется в кавычках | Многострочное поле остаётся одной ячейкой, содержит исходный перевод строки и заключено в кавычки. |
| 8 | id счёта не изменяется | Для каждой выбранной записи id в CSV побайтно совпадает с исходным id. |
| 9 | id клиента сохраняет ведущие нули | Клиентский id вроде `00123` импортируется как `00123`, а не как число `123`. |
| 10 | Дата счёта имеет формат `YYYY-MM-DD` | В каждой дате проверены шаблон и значение, включая тестовую дату с ведущими нулями. |
| 11 | Валюта — трёхбуквенный код | Валютное поле проходит проверку трёх букв и не преобразуется в символ или локальное название. |
| 12 | Сумма использует точку и два знака после неё | Суммы проверены на формат `-?digits.digits` с ровно двумя знаками после точки. |
| 13 | Нулевая сумма сохраняется | Нулевая сумма остаётся `0.00` и присутствует в импортированном результате. |
| 14 | Отрицательная сумма сохраняет знак | Отрицательная сумма импортируется со знаком минус и тем же числовым значением. |
| 15 | Пустое необязательное поле даёт пустую ячейку | Отсутствующее необязательное значение даёт пустую CSV-ячейку без текста-заглушки. |
| 16 | Отсутствие обязательного id завершает выгрузку явной ошибкой | Fixture без обязательного id прекращает выгрузку с видимой ошибкой; неполный файл не объявляется успехом. |
| 17 | Порядок строк совпадает с выбранным порядком счетов | Последовательность id в файле равна последовательности выбранных счетов. |
| 18 | Число строк равно числу выбранных счетов | Число импортируемых записей равно числу выбранных счетов, без заголовка в счётчике. |
| 19 | Скрытые фильтром счета не попадают в файл | Счёт, скрытый фильтром, отсутствует в CSV и в импортированном наборе. |
| 20 | Повторное действие без изменения данных даёт те же байты | Два запуска на неизменённых данных дают одинаковый SHA-256 файла. |
| 21 | Отмена диалога сохранения не создаёт файл | После отмены проверка целевого пути показывает отсутствие нового файла. |
| 22 | Ошибка записи показана оператору и не объявлена успехом | Принудительная ошибка записи даёт сообщение оператору и не даёт сигнал или статус успеха. |

**Завершение:** все 22 проверки выше пройдены; локальный файл принят реальным
валидатором сторонней бухгалтерии; тот же тестовый набор с крайними случаями
одним полным импортом загружен без потери строк и значений. В evidence целого
сохранены результаты байтовых проверок, валидатора и импорта, включая fixture
с запятой, кавычкой, переводом строки, ведущими нулями, нулевой и отрицательной
суммой, пустым необязательным полем, отсутствующим обязательным id, фильтром,
отменой и ошибкой записи. Скриншот кнопки успеха evidence не заменяет.

**Возврат непринятой:** результат возвращается, если хотя бы одна строка
таблицы не проверена или не пройдена, требуется ручная правка, валидатор
принимает файл, но импорт теряет строку или значение, повторный запуск меняет
байты, скрытый счёт попадает в файл, отмена или ошибка записи создаёт ложный
успех, отсутствуют реальные результаты валидатора/импорта, изменяется внешняя
схема, появляется передача по сети или добавляется email, синхронизация либо
изменение редактора счетов.

## Канон

- `probes/canon.md#L3-L4` требует локального действия без сетевой передачи и
  принятия схемы одним целым импортом; это ограничивает реализацию локальным
  файлом и проверкой одного полного импорта.
- `probes/canon.md#L8-L29` содержит 22 обязательных независимых свойства; они
  перенесены без сокращения в таблицу критериев 1–22 и определяют байты,
  значения, выборку, повторяемость и поведение сохранения.
- `probes/canon.md#L31-L32` требует реальные результаты валидатора и импорта
  тестового набора с крайними случаями; поэтому финальное доказательство не
  может состоять из самоотчёта или скриншота.
- `probes/epic.md#L15-L18` оставляет только локальную выгрузку выбранных счетов
  и исключает email, синхронизацию и изменение редактора; эти границы являются
  условием возврата и остановки работы.
- `probes/epic.md#L20-L27` задаёт завершение по валидатору и импорту, один цикл
  реализации и проверки и запрет менять внешнюю схему ради зелёной проверки;
  несовместимость схемы требует вопроса владельцу.
- `probes/GOAL.md#L3-L4` задаёт отсутствие ручной правки и успех без потери
  строк; это цель целого, а не разрешение ослабить отдельные поля.
