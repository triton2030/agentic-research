# Решения по первой волне

Волна завершена обоими независимыми проверяющими. Проверенный пакет неизменен
в `packages/`, manifest.json содержит его точные байты. Последующие исправления
находятся в `../packages/`; новая волна не запускалась.

| Находка | Решение и основание | Исправление / проверка |
| --- | --- | --- |
| Instructions 1 / Opus Н1: evidence не доходит до эпика | Принять: прямое сохранённое решение владельца 2026-09-02:23 | C4 и task-schema требуют обновить evidence и состояние эпика; epic-schema допускает промежуточное evidence; checker больше не запрещает его; regression test |
| Instructions 2: null boolean скрывает эпик | Принять: наблюдаемый дефект type validation | sentinel MISSING; тест null launch падает на старой версии и проходит после исправления |
| Instructions 3: нагрузка C1–C5 | Принять: критерии были одновременно предъявлены | явные моменты и окончания C2 → C1 → C3; C5 до продолжения, C4 во время работы, C1/C4 при закрытии; проверенный вход не пересобирается без расхождения |
| Instructions 4: порядок намерения | Принять: текущий контракт goal-context | существующее Зачем стало Контекстом; Задача/Критерии/Цель следуют после; Цель выражает выбор при конфликте; task/epic H2 не меняются |
| Instructions 5: descriptions >200 | Принять: буквальная норма skill-short-description | укорочены два description; проверка YAML-развёрнутой длины |
| Opus Н2: planning не оставляет видимый вопрос | Принять: маршрут имел только положительный выход | Задача/критерий planning передают вопрос 1plan-map; question-schema принимает его к существующему или предложенному эпику с пустым допуском, без повторного круга admission |
| Opus Н3: допуск не открывается | Принять: поле становится опорой автономного продолжения | обе схемы задают открываемый файл:строка (например, 1chat-recall) или permalink, а не фразу «решение от даты»; checker не объявляется проверкой подлинности разрешения |
| Opus Н4: снять число «пара» | Отклонить: пользователь утвердил точный C2 вместе с C1–C5 2026-09-02:21; baseline C2 требует буквально пару строк. Наблюдаемого вреда от двух цитат не предъявлено | правило сохраняется. Превышение числа обоими probes записано как предел управляемости текстом, не как разрешение изменить решение владельца |

## Собственные находки после снимка волны

- YAML-alias производного поля ссылался на узел непроизводного; --sync
  удалял anchor и оставлял повреждённый файл. В tempfile воспроизведены
  `preflight_ok=True`, `sync_ok=False`, `task_changed=True`. Теперь каждый
  подготовленный буфер заново разбирается и сравнивается с ожидаемыми полями
  и неизменным телом до первой записи; regression сохраняет оба файла.
- Индекс всех Markdown строился для каждого плана при проверке placement.
  Теперь строится один раз на проверку; regression наблюдает один root-scan.

## Случаи и нагрузка task

Это счёт управления автором/исполнителем, не число бизнес-условий задачи и не
число YAML-ключей. Шаблон и checker держат механическую форму.

| Момент | Вход → выход | Одновременно применимое |
| --- | --- | --- |
| Подготовка оснований | допуск и источники → доставленный контекст C2 | адрес до строки; ключевая пара; явное отсутствие внешних оснований при нём; влияние канона; разрешимость без чата; сохранение границы — до 6 |
| Сборка | C2 → наблюдаемый контракт C1 | лазейки с проверками; отдельное завершение; отдельный возврат; сохранение границы — 4 |
| Проверка объёма | собранный файл → упаковка C3 | число единиц; порог; перепаковка при превышении; объяснение неделимости; реальная ось разделения; сохранение границы — до 6 |
| Сверка продолжения | живые основания + задача → совместимый контракт C5 | совпадение цели/границы/остановки; источник изменения; владелец эпика при сдвиге; открытое расхождение; владелец продуктовой записи — до 7 |
| Исполнение | сверенный контракт → актуальный прогресс C4 | состояния подзадач; отчёты; точка продолжения; обновление тем же ходом; evidence части; счётчики; сохранение границы — 7 |
| Закрытие | достигнутый результат → принятое целое | готовые проверки C1; отдельный возврат; evidence целого; счётчики; вклад в evidence эпика; актуальное состояние; сохранение границы — 7 |

Переходы не объявляют семантические условия автоматически доказанными. При
обнаруженном расхождении возвращается затронутый случай; приёмка исхода может
требовать многих бизнес-проверок. Это реальное пересечение ответственности,
не обещание, что весь жизненный цикл помещается в семь фактов.

Сравнительные probes сохраняют evidence для неснятых C1–C5 и снятых вызовов:
условия результата не ослаблены последними правками. Новые переходы вопроса и
допуска проверены по обеим сторонам схем, а технические изменения — тестами.
