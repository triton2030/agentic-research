# Контракт встроенной проверки

Scope: проверка и вычисление механических свойств новой формы планирования.
Не проверяет смысл канона, подлинность согласия, достаточность доказательства,
чтение источников или правильность декомпозиции. Никаких обходов старых проектов.

## CLI и зависимости

`uv run --script <skill 1plan-map>/scripts/check_plans.py --root <корень проекта>`
по умолчанию только читает. `--sync` записывает только производные счётчики и
список задач; `--snapshot <путь эпика>` только печатает хеш. Exit 0 = проверенные
механические свойства прошли, 1 = ошибки данных, 2 = неверный вызов/корень.
PyYAML safe_load (PEP 723 dependency) вместо собственного YAML-парсера.
Без сетевого чтения документов и без исполнения содержимого Markdown.

## Размещение и структура

Корень карты `<project>/_ops/plans`.
В нём обязательны `Дашборд.base`, `Планы.base` (валидный YAML с views).
Эпики `<plans>/эпики/<Имя>/epic - <Имя>.md`; задачи в той же папке
`task - <Имя>.md`. Вопросы `<plans>/вопросы/<Имя>.md`.
Сканирование должно обнаруживать файл с префиксом, у которого нет `тип`, а не
молча пропускать. Служебные README/AGENTS/CLAUDE не являются планами.
Вложенные папки `_evidence` — доказательства, не план-файлы.

H2 эпика точно и по порядку: Зачем, Цель, Канон, Границы,
Критерии завершения, Аппетит, Состояние.
H2 задачи: Задача, Зачем, Цель, Критерии приёмки, Канон,
Подзадачи, Состояние.
H2 вопроса: Вопрос, Влияние, Варианты, Ответ (Ответ может быть пуст до решения).
Исключить заголовки внутри fenced code blocks. У каждого обязательного раздела
есть непустое содержимое, кроме незаполненного Ответа вопроса.

## Поля

Общие обязательные: `тип` (эпик/задача/вопрос), `статус`, `обновлено` ISO date.
Общий словарь эпика/задачи: ✅ готово, 🔨 в работе, ◽ в очереди,
🔒 заблокировано, 🛑 затык, ⏳ отложено.

Эпик: описание string, область string, порядок positive int, запуск bool,
health enum 🟢/🟠/🔴/не проверено, ранний-индикатор string,
канон list[project-relative file paths], зависит-от list[wikilinks to epics],
допуск string (empty while proposed), задач int, задачи list[wikilinks],
задач-готово int, evidence string (empty until evidence exists; progress allowed,
whole-outcome evidence required when epic accepted).

Задача: эпик wikilink to parent, допуск string (literal `эпик` or decision
address), эпик-снимок 64 hex, траектория string, режим execution/wayfinding,
порядок positive int, подзадач int, подзадач-готово int, evidence string.
Optional вопрос wikilink or empty string. Допуск `эпик` требует непустого
допуска эпика; checker не доказывает, что его действительно дал человек.

Вопрос: статус открыт/отвечен, касается wikilink to task/epic, адресат string,
срок ISO date or empty string, ответ-опора string (empty until answered).

Любой markdown-путь в `канон` существует внутри корня проекта; GOAL
`_ops/GOAL.md` существует. [] допустим при отсутствии канона.
Wikilinks допускают полный путь от project-root без .md либо уникальный stem.
Неоднозначная/битая ссылка — ошибка. Связь эпик у задачи совпадает с папкой.
Зависимости эпиков существуют; нет самоссылок и циклов.
Порядок эпиков главного пути уникален, порядок задач уникален внутри эпика.
Активная задача требует активного эпика и непустого допуска; активная задача
за закрытой/отложенной/незавершённой необходимой зависимостью — ошибка.
Отложение не заменяется автоматической блокировкой. Статусы checker не пишет.

## Подзадачи и завершение

3–7 чекбоксов в разделе Подзадачи, достигнутых состояний, а не шагов.
Смысл формулировки человек проверяет сам. После каждого чекбокса — callout
`> [!note]- Отчёт`; разрешена пустая строка перед callout.
В нём `> статус YYYY-MM-DD: <текст>`; у [x] — непустое
`> доказательство: <адрес>` (пустые значения и «—» не evidence).
Закрытая задача требует всех [x] и непустого evidence целого.
Закрытый эпик требует непустого evidence целого и не содержит незавершённых
задач; обратное неверно: все задачи закрыты не закрывает эпик автоматически.
Отвеченный вопрос требует непустого Ответа и ответ-опора.

## Снимок

Снимок включает всё намерение эпика, включая преамбулу до первого H2,
непроизводные frontmatter, все разделы кроме Состояние, а также содержимое
_ops/GOAL.md и файлов, перечисленных в `канон` эпика.
Из frontmatter исключены только `статус`, `health`, `обновлено`, `задач`,
`задачи`, `задач-готово`, `evidence`. Стабильная нормализация YAML и новых строк.
Изменение канона/GOAL/цели/границ меняет снимок; счётчики и прогресс не меняют.
Снимок сравнивается у незакрытых задач. Историческая закрытая задача может
держать прежний снимок. `--sync` никогда не освежает снимки.

## Производные и атомарность

Эпик: задач = число колоцированных задач, задач-готово = число ✅ задач,
задачи = полные wikilinks этих задач, упорядоченные по порядок и имени.
Задача: подзадач/подзадач-готово = чекбоксы и [x].
`--sync` предварительно проверяет все непроизводные условия. При ошибках ни
один файл не изменяется. При успехе обновляет только названные пять полей,
сохраняя прочие поля и тело; затем выполняет обычную проверку. Ни допуск,
ни evidence, ни даты, ни статусы, ни снимки не порождаются автоматически.

## Проверка реализации

В pytest/unittest фикстуре под tempfile собрать валидную пару и оба Bases.
Проверить проход валидной пары; новые имена; missing тип; неверный родитель;
неоднозначные/битые ссылки; порядок разделов; нет доказательства [x]; ложное
закрытие целого; изменение преамбулы и канона меняет hash; derived/Состояние
не меняют; stale snapshot; --sync изменяет только derived и отказывается
писать при иной ошибке; закрытый эпик с живой задачей; блокирующие зависимости.
Никаких изменений действующих `_ops/plans` и внешних проектов в этой сессии.
