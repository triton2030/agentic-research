# Evidence: механизм проверки формы

Исполнитель — субагент Claude Opus по заданию автора; перепроверено автором
2026-09-25 командами ниже.

## Что изменилось

`skills/shared/1planning/portable/scripts/check_plans.py` (копия прежнего
чекера `1plan-map`, 1253 → 1942 строки) различает форму файла по точной
последовательности H2:

- роутер-задача: «Цель», «Прочитать», «Не входит», «Готово, когда»;
- роутер-эпик: «Цель», «Не входит», «Порядок», «Готово, когда»;
- прежняя форма — прежние проверки без изменений.

Для роутера: поля прежней формы (`эпик-снимок`, `траектория`, `основания`)
запрещены; чекбоксы только в «Готово, когда», хотя бы один; отчёт-callout
запрещён; счётчики считаются по «Готово, когда»; `✅ готово` требует всех
`[x]` и evidence; в «Прочитать» есть ссылка; видимый текст задачи не больше
`ROUTER_TASK_MAX_CHARS = 3500`; каждая ссылка тела разрешается в файл внутри
проекта, фрагмент — в заголовок (без учёта регистра и пунктуации, slug GitHub,
`#^блок`); `#L<n>` не принимается. «Порядок» эпика ссылается на каждый файл
задачи его папки.

## Побочные находки

- В legacy-задаче mavo3 «Перенос оплаты за файл» четыре ссылки на черновики,
  перенесённые в архив, не разрешаются; legacy-файлы ссылок не проверяют.
- Голый `[[GOAL]]` в mavo3 неоднозначен (семь файлов с этим именем из-за
  архивов): в роутере нужны пути от корня или относительные ссылки.
