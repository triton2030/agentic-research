# Минимальный commander-intent pass

Повторяющиеся формулировки цели и протокола сжаты в определения, которые агент
может удержать как модель: полный handoff задан один раз как
`result + boundary + proof + critical surprise`; accepted topology — один раз
как non-overlap results в dependency order с proof; valid entry — один раз как
полный handoff без drift для non-duplicate work во frontier.

После чистой пробы оставлены только четыре уточнения, которые нельзя безопасно
вывести из общей цели:

- `approval полного handoff`: иначе можно принять частичный packet;
- `названные книга и метод`: иначе trace лишь имитирует decomposition;
- map сначала repair: иначе недопустимая карта может остаться единственным
  результатом;
- `semantic drift` как невалидный entry: одинаковый result скрывает изменение
  boundary/proof/surprise при resume.

Из финальной runtime-формы убраны дублирующие цели `1planning` о передаче и
неисполнении, а также цель карты о самой топологии: их уже несут определения и
протокол. Цель карты о границе допуска была возвращена: из «разных авторов» не
выводится запрет карте самой допускать работу или писать файл задачи.

Не добавлены references, schemas, stages, catalogues или повторное чтение
root/subtree в `1plan-map`/`1plan-task`: для этого нет отдельного harm, а
`1planning` уже владеет решением и чтением применимых инструкций. Неразложимые
атомы выше `~20` остались намеренно: это не бюрократия, а проверяемые hard
gates, прямо требуемые owner-evidence и acceptance finding.
