## Функция

Владелец решения о допуске и существенной декомпозиции задачи в чате. Не
владеет долговечным план-файлом; принятые значения попадают в поля, которыми
владеют `1plan-map` или `1plan-task`.

## Новые ограничения

- Каждый принятый planning-вывод называет долговечное поле назначения. Так ось
  декомпозиции не теряется между окнами, а planning-правда не остаётся в чате.
- Допуск и срез — последовательные стадии; в каждый момент открыт один
  самостоятельный reference, а результат первой стадии записан до второй.
- Допуск ищет срез одного ответственного агента с активным ядром около 20
  независимых единиц. Превышение вызывает аудит упаковки; неделимая цель
  остаётся целой с числом и причиной, а смыслы нельзя прятать в длинной фразе.
- Владелец утверждает материальные выборы, а не все служебные landing values;
  выводимые поля сериализуются без отдельного ритуала.
- Native Plan Mode сохраняет planning-функцию в чате, но не даёт этому скилу
  полномочий создавать долговечные файлы.

## Цена строгости

- **Долговечные landing values:** default — решение остаётся в чате → механизм
  — назвать каждое поле назначения → вред — ложная точность для несущественного
  → цена — сериализуются только значения, меняющие исполнение.
- **Один reference на стадию:** default — агент читает весь пакет сразу →
  механизм — admission/cut/approval с записанным переходом → вред —
  межстадийная связь может потеряться → цена — выход первой стадии явно
  становится входом второй.
- **Один ответственный агент:** default — ответственность распадается между
  окнами → механизм — один владелец задачи → вред — буквальный запрет полезных
  probes → цена — помощник может вернуть evidence, но не владеть решением.
- **Бюджет около 20:** default — агент тащит всю документацию → механизм —
  считать независимые смыслы и проверять упаковку → вред — искусственное
  дробление или скрытый счёт → цена — честное `неделимо` при отсутствии оси.
- **Только применимые источники:** default — агент читает весь корпус →
  механизм — найти релевантные носители после GOAL/эпика/задач → вред — можно
  пропустить неожиданно применимое правило → цена — показать найденные
  ограничивающие строки и дать clean reader проверить пробел.
- **Материальное утверждение:** default — служебное «да» принимается за выбор →
  механизм — назвать цель, приоритет, границу, authority и реальную развилку →
  вред — выводимое поле может оказаться материальным → цена — включать его в
  gate только когда формулировка меняет решение.
- **Native Plan Mode без durable-write:** default — planning-скилл конкурирует
  с системной поверхностью → механизм — выполнять допуск в режиме, но не писать
  файлы → вред — результат может остаться transient → цена — утверждённый
  landing packet явно маршрутизируется durable-owner-у.
- **Trigger-only description:** default — описание пересказывает процесс →
  механизм — оставить только момент вызова → вред — skip/near-miss не видны в
  metadata → цена — границы остаются в русском теле и проверяются контрастами.
- **Русский runtime:** default — English-тело затрудняет owner review → механизм
  — инструкции на русском → вред — можно перевести устойчивый token → цена —
  имена, команды, schema keys и код остаются литеральными.

## Закрытые неверные прочтения

- «Скилл планирования пишет файл плана» → протокол 5 запрещает запись и выдаёт
  значения.
- «Фронтир карты разрешает следующую задачу» → протокол 2 требует допуска.
- «20 пунктов можно спрятать в одно предложение» → протокол 4 считает
  независимые смыслы.
- «Больше 20 всегда означает две задачи» → протокол 4 требует реальной оси и
  допускает честную неделимость.
- «Любое новое evidence требует полного переплана» → смысловую границу
  проверяет `1plan-task`; обычное исполнение остаётся у него.
- «Native Plan Mode отменяет скептический допуск» → граница сохраняет допуск и
  запрещает лишь durable-запись.

## Маршруты

- использовать: `Что нам делать дальше?`
- использовать: `Это evidence изменило принятую границу задачи.`
- использовать: `Крупная ошибка могла сделать текущий план неверным.`
- пропустить: `Продолжи следующую утверждённую подзадачу.` → `1plan-task`
- near miss: `Переставь эпики проекта после запуска.` → `1plan-map`

## Текущий счётчик черновика

Активный набор раскроен на тело + один из трёх самостоятельных references;
буквальный пересчёт повторяется на втором цикле `check-approve`.
