# Как надо и как не надо

Вход: сомнение в размещении, вложенности, имени или отсылке. Выход: решение по правилу с парным примером; само правило целиком — в теле скила.

Парные примеры из выдуманных продуктов: клиника, школа, CRM, магазин, туры, фитнес. Имена полок и вещей выдуманы и в реальной базе берутся из `AGENTS.md` базы. В угловых скобках — что раскрывает файл, а не как его назвать: `<чего хочет>` может называться «Мотивы». Набор сторон в примерах намеренно разный: он зависит от вещи, а не от шаблона. Существующие имена не меняются без решения владельца.

Сгруппировано по правилу. В каждой паре: ошибка, исправление, одна строка почему.

# Путь — это знание: вложенность = принадлежность

## Вложенность без принадлежности

Не надо (один тур входит в разные маршруты):
```
понятия/
  маршрут/
    тур/
      день тура/
```
Надо:
```
понятия/
  маршрут/
    <что это>
    <как устроен>          ← перечисляет туры по имени
  тур/
    свойства/
      <что это>
    день тура/
      <что это>
```
Путь «маршрут → тур» утверждает, что тур есть только в этом маршруте. Это ложь, и её прочитает каждый, кто увидит путь. День тура принадлежит одному туру — вложен честно, а своё описание тур держит подвещью, потому что рядом с подпапкой файлов не бывает.

Не надо (клиника):
```
понятия/
  врач/
    приём/
```
Надо:
```
понятия/
  врач/
    <что это>
  приём/
    <что это>
    <как устроено>          ← «проводит один врач»
```
Приём связан с врачом, но не принадлежит ему: у приёма есть ещё пациент, кабинет, время. Связь — упоминание, не вложенность.

## Принадлежность, не отражённая в пути

Не надо (CRM):
```
понятия/
  сделка/
  этап сделки/
  комментарий к сделке/
```
Надо:
```
понятия/
  сделка/
    сущность/
      <что это>
    этап/
      <что это>
    комментарий/
      <что это>
```
Этап и комментарий существуют только внутри сделки. Плоская раскладка теряет это знание, и имена приходится удлинять, чтобы его вернуть.

## «Для» принято за «внутри»

Не надо:
```
люди/
  покупатель/
    <кто это>
    каталог/               ← экран внутри вещи «покупатель»
```
Надо:
```
люди/
  покупатель/
    <кто это>
для покупателей/
  каталог/
```
Каталог — для покупателя, а не часть покупателя. Кружка для чая не лежит внутри чая.

# Папка — либо файлы, либо папки

## Файл рядом с подпапками

Не надо:
```
каталог/
  <как устроено>
  фильтры/
    <как устроено>
```
Надо (фильтры — вещь со своими сторонами):
```
каталог/
  список товаров/
    <как устроено>
  фильтры/
    <как устроено>
```
или (фильтры — абзац):
```
каталог/
  <как устроено>          ← абзац о фильтрах внутри
```
Файл рядом с подпапками не читается: он про весь каталог или про то, что не влезло в фильтры? Своё содержимое вещь с подвещами держит подвещью с настоящим именем, а не файлом «общее».

## Полка с файлами

Не надо:
```
для покупателей/
  чего хочет покупатель
  каталог/
```
Надо:
```
люди/
  покупатель/
    <кто это>
    <чего хочет>
для покупателей/
  каталог/
```
У полки нет свойств, поэтому в ней нет файлов. Покупатель как вещь живёт среди людей продукта; полка — место, где лежат его экраны.

## Полка, названная как вещь

Не надо (клиника):
```
врачи/
  расписание/
  профиль/
```
Надо:
```
люди/
  врач/
    <кто это>
    <чего хочет>
для врачей/
  расписание/
  профиль/
```
«Врачи» здесь — полка экранов для врачей, а названа как вещь. Полку от вещи отличает не «внутри только папки»: у вещи с подвещами тоже только папки. Отличает смысл: на врача можно показать пальцем, и о нём есть что сказать — это вещь среди людей продукта.

# Файл — одна сторона вещи

## Свойство вместо вещи

Не надо (маркетплейс):
```
безопасность/
  пароли
  оплата
  личные данные
```
Надо:
```
для покупателей/
  вход/
    <как устроено>          ← правила про пароли
общее/
  оплата/
    <как устроено>          ← правила про защиту платежа
```
Безопасность нельзя показать пальцем и посчитать. Папка-свойство становится второй свалкой: правило живёт и там, и у вещи, и они расходятся.

## Имя без ясных границ содержания

Не надо (клиника):
```
запись на приём/
  описание
  функционал
  требования
  спецификация
  заметки
```
Надо:
```
запись на приём/
  <роль в системе>
  <как выглядит>
  <как устроено>
  <что бывает не так>
```
«Описание» и «функционал» — про одно и то же, агент положит факт в оба. «Спецификация» называет тип документа, а не сторону вещи. Стороны у одной вещи не пересекаются.

## Имя-вопрос

Не надо:
```
корзина/
  Как покупатель добавляет товар в корзину
  Что происходит, когда корзина теряется
```
Надо:
```
корзина/
  <действия>
  <при потере>
```
Вопрос задаёт границы содержания, но не форму имени. Имя — короткое словосочетание о стороне вещи; по нему и по пути видно, что внутри и когда это читать.

## Мешок

Не надо (CRM):
```
карточка клиента/
  <как устроено>
  детали
  разное
  прочее
  заметки
```
Надо:
```
карточка клиента/
  <как устроено>
  <что бывает не так>
  <что видит человек>
  <техническое>
```
«Детали» и «разное» — «всё остальное». Никто не знает, что туда класть и что оттуда читать. Разобранный на стороны мешок показывает владельцу то, что было в нём похоронено.

## Файл с именем папки

Не надо (фитнес):
```
тренировка/
  тренировка
  <как устроено>
```
Надо:
```
тренировка/
  <зачем нужна>
  <как проходит>
```
Файл-тёзка пытается описать вещь целиком и дублирует стороны рядом.

## Гигантский файл, заговоривший за пределами имени

Не надо:
```
каталог/
  <как устроено>          ← 40 экранов текста: и фильтры, и оплата, и что такое товар
```
Надо:
```
каталог/
  <как устроено>          ← только каталог, сколько бы ни вышло
общее/
  оплата/
    <как устроено>
понятия/
  товар
```
Длина не ограничена; ограничено число смыслов. Файл, который говорит больше, чем обещает имя, набрал знание из чужих папок: оплата и товар нужны и другим экранам, и там их будут искать.

## Вопрос, пересекающийся с соседом

Не надо:
```
корзина/
  <как устроено>
  <что бывает не так>
  пограничные кейсы          ← то же, что «что бывает не так»
  UX-соображения             ← куски «как устроено»
```
Надо:
```
корзина/
  <как устроено>
  <что бывает не так>
```
Сторона, пересекающаяся с соседом, — второй дом для тех же фактов; материал без своей стороны — абзац в существующем файле или подвещь.

# Когда появляется папка

## Действие без экрана как папка

Не надо:
```
корзина/
  добавление товара/
  удаление товара/
```
Надо:
```
корзина/
  <как устроено>          ← абзацы: добавить, удалить, изменить
```
Но:
```
для мастерских/
  приём заказа/
    <как выглядит>
    <как устроено>
```
Кнопка — абзац. Экран с формой в несколько шагов — вещь.

## Папка ради одного абзаца

Не надо (фитнес):
```
понятия/
  подход/
    <что это>             ← три строки, больше сказать нечего
```
Надо:
```
понятия/
  подход
```
Одиночный файл с именем понятия, пока не появится вторая сторона. Тогда файл становится папкой.

## Файл порезали вместо вещи

Не надо:
```
каталог/
  как работает 1
  как работает 2
  как работает продолжение
```
Надо:
```
каталог/
  список товаров/
    <как устроено>
  фильтры/
    <как устроено>
  сортировка/
    <как устроено>
```
Файл вырос — дели по логике: на стороны в той же папке, а если внутри прятались другие вещи, как здесь, — на подвещи; тогда и собственное содержимое каталога получает имя подвещи. Нумерованные куски — не разделение.

## Папка, созданная агентом молча

Не надо:
```
[агент получил материал про уведомления и создал]
общее/
  нотификации/
    <как устроено>
```
Надо:
```
[агент спрашивает владельца]
Материал про уведомления не ложится ни в одну вещь. Варианты:
1. общее/уведомления — процесс, идущий и студии, и покупателю
2. абзац в общее/путь заказа — если уведомления только про заказ
3. понятия/уведомление — если это понятие, которое встретится во многих экранах
Какой?
```
Папка рождается через владельца. «Нотификации» — агентское слово; владелец сказал бы «уведомления». Выбор записывается в `AGENTS.md` базы.

# Один факт — одно место

## Процесс размазан по экранам

Не надо:
```
для покупателей/
  оформление заказа/
    <как устроено>        ← весь путь заказа
для мастерских/
  карточка заказа/
    <как устроено>        ← снова весь путь заказа
```
Надо:
```
общее/
  путь заказа/
    <как устроено>        ← описан один раз
для покупателей/
  оформление заказа/
    <как устроено>        ← «начинает путь заказа, этап заявка»
для мастерских/
  карточка заказа/
    <как устроено>        ← «показывает путь заказа с этапа согласования»
```
Экран говорит, где в процессе стоит. Два пересказа разойдутся.

## Знание о вещи там, где с ней работают

Не надо (ресторан):
```
для владельца/
  редактор меню/
    <как устроено>        ← здесь требования к фотографии блюда
```
Надо:
```
понятия/
  блюдо/
    <как устроено>        ← требования к фотографии
для владельца/
  редактор меню/
    <как устроено>        ← «собирает меню из блюд» — называет, не объясняет
```
Верно про блюдо независимо от экрана — у блюда. Меню для гостя покажет те же фотографии, и строящий его агент будет искать требования у понятия, а не в чужом инструменте.

## Техническое вынесено на отдельную полку

Не надо:
```
техническое/
  данные каталога
  вывод каталога
для покупателей/
  каталог/
    <как выглядит>
```
Надо:
```
для покупателей/
  каталог/
    <как выглядит>
    <как устроено>
    <техническое>        ← данные и вывод этого экрана
система/
  <устройство>          ← общее для всей системы: стек, движок, где живёт правда
```
Техническое о вещи — у вещи: владелец хочет понимать все вещи, включая технические, а агент строит вещь из одной папки. Своя вещь только у устройства системы целиком.

## Папки по ролям или этапам работы

Не надо:
```
дизайн/
  каталог
разработка/
  каталог
```
Надо:
```
для покупателей/
  каталог/
    <как выглядит>        ← «дизайн»
    <техническое>         ← «разработка»
```
Роль — кто делает, а не что описано. Читает всё владелец, и место в дереве задаёт вещь, а не роль.

## Документация на код

Не надо:
```
система/
  функции корзины/
    addToCart
    removeFromCart
```
Надо:
```
система/
  <устройство>           ← где лежит код корзины, одной строкой
```
Канон кода — код. Описание функций устаревает при первом коммите.

# Упоминают вещи, а не файлы

Здесь агент ошибается чаще всего, потому что ссылка на файл кажется точнее.

## Ссылка на файл

Не надо:
```
каталог/<роль в системе>:
  «см. люди/покупатель/<чего боится>»
```
Надо:
```
каталог/<роль в системе>:
  «каталог — то, что видит покупатель; что бы ни решал, помни про него»
```
Набор файлов у вещи меняется, имя вещи — нет. Читатель сам откроет папку и возьмёт нужное.

## Указание, какой файл читать

Не надо:
```
корзина/<техническое>:
  «Перед реализацией прочитай общее/оплата/<техническое> и общее/оплата/<что бывает не так>»
```
Надо:
```
корзина/<техническое>:
  «Корзина передаёт заказ в оплату.»
```
Агент, строящий корзину, сам откроет папку оплаты и решит, что ему нужно сегодня. Адрес источника в сноске — другое: он доказывает, откуда взят факт, а не указывает, что читать.

## Пересказ вместо упоминания

Не надо (CRM):
```
сделка/<как устроено>:
  «Клиент — это компания или человек, с которым мы ведём переговоры;
   у него есть контакты, история, ответственный менеджер…»
```
Надо:
```
сделка/<как устроено>:
  «Сделка всегда принадлежит одному клиенту.»
```
Что такое клиент — у клиента. Сделка называет его по имени.

## Единственное допустимое исключение

Можно:
```
напоминания/<как устроено>:
  «Время напоминания зависит от длительности приёма.»
```
Документ по смыслу зависит от одного конкретного свойства другой вещи — можно назвать свойство словами. Если так приходится делать часто — длительность на самом деле вещь.

# Имена

## Имена под агента

Не надо:
```
каталог/
  spec_catalog_v2_final
  каталог 2026 09 09
  как работает (старое)
```
Надо:
```
каталог/
  <как устроено>
```
Версии и даты — признак, что файл боятся править. Правят файл; почему поменяли — в сноске и в корпусе слов владельца.

## Имя не из речи владельца

Не надо:
```
для покупателей/
  модуль оформления/
  экран корзины пользователя/
```
Надо:
```
для покупателей/
  оформление заказа/
  корзина/
```
Владелец говорит «корзина», не «экран корзины пользователя». Имя вещи — как в разговоре; если владелец сам говорит «страница товара», это и есть имя.

## Смешение языков и транслит

Не надо:
```
для покупателей/
  checkout/
  katalog/
```
Надо:
```
для покупателей/
  оформление заказа/
  каталог/
```
Язык имён один — язык владельца. Даже если в коде это checkout.

## Переименование существующего

Не надо:
```
[в базе была папка «покупка»; агент переименовал в «оформление заказа», потому что так правильнее]
```
Надо:
```
[агент оставляет «покупка» и пишет владельцу]
В базе есть «покупка», по смыслу это экран оформления заказа. Оставить или переименовать? На «покупку» ссылаются четыре файла.
```
Имя вещи — часть карты владельца и адрес для упоминаний. Меняется только его решением.

# Планы — не источник

## Решение осталось в закрытом плане

Не надо:
```
[план задачи «фильтры каталога» закрыт; в нём «решили: фильтр по цене — ползунок»; в базе про это ничего]
```
Надо:
```
каталог/фильтры/<как устроено>:
  «Цена задаётся ползунком, не двумя полями.»[^1]
[в плане — ничего, или «перенесено в базу»]
```
Через месяц никто не читает закрытые планы. Решение переезжает, не копируется, в папку вещи; откуда оно — в сноске.

## План внутри базы

Не надо:
```
для покупателей/
  каталог/
    план работ
    статус
```
Надо:
```
[в базе — только стороны каталога; план и статус — в слое планирования]
```
Работа — не свойство вещи. База отвечает «что верно», план — «что делаем».
