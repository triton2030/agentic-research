# Pitch Coherence Audit

**Type — rigid review skill.** Шесть осей и ledger не сокращаются. Адаптация
к стадии идёт только через планку внутри критериев, не через структуру.

## Когда использовать

- После любой правки текста deck, memo или pitch script.
- После правок дизайна слайдов, которые затронули текст на них.
- Когда пользователь говорит: «проверь питч», «не сломал ли я нарратив»,
  «что скажет инвестор», «does this still pitch», «check pitch narrative».
- Автоматически — итеративно, как часть рабочего цикла над питчем.
- Через явный вызов `$pitch-coherence-audit` из Codex CLI.

## Когда не использовать

- Питч-текста ещё нет — сначала выработать нарратив, не этот скилл.
- Работа по визуалу слайдов — другой инструмент, не этот.
- Общее качество прозы — другой инструмент.
- Проверка рендера по скриншоту — визуальный аудит, не этот скилл.

## Контекст на входе

- Конкретный файл питча или список файлов, которые составляют одну
  текущую версию deck, memo или script.
- Папка допустима только как способ найти текущие canonical материалы.
  Если внутри несколько драфтов, экспортов, backup-копий или версий,
  сначала сузить audit target до одной версии.
- Контекст инвестора: стадия, профиль инвестора, one-line thesis.
- `pitch-context.md` канонически живёт рядом с target: если target —
  один файл, то в том же каталоге; если несколько — в ближайшем общем
  родителе. Если файл есть — читать первым. Если нет — запросить три
  ответа у пользователя. Сохранять в `pitch-context.md` только при
  работе с файловыми материалами и только после подтверждения пути
  пользователем; иначе держать контекст в рамках текущего аудита.
- Staleness: если сохранённая стадия расходится с тем, что пользователь
  говорит сейчас, или файл старше 30 дней — переспросить одним вопросом
  и обновить.
- Форматы target: текстовые (`.md`, `.txt`, плейнтекст). Если target —
  `.pptx`, `.pdf`, `.key`, `.fig` или иной бинарник, скилл
  останавливается и просит текстовый экспорт или connector. Ledger по
  непрочитанному файлу — обход.

## Рабочий ход

Проходить шаги по порядку. Пропустить ось = недействительный аудит.

### 1. Загрузить контекст

Сначала искать контекст в уже данных пользователем материалах и в
соседнем `pitch-context.md` по канонической локации (см. «Контекст на
входе»). Если его нет — одним сообщением попросить у пользователя три
коротких ответа:

- Стадия инвестора: pre-seed / seed / Series A / growth (или ближайшая).
- Профиль фонда или инвестора — сектор, размер, тип.
- One-line thesis проекта — как пользователь формулирует суть.

Если есть `pitch-context.md`, но стадия в нём расходится с текущим
разговором или файл старше 30 дней — переспросить одним вопросом и
обновить. Старый контекст без проверки не использовать.

Если аудит идёт по файловым материалам и запись уместна, сохранить
ответы в `pitch-context.md` по канонической локации — только после
подтверждения пути пользователем. Если нет — использовать контекст
только в текущем аудите.

### 2. Выбрать audit target и загрузить материал

Сначала определить один текущий target: deck, memo или script, который
реально собираются показывать.

- Если пользователь дал конкретные файлы — читать только их.
- Если пользователь дал папку — выбрать только current/canonical files.
- Если внутри папки несколько правдоподобных версий — уточнить одним
  коротким сообщением, что считать текущей.
- Явно исключать архивы, старые драфты, экспортные файлы, backup-копии
  и параллельные версии, если пользователь не просил сравнение.

**Binary guard.** Если target — `.pptx`, `.pdf`, `.key`, `.fig` или
иной бинарник, не придумывать содержимое: остановиться и попросить
либо текстовый экспорт, либо запустить connector (`pptx`, `pdf`) для
извлечения текста. Ledger по непрочитанному файлу — недействительный.

Не гадать про содержимое — читать только выбранный target.

### 3. Построить Narrative Coherence Ledger

Обязательный артефакт. Один проход, шесть осей, плюс drift. Для каждой
оси заполнить четыре поля:

- **Claim** — прямая цитата или короткий пересказ с `file:line` якорем.
- **Investor lens** — как это прозвучит для инвестора на данной стадии
  (критерии — `references/stage-criteria.md`).
- **Diagnosis** — один из: alive / weakened / broken / missing.
- **Fix direction** — куда тянуть, не готовый текст.

Шесть осей:

1. **Problem** — живая конкретная боль конкретного человека или роли,
   не абстрактная категория рынка.
2. **Unique insight** — неочевидная истина, которую видят только эти
   фаундеры. Если истина известна всем — это не insight, это консенсус.
3. **Why now** — явный катализатор, который сделал возможным то, что
   раньше не получалось. Без него фаундер звучит как "давно пора".
4. **Wedge** — узкий плацдарм, который реально можно взять. Широкий
   рынок в ask — красный флаг, не сила.
5. **Proof** — доказательство уровня стадии (см. `references/stage-criteria.md`).
   Переоцененное или недостающее proof одинаково ломает питч.
6. **Ask and milestone** — конкретная сумма и явная следующая точка,
   которую она разблокирует. «Нанять команду и расти» — не milestone.

### 4. Coherence drift check

После заполнения осей — отдельная проверка: не противоречат ли они
друг другу. Главный фейлмод итераций: правка в одной оси рушит другую.
Типовые дрифты:

- Problem сузился, а wedge остался прежним — теперь они из разных миров.
- Proof наростили метриками, а why-now остался старый — проект звучит
  как already-solved.
- Insight сгладили ради ясности — осталась просто идея продукта.
- Ask вырос, а milestone не сдвинулся — ask не обоснован.

Найти не все симптомы, а корень — одну ось, которая сломала остальные.

### 5. Verdict

Один из трёх:

- **Ship-ready** — все оси alive, drift чист. Питч можно показывать.
- **Needs fix** — 1–2 оси weakened или есть локальный drift. Перечислить
  must-fix до показа.
- **Fundamental issue** — ось broken или missing, или insight — не insight.
  Переадресовать на выработку нарратива: правкой текста не лечится.

## Развилки

- Оси 1–3 ослаблены, proof сильный — инвестор увидит "ещё один me-too
  с метриками". Fix осей 1–3 критичнее, чем усиление proof.
- Proof слабее стадии — не лечить громкой риторикой. Помечать как
  fundamental issue.
- Drift серьёзный — искать одну ломающую ось, не лечить всё разом.
- Пользователь спорит с диагнозом — не сдавать позицию из-за напора.
  Сдать позицию, только если он приносит факт из pitch-context.md или
  материала, которого скилл не видел.

## Done when

- Ledger заполнен для всех шести осей с `file:line` якорями.
- Drift явно прокомментирован — есть он или его нет.
- Verdict вынесен с перечнем must-fix, если он нужен.
- Fix directions сформулированы как направления, не как готовые правки.
- Попытка назвать питч «ок, мелкие правки» без ledger — не проход, а обход.

## Anti-bypass

- Пропустить ось = недействительный аудит. «Недостаточно данных» — не
  оправдание: ось помечается `missing` и идёт в must-fix.
- Нельзя заменять ledger устным пересказом. Артефакт — текст с якорями.
- Ship-ready без заполненных якорей — не ship-ready.
