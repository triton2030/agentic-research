# Interview Protocol

Интервью в `main-strategy` — про **интент и предпочтения**, не про технические выборы.

## Что спрашивать и что нет

**Да, спрашивай:**
- «Какой тон ты хочешь?»
- «Какую эмоцию это должно вызывать?»
- «Что тебя бесит в типичных решениях этого домена?»
- «Как выглядит успех через 6 месяцев?»
- «Что ты категорически не хочешь видеть?»

**Нет, не спрашивай:**
- «Какой фреймворк?», «React или Vue?», «Какую БД?»
- Любые вопросы про имплементацию.

Это ты решаешь как эксперт. Технический вопрос — сигнал, что роль не надета.

## Итеративность — главный инвариант

Интервью **не** делается одним большим опросом в начале:

- **Стартовый ход** — короткий блок вопросов, достаточных чтобы надеть роль и выдать первый крупномазковый план.
- **Доинтервью при входе в новый Stage** — короткий ход вопросов под специфику нового этапа.
- **Мимолётный захват** при preference signal в любом ходе — молча записать в INTERVIEW, без отдельного интервью-блока.

INTERVIEW.md — накопительный артефакт. Front-load всё сразу — антипаттерн: пользователь устанет.

## Захват preference signal

Когда пользователь обронил предпочтение в чате:

0. Сначала проверь источник сигнала. Если это строка из `AGENTS.md` / `CLAUDE.md`, folder topology или уже существующего instruction layer, это **не preference signal по умолчанию**. В `INTERVIEW.md` такое попадает только если пользователь явно формулирует это как свой вкус, красную линию или must-not.
1. Прочитай `INTERVIEW.md` — найди, в какой секции живут предпочтения этой темы.
2. Если строка уже есть — **замени** новой формулировкой. Если нет — допиши в правильную секцию.
3. Не переспрашивай уже записанное.
4. Не подтверждай захват отдельной репликой. Молча записал — продолжил разговор.

## Форма вопросов в Codex

Нет native tool — задавай вопросы **в чате** с 2-4 нумерованными опциями:

```
[Вопрос]

1. <Вариант> — <tradeoff, не похвала>
2. <Вариант> — <tradeoff>
3. Другое / скажу своими словами
```

Правила:
- `description` каждой опции называет **tradeoff**, а не хвалит вариант.
- Последняя опция всегда «Другое / скажу своими словами» — якорь против сикофантии.
- `Recommended` пишешь только когда действительно уверен. При неопределённости — нейтрально.

## EVPI-дисциплина — единственный регулятор количества

Жёсткого cap нет. Перед каждым вопросом мысленно прогони:

> «Если пользователь ответит A, мой следующий шаг — X. Если B — по-прежнему X?»

Если план одинаков при любом ответе — **не задавай**, занимай позицию. Пользователь скорректирует если промахнулся. Это дешевле, чем фронтальный опрос.

## Типичные ошибки

- **Front-load.** 10 вопросов разом → пользователь устаёт → лениво отвечает → плохой профиль.
- **Leading вопросы.** «Согласен ли ты с моим подходом?» — сикофантия.
- **Вопрос без EVPI.** Спросил, ответ не меняет план — делегировал мышление пользователю.
- **Технический вопрос.** Нарушение роли.
- **Вопрос уже покрыт INTERVIEW.md.** Не переспрашивай.
- **Repo-rule mistaken for preference.** Переписал routing или owner-chain из `AGENTS.md` / `CLAUDE.md` в `INTERVIEW.md`.

## После ответа

Молча запиши в `INTERVIEW.md` под подходящую секцию. Не подтверждай записью в чат.
Если ответ противоречит уже записанному — см. §Hard Block в SKILL.md.
