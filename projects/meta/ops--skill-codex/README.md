# Ops — Codex

Рабочая папка по Codex-версии скилла `ops`. Содержимое и логика параллельны [`ops--skill-claude-code/`](../ops--skill-claude-code/README.md).

Скилл заставляет агента не верить постановке на слово: сначала pressure-test framing, собрать strategic aim как рабочую гипотезу, пройтись от first principles и выбрать одну лучшую профессиональную роль, только потом действовать.

Если по всей переписке видно, что проблема не только в задаче, но и в самих агентных инструкциях проекта, `ops` может предложить короткую правку в `AGENTS.md` или другой project-local instruction layer. Не правит молча — только поднимает предложение.

Если проект живёт через `ops`, скилл должен сначала проверить сам слой `ops`: папка должна существовать. `NORTH-STAR.md` он пишет только в конце, если файла ещё нет и framing уже прошёл pressure-test.

## Отличия От Claude Code Версии

Логика и этапы совпадают полностью. Отличается механика шага "вопросы", но не только она: Codex-версия жёстко трактует запрос как гипотезу, а не как спецификацию по умолчанию.

- Claude Code использует `AskUserQuestion` — структурированный UI с опциями и описаниями.
- Codex такого тула не имеет. Вопросы задаются в чате обычным списком с явно названными альтернативами.

Формат вопроса в Codex-версии:

````
Вопрос, который проверяет рамку?
- Вариант A — последствия: ...
- Вариант B — последствия: ...
- Вариант C — последствия: ...
````

Смысл тот же: каждый вопрос имеет право на существование, только если ответ на него меняет выбор подхода или может доказать, что пользователь целится не туда.

На старте `ops` только проверяет `ops/`. `NORTH-STAR.md` он создаёт или сверяет в конце, уже из locked truth и собранных evidence, а не использует как ранний якорь.

Прочие соглашения переносятся один в один: гипотеза задачи, жёсткий pressure test рамки, first-principles проход, одна главная профессиональная роль, право прямо возражать пользователю, варианты с явной ценой выбора, анти-сикофантный блок и маленький meta-check на случай, если узкое мышление рождается из project instructions, а не только из самой задачи.

## Файлы

## Установка

Путь установки скиллов в Codex зависит от версии клиента. На момент написания (апрель 2026) персональные скиллы Codex ожидаются по `~/.agents/skills/`. Перед деплоем уточнить актуальный путь в документации Codex.

## Ограничения

Те же, что у Claude Code версии: размытый триггер, коллизия с `superpowers:brainstorming`, зависимость постобработки от наличия `planning/*` файлов.
