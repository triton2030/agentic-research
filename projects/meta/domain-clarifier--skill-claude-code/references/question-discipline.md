# Question Discipline

Domain questions are expensive. Ask only when an answer changes a future move.

## Consequential Question Test

Before asking, complete this sentence:

> If the answer is A, I will do X. If the answer is B, I will do Y.

If X and Y are the same, do not ask.

## Good Questions

- expose missing prerequisites;
- choose between materially different Stage orders;
- choose between materially different task scopes;
- change acceptance criteria or verification;
- prevent domain confabulation.

## Bad Questions

- ask the user to choose implementation details the agent should own;
- collect taste already stored in `INTERVIEW.md`;
- confirm the agent's preferred answer;
- delay a decision without changing the plan.

## After Answer

Route the durable answer:

- user preference or vision -> `user-interview`;
- strategy or Stage shape -> `project-roadmap`;
- task order, task scope, criteria, or verification -> `task-contract`.
