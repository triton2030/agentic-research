# Design Auditor [DEPRECATED]

Рабочая папка по Codex-скиллу `design-auditor`.

## Статус

Удалён из глобально установленных Codex skills 17 апреля 2026.

## Что Это Теперь Такое

Эта папка теперь хранит не активный skill, а короткую память о том, почему мы не стали держать `design-auditor` как installed skill.

Последняя рабочая гипотеза была такой: вместо тяжёлого audit-комбайна превратить его в тонкий router между уже существующими скиллами:

- `$playwright` — когда сначала нужно собрать или стабилизировать browser evidence;
- `$screenshot-design` — когда главный артефакт уже скриншот и нужен жёсткий visual review;
- `$guide-subagents` — когда evidence уже надёжен и правда есть смысл готовить native Codex subagents для breadth across lenses.

## Почему Это Сильнее

После проверки оказалось, что даже в этой упрощённой форме отдельный installed skill не даёт достаточно собственной ценности.

Проблема старой версии была не только в длине. Она пыталась одновременно:

- захватывать страницу;
- управлять браузерным проходом;
- оркестрировать внутренних reviewer'ов;
- собирать memo;
- и хранить собственный тяжелый runtime.

Для Codex это оказалось слабой формой. Она дублирует уже существующие навыки и тащит лишний routing-layer туда, где узкие skills уже достаточно сильны сами по себе.

Почему удалили:

- screenshot-first случаи уже лучше закрывает `$screenshot-design`;
- live-page ветку в проекте сильнее закрывает `$playwright-guide` + `$playwright`/`$playwright-interactive`;
- delegation-ветка через `$guide-subagents` слишком редкая, чтобы оправдать отдельный глобальный trigger;
- после critique естественный следующий шаг чаще ведёт в `$impeccable`, а не в отдельный router.

## Граница Скилла

Если когда-нибудь идея вернётся, только в более узкой форме. Например:

- не общий design-audit router;
- а редкий breadth-signoff step после уже стабильного evidence;
- или просто project-local helper, а не глобально установленный skill.

## Рабочая Гипотеза

На сегодня вывод такой: для Codex глобально установленный `design-auditor` не нужен. Полезнее держать сильные узкие skills и не добавлять поверх них router без собственной частой территории.
