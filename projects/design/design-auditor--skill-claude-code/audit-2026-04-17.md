# design-auditor — Аудит 2026-04-17

Источник: `~/.claude/marketplaces/design-auditor/` v2.0.0.

Сверка с `knowledge/wisdom-skills-plugins.md`, `knowledge/guides/perfect-skills.md`, `knowledge/practical-guides/claude-code-skills.md`, глобальным `~/.claude/CLAUDE.md`, `ops/learnings.md`.

## Резюме

Центральная идея скилла — **несколько независимых профессиональных линз с явно прописанными blind spots** — валидна и не перекрывается с `my-skills:screenshot-design` (тот даёт depth одного evidence-ledger прохода, design-auditor — breadth across lenses). Но реализация несёт runtime-баг и ряд дефектов оформления. Решение: не выпиливать, а починить и упростить (см. [changes-2026-04-17.md](changes-2026-04-17.md)).

## Находки

### 1. Runtime-баг в именах субагентов (критично)

В `SKILL.md` v2.0.0 агенты перечислены как `render-integrity`, `hierarchy-scannability`, `layout-flow`, `visual-craft`, `distinctiveness`. Реальный `subagent_type` — значение frontmatter-поля `name:` агента, которое было в human-readable форме (`"Render Integrity"`, `"Hierarchy & Scannability"` и т.д.). При dispatch по именам из SKILL.md модель промахивалась.

Починено в 3.0.0: `name:` в агентах = kebab-case filename, SKILL.md совпадает.

### 2. Отсутствуют обязательные секции

По `perfect-skills.md` и `claude-code-skills.md` скилл должен декларировать: «когда не использовать», «done when», тип (rigid/flexible), output contract. В v2.0.0 было только «Interpreting Results» и «Re-use During a Session» прозой.

Починено в 3.0.0: все секции добавлены, тип заявлен как flexible.

### 3. Коллизия с `my-skills:screenshot-design`

Глобальный `~/.claude/CLAUDE.md` делает `screenshot-design` мандатным при визуальных задачах; `my-skills` бьёт сторонние по приоритету. В v2.0.0 design-auditor не разводил себя со screenshot-design и выглядел как слабый дубликат.

Починено в 3.0.0: в description явно «breadth across lenses; для depth-first evidence-ledger — screenshot-design». «When not to use» тоже ссылается на screenshot-design.

### 4. Playwright spin-up противоречит глобальному правилу

`scripts/capture_page.mjs:8` делал `createRequire(...${process.cwd()}/package.json)` + `require("playwright")`. Требовал `playwright` как npm-зависимость в CWD. Для глобально установленного скилла — хрупко. Глобальный CLAUDE.md: «не поднимать отдельный Chromium — MCP уже работает».

Починено в 3.0.0: скрипт удалён. Capture теперь делается тем, что есть под рукой (playwright MCP для live URLs).

### 5. description слишком тонкий

Две строки, два триггера. По `claude-code-skills.md` description должен быть «слегка настойчивым», перечислять триггерные фразы, типы задач и контексты.

Починено в 3.0.0: триггеры ru/en, сценарии, явное разведение с screenshot-design.

### 6. Пять параллельных линз — избыточная поверхность

5 агентов × sonnet × 2 viewport × 3 tile = много контекста и цены. При этом `render-integrity` дублирует self-check оркестратора, а `hierarchy-scannability` и `layout-flow` сильно пересекаются (оба про композицию и flow).

Починено в 3.0.0: 5 → 3 (structure = merge hierarchy+layout, craft, identity). Модели sonnet → opus — меньше агентов позволяет сильнее каждую модель без раздувания стоимости.

### 7. Отсутствие forcing function внутри агентов

Каждый агент в прозе сам себе напоминает про blind spot. Это вежливое напоминание, не дисциплина. Evidence-ledger формат (как в screenshot-design) агентам не навязан.

Не чиним в 3.0.0 осознанно: design-auditor — flexible-скилл, его ценность именно в свободном профессиональном взгляде, а не в жёстком формате. Evidence-ledger живёт в screenshot-design — туда и идти, когда нужна дисциплина.

## Что оставлено без изменений

- Идея «специалистов с blind spots» — сохранена.
- Глобальная установка плагина в том же `installPath`.
- Flexible-природа скилла.
