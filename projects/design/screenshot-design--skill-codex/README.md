# Screenshot Design

Рабочая папка по Codex-скиллу `screenshot-design`.

Он нужен для одной узкой, но повторяющейся задачи: разбирать интерфейс по скриншоту так, чтобы модель не отделывалась общими словами вместо настоящего визуального чтения.

## Что Это За Скилл

`screenshot-design` — rigid screenshot-first скилл для визуального аудита UI по одному или нескольким скриншотам.

Его фокус не на коде, не на Figma и не на браузерной проверке. Он нужен именно там, где важно понять, что видно на экране:

- как читается иерархия;
- где ломается логика блоков;
- где отступы собирают или разваливают структуру;
- насколько аккуратно работают выравнивание, плотность, ритм и контраст;
- выглядит ли экран собранным и намеренным, а не случайно “симпатичным”.

## Главная Ставка

Скилл не верит самоотчёту модели и не разрешает перепрыгивать от картинки сразу к вкусовому вердикту.

Его архитектура держится на трёх обязательных механизмах:

- `Visual Evidence Ledger` — промежуточный артефакт до любого диагноза;
- `Perception:` tag на каждом bullet — чтобы fragile reads не превращались в “факты”;
- `Re-attention pass` — повторный проход по скриншоту против рекомендаций, чтобы ловить дрейф внимания.

При этом внешний ответ не должен нести лишний процесс ради процесса. Обязателен видимый audit trail, а не пользовательский чеклист прогресса.

Без этого screenshot review слишком легко обходит сам себя:

- красивыми фразами без опоры на пиксели;
- хрупкими визуальными чтениями вроде мелкого текста, микровыравнивания и счёта;
- длинным reasoning, который уезжает от реального региона экрана.

## Что Важно Не Потерять

Критичные инварианты у этой версии такие:

- нельзя убирать `Perception:` из ledger bullet;
- нельзя убирать `Re-attention pass`;
- нельзя превращать внутренний workflow в обязательный user-facing progress checklist;
- нельзя схлопывать references обратно в `SKILL.md`;
- нельзя ослаблять trigger в description;
- нельзя превращать этот скилл в browser audit, code review или Figma workflow.

## Что Лежит Внутри

В installed-версии скилл должен оставаться lean:

- `SKILL.md` — только trigger, границы, workflow и done when;
- `references/output-contract.md` — точный формат ledger и финального отчёта;
- `references/failure-modes.md` — anti-bypass и red flags;
- `references/perception-limits.md` — каталог слабых мест мультимодального зрения.

Человеческое описание и контекст остаются в этой проектной папке, но не переносятся в installed skill.
