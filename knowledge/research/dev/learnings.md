## Проверено

- В инженерных задачах acceptance criteria лучше формулировать через наблюдаемый артефакт: diff, вывод команды, содержимое файла, HTTP-код или test report.
- Self-report не считается подтверждением для code work. Агент должен показать проверяемый след результата.
- Testable in isolation особенно важно в code tasks: если критичное требование нельзя проверить отдельно, постановка почти наверняка слишком расплывчата.
- Чем ближе агент к изменению файлов, доступов и внешних систем, тем важнее короткий цикл `read -> change -> verify`, а не длинная неподтверждённая траектория.
