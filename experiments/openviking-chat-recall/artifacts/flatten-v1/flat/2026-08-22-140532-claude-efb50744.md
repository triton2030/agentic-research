- Владелец решил после аудита запускать множество Codex-агентов, именно `Luna Max`, для создания этой библиотеки. [L21]
- Владелец предложил использовать `Luna Max` для выполнения инструкций, а для размышлений, принятия решений, поиска конфликтов и более сложной когнитивной работы — умные модели `сол Хай`. [L22]
- Владелец решил не создавать агентов, которые строят карту из всех файловых цитат, поскольку это нереалистично. [L23]
- Владелец решил симулировать работу OpenViking, не изобретая заново систему обновления документов, описанную в документации OpenViking в интернете. [L24]
- Критерий симуляции — обрабатывать цитаты постепенно, порциями по 10: одна `Luna Max` создаёт файлы по первой порции, следующая получает следующую порцию, смотрит на уже созданные файлы и дополняет или переписывает их, чтобы уменьшить когнитивную нагрузку. [L25]
- Владелец решил до конца придерживаться рекомендованной схемы: без `changeset`-слоя заявок с манифестами и хешами, с батчами, процедурой OpenViking в промпте, смысловым аудитом и git как откатом, не запрашивая дополнительных согласований. [L26]
- Владелец предложил создать отдельную копию папки цитат, отдельно переписывать каждый файл в сухое знание без историчности и речевого мусора, а затем объединять файлы по схожим темам. [L27]
- Владелец решил организовать один workflow, который одной командой запускает множество `Luna Max`-агентов, организуя их работу по порядку и параллельно. [L28]
