- Владелец выбрал `1html` для задачи автоматического дизайна. [L25]
- Владелец уточнил, что цель автоматизации `1html` — облегчать агенту написание HTML-кода, а не упрощать визуальный дизайн. [L26, L27]
- Владелец поправил, что `1html` не должен ограничивать свободу дизайна обязательными шаблонами, а содержимое каждой React Flow node должно легко меняться под задачу. [L33, L40]
- Владелец решил добавить в `1html` отдельный React Flow workflow для больших нод с интерактивными toggles и accordions внутри и анимированными линиями, показывающими течение данных; workflow не нужен, если он не работает без dev server. [L35, L38]
- Владелец задал, что React Flow должен следовать шрифтам и цветам палитры, а не вводить собственный визуальный язык. [L36]
- Владелец решил, что `1html` должен заменять стену текста иллюстративными HTML-артефактами: показывать вложенность, использовать разные графики, flow maps, bar charts и pie charts, анимации, timelines, accordions, popups и текст на hover, а также учитывать последние возможности CSS и HTML. [L37]
- Владелец решил включить в планы переработки `1html` мощные библиотеки с примерами разнообразной визуализации данных. [L41]
- Владелец потребовал, чтобы текущая переработка `1html` качественно следовала `1planning`. [L42]
- Владелец поправил направление `1html`: вместо процедурных проверок нужно задать агенту рамку мышления, максимально ускорить создание дизайна без лишних проверок, команд и шагов и создавать агентскую инструкцию в папке артефактов, чтобы агенту не приходилось читать скил. [L45]
- Владелец задал архитектуру `1html`: одна папка `HTML_artifacts` должна содержать общие components, styles и libraries, переиспользуемые множеством HTML-файлов, без отдельных копий для каждого артефакта. [L46, L47]
- Владелец решил исправлять `1html` одновременно в Claude и Codex. [L48]
- Владелец уточнил, что showcase-артефакт с React Flow, ECharts, Mermaid и nested structures должен находиться в текущем репозитории `agentic-research`, а не внутри Mavo. [L50]
- Владелец задал целью DaisyUI-подхода упростить разработку для агента. [L54]
- Владелец решил использовать `cupcake` как утверждённую локальную DaisyUI-тему по умолчанию для Visual Systems Lab и `1html`, а для элементов, которых нет в DaisyUI, переиспользовать ту же тёплую палитру вместо создания второй палитры. [L53, L55, L63]
- Владелец задал для `1html` и Visual Systems Lab, что `primary` служит фоном, а `primary-content` — текстом и графиками; это правило должно быть отражено в документации. [L60, L61]
- Владелец решил обновить весь скилл `1html` для использования DaisyUI-цветов и уточнил, что это касается не только текста. [L64, L65]
- Владелец решил проверить, где `1html` изобретает собственные компоненты вместо возможностей DaisyUI и где skill, примеры или scripts не используют DaisyUI для экономии времени, сделав DaisyUI самым лёгким default-путём без ограничения композиции. [L67]
- Владелец решил использовать множество независимых Opus-субагентов как советников и проверяющих для финального exact-current аудита DaisyUI/cupcake-кандидата `1html`. [L66, L69]
- Владелец решил, что отдельная Codex-задача conservative HTML smoke не должна блокировать или менять текущую DaisyUI/cupcake-коррекцию `1html`. [L68]
- Владелец одобрил описание minimal header scaffold в более ранней части текста `1html` как часть возможного рефактора и упрощения всего скила. [L70]
