- Владелец решил ограничить 1skill-architect тремя reference-файлами, один из которых посвящён наиболее распространённым ошибкам мышления агентов. [L19, L25]
- Владелец задал для 1skill-architect критерий: агент должен использовать скилл, короткий заголовок не должен дублировать тело, а основное тело должно быть преимущественно роутером когнитивного протокола. [L20]
- Владелец предложил для references двухчастную типологию: cognitive protocol или предметное знание вроде design system; каждый такой файл должен быть не длиннее 2000 символов, а документацию следует делить по смыслу. [L21]
- Владелец решил хранить скилл в одной папке с версиями внутри при необходимости, без отдельного деления на Claude и Codex, хотя скиллы обычно зеркалятся. [L22]
- Владелец поправил источник определения провала: для когнитивного скила владелец должен указать, что считает провалом, а скилл, основанный на его желаниях, без его вводных автоматически не создаётся. [L23, L27]
- Владелец выделил второй жанр скилов: справочный скилл вроде design system должен опираться на поведение модели, а не на личные пожелания владельца. [L24]
- Владелец решил учитывать в скилах провалы наиболее мощных используемых моделей, включая Codex и Opus. [L25]
- Владелец поправил 1skill-architect: даже прямое указание способа не отменяет требования доказать модели необходимость коррекции, назвав её default, иначе модель может не принять изменение. [L26]
- Владелец решил сокращать длинные процедуры и протоколы через названия популярных методологий, аббревиатуры или имена методологий и применять этот принцип также к собственному тексту скила. [L28]
