# Flatten — второй маршрут: сначала убрать разговор, потом группировать

Замысел владельца 2026-08-22: сделать копию папки цитат и переписать **каждый
файл отдельно** так, чтобы он перестал быть файлом цитат — убрать историчность,
речевой сор и оставить сухое знание в его финальном состоянии. Объединение по
темам — отдельный второй шаг.

## Почему этот маршрут отделён от батч-схемы

Батч-схема просит одного писателя одновременно не исказить сказанное и решить,
как разложить его по страницам. Эти работы тянут в разные стороны: чтобы не
исказить — держись реплики, чтобы разложить — оторвись от неё. За четыре полных
прогона число находок шло 29 → 17 → 7 → 15, то есть механизм качался, а не
сходился.

Flatten разводит работы по шагам. Шаг 1 не требует общего контекста, поэтому
идёт параллельно и проверяется локально: один файл против одного файла.

## Шаг 1 — сделано

- контракт: `prompts/flatten-file.v1.md`;
- раннер: одна команда, 20 шардов по 10 файлов, пять `gpt-5.6-luna/max`
  одновременно; прогоны — `_workspace/flatten-v1/runs/`;
- вход: 197 файлов `_ops/chat-recall/`, 956 421 байт;
- выход: `flat/`, 197 файлов, 347 864 байта — **сжатие 2,75×** до всякого
  схлопывания дублей между файлами;
- имена один в один с источником; файлов «знаний нет» — один.

Модальность каждой позиции берётся из поля `type` самой записи, а не
угадывается. Замер по точному корню слова: 872 пункта из 1000 совпали (87,2%);
проверенные вручную расхождения — синонимы верной модальности («уточнил»,
«скорректировал» вместо «поправил»), то есть инструмент меряет словарь, а не
смысл.

## Шаг 2 — дальше

Объединить файлы в более крупные по схожести обсуждаемой темы. Здесь живёт
трудная часть, которую шаг 1 не убирает, а откладывает: дубли между файлами и
актуальность между разговорами. Материал на входе уже чистый.

## Границы

проекция; её можно удалить и построить заново.
