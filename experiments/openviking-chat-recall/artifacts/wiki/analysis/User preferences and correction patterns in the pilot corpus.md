# User preferences and correction patterns in the pilot corpus

This analysis asks which user preferences recur across the pilot holders and how they are enforced through corrections. The corpus shows a consistent pattern: the user permits initiative, but repeatedly corrects abstraction drift, unnecessary complexity, evidentiary substitution, and imprecise scope.

## Preferences that recur

### Preference for concise but faithful capture

The user wants entries that preserve the essence of what was said with minimal distortion: literally quote-like, but slightly shortened when that improves usefulness ([2026-07-22 skill creation](viking://resources/chat-recall-pilot/2026-07-22-105500-claude-d8a832a4/2026-07-22-105500-claude-d8a832a4.md)). This is a preference about fidelity, not about verbatim raw transcripts.

### Preference for simple, reliable systems

On 2026-08-11 the user explicitly says the simpler system is better and more reliable, even referencing a previous removal of a whole reading layer for that reason ([2026-08-11 codex holder](viking://resources/chat-recall-pilot/2026-08-11-163847-codex-019ff09d/2026-08-11-163847_2more_5a7a2bfd_2.md)). This preference recurs as a correction signal whenever architecture grows too complex for its demonstrated value.

### Preference for grounded retrieval rather than speculative routing

The user accepts retrieval aids such as session-context cards, but only when their role stays limited to finding the right file. The same 2026-08-14 records explicitly reject treating those cards as proof of owner positions or as substitutes for quotes ([2026-08-14 codex holder part 1](viking://resources/chat-recall-pilot/2026-08-14-124028-codex-019fff2e/Chat_recall_2026-08-14_codex_019fff2e/Chat_recall_2026-08-14_codex_019fff2e_1.md); [2026-08-14 codex holder part 2](viking://resources/chat-recall-pilot/2026-08-14-124028-codex-019fff2e/Chat_recall_2026-08-14_codex_019fff2e/Chat_recall_2026-08-14_codex_019fff2e_2.md)).

### Preference for initiative with visible limits

Later August holders show tolerance and even preference for autonomous action by agents, but they also preserve boundaries, candidate-rule status, and later corrections rather than unconditional approval ([2026-08-20 codex holder parts 2-4](viking://resources/chat-recall-pilot/2026-08-20-222832-codex-01a02036/Chat_recall_2026-08-20_codex_01a02036/Chat_recall_2026-08-20_codex_01a02036_2.md); [2026-08-21 codex holder 01a020be](viking://resources/chat-recall-pilot/2026-08-21-010201-codex-01a020be/2026-08-21-010201-codex-01a020be.md)).

## How corrections are expressed

The user often corrects by narrowing the scope rather than by rejecting the whole direction. Examples include saying the experiment is about the script, not the skill; saying an index file names topics but is not itself the evidence source; and saying session backfill must read the real sessions rather than infer context from quote snippets alone ([2026-08-11 codex holder](viking://resources/chat-recall-pilot/2026-08-11-163847-codex-019ff09d/2026-08-11-163847_2more_5a7a2bfd_2.md); [2026-08-14 codex holder part 1](viking://resources/chat-recall-pilot/2026-08-14-124028-codex-019fff2e/Chat_recall_2026-08-14_codex_019fff2e/Chat_recall_2026-08-14_codex_019fff2e_1.md)).

Another pattern is correction by boundary phrase. The user says certain metadata should not exist, certain file-level signals should not be treated as truth, and certain confirmations still need to be literal and live even after broad permission to continue ([2026-08-11 codex holder](viking://resources/chat-recall-pilot/2026-08-11-163847-codex-019ff09d/2026-08-11-163847_2more_5a7a2bfd_2.md); [2026-08-14 codex holder part 2](viking://resources/chat-recall-pilot/2026-08-14-124028-codex-019fff2e/Chat_recall_2026-08-14_codex_019fff2e/Chat_recall_2026-08-14_codex_019fff2e_2.md)).

## Conclusion

The strongest cross-source pattern is not a fixed doctrine of passivity or autonomy. It is a preference for useful forward motion that remains corrigible. The user accepts new mechanisms and agent initiative when they produce concrete gains, but repeatedly reinstates boundaries when the system starts to confuse hints with evidence, complexity with quality, or permission to proceed with permission to decide on the user's behalf.
