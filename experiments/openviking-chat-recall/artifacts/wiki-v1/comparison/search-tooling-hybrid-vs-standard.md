# Чем искать слова владельца: скриптом, hybrid-поиском или стандартными инструментами агента?

Способ поиска не закрыт: local hybrid-поиск после проверки становится полноценным дефолтом, но параллельно опробуется поиск без скрипта — стандартными инструментами и явными стратегиями по topics и types, потому что такой подход может оказаться сильнее скрипта. Отдельно ставился вопрос хранения: один большой файл базы данных против множества Markdown-файлов.

Общий критерий у всех вариантов один: поиск должен быть лёгким и быстрым и превосходить стандартный агентный поиск, причём улучшение не обязано быть многократным. Гибридная стратегия выглядит так: ключевые слова и синонимы → лучшие файлы-кандидаты → сжатие через `gpt-5.6-luna`; короткие пересказы владелец считает снижающими качество, потому что формулировки теряют смысл.

## Взвешенные варианты

- Владелец предложил поискать исследование о том, будет ли агенту удобнее один большой файл базы данных с поиском своими инструментами вместо множества Markdown-файлов, сравнив варианты по экономии токенов, скорости работы, желанию агентов пользоваться ими и качеству получаемых знаний.
- Владелец решил после проверки перевести local hybrid-поиск chat recall из экспериментального статуса в полноценный дефолт.
- Владелец решил опробовать поиск без скрипта: агент использует стандартные инструменты и явные стратегии по topics и types, потому что такой подход может оказаться сильнее скрипта.
- Владелец предложил для `1chat-recall` гибридный поиск: искать ключевые слова и синонимы, находить лучшие файлы-кандидаты и только затем передавать их `gpt-5.6-luna` через `codex_recall.py` на сжатие; короткие пересказы он считает снижающими качество, потому что формулировки теряют смысл.

## Критерии и рамки сравнения

- Владелец задал критерий для развития поиска нужных цитат: рассматривать более продвинутые и эффективные локальные технологии, свежие и лёгкие на текущий момент.
- Владелец задал критерий для поиска цитат: он должен быть лёгким и быстрым и превосходить стандартный агентный поиск; улучшение не обязано быть многократным.
- Владелец уточнил роль INDEX.md в benchmark: файл показывает, что лежит в проекте, а искать evidence нужно в папке _ops/chat-recall.
