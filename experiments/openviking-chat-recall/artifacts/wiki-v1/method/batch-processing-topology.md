# По какой процедуре обрабатываются цитаты — батчами или слиянием?

Обработку решено вести по хронологическим батчам из десяти holder-файлов: новый writer получает только свой батч и текущую Wiki и редактирует её, не читая всех предыдущих цитат. Если новый батч дополняет или меняет знания, существующие Wiki-документы переписываются — вместо параллельного слияния разнородных хронологий. Каждый новый writer смотрит на уже созданные файлы и дополняет или переписывает их, чтобы уменьшить когнитивную нагрузку; правило и полный план должны быть записаны в документации и планах.

## Топология обработки

- Владелец предложил и уточнил топологию обработки: идти по хронологическим батчам из десяти holder-файлов, переписывая существующие Wiki-документы, если новый батч дополняет или меняет знания, вместо параллельного слияния разнородных хронологий. Критерий симуляции — обрабатывать цитаты постепенно, порциями по 10: одна `Luna Max` создаёт файлы по первой порции, следующая получает следующую порцию, смотрит на уже созданные файлы и дополняет или переписывает их, чтобы уменьшить когнитивную нагрузку.
- Владелец решил начать проверку с десяти самых старых файлов одним Luna-процессом, а затем продолжить следующим батчем из десяти файлов.

## Граница чтения writer'а

- Владелец решил, что каждый новый writer получает только свой батч из десяти файлов и текущую Wiki, редактируя её без чтения всех предыдущих цитат; это правило и полный план должны быть записаны в документации и планах.

## Отброшенная альтернатива

- Владелец решил не создавать агентов, которые строят карту из всех файловых цитат, поскольку это нереалистично.
