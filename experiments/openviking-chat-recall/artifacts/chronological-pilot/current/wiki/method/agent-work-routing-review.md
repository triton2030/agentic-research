# Как направлять долгую агентскую работу и проверять результат?

Используй метод, когда нужно прочитать много материалов, получить мнение или контролировать долгую работу: выбранный исполнитель должен оставить проверяемый результат, а не зависнуть без видимого прогресса.

## Routing

1. Для разведки и чтения многих вещей назначь умного помощника; допустимы fleet writers либо один writer с последующей проверкой его работы.
2. В записи от 2026-07-27 указана preference: Sol extra-high — для сложного мышления в диалоге; Medium — основной для письма и параллельной работы; Terra medium — для простых задач.
3. Разделяй роли: Opus пишет, caller проверяет его работу.
4. Native monitor и чтение Claude docs были только предложены как возможные aids; выбор инструмента этим batch не установлен.

## Check

После долгой работы проверь, что writer оставил видимый результат и что его работа просмотрена caller; для fleet или одного writer сохраняется тот же review step.

## Boundary

Эта страница про code/tool work; она не утверждает общие личные preferences. Model names and support are dated source preferences, not a current runtime guarantee.
