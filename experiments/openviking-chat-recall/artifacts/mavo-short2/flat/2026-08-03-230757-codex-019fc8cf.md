- Владелец предложил рассматривать установленные локальные скилы как продукт. [L21]
- Владелец поправил: речь только о локальных скилах MAVO, которые начинаются с цифры 2; глобальные 1* остаются лишь внешним механизмом для конкретных ссылок. [L25]
- Владелец решил, что скилы работают как невидимый operating layer (без ручного выбора skill пользователем); явный вызов skill остаётся escape hatch. [L22]
- Владелец решил, что первый пользователь skill-системы — Founder и его Codex/Claude workflows; переносимый внешний продукт отложен до доказанного dogfood-поведения. [L23]
- Владелец решил принять сквозной benchmark (неоднозначный запрос → owners → решение → изменение → runtime verification → closeout) как направление, пока он отложен. [L24]
- Для материальных изменений Canon владелец принял порядок: classify via 2canon-spec-sync → optional 2bdr → exact Canon writer → finish sync → final audit. [L26]
- Владелец решил, что 2canon-audit остаётся чистым verifier'ом: repair возвращается exact writer'у, затем 2canon-audit запускается заново. [L27]
- Владелец решил, что для Canon нужен явный structural-only delta с определённым carrier review behavior и без ложного semantic bump. [L28]
- Владелец решил сузить связь 2mavo-agent-layer → 2canon-audit до Canon-specific routing; acceptance skill не сертифицирует собственное изменение. [L29]
