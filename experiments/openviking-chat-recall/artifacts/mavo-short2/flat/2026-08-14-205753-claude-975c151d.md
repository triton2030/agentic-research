- Владелец предложил сделать личный сайт прогресса проекта: видно, на какой стадии проект, что ещё нужно сделать и когда всё будет закончено. [L17]
- Сайт он предложил запушить на Vercel с Google-аутентификацией, а контент держать в файлах Markdown, чтобы агентам было легко его редактировать и это не спорило с инструментом планирования. [L17]
- В выборе между самописным сайтом прогресса и готовым инструментом владелец предпочитает готовый инструмент вместо собственного кода. [L22]
- Сам сайт должен быть написан с минимальным количеством кода, потому что это чисто личный инструмент владельца. [L17]
- Для совместимости сайта с планированием владелец предложил слегка переделать скил `1planning`: выбирать при записи планов такой формат Markdown, который сайт сможет парсить, не ломая логику скила. [L18]
- По дизайну владелец предпочитает карточки: большие предстоящие стадии проекта и небольшие таблетки статусов (в работе, не в работе); открытая стадия раскрывается в свои задачи, у каждой задачи виден статус (приступили, не приступили); отдельная страница — бэклог. [L19]
- Владелец предпочитает визуально компактный интерактивный просмотрщик планов с анимациями простому показу Markdown-файлов, потому что Markdown-файл — всегда стена текста. [L20]
- Владелец предложил поменять жёсткое требование репозитория Node 26 на Node 24, потому что Vercel нативно поддерживает максимум 24. [L21]
- Владелец предложил использовать taskforge.md (https://taskforge.md/) как внешнего кандидата вместо самописного просмотрщика. [L21]
