# Пробник раннего allocation gate — критерий записан ДО результата

## Что проверяем

Ловит ли отдельная дешёвая карта «запись -> страница» те же terminal-дефекты,
которые в attempt-002 стали видны только после полного написанного кандидата и
шести осей аудита.

Пробник разовый. Постоянным шагом механизма allocation становится только по
этому замеру, а не потому, что код уже написан
(`modules/wave-6f-full-backfill-transition.md`, раздел T4).

## Разбор attempt-002 по слоям

| Класс | Что это | Виден в карте? |
| --- | --- | --- |
| S1 · split answer | один ответ владельца разрезан по двум страницам | да — сравнением H1 |
| S1 · mixed jobs | одна страница несёт два независимых вопроса | да — по H1 и составу записей |
| S2 · пропущенные повторы | 1 группа заявлена, 4 существуют | да — repetition_groups в карте |
| S4 · page-type drift | `method`/`entity` размечены `concept` | да — page_type в карте |
| S3 · attribution drift | объективизация, ослабление решения, смена субъекта | **нет** — живёт только в прозе |

Предсказание: три класса из четырёх ловятся до прозы; S3 остаётся за полным
аудитом, поэтому полный semantic audit не отменяется ни при каком исходе.

## Условие успеха пробника

Аудит карты обязан назвать с адресами:

1. отсутствие раздельных страниц для `owner-historical-capture` и
   `owner-quote-capture` — либо обоснование, почему они всё же раздельны;
2. отсутствие расщепления позиции «в скиле только дельта» между двумя
   страницами;
3. разделение двух вопросов, слитых в attempt-002 в `owner-agent-metadata`;
4. не менее трёх repetition groups из четырёх известных:
   `cr-92ba68ae02b88b40`+`cr-1d42692df43b815f`,
   `cr-0c56f9b82f11ffc7`+`cr-9e42f2995175d537`,
   `cr-9e42f2995175d537`+`cr-e0cc9eb95585f23d`,
   плюс уже заявленная группа из трёх записей;
5. верный `page_type` для процедуры записи цитат (`method`) и для трёх named
   things (`entity`).

## Условие провала

Карта воспроизводит те же allocation-дефекты, что и attempt-002, ИЛИ аудит
карты не находит их дешевле полного аудита. Тогда prompt-only и
allocation-only маршруты оба опровергнуты, и механизм уходит в Wayfinding:
пересмотр размера batch и роли модели.

## Что замеряем отдельно

Стоимость: один прогон карты + один аудит карты против одного полного
кандидата + шести осей аудита. Телеметрии по шагам в проекте нет — фиксируем
хотя бы число оплаченных прогонов и объём выхода.
