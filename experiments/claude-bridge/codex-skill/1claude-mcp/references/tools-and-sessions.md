# Инструменты и сессии

Справочник нужен при выборе формы вызова или работе с native `session_id`.
Callable schema текущего хоста определяет точные поля; открытая задача может
сохранять схему старого MCP-процесса.

## Когда достаточно одного ответа

`mcp__claude_mcp__claude_ask` принимает `prompt`, существующий `cwd`, выбранный
`profile` и optional `effort`. Без `session_id` это новый разговор; с ним —
продолжение. Профиль свежего вызова определяет модель, а при resume модель и
effort принадлежат native session. Публичные поля `requested_model` и
`requested_effort` тогда равны `null`.

One-shot блокируется до результата. Когда другой полезной работы нет, обычное
ожидание подходит. Если независимая работа есть, host может держать вызов в
фоне: в Codex `functions.exec` позволяет оставить Promise в выполняющейся
ячейке, отдать управление
через `yield_control()` и позже забрать результат. После yield та же ячейка
дожидается Promise через `await` и сохраняет результат: завершение ячейки
уничтожает незавершённые Promise. Host получает выход продолжающейся ячейки
через `functions.wait` с её `cell_id`. Это два способа ожидания
одного вызова, а не причина заводить другую Claude session.

## Когда нужны продолжение и управление

`mcp__claude_mcp__claude_session` держит живой процесс между сообщениями.

| Операция | Что делает и когда доступна |
| --- | --- |
| `open_fresh` | Новый разговор: `prompt`, `cwd`, `profile`, optional `effort` |
| `open_resume` | Открывает существующий native `session_id` с новым `prompt` и `cwd` |
| `send` | Следующий `prompt` в idle session |
| `steer` | Корректирует активный turn через native interrupt и новое сообщение |
| `stop` | Закрывает текущий процесс; native conversation остаётся для resume |

Один ID обозначает именно Claude conversation, не второй идентификатор моста.
Одна native session допускает одного live writer; несколько независимых
разговоров могут работать одновременно. Registry живёт в MCP-процессе:
после его перезапуска lease исчезает, а native history остаётся.

## Когда нужно понять состояние

`mcp__claude_mcp__claude_observe` принимает `session_id`.

| `detail` | Что доступно |
| --- | --- |
| `summary` | Фаза, направление работы, текущий инструмент, число фоновых задач, terminal и warnings |
| `activity` | Ограниченная лента изменений, без raw tool I/O |
| `conversation` | Видимые сообщения пользователя и Claude |
| `diagnostic` | Состояние процесса, сохранённых событий и подробность terminal error |

`cursor` отмечает полученную позицию; `wait_ms` с ним ждёт изменения.
Без cursor ответ возвращается сразу. `limit` и `max_chars` ограничивают peek.
Для чтения уже готового ответа cursor последнего summary может быть слишком
поздним: запрос conversation без него включает сохранённый текст.

`possibly_stalled` — эвристика отсутствия активности. `requires_action`
показывает ожидание действия, `closing` — незавершённое закрытие процесса.
Это сведения для решения агента, а не автоматическая команда повторить запуск.

## Когда ищешь уже открытую Claude session

`mcp__claude_mcp__claude_sessions` с `op: list_active` возвращает metadata;
optional `cwd` сужает список. `op: read` возвращает ограниченный хвост видимой
переписки active `session_id`. Эти операции не получают управление процессом.
Просматривать можно и другие Claude-модели; исполнение через этот мост
поддерживает семейства Opus 5 и Fable 5. Native session с действующим writer
не становится доступной для второго writer через `open_resume`.
