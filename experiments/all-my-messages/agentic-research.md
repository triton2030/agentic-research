`md-mcp → CLI` рефактор уже delivered и архивирован (commit `400aa2d` + `92795e5`). Four-критик fresh-eyes audit (`architecture-critic`, `developer-critic`, `auditor`, `smith`) подтвердил contract pass (audit 14/14), но выявил **корректировочные дефекты и maintenance debt**:

- Broken import + dead module: `src/md_cli/decorators.py:9` импортит несуществующий `INTENT_KEYS` из `transactions.py`. Модуль никем не импортируется → не падает в runtime, но это broken artifact от pre-refactor состояния.
- Реальный bug в transaction protocol: `canonical_intent()` не нормализует пути, хотя `compute_fingerprint()` нормализует. Симптом: dry-run с `corpus="docs"` (relative) + confirm с `corpus="/abs/docs"` (absolute) → false positive `args_mismatch`.
- Envelope-контракт нарушается на unexpected exceptions: `runner.run_tool` и `handlers/_generic.py::_call` ловят только `FileNotFoundError/PermissionError/TypeError`. `URLError`, `socket.timeout`, `nx.NetworkXError` летят raw traceback вместо JSON envelope — нарушает MCP-like contract для agent caller.
- Inconsistent abstraction в Layer 2: 3 из 5 workflows (`orient`, `edit_context`, `section_blast_radius`) — реальная композиция; 2 (`query_by_type`, `refactor_candidates`) — пустые re-exports. Real logic для query_by_type/refactor_candidates живёт в `navigator/api.py:1125-1195`.
- Proxy magic в `navigator/__init__.py` (`_NavigatorPackage` + `_CallableModuleProxy`) — load-bearing (`tests/test_rerank.py` использует `monkeypatch.setattr(search_mod, "rerank_documents", ...)` — это attribute SET на module через proxy). Closeout помечен как «deferred cleanup», но без rationale-docs. Документировать, не удалять.
- Legacy `scripts/md_navigator.py` + `scripts/md_graph.py` — intentional fallback (documented в `docs/skills-semantic-equivalence.md`), но без visible deprecation marker для следующего maintainer.
- `_ops/findings/2026-05-22-mcp-refactor-closeout.md` rollback-section не указывает earliest safe deletion date для backup tag.

Outcome: hardened transaction safety + envelope contract + чистая Layer 2 + явная маркировка intentional legacy и proxy magic, минимум 6 новых adversarial/regression тестов, full suite (177 + new) зелёный. Один atomic commit.

## Через 5 вопросов структурного механизма

Какое слоё держит "как правильно использовать md"?

- Устойчивая рамка (политика) → AGENTS.md? Нет, это не глобальный закон.
- Повторяемый рабочий ход → **skill**? Да.
- Определение done → planning? Нет.
- Опасный сбой → runtime/hook? Нет (две-шаговый protocol уже это держит).
- Вкус / judgment → **skill + канон примеров**? Да, для jq snippets.

**Вердикт**: jq idioms + assembly patterns переносим в `1md-navigator` (+ tangent в `1ia-audit` / `1md-graph` где они используют конкретные tools).

## Что переносим из tool в skill

| Из tool выкидываем | В skill переносим |
|---|---|
| `--brief` mode (~150 строк) | jq snippets per tool — `references/idioms.md` |
| `_build_command` general parser (~50) | inline pattern в SKILL.md «возьми из `_envelope.lock`, подставь в команду» |
| `next_step[].command` string | оставить `next_step.tool` + `args` — skill учит сборке |
| Search→extract adapter `_adapt_stdin_map` (~50) | готовый jq selector в `references/idioms.md` |
| `_brief` payload fallback | nothing — skill вместо |
| sentinel rollback + polling race | удаляем (personal tool — race не существует) |

**Tool становится**: pure unix utility — JSON in (где нужно) → JSON out. `_envelope.lock`, `_envelope.recommended_action`, `next_step.tool/args`, `hint` строки, two-step protocol, sentinel split — **остаются** (это data shape + safety, не help).

## Конкретно для скилов

**`1md-navigator/SKILL.md`** — короткий router, не правится много:

**`1md-navigator/references/idioms.md`** — новый файл, **condition-load** (читается только когда agent делает соответствующую операцию). Примеры:

```markdown
## Brief — компактный output без --brief flag

# search top-N
md search CORPUS --query "X" --json \
  | jq -r '.results[:3] | .[] | "[\(.section_id)] \(.relative_path):L\(.start_line) | \(.heading_chain) | rrf=\(.rrf_score)"'

# overlaps
md overlaps CORPUS --json \
  | jq -r '.pairs[] | "sim=\(.similarity) \(.a.relative_path):L\(.a.start_line) ↔ \(.b.relative_path):L\(.b.start_line) | \(.a.heading_text)"'

# repeated-concepts
md repeated-concepts CORPUS --json \
  | jq -r '.concepts | sort_by(-.unique_files)[] | "files=\(.unique_files) cohesion=\(.mean_cohesion) | \(.label) | medoid: \(.medoid.relative_path)"'

## Dry-run → confirm (mutating ops)

tx=$(md index CORPUS --dry-run --json | jq -r '._envelope.lock.transaction_id')
md index CORPUS --confirm --transaction-id $tx --json

## Search → extract pipe (read top-N в одном вызове)

# search payload → map shape adapter в jq
md search CORPUS --query "X" --json | jq '{
  root: .root,
  files: [.results | group_by(.file_id) | .[] | {
    id: .[0].file_id,
    path: .[0].path,
    relative_path: .[0].relative_path,
    description: (.[0].file_description // ""),
    headings: [.[] | {
      id: .section_id, file_id: .file_id, line: .start_line,
      level: .level, text: .heading_text
    }]
  }]
}' | md extract --map-stdin --headings 1.2,2.3,4.1 --extract --json
```

## Плюсы (значительные для personal tool)

- **Tool становится ~250 строк короче** — меньше Python, меньше тестов, меньше bug surface
- **Skill можно править без regression risk** — markdown, нет CI, изменил — работает
- **`references/` загружаются условно** — main SKILL.md тонкий, attention budget не сожжён
- **DRY относительно проекта в целом** — это **именно** то что проект про-агентит делать с другими tools, теперь применено на себе

## Минусы (для понимания, не для блокировки)

- **Drift возможен** — tool ушёл, skill устарел (jq snippet ссылается на старое поле). Mitigation: периодический smoke (раз в месяц прогнать jq snippets, ловит drift). На personal tool ты это сам почувствуешь когда команда сломается.
- **Agent attention budget на чтение idioms.md** — но: только когда нужно (condition-load), и одно место правды против рассеянных flag'ов.
- **`--map-stdin` adapter уходит в jq** — JQ-selector на 8 строк vs Python adapter на 50 строк. JQ читается тяжелее, но **переносим** для опытного агента.

## Owner Decision Map: что меняется

```
Текущее:
- Tool: brief mode, command builder, adapter — code owner (тесты, schema)
- Skill: thin router catalog

Становится:
- Tool: data + safety primitives (envelope.lock, next_step.tool/args, two-step, sentinel)
- Skill 1md-navigator: workflow idioms — markdown owner, нет тестов
- Skill 1md-navigator/references/idioms.md: deep usage knowledge
```

Это **смещает owner** для usage knowledge с `developer-critic` поверхности на **skill author** поверхность (читай: твоя + Claude совместная правка markdown'а вместо code review).

Важное общее правило: всё, что **меняет файлы или индекс**, делается через `--dry-run` → взять `_envelope.lock.transaction_id` → `--confirm --transaction-id <id>`.

**Ориентация и чтение**
- `md orient` — быстрый обзор корпуса: статус индекса, список файлов, важные узлы.
- `md corpus-scan` — находит все Markdown-корпуса и неиндексированные папки в репо.
- `md status` — показывает, свежий ли индекс и нужно ли запускать `md index`.
- `md ls` — список файлов с `description`, title и числом заголовков.
- `md toc` — оглавление с устойчивыми id секций, например `1.2`.
- `md extract` — достаёт выбранные файлы/секции из результата `ls` или `toc`.
- `md search-read` — главный новый путь: найти по смыслу и сразу вернуть тексты секций.
- `md search` — поиск по смыслу, но только handles/snippets без полного чтения.
- `md read-related` — читает соседний контекст файла: ссылки, backlinks, связанные материалы.
- `md importance` — ранжирует файлы по важности в графе ссылок.

**Граф, ссылки и безопасность правок**
- `md preflight` — перед правкой файла показывает must-read, must-update, blockers.
- `md edit-context` — composite: preflight + related context перед редактированием.
- `md impact` — что сломается при удалении/переименовании файла.
- `md section-blast-radius` — радиус последствий для секции: граф + семантические соседи.
- `md deps` — прямые и обратные зависимости одного файла.
- `md check` — битые wikilinks, anchors и markdown links.
- `md scan` — проблемы frontmatter: missing, legacy, unknown, invalid.
- `md health` — общий graph-health: coverage, hubs, orphans, cycles, broken links.
- `md cycles` — циклы в graph-зависимостях.
- `md changed` — проверяет изменённые `.md` файлы через preflight, удобно перед commit.

**Семантика, дубли и IA**
- `md overlaps` — пары похожих секций, хорошо для дублей и смыслового размазывания.
- `md repeated-concepts` — recurring concepts: где одна идея повторяется по корпусу.
- `md audit` — большой аудит корпуса: дубли, smeared owner truth, clusters, health score.
- `md query-by-type` — найти секции определённого типа: rules, decisions, definitions, open questions.
- `md refactor-candidates` — предложения по реорганизации, только для human review.
- `md profile-sections` — классифицирует секции по типам; нужно для `query-by-type` и refactor proposals.

**Изменяющие инструменты**
- `md index` — прогревает/обновляет embedding index для поиска и overlaps.
- `md init` — добавляет недостающий graph-frontmatter в Markdown-файлы.
- `md strip` — удаляет legacy/unknown frontmatter поля и, опционально, старые related-docs секции.

**Диагностика**
- `md ping` — проверяет, что CLI и backend живы.

# MD-tools — что не понравилось
## 1. Stderr leak в stdout
`md_navigator: using OpenRouter key from /Users/...` пишется в stderr, но **внутри `md search-read`** появлялось и в stdout. Постоянно нужен `2>/dev/null`. Это **хрупкий contract**.
## 2. Inconsistent API типов
`md health` возвращает `broken_graph_links` как **int**, а `cycles` — как **list объектов**. Один и тот же endpoint имеет mixed types. Первый запуск с `len(...)` упал TypeError.
## 3. `md changed` показал только 4 файла после моих 11 правок
Я ожидал, что после 11 unstaged edits, `md changed --base HEAD` покажет все 11. Показал только 4 файла в `_ops/` (root AGENTS, GOAL, project-graph, skills-map). Семантически не понятно, что именно команда считает «changed». Возможно, git diff-related, но непрозрачно.
## 4. `md repeated-concepts` без `--path-include` = 270KB output
Один запуск без path-include дал 270KB JSON. Это **превзошло разумный context budget**. Сейчас в `output too large` сохраняется в файл, что spasает, но **по умолчанию опасно**.
## 5. `md index --confirm` workflow требует trial-and-error
- `--confirm` без `--fingerprint` → `transaction_required` error.
- `md index --dry-run --json` **не показывает fingerprint** в JSON.
- `--confirm --fingerprint auto` → `drift_detected` error, который **в response** показывает реальный fingerprint.
- Третий запуск с правильным fingerprint — успех.
Это не intuitive. UX: или `--dry-run` должен возвращать fingerprint в JSON, или `--confirm` без аргумента должен auto-confirm.
## 6. `md status --json` слишком verbose
3KB JSON каждый запрос. Мне обычно нужны 3 поля: `state`, `pending_chunks`, `drift_count`. `--brief` / `--field` хорошо бы добавить.
## 7. `md search-read` забивает контекст
10 sections с полным content — 14KB. Параллельно 3 запроса — 40KB+ в одно сообщение. Часто полный content не нужен — heading_chain + snippet достаточно. `--no-body` flag по умолчанию для exploratory probes был бы полезен.

## A. AGENTS.md / CLAUDE.md — что прописать жёстче
