`agentic-research` — мастерская знаний и полигон для обсуждений и экспериментов,
но **продукт всегда снаружи репо**: глобальные скилы (`~/.claude/skills/1*`,
`~/.codex/skills/`) и общие паттерны инструкций / промптов / хуков, работающие
во всех проектах. `knowledge/` и разговоры здесь обслуживают эту цель, не
существуют ради себя.

Граф зон — `depends-on` в шапках subtree `AGENTS.md` (читает `1md-graph`).
`README.md` — входной контекст для человека.

## Конвенции Базы

- **Имена файлов и папок в `knowledge/` — русские**, словами владельца о
  предмете. Английскими остаются только имена, которые грузит платформа
  (`README.md`, `AGENTS.md`, `CLAUDE.md`, `SKILL.md`) и дословные снимки чужих
  артефактов, где имя — часть улики.
- **Знак пробела — callout `[!question]`.** Место, где знания нет, помечается
  им. Без знака пустота читается как «здесь уже разобрались», и вопрос,
  которым никто не занимался, закрывается молча.
- **Первый уровень `knowledge/` раскладывается по предметам**, а не по стадии
  готовности документа: модель · рантайм · агент · скил · инструкция · понятия.
  Исследование и эталон по предмету лежат внутри его папки. Решение владельца
  2026-09-10; образец формы — `knowledge/скил/`.
- **`README.md` — раскладка своей папки и единственное исключение** из правила
  «папка держит либо файлы, либо папки». Он отвечает на «что здесь и когда это
  читать», знания о предмете не накапливает. Пустой README хуже отсутствующего:
  объявленный владелец, который молчит, читается как «здесь уже разобрались».
- **Читалка владельца — Obsidian**, разметка обычная markdown с пустой строкой
  после заголовка. Имена с пробелами — норма; в markdown-ссылке такой путь
  берётся в угловые скобки: `[текст](<папка/имя с пробелами.md>)`.
- **Форма сноски — markdown `[^id]` внизу файла**, адрес до строки: файл и
  строка, документ и заголовок, адрес слов владельца в корпусе. Внешнее
  сведение несёт дату и источник.
- **Снятое уходит в `снятое/` внутри своей папки** вместе с одной строкой о
  том, чем оно перестало быть правдой. Живая база снятого не содержит, и агент
  не ходит туда за маршрутом.
- **Эталоном становится чужой артефакт, из которого вынимается повторимый
  урок**: системный промпт, `CLAUDE.md`, `AGENTS.md`, README чужого репозитория,
  манифест скила с его `references/`, инструкция агента или плагина. Не идут в
  эталоны сгенерированные артефакты, если они не иллюстрируют сам приём, и
  собственные наработки без внешнего источника.
- **Эталон чужого артефакта сохраняется дословно**, включая имена файлов и
  вложенность: форма исходника — часть предмета изучения. Это второе названное
  исключение из правила «папка держит либо файлы, либо папки»: внутрь дословного
  снимка правила базы не заходят. Наш разбор лежит соседней подвещью.

## Правила Этого Репо

- **Правка скила — глобальный артефакт** (cross-project, veto-class): пиши
  project-independent, без путей и допущений текущего проекта.
  **Названное исключение — семья планирования** (`1planning`, `1plan-map`,
  `1plan-task`): решением владельца 2026-08-31 точная схема планирования
  mavo-short2 — адреса `_ops/map`, колокация задач внутри эпика, ключи
  frontmatter, словарь статусов и Obsidian Bases — объявлена общим
  стандартом для всех проектов
  (`_ops/chat-recall/2026-08-31-202257-claude-86d85f7e.md#L25`). Не
  откатывай эти адреса как нарушение правила выше.
- **Владелец пакета — сначала tracked owner.** Есть папка в `skills/shared/**`
  или `skills/{claude,codex}/**` — правь её, а `~/.claude/skills/` и
  `~/.codex/skills/` считай projection. Нет tracked owner — live installed
  package остаётся единственной правдой; parity и второй source tree не
  выдумывай. Реестр владельцев — `skills/shared/README.md`.
- **`skills/1<name>/` — история, не скил.** Внутри `origin.md`, `cut.md`,
  `evidence.md`, снапшоты `live-*` и `tracked-*`, иногда `product-frame*.md`
  снятого скила. Никогда не правь их как живой контракт и не принимай их
  `product-frame*.md` за действующий.
- **До первого существенного суждения** прочитай целиком
  `_ops/product-frames/agentic-research{,.principles}.md`. При правке скила —
  плюс `product-frame*.md` из его tracked owner-папки, если она есть; рамки
  неприменимых скилов не pre-load'ятся.
- **Перед правкой skill / agent / instruction** начинай с папки той вещи, о
  которой правка: `knowledge/скил/` для скилов, `knowledge/инструкция/` для
  инструкций и промптов, `knowledge/агент/` для поведения агента.
- **GitHub здесь — backup-диск локального `main`**, не branch/PR flow. Коммить
  и пушь свободно прямо в `main`, без веток, без спроса. Не блокируйся на git.
- **Перед финалом** покажи только существенное evidence: что изменено, чем
  проверено, какие риски остались. По-русски и без справочного шума; короткой
  делает сдачу отбор материала, а не сжатие фраз.
